### 2.3 故障回退 — `200` + `summary_rule_based`

**前置**：在以下任一条件下重复请求同一接口（每次可只测一种，或合并记录）：

- 故意错误 `SUMMARY_AI_API_KEY`；
- `SUMMARY_AI_TIMEOUT_MS=1`（或极小值）触发超时；
- 供应商返回非 2xx（若环境可稳定复现）；
- 模型返回非约定 JSON、缺字段、`conversationId` 不匹配等（若可构造）。

**预期**：

- 每次均 **HTTP 200**。

### 2.5 ChatPage — AI 摘要试点按钮与失败隔离

**步骤**：

1. 打开带 `conversationId` 的聊天页（ChatPage）。
2. 点击 **「拉取 AI 摘要（试点）」**。
3. 在配置正确时，应在摘要区域下方展示第二块卡片（带 `sourceType` 等 meta）；配置关闭或失败时，接口仍 200 则卡片可为规则占位文案，或网络/401 时仅 AI 块展示错误提示。
4. 确认 **消息列表** 与 **发送消息** 不受 AI 摘要加载失败影响（可故意断网或清 token 仅验证前端：AI 块报错，发消息流程仍可操作至各自独立结果）。

**预期**：

- 按钮可重复点击；loading 状态不锁死整页。
- 失败时错误文案出现在 **AI 摘要试点区域**，**不**替代主摘要卡片逻辑、**不**清空 Copilot 区域。
- 未点击按钮时，**不**自动请求 `/summary-ai/...`（与「不绑发消息路径」一致）。

**结果记录**：

- [x] 通过 / [ ] 未通过  
- 执行时间：**2026-04-10**（补测，浏览器）  
- 备注：**已通过（成功路径 + 触发隔离核对）**。环境：`http://localhost:5173/chat?conversationId=<id>&userId=<viewer>`（已登录态）。**未点击**「拉取 AI 摘要（试点）」前，网络面板**无** `GET .../summary-ai/...`（仅有 chat /summary、copilot、messages 等既有请求）。**点击**后出现 `GET http://localhost:3001/summary-ai/conversations/<id>` → **200**，页面出现第二块「会话摘要」区域及 P6.5 试点脚注文案；主摘要与 Copilot 区域仍保留。消息输入框与发送按钮仍存在（发送禁用与空内容等业务规则一致，**非** AI 请求导致整页锁死）。**未测**：断网 / 清 token 下的失败文案分区（按实现应为 AI 块独立报错）；若需零容忍可另开一轮专项。
