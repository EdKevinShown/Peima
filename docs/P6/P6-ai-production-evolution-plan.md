# P6：真实 AI 生产链演进（Worker / 模型 / Agent / Simulation）— 规划

> **状态**：**规划文档**。**中远期方向**，**不是** 当前仓库已承诺的开发范围；**未实现**。  
> **前置**：P0～P3 已完成；P4 / P5 分别从 **体验** 与 **治理** 侧铺垫；P6 讨论 **替换或增强规则层** 的工程路径。

---

## 1. 标题

**P6 — 真实 AI 生产链演进**：在 **明确 SLA、成本与合规** 的前提下，将 **Worker、外部模型服务、可选多 Agent 编排、simulation** 等 **逐步** 引入，使摘要、匹配洞察、Copilot 等能力 **可以** 由模型产出，同时 **保留** `sourceType` / `sourceVersion` 与降级到规则层的能力。

---

## 2. 本阶段定位

README 长期口径：**真实 AI Agent、多 Agent、生产级模型链尚未正式接入**。P6 文档用于 **提前对齐**「若要做，分几步、依赖什么、如何验收」，避免与 P4（体验）、P5（治理）混谈。  
**任何 P6 子项开工前**，应 **单独立项**（预算、模型供应商、数据出境等），**本文件不构成承诺**。

---

## 3. 与前一阶段的关系

| 阶段 | 关系 |
|------|------|
| **P5** | 历史与审计 **为模型输出** 提供 **归因与回滚依据**；P6 产出的内容应 **写入可追溯字段**，**不** 绕过 P5 若已建立的权限与保留策略。 |
| **P4** | 用户端 **仍通过** 既有 API/UI 消费结果；P6 **尽量** 不强制用户感知「是否模型生成」（可由 `sourceType` 控制展示）。 |
| **P3** | 时间线可 **未来** 展示「模型生成类」事件（需新类型与产品同意）；**非** P6 启动必要条件。 |

---

## 4. 本阶段核心目标（方向性）

1. **可插拔**：规则层与模型层 **可切换或并行 shadow**，失败 **可降级**。  
2. **可观测**：token、延迟、错误率、成本 **可度量**（至少日志级）。  
3. **可治理**：与 P5 的权限、历史策略 **兼容**；**不** 默认全量用户上模型。  

---

## 5. 建议纳入范围（做什么）— 分梯队

**梯队 A（基础设施，通常最先）**

- Worker 中 **异步任务** 框架扩展（队列、重试、死信），与现有 cron/batch-match **共存**。  
- **模型调用适配层**（单一 provider 亦可）：超时、重试、密钥管理、**不** 把 key 提交进仓库。  

**梯队 B（业务替换试点）**

- 选定 **一条** 低风险链路试点（例如 **摘要生成** 或 **matchInsights  enrichment**），**双写** 或 **AB** 由配置控制。  
- 延续 **`sourceType` / `sourceVersion`**，标明 `rule-based` vs `model-*`。  

**梯队 C（中远期）**

- **多 Agent / simulation 流水线**：仅 **设计文档 + PoC** 即可单独里程碑；**不** 默认进入 MVP。  
- **WebSocket / 流式输出**：与当前 HTTP 聊天 **分离决策**，避免绑架 P0 契约。  

---

## 6. 明确不纳入范围（不做什么）

- **不** 在本文件发布时 **默认开启** 任何付费 API 或用户数据出境流程。  
- **不** 用「先上模型再补治理」**颠倒** P5 与 P6 顺序（除非明确接受风险并经书面批准）。  
- **不** 将 P6 **等同于** P4 体验优化或 P5 后台建设。  

---

## 7. 预期产出物（若启动）

- 独立 **`docs/P6/`** 子文档：供应商评估、RAG 是否采用、数据流图。  
- 代码：**适配层 + 配置 + 可选 feature flag**；**迁移**（若存模型元数据）。  
- **运行手册**：密钥轮换、降级开关、on-call 说明。  

---

## 8. 验收口径 / 完成标准（启动后适用）

- **功能**：试点链路在 **flag 关闭** 时与现状 **行为一致**；**flag 打开** 时 **可生成** 可验收的模型输出。  
- **非功能**：P95 延迟与错误率 **有** 监控阈值；超阈值 **自动降级** 或告警。  
- **合规**：数据处理 **符合** 当时有效的产品/法务结论（本规划 **不** 替代法务审查）。  

---

## 9. 主要风险与依赖

| 风险 / 依赖 | 说明 |
|-------------|------|
| **成本** | Token 与 QPS **不可控** 可导致账单风险；需 **预算帽** 与限流。 |
| **质量与安全** | 模型 **幻觉、注入、越权建议**；需 **护栏** 与人工抽检流程。 |
| **供应商** | 单点故障；需 **多 provider 或规则降级** 策略。 |
| **组织** | 需 **明确 owner**（ML/后端/产品）；否则 P6 停留在文档层。 |

---

## 10. 推荐实施顺序

1. **决策门**：是否进入梯队 A（基础设施）— **无决策则不写生产代码**。  
2. **梯队 A** 完成后再选 **试点业务**（梯队 B）。  
3. **梯队 C** 仅在有 **明确产品场景与预算** 后启动 PoC。
