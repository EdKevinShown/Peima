# P6.7 Final Match Primary Conclusion — 首轮收口记录

## 一句话结论

本轮已在 **`GET /matching/result/:userId`** 读路径上稳定附加 **`primaryConclusion`**（规则直出 / 模型成功 / 模型失败回退三态），与既有匹配写库与展示字段解耦；A1 / A2 / A3 均已验证，实现与文档口径收口，**本轮不再继续修改 P6.7 功能**。

## 本轮目标

在最终匹配结果读取接口中，为用户提供一段可展示的「最终匹配主结论」文案，来源可区分规则层与模型层，并在模型不可用时回退到规则摘要，且**不改变**既有匹配决策与持久化字段。

## 实现范围

- **API**：`MatchingService.getLatestResultForUser` 在查询最新 `MatchResult` 后调用 `FinalMatchConclusionService.generate`，将返回值合并为响应字段 `primaryConclusion`。
- **模块**：`apps/api/src/modules/matching/` 下独立配置（`FINAL_MATCH_CONCLUSION_AI_*`）、专用 AI 客户端、提示词与 mapper；`MatchingModule` 注册上述提供者。
- **契约**：`packages/shared/types` 中 `PrimaryConclusion` 四字段类型；Web 侧 `getMatchingResult` 与 `FinalMatchPage` 对 `primaryConclusion` 做形状守卫后展示主结论区块。

## 明确边界

下列事项**不在本轮实现范围内**，且本轮**未改动**：

- 匹配决策逻辑、批处理、worker 写库路径；
- `MatchResult` 上既有字段 **`finalScore`**、**`reasonSummary`**、**`matchInsights`** 的写入与语义；
- P6.5 Summary AI、P6.6 Match Explanation AI 的配置与调用链；
- Prisma schema 迁移、队列化生成主结论、结果缓存落库等。

## 接口与返回扩展

- **路径与方法**：`GET /matching/result/:userId`（与其它 matching 接口相同，需 JWT 且路径 `userId` 与 token 一致）。
- **扩展字段**：在原有 `MatchResult` 序列化之上增加 **`primaryConclusion`**，类型为对象，字段见下节。

## sourceType / sourceVersion / fallbackUsed 口径

| 场景 | 说明 | `sourceType` | `fallbackUsed` | `sourceVersion` |
|------|------|--------------|----------------|-----------------|
| **A1** | 规则直出（AI 关闭或无有效 API Key，未发起模型调用） | `final_match_conclusion_rule_based` | `false` | `p7-final-match-conclusion-rule-v1` |
| **A2** | 模型调用成功且返回可解析的有效 `content` | `final_match_conclusion_model_<slug>`（`slug` 来自配置或 Base URL 推断） | `false` | `<slug>\|<model>\|p7-final-match-conclusion-prompt-v1` |
| **A3** | 模型失败或返回无法映射为有效主结论文案，回退规则层拼装文案 | `final_match_conclusion_fallback_rule_based` | `true` | `p7-final-match-conclusion-rule-v1` |

**`primaryConclusion` 固定四字段**：`content`（string）、`sourceType`（string）、`sourceVersion`（string）、`fallbackUsed`（boolean）。A1 与 A3 的 **`sourceType` 不同**，用于区分「从未走模型」与「走模型失败后回退」。

## 日志事件口径（`final_match_conclusion`）

- **事件名**：结构化日志字段 `event` 取值为 **`final_match_conclusion`**（与 P6.5 / P6.6 事件分离）。
- **结果分类**（`outcome`）：
  - **`rule_only`**：未调用模型（如开关关闭、缺 Key），对应 A1；
  - **`model_ok`**：模型返回可用内容，对应 A2；
  - **`fallback`**：模型路径失败或内容无效后回退规则文案，对应 A3。
- **辅助字段**：含 `matchResultId`、`durationMs`、`providerSlug` 等；HTTP 类失败时可含 `status`。本轮**未**为改变归因而调整上述 `event` / `outcome` 命名。

## A1 / A2 / A3 验收记录

| 编号 | 场景 | 验收结论 |
|------|------|----------|
| **A1** | 规则直出 | **通过**：`primaryConclusion` 为规则拼装文案，`sourceType` 为 `final_match_conclusion_rule_based`，`fallbackUsed` 为 `false`。 |
| **A2** | 模型成功 | **通过**：`primaryConclusion.content` 来自模型 JSON 中的 `content`，`sourceType` 为 `final_match_conclusion_model_<slug>`，`fallbackUsed` 为 `false`。 |
| **A3** | 模型失败回退 | **通过**：响应仍为可读主结论（规则层同源逻辑），`sourceType` 为 `final_match_conclusion_fallback_rule_based`，`fallbackUsed` 为 `true`。 |

**前端展示验证（页面侧闭环）**：Final Match 页面在 `primaryConclusion` 符合约定字段形态时渲染「最终匹配主结论」区块；该展示与进入聊天、关系时间线等既有主行动入口并行存在，未改变上述入口的可用性与布局优先级。本项用于确认接口契约与页面呈现一致，作为本轮页面侧收口依据。

环境变量前缀为 **`FINAL_MATCH_CONCLUSION_AI_*`**，与 P6.5 / P6.6 前缀隔离；具体键名以实现代码 `final-match-conclusion.config.ts` 为准。

## 本轮关键修正点

1. **A1 / A3 归因分离**：规则直出与模型失败回退不再共用同一 `sourceType`；回退场景使用 `final_match_conclusion_fallback_rule_based` 并置 `fallbackUsed: true`。
2. **Kimi K2.5 专用请求体**（仅 P6.7 `FinalMatchConclusionAiClient`）：当 **`providerSlug === "kimi"`** 且 **`model`（去空白、小写）为 `kimi-k2.5`** 时：
   - 请求体包含 **`thinking: { "type": "disabled" }`**，以降低非展示向推理对输出形态的影响；
   - **不发送** `temperature`、`max_tokens` 及本轮未使用的其它采样参数，以适配 Kimi K2.5 的参数约束；
   - 其它 provider / model 组合仍发送 **`temperature: 0.35`** 与 **`max_tokens: 800`**，行为与 Kimi 分支前一致。

上述修正**仅**作用于 P6.7 主结论调用链，**未**引入通用「thinking 策略」框架或新环境变量项。

## 最终结论

P6.7 首轮目标已达成：读路径附加主结论、三态可验收、归因字段与日志事件独立且与 P6.5 / P6.6 解耦；Kimi K2.5 调试中发现的不兼容请求字段已按最小差异在专用客户端内处理。**本轮对 P6.7 实现予以收口，不再继续修改功能行为。**
