# P6.8 / P6.10 收口后 — 最小系统回归清单（手动）

> **性质**：进入「真正 AI 模拟匹配」等下一阶段前的**最小手动回归**；**不**替代全量 e2e，**不**要求本清单内编写自动化代码。  
> **范围**：与当前仓库已跑通能力一致 — **Final match 主链（规则/占位）**、**三页会话 URL 自愈**、**P6.8 生成 / mine / accept / dismiss**、**P6.10 pending 禁用态**、**batch-match 的稳定触发方式**（以本机已验证路径为准）。  
> **关联文档**：阶段事实与边界见 **`docs/P6/P6.8-P6.10-phase-closure-handoff.md`**；联调命令风格可参考 **`docs/P2/P2.5-integration-checklist.md`**（本清单不重复展开 curl 全集）。

## 1. 测试范围

| 域 | 覆盖内容 | 本清单**不**覆盖 |
|----|----------|------------------|
| **Final match 主链** | `preview-pool` → `POST /matching/enqueue` → **一轮** `batch-match` → `GET /matching/result/:userId`（及 Final Match 页） | AI 模拟匹配、worker 打分公式变更验收 |
| **会话 URL** | `/chat`、`/copilot`、`/chat/timeline` 在仅有 **`userId`**（query 或 `localStorage.peimaUserId`）时 **`createConversation` + `replace`**；三页互跳 **`conversationId` 不丢** | 未登录、无 `userId` 的无法自愈文案逐项验收 |
| **P6.8** | 生成 → **`GET /profile-suggestions/mine`** → **accept** / **dismiss** | LLM 输出质量、全部分支错误码矩阵 |
| **P6.10** | 存在 **pending**（与 **`docs/P6/P6.8-*`** 约定 **`sourceVersion`** 一致）时，ChatPage 生成按钮**禁用**且**有单行说明** | `mine` 未带回记录时的 429 事前拦截等边界 |
| **Worker** | 团队/个人**已验证的一条**稳定触发方式（**`POST /admin/batch-match/run-once`**、**`POST /test/matching/run-batch-once`**，或 **`apps/worker`** 下 **`build` + `node dist/... --batch-match`** / **`tsx ...`** 等）能跑完一轮 | 将某条 `pnpm filter` 命令写死为全环境默认 |

**环境前置（与 README「当前项目状态 · 本地联调注意」一致）**

- 根目录 **`.env`**：`DATABASE_URL` 与 API/Web 共用；JWT 可用。  
- **`packages/database`**：已 **`prisma migrate deploy`**（或团队等价），与 **schema** 对齐（避免 **`/profile-suggestions/mine`** 缺列 500）。  
- **`pnpm dev:api`**、**`pnpm dev:web`**（或等价）；**`VITE_API_BASE_URL`** 指向 **API**，非 Vite 自身端口。  
- 测试 viewer：**已登录**；**`user_profile`** 已存在（**enqueue** 前提）；**`createConversation`** 前提满足（通常需最新 **`match_result`**）；预览池规则所需 **≥6** 名带 **`user_images`** 的其他用户（或当前环境已满足的最小数据）。  
- 若使用 **admin / test** 触发 batch：**`PEIMA_ADMIN_USER_IDS`**、**`PEIMA_TEST_MATCH_*`** 等见 **`apps/api`** 实现与根 **README** 说明。

## 2. 测试顺序（须按序执行）

1. **M0 准备**：迁移、服务、数据、触发方式确认。  
2. **M1 Final match 主链**：预览池 → 入队 → **一轮** batch → 拉结果。  
3. **M2 会话 URL 自愈**：三页裸进 → `replace` → 顶栏互跳。  
4. **M3 P6.8**：生成 → **mine** → **accept** →（条件允许时）**dismiss**。  
5. **M4 P6.10**：在 **pending** 仍存在时确认禁用态；**accept** 后确认恢复（若无其它 block）。  
6. **M5 Worker 稳定跑法**：将**实际使用的**一条命令或接口**记录在案**；在仍有 `waiting` 或可复制数据的前提下**重复验证一次**（或记录「无 waiting 故跳过」）。

**顺序理由**：主链与 DB 先稳，再测依赖 **`conversationId`** 的页面与 P6.8；**P6.10** 依赖 **pending**，紧接生成之后最省步骤。

---

## 3. 通过标准（整轮「通过」）

- **M1**：同一 viewer 下 **active 预览池** → **enqueue 成功** → **batch 成功** → **`GET /matching/result/:userId`** 与 Final Match **可读**；结果仍为**规则/占位**口径（不要求 AI）。  
- **M2**：三页在仅有 **`userId`** 时 URL 最终含 **`conversationId` + `userId`**；互跳**不丢**参数。  
- **M3**：生成成功或业务拒绝有明确反馈；**mine** 含 **pending**；**accept** / **dismiss** 后状态与既有产品预期一致。  
- **M4**：**pending** 时按钮 **disabled** + **可见说明**；无 pending 时（且无其它 block）可再次点击生成。  
- **M5**：所选触发方式**可重复执行成功**（或单次成功且原因可解释）；与 **M1** 使用的路径**一致并留档**。

## 5. 执行清单（M0–M5）

### M0 准备

- [ ] 根目录 **`.env`**：`DATABASE_URL`、JWT；若用 admin/test：**`PEIMA_*`** 已按本机**已验证**方式配置。  
- [ ] **`packages/database`**：`pnpm exec dotenv -e ../../.env -- prisma migrate deploy --schema=./prisma/schema.prisma`（从 **`packages/database`** 目录；或团队等价命令）已成功。  
- [ ] **`pnpm dev:api`**、**`pnpm dev:web`**；**`VITE_API_BASE_URL`** 指向 API。  
- [ ] 测试 viewer：**已登录**、**`user_profile`** 存在；预览池所需 **6+** 带图候选（或环境已满足）。  
- [ ] **Worker / batch**：在本机选定 **一条**稳定跑法（admin **或** test **或** worker `main` / `package.json` **scripts** 中 **`--batch-match`** 路径），并**写下**实际命令或接口路径（供 M5 与复盘一致）。

### M1 Final match 主链

- [ ] **`POST /preview-pool/generate`**（JWT 与 body **`userId`** 一致）→ **200**，池 **active**、items 完整。  
- [ ] **`POST /matching/enqueue`** → **200**，队列 **`waiting`**。  
- [ ] 使用 **M0 选定**的方式执行 **一轮** `batch-match` → 成功；viewer 队列 **`matched`** 或出现新 **`match_result`**（与实现一致即可）。  
- [ ] **`GET /matching/result/:userId`** → **200**；**`/final-match?userId=…`** 可读。

### M2 会话 URL 自愈

- [ ] 仅保证 **`userId`**（URL 或 **`localStorage.peimaUserId`**）→ 打开 **`/chat`** → URL **`replace`** 后含 **`conversationId`**。  
- [ ] 同上打开 **`/copilot`**、**`/chat/timeline`** → 各自 **`replace`** 成功。  
- [ ] 顶栏 **聊天 / 沟通洞察 / 关系时间线** 互跳 **≥2 次** → **`conversationId`（及 `userId`）** 保持。

### M3 P6.8（生成 / mine / accept / dismiss）

- [ ] **`/chat`** 带参页：消息量满足门槛 → **触发生成** → 成功或预期业务错误。  
- [ ] **`GET /profile-suggestions/mine`** → **200**，含 **pending**（与 P6.8 **`sourceVersion`** 一致）。  
- [ ] **accept** 一条 → 状态更新；聚合侧有**可观察**变化（与既有验收一致即可）。  
- [ ] **dismiss**（在环境允许第二条 pending 或另建场景时）→ 与 **accept** 路径区分符合预期。

### M4 P6.10（pending 禁用态）

- [ ] 存在 **P6.8 pending** 时：生成按钮 **disabled**，**单行说明**可见。  
- [ ] **accept** 掉该 pending 后：按钮恢复可点（无其它 block 时）。

### M5 Worker 稳定跑法（留档与复验）

- [ ] 将 **M0** 写下的**同一条**触发方式再执行一次 → 仍成功；或记录「无 **`waiting`** / 无重复场景故跳过」及原因。
