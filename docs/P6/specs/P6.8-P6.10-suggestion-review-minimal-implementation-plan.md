# P6.8 / P6.10 建议生成与审阅规则收口 — 最小实现计划

> **唯一依据**：`./P6.8-P6.10-suggestion-review-minimal-implementation-scope.md`（下称《范围说明》）。  
> **主线**：与《范围说明》一致 —「P6.8 建议：消息增量绑定 + 审阅可读摘要（最小规则收口）」。**不**进入 AI 模拟匹配，**不**扩展《范围说明》§5 所列「明确不动」范围。

---

## 1. 实现顺序（总序）

按《范围说明》§2（后端权威优先）与 §1（P1–P6 依赖关系），推荐 **自上而下** 为：

| 步序 | 名称 | 覆盖《范围说明》 | 目的 |
|------|------|------------------|------|
| **S1** | **可追溯数据先行** | P3 | 先有 **可查询** 的「消息快照 / cursor」持久化语义，门禁才有锚点 |
| **S2** | **生成链硬门禁 + 回归锚** | P1、P2、P6 | 在 **`POST .../profile-completion-suggestion`** 路径上落实 **允许/拒绝**；同步确认 **409 / pending** 与 **错误语义** 不被削弱 |
| **S3** | **审阅摘要载荷** | P4 | 在 **成功生成** 的响应（及/或与 `mine` 同源的读取路径）中返回 **与 `proposedPatch` 同源** 的摘要字段 |
| **S4** | **Chat 默认 UI** | P5 | 默认展示摘要、**patch/JSON** 降级；生成按钮 **辅助** 态与后端拒绝对齐 |

**原则**：**S1 → S2 → S3** 必须 **严格后端先行**；**S4** 在 **S3 的响应契约稳定后** 再开工，避免前端与临时字段反复对齐。

---

## 2. 第一批必须先改哪几个点

「第一批」定义为：**未完成后序不应开工** 的最小集合（仍属同一条主线，不拆并行子项目）：

| 批次 | 必须先完成的点（对齐《范围说明》§1） | 理由 |
|------|--------------------------------------|------|
| **第一批** | **P3**（可追溯绑定 / cursor 持久化）+ **P1**（无新消息拒绝）+ **P2**（同增量单 `pending`）+ **P6**（不削弱 409 与 P6.10 相关后端语义） | P1/P2 依赖 **可查询** 的进展锚点；P6 与 P1/P2 **同路径** 回归，应 **同一批合并验证**，避免「门禁上了但 409 退化」 |

**说明**：**P4**（摘要载荷）虽为 Must，但建议在 **第一批行为在 API 层可稳定复现** 后再上，以免同一 PR 内混杂「门禁逻辑」与「展示字段」两类缺陷根因。若团队强制单 PR 交付，仍须 **同一 PR 内按 S1→S2→S3 顺序提交/自测**，不得颠倒。

---

## 3. 每个点大概会落在哪类模块

与《范围说明》§4 一致，按下表将 **P1–P6** 映射到 **模块类型**（不展开具体文件名）：

| 点 | 主要模块类型 |
|----|----------------|
| P1、P2、P6 | **API — 会话画像生成入口**（Controller / Service）、**API — 建议域**（Service / Repository）、**API — 会话与消息读**（只读查询） |
| P3 | **数据持久化**（Prisma schema + migration）、**API — 建议域**（写入 cursor 或等价字段）、必要时 **会话域** 只读校验 |
| P4 | **API — 会话画像生成入口** 与/或 **API — 建议域**（摘要派生与序列化）、**API — 建议查询**（若摘要随 `mine` 返回） |
| P5 | **Web — Chat**、**Web — API 客户端** |
| P6（验证） | 与 P1/P2 **同一批** 在 **建议域 + 生成入口** 上作 **回归断言**（含集成/手测清单） |

---

## 4. 哪些要先做后端，哪些后补前端

| 顺序 | 工作面 | 内容（对齐《范围说明》§2、§3） |
|------|--------|--------------------------------|
| **先做** | **后端** | P3、P1、P2、P6、P4（**生成/读取响应契约**）；含：持久化、门禁、409 语义、错误体、**摘要载荷字段** |
| **后补** | **前端** | P5：**默认展示**摘要、**patch 降级**、按钮 **辅助** 禁用/提示（**不得**作为唯一拦截）；依赖 **已冻结** 的后端字段与错误码映射 |

---

## 5. 做完后如何按 acceptance checklist 验收

与《范围说明》§6 完全一致，实施上按 **`docs/P6/acceptance/P6.8-P6.10-suggestion-review-minimal-acceptance-checklist.md`** 执行：

1. **必测闭环**：自 **B1** 顺序做到 **B11**（**B4** 可引用 **B1** 证据，须在验收记录中 **显式引用**）。  
2. **不测项守门**：确认 **N1–N6** 未升格为本阶段硬门槛。  
3. **BR / FR 核对**：实现与 **BR1–BR6**、**FR1–FR4** 对照；有等价实现时 **备注一行映射**。  
4. **整轮结论**：仅当验收清单 **§5** 三条件同时满足，记 **通过**；否则 **未通过** 并指向失败 **B#**。

**建议**：每完成 **S1/S2/S3** 中的一步，即 **局部跑** 与本步相关的 **B#**（不必等 S4 才测 B1–B3）；**S4** 完成后 **整表 B1–B11** 再走一遍出 **整轮结论**。
