> **Status: Done（代码落地）**

## 1. 本轮目标

- 在 **不改变** `GET /copilot/conversations/:conversationId/insights` 路径与响应主结构的前提下，增加 **可选** OpenAI 兼容 Chat Completions 调用。
- **成功**：`sourceType` 为 `model_<slug>`（**P6.2**：优先 `AI_PROVIDER`，否则按 `AI_BASE_URL` 推断 slug），`sourceVersion` 为 **`slug|model|prompt 版本`** 三节（见 `docs/P6/specs/P6.2-copilot-llm-runbook.md`）。
- **失败或未启用**：回退至既有 `buildCopilotInsights`，`sourceType` 为 `rule_based`（`P2SourceType.RuleBased`），与改造前行为一致。
- **不** 落库、**不** 改聊天写路径、**不** 扩展 summary / matching / worker。

## 3. 成功路径验证结果

| 项 | 结果 |
|----|------|
| 接口路径 | **未变**：仍为 `GET /copilot/conversations/:conversationId/insights` |
| 启用模型且配置合法 | 代码路径：调用 Chat Completions → 校验 JSON → 返回 `sourceType = model_<slug>`，**P6.2** 起 `sourceVersion = <slug>\|<AI_MODEL>\|<promptVersion>` |
| **自动化** | 本机曾执行 `pnpm exec tsc -p apps/api/tsconfig.json --noEmit` **通过**（依赖已 `prisma generate` 且 shared 文件齐全） |
| **人工（push 前建议）** | 设置 `AI_COPILOT_ENABLED=1`、`AI_API_KEY`、`AI_MODEL`（及按需 `AI_BASE_URL`），用登录态请求上述 GET，确认响应中 `sourceType` 前缀为 `model_` |

## 4. Fallback 验证结果

| 场景 | 预期 | 代码行为 |
|------|------|----------|
| `AI_COPILOT_ENABLED` 未启用 / 假值 | 仅规则层 | 不发起 HTTP；`rule_based` |
| 启用但无 `AI_API_KEY` | 规则层 + warn 日志 | `missing_api_key` → `rule_based` |
| 超时 / 非 2xx / 网络 / 空内容 / 非法 JSON / 字段校验失败 | 规则层 + warn 日志 | `fallback` + 原因枚举 |

**人工（push 前建议）**：错误 key 或 `AI_TIMEOUT_MS=1` 仍应 **HTTP 200** + `rule_based`，且聊天发消息不受影响。

## 6. 已知限制

- 仅 **OpenAI 兼容** `POST /v1/chat/completions`；其它厂商需兼容网关或后续再接专用适配。
- **同步**、单次请求，无 Worker、无流式、无多 Agent。
- 模型输入为 **截断后的** 聚合字段 + 最近若干条消息摘要（role 为 me/them），仍受 token 与供应商策略约束。
- `prepare` 会在 `pnpm install` 时执行 `prisma generate`；若环境禁用 install scripts，需手动生成 Prisma Client。
- 工作区若同时存在 `peima` / `Peima` 路径混用，可能导致 pnpm junction 异常，应统一目录后重装依赖。
