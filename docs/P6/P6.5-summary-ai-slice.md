**第一轮实现（最小）**

- **接口**：`GET /summary-ai/conversations/:conversationId`（JWT，参与者校验同 chat）。
- **配置前缀**：`SUMMARY_AI_*`（见根目录 `.env.example`）。
- **日志**：`event: summary_ai`；禁止打印 key 与完整对话原文。

**核心原则**

- Summary **独立接口**
- Summary **独立配置前缀**
- Summary **独立** `sourceType` / `sourceVersion`
- Summary **独立日志事件**
- Summary **独立 fallback**
- **不影响** Copilot 与主聊天主链路

---

## P6.5 定义：Summary AI 化（独立切片）

### 1. 做什么（范围内）

- 为**单一会话 / 线程**提供**摘要能力**：在**独立接口**上返回「当前可见上下文的摘要文本」（或结构化摘要字段，以立项时定的 JSON 契约为准）。
- 实现上采用**独立模块**（配置、客户端、服务层、日志事件名）与 **Copilot 洞察**、**主聊天发消息**解耦；仅只读业务数据，**不写库**（除非立项时明确需要审计表，本切片默认不落库）。
- 通过 **`sourceType` / `sourceVersion`** 标明摘要来自 **规则/占位** 还是 **模型**，便于日志与前端展示对齐。
- 提供**最小可观测性**：专用结构化日志（例如 `summary_ai` 或等价前缀）、**不含密钥与全文消息**，错误信息截断。

### 2. 不做什么（范围外）

- **不做** Matching AI、Explanation AI、推荐排序 AI 等其它智能能力。
- **不上** Worker / 队列 / 异步任务、定时全量摘要、多步骤 Agent。
- **不做** multi-agent、simulation、与摘要无关的 prompt 实验平台。
- **不修改** Copilot 现有契约与行为（`GET .../insights` 等）；**不依赖** Copilot 模块实现摘要（避免「一处改动两处炸」）。
- **不把**摘要写进主链路 `POST` 发消息的**必经路径**（用户不发摘要请求就不应触发摘要逻辑）。

### 3. 为什么先做 Summary（优先级理由）

- **用户价值清晰**：「长对话一眼看懂」比匹配、解释更容易定义成功标准。
- **边界易切**：典型为**只读、按需调用**，对核心聊天写入路径侵入小，适合作为**第一条扩展 AI** 练熟「配置 + 调用 + 回退 + 验收」全套切片打法。
- **故障易归因**：独立接口 + 独立日志事件后，线上问题可优先收敛到 **summary 模块**，而不是和 Copilot 或发消息混在一处。

### 4. 独立入口是什么

- **API**：单独的资源路径（例如「按 `conversationId` 获取摘要」的 **GET** 或经评审后的 **POST**），**仅**服务摘要；路由、Controller、Service 命名与 Copilot 分离。
- **前端**：单独触发点（例如会话详情/侧栏「生成摘要」、或进入某页时的一次请求），**不得**绑在每条 Copilot 洞察或每条消息发送上（除非产品明确且仍保持可关闭）。
- **配置**：环境变量与 Copilot **前缀分离**（例如 `SUMMARY_*` 与 `AI_COPILOT_*` / `AI_*` 区分），避免改 Copilot 配置误伤摘要或反之。

### 5. Fallback 怎么做

- **默认策略**：模型不可用（未开启、无 key、超时、HTTP 非 2xx、JSON/字段校验失败等）时，接口仍返回 **HTTP 200**（与现有 Copilot 试点口径一致），正文为**规则层或空摘要 + 明确来源标记**，**不**拖垮主聊天。
- **禁止**：因摘要失败导致前端整页报错、或阻断发消息；摘要失败时**最多**影响摘要区域展示。
- **日志**：凡走模型路径，无论成功/失败，均打**本切片专用**日志，`outcome` / `reason` 枚举与 runbook 表对齐（可单独维护「Summary 原因码表」一页，不必与 Copilot 混用同一套 reason 语义 unless 刻意复用类型名）。

### 6. `sourceType` / `sourceVersion` 怎么区分

- **命名空间与 Copilot 分离**，避免混读为 Copilot 产出：
  - 示例（具体字符串以实现时统一）：`sourceType` 如 `summary_rule_based`、`summary_model_<slug>`；或固定前缀 `summary_...`，**不得**复用 `rule_based` / `model_<slug>` 作为摘要的唯一标识（除非全站约定「同一字段多语义」，本切片要求**摘要自有取值空间**）。
- **`sourceVersion`**：规则层用**规则模板版本**（如 `p6.5-summary-rule-v1`）；模型层用**可解析的多段版本串**（如 `<slug>|<model>|<prompt 版本>`），与 Copilot 的 `sourceVersion` 格式可相似，但**前缀或首段**必须能区分「这是摘要」。
- **文档要求**：在 P6.5 验收材料中给出**对照表**：各 `sourceType` 含义、与配置项的对应关系，避免运维把摘要的 `model_xxx` 当成 Copilot。

### 7. 验收怎么做

- **功能**：在标准配置下，摘要接口返回非空且 `sourceType` 为模型类；关闭模型或错误 key 时，仍为 200 且为规则/占位类 `sourceType`，UI 可理解。
- **隔离**：压测或故障注入摘要接口时，**Copilot 洞察**与 **主聊天收发**行为与基线一致（无新增 5xx、无额外强依赖）。
- **归因**：日志中可通过 **固定 `event`（或等价字段）** 100% 过滤出摘要相关请求；出现问题时能说明「仅 summary」而不打开 Copilot 代码路径。
- **回退**：关闭摘要功能（环境开关或功能 flag）后，前端无摘要区域异常；接口可返回「未开启」类规则结果或直接不展示入口（产品二选一，须在切片内定死一种）。
- **安全与合规**：日志与响应中无 API Key、无完整对话原文批量泄露；超时与体长上限有约定值。

### 8. 本切片要保证的三条目标（对照检查）

| 目标 | 含义 |
|------|------|
| 可独立排查 | 专用接口 + 专用日志事件 + 专用配置前缀 + 独立原因码/ runbook 小节。 |
| 问题可归因到 summary | `sourceType`/`sourceVersion` 与日志 `event` 可唯一标识「摘要链路」，不与 Copilot 共用同一套未加前缀的取值。 |
| 不影响 Copilot 与主链路 | 摘要不嵌入发消息必经路径；不修改 Copilot 契约；失败仅局部 fallback。 |

以上为 **P6.5 仅 Summary AI 化** 的切片定义；后续若立项实现，再在此基线上补「具体 URL、字段表、环境变量清单」即可，仍保持单功能独立验收与回退。
