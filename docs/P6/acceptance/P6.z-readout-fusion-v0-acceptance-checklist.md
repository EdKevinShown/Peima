# P6.z Readout Fusion v0 — 最小手工验收 Checklist（导览层）

> **目标**：确认「一眼读数」是 **导览层**（短、一次扫读、不抢下面三块主能力），且 **不依赖** 用户先点 P6.x / P6.y。  
> **前置**：`pnpm dev:api` + `pnpm dev:web`；测试账号有 **最新匹配结果**、viewer 与候选人均有 **问卷画像**（与 P6.y 一致）。

---

## 建议验收顺序（由外到内、由正常到异常）

按 **步骤 1 → 7** 顺序执行；前 5 步可在 **同一浏览器会话** 内完成，步骤 6 需换 Token 或改 URL，步骤 7 为降级观察。

| 步骤 | 验收点 | 成功时应看到什么 | 失败时优先怀疑的链路 |
|------|--------|------------------|------------------------|
| **1** | Hero 下方读数条是否正常出现 | 进入 `/final-match?userId=<与 JWT 一致的 id>` 且主结果加载成功后，在 **匹配指数 Hero 正下方**、**「了解这次匹配」之前**，出现浅灰边框的 **「一眼读数」** 区块，含 headline + 两条 bullet | `getMatchingResult` 未返回 `id`；前端 `load` 里 fusion 请求未发出；**401/403** 导致 `getMatchReadoutFusion` 被 catch 后整块隐藏；API 未注册或路径错误 |
| **2** | 不需要先点 P6.x / P6.y，Fusion 就能直接返回 | **刷新页面后**，在 **从未点击**「获取相处参考」「生成初次聊天预判」的情况下，读数条 **仍然出现** 且文案完整 | 误把读数条绑在 `matchReview` / `interactionSim` state 上；`load` 未在 `setResult` 后调用 `getMatchReadoutFusion` |
| **3** | `headlineZh` 像总读数结论，而不是摘要 | 首行以 **「总读数：」** 开头；**一整句立场判断**（偏积极 / 偏保守 / 中性），**没有**罗列维度、**没有**复制下方长段落的句式 | `match-readout-fusion-fusion.rule.ts` 里 `headlineForAggregate` 被改坏；或前端展示了错误字段 |
| **4** | 两条 `bulletsZh` 分工为「行动上 / 注意点」，且不重复 headline | 两条列表项分别以 **「行动上：」** 与 **「注意点：」** 起头；内容为 **短提示**，**不**再写一遍「总读数：…」式总结句 | `bulletsFor` 文案表与 headline 未区分职责；前端把 `headlineZh` 重复拼进 bullet |
| **5** | `tensionZh` 仅在冲突场景出现，平常为空 | **多数样本**：读数条 **没有** tension 灰色说明段；折叠「读数依据」里 `ruleTrace` **不含** `tension_A`/`B`/`C`。刻意找 **系统偏乐观 + 复审或首轮偏保守** 等冲突样本时，出现 **单独一行** 较浅字的 tension，且 `ruleTrace` 含 `tension_*` | `tensionCase` 条件过宽导致常亮；或从不触发需对照 `debug.inputs` 三档与文档 A/B/C |
| **6** | GET 的 **403 / 404** | **403**：用 **另一用户 JWT** 请求当前用户的 `matchResultId`（或反过来的 id），HTTP **403**。**404**：无效 `matchResultId` → **404**；viewer 或 candidate **无画像**（若你能造出该数据）→ **404** | `MatchReadoutFusionService` 鉴权与 `findUnique`；`QuestionnaireService.getProfileForUser` 抛 `NotFoundException` 是否被转成 404 |
| **7** | Fusion 失败时整块隐藏，不影响主页面 | 临时 **关 API** 或把 fusion URL 指错，使 `getMatchReadoutFusion` 失败：页面 **无**「一眼读数」条，但 **Hero、了解这次匹配、P6.y/P6.x 区块** 仍正常；无整页白屏 | `load` 里 `catch` 未吞掉 fusion 错误导致外层 `setResult` 失败；或 fusion 错误向上冒泡 |

## 与「导览层」目标逐条对照（自检表）

- [ ] **1** Hero 下、第二层上，出现窄条「一眼读数」，视觉弱于下方大卡片。  
- [ ] **2** 不点 P6.x / P6.y，刷新后读数仍在。  
- [ ] **3** `headlineZh` = 一句总结论（总读数：…），非摘要、非列表。  
- [ ] **4** `bulletsZh[0]` 行动上、`bulletsZh[1]` 注意点，语义与 headline 不重复。  
- [ ] **5** 平常无 `tensionZh` 段落；冲突样本有 tension + `ruleTrace` 含 `tension_*`。  
- [ ] **6** 403 / 404 与约定一致。  
- [ ] **7** fusion 失败仅隐藏读数条，其余 Final Match 正常。

## API 直验（可选，与步骤 5、6 一起做）

```http
GET /match-readout-fusion/match-results/:matchResultId
Authorization: Bearer <JWT>
```

- 与页面同一 `matchResultId` 时，body 应与读数条展示一致；`tensionZh` 多为 `""`；`debug.inputs` 含 `workerStance` / `p6xStance` / `p6yStance`。
