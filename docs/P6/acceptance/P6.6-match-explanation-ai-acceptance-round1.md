## 1. 验收目标（本轮必须满足）

| 编号 | 目标 | 判定 |
|------|------|------|
| A1 | 关闭 Match Explanation AI（`MATCH_EXPLANATION_AI_ENABLED` 未为真）时，接口仍 **HTTP 200**，且 `sourceType` 为 **`match_explanation_rule_based`** | 见 §2.1 |
| A2 | `MATCH_EXPLANATION_AI_*` 正确配置且模型返回合法 JSON 时，接口 **HTTP 200**，且 `sourceType` 为 **`match_explanation_model_<slug>`**（`<slug>` 与 `MATCH_EXPLANATION_AI_PROVIDER` 或 BASE_URL 推断一致） | 见 §2.2 |
| A3 | 模型路径故障（无 key、错 key、超时、非 2xx、空 content、JSON / `matchResultId` / `explanationText` 校验失败等）时，仍 **HTTP 200**，且 **`sourceType === match_explanation_rule_based`** | 见 §2.3 |
| A4 | **FinalMatchPage** 仅**点击**「生成 AI 匹配说明（试点）」后才请求本接口；失败**仅影响** explanation 试点区块；**不阻断**主 CTA（进入聊天、查看时间线等） | 见 §2.4 |
| A5 | **不影响**现有 **`GET /matching/result/:userId`**、进入聊天、查看时间线、**Copilot**、**Summary** 相关行为与契约（与验收基线一致，无因本切片引入的回归） | 见 §2.5 |

**说明**：**401 / 404**（未登录、非本人、`matchResultId` 不存在）属于鉴权与资源错误，**不属于** A1/A3 的「模型失败仍 200 + 规则回退」范围；验收时勿混淆。

### 2.3 A3 — 错 key / 超时等模型失败 → `200` + `match_explanation_rule_based`

- `MATCH_EXPLANATION_AI_TIMEOUT_MS=1`（或极小值）触发超时；
