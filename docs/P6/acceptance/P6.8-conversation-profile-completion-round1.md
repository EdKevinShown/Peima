# P6.8 Conversation Profile Completion AI — 首轮收口（Round 1）

## 1. 一句话结论

**P6.8 首轮已落地并收口**：在 Chat 域提供唯一入口，基于当前会话近期消息调用独立配置的 LLM，生成一条 **pending** 的 `ProfileUpdateSuggestion`，沿用既有 **mine / accept / dismiss** 闭环；不触碰 matching、不自动写 `UserProfile`、不引入 Worker / 多 Agent。

## 2. 本轮目标

- 基于**当前聊天会话**内容，产出**可审阅**的人格画像维度补全建议（`proposedPatch` 与现有 `UserProfile` 浮点维度一致）。
- **复用**既有 `profile-suggestions` 持久化与前端 **accept / dismiss** 流程，不重构该主链。
- 配置与 **P6.5 / P6.6 / P6.7** 一致：**独立环境变量前缀**，不与 `SUMMARY_AI_*` 耦合。
- **首轮**仅 **ChatPage** 提供人工触发，不扩展到 Copilot / admin / timeline 产品改造 / suggestion center。

## 3. 实现范围

| 层级 | 内容 |
|------|------|
| API | `POST /chat/conversations/:conversationId/profile-completion-suggestion`；可选 body：`{ "messageLimit"?: number }`（1～200，与 timeline 上限对齐）；JWT；参与者校验与消息读取复用 `ChatService.getConversationWithMessages`。 |
| AI | `PROFILE_COMPLETION_AI_ENABLED`、`PROFILE_COMPLETION_AI_API_KEY`、`PROFILE_COMPLETION_AI_BASE_URL`、`PROFILE_COMPLETION_AI_MODEL`、`PROFILE_COMPLETION_AI_PROVIDER`、`PROFILE_COMPLETION_AI_TIMEOUT_MS`；OpenAI-compatible `chat/completions`。 |
| 持久化 | 成功时调用 `ProfileSuggestionService.create`，写入 **一条** `pending` 建议。 |
| 校验 | LLM 输出 JSON → `parseProfileProposedPatch` → **P6.8 白名单过滤**（见下「生成白名单」）；过滤后无允许键则 **422**，不写入。 |
| 题库 branch 空间 | **P6.8.x**：`axisId`+`branch` 在持久化前经 `computeBranchOpportunitiesFromQuestionBank` 过滤，**只保留题库合法 branch**；部分非法时丢弃非法项后照常生成；**全部非法**时 **422**（不写入）。 |
| Web | `apps/web/src/api/chat.ts` 增加 `postProfileCompletionSuggestion`；**ChatPage** 增加「根据本轮对话生成画像建议」按钮，成功后 `loadProfileSuggestions()`。 |
| 模块位置 | 实现落在 `apps/api/src/modules/chat/`（config、client、prompt、service、DTO），`ChatModule` `imports` `ProfileSuggestionModule`。 |

**P6.8 `proposedPatch` 生成白名单（当前已收紧）**：仅允许 **initiativeLevel**、**socialEnergy**、**emotionalExpression**、**relationshipPace** 四键；**confidence**、**decisionOrientation**、**conflictResponse** 已从 P6.8 生成路径排除（system prompt 仅列允许键 + 服务端 `pickProfileCompletionRound1Patch` 过滤，模型越界键不落库）。**既有**历史 suggestion **不做**回溯清洗；**仅**收紧之后**新生成**的 P6.8 建议受上述白名单约束。

**本轮未修改**：`packages/shared/constants/p2-source-type.ts`（未新增 `P2SourceType` 枚举值）。

## 5. 接口与最小前端接入点

**接口**

- **方法 / 路径**：`POST /chat/conversations/:conversationId/profile-completion-suggestion`
- **鉴权**：`Authorization: Bearer <JWT>`（与现有 chat 一致）
- **Body**：可选 `{}` 或 `{ "messageLimit": <1..200> }`
- **成功**：`200`，响应体为新建的 `ProfileUpdateSuggestion`（`status: pending`）
- **典型失败**：无消息 `400`；AI 未开或未配 key `503`；上游/超时等 `502`；JSON 无效或无可用维度 `422`

**前端接入点**

- 页面：**ChatPage**（带 `conversationId` 的聊天页）。
- 交互：单次点击触发上述 POST，错误仅展示在按钮旁；**不**影响消息列表加载与发送。
- 列表与处置：仍使用 **`GET /profile-suggestions/mine`** + **`ProfileSuggestionCard`** + **`POST .../accept` / `POST .../dismiss`**。

## 7. 验收记录（本轮已完成、已验证）

以下项已在实现侧与人工/联调路径上**核对通过**，作为 Round 1 收口依据。

| 项 | 预期 | 结果 |
|----|------|------|
| 生成 pending | 会话有消息、AI 配置有效且模型返回合法 JSON 且含至少一个**白名单内**维度时，**创建**一条 `pending` 建议，`sourceType`/`sourceVersion` 符合 §6。 | **通过** |
| mine 可见 | 生成后 **`GET /profile-suggestions/mine`** 与 ChatPage 侧栏列表**可见**新建议。 | **通过** |
| accept | 对 **pending** 调用 **`POST /profile-suggestions/:id/accept`**，状态变为 accepted；若 proposedPatch 含有效字段，则按既有逻辑更新 UserProfile。 | **通过** |
| dismiss | 对 **pending** 调用 **`POST /profile-suggestions/:id/dismiss`**，状态变为 dismissed。 | **通过** |
| 422 | 模型输出无法解析为合法 JSON，或解析后经白名单过滤**无**任何允许键：接口 **422**，**不**新增 suggestion 行。 | **通过** |
| 非 pending → 400 | 对已 **非 pending** 的建议再次 **accept** 或 **dismiss**：**400** `suggestion is not pending`（既有 `ProfileSuggestionService` 行为）。 | **通过** |
