# P6.z — Final Match 读数合成（Readout Fusion）v0 — 可开工实现说明

> **当前主链定义（唯一真源）**：以 [`P6-current-matching-chain-single-source-of-truth.md`](./P6-current-matching-chain-single-source-of-truth.md) 为准；本文若与其冲突，以真源文档为准。

> **性质**：实现前约定；**本文件不含代码**。约束对齐：不依赖用户先点 P6.x / P6.y；不改 worker；不持久化；不开新页；导览层、非第四份长报告。

## 1. 最终接口路径与方法（唯一方案：新增只读 GET）

| 项 | 约定 |
|----|------|
| **方法** | `GET` |
| **路径** | **`/match-readout-fusion/match-results/:matchResultId`** |
| **鉴权** | 与 P6.y 一致：`Authorization: Bearer <JWT>`，且 **`tokenUserId === MatchResult.userId`**；否则 **403**。 |
| **404** | 无该 `matchResultId`、或 viewer/candidate **任一侧**问卷画像缺失（与 P6.y 拉画像口径一致，便于前后端排错）。 |
| **200 body** | 见下节「最小输入」推导出的 **只读 DTO**（`headlineZh` / `bulletsZh` / `tensionZh` / `debug`）；**不落库**。 |

**不采用**：前端仅用已有三个接口响应自行拼装（避免规则双份、与后端演进漂移）。

**模块形态**：新建 Nest 模块（如 `match-readout-fusion`），与 `match-review-ai`、`interaction-simulation-lite` 并列；handler 内 **顺序调用已有纯函数 / 私有规则逻辑的可提取副本**，不依赖客户端曾请求 P6.x POST 或 P6.y GET。

## 2. 这层最小输入应依赖哪些「现有信号」

服务端在一次 GET 内自行计算，**不读取**用户是否曾点开或缓存过 P6.x / P6.y 的 HTTP 结果。

| 来源 | 字段 / 产物 | 用途 |
|------|----------------|------|
| **`MatchResult` 行** | `id`、`userId`、`candidateUserId`、`finalScore`（worker 系统分）、`createdAt`（可选：仅 debug 或文案不提） | **系统层**主信号；与问卷静态层对照。 |
| **问卷画像（同源）** | `QuestionnaireService.getProfileForUser(viewer)`、`getProfileForUser(candidate)` | 与 P6.x / P6.y 相同闸门。 |
| **静态摘要** | `buildMatchReviewStaticSummary(...)` → `reviewStaticScore`、`staticSummary` | P6.x / P6.y 共享输入；fusion **必须**依赖。 |
| **P6.x 规则快照** | 与 `MatchReviewAiService` 内 **`buildRuleAiReview(reviewStaticScore, staticSummary)`** 等价产物：`recommendation`、`conversationPotential`、`longTermPotential`（v0 **只用这三元 + recommendation**，不必展开 strengths/risks 全文进规则表） | **问卷复审层**的确定性读数；**不**在本 GET 内默认再调 Match Review 大模型（避免双倍 LLM、且与「v0 规则层」一致）。 |
| **P6.y 规则快照** | `buildInteractionSimulationLiteRulePayload({ reviewStaticScore, staticSummary })` → `overall.verdict`，以及 **continuationSignal.band**（或再加 `pickupEase.band` 仅作 bullet 素材，保持极简） | **首轮互动层**的确定性读数；**不**在本 GET 内默认再调 Interaction Lite 大模型。 |

**显式不包含（v0）**：`matchInsights` 全文、P6.x/P6.y **模型**输出、历史 POST 缓存、worker 内部中间分。

## 3. `headlineZh` / `bulletsZh` / `tensionZh` 职责边界

| 字段 | **负责** | **不负责** |
|------|-----------|------------|
| **`headlineZh`** | **一句**用户可扫读的总立场（是否值得认真了解、整体偏积极 / 中性 / 偏保守）。全页「导览锚点」。 | 不复述长解释、不展开维度列表、不重述整段 AI Match Review 或四轴全文。 |
| **`bulletsZh`** | **2～3 条**极短提示：每条只指向「下一步注意力」的一个方向（例如系统分、问卷复审档位、首轮互动总评之一），**口语化、无编号论文感**。 | 不做证据链、不贴具体分数数字（可选：最多一条带「系统分与问卷信号」字样而不堆数字）。 |
| **`tensionZh`** | **仅当**系统分 / P6.x 规则 recommendation / P6.y verdict 三者归一后的「立场」出现 **可对用户造成困惑的冲突** 时，输出 **一句**说明「矛盾从哪来、用户该怎么理解」（例如：系统匹配度不低，但首轮互动信号偏保守——建议先轻聊验证）。 | 不是第二篇小作文；无冲突时 **必须为空字符串或 `null`**（实现二选一文案约定即可）。 |

## 4. v0 规则层：不一致时如何生成可读总判断

### 4.1 先把三源压成「立场档」

实现时建议用内部枚举（不必外露 API）三档即可：**`up` / `mid` / `down`**。

1. **系统分（worker `finalScore`）**  
   - 将 `finalScore` 规范到 0–100 后与阈值比较（与 Final Match 展示口径一致；若存在 0–1 存储，先换算）。  
   - 建议默认阈值（可在常量中单点调整）：**≥ 62 → `up`**；**40–61 → `mid`**；**< 40 → `down`**。

2. **P6.x 规则 `recommendation`**  
   - `strong_match` / `match` → **`up`**  
   - `cautious_match` → **`mid`**  
   - `not_recommended` → **`down`**

3. **P6.y 规则 `overall.verdict`**  
   - `worth_exploring` → **`up`**  
   - `cautious` → **`mid`**  
   - `pause` → **`down`**

### 4.2 总立场（供 `headlineZh` 用）

- **三档一致为 `up`**：headline = 积极总读数（例如整体鼓励小步了解，仍提醒线下感受）。  
- **三档一致为 `down`**：headline = 保守总读数（例如建议放慢、先照顾舒适度）。  
- **三档一致为 `mid`**：headline = 中性总读数（例如「信号混杂度不高，可先轻松接触再判断」类）。  
- **任一源为 `down`**，且另两源并非全 `down`：**总立场取 `down` 偏保守**（用户安全优先），用于 headline 主基调。  
- **无 `down`、但 `up` 与 `mid` 混杂**：总立场取 **`mid`**，headline 中性略鼓励或中性略保留（文案表二选一，由实现常量表固定）。

### 4.3 `tensionZh` 触发与写法

- **触发**（满足其一即可，避免过宽）：  
  - **A**：系统为 **`up`**，且 **P6.x 与 P6.y 中至少一个为 `down`**。  
  - **B**：系统为 **`down`**，且 **P6.x 与 P6.y 中至少一个为 `up`**。  
  - **C**：系统 **`mid`/`up`**，且 **P6.x 与 P6.y 同时为 `down`**。  
- **不触发**：三源已一致；或仅为 `up`/`mid` 轻微差异且无 `down`（用 headline + bullets 消化即可）。  
- **内容**：一句点明 **「谁与谁不一致」**（系统匹配 vs 问卷复审 vs 首轮互动），**不给对策清单**（对策放在 bullets 第一条方向性提示，而非 tension 里展开）。

### 4.4 `bulletsZh` 生成顺序（固定 2～3 条）

1. **第一条**：对齐总立场的一句话行动暗示（轻聊 / 先观察 / 放慢）。  
2. **第二条**：若存在 `tensionZh`，则概括「优先信哪一层」（默认：**首轮互动与复审偏保守时，优先信问卷与互动信号，系统分代表排序不代表现场相处**——实现时压缩为一句短 bullet）。  
3. **第三条（可选）**：仅当总立场为 `mid` 且无 tension 时，补一句「系统分与问卷信号接近，可结合下方详情」类短句；否则省略以保持三条上限。

### 4.5 `debug`（建议最小字段，便于验收与后续 LLM）

- `fusionVersion`: 如 `p6.z-readout-fusion-rule-v0`  
- `inputs`: 三源的原始枚举 / 分档（不含大段文本）  
- `ruleTrace`（可选）：极短字符串枚举，如 `consensus_up` / `min_down_wins` / `mixed_mid` / `tension_A`…

## 5. FinalMatchPage 上具体放在哪个位置最合适

- **位置**：**紧接在首屏 Hero（标题 + 匹配指数 + 更新日期）之后**，**在「了解这次匹配」整块（`matchInsights`）之前**。  
- **形态**：**一条横向「读数条」**：背景与 Hero 区分但弱于下方大卡片；**一行 headline（可稍加重）+ 下方 2～3 行短 bullet**；`tensionZh` 若有，用 **一行浅色辅助文**紧挨 bullet 下方（仍控制在「条」内，不新开卡片标题「深度分析」）。  
- **交互**：默认 **无「展开全文」**；可选 **`<details>` 折叠「读数依据」**（仅列三源档位/枚举，半行级），避免变成第四报告。  
- **加载**：与 `getMatchingResult` 成功后并行或串行拉 fusion GET；失败时 **整条条目隐藏或一行降级**，不打断主结果与下方三层能力。

---

## 6. 本轮明确不做什么

- 不新增路由页面、不改 `worker`、不写任何 **AI 结果表** 或缓存表。  
- 不在本 GET 内 **默认串联** P6.x / P6.y **大模型**（v0 以规则快照为准；后续子阶段再谈「可选一次 LLM 润色 headline」）。  
- 不把 `matchInsights` 全文、P6.x strengths/risks 长列表、P6.y 四轴长文案 **搬进** fusion 主文。  
- 不强制用户先触发 `POST /match-review-ai/review` 或 `GET …/interaction-simulation-lite/...`。  
- 不把 fusion 做成 **第四个大卡片报告**（禁止与「AI 匹配复审」「互动预判」同量级标题 + 长正文并列）。  
- 不修改 P6.x「仅 latest + POST」、P6.y「按 matchResultId + GET」的既有对外契约（fusion 仅新增 GET）。  
- 不在 v0 追求三源 **数学一致** 或自动「纠正」worker 分。

## 7. 最小测试建议（只列项，不编码）

1. **纯函数单测**：给定固定的 `(finalScore, recommendation, verdict[, continuationBand])` 三元组表，断言 `headlineZh` / `bulletsZh` 长度上限、`tensionZh` 仅在触发条件出现。  
2. **优先级单测**：任一 `down` + 他源非全 `down` → 总立场偏保守；三 `up` → 积极 headline。  
3. **GET 鉴权**：非 `MatchResult.userId` 的 JWT → **403**；不存在 id → **404**。  
4. **GET 画像缺失**：与 interaction lite 一致路径 mock → **404**（或约定文案）。  
5. **与 POST 无关**：不调用 `postMatchReviewAi`、不依赖前端 state，仅调 fusion GET 仍得稳定 body。  
6. **可选快照测试**：对 1～2 组「全一致」「系统高 + 双保守」fixture 做 golden string（短文案表稳定后）。  
7. **前端冒烟**：有 `matchResultId` 的 Final Match 首屏在 fusion 成功时出现读数条，且不挤压下方三块主能力入口。
