# P6.4：Copilot 运行稳定性收口

> **Status: Done（第一轮：文档 + 日志字段对齐，见 `P6.2-copilot-llm-runbook.md` §9 起）**

**P6.4** 是 **运行稳定性与可维护性收口**，不是新一轮 AI 功能开发。在 **不扩展 P6 能力边界** 的前提下，把已落地的「真实 AI Copilot（只读，失败可回退）」在 **运行、排障、配置、观测** 上收齐口径。

**明确不包含**：summary AI 化、matching / explanation AI 化、Worker / 队列 / 异步、multi-agent、simulation；**不** 改数据库 / Prisma；**不** 引入新业务能力。

**前置**：P6-MVP 已定义；P6.1 已实现；P6.2 已收口；P6.3 首轮验收已通过（见同目录下各文档）。

---

## 1. 目标

在 **不增加新 AI 能力、不改数据层** 的前提下，使 Copilot 模型路径在联调与运行环境中 **稳定可解释、问题可复现、回退可核对**。

1. **日志可排障**：`copilot_ai` 相关结构化日志 **字段集合固定、语义写清**（含 `outcome`、`reason`、耗时、可选 `slug`/非敏感配置摘要），便于检索与后续告警对接（不要求在本阶段上完整监控平台）。
2. **Fallback 可解释**：**失败原因枚举** 与 **用户/运维排查路径** 在文档中 **一一对应**（与 `CopilotChatCompletionsClient` / `CopilotService` 中已有分类对齐）。
3. **配置可维护**：`.env.example` 与 runbook **补全边界说明**（如 `AI_PROVIDER` 与 host 推断、`openai_compatible` 含义、DeepSeek 与官方 OpenAI 对照）。
4. **运行说明最小补全**：在 **现有** `docs/P6/P6.2-copilot-llm-runbook.md` 上 **增量**「稳定性」相关小节（例如：当前无自动重试的说明、误配清单），**不** 另起大部头手册。
5. **可选极轻 UI**：仅在 **已有** `CopilotInsightCard` 上对 **文案或可访问性** 做 **必要时** 的微调，与文档口径一致；**不** 新页面、**不** 重做样式。

---

## 2. 明确不做什么

- **不** 扩展：summary、matching / explanation、Worker、multi-agent、simulation。
- **不** 新增业务接口；**不** 改变 `GET /copilot/conversations/:conversationId/insights` 的路径、鉴权与 **主响应 JSON 形状**（允许仅日志侧增强，属实施阶段约定）。
- **不** 改 Prisma / 数据库；**不** Copilot 洞察落库；**不** 新表。
- **不** 将 P6.4 做成「更聪明的建议」「新 prompt 策略」「多模型路由」等产品功能。
- **不** 大改 README 结构（若未来仅增加一行指向 `docs/P6/` 的链接，须单独评估，**默认不在 P6.4 范围**）。
- **不** 在日志中输出密钥、完整 prompt 或完整消息正文（延续最小数据暴露原则）。

---

## 3. 为什么是当前最合理的下一步

- P6.1～P6.3 已验证 **成功路径、fallback、前端与主链路隔离**；下一步自然不是「再接一个 AI」，而是 **运维与稳定性口径** 的收口。
- 代码侧已有结构化日志与 failure kind，**与文档的字典对齐** 成本低、风险可控，且 **不扩大** `docs/P6/P6-ai-production-evolution-plan.md` 所述全量生产链承诺。
- 实际接入多为 **OpenAI 兼容 + 指定厂商（如 DeepSeek）**，配置与 `sourceType` 语义需在 **运行侧** 持续可读，P6.4 负责 **固化** 而非 **扩张**。
