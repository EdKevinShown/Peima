## 5. 最小提示规则

### 5.1 事前（按钮禁用 + 单行说明）

仅当依据 **当前页 messages** 与 **`mine` 已返回列表**可判断时生效；**同一时间只展示一个**禁用原因，**优先级固定**为：

1. **消息不足**：参与推导的「消息切片」条数 **&lt; 6**（与 P6.9 切片口径对齐：总会话条数 ≤ 默认窗口时等于总会话条数，否则等于窗口上限条数）。
2. **已有 pending**：列表中存在 **`status = pending`** 且 **`sourceVersion = p6.8-profile-completion-ai-v1`** 的建议。
3. **冷却中**：列表中存在上述 `sourceVersion` 的条目，且据 **`createdAt` 最近一条**（任意状态）距当前 **&lt; 1 小时**。若 **`mine` 分页/条数上限**导致最近一条 P6.8 记录**未出现在当前列表中**，则**不**强行事前禁用，改由用户触发 POST 后依赖 **429** 与事后文案（本轮**不**为冷却单独加接口）。

### 5.2 事后（`postProfileCompletionSuggestion` 固定映射）

与事前口径对齐的**统一中文**（**不**替代 422 / 5xx 等其它错误的详情展示）：

| HTTP | 用户可见文案（固定） |
|------|----------------------|
| **400** | 当前会话用于生成的消息不足 6 条 |
| **409** | 已有一条待处理的画像补全建议 |
| **429** | 当前画像补全建议仍在冷却时间内 |

## 6. 与 P6.9 的关系

- P6.9 定义 **何时**拦截与 **HTTP 状态码**；P6.10 **不**改变上述语义，仅在 Web 侧**预演**可推导的拦截条件，并对 **400 / 409 / 429** 做**展示层**统一文案。
- 事前条数、pending 判定、`sourceVersion` 与冷却时长与后端治理**一致**；若前后端数据视图不一致（例如 `mine` 未包含用于冷却的最近一条），以 **POST 实际返回**为准。
