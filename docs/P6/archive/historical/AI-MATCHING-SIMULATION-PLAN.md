## 概括（3 分钟看懂）

这份方案想做的事情很简单：**先用便宜的方法从很多人里挑出最可能合适的配对，再把贵的 AI 对话预算用在这些配对上，最后给出有依据的结论**。

可以把它理解成 3 步：

1. **先大范围筛人（不跑大模型）**  
   我们先用用户问卷里的 20 维特征做“维度函数化兼容打分”，把明显不合适的对先去掉，再留下一个“更可能合适”的候选池。  
   这一步的目标是：快、便宜、别漏掉好对。

2. **再让 AI 分层模拟对话（由浅到深）**  
   不会一上来就让每一对聊很多轮，而是分三层：  
   - 第一层看有没有聊天感觉  
   - 第二层看出现小摩擦时能不能接得住  
   - 第三层看价值观和长期相处是否能落地  
   每一层都会淘汰一部分，只让更有希望的对进入下一层。

3. **最后按统一规则打分和排序**  
   重点看几件事：是否双向投入、聊得顺不顺、遇到分歧能不能修复、价值观是否一致、是否尊重边界、现实中能不能走下去。  
   如果出现硬冲突（例如严重边界问题），会被直接压分或淘汰。

---

### 为什么这套方案靠谱

- **成本可控**：不是所有人两两都跑 AI，对话预算集中用在最有希望的配对上。  
- **结果可解释**：每句对话都要有依据（来自维度/标签/场景），不是模型随便发挥。  
- **能复盘能调优**：每次为什么晋级、为什么淘汰、为什么高分，都能查到证据。  
- **可逐步迭代**：先把主流程跑通，再慢慢优化细节和权重。

---

### 这份文档里你会看到什么

- 阶段 A/B：怎么做快速筛选，选出最有可能的配对  
- 阶段 C：怎么做分层 AI 模拟对话  
- Evaluator：怎么根据对话判断“合不合适”  
- 可解释性协议：怎么保证“每句话有依据，结论可审计”

如果只记一句话：**先快筛，再深聊，最后给出有证据的匹配结论。**

本文档描述一条 **「问卷输出 → 矩阵快速筛选 → 双人契合度倒序列表 → Ditto 式循序渐进模拟漏斗」** 的产品与技术路线，并给出 **P0 可落地的默认参数**（漏斗层级、每轮对话量、AI 协同、批次调用预算）。**阶段 C 默认 `funnel-v2`**：在矩阵筛后的头部对上，用**明显更多的逐层对话轮数**，尽量支撑「两人是否**真的合适**」的模拟判断（仍非现实约会替代，见 **1.2**）。与现有问卷画像模块对齐时，特征来源见 `QUESTIONNAIRE-PROFILE-ALGORITHM.md` 与 `UserProfile` G1-R 字段。

## 1. 目标与非目标

### 1.1 目标

- **快速**：大池子下避免「所有人两两都跑大模型」（复杂度约 **N×N** 条边爆炸）。
- **可排序**：产出 **按契合度从高到低** 的「候选配对」列表（倒序 = 最高分在前）。
- **可解释**：模拟阶段产出「相处片段 + 摩擦点 + 匹配结论」类结构化结果，便于 UI 与复盘。
- **对话量足以支撑判断**：在晋级深层的对上，通过 **L1→L2→L3** 足够多的「双方各一句」轮次（默认 **`funnel-v2`**，见 **6.5**），让价值观、摩擦修复、节奏等信号有时间展开，而不是仅靠极少轮次下结论。
- **可迭代**：矩阵权重、场景脚本、轮次、模型角色数均可版本化（`schemaVersion` / `simulationVersion`）。

### 1.2 非目标（P0 不做）

- 不做法律/婚恋承诺级结论；输出为 **模拟与建议**，需产品免责声明。
- 不替代现有 `batch-match` 规则分（可并行存在，后续再融合）。

## 4. 阶段 A：硬过滤与函数打分

### 4.1 硬过滤（非 AI）

按产品规则缩小合法配对集合 **E**（示例维度，可按你们数据改）：

- 基础：非本人、非已匹配/黑名单、账号状态可用。
- 业务：地理、年龄差、取向/匹配对象偏好等（若有字段）。

输出：每位用户 **可行邻居集合** `N(i)`（所有能和用户 i 配的用户 j 的集合）。

### 4.2 P0 执行主线：函数化兼容矩阵（上三角形式）`X = TComp`

P0 快筛统一使用 **函数化兼容矩阵（上三角形式）** `TComp`。对任意两位用户 `i,j`：

```
X[i][j] = TComp(i,j)
```

其中 `TComp(i,j)` 由：

1. **上三角函数项**（`a<b` 的维度对函数）  
2. **置信门控**（`min(c_i,c_j)`）

组合得到，详见 **5.4.3、5.4.8、5.4.9**。

---

### 4.3 参数汇总（执行）

- 缺失维填 **0.5**  
- 无向对分数：`(X[i][j] + X[j][i]) / 2`  
- 当前缩边：函数化兼容分 Top-K（上三角形式，`K_top=200`）+ 全局配对  
- 模拟输入：**20 维 float + confidence + 标签摘要**  
- 维度间交互：上三角 `W_ab` 默认全 0（保留实现位）

**`matrixVersion`（快筛用）**：固定 **`function-compat-tri-v1`（`X=TComp`）**。

---

### 4.4 原始特征矩阵 **F**（n × 20）

设池子里有 **n** 个用户，按固定顺序编号 `i = 0 .. n-1`（顺序可为 `userId` 字典序或 `updatedAt`，**整次批处理内不变**）。

1. 从 `UserProfile` 取 G1-R 二十轴，与代码中 `G1R_PROFILE_KEYS` 顺序一致（共 20 列）。
2. 构造矩阵 **F**，形状 **n 行 × 20 列**：

```
F[i][d] =  数据库中用户 i 的第 d 个轴的 float 值   若不为 null
F[i][d] =  0.5                                   若为 null
```

3. **全 null 极端行**（理论上极少）：若某行 20 维全是 null（填完后全 0.5），则 L2 范数为 `sqrt(20 * 0.5^2) > 0`，仍可归一化；若业务上存在「全轴无数据」用户，**在硬过滤阶段剔除**，不进入矩阵。

---

### 4.5 函数化兼容矩阵（上三角形式）`TComp`（n × n）

P0 快筛分统一由上三角函数决定。对任意用户对 `(i,j)`：

```
u_d(i,j) = f_d(x_id, x_jd)
S_tri(i,j) = sum_{1<=a<b<=20} W_ab * phi_ab( u_a(i,j), u_b(i,j) )
TComp(i,j) = clamp(S_tri, 0, 1) * min(c_i, c_j)
```

其中：

- `W_ab` 为上三角交互权重，默认全 0（保留实现位）
- `f_d` 为维度基础 function，`phi_ab` 为上三角组合函数
- `TComp(i,j)` 对称，可直接作为阶段 B 的输入边权

---

## 5. 阶段 B：候选缩边与全局配对

### 5.1 为什么不全量 N×N 模拟

- 大模型成本与延迟随边数爆炸；矩阵阶段应 **纯数值/矩阵运算**（CPU/GPU 均可，易批处理）。

### 5.2 执行算法：硬过滤 + Top-K 稀疏化 + 无向对分数 + 全局排序

以下用 **对对矩阵 `X=TComp`**（见 **4.2/4.5**）。记 **硬过滤**：`allowed(i, j)` 为真当且仅当用户 **j** 属于 **i** 的可行邻居集 `N(i)`，且 **i** 属于 `N(j)`（无向合法）；并排除 `i == j`。

#### 术语：有向分、无向对、无向分（`matrixScore`）

- **有向边 / 有向分**：**Top-K** 步骤里出现的是 **(i → j)** 有向边；边上的分 **`score_ij = X[i][j]`** 可理解为「在矩阵里 **i 与 j** 这一条**有序索引**上的值」。**`X` 对称时** **`X[i][j] = X[j][i]`**，数值与箭头方向无关，但**构图**上仍区分 **i→j** 与 **j→i**（两人各自提名自己的 Top-K）。
- **无向对**：无序对 **`{A,B}`** 在实现里规范成 **`a = min(A,B), b = max(A,B)`**；把多人产生的有向边并集时，**`(i,j)` 与 `(j,i)` 合并为同一无向对**，避免重复进入排序列表。
- **无向分**：对无向对 **`(a,b)`** 定义的 **`matrixScore(a,b) = (X[a][b] + X[b][a]) / 2`**。当前 `X=TComp` 为对称矩阵，因此 **`matrixScore(a,b) = X[a][b]`**，与把谁写在左边无关，**`L` 中排序用的就是这个无向分**。若将来使用非对称 `X`，仍保留该平均式或改用业务规定的对称化 `sym(i,j)`，并在 `matrixVersion` 子版本里写清。

#### 步骤 1：每人保留 Top-K 条有向候选边（K=32）

对每个用户 **i**：

1. 构造候选集合 `C_i = { j | j != i 且 allowed(i,j) }`。
2. 对 `C_i` 中每个 **j**，查矩阵元素 **score_ij = X[i][j]**（`X` 对称，故 **`X[j][i] = X[i][j]`**）。
3. 将 `C_i` 按 **score_ij 从高到低** 排序，只保留前 **K=32** 个 **j**，得到有向边集合：  
   `E_i = { (i, j_1), (i, j_2), ..., (i, j_K) }`（若候选不足 K，则全保留）。

#### 步骤 2：合并所有用户的 Top-K 边，得到无向候选对集合

初始化空集合 **P**（元素为无向对）。

对每个用户 **i**，对 `E_i` 中每条有向边 **(i, j)**：

- 令 **a = min(i, j)**，`b = max(i, j)`，把无向对 **(a, b)** 插入 **P**（用集合或哈希去重，避免重复插入）。

**直觉**：只要 **i** 把 **j** 放进自己的 Top-K，或 **j** 把 **i** 放进自己的 Top-K，该对就会进入 **P**（并集，不是必须双向都在对方 Top-K）。

#### 步骤 3：无向对的最终矩阵分（取平均）= **无向分**

对 **P** 中每个无向对 **(a, b)**（`a < b`）：

```
matrixScore(a, b) = ( X[a][b] + X[b][a] ) / 2
```

**注**：**`matrixScore` 即上文定义的「无向分」**。**`X` 对称**时 **`X[a][b] == X[b][a]`**，上式等于 **`X[a][b]`**。仍写平均是为了与「未来若改为非对称 `X`」兼容。

#### 步骤 4：全局倒序排序（所有进入 P 的对）

将 **P** 中所有无序对按 **matrixScore 从高到低** 排序：

- 若分数相同，固定使用二级键 **`(userId_a, userId_b)` 字典序** 打破平局，保证排序稳定、可复现。

输出列表 **`L`**：`[ (a, b, matrixScore), ... ]`，**第一名 = 在集合 P 内矩阵意义下最契合的一对**。

**与「全员两两全排序」的关系（重要）**  
每人只保留 **Top-K**，因此 **`L` 排序的是稀疏并集 `P` 里的对**，不是全池 **N×(N-1)/2** 条边。若业务明确要求 **全量两两榜单**：把步骤 1 改为「对每个 **i**，取 **C_i 全部邻居**（等价 **K = n-1** 或取消 Top-K）」，步骤 2–4 不变，即可对 **所有 allowed 无向对** 用同一 **matrixScore** 排序。

#### 步骤 5：与阶段 C（模拟）的衔接（M=200）

只对 **`L` 中前 M=200 条** 无向对进入 L1。  
**P0 主链路执行口径**见 **5.4**：先最大权匹配得到 `PairSet`，再取 `PairSet` 前 M=200 对进入 L1。

#### 复杂度（便于实现选型）

- 构造 **F** 与 **`X=TComp`**：朴素按每对上三角维度对计算，约 **O(n^2 * C(20,2))**；`n` 很大时可先召回缩池，再对候选边算分。
- Top-K 每用户：O(度 log 度) 或 O(n log n) 若每用户扫全体邻居。
- 排序 **|P|** 条：`|P| <= n*K` 量级（常数因子），**O(n K log(nK))**。

### 5.2.1 召回与 Top-K 的关系（执行说明）

#### 与 **Top-K（步骤 1）** 的关系

- Top-K 是“每人先取局部最优候选”的降本机制，与最终 pair 排序配合使用。  
- 当前执行口径下，候选缩边使用 `edgeScore` 直接取 Top-K；最终得分仍按 `TComp` 在候选边上计算。  
- 当规模较大时，先 ANN 召回再函数打分，是主链路默认做法。

互补/风险/双高双低等语义统一在上三角函数 `phi_ab(...)` 中表达，不依赖召回阶段的距离定义。

### 5.3 列表条目结构（执行结构）

每条至少包含：

- `userA`, `userB`
- `matrixScore`（P0 默认来自 **`X=TComp`**；见 **5.4.3 / 5.4.9**）
- `matrixVersion`（P0 固定写 **`function-compat-tri-v1`**）
- `hardFilterPassReason`（调试字段）

### 5.4 对话模拟前的大规模筛选（执行口径）

为贴近 Ditto 式「先大规模缩池，再把深度模拟预算打在最可能配对上」的目标，阶段 B 在阶段 A 的打分结果上执行候选缩边与全局配对。该段与 **4.2** 的统一记号 `X` 兼容，且不改变阶段 C 的漏斗结构。

#### 5.4.1 三段式流程（先缩边、再精排、后成对）

```
合法用户池 U
  → 硬过滤（4.1）得到 allowed(i,j)
  → 候选缩边（5.4.2）得到 C(i)
  → 对称精排（5.4.3）得到 pairScore(i,j)
  → 全局配对（5.4.4）得到 PairSet
  → 按 pairScore 倒序取 Top M 进入阶段 C
```

#### 5.4.2 候选缩边：函数分 + 上三角直接 Top-K（执行）

在 `allowed(i,j)` 约束内，直接用主评分函数计算候选分并缩边，不再走“先余弦召回再重排”。

对每个用户 `i`：

1. 对所有合法 `j in N(i)` 计算：

```
edgeScore(i,j) = TComp(i,j)
```

2. 按 `edgeScore(i,j)` 倒序取前 `K_top`，得到：

```
TopK(i),  K_top 默认 200
```

3. 定义候选集合：

```
C(i) = TopK(i)
```

实现要点：

- 分数定义与主链路一致，避免“召回分数与精排分数不一致”；
- 若在线池过大，可先用 ANN 生成粗候选 `K0`，再在 `K0` 上计算 `edgeScore` 取 `K_top`；
- `edgeScore` 要求对称（或在入图前做对称化）以便后续 Blossom 直接使用。

#### 5.4.3 对称精排分：上三角函数兼容主干（P0）

P0 不使用单向分作为最终 pair 分，统一采用单向分对称化后的无向 pair 分：

```
s_ij = score(i→j)
s_ji = score(j→i)
pairBase(i,j) = (s_ij + s_ji) / 2
pairScore(i,j) = pairBase(i,j) * min(c_i, c_j)
```

其中 `score(i→j)` 在 P0 统一为 **上三角函数兼容分**（归一到 0～1）：

```
score(i→j) = TComp(i,j)
```

其中：

```
u_d(i,j) = f_d(x_id, x_jd)
S_tri(i,j) = sum_{1 <= a < b <= 20} W_ab * phi_ab( u_a(i,j), u_b(i,j) )
TComp(i,j) = clamp(S_tri(i,j), 0, 1) * min(c_i, c_j)
```

默认约束：

- `W_ab = 0`（仅保留上三角实现位）
- 每个维度先选 `f_d`，再为维度对选择 `phi_ab`（见 5.4.9）

#### 5.4.4 从“候选边列表”到“最终几对”：最大权匹配

本批最终配对统一在候选边图上执行 **最大权匹配**（max-weight matching）：

- 点：用户
- 边：`(i,j)`，边权 `pairScore(i,j)`
- 约束：每个用户在一个批次中最多被分到 1 对

得到 `PairSet` 后按 `pairScore` 倒序，即可直接产出全局 Top 对；再截断前 **M** 对进入阶段 C。

“每人 Top-K 候选页”作为调试/分析视图并行产出；批次最终配对只以最大权匹配结果为准，避免热门用户被重复占用。

#### 5.4.5 默认参数（执行）

| 参数 | 默认值 | 备注 |
|------|--------|------|
| `K_top` | **200** | 每人保留的函数分 Top-K 候选数 |
| `M` | **200** | 进入阶段 C 的 pair 数（与 5.2 / 6.4 对齐） |
| 评分参数 | `W_ab=0` | 上三角交互项默认关闭 |

#### 5.4.8 上三角函数（执行）

在本方案中，上三角是唯一主打分。先对每个维度计算基础函数分，再在上三角里做组合：

```
u_d(i,j) = f_d(x_id, x_jd)
S_tri(i,j) = sum_{1 <= a < b <= 20} W_ab * phi_ab(u_a, u_b)
TComp(i,j) = clamp(S_tri(i,j), 0, 1) * min(c_i, c_j)
```

其中：

- `W_ab` 仅存上三角（`a < b`），避免重复参数；
- `f_d` 为维度基础 function（例如 `similar`），先单独定义再进入上三角；
- `phi_ab` 为上三角组合函数，V1 默认可取 `phi_ab(u_a,u_b) = u_a * u_b`；
- 所有 `W_ab` 默认 **0**（只保留实现位，不影响当前分数）。

后续可按证据逐步开启少量 `W_ab`（例如 `controlNeed × independence`），并要求每次开启都有离线回放与回归记录。

### 5.4.9 仅上三角函数兼容（执行配置）

P0 不再使用单维兼容函数主项，匹配分完全由上三角函数决定。

#### A) 维度集合定义

- `D_inter`：允许进入上三角交互项的维度（默认 20 维全量）

#### B) 上三角函数主式

对任意用户对 `(i,j)`：

```
u_d(i,j) = f_d(x_id, x_jd)
S_tri(i,j) = sum_{a<b, a,b in D_inter} W_ab * phi_ab( u_a(i,j), u_b(i,j) )
TComp(i,j) = clamp(S_tri(i,j), 0, 1) * min(c_i, c_j)
```

并将 `TComp` 作为 **5.4.3** 中 `score(i→j)` 的主输入。

#### C) 维度基础 function（单独定义，放入上三角使用）

这些 function 先按维度计算 `u_d`，再进入上三角组合。每个函数都输出 `[0,1]`。

1) `similar`（越接近越好）  
含义：两个人在该维度越接近，得分越高。

```
f_similar(x,y) = 1 - abs(x-y)
```

2) `complement`（互补更好）  
含义：该维度一高一低更有利。

```
f_complement(x,y) = abs(x-y)
```

3) `both_high`（双高更好）  
含义：两人都高时加分明显。

```
f_both_high(x,y) = min(x,y)
```

4) `both_low_penalty`（双低惩罚）  
含义：两人都低时扣分，避免“双低风险”。

```
f_both_low_penalty(x,y; alpha) = 1 - alpha * min(1-x, 1-y), alpha in [0,1]
```

5) `distance_band`（容忍带）  
含义：小差异可接受，超过阈值后快速降分。

```
f_distance_band(x,y; t1,t2) =
  1                         , if abs(x-y) <= t1
  (t2-abs(x-y))/(t2-t1)     , if t1 < abs(x-y) < t2
  0                         , if abs(x-y) >= t2
```

6) `custom`（白名单表达式）  
含义：用于业务自定义函数，必须可审计。

```
f_custom = expr(x,y,abs,min,max,clamp,+,-,*,/)
```

#### D) 上三角组合函数模板（执行公式）

1) `tri_diff_product`（默认）

```
phi_ab(u_a, u_b) = u_a * u_b
```

2) `tri_signed`

```
phi_ab(u_a, u_b) = (2*u_a - 1) * (2*u_b - 1)
```

3) `tri_min_gap`

```
phi_ab(u_a, u_b) = min(u_a, u_b)
```

4) `tri_max_gap`

```
phi_ab(u_a, u_b) = max(u_a, u_b)
```

5) `tri_soft_band`

```
phi_ab(u_a, u_b) = exp( -((u_a-m_a)^2 + (u_b-m_b)^2) / (2*s^2) )
```

6) `tri_custom`（白名单表达式）

```
phi_ab = expr(u_a, u_b, min, max, clamp, +, -, *, /)
```

执行约束：`W_ab` 默认全 0；任意开启/修改都需离线回放与回归记录。`f_d` 与 `phi_ab` 都必须版本化留痕。

#### F) 缺失与兜底规则

- 任一维度缺失先填 0.5；  
- 若用户有效维度占比低于阈值（例如 < 30%），该用户不进入主池；  
- 任一侧 `confidence < 0.2` 时，该 pair 不进入 `PairSet`（硬过滤补充规则）。

### 5.6 测试与验收（执行）

当前版本只做 5 类测试，全部通过后方可进入灰度：

1. **合法性测试**  
   - 目标：`PairSet` 中不存在违反硬过滤规则的 pair。  
   - 验收：非法 pair 数量必须为 0。

2. **对称性测试**  
   - 目标：对任意 pair，`pairScore(i,j) == pairScore(j,i)`（容差内）。  
   - 验收：随机抽样与全量离线检查均通过。

3. **唯一性测试（匹配约束）**  
   - 目标：最大权匹配后每个用户在同一批次最多出现一次。  
   - 验收：任意用户重复配对次数必须为 0。

4. **稳定性测试（可复现）**  
   - 目标：同一输入重复运行，输出顺序与结果一致。  
   - 验收：固定随机种子与 tie-break 下，结果哈希一致。

5. **性能测试（规模压测）**  
   - 目标：在目标用户规模下，批处理时延与内存可控。  
   - 验收：达到预设 SLA（由环境容量表定义），且无异常中断。

#### 5.6.3 上线前检查清单（必须通过）

1. **对称性与稳定性**

### 5.7 三维度完整演示（可直接手算与联调）

本例仅用于开发演示，展示“函数化兼容矩阵（上三角形式）+ 对称精排”的完整计算链路。

#### 5.7.1 维度与输入

用 3 个维度（先算 `f_d`，再进上三角）：

- `d1 = conflictHandling`
- `d2 = controlNeed`
- `d3 = emotionalExpression`

基础函数选择（示例）：

- `f_d1 = similar`
- `f_d2 = both_low_penalty(alpha=1.0)`
- `f_d3 = similar`

两位用户：

```
User A: d1=0.80, d2=0.70, d3=0.20, confidence=0.90
User B: d1=0.60, d2=0.90, d3=0.40, confidence=0.80
```

#### 5.7.2 上三角分 `S_tri`

定义上三角权重与组合函数（示例）：

```
W_12 = 0.40
W_13 = 0.30
W_23 = 0.30
phi_ab(u_a,u_b) = u_a * u_b
```

先算单维基础分：

```
u_1 = 1-|0.80-0.60| = 0.80
u_2 = 1-1.0*min(1-0.70,1-0.90) = 0.90
u_3 = 1-|0.20-0.40| = 0.80
```

上三角主分：

```
S_tri = 0.40*(0.80*0.90) + 0.30*(0.80*0.80) + 0.30*(0.90*0.80)
      = 0.704
```

门控后：

```
TComp = clamp(0.704, 0, 1) * min(0.90, 0.80)
      = 0.5632
```

#### 5.7.3 对称精排与最终 pair 分

演示里设 `s_ij = s_ji = TComp = 0.5632`（对称输入）：

```
pairBase = (s_ij + s_ji)/2 = 0.5632
pairScore = pairBase = 0.5632
```

## 6. 阶段 C：Ditto 式循序渐进模拟漏斗（`simulationVersion = funnel-v2`，P0 默认）

本节采用 **由浅入深的漏斗**：越往后样本越少、单对成本越高，整体更接近 Ditto「先 vibe、再对话、再价值观与场景」的路径。产品上希望在**晋级到深层的对上**积累**足够多的对话轮次**，再综合 **Evaluator** 输出判断「是否真合适」，因此 **P0 固定采用 `funnel-v2`**（每层轮数见 **6.5**）。P0 的筛选执行口径见 **5.4**（`X=TComp` + 函数化兼容分 Top-K 缩边（上三角形式） + 对称精排 + 最大权匹配）；人设输入与解释输入按 **2.2** 执行（20 维 + confidence + 标签摘要）。

### 6.1 与参考架构的对应关系

| Ditto 概念 | 本方案落点 |
|------------|------------|
| Building Persona | 问卷写库 + 20维/置信度/标签摘要的人设约束（不做照片吸引力分析，可 P1） |
| Pre-Date / Pool | 快筛矩阵 **`X=TComp`** + 函数化兼容分 Top-K 缩边（上三角形式） + 对称精排 + 最大权匹配，取 Top **M** 进入漏斗 |
| Date Simulations（渐进） | **`funnel-v2`**：**L1 → L2 → L3**，逐层淘汰；默认 **5 / 7 / 12** 轮/层（**6.5**） |
| Rank & Approve | **L3 结束后**按终评排序，产出短名单 |
| Date Planning | **P1**：邀约话术/日程草案（本 P0 不写死实现） |
| Memorize + Iterate | **P1**：反馈回写画像或权重（本 P0 仅占位） |

### 6.2 触发范围（入口规模）

- 对 **`PairSet` 前 M=200** 对 **全部跑 L1**（相对 L2/L3 仍偏浅，但 **`funnel-v2`** 下 L1 已有 **5** 轮对话，非极简）。  
- **L2 / L3** 仅对 **6.4 节**筛选后的子集继续；未晋级对持久化 **L1 分数与摘要** 即可。

### 6.3 漏斗总览（数据流）

```
PairSet（pairScore 倒序）
    │ 取 Top M=200
    ▼
┌───────────────────────────────────────┐
│ L1 第一印象 + Vibe（默认 funnel-v2）   │  每对 5 轮对话 + 1 次关卡评估
└───────────────────┬───────────────────┘
                    │ 保留前 M1=120（按 L1 分数）
                    ▼
┌───────────────────────────────────────┐

└───────────────────┬───────────────────┘
                    │ 保留前 M2=60
                    ▼
┌───────────────────────────────────────┐
```

### 6.4 晋级规则（执行口径：按分层分数截断 + 固定地板）

对每一层结束时的评分 **`stageScore`**（由该层 **Evaluator** 输出，范围固定 **[0,1]**）：

| 边界 | 默认值 | 规则 |
|------|--------|------|
| 进入 L1 的对数 | **M = 200** | 即 **PairSet** 前 200 条 |
| L1 → L2 | **M1 = 120** | 跑完 L1 后：先剔除 **`stageScore_L1 < 0.45`** 的对（**地板**，默认 **开启**）；在剩余对中按 **`stageScore_L1` 从高到低** 取前 **120** 进入 L2；若剩余不足 120，则 **有多少进多少**。 |
| L2 → L3 | **M2 = 60** | 跑完 L2 后：先剔除 **`stageScore_L2 < 0.50`** 的对（地板固定开启）；在剩余对中按 **`stageScore_L2`** 从高到低取前 **60** 进入 L3；若剩余不足 60，则有多少进多少。 |
| L3 结束短名单 | **M3 = 30** | 跑完 L3 后，按 **`finalScore`（终评）** 倒序取前 **30** 对作为 **Rank 输出**（产品可再人工 approve）。 |

**淘汰率目标（非硬约束，仅验收参考）**：L1 末约 **40%** 出局；L2 末约 **50%** 在晋级者中再出局；L3 全跑完再截 **Top30**。

### 6.5 各层「场景」定义（`funnel-v2`，P0 默认）

**约定**：每层内 **1 轮 = 双方各 1 句**；每层 **每轮 1 次 LLM 调用** 同时生成 A/B 两句（与旧版 6.x 一致，便于解析 JSON）。

| 层 | 主题（对齐 Ditto 渐进） | 每对 **对话轮数** | 该层结束 **Evaluator 次数** |
|----|-------------------------|-------------------|-----------------------------|
| **L1** | **First Impression + Vibe**：初见、氛围、是否愿意继续聊 | **R_L1 = 5**（共 10 条消息） | **1**（输出 `stageScore_L1`、redFlags 计数、晋级信号） |
| **L2** | **Conversation Flow + 轻摩擦**：日程冲突/误解类小摩擦，看修复与节奏 | **R_L2 = 7**（共 14 条消息） | **1**（`stageScore_L2`） |
| **L3** | **Shared Values + Scene**：金钱/家庭/边界/中长期取向；可多节拍推进 + 场景收尾 | **R_L3 = 12**（共 24 条消息） | **1**（`finalScore` + `greenFlags` / `redFlags` / `recommendedNextStep`） |

**`funnel-v2` 设计意图**：在仍保持「浅→深」漏斗与 **M / M1 / M2** 截断的前提下，确保打满三层时有足够对话轮数，让节奏、摩擦修复、价值观与场景线索有时间展开，从而更接近「判断两人**是否真的合适**」所需的信息量；**并非**宣称已等价真人长期相处。

三层合计（打满 **L1→L2→L3**）：**5 + 7 + 12 = 24** 轮生成 + **3** 次评估 = **27 次 LLM 调用 / 对**。大量对仍会在 L1/L2 提前结束，仅晋级深层的对承担更高轮次。

**批次粗算（`funnel-v2`，默认 M / M1 / M2 / M3 不变）**

- L1：`200 × (5 + 1) = 1200` 次调用  
- L2：`120 × (7 + 1) = 960` 次  
- L3：`60 × (12 + 1) = 780` 次  
- **合计约 2940 次 / 批**（仍低于「200 对整批打满 **27** 次」的 **`200×27=5400`**，因漏斗淘汰。）

### 6.5.1 为何不采用「每阶段约 50 轮」这类极深对话

若指 **L1、L2、L3 每一层都对同一对跑满约 50 轮**（仍按本文「1 轮 = 双方各 1 句、每轮 1 次生成调用」），在 **当前批量漏斗（M=200 进 L1、再截断到 M1/M2）** 的前提下，**一般不作为 P0 现实默认**，原因如下。

1. **调用量与成本**  
   - 仅 **L1**：**`200 × (50 + 1) = 10200`** 次生成+评估量级，已约为 **`funnel-v2` 整批（约 2940）** 的 **3 倍以上**，而 L1 仍是入口最广的一层。  
   - 若三层各 **50** 轮且大量对打满，整批调用会再上一个数量级；与「矩阵先筛、模拟只做头部」的**成本控制**目标冲突。

2. **边际收益递减**  
   - 无新场景节拍、无新评估维度时，轮数堆到几十轮以后，模型容易**重复套路**，对「是否真合适」的**额外可区分信号**往往变弱；更划算的是 **少而结构化**的推进（明确冲突点、修复尝试、价值观切口），而不是同一层内线性堆轮数。

3. **上下文与工程**  
   - 轮数极高时，完整 transcript 会逼近或超过常见模型的**上下文窗口**，必须引入**摘要再注入、滑动窗口、分层记忆**等机制，否则后期轮次质量下降；这已超出「只加 R」的轻量改动，应单独版本化（例如 `simulationVersion` 子版本 + 专用记忆管线）。

4. **若产品仍要「极深」**  
   - 更现实的路径是：**只对极少数终局候选**（例如已进 **L3** 且 **`finalScore` 靠前**的 **Top N**）再开「加深包」或第二模拟版本，而不是对 **200 进 L1** 的每一对都做 **50** 轮。

**结论**：「每阶段 **50** 轮」不是数学上不可能，但在**批量匹配 + 漏斗截断**的产品形态下，**默认不现实**；当前 **`funnel-v2`（5 / 7 / 12）** 是在「更深对话」与「整批可承受」之间的折中。若商业上确认要为 **Top N** 买「极深单对模拟」，宜单独定价、单独版本与单独容量规划，不宜与 **M=200** 的 L1 入口绑死。

### 6.6 AI 协同（每层不变）

每层仍采用 **逻辑 3+1**：

| 角色 | 职责 |
|------|------|
| **Facilitator** | 场景设定、回合推进 |
| **Persona-A / Persona-B** | 严格按问卷特征（20 维 + confidence + 标签摘要）发言（可合并为单次结构化输出） |
| **Evaluator** | 该层结束打分 + 晋级信号（结构化 JSON） |

**工程默认**：同一 LLM **串行**多轮（成本低、易审计）；与旧版说明一致。

### 6.7 持久化输出（执行 schema）

对无向对 **(A,B)** 按以下结构持久化：

- `simulationVersion`：`funnel-v2`
- `layer1`：`transcriptSummary`、`stageScore_L1`、`evaluatorJson`
- `layer2`：同上（若未晋级可为 null）
- `layer3`：`transcriptSummary`、`finalScore`、`greenFlags`、`redFlags`、`recommendedNextStep`
- `rankInBatch`：本批 L3 后的名次

### 6.8 `simulationVersion`（执行）

- **固定值**：`funnel-v2`  
- 如后续引入新版本，必须在修订记录中给出“为何优于当前主逻辑”的量化证据后再替换。

### 6.8.1 未通过 pair 的回池机制（执行）

模拟未通过后，**不采用“全员从头重跑”**，统一按失败原因分流回池，走增量批处理：

1. **硬不通过（红线类）**  
   - 规则：不立即回池；进入长冷却或强降权。  
   - 默认口径：`cooldown_hard = 7~30 天`；冷却期内不参与 AB 配对。

2. **软不通过（分数不足）**  
   - 规则：用户可回池，但失败 pair 不立即重试。  
   - 默认口径：`cooldown_soft = 24~72 小时`，并写入 `recentPairBlocklist` 防止下一批重复命中。

3. **信息不足型失败（证据不足 / confidence 低）**  
   - 规则：先引导补充问卷或标签，再回池。  
   - 默认口径：若 `confidence < 0.2`，优先补全资料；补全后再进入 AB。

4. **同一 pair 重试限制**  
   - 规则：同一 `(userA,userB)` 不允许连续批次重试。  
   - 默认口径：`retry_gap >= 14 天`，且 `max_retry <= 2`（超限后仅在资料显著更新时解锁）。

5. **批处理执行口径**  
   - 每批次只对“当前可用池”执行 AB + C；  
   - 历史失败 pair 按冷却与重试规则过滤；  
   - 不做全量历史回放式重算，避免抖动与成本失控。

实现建议（字段）：`failType`、`cooldownUntil`、`retryCount`、`lastTriedAt`、`recentPairBlocklist`。

### 6.9 可解释性与依据校验协议（P0 强制执行）

为避免“模型自由发挥导致结论不可审计”，P0 模拟链路统一采用 **受约束生成 + 规则校验 + 失败告警/重写**。该协议作为上线与回归验收必选项执行。

#### 6.9.1 依据原子（Evidence Atoms）

每对在进入 L1 前先生成一份 **有限依据池**，模型只允许引用池内 ID，不得自造：

- `D_*`：维度依据（20 维连续值及区间结论）  
  例：`D_conflictHandling_high`、`D_lifePace_gap_mid`
- `T_*`：标签依据（主/候选/风格标签）  
  例：`T_family_priority`、`T_social_low_need`
- `P_*`：pair 关系依据（两人之间的结构性关系）  
  例：`P_value_align_money`、`P_boundary_risk_space`
- `S_*`：场景依据（当前层与当前轮次目标）  
  例：`S_L2_mild_conflict_probe`

每个依据原子统一携带简短自然语言说明 `rationaleText`，用于开发调试与审计页面展示。

#### 6.9.2 每轮输出契约：每句话必须带依据

单轮（双方各一句）统一输出结构化 JSON；每个 utterance 必须包含至少 1 个 `basisId`：

```json
{
  "turnIndex": 3,
  "messages": [
    {
      "speaker": "A",
      "utterance": "...",
      "basisIds": ["D_...", "S_..."],
      "intent": "ask|respond|repair|advance",
      "confidence": 0.82
    },
    {
      "speaker": "B",
      "utterance": "...",
      "basisIds": ["T_..."],
      "intent": "respond",
      "confidence": 0.78
    }
  ]
}
```

**硬约束**：`basisIds` 为空即判该句不合格，不进入持久化 transcript。

#### 6.9.3 服务端校验器（非模型自证）

每轮落库前执行校验：

1. **引用有效性**：`basisIds` 必须都存在于本对依据池。  
2. **最小依据数**：每句 `basisIds.length >= 1`。  
3. **语义一致性**：句子内容与 `basisIds` 对应语义需一致（规则关键词 + 轻量 NLI 皆可）。  
4. **边界规则**：不得违反 `redLines`（越界话题、禁忌引导等）。  
5. **新设定约束**：不允许无依据新增关键人设事实。

校验失败后按固定策略执行：

- **离线评测/回归**：严格模式，失败即重写该句（带失败原因回喂），重试超限则整对终止并标记失败。  
- **线上流量**：宽松模式，允许落库但打 `ungrounded=true`，并触发告警；`ungrounded=true` 的对不得进入最终 Top 榜单。

#### 6.9.4 开发者告警与可观测性

告警码固定为：

- `MISSING_BASIS`：句子无依据  
- `INVALID_BASIS_REF`：引用不存在依据  
- `WEAK_ENTAILMENT`：语义匹配弱  
- `REDLINE_VIOLATION`：触发边界违规  
- `UNSUPPORTED_NEW_FACT`：无依据新事实

每条告警至少记录：

- `batchId`, `pairId`, `layer`, `turnIndex`, `speaker`
- `utterance`
- `basisIds`
- `errorCode`, `errorMessage`
- `rewriteAttempt`

#### 6.9.5 终评可解释性最小契约

Evaluator 输出除 `stageScore/finalScore` 外，必须包含：

- `personaBasisTop`：本层最主要的依据原子（Top N）  
- `decisionBasisTop`：直接支撑结论的证据片段（含 turn 引用）  
- `counterEvidence`：至少 1 条反证/不利信号  
- `uncertainty`：不确定性来源（信息不足、冲突未充分展开、轮次不足等）

该契约用于产品侧“为什么给出这个结论”的解释展示，也用于线下误判复盘。

#### 6.9.6 Evaluator 最终打分公式（执行版）

Evaluator 最终打分按以下固定公式执行。记六个主因子（均在 **[0,1]**）：

- `R`：`reciprocity`
- `F`：`flow`
- `C`：`conflict_repair`
- `V`：`values_alignment`
- `B`：`boundary_respect`
- `H`：`future_feasibility`

并记每因子的证据可信度 `q_k ∈ [0,1]`、先验均值 `mu_k`（固定为 **0.5**），总不确定性 `U ∈ [0,1]`，风险强度 `G ∈ [0,1]`，硬门槛标记 `D ∈ {0,1}`。

**(1) 基础加权分**

```
S_base = 0.15*R + 0.15*F + 0.20*C + 0.25*V + 0.15*B + 0.10*H
```

**(2) 证据可信度修正分**（证据弱时回归先验）

```
S_evi = Σ_k [ w_k * ( q_k * s_k + (1 - q_k) * mu_k ) ]
```

其中 `k ∈ {R,F,C,V,B,H}`，`w_k` 取上式固定权重，`mu_k = 0.5`。

**(3) 不确定性惩罚**

```
S_unc = S_evi * (1 - λ * U)
λ = 0.35
```

**(4) 风险门控**

```
if D == 1:
    S_final = min(S_unc, τ_hard)
else:
    S_final = S_unc * exp(-γ * G)
```

固定参数：

```
τ_hard = 0.39
γ = 1.2
```

**(5) 排序与晋级使用分**

- L1/L2 层间晋级使用 `stageScore`（同构公式，按该层 transcript 计算）。
- L3 最终排序使用 `finalScore = S_final`。
- `D==1` 的 pair 不进入最终 `Top M3` 曝光名单。

#### 6.9.7 `q_k / U / G / D` 计算口径（执行版）

为保证可复算，按以下固定口径计算：

1. `q_k`（因子证据可信度）由三项线性组合：

```
q_k = clamp( 0.45*coverage_k + 0.35*entailment_k + 0.20*(1-contradiction_k), 0, 1 )
```

2. `U`（总体不确定性）：

```
U = clamp( 0.50*evidence_sparsity + 0.30*low_entailment_ratio + 0.20*turn_insufficiency, 0, 1 )
```

3. `G`（风险强度）：

```
G = clamp( 0.50*redflag_severity + 0.30*boundary_tension + 0.20*value_conflict, 0, 1 )
```

4. `D`（硬门槛）触发条件（任一满足即 1）：

- 出现严重边界违规（`REDLINE_VIOLATION` 且 severity=high）
- L3 价值观硬冲突条目命中（配置表中的 hard-conflict 对）
- 连续两层出现不可修复冲突（`conflict_repair < 0.2` 且 contradiction 高）

#### 6.9.8 执行结论（P0）

- 仅 prompt 不作为依据控制手段；  
- 统一执行 **依据原子 + 结构化输出 + 服务端校验 + 失败重写/告警 + 门控打分公式**；  
- 该协议直接决定晋级、排序与曝光，作为主链路评分标准。
