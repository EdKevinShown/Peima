# P6.2 — Copilot 真实 LLM 运行手册（OpenAI 兼容，含 DeepSeek）

> **Status: Reference**  
> 范围：**仅** `GET /copilot/conversations/:conversationId/insights` 的模型路径与回退；不涵盖摘要、匹配、Worker、多 Agent。

---

## 1. 环境变量语义

| 变量 | 语义 |
|------|------|
| `AI_COPILOT_ENABLED` | `1` / `true` / `yes` 为开启；否则 **只走规则层**（不请求外网）。 |
| `AI_PROVIDER` | **厂商/品牌 slug**（用于 `sourceType = model_<slug>`）。**强烈建议显式设置**；未设置时 API 会按 `AI_BASE_URL` 的 **hostname** 做保守推断（见 §4）。 |
| `AI_BASE_URL` | OpenAI 兼容 API 根 URL（**无**尾部 `/`）。DeepSeek 示例：`https://api.deepseek.com`。留空则默认 `https://api.openai.com`。 |
| `AI_MODEL` | 供应商侧的 **model / deployment 名**（如 DeepSeek：`deepseek-chat`）。 |
| `AI_API_KEY` | 供应商 API Key；**勿提交**到仓库。 |
| `AI_TIMEOUT_MS` | 单次 Chat Completions 超时（毫秒），超时 **触发 fallback**。 |

**协议说明**：实现固定为 **`POST {AI_BASE_URL}/v1/chat/completions`**（OpenAI 兼容）。与「实际供应商是 DeepSeek / OpenAI / 自建网关」正交：由 `AI_BASE_URL` + `AI_MODEL` + Key 决定打到谁。

---

## 2. DeepSeek 推荐配置（本地 `.env`，勿提交）

```env
AI_COPILOT_ENABLED=1
AI_PROVIDER=deepseek
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-chat
AI_API_KEY=<你的 key>
# AI_TIMEOUT_MS=25000
```

要点：

- **`AI_PROVIDER=deepseek`** 可避免在仅看 `sourceType` 时被误读成 OpenAI（旧版默认 slug 曾易混淆）。
- **`AI_BASE_URL`** 必须与控制台文档一致；若走代理，填代理根地址。

---

## 3. `sourceType` / `sourceVersion` 口径（P6.2）

| 场景 | `sourceType` | `sourceVersion` |
|------|--------------|-----------------|
| 规则层（未启用 / 失败 / 校验失败） | `rule_based` | 与 `copilot-rules` 一致（如 `p2-copilot-rule-v1`） |
| 模型成功 | `model_<slug>`，`slug` 来自 `AI_PROVIDER` 或 host 推断 | `<slug>\|<AI_MODEL>\|<prompt 版本>`，例如 `deepseek|deepseek-chat|p6-copilot-prompt-v1` |

`slug` 仅小写字母、数字、下划线，便于日志与展示映射。

---

## 4. `AI_PROVIDER` 未设置时的推断规则（保守）

按 `AI_BASE_URL` 解析出的 hostname（小写）：

- 含 `deepseek` → `deepseek`
- 含 `openai` → `openai`
- 含 `anthropic` → `anthropic`
- 其它 → **`openai_compatible`**（表示「OpenAI 兼容端点」，**不**断言厂商）

自定义域名网关若无法匹配，**请设置 `AI_PROVIDER`**（如 `my_gateway` → `model_my_gateway`）。

---

## 5. Fallback 何时触发、如何验证

**触发**（均返回 **HTTP 200** + 规则层 + `sourceType: rule_based`）：

- `AI_COPILOT_ENABLED` 未开
- `AI_API_KEY` 为空
- 网络错误、超时、`AI_BASE_URL` 非 2xx
- 响应体无法解析为合法 JSON、或模型 JSON 未通过服务端校验

**验证建议**：

1. **基线**：关闭 `AI_COPILOT_ENABLED`，请求 insights → `rule_based`。
2. **成功**：按 §2 配置，请求 insights → `sourceType` 为 `model_deepseek`（或你的 `AI_PROVIDER`），`sourceVersion` 三节。
3. **回退**：故意错误 `AI_API_KEY` 或 `AI_TIMEOUT_MS=1` → 仍为 200 + `rule_based`；服务端日志 `event: copilot_ai`，`outcome: fallback`。

---

## 6. 本地怎么开

1. 根目录 `.env`（已 gitignore）按 §2 填写；或只开规则层做 UI 回归。
2. `pnpm install`（会 `prisma generate`，见根 `package.json` `prepare`）。
3. `pnpm dev:api`，前端 `pnpm dev:web`（或现有脚本）。
4. 登录后打开 `/chat` 与 `/copilot?conversationId=...`，看 Copilot 卡片与 **轻量来源提示**。

---

## 7. 常见误配排查

| 现象 | 可能原因 |
|------|----------|
| 一直是 `rule_based` | 未启用、无 key、或请求失败；看 API 日志 `copilot_ai` |
| `model_openai_compatible` | 未设 `AI_PROVIDER` 且 host 未匹配已知厂商；设 `AI_PROVIDER` |
| 401 / 403（仍 fallback） | Key 或 base URL 错误；用 curl 对同一 URL 测 Chat Completions |
| 超时 fallback | 调大 `AI_TIMEOUT_MS` 或检查网络 |
| 内容空或总回退 | 模型返回非约定 JSON；检查 prompt 版本与 mapper 校验 |

---

## 8. 与聊天主链路关系

- Copilot **只读 GET**；失败 **不** 影响 `POST` 发消息。
- **无** 数据库写入、无 Worker。
