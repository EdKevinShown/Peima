# P6.2 — Copilot 真实 LLM 运行手册（OpenAI 兼容，含 DeepSeek）

> **Status: Reference**  
> 范围：**仅** `GET /copilot/conversations/:conversationId/insights` 的模型路径与回退；不涵盖摘要、匹配、Worker、多 Agent。

---

## 1. 环境变量语义

| 变量 | 语义 |
|------|------|
| `AI_COPILOT_ENABLED` | `1` / `true` / `yes` 为开启；否则 **只走规则层**（不请求外网）。 |
| `AI_PROVIDER` | **厂商/品牌 slug**（用于 `sourceType = model_<slug>`）。**强烈建议显式设置**；未设置时 API 会按 `AI_BASE_URL` 的 **hostname** 做保守推断（见 §4）。 |
| `AI_BASE_URL` | OpenAI 兼容 API 根 URL（**无**尾部 `/`）。DeepSeek 示例：`https://api.deepseek.com`。留空则默认 `https://api.openai.com`。 |
| `AI_MODEL` | 供应商侧的 **model / deployment 名**（如 DeepSeek：`deepseek-chat`）。 |
| `AI_API_KEY` | 供应商 API Key；**勿提交**到仓库。 |
| `AI_TIMEOUT_MS` | 单次 Chat Completions 超时（毫秒），超时 **触发 fallback**。 |

**协议说明**：实现固定为 **`POST {AI_BASE_URL}/v1/chat/completions`**（OpenAI 兼容）。与「实际供应商是 DeepSeek / OpenAI / 自建网关」正交：由 `AI_BASE_URL` + `AI_MODEL` + Key 决定打到谁。

---

## 2. DeepSeek 推荐配置（本地 `.env`，勿提交）

```env
AI_COPILOT_ENABLED=1
AI_PROVIDER=deepseek
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-chat
AI_API_KEY=<你的 key>
# AI_TIMEOUT_MS=25000
```

要点：

- **`AI_PROVIDER=deepseek`** 可避免在仅看 `sourceType` 时被误读成 OpenAI（旧版默认 slug 曾易混淆）。
- **`AI_BASE_URL`** 必须与控制台文档一致；若走代理，填代理根地址。

---

## 3. `sourceType` / `sourceVersion` 口径（P6.2）

| 场景 | `sourceType` | `sourceVersion` |
|------|--------------|-----------------|
| 规则层（未启用 / 失败 / 校验失败） | `rule_based` | 与 `copilot-rules` 一致（如 `p2-copilot-rule-v1`） |
| 模型成功 | `model_<slug>`，`slug` 来自 `AI_PROVIDER` 或 host 推断 | `<slug>\|<AI_MODEL>\|<prompt 版本>`，例如 `deepseek|deepseek-chat|p6-copilot-prompt-v1` |

`slug` 仅小写字母、数字、下划线，便于日志与展示映射。

---

## 4. `AI_PROVIDER` 未设置时的推断规则（保守）

按 `AI_BASE_URL` 解析出的 hostname（小写）：

- 含 `deepseek` → `deepseek`
- 含 `openai` → `openai`
- 含 `anthropic` → `anthropic`
- 含 `azure` 或 `microsoft` → `azure_openai`
- 其它 → **`openai_compatible`**（表示「OpenAI 兼容端点」，**不**断言厂商）

自定义域名网关若无法匹配，**请设置 `AI_PROVIDER`**（如 `my_gateway` → `model_my_gateway`）。

---

## 5. Fallback 何时触发、如何验证

**触发**（均返回 **HTTP 200** + 规则层 + `sourceType: rule_based`）：

- `AI_COPILOT_ENABLED` 未开
- `AI_API_KEY` 为空
- 网络错误、超时、`AI_BASE_URL` 非 2xx
- 响应体无法解析为合法 JSON、或模型 JSON 未通过服务端校验

**验证建议**：

1. **基线**：关闭 `AI_COPILOT_ENABLED`，请求 insights → `rule_based`。
2. **成功**：按 §2 配置，请求 insights → `sourceType` 为 `model_deepseek`（或你的 `AI_PROVIDER`），`sourceVersion` 三节。
3. **回退**：故意错误 `AI_API_KEY` 或 `AI_TIMEOUT_MS=1` → 仍为 200 + `rule_based`；服务端日志 `event: copilot_ai`，`outcome: fallback`。

---

## 6. 本地怎么开

1. 根目录 `.env`（已 gitignore）按 §2 填写；或只开规则层做 UI 回归。
2. `pnpm install`（会 `prisma generate`，见根 `package.json` `prepare`）。
3. `pnpm dev:api`，前端 `pnpm dev:web`（或现有脚本）。
4. 登录后打开 `/chat` 与 `/copilot?conversationId=...`，看 Copilot 卡片与 **轻量来源提示**。

---

## 7. 常见误配排查

| 现象 | 可能原因 |
|------|----------|
| 一直是 `rule_based` | 未启用、无 key、或请求失败；看 API 日志 `copilot_ai` |
| `model_openai_compatible` | 未设 `AI_PROVIDER` 且 host 未匹配已知厂商；设 `AI_PROVIDER` |
| 401 / 403（仍 fallback） | Key 或 base URL 错误；用 curl 对同一 URL 测 Chat Completions |
| 超时 fallback | 调大 `AI_TIMEOUT_MS` 或检查网络 |
| 内容空或总回退 | 模型返回非约定 JSON；检查 prompt 版本与 mapper 校验 |

---

## 8. 与聊天主链路关系

- Copilot **只读 GET**；失败 **不** 影响 `POST` 发消息。
- **无** 数据库写入、无 Worker。

---

## 9. `copilot_ai` 结构化日志（P6.4）

以下日志由 `CopilotService` / `CopilotChatCompletionsClient` 输出，**单行 JSON**（便于 grep / 日志平台解析）。**禁止**打印 `AI_API_KEY`、完整 prompt 或完整用户消息正文；`detail` 仅保留 **截断后的** 供应商错误片段。

### 9.1 字段说明

| 字段 | 出现场景 | 含义 |
|------|----------|------|
| `event` | 必有 | 固定为 `copilot_ai`。 |
| `conversationId` | fallback / model_ok | 当前会话 id。 |
| `outcome` | fallback / model_ok | `fallback` = 已回退规则层；`model_ok` = 本请求采用模型输出。 |
| `reason` | fallback | 失败原因码，见 **§10**；与代码中 `result.kind` 或服务内常量一致。 |
| `status` | 部分 fallback | HTTP 状态码（`kind === http` 时由供应商返回）。 |
| `detail` | 部分 fallback | 供应商错误体或解析错误信息摘要（已截断）。 |
| `durationMs` | 发起过 HTTP 的 fallback / model_ok | 自发起 Chat Completions 至返回的耗时（毫秒）。 |
| `providerSlug` | P6.4 起：fallback / model_ok | 非敏感配置快照：解析后的厂商 slug（与 `sourceType` 中 `model_<slug>` 的 slug 一致），便于排查「以为在打 A 实际配置像 B」。 |
| `sourceType` | model_ok | 成功响应将携带的 `sourceType`（`model_<slug>`）。 |

**说明**：`AI_COPILOT_ENABLED` 为假时，服务在调用模型前即返回规则层，**通常不产生** `copilot_ai` 日志（属预期，非故障）。

---

## 10. Fallback `reason` 原因码表

| `reason` | 产生位置 | 含义 | 建议排查 |
|----------|----------|------|----------|
| `missing_api_key` | `CopilotService` 或 Client | 未配置有效 `AI_API_KEY`（服务在发 HTTP 前即拦截，或 Client 二次校验）。 | 在 `.env` 中设置密钥；勿提交仓库。 |
| `disabled` | `CopilotChatCompletionsClient` | 客户端内判定未启用（正常路径下服务已拦截，**极少**出现在日志）。 | 确认 `AI_COPILOT_ENABLED`。 |
| `timeout` | Client | `AI_TIMEOUT_MS` 内未完成请求（`AbortError`）。 | 调大超时；检查网络与供应商延迟。 |
| `network` | Client | DNS、连接重置等非 HTTP 错误。 | 检查 `AI_BASE_URL`、代理、防火墙。 |
| `http` | Client | 供应商返回非 2xx；见 `status` 与 `detail`。 | Key、额度、URL、model 名是否被供应商接受。 |
| `empty_content` | Client | 响应 200 但 `choices[0].message.content` 为空。 | 换模型或查供应商返回格式。 |
| `invalid_json_response` | Client | 响应体非合法 JSON（含 HTTP 200 但 body 异常）。 | 网关是否改写响应；勿经会注入 HTML 的代理。 |
| `invalid_model_payload` | `CopilotService` | 模型返回的 JSON 未通过服务端校验（字段、长度、`conversationId` 等）。 | 查看 prompt 版本；供应商是否遵循 JSON-only 约定。 |

回退后 API 行为不变：**HTTP 200** + `sourceType: rule_based` + 规则层内容。

---

## 11. 重试行为说明（当前无自动重试）

- Copilot Chat Completions 为 **单次请求**：失败即按 §10 记日志并 **fallback**，**不会** 在服务端自动重试、不退避、不排队。
- 若需重试，由 **客户端用户**（例如刷新 Copilot / 重新进入会话）或 **未来** 独立运维能力实现；**不在** P6.4 范围内实现自动重试。

---

## 12. 稳定性自检清单（第一轮）

1. **关模型**：`AI_COPILOT_ENABLED=0` → insights 为 `rule_based`，且无异常依赖外网。  
2. **开模型 + 正确配置**：`200` + `model_<slug>` + `sourceVersion` 三节。  
3. **错密钥**：仍为 `200` + `rule_based`，日志 `outcome:fallback`、`reason` 为 `http` 或 `missing_api_key` 等可解释值。  
4. **超短超时**：`AI_TIMEOUT_MS=1` → fallback，日志含 `timeout`。  
5. **slug 可读**：DeepSeek 场景下 `sourceType` 不为误导性 `model_openai`（应 `model_deepseek` 或显式 `AI_PROVIDER`）。

---

## 13. 常见误配与 `sourceType` / `sourceVersion` 对照

| 误配或现象 | 典型 `sourceType`（成功时） | 典型 `sourceVersion`（成功时） | 说明 |
|------------|----------------------------|-------------------------------|------|
| 未设 `AI_PROVIDER`，host 无法识别 | `model_openai_compatible` | `openai_compatible\|…` | 表示 **协议兼容端点**，非断言 OpenAI 官方；建议设 `AI_PROVIDER`。 |
| DeepSeek 官方 URL，未设 `AI_PROVIDER` | `model_deepseek` | `deepseek\|<model>\|<prompt>` | 由 host 推断 slug。 |
| 官方 OpenAI，`AI_BASE_URL` 默认 | `model_openai` | `openai\|…` | host 含 `openai`。 |
| 任意失败或未启用模型路径 | `rule_based` | `p2-copilot-rule-v1`（规则模板版本） | 与模型 `sourceVersion` **格式不同**，可据此区分。 |

与 **§7** 表格可对照阅读：§7 偏「现象 → 原因」，本表偏「标识符 → 配置含义」。
