## 6. Safe fallback wording guide

### Preferred (docs · UI · logs · runbooks)

| Phrase | Use when |
|--------|----------|
| **safe fallback** | P7.6 read path cannot apply sidecar |
| **safe baseline display** | Output of `resolveMatchResultDisplay` used as overlay input |
| **stable baseline result** | Existing `MatchResult` row + baseline display |
| **original stable result** | Explaining `match_result_original` enum |
| **stable finalize fallback** | Explaining `static_fallback` enum (pairwise path) |
| **finalize fallback** | Shorthand in technical docs |
| **matching_pending** | `batch_match_queue` waiting/processing · waiting page |
| **no_result** | No queue + no `MatchResult` (future typed state) |
| **fallback to baseline display** | Replacing「fallback to legacy」|
| **safe_fallback_reason** | Replacing `fallbackReason` in external docs (code field rename optional later) |

### Avoid

| Phrase | Why |
|--------|-----|
| legacy photo matching fallback | Product decision: photo matching deprecated |
| old photo matching fallback | Same |
| legacy fallback (standalone) | Implies photo engine |
| legacy display | Implies photo display path |
| fallback to old photo matching | Incorrect mechanism |
| static fallback = photo fallback | Wrong; it is finalize/static Top1 path |

**Enum rule:** If response contains `"displaySourceType": "static_fallback"`, docs MUST explain **stable finalize fallback**, not photo.
