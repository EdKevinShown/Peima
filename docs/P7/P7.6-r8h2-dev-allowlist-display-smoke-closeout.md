## 1. 一句话结论

P7.6-r8h2 在 **dev/staging** 验证 P7.6 read path overlay：env enabled + allowlist + 未 rollback sidecar 时，**4/4** viewer 返回 `displaySourceType=p76_allowlist_sidecar_readonly` 且 `displayCandidateUserId=sidecar.selectedCandidateId`；**rolledBack** 与 **non-allowlist** 均 safe fallback (baseline display)；`violation_count=0`；`finalScore` 与 legacy `candidateUserId` **未改**。**不是** production rollout。

**方法说明：** Route C 5 viewer 在 dev DB **无** `match_results` 行（[r7k2](./P7.6-r7k2-m6-comparison-sql-evidence-closeout.md) `NO_MATCH_RESULT`），无法对其实际执行 `GET /matching/result/:viewerUserId`。本轮使用与 production 相同的 `resolveMatchResultDisplay` + live `p76_allowlist_apply_meta`（等同 r8h1 接入路径），synthetic `MatchResult` 仅提供 legacy `candidateUserId` / `finalScore` 基线。
