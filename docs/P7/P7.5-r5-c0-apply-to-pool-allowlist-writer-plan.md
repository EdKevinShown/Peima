## 1. 一句话结论

在 **r5-b dry-run 五案全 PASS**（[r5-b1](./P7.5-r5-b1-apply-eligibility-dry-run-local-signoff.md) / [r5-b2](./P7.5-r5-b2-apply-dry-run-signoff-closeout.md)）的基础上，**P7.5-r5-c** 在本方案下 **只允许 allowlist-only writer**：当且仅当 **`PEIMA_ONBOARDING_VISION_APPLY_TO_POOL=1`**、**allowlist 非空**、**viewer 在 allowlist**、**eligibility 为 ok**、**guardrails 全通过** 时，才把与 **`visualRankingShadow` 同源** 的 3+2+1 **候选与分数**写入 **本次 `generate()` 新创建** 的 `OnboardingPhotoPreviewPoolItem`。**默认关闭**；**本阶段不启用 `PEIMA_ONBOARDING_VISION_APPLY_PERCENT` 灰度**（percent 可保留读入，但 **不参与** writer 决策）；**不碰** worker、`MatchResult`、`finalScore`、旧 `PreviewPool`、正式匹配主链。

## 4. Env 策略（r5-c = allowlist-only）

### 4.1 本阶段推荐配置形态

与 [r5-b](./P7.5-r5-b-apply-eligibility-dry-run-closeout.md) 相同变量名，**但 writer 语义收紧**：

```env
PEIMA_ONBOARDING_VISION_APPLY_TO_POOL=1
PEIMA_ONBOARDING_VISION_APPLY_ALLOWLIST_USER_IDS=<逗号分隔 viewer cuid>
PEIMA_ONBOARDING_VISION_APPLY_PERCENT=0
PEIMA_ONBOARDING_VISION_APPLY_SOURCE_VERSION=onboarding-photo-preview-v2-vision
```

### 4.2 规则（评审锁定）

| 条件 | writer 行为 |
|------|-------------|
| `APPLY_TO_POOL` **≠** `"1"` | **只写 v1**（与现网一致） |
| **allowlist 为空** | **只写 v1**；**即使** 将来 env 中 `PERCENT=100`，**r5-c 实现不得**仅凭 percent 进入 writer（percent 灰度 **另开** [§13](#13-r5-c-拆分建议) **r5-d** 评审） |
| viewer **不在** allowlist | **只写 v1** |
| allowlist **命中** 且 §5 全通过 | **可写 v2**（shadow 同源 items） |
| `PERCENT` | **读入保留**，默认 **0**；**r5-c1 不参与** writer 门禁逻辑（与 r5-b 评估路径 **硬分叉**：writer 入口 **不**调用「空 allowlist + percent」分支） |
| 关闸 / 清 allowlist | 下一次 `generate()` **回 v1** |

## 5. Writer 触发条件（必须全部满足）

以下 **12 条** 全部满足，才允许在 **create 新池** 时使用 **shadow 槽位** 覆盖 item 的 `candidateUserId` / `score` / `reasonTags` 并设 `sourceVersion=v2`。

1. `readOnboardingVisionApplyEnv().applyToPoolEnabled === true`（`PEIMA_ONBOARDING_VISION_APPLY_TO_POOL === "1"`）。
2. **`allowlistUserIds.length >= 1`**（**本阶段强制**；空列表 **永不** writer）。
3. `viewerUserId ∈ allowlist`。
4. **`evaluateOnboardingVisionApplyEligibility`（或 r5-c1 等价合并函数）** 在 **allowlist-only 语义** 下输出 **`reason === "ok"`** 且 **`eligible === true`**（与 r5-b 对齐的 guard + shadow 有效前提下；**实现时**须单独单测「忽略 percent 的 writer 专用 eligibility」，避免与 dry-run 路径混用同一出口而未删 percent 分支）。
5. **`VisualRankingShadowV1`**（或 persist 前内存对象）**结构有效**：`schemaVersion` 合法、`slots.length === 6`、与 3+2+1 tier 顺序一致。
6. **Baseline / 拟写入** 的 6 个 **`candidateUserId` 全局唯一**。
7. **`previewPoolRowDisplaySourceKey`** 意义下 **6 个 source key 互异**（与 r4-o2 一致）。
8. **无 viewer self**（candidate ≠ viewer）。
9. **无 opposite gender violation**（二元门控；unknown 不得入池）。
10. **无 blocked review**（与 r3/r4 **首张可用图** / vision 输入规则一致：用于池与 shadow 的 candidate 首张图不得处于 `rejected` / `needs_reupload` / `appealed` / `appeal_rejected` 等 **禁用** 状态；**具体字段以 r5-c1 实现 closeout 钉死**）。
11. **候选数量与槽位**：生成路径上 **仍为 6 槽**；若 baseline 已无法 6 人，维持现有 **`BadRequestException`**，**不**为 writer 单独「凑 shadow」。
12. **`applySourceVersion`** 来自 env，且与 `OnboardingPhotoPreviewPool.sourceVersion` 写入值 **一致**、在 allowlist 配置下 **白名单**（默认 `onboarding-photo-preview-v2-vision`）。

**任一失败**

- **写 v1 items**（与当前 `generate()` 行为一致）。
- Shadow **`summary.applyDryRun`** 仍记录 **具体 `reason`**（与 r5-b 一致）；**不**因 writer 未命中而对用户 **额外**抛错（除非 baseline 本身失败）。
- 根 **`VisualRankingShadowV1.appliedToPool`** 与 **r4-c audit** 兼容策略见 **§7**（**不得**在未评审前提下把 `summary.applyDryRun.appliedToPool` 改为 `true`，以免破坏 r5-b 签收语义）。

## 6. 写入内容

### 6.1 当 apply（writer）成功时

**`OnboardingPhotoPreviewPool`**

- `sourceVersion` = `readOnboardingVisionApplyEnv().applySourceVersion`（默认 **`onboarding-photo-preview-v2-vision`**，与 [r5-a §6](./P7.5-r5-a-onboarding-vision-apply-to-pool-design.md) 一致）。

**`OnboardingPhotoPreviewPoolItem`（每条）**

- `candidateUserId`：取 **shadow** 对应 `rankInPool` 的 **`shadowCandidateUserId`**（与 r3 builder 输出同源）。
- `score`：取 shadow **`shadowScore`**（或实现 closeout 规定的归一化口径）。
- `reasonTags`：在保留 v1 trace（如 `onboarding-photo-preview-v1` / `tier:*`）策略上 **叠加** `vision:apply` 等短码（**以 r5-c1 closeout 为准**）。

### 6.2 不得修改

- **`rankInPool`**（1–6）、**`tier`** 字符串、`**displayMode**`（`clear` / `blurred` / `hidden`）—— **仅换人换分换 tag**，**不改** 3+2+1 **结构**。
- **viewer 用户行**、**candidate profile** 实体、**`UserImage`** 二进制与 review 状态（writer **只读**门控结果）。

## 7. Shadow / audit metadata（兼容 r5-b 与 r4-c）

### 7.1 问题

- r5-b 签收与类型约定：`VisualRankingShadowV1` 根 **`appliedToPool`** 曾为 **字面量 `false`**；`summary.applyDryRun.appliedToPool` **恒 `false`**（dry-run）。
- r4-c `parseVisualRankingShadowPayloadSafe` 当前对 **`appliedToPool !== false`** 的行判 **invalid**。
- 若成功写 pool 后把 **`summary.applyDryRun.appliedToPool` 改为 `true`**，会 **混淆**「dry-run 子结构」与「真实写回」两套读者心智，**不推荐**。

### 7.2 推荐兼容策略（实现前在 r5-c1 定稿其一）

**方案 A（推荐）：payload `schemaVersion` 升级 + audit 分叉**

- 新行使用 **`visual-ranking-shadow-v2`**（或等价 bump 名），根字段 **`appliedToPool: boolean`**，真实写回成功为 **`true`**。
- **r4-c audit CLI**：对 v1 行保持现有校验；对 v2 行 **扩展解析**（**必须**另起单测与迁移说明）。
- **`summary.applyDryRun`**：可 **保留** r5-b 形状且 **`appliedToPool` 仍为 `false`**，表示「当时 dry-run 评估块」；真实写回走 **`summary.applyResult`**（见下）。

**方案 B：根 `appliedToPool` 仍为 `false`，仅用新 summary**

- 根 **`appliedToPool` 不表达真实写回**；使用 **`summary.applyResult`**：

```json
{
  "evaluated": true,
  "applied": true,
  "reason": "ok",
  "sourceVersion": "onboarding-photo-preview-v2-vision"
}
```

- **缺点**：运维若只看根字段会 **误判**；文档与 Grafana 查询须 **显式约定**「以 `applyResult.applied` 为准」。

**不推荐**：修改 **`applyDryRun.appliedToPool`** 为 `true`。

### 7.3 apply 失败 / v1 回落时

- 根 **`appliedToPool`** 按所选 schema **为 `false`**。
- **`summary.applyDryRun`**：与 r5-b 相同，`eligible` / `reason` 反映 **未写 v2** 的原因。
- **`summary.applyResult`**（若采用方案 A/B）：`applied: false`，`reason` 与 dry-run 或 writer 合成原因一致（**实现 closeout** 给枚举表）。

- **v1 / v2** 只读语义清晰；**旧池不迁移**。

## 9. 回滚

**一键回滚（配置）**

```env
PEIMA_ONBOARDING_VISION_APPLY_TO_POOL=0
PEIMA_ONBOARDING_VISION_APPLY_ALLOWLIST_USER_IDS=
PEIMA_ONBOARDING_VISION_APPLY_PERCENT=0
```

**回滚后行为**

- 下一次 **`generate()`** 仅创建 **v1** pool。
- 库内 **已存在 v2 pool** **不批量改写**；用户 **再次生成** 可得 v1 active（沿用现有 archive 语义）。
- **不影响** `MatchResult` / worker / `finalScore`。

## 10. 测试计划

### 10.1 Unit

| 场景 | 期望 |
|------|------|
| env off | v1 |
| allowlist 空 | v1 |
| allowlist miss | v1 |
| allowlist hit + eligible | v2 |
| `percent=100` 且 allowlist 空 | **v1**（本阶段强制） |
| duplicate candidate / source / gender / self guard | v1 |
| shadow missing / invalid | v1 |

### 10.2 Service / integration

- apply 成功：`sourceVersion` = v2；items 的 `candidateUserId` 与 **shadow 槽位** 一致；**rank/tier/displayMode** 不变。
- apply 失败：与 baseline v1 **一致**（或对同一 fixture 断言）。
- shadow persist：**`applyResult` / `schemaVersion`** 符合 §7。
- **active audit**：v2 生成后 **全 PASS**。
- env 回滚后再 generate：**v1**。

### 10.3 本地 signoff（r5-c2 文档化）

- allowlist 内用户 → v2；非 allowlist → v1。
- 页面 6 项、无 duplicate / self / gender violation（与 r4-o3 精神一致）。
