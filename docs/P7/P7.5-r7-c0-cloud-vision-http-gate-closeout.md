## 4. Adapter registry 选择规则

`resolveCloudVisionAdapter(env, { imageId?, userId?, routedFrom? })`

### 返回 `mock`（任一满足）

| 条件 | `reason` |
|------|----------|
| `enabled !== true` | `vision_disabled` |
| `provider` 非 `cloud` / `zhipu` | `provider_not_cloud` |
| `cloudDryRun === true` | `cloud_dry_run` |
| `cloudHttpEnabled !== true` | `cloud_http_disabled` |
| `cloudVendor === "mock"` | `cloud_vendor_mock` |
| `apiKey` 为空 | `api_key_missing` |
| image + user allowlist 均为空 | `allowlist_empty` |
| `imageId` / `userId` 均未命中 allowlist | `allowlist_miss` |

### 返回 `real-disabled`（全部满足）

- `enabled=true`
- `provider ∈ { cloud, zhipu }`（**zhipu 不绕过闸**）
- `cloudDryRun=false`
- `cloudHttpEnabled=true`
- `cloudVendor !== mock`
- `apiKey` 非空
- allowlist 非空且 `imageId` 或 `userId` 命中
- **且** r7-c0 **无**真实 adapter 实现 → `live_gate_passed_real_not_implemented`

---

## 5. 为什么 r7-c0 仍不发真实 HTTP

- **未实现** `cloud-vision.zhipu-adapter.ts` / HTTP client / `fetch`。
- `real-disabled` 分支在 facade 内直接 **`mergeCloudFallbackWithRules`**，**不**调用 `CloudVisionMockAdapter`。
- 即使误配 `CLOUD_DRY_RUN=0` + `HTTP_ENABLED=1` + allowlist 命中，也 **不会** 出网。

---

## 6. Facade 行为

| `adapter` | 行为 |
|-----------|------|
| **mock** | `CloudVisionMockAdapter.analyzeSync` → normalizer → ok 或 mock 内 fallback |
| **real-disabled** | **无 HTTP**；`fallbackUsed=true`；`fallbackReason=cloud_real_adapter_not_implemented`；tags 来自 **rules**；`sourceVersion` 仍为 `p7.5-r7-cloud-dry-run-v1` |

外层 **try/catch** 保留；**不向**上传主链 throw。
