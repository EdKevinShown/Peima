# P7.5-r4-c — Visual ranking shadow audit CLI Closeout

## 本轮目标

提供**只读** CLI，从 `OnboardingPhotoPreviewPoolShadow` 聚合 `VisualRankingShadowV1`，输出 JSON，用于判断是否适合进入 **P7.5-r5 APPLY_TO_POOL 设计方案**评审（不等于启用 APPLY）。

## 产出物

| 路径 | 说明 |
|------|------|
| `apps/api/src/modules/onboarding/vision/visual-ranking-shadow-audit.ts` | 校验 payload、聚合指标、`readyForApplyToPoolDesign` 阈值（纯函数） |
| `apps/api/src/dev-cli/p75-r4-visual-ranking-shadow-audit-cli-args.ts` | 参数解析 |
| `apps/api/src/dev-cli/p75-r4-visual-ranking-shadow-audit-runner.ts` | Nest minimal context + Prisma 查询 + stdout JSON |
| `apps/api/test/visual-ranking-shadow-audit.spec.ts` | 聚合与阈值单元测试 |

## CLI 命令

需要先编译 API：

```bash
cd apps/api && pnpm exec nest build
pnpm --filter @peima/api run p75:r4-shadow-audit
```

常用参数：

| 参数 | 默认 | 说明 |
|------|------|------|
| `--limit` | 100 | 最多扫描的 shadow 行数（聚合分布用；上限 50000） |
| `--userId` | 无 | 仅该 viewer 的 pool / shadow |
| `--sourceVersion` | `p7.5-r3-visual-ranking-shadow-v1` | payload 版本 |
| `--since` / `--until` | 无 | `yyyy-mm-dd`（UTC 日界） |
| `--jsonl` | false | 为 true 时先输出每行脱敏摘要，再输出总 JSON |

`shadowType` 固定为 `visual_ranking_shadow`（与库内写入一致）。

## 输出指标（`schemaVersion: p7.5-r4-shadow-audit-v1`）

根对象含：

- `summary.totalShadowRows`：本 CLI **扫描样本**行数（受 `--limit`）
- `summary.validShadowRows` / `invalidShadowRows`：样本内能通过 schema 校验的 payload 计数
- `summary.shadowCoverageRate`：`shadowRowsMatchingQueryTotal ÷ poolsMatchingFilterTotal`（全量 count，与同 filter 对齐）
- `summary.shadowRowsMatchingQueryTotal`、`poolsMatchingFilterTotal`
- `changedSlotsDistribution`、`changedTiersFrequency`（**按行**：该行某 tier 是否至少 1 个 changing slot）、`tierChangeRate`
- `avgCandidatesWithVision` / `avgCandidatesMissingVision`、`viewerVisionAvailableRate`
- `applyToPoolIgnoredCount`、`fullShuffleRate`
- `topReasonTags`

## readyForApplyToPoolDesign

与 **P7.5-r4-a** 阈值一致（仅门禁「是否适合做 r5 **设计**」）：

| 检查 | 条件 |
|------|------|
| 覆盖率 | `shadowCoverageRate >= 0.8` |
| pools | 匹配的 pool 数 > 0（否则无法定义覆盖率） |
| 样本 | `validShadowRows >= 50` |
| Missing vision | `avgCandidatesMissingVision < 1.2` **或** missing / (missing+vision) `< 0.2` |
| Viewer vision | `viewerVisionAvailableRate >= 0.6` |
| 变更幅度 | `avgChangedSlots ∈ [0.3, 2.5]` |
| 全槽洗牌 | `changedSlots=6` 占比 `< 1%` |
| Tier | reflow `< 15%`，aesthetic `< 40%`，style_similar `< 50%` |

否则 `readyForApplyToPoolDesign: false`，`reasons[]` 说明原因。

## 隐私边界

- 主 JSON **不含** `candidateUserId`、`viewerUserId`、`poolId`、图片 URL、原始 `payloadJson`、`detectionScoreJson`、`reviewNote`
- `--jsonl` 行仅含：`ok`、`changedSlots`、`viewerVisionAvailable`、`applyToPoolIgnored`

## Payload 校验

- `schemaVersion === visual-ranking-shadow-v1`
- `appliedToPool === false`
- `slots` 长度为 6，tier 顺序与 onboarding 3+2+1 一致；`changedSlots` 与 `wouldChange` 一致；`summary.changedTiers` 与变化的 slot tiers 一致
- 失败计入 `invalidShadowRows`，进程不崩溃
