## 5. Enrichment 方案

### 5.1 方案 A — 只读 SQL 核查（推荐先做）

| 动作 | 说明 |
|------|------|
| 查询 | 5 viewer **最新** `MatchResult`（`viewerUserId` · `candidateUserId` · `updatedAt`） |
| 查询 | `matchInsights` 是否含 `rrmV2Top2Selector` · Top2 · `selectedCandidateId` |
| 查询 | M6 `sourceVersion` / 生成时间 vs pool `p7.6-r7j3-staging-cohort-v1` |
| 对比 | Route C `r7g2-stage1` `selectedCandidateIds` vs M6 Top2 集合 |
| 产出 | **comparison readiness table**（§6）→ [r7k2](./P7.6-r7k2-m6-comparison-sql-evidence-closeout.md) closeout |

**边界：** 只读 · **不写 DB** · **不触发 worker**

### 5.2 方案 B — 重新跑 staging batch match（条件触发）

| 条件 | 说明 |
|------|------|
| 触发 | 方案 A 显示 M6 **缺失** 或 **stale** 且 PM 书面要求补强 |
| 方式 | 现有 worker / batch-match 路径 |
| 禁止 | 手写 `MatchResult` · 手写 `finalScore` · 改 worker 排序 · 改 M6/RRM 主链 |
| 产出 | 新 `MatchResult` / `matchInsights` → **重跑 r6b** comparison |
| 注意 | worker 仍读 **legacy** pool（[r1](./P7.6-r1-legacy-matching-dependency-audit.md)）；与 onboarding pool **可能仍不一致** — 须在 r7k2 披露 |

### 5.3 方案 C — PM 接受 caveat（不补 M6）

| 项 | 说明 |
|----|------|
| 前提 | PM **书面**接受：5/5 `wouldChangeM6Top2=true` 因无/stale M6 · 非 pipeline 缺陷 |
| 允许 | 进入 **P7.6-r8** **allowlist-only apply design** |
| 禁止 | 视为 production rollout · percent · `APPLY_TO_POOL` |

### 5.4 推荐路径

```text
r7k1 plan (本文档)
  → r7k2 方案 A：只读 SQL evidence closeout
  → 若 M6 可解释 → PM signoff (PASS_TO_R8_ALLOWLIST_DESIGN)
  → 若 M6 缺失/stale 且 PM 要求 → 方案 B batch match + 重跑 r6b
  → 若不可解释 → BLOCK_R8 / 继续 enrichment
  → PM PASS → r8 allowlist design only
```

**推荐：** **先做方案 A**。若 M6 缺失或 stale，**再决定**是否方案 B。

## 6. SQL evidence table（r7k2 产出 schema）

[r7k2](./P7.6-r7k2-m6-comparison-sql-evidence-closeout.md) 按 viewer 填表，字段如下：

| 字段 | 说明 |
|------|------|
| `viewerUserId` | Route C clean viewer |
| `hasMatchResult` | 是否存在至少一条 MatchResult |
| `matchResultId` | 最新 MatchResult id（若有） |
| `matchResultCandidateUserId` | 该行 candidate |
| `matchResultUpdatedAt` | ISO 时间 · 与 r7j4 构建时间对比 |
| `hasM6RrmTop2` | `matchInsights.rrmV2Top2Selector` 存在 |
| `m6Top2CandidateIds` | M6 Top2 数组（脱敏 id only） |

| `comparisonGapReason` | 如 `NO_MATCH_RESULT` · `STALE` · `POOL_MISMATCH` · `MISSING_M6_INSIGHTS` · `SELECTED_DIFFERS` · `COMPARABLE` |

**Privacy：** SQL 输出 / closeout **不得**含 `imageUrl` · `detectionScoreJson` 全文 · raw profile · API key。

## 7. PASS / BLOCK 判断（PM 门槛）

### 7.1 `PASS_TO_PM_REVIEW`

| # | 条件 |
|---|------|
| 1 | M6 caveat **可解释**（如无 MatchResult → flag 预期 · 非 shadow bug） |
| 2 | P0 / P1 = **0** |

| 4 | PM **接受** `wouldChangeM6Top2=true` 的原因（书面） |

→ 可讨论 **`PASS_TO_R8_ALLOWLIST_DESIGN`**（仍 **非** apply）

### 7.2 `NEED_M6_ENRICHMENT`

| # | 条件 |
|---|------|
| 1 | M6 **缺失**（无 `rrmV2Top2Selector`） |
| 2 | M6 **stale**（cohort 前 · pool 已变） |
| 3 | M6 pool **不一致**（legacy pool ≠ Route C six-pack） |
| 4 | M6 `selectedCandidateId` **缺失** |
| 5 | r6b comparison **不足以**支撑 PM 判断 |

→ 执行方案 A 完整证据；必要时方案 B

### 7.3 `BLOCK_R8`

| # | 条件 |
|---|------|
| 1 | M6 差异 **不可解释** 且非缺失类 |
| 2 | legacy / display / worker 对照 **不可信** |
| 3 | PM 要求补强但 **未完成** r7k2 / batch match |

→ **不得**进入 r8 allowlist design
