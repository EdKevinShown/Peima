## 4. 20D 双向定义

### 4.1 语义（产品）

| 符号 | 含义 |
|------|------|
| **AtoB20DFit** | **Viewer（A）** 的择偶偏好 + 画像需求，对 **candidate（B）** 的 20 维画像 / 可观测特征的满足度 |
| **BtoA20DFit** | **Candidate（B）** 对 **viewer（A）** 的反向满足度 |
| **mutual20DFit** | 双向综合；用于 Stage 2 排序与 Top2 短名单 |

「20D」在本设计中指 **G1-R 问卷轴**（`UserProfile` 上 20 个关系维度）及与之配套的 **preference** 项，**不是** PhotoVisual tags。

### 4.2 计算映射（复用现有函数）

与 [r1 §5](./P7.6-r1-legacy-matching-dependency-audit.md) 对齐，**不重写**轴公式：

| 方向 | 建议组合（r4a 实现时锁定） | 现有函数 |
|------|---------------------------|----------|
| **A→B** | `profile` + `preference` 加权（**不含** preview pool `baseScore`、**不含** style） | `computeProfileScore(viewerProfile, candidateProfile)` · `computePreferenceScore(viewerPref, candidateDemographics)` |
| **B→A** | 同上，**交换** viewer / candidate 角色 | 同上，参数对调 |
| **归一化** | 各子分 `[0,1]` 后加权；权重 **与 `computeFinalScoreV1` 的 profile/pref 部分对齐或文档化差异** | 见 `apps/worker/src/jobs/matching-score.ts` |

**明确排除**（避免与 Stage 1 / worker 混淆）：

- **不用** `computeFinalScoreV1` 作为 `AtoB20DFit` 或 `BtoA20DFit`（其含 `preview` + `style` + 单向假设）。  
- **不用** `PreviewPoolItem.baseScore` 进入 Stage 2（legacy pool 项）。  
- **`computeStyleScore`** 属于照片风格层，归属 Stage 1；Stage 2 **默认不重复计入**。

**初版 20D-only 合成（建议）**：

```text
AtoB20DFit = w_prof * profileScore(A→B) + w_pref * preferenceScore(A→B)
BtoA20DFit = w_prof * profileScore(B→A) + w_pref * preferenceScore(B→A)

其中 w_prof + w_pref = 1（建议 w_prof=0.4, w_pref=0.6，与 finalScore v1 中 profile/pref 相对比重同量级；r4a 单测锁定）
```

### 4.3 mutual20DFit

**推荐（初版）** — 短板敏感：

```text
mutual20DFit = harmonicMean(AtoB20DFit, BtoA20DFit)

harmonicMean(a,b) = (a>0 && b>0) ? 2ab/(a+b) : 0
```

**备选**（与 Stage 1 PhotoVisual 对齐，便于 PM 对比）：

```text
mutual20DFit = 0.5 * AtoB20DFit + 0.5 * BtoA20DFit - imbalancePenalty

imbalancePenalty = max(0, |AtoB20DFit - BtoA20DFit| - τ) * k   （τ、k 由 r4a 常量表锁定）
```

**设计理由**：双向匹配中**任一侧过低**应拉低综合分；`harmonicMean` 比算术平均更保守，避免「单向极高、反向极低」仍排前。  
**审计**：shadow JSON 可同时输出 `mutual20DHarmonic` 与 `mutual20DArithmetic`（optional），**排序键**仅用其一（默认 harmonic）。

### 4.4 imbalancePenalty

| 字段 | r4 默认 |
|------|---------|
| `imbalancePenalty` | 记录 `|AtoB20DFit - BtoA20DFit|` 或公式 penalty；**harmonic 模式下可为 0**（惩罚已内含于 harmonic） |

## 5. 复用现有 20D 算法

### 5.1 文件清单（r1 审计）

| 文件 | 符号 | 角色 | r4 用法 |
|------|------|------|---------|
| `apps/worker/src/jobs/matching-score.ts` | `computeProfileScore` | 20 轴平均相似度（单向） | **调用两次** → A→B、B→A |
| 同上 | `computePreferenceScore` | viewer pref → candidate 字段 | **调用两次** |
| 同上 | `computeStyleScore` | styleTags Jaccard | **Stage 2 不用**（Stage 1 已覆盖） |
| 同上 | `computeFinalScoreV1` | worker 最终排序分 | **禁止改** · **禁止**作为 mutual20D |
| `packages/shared/matching/preference-score.ts` | `computePreferenceScore` / `computeStyleScore` | shared 实现 | worker 与 API 同源；r4a **import shared** |
| `apps/worker/src/jobs/relationship-profile-score-v2.ts` | `computeRelationshipProfileScoreV2` | V2 bands/caps | **可选** parallel 观测字段；**不**决定 Stage 2 排序 |
| `apps/api/src/modules/matching/matching-relationship-profile-score-v2.ts` | `resolveRelationshipProfileScoreV2Shadow` | API 投影 | 只读参考 |
| `apps/worker/src/jobs/batch-match-match-insights.ts` | `buildWorkerMatchInsightsForBestMatch` | 写 `matchInsights` | **不改**；r4 产出**独立** shadow JSON |
| worker `batch-match.processor` | — | `finalScore` 排序赢家 | **不改** |

### 5.2 设计原则

1. **不重写** 20 维轴相似度公式。  
2. **不改** `computeFinalScoreV1` 签名、权重、调用点。  
3. **不改** worker 当前「按 `finalScore` 选 winner」行为。  
4. r4 仅新增 **双向 wrapper** + shadow 组装。  
5. `matchInsights.scoreShadowV2` 仍为 **观察**（M6 V2）；P7.6 Stage 2 shadow **独立 schema**，`appliedToFinalScore: false`。  
6. 读路径 **不得 throw**；缺画像 → fallback reason（§8）。

### 5.3 与 `scoreShadowV2` 的关系

| 产物 | 决定赢家 | 与 Stage 2 关系 |
|------|----------|-----------------|
| `MatchResult.finalScore` | **是**（worker） | **只读对照**；old/new audit 用 |
| `matchInsights.scoreShadowV2` | **否** | 可并列写入 **observation**（`displayScore100` 等），**不**替代 `mutual20DFit` 排序 |
| `TwentyDBidirectionalRankingShadowV1` | **否** | P7.6 Stage 2 **权威 shadow**（漏斗内） |

## 7. 排序规则

对 **eligible** 且 `mutual20DFit != null` 的候选：

1. `mutual20DFit` **降序**
2. 平局：`AtoB20DFit` **降序**
3. 再平局：`BtoA20DFit` **降序**
4. 再平局：`candidateUserId` **升序**（稳定、可复现）

**输出**：

| 字段 | 规则 |
|------|------|
| `rankedCandidates` | 上述排序后**全量** Stage 1 输入列表（含 ineligible 行，fit 可为 null） |
| `topNCandidateIds` | 前 N 名 eligible（N 默认 = `min(len(selected), 20)` 或 CLI `--topN`） |
| `top2CandidateIds` | 前 **2** 名 eligible |
| `selectedBy20DOnlyCandidateId` | `top2CandidateIds[0]` 或 `rankedCandidates[0]`（仅表示 20D 排序第一，**非** RRM 最终选择） |

**r4 不选择最终 match winner**；最终 2 选 1 交给 **P7.6-r5 RRM Top2 Final Selector**。

## 8. Eligibility / fallback

### 8.1 原则

- 读路径 **不 throw**。  
- 缺数据 → `eligible=false` 或 stage 级 fallback；仍保留 audit 行。

### 8.2 Viewer 级

| 条件 | 行为 |
|------|------|
| `UserProfile` 缺失或有效轴不足 | `stage2TwentyD.top2CandidateIds=[]` · `fallbackReason=VIEWER_PROFILE_MISSING` |
| `UserPreference` 缺失 | 可用 **空 pref** 继续（preference 子分为 0 或默认）；记录 `PREFERENCE_MISSING` 在 `missingSignals` |

### 8.3 Candidate 级

| 条件 | 行为 |
|------|------|
| `UserProfile` 缺失 | `eligible=false` · `CANDIDATE_PROFILE_MISSING` · fits `null` |
| 画像部分轴 null | **可**计分（`computeProfileScore` 跳过 null 轴）；记录 `missingSignals` |
| `SCORE_INPUT_INVALID` | 非法 NaN / 越界 → 该候选 ineligible |
| `SCORE_CALCULATION_FAILED` | 捕获异常 → 该候选 ineligible；**不**中断整批 |

### 8.4 取舍：ineligible 是否留在 `rankedCandidates`

**推荐**：**保留**（与 Stage 1 一致），`AtoB20DFit` / `BtoA20DFit` / `mutual20DFit` 为 `null`，**不进入** `top2CandidateIds`。
