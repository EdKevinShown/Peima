# P7.4-r1d-c — Admin Photo Review API 设计（仅方案）

> 状态：**设计确认稿**；本轮 **不改代码、不写 migration、不做 Admin 页面**。  
> 前置：**P7.4-r1d-b**（`reviewStatus` 字段 + 自动写入规则）、**P7.4-r1d** 总设计。

---

## 1. 一句话结论

**新增独立模块 `AdminPhotoReviewController`（`/admin/photo-review`），复用 `JwtAuthGuard` + `RbacGuard` + 新权限 `manage_photo_review`（授予 `OPERATOR` / `ADMIN`）；MVP 实现 list + detail + approve/reject/needs-reupload；`reset` 与 Audit 写入后置；P7.4-r1d-c 阶段不改 `hasPassingPhoto` / `nextStep`（门禁在 r1d-e 接入）。**

---

## 2. API 范围

| # | 方法 | 路径 | MVP | 说明 |
|---|------|------|-----|------|
| 1 | GET | `/admin/photo-review/items` | **必须** | 分页列表 + 筛选 |
| 2 | GET | `/admin/photo-review/items/:imageId` | **必须** | 单张详情（含完整 `detectionScoreJson`、`reviewNote`） |
| 3 | POST | `/admin/photo-review/items/:imageId/approve` | **必须** | 审核通过 |
| 4 | POST | `/admin/photo-review/items/:imageId/reject` | **必须** | 审核拒绝 |
| 5 | POST | `/admin/photo-review/items/:imageId/needs-reupload` | **必须** | 要求重传 |
| 6 | POST | `/admin/photo-review/items/:imageId/reset` | **后置** | 运营纠错 / 退回队列；r1d-c3 末或 r1d-c4 |

**不做（本轮）**：Admin 前端页面、用户申诉 API、批量审核、自动分配工单。

**模块边界**：`apps/api/src/modules/admin-photo-review/`（或 `admin/photo-review/` 子模块），**不**扩展 `ImagesController`（`/images` 仍为普通用户）。

## 3. RBAC / 权限设计

### 现有能力（可复用）

| 组件 | 路径 | 用途 |
|------|------|------|
| `JwtAuthGuard` | `apps/api/src/modules/auth/jwt-auth.guard.ts` | JWT 认证 |
| `RbacGuard` + `@RequirePermission` | `apps/api/src/common/rbac/rbac.guard.ts` | 权限校验 → 403 |
| `RbacService.checkPermission` | DB `user_roles` + `role_permissions` + env `PEIMA_*_USER_IDS` | |
| `UserRole` | `@peima/shared/constants`：`ADMIN`, `OPERATOR`, `DATA_ANALYST`, `REGULAR_USER` | |
| `AuditService.recordAction` | `apps/api/src/common/audit/audit.service.ts` | 未来写审计（r1d-c4） |

**无** 独立 `AdminGuard`；部分 legacy `AdminController` 用 `PEIMA_ADMIN_USER_IDS` + `adminService.assert*`——Photo Review **不推荐** 仅用 env 白名单，应走 RBAC 以便运营（`OPERATOR`）使用。

### 推荐新增权限

```typescript
// packages/shared/constants/p5-rbac.ts（未来 r1d-c2）
Permission.MANAGE_PHOTO_REVIEW = "manage_photo_review"
```

| 角色 | 是否拥有 |
|------|----------|
| `REGULAR_USER` | 否 |
| `OPERATOR` | **是**（主运营角色） |
| `DATA_ANALYST` | 否（可选只读后续 `view_photo_review`） |
| `ADMIN` | **是** |

实现方式（r1d-c2）：

1. 扩展 `Permission` 枚举 + `ROLE_PERMISSIONS_MAP`。
2. DB seed / migration 插入 `role_permissions`（若项目用表驱动）；或仅靠 map + env 合并（与现网一致）。
3. 控制器：

```typescript
@Controller("admin/photo-review")
@UseGuards(JwtAuthGuard, RbacGuard)
export class AdminPhotoReviewController {
  @Get("items")
  @RequirePermission(Permission.MANAGE_PHOTO_REVIEW)
  list(...) {}
}
```

### 非 admin / 无权限

- 未登录 → `401`（JwtAuthGuard）。
- 已登录无 `manage_photo_review` → **`403 Forbidden`**（与现网 RBAC 一致）。

### reviewedByUserId

- 一律写 **`req.user.userId`**（JWT `sub` / 当前登录运营账号）。
- **禁止** body 传入 `reviewedByUserId`（防伪造）。

## 4. 列表查询设计

### `GET /admin/photo-review/items`

**Query（`ListPhotoReviewItemsQueryDto`）**

| 参数 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `reviewStatus` | string? | `pending_review` | 逗号分隔或重复 query；空 = 不按 review 筛 |
| `detectionStatus` | string? | — | `passed` \| `failed` \| `skipped` |
| `reasonCode` | string? | — | 匹配 `detectionReasonCodes` **或** `reviewReasonCodes` 包含 |
| `hasWarnings` | boolean? | — | `detectionScoreJson.warnings` 非空 |
| `userId` | string? | — | 指定用户 |
| `createdAfter` | ISO date? | — | `createdAt >=` |
| `createdBefore` | ISO date? | — | `createdAt <=` |
| `sort` | `asc` \| `desc`? | **`asc`** | 按 `createdAt`（待审先进先出） |
| `limit` | number? | `20` | max 100 |
| `cursor` | string? | — | `createdAt_id` 复合游标（推荐） |

**不推荐** offset `page` 作为首选（大表性能差）；可提供 `page`+`pageSize` 作为二期。

**默认列表**：`reviewStatus=pending_review`，`sort=asc`（最早待审优先）。

**Prisma 示意**：

```typescript
where: {
  reviewStatus: { in: reviewStatuses },
  detectionStatus: detectionStatus ? detectionStatus : undefined,
  userId: userId ?? undefined,
  createdAt: { gte: createdAfter, lte: createdBefore },
  // hasWarnings: raw SQL jsonb_array_length(warnings) > 0 或应用层过滤（MVP 可应用层）
}
orderBy: [{ createdAt: sort }, { id: sort }]
take: limit + 1
```

### 列表项 DTO（`AdminPhotoReviewListItemDto`）

| 字段 | 说明 |
|------|------|
| `imageId` | `UserImage.id` |
| `userId` | |
| `imageUrl` | 完整 URL（Admin 内网/ VPN）；可选二期 `thumbnailUrl` |
| `detectionStatus` | |
| `detectionReasonCodes` | |
| `detectionSummary` | 从 `detectionScoreJson` 提炼：`faceCount`, `warnings`, `primaryFace.index`, `quality.meanLuma`… |
| `detectionRulesVersion` | |
| `detectedAt` | |
| `reviewStatus` | |
| `reviewReasonCodes` | |
| `reviewedAt` | |
| `reviewedByUserId` | |
| `reviewNote` | **Admin 可见** |
| `createdAt` / `updatedAt` | |

**响应**：

```json
{
  "items": [ ... ],
  "nextCursor": "2026-05-15T10:00:00.000Z_cuidxxx",
  "totalApprox": null
}
```

`totalApprox` 可选（count 慢则省略）。

## 5. 单张详情设计

### `GET /admin/photo-review/items/:imageId`

返回 `AdminPhotoReviewDetailDto`：

- `UserImage` 全字段（含 `reviewNote`）
- `detectionScoreJson` **完整**（含 `primaryFace`、`warnings`）
- `user` 摘要：
  - `userId`（必须）
  - `displayName` / `nickname`：若 `User` 表有则返回
  - **email / phone**：默认 **不返回**；与现网 admin 一致时再开；若返回则 **脱敏**（`u***@domain.com`）

**脱敏建议**：

| 字段 | MVP |
|------|-----|
| userId | 不脱敏（运营需定位） |
| email | 不返回或脱敏 |
| phone | 不返回 |
| imageUrl | 返回（仅 admin 鉴权后） |

## 6. 审核动作语义

**通用**：每次 POST 在**单事务**内更新 `UserImage`；`reviewedAt = now()`，`reviewedByUserId = actorUserId`；`reviewNote` 来自 body.note（trim，可空除非规则要求）。

**不修改**：`detectionStatus`、`detectionReasonCodes`、`detectionScoreJson`（机器结果只读）。

### approve

| 字段 | 值 |
|------|-----|
| `reviewStatus` | `approved` |
| `reviewReasonCodes` | `[]` 或 `[MANUAL_APPROVED]`（推荐 **空数组**，note 承载说明） |
| `reviewedAt` | now |
| `reviewedByUserId` | actor |

### reject

| 字段 | 值 |
|------|-----|
| `reviewStatus` | `rejected` |
| `reviewReasonCodes` | body.reasonCodes（**必填 ≥1**） |
| `reviewedAt` / `reviewedByUserId` / `reviewNote` | 同上 |

### needs-reupload

| 字段 | 值 |
|------|-----|
| `reviewStatus` | `needs_reupload` |
| `reviewReasonCodes` | body.reasonCodes（**必填 ≥1**；应含 `NEEDS_REUPLOAD` 或具体原因码） |
| 其余 | 同上 |

### reset（后置，推荐语义）

用于运营误操作或重新入队：

| 字段 | 值 |
|------|-----|
| `reviewStatus` | 默认 `pending_review`；body 可选 `targetStatus`: `pending_review` \| `not_required` |
| `reviewReasonCodes` | `[]` 或保留 `DETECTION_SKIPPED_REVIEW`（若机器为 skipped） |
| `reviewedAt` | **`null`** |
| `reviewedByUserId` | **`null`** |
| `reviewNote` | **`null`** 或保留历史 note 于 audit only（推荐清空字段，历史在 AuditLog） |

**状态机（简化）**

```text
not_required ──(skipped auto)──► pending_review
pending_review ──approve──► approved
pending_review ──reject──► rejected
pending_review ──needs-reupload──► needs_reupload
* ──reset──► pending_review | not_required
```

非法转换（如 `approved` → `pending_review` 无 reset 权限）→ **409**。

## 7. reasonCodes 白名单

### Admin 可写 `reviewReasonCodes`（动作时）

| Code | 典型动作 |
|------|----------|
| `MANUAL_APPROVED` | approve（可选，推荐不用） |
| `MANUAL_REJECTED` | reject |
| `NEEDS_REUPLOAD` | needs-reupload |
| `FACE_NOT_CLEAR` | reject / needs-reupload |
| `MULTIPLE_FACES_REVIEW` | reject / needs-reupload |
| `SUSPECTED_NON_PERSON` | reject |
| `INAPPROPRIATE_CONTENT` | reject |
| `LOW_QUALITY` | reject / needs-reupload |
| `USER_REQUESTED_REVIEW` | reset / 入队 |
| `MANUAL_OVERRIDE` | 任意 |
| `DETECTION_SKIPPED_REVIEW` | 只读（机器写入）；reset 时可重设 |

**自动写入（r1d-b，非 admin POST）**：`DETECTION_SKIPPED_REVIEW` 等——与 admin 白名单分离校验。

### 校验规则

| 动作 | reasonCodes | note |
|------|-------------|------|
| **approve** | **可选**（默认 `[]`） | 可选，max **500** |
| **reject** | **必填 ≥1**，白名单内 | 建议必填，max 500 |
| **needs-reupload** | **必填 ≥1**，且建议含 `NEEDS_REUPLOAD` | 建议必填，max 500 |
| **reset** | 可选 `[]` | 可选 |

`class-validator`：`@IsIn(WHITELIST, { each: true })`，`@ArrayMinSize(1)` on reject/needs-reupload。

## 8. 是否影响 onboarding nextStep

### 方案比较

| | 方案 1：r1d-c 仅 API | 方案 2：同步接入门禁 |
|---|----------------------|---------------------|
| **行为** | 运营可标 approved/rejected，用户侧仍只看 `detectionStatus` | `hasPassingPhoto` 考虑 `reviewStatus` |
| **优点** | 零回归风险；可分阶段上线 | 拒绝后用户无法继续，产品一致 |
| **风险** | rejected 用户仍可能继续 onboarding | 需改 `OnboardingService` + 前端文案 |
| **推荐阶段** | **P7.4-r1d-c** | **P7.4-r1d-e** |

### 推荐（与用户倾向一致）

**P7.4-r1d-c / c2 / c3：不改 `hasPassingPhoto` / `nextStep`。**

未来 **r1d-e** 门禁草案：

```typescript
function isPassingPhoto(row): boolean {
  if (["rejected", "needs_reupload", "appeal_rejected"].includes(row.reviewStatus)) return false;
  if (["approved", "appeal_approved"].includes(row.reviewStatus)) return true;
  if (row.reviewStatus === "pending_review") return row.detectionStatus in ["passed", "skipped"]; // 继续允许
  return row.detectionStatus in ["passed", "skipped"];
}
```

## 11. 错误处理

| 场景 | HTTP | 说明 |
|------|------|------|
| 未登录 | 401 | Jwt |
| 无权限 | 403 | Rbac |
| imageId 不存在 | 404 | |
| reasonCode 非法 | 400 | 白名单 |
| reject/needs-reupload 无 reasonCodes | 400 | |
| note 超长 | 400 | |
| 非法状态转换 | **409** | 如对已 `approved` 再 reject（除非允许 override 策略） |
| 并发双审 | **409** | `updateMany where id AND reviewStatus = expected`；`count=0` → 409 |
| 已物理删除 | 404 | Prisma `P2025` |

**并发策略（推荐）**：

```typescript
const updated = await prisma.userImage.updateMany({
  where: { id: imageId, reviewStatus: currentStatus },
  data: { ... },
});
if (updated.count === 0) throw new ConflictException("review status changed");
```

POST  body 可选 `expectedReviewStatus`（乐观锁，二期）。
