# P7.5-r4-o3 — Preview Pool 本地手测签收 Closeout

## 1. 签收目标

本轮 **仅做本地手测与文档签收**，不继续修改业务代码。验证并记录以下链路在 **本地 PostgreSQL + 本地 API/Web** 下可重复跑通、结果符合预期：

- **Account（r4-l）**：匹配偏好可选；空偏好不限制；年龄/身高可单侧或留空；`/account` 不展示「照片风格偏好」。
- **Photo preference（r4-k 延续）**：照片风格偏好 **唯一编辑入口** 为 `/onboarding/photo-preference`。
- **Candidate import（r4-h / r4-n / r4-n1）**：`dev-assets/test-user-images/mapping.json` demo-safe；import 报告与幂等。
- **Funnel（r4-m）**：指定 viewer 下异性门控后候选数量充足，不再出现「当前约 0 位」类误判语境。
- **Preview pool 生成与展示（r4-o1 / r4-o2）**：6 人池、`candidateUserId` 与 **source image key** 去重、异性门控；**active pool audit** 输出可用于签收核对。

**边界（本轮不改代码）**：不启用 `APPLY_TO_POOL`；不接云 API；不做 AI 美化/头像、人脸比对、身份认证、颜值评分；**不根据照片自动判断或纠正** `User.gender`。若发现 **P0/P1**（例如门控被绕过、PII 泄漏、生成逻辑破坏生产安全），应 **停止签收** 并在 issue/PR 中说明，**不在本轮文档内做大改**。

## 7. Active Pool Audit 结果

在 **重新生成预览池之后** 运行 `p75-r4-o2-preview-pool-active-audit`（§3）。对输出 JSON 中 **`items`（最多 6 条）** 逐项核对：

| 检查项 | 签收要求 |
|--------|-----------|
| `duplicate_candidate_user_id` | 全部为 **false** |
| `duplicate_image_source_key` | 全部为 **false** |
| `violates_opposite_gender_gate` | 全部为 **false** |
| `is_viewer_self` | 全部为 **false** |
| `source_image_key` | 6 条 **可区分**（互不相同） |

**若任一为 true**：本节签收标为 **未通过**，并记录原因（例如旧 active pool 未刷新、DB 性别与 mapping 未同步 import、或本地数据被手工污染）。**不在本轮仅文档任务中直接改代码修复**。

**若首张仍「视觉上像男性」，但 `candidate_gender_raw` / DB 为 `female`**：归类为 **demo 数据质量问题**（人工 mapping / 历史导入与视觉不一致），**不阻断** r4 Preview Pool 链路签收；**不**在本轮引入 AI 性别识别或自动改写 `User.gender`。

## 8. 已知限制

- **素材结构**：`dev-assets/test-user-images` 当前 **female 多、male 少**（见 mapping `_devNote_r4o1` / `_devNote_r4o2`）。
- **Male viewer**：可完整验收 **6 人 female** preview pool（在 funnel `after_opposite_gender_gate_final >= 6` 前提下）。
- **Female viewer**：若 **只依赖** 本文件夹导入的候选，**可能无法凑满 6 名 male** —— **dev 素材限制**，需在文档或后续迭代中补充男性测试图或依赖其他种子数据。
- **视觉 vs DB 性别**：若仅视觉疑似与 `User.gender` 不符，按 **demo 数据质量** 记录；**不**接 AI / 人脸识别 / 自动性别判断；**不**在本轮放宽产品门控。
