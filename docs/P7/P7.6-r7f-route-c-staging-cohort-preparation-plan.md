## 3. Route C 目标

### 3.1 最低目标

| # | 目标 |
|---|------|
| 1 | **5** 个 staging viewers |
| 2 | 每个 viewer **≥6** candidates |
| 3 | viewer + 每 candidate：**passed image** · Cloud Vision tags · meaningful **20D** · **user_preferences** |
| 4 | 尽量每个 viewer 有 **`MatchResult`** |
| 5 | 尽量每个 viewer 有 **M6** `rrmV2Top2Selector` 对照 |

### 3.2 推荐目标

| # | 目标 |
|---|------|

| MatchResult / M6 | 多数缺失 | **尽量齐全** |
| PM 证据强度 | 技术 smoke | **PM 主证据** |

## 4. 数据准备原则

### 4.1 优先（按顺序）

| 优先级 | 策略 |
|--------|------|
| **1** | 使用**真实** dev/staging user（非 r7c4/r7c5 手工 pool） |
| **2** | 对已有 **passed** images 做 Cloud Vision backfill |
| **3** | 使用**真实或半真实**问卷 20D（`nonNull20DCount` ≥4，推荐 ≥18） |
| **4** | 使用**真实**偏好 `user_preferences` |
| **5** | 跑 **batch match** 让 legacy worker **自行**产生 `MatchResult` / M6 insights |

### 4.2 避免

| 禁止 / 避免 | 原因 |
|-------------|------|
| 纯 **synthetic** onboarding pool（r7c5 模式） | 不能支撑 PM 商业判断 |
| 过多 **dev-only seed**（profile/preference 手工向量） | 标记 `seedDependent` · 降 PM 证据强度 |
| 绕过 **gender / preference** gate | 审计无效 |
| **手写** `MatchResult` / `matchInsights` | 伪造 legacy 对照 |
| **手写** `finalScore` | 污染主链 |
| **修改** worker 排序结果 | 非 shadow 审计 |

| `seedDependent` | **`false`** |

**选型 SQL：** 复用 r7c §4 viewer selection；优先 `recommendedForBatch=true` 且 `hasMatchResult` + `hasM6RrmTop2` 行；**排除** r7d 三个 synthetic viewer（除非 PM 明确纳入对照）。

## 6. Candidate cohort 设计

每个 viewer 的 **candidates** 须满足：

| # | 要求 |
|---|------|
| 1 | 至少 **6** 人（推荐 6–10） |
| 2 | **不包含** viewer 自身（self candidate check = 0） |
| 3 | 通过 **gender / preference** gate（与 r3b 一致） |
| 4 | **usable live vision**（`detectionStatus=passed` + score JSON） |
| 5 | **meaningful 20D** `user_profile` |
| 6 | **`user_preferences`** 行存在 |
| 7 | 尽量覆盖不同 **photoVisualTags** / **20D** / **RRM** 节奏差异（避免 6 人向量完全相同） |

**池来源（优先级）：**

1. 既有 **active** `onboarding_photo_preview_pools`（非 dev-p76-r7c5-*）  
2. staging 导入 cohort + 正常 onboarding 流程生成的池  
3. **不**新建 dev-only synthetic pool（除非 PM 书面例外并标注）

---

## 7. Batch match / M6 对照准备

| 项 | 说明 |
|----|------|
| **MatchResult** | 在 **dev/staging** 跑正式 **batch-match**，由 legacy worker **写入**；**禁止**手写 JSON |
| **finalScore** | **禁止**手工修改 |
| **worker 排序** | **禁止**事后改序 |
| **M6** | 若 batch 产出 `matchInsights.rrmV2Top2Selector`，作为 r6b `--compareM6=true` 对照 |
| **M6 缺失** | 记录 `comparison unavailable`；**不阻塞**单 viewer 技术审计，但 **降低** PM 证据强度 |
| **P7.6 shadow** | r3b→r6b 仍 **dry-run** · 全部 `applied*=false` |

**与 r7d 对比：** r7d 无 MatchResult → `differenceStage` 多为 `no_change` 且 legacy 为空；Route C 应出现 **可解释的** `legacy_mismatch` / `differs_from_m6_top2` 等（若真实数据如此），供 PM 审阅。

## 8. 每个 viewer 执行流程（r7g 执行）

对每个入选 staging viewer（`--dryRun=true`）：

| Step | 动作 | 产出 |
|------|------|------|
| 1 | **r3b** PhotoVisual First Pool audit | `r3b.json` |
| 2 | **r4b** 20D Bidirectional Ranking（r3b 的 6 人 `--candidateUserIds`） | `r4b.json` |
| 3 | **r5b** RRM Top2（r4b Top2 + 20D winner） | `r5b.json` |
| 4 | **r6b** End-to-end（**优先** stage JSON 路径） | `r6b.json` |
| 5 | PM 填写 §9 Evidence Table 一行 | closeout |

**r6b 路径（推荐）：**

```text
--stage1AuditJsonPath=artifacts/p76/r7g/<V>/r3b.json
--stage2AuditJsonPath=artifacts/p76/r7g/<V>/r4b.json
--stage3AuditJsonPath=artifacts/p76/r7g/<V>/r5b.json
--compareLegacy=true
--compareM6=true
```

**目的：** 保留 stage 间 **mutual** 分数；避免仅显式 id 跑 r6b 导致分数丢失（见 [r7c §7.4](./P7.6-r7c-multi-sample-audit-execution-runbook.md)）。
