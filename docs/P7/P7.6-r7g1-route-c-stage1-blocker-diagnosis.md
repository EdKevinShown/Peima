## 4. 初步判断

### 4.1 不是 r7j4 cohort 缺失

| 检查 | 结果 |
|------|------|
| active pool 存在 | **是**（5/5） |
| 每 pool 6 items | **是** |
| candidate_ids 非空 | **是** |
| r7g §4 `recommendedForRouteC` | **5** |

**结论：** 阻塞**不是**「没有 clean pool」，而是 **audit runner 与 pool 数据未对齐**。

### 4.2 更可能根因（技术）

| # | 假设 | 说明 |
|---|------|------|
| 1 | **r3b 未读 pool items** | `p76-photovisual-first-pool-db-adapter` 中 `collectGatedCandidatesReadOnly` **全库扫描** `users`（`images` + `relationProfile`），**不**读取 `onboarding_photo_preview_pool_items`；`sourcePoolType=onboarding_gated_cohort` 为标签，**非**「从 active pool 取候选」 |
| 2 | **eligibility 与 Route C pool 口径不一致** | Stage1 `evaluatePhotoVisualPairEligibility` 要求 **gender / preference / vision / styleTags** 等；r7j4 readiness 仅要求 pool 内 vision+20D+pref **计数**，**不**保证通过 r3b gate |
| 3 | **GENDER_GATE** | r7j4 多数 viewer/candidate 为 **female**；二元 gender gate 要求**异性** → 同池内大量候选可能被拒 |
| 4 | **PREFERENCE_GATE** | 多人 `preferredCities={Sydney}` · `city=上海` → preference hard gate 可能全拒 |
| 5 | **MISSING_STYLE_TAGS** | r3b 使用 `user_images.styleTags`；r7j4 主证据来自 **Cloud Vision `photoVisualTags`**（`detectionScoreJson`），**styleTags 常为空** → 双空触发 `MISSING_STYLE_TAGS` |
| 6 | **扫描窗口** | `limit=12` 批扫描可能**未命中** pool 内 8 人 cohort（取决于 `users.createdAt` 排序） |

**综合：** Route C **readiness SQL** 与 **r3b Stage1 shadow** 是**两套口径**；当前 r7g 命令无法将 r7j4 pool **投影**为 `selectedCandidateIds`。
