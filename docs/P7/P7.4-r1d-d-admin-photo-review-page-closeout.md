# P7.4-r1d-d — Admin Photo Review 页面 Closeout

## 本轮目标

在前端 Admin 区域新增 **照片审核** 页面，供运营 / 管理员查看待审照片并执行 approve / reject / needs-reupload。仅改前端，不改后端 schema / 检测 / onboarding 门禁。

## 新增页面

| 路径 | 组件 |
|------|------|
| `/admin/photo-review` | `apps/web/src/pages/AdminPhotoReviewPage.jsx` |

路由注册：`apps/web/src/router/index.jsx`  
首页「更多」内链增加「照片审核」入口（与 AI 模拟内部分诊并列）。

## 新增前端 API client

`apps/web/src/api/adminPhotoReview.ts`

| 函数 | 方法 |
|------|------|
| `listAdminPhotoReviewItems(params)` | GET `/admin/photo-review/items` |
| `getAdminPhotoReviewItem(imageId)` | GET `/admin/photo-review/items/:imageId` |
| `approveAdminPhotoReviewItem(imageId, body)` | POST `.../approve` |
| `rejectAdminPhotoReviewItem(imageId, body)` | POST `.../reject` |
| `needsReuploadAdminPhotoReviewItem(imageId, body)` | POST `.../needs-reupload` |

辅助：

- `buildAdminPhotoReviewListQuery` — query 序列化
- `validateReviewReasonCodes` — 前端提交前校验
- `PHOTO_REVIEW_REASON_CODES` — 白名单常量

复用 `authHeaders()` / `baseUrl`；专用错误文案（401 / 403 / 404 / 400 / 409 / 网络）。

## 支持的筛选

| 控件 | 默认 |
|------|------|
| reviewStatus | `pending_review` |
| detectionStatus | 全部 |
| reasonCode | 文本 |
| hasWarnings | 全部 / 有 / 无 |
| userId | 文本 |

说明：后端列表 API 在未传 `reviewStatus` 时仍默认 `pending_review`；下拉「全部」当前与默认等效（未改后端）。

支持 **cursor 加载更多**。

## 支持的审核动作

详情弹窗内：

| 动作 | reasonCodes | note |
|------|-------------|------|
| Approve | 不需要 | 可选 ≤500 |
| Reject | 多选 ≥1 | 可选 ≤500 |
| Needs reupload | 多选 ≥1（默认勾选 NEEDS_REUPLOAD） | 可选 ≤500 |

成功后刷新详情；若当前筛选为 `pending_review` 且状态已变更，从列表移除该行。

提交中按钮 disabled；错误以 `role="alert"` / `role="status"` 展示。

## 错误处理

| 状态 | 提示 |
|------|------|
| 401 | 登录已失效 |
| 403 | 无权限访问照片审核 |
| 404 | 照片不存在 |
| 400 | 参数校验失败 |
| 409 | 状态已被他人更新，请刷新 |
| 网络 | 稍后重试 |

## 普通用户边界

- 本页仅 Admin 路由；普通用户 onboarding / images 流程 **不** 展示 `reviewNote`。
- **未** 将 `reviewStatus` 接入 onboarding `nextStep`。
