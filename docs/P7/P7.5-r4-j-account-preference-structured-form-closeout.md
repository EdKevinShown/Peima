# P7.5-r4-j — Account / Preference 结构化表单 closeout

## 本轮目标

将 **`/account`**（`AccountPage.jsx`）中资料与匹配偏好从「自由填空」改为 **下拉 / 单选 / chip 多选**，与后端 **枚举 + 范围校验** 对齐，便于偏好硬门槛、 onboarding **photo preview gender gate (`User.gender`)** 等链路使用结构化数据。

**地区 / 学历 / 职业词表的「中国化 + 省级地区」修订** 见 **[P7.5-r4-j1-account-form-china-localization-closeout.md](./P7.5-r4-j1-account-form-china-localization-closeout.md)**（取代本文曾列出的澳州城市枚举等旧表述）。

## 为什么要从填空改为选择题

- **Gender gate / 预览池**：预览生成依赖 `User.gender` 为 **`male` | `female`**；结构化采集减少空串与乱码。
- **偏好硬门槛**：`preference-hard-gate` 与城市、学历、职业等字段做 **集合 / 区间** 比较；自由文本会导致「写得进、筛不动」。
- **不接云 API、不用 AI**：标签与枚举全部来自封闭词表。

## 字段落库（审计结论）

| 分组 | 字段 | Prisma | 备注 |
|------|------|--------|------|
| 资料 | nickname, gender, age, city, height, education, occupation, relationshipGoal, bio | **`users`** | 均在 `User`；无单独 `UserProfile` 扁平字段以外的迁移。 |
| 偏好 | min/max age & height, preferredCities, *_Preferences, styleTags | **`user_preferences`** | `UserPreference` one-to-one。 |

**本轮未做 DB migration**：沿用现有字符串 / 数组列；枚举合法性由 API + UI 约束。

### `POST /users`（注册用 CreateUserProfileDto）

仍为较宽校验（兼容种子 / 脚本）；**账号页编辑**走 **`PATCH /users/:id`**（`UpdateUserProfileDto`，本轮收紧）。

## 性别必填规则（Account 页面）

- 前端：**未选择男/女时禁止提交「保存资料」**，提示错误文案。
- 后端：**若 PATCH 传入 `gender`，仅允许 `male` | `female`**（class-validator）。
- onboarding **preview generate**：空 / 非法 `User.gender` 继续 **`BadRequestException`**（参见 r4-i），用户需回本页补全。

## 选项列表（与 `@peima/shared/constants` 一致）

详见 **`p75-r4-j-account-form.ts`**；**省级地区、中国学历、中国职业** 的最终清单以 **r4-j1** 文档为准。

- **性别**：`male`、`female`（前端展示「男」「女」）。
- **年龄**：18–60（整数，`User.age`）。
- **身高**：140–210 cm，`User.height`。
- **所在地 / 偏好地区**：字段名仍为 `city` / `preferredCities`，存 **省级地区** 封闭词表（非地级市 / 外国城市）。
- **关系目标**：五种中文枚举。
- **风格标签**：与 **P7.5 photoVisualTags** 同一 **18** 词条表；`onboarding-vision-taxonomy.ts` **从 shared 引入**，避免漂移。

匹配偏好：`preferredCities` 等与资料同一套省级词表；年龄与身高上下限 **独立下拉**，且 **min ≤ max**。

## 前端校验（AccountPage.jsx）

- 必选性别；昵称 2–20（若填写）；bio ≤ 200。
- minAge/maxAge、minHeight/maxHeight：成对出现时校验 min ≤ max。
- styleTags：**仅 chip 可选**，无自由输入。
- **PUT 偏好**：始终提交当前 chip 选中结果（含空数组）；服务端仍要求至少一项「可匹配维度」（与原有 `preferenceGateDenominator` 逻辑一致）；**仅靠 styleTags 无法满足新建偏好**（styleTags 不计入 denom）。
- Account **`select`** 控件统一高度、padding 与自定义箭头，占位文案为「请选择」，修正文字与原生箭头视觉不居中问题（仅 UI，无业务变更）。

## 后端校验

- **`UpdateUserProfileDto`**：`gender`/`city`/`education`/`occupation`/`relationshipGoal` 使用 `@IsIn` 白名单；`age`/`height` 边界 18–60、140–210；`nickname` 2–20；`bio` max 200。
- **`CreateOrUpdatePreferenceDto`**：年龄 / 身高整数范围与上同；`styleTags` 最大条数 24。
- **`PreferencesService`**：`assertStructuredPreferenceLists` 校验各数组元素属于对应白名单；未知值 **400**。

## 对 onboarding preview gender gate 的影响

用户在本页将 **`User.gender` 存为 `male`/`female`** 后，`OnboardingPhotoPreviewPoolService.generate()` 可正常走异性过滤；若仍提示完善性别，前端已增加 **引导文案** 指向本页。

## 测试结果

推荐回归（避免宽泛的 `profile|users` 误匹配其它套件）：

```bash
pnpm --filter @peima/api test -- "account-form.dto|preferences.service.upsert-gate|onboarding-preview-gender|onboarding-photo-preview-pool|onboarding-vision-profile"
pnpm --filter @peima/web run build
pnpm --filter @peima/shared build
```

会话内：`@peima/web` **build 通过**；上述 **Jest 窄范围用例通过**。全量 `pnpm install` 若在 Windows 上触发 **Prisma EPERM rename**，属环境文件锁问题，与本轮代码无关。
