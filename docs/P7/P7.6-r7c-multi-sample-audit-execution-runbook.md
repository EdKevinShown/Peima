## 4. Viewer 选择 SQL（只读）

在 **dev/staging** 库执行；**禁止** UPDATE/INSERT/DELETE。表名来自 Prisma `@@map`。

### 4.1 辅助：单用户画像维度非空计数

P7.6-r4b 使用 `user_profile` 上 G1R 维度（与 `p76-20d-bidirectional-ranking-profile-score` 一致）。下列 SQL 用 **6 个核心维度** 近似 `meaningful 20D`（可按代码扩展为全量维度列表）。

```sql
-- P7.6-r7c: candidate viewers for multi-sample audit (READ-ONLY)
-- Run against dev/staging only. Adjust LIMIT as needed.

WITH profile_dims AS (
  SELECT
    up."userId",
    (
      (CASE WHEN up."relationshipPace"    IS NOT NULL THEN 1 ELSE 0 END) +
      (CASE WHEN up."emotionalStability" IS NOT NULL THEN 1 ELSE 0 END) +
      (CASE WHEN up."communicationStyle" IS NOT NULL THEN 1 ELSE 0 END) +
      (CASE WHEN up."conflictHandling"   IS NOT NULL THEN 1 ELSE 0 END) +
      (CASE WHEN up."lifePace"           IS NOT NULL THEN 1 ELSE 0 END) +
      (CASE WHEN up."socialNeed"         IS NOT NULL THEN 1 ELSE 0 END)
    ) AS non_null_core_dim_count
  FROM user_profile up
),
viewer_vision AS (
  SELECT
    ui."userId",
    BOOL_OR(
      ui."detectionStatus" = 'passed'
      AND ui."detectionScoreJson" IS NOT NULL
    ) AS has_live_vision
  FROM user_images ui
  GROUP BY ui."userId"
),
onboarding_pool AS (
  SELECT
    opp."userId" AS viewer_user_id,
    COUNT(DISTINCT oppi."candidateUserId") AS candidate_pool_count
  FROM onboarding_photo_preview_pools opp
  JOIN onboarding_photo_preview_pool_items oppi ON oppi."poolId" = opp."id"
  WHERE opp."status" = 'active'
  GROUP BY opp."userId"
),
candidate_vision AS (
  SELECT
    oppi."userId" AS viewer_user_id,
    COUNT(DISTINCT oppi."candidateUserId") FILTER (
      WHERE EXISTS (
        SELECT 1 FROM user_images ci
        WHERE ci."userId" = oppi."candidateUserId"
          AND ci."detectionStatus" = 'passed'
          AND ci."detectionScoreJson" IS NOT NULL
      )
    ) AS candidate_with_vision_count
  FROM onboarding_photo_preview_pool_items oppi
  JOIN onboarding_photo_preview_pools opp ON opp."id" = oppi."poolId" AND opp."status" = 'active'
  GROUP BY oppi."userId"
),
candidate_profile AS (
  SELECT
    oppi."userId" AS viewer_user_id,
    COUNT(DISTINCT oppi."candidateUserId") FILTER (
      WHERE pd_c.non_null_core_dim_count >= 4
    ) AS candidate_with_20d_profile_count
  FROM onboarding_photo_preview_pool_items oppi
  JOIN onboarding_photo_preview_pools opp ON opp."id" = oppi."poolId" AND opp."status" = 'active'
  LEFT JOIN profile_dims pd_c ON pd_c."userId" = oppi."candidateUserId"
  GROUP BY oppi."userId"
),
candidate_pref AS (
  SELECT
    oppi."userId" AS viewer_user_id,
    COUNT(DISTINCT oppi."candidateUserId") FILTER (
      WHERE cp."userId" IS NOT NULL
    ) AS candidate_with_preference_count
  FROM onboarding_photo_preview_pool_items oppi
  JOIN onboarding_photo_preview_pools opp ON opp."id" = oppi."poolId" AND opp."status" = 'active'
  LEFT JOIN user_preferences cp ON cp."userId" = oppi."candidateUserId"
  GROUP BY oppi."userId"
),
latest_match AS (
  SELECT DISTINCT ON (mr."userId")
    mr."userId",
    mr."id" AS match_result_id,
    mr."candidateUserId",
    (mr."matchInsights" ? 'rrmV2Top2Selector') AS has_m6_rrm_top2
  FROM match_results mr
  ORDER BY mr."userId", mr."updatedAt" DESC, mr."createdAt" DESC
)
SELECT
  u."id" AS "viewerUserId",
  COALESCE(vv.has_live_vision, false) AS "hasLiveVision",
  COALESCE(pd.non_null_core_dim_count, 0) AS "nonNull20DCount",
  (pref."userId" IS NOT NULL) AS "hasPreference",
  COALESCE(op.candidate_pool_count, 0) AS "candidatePoolCount",
  COALESCE(cv.candidate_with_vision_count, 0) AS "candidateWithVisionCount",
  COALESCE(cprof.candidate_with_20d_profile_count, 0) AS "candidateWith20DProfileCount",
  COALESCE(cpref.candidate_with_preference_count, 0) AS "candidateWithPreferenceCount",
  (lm."userId" IS NOT NULL) AS "hasMatchResult",
  COALESCE(lm.has_m6_rrm_top2, false) AS "hasM6RrmTop2",
  (
    COALESCE(vv.has_live_vision, false)
    AND COALESCE(pd.non_null_core_dim_count, 0) >= 4
    AND pref."userId" IS NOT NULL
    AND COALESCE(op.candidate_pool_count, 0) >= 6
    AND COALESCE(cv.candidate_with_vision_count, 0) >= 6
    AND COALESCE(cprof.candidate_with_20d_profile_count, 0) >= 6
    AND COALESCE(cpref.candidate_with_preference_count, 0) >= 6
  ) AS "recommendedForBatch"
FROM users u
LEFT JOIN viewer_vision vv ON vv."userId" = u."id"
LEFT JOIN profile_dims pd ON pd."userId" = u."id"
LEFT JOIN user_preferences pref ON pref."userId" = u."id"
LEFT JOIN onboarding_pool op ON op.viewer_user_id = u."id"
LEFT JOIN candidate_vision cv ON cv.viewer_user_id = u."id"
LEFT JOIN candidate_profile cprof ON cprof.viewer_user_id = u."id"
LEFT JOIN candidate_pref cpref ON cpref.viewer_user_id = u."id"
LEFT JOIN latest_match lm ON lm."userId" = u."id"
WHERE u."id" <> 'cmo7ksq8s00006znosryc9k0n'  -- exclude Batch 0 baseline (already audited)
ORDER BY "recommendedForBatch" DESC, "hasMatchResult" DESC, "candidatePoolCount" DESC
LIMIT 30;
```

**说明：**

| 字段 | 含义 |
|------|------|
| `hasLiveVision` | viewer 至少一张 `detectionStatus=passed` 且 `detectionScoreJson` 非空 |
| `nonNull20DCount` | viewer `user_profile` 核心维度非空数（≥4 视为 meaningful） |
| `candidatePoolCount` | active onboarding preview pool 去重候选数 |
| `recommendedForBatch` | 满足 r7b §4 纳入条件的启发式布尔 |

**优先手动复核：** `recommendedForBatch=true` 的前 **5** 行；排除 gender 空、明显测试账号、需大规模 seed 的池。

**r7c1 实测（dev DB）：** `recommendedForBatch=true` → **0**。见 [r7c1 closeout](./P7.6-r7c1-viewer-selection-data-readiness-closeout.md)。最接近 partial：`cmp70ft7a001e6znksjb2jo03`（缺 viewer 20D · 4/6 候选 profile · 无 MatchResult/M6）。

## 6. Per-viewer 执行流程

```text
FOR each viewer V in First Batch (includeInBatch=yes):

  mkdir artifacts/p76/r7c/<V>/

  1. r3b  → artifacts/p76/r7c/<V>/r3b.json
     IF selectedCandidateIds empty:
       log blocker: VISION_NOT_OK | GENDER_GATE | PREFERENCE_GATE |
                    EMPTY_PHOTO_VISUAL_TAGS | MISSING_STYLE_TAGS | OTHER
       → mark runnable=no, SKIP to next viewer

  2. Extract candidateUserIds from r3b.json (shadow.stage1PhotoVisualPool.selectedCandidateIds
     or top-level selectedCandidateIds)

  3. r4b  → r4b.json
     IF top2CandidateIds empty:
       log: CANDIDATE_PROFILE_MISSING | PREFERENCE_MISSING | VIEWER_PROFILE_MISSING
       IF seed applied → seedDependent=true
       → runnable=no OR continue with partial (document in r7d)

  4. Extract top2CandidateIds, selectedBy20DOnlyCandidateId from r4b.json

  5. r5b  → r5b.json
     IF selectedByRrmCandidateId empty:
       log: VIEWER_RRM_PROFILE_MISSING | CANDIDATE_RRM_PROFILE_MISSING | TOP2_NOT_AVAILABLE
       note fallback to 20D winner if any

  6. r6b  → r6b.json  (prefer stage JSON paths)
     Verify: finalShadow.selectedCandidateId, legacyComparison, applied all false

  7. Append row to §9 Evidence table; PM fills verdict in r7d
```

| Blocker | 动作 |
|---------|------|

| RRM 信号不足 | 记录 `insufficient_signal`；若回退 20D winner，在 r7d 注明 |
