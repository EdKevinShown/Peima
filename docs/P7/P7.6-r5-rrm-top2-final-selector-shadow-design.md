## 5. RRM 双向定义

### 5.1 语义（产品）

| 符号 | 含义 |
|------|------|
| **AtoBRrmFit** | **Viewer（A）** 的关系推进节奏、边界与压力耐受，对 **candidate（B）** 是否「顺、可持续、低越界风险」 |
| **BtoARrmFit** | **Candidate（B）** 对 **viewer（A）** 的反向评估 |
| **mutualRrmFit** | 双向关系推进综合适配度；用于 Top2 内 **2 选 1** |

关注维度（与 [P7.6 plan §5](./P7.6-bidirectional-mutual-matching-system-plan.md) 一致）：

- 推进快慢是否匹配 · 主动/被动互补 · 互动频率  
- 边界感冲突 · 冷场/误解/越界风险 · 修复潜力  

### 5.2 计算建议（r5a 锁定）

**推荐 — 短板敏感（与 Stage 2 harmonic 对齐）**：

```text
mutualRrmFit = harmonicMean(AtoBRrmFit, BtoARrmFit)

harmonicMean(a,b) = (a>0 && b>0) ? 2ab/(a+b) : 0
```

**备选 — 保守 min（强调双向门槛）**：

```text
mutualRrmFit = min(AtoBRrmFit, BtoARrmFit) + ε * tieBreaker
```

**设计原则**：

- RRM 是**最后 2 选 1**，不应让**单向高分**掩盖**单边压力/越界/节奏不合**。  
- `rhythmRiskFlags` · `pressureRiskFlags` · `boundaryRiskFlags` 高时，应在排序中**降级**（§8），而非仅看 raw fit。

### 5.3 与 20D 的区分

| 层 | 问题 |
|----|------|
| **20D** | 画像/偏好兼容 — 「合不合适」 |
| **RRM** | 关系推进节奏 — 「推进起来顺不顺、稳不稳」 |

同一对用户可在 20D 接近时，因 RRM 风险 flags 不同而在 Stage 3 分出胜负。

type RrmTop2FinalSelectorShadowV1 = {

    appliedToPool: false;
    appliedToFinalScore: false;
    appliedToMatchResult: false;

  };

### 7.3 `RrmRankedCandidateV1`

```typescript
type RrmRankedCandidateV1 = {
  candidateUserId: string;
  rank: number;                         // 1-based within Top2
  AtoBRrmFit: number | null;
  BtoARrmFit: number | null;
  mutualRrmFit: number | null;
  rhythmRiskFlags: string[];
  pressureRiskFlags: string[];
  boundaryRiskFlags: string[];
  repairPotentialSignals: string[];
  missingSignals: string[];
  fallbackReason: RrmFallbackReason | null;
  eligible: boolean;
};
```

### 7.4 `wouldChange20DWinner`

```text
wouldChange20DWinner =
  selectedByRrmCandidateId != null
  && selectedBy20DOnlyCandidateId != null
  && selectedByRrmCandidateId !== selectedBy20DOnlyCandidateId
```

用于 PM / old-new audit：**RRM 是否会在 Top2 内推翻 20D-only 赢家**（shadow 对照，不写 DB）。

## 8. 排序规则

在 `evaluatedCandidateIds`（有效 Top2 子集）上排序：

| 优先级 | 键 | 方向 |
|--------|-----|------|
| 1 | `mutualRrmFit` | desc |
| 2 | risk flag 总数（`rhythm` + `pressure` + `boundary`） | asc |
| 3 | `repairPotentialSignals.length` | desc |
| 4 | `candidateUserId` | asc（稳定 tie-break） |

**输出**：

- `stage3Rrm.rankedCandidates`（长度 ≤ 2）  
- `selectedByRrmCandidateId` = rank 1 且 `eligible=true` 的 `candidateUserId`  
- `wouldChange20DWinner`（§7.4）  
- `finalShadow.stage3SelectedCandidateId` = `selectedByRrmCandidateId`（shadow 语义；**非** `MatchResult` 字段）

### 8.1 信号不足时的默认

```text
IF mutualRrmFit 无法区分 OR 全员 ineligible OR RRM_INSUFFICIENT_SIGNAL:
  selectedByRrmCandidateId = selectedBy20DOnlyCandidateId
  wouldChange20DWinner = false
  fallbackReason = RRM_INSUFFICIENT_SIGNAL
```

## 9. Eligibility / fallback

### 9.1 候选数量

| 条件 | 行为 |
|------|------|
| `top2CandidateIds.length < 2` | `fallbackReason = TOP2_NOT_AVAILABLE` · `selectedByRrmCandidateId = null` · **不进入** RRM 评分 |
| `top2CandidateIds.length === 2` | 正常评估 |

### 9.2 Profile / 输入

| 条件 | 行为 |
|------|------|
| viewer 缺 RRM rhythm profile | `VIEWER_RRM_PROFILE_MISSING` · 回退 `selectedBy20DOnlyCandidateId` |
| 某 candidate 缺 profile | `CANDIDATE_RRM_PROFILE_MISSING` · 该候选 `eligible=false`；若仅 1 人 eligible 则 winner 为另一人或 fallback |
| NaN / 非有限分数 | `RRM_INPUT_INVALID` |
| 计算异常 | `RRM_SCORE_CALCULATION_FAILED` · **不 throw** |

### 9.3 Fallback reason 枚举

```text
TOP2_NOT_AVAILABLE
VIEWER_RRM_PROFILE_MISSING
CANDIDATE_RRM_PROFILE_MISSING
RRM_INPUT_INVALID
RRM_SCORE_CALCULATION_FAILED
RRM_INSUFFICIENT_SIGNAL
```

## 11. 与现有 M6 / RRM 的关系

| 维度 | M6 RRM V2 Top2（现有） | P7.6-r5 Stage 3（新） |
|------|------------------------|----------------------|
| **候选集** | worker pool 全量 scored 行 | Stage 2 **固定 Top2** |
| **评分输入** | `scoreShadowV2.displayScore100` | normalized **RRM rhythm** input（r5a 定义） |
| **写入** | `matchInsights`（env 门控） | P7.6 funnel shadow JSON / audit stdout |
| **改 winner** | **否**（shadow / display） | **否** |
| **替换关系** | **不直接替换** | 并行 funnel shadow；old/new audit 对比 |

**设计立场**：

- P7.6-r5 是 **Photo → 20D → RRM** 漏斗的 Stage 3 shadow，**不是** M6 主链的重写。  
- r5a/r5b **可复用** M6 的 `contextFlags` 命名风格、`guardrails` 思想、`riskFlags` 分类，但输入边界不同。  
- `comparisons.m6RrmV2Top2CandidateIds` 仅供审计：**M6 Top2 与 P7.6 Top2 可能不同**（候选集不同）。

## 14. 风险

| 风险 | 缓解 |
|------|------|
| RRM **过早替代** 20D winner 且无 PM 解释 | `wouldChange20DWinner` + `reasonSummary`；old/new audit |
| **误写** `MatchResult` / `matchInsights` | `appliedToMatchResult: false` 硬编码 · r5b `--dryRun=true` |
| **误改** `displayCandidateUserId` | 文档 + 代码审查边界（§6） |
| 与 **M6 `rrmV2Top2Selector`** 混淆 | 命名 `stage3Rrm` · 独立 `schemaVersion` |
| RRM score **缺少稳定 profile** | r5a 先用 normalized input；r5b 只读 DB adapter |
| **risk flags 过度解释** | flags 仅排序降级 + audit；不自动改画像 |
| PM 难解释 RRM 推翻 20D | 输出 `rankedCandidates` breakdown + comparisons |
| **old/new audit 缺失** | r6 阶段对照 worker winner / M6 Top2 / P7.6 funnel |
