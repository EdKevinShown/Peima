## 3. Smoke behavior

### Default (unchanged)

- `P76_SMOKE_EXPECT_RESULT_STATE_CONTRACT` unset or not `1`
- `PEIMA_P76_RESULT_STATE_CONTRACT_ENABLED` not set by the script
- Same read-path display / persistence assertions as P7.6-r9b
- 404 on no row when API flag off (script does not enable contract flag)

### Contract mode (opt-in)

Set before running r9b:

```bash
P76_SMOKE_EXPECT_RESULT_STATE_CONTRACT=1
```

The script sets `PEIMA_P76_RESULT_STATE_CONTRACT_ENABLED=1` on the in-process Nest app (no external API restart needed for this harness).

Assertions on **HTTP 200**:

| Check | Rule |
|-------|------|
| `contractVersion` | `"p7.10-r4a-result-state-contract-v1"` |
| `resultState` | One of `ready`, `safe_fallback`, `matching_pending`, `no_result` |
| `matching_pending` | `queue.status` ∈ `waiting` \| `processing` \| `ready` |
| `no_result` | `noResult.reason` present |
| `ready` / `safe_fallback` | `candidateUserId` or `displayCandidateUserId` present; then **existing** read-path display / DB unchanged checks apply |

| `resultState` | Pass rule in contract mode |
|---------------|----------------------------|
| `matching_pending` | Contract shape only (does not require persisted `MatchResult` row) |
| `no_result` | Contract shape only |
| `ready` / `safe_fallback` | Contract shape **plus** legacy r9b read-path PASS criteria |

Artifacts: `artifacts/p76/r9b/http-get-smoke-results.json` includes `resultState`, `contractVersion`, `resultStateContractPass`, `resultStateContractErrors`, `resultStateContractOnly`.

### External API only

If hitting a separately started API (not this script), set `PEIMA_P76_RESULT_STATE_CONTRACT_ENABLED=1` on the API process **and** use contract-mode expectations in your client (or run this script’s in-process path).
