# P7.4-r1d-c3 — Admin Photo Review 写操作 API Closeout

## 本轮目标

在 r1d-c2 只读 API 基础上，实现管理员对 `UserImage` 的审核写操作：**approve**、**reject**、**needs-reupload**。不接入 audit、Admin 页面、onboarding 门禁。

## 新增 POST 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/admin/photo-review/items/:imageId/approve` | `reviewStatus=approved`，`reviewReasonCodes=[]` |
| POST | `/admin/photo-review/items/:imageId/reject` | `reviewStatus=rejected`，必填 `reasonCodes` |
| POST | `/admin/photo-review/items/:imageId/needs-reupload` | `reviewStatus=needs_reupload`，必填 `reasonCodes` |

三个接口均返回与 `GET .../items/:imageId` 相同的 **详情 DTO**。

## DTO 与校验

| DTO | 字段 | 规则 |
|-----|------|------|
| `ReviewPhotoApproveDto` | `note?` | max 500；无 `reasonCodes` |
| `ReviewPhotoActionWithReasonsDto` | `reasonCodes`, `note?` | `reasonCodes` ≥1，白名单；`note` max 500 |

**reasonCodes 白名单**（`PHOTO_REVIEW_ADMIN_REASON_CODES`）：

`MANUAL_APPROVED`, `MANUAL_REJECTED`, `NEEDS_REUPLOAD`, `FACE_NOT_CLEAR`, `MULTIPLE_FACES_REVIEW`, `SUSPECTED_NON_PERSON`, `INAPPROPRIATE_CONTENT`, `LOW_QUALITY`, `USER_REQUESTED_REVIEW`, `MANUAL_OVERRIDE`

- **approve**：忽略 body 中的 `reasonCodes`（DTO 无该字段），写入 `[]`。
- **reject / needs-reupload**：至少 1 个白名单 code；**不强制** needs-reupload 必须含 `NEEDS_REUPLOAD`（最小实现）。
- 非法 / 空 `reasonCodes` → **400**（`ValidationPipe`）。
- `forbidNonWhitelisted: true` → body 不能传 `reviewedByUserId` 等未知字段。

## reviewStatus 写入语义

每次 POST 仅更新审核字段：

| 字段 | 值 |
|------|-----|
| `reviewStatus` | `approved` / `rejected` / `needs_reupload` |
| `reviewReasonCodes` | approve→`[]`；reject/needs-reupload→body |
| `reviewedAt` | `now()` |
| `reviewedByUserId` | JWT `userId`（非 body） |
| `reviewNote` | `body.note` trim 后或 `null` |

**不修改**：`detectionStatus`、`detectionReasonCodes`、`detectionScoreJson`、`detectionRulesVersion`。

## 状态转换与并发

允许从以下状态覆盖写入：`pending_review`、`not_required`、`approved`、`rejected`、`needs_reupload`。

- `appealed` / `appeal_*` 等 → `updateMany` 不匹配 → **409**。
- `imageId` 不存在 → **404**。
- 乐观锁：`updateMany` 条件含 `id` + `updatedAt` + 允许的来源 `reviewStatus`；`count !== 1` → **409**（并发或非法状态）。

后续可加强：返回冲突时的最新 `updatedAt` 供前端刷新。

## 权限设计

复用 r1d-c2：

- `JwtAuthGuard` → 未登录 **401**
- `RbacGuard` + `Permission.MANAGE_PHOTO_REVIEW` → **403**
- `reviewedByUserId` 仅来自 `req.user.userId`

## 普通用户接口边界

- `/images` 仍用 `UserImagePublicDto`，不暴露 `reviewNote`。
- 普通用户不能访问 `/admin/photo-review/*`，不能改 `reviewStatus`。
- 无 appeal API。

## onboarding nextStep

**未改**。`approved` / `rejected` / `needs_reupload` 暂不影响 `hasPassingPhoto` 或 `nextStep`（留给 **P7.4-r1d-e**）。
