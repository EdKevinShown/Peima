## 5. Allowlist 规则

apply **仅**允许命中 allowlist 的 viewer。

### 5.1 Allowlist 输入

| 维度 | 说明 |
|------|------|
| `viewerUserId` allowlist | 必填（如 r7k 五 viewer） |
| optional `poolId` allowlist | 限制 pool |
| optional `candidateUserId` allowlist | 限制可写 candidate |
| optional `sourceVersion` allowlist | 如 `p7.6-r7j3-staging-cohort-v1` |

### 5.2 必须全部满足（才允许非 dry-run 写 sidecar）

| # | 条件 |
|---|------|
| 1 | `PEIMA_P76_ALLOWLIST_APPLY_ENABLED=1` |
| 2 | `PEIMA_P76_ALLOWLIST_APPLY_DRY_RUN=0` |
| 3 | `viewerUserId` ∈ allowlist |
| 4 | `finalShadow.selectedCandidateId` **非空** |
| 5 | r6b / r7g audit artifact **或** 已持久化 sidecar 存在 |
| 6 | [r7l](./P7.6-r7l-pm-signoff-for-r8-allowlist-design.md) PM signoff **存在** |
| 7 | **Ops signoff** 存在（apply 实现阶段） |
| 8 | rollback 路径 **ready** |
| 9 | P0 / P1 = **0** |
| 10 | 无 gate error |
| 11 | applied flags 初始 **全 false** |

### 5.3 未命中 allowlist

| 行为 | 说明 |
|------|------|
| 不 apply | 不写 sidecar |
| 只记录 audit | `blockedByAllowlist` |
| display / worker | 继续 **legacy / existing** 路径 |

**初始 allowlist 建议（与 r7k 一致）：**  
`cmr4hm001016z64demo00m05a` · `cmfemn00100016z64seed0001` · `cmr4hf000716z64demo00f04a` · `cmr4hf000916z64demo00f05a` · `cmr4r7j4050025z64stag0001`

## 7. Apply 流程设计

```text
1. 读取 viewerUserId
2. 检查 env gate (enabled, dryRun, signoff flags)
3. 检查 allowlist (viewer + optional pool/candidate/sourceVersion)
4. 读取最新 P7.6 Route C audit artifact / 已有 sidecar
5. 校验 finalShadow.selectedCandidateId 非空
6. 校验 applied* flags 全 false（或 rolledBack 后可重试策略 — r8b 定义）
7. 校验 PM signoff (r7l) + Ops signoff (r8d)
8. dry-run → 输出 wouldApply JSON（不写 DB）
9. 若 dryRun=false 且二次签核通过 → 写 apply sidecar ONLY
10. 不改 MatchResult / finalScore / worker / display
11. admin / PM 页面展示 apply meta
12. 支持 rollback
```

**r8 本轮：** 仅文档化流程 · **不实现** runner / API。

## 8. Storage 设计

**r8 只设计，不实现 migration。**

### 8.1 选项 A — 新表 `p76_allowlist_apply_meta`（**推荐**）

| 优点 | 缺点 |
|------|------|
| 与主链清晰隔离 | 需要 migration（**r8a**） |
| 易 rollback · 易 audit | 多一张表运维 |
| 不污染 `matchInsights` | — |

建议列：`id` · `viewer_user_id` · `meta_json` · `applied` · `rolled_back` · `created_at` · `updated_at` · `rollback_token`

### 8.2 选项 B — `matchInsights.p76AllowlistApplyMeta`

| 优点 | 缺点 |
|------|------|
| 少表 | **污染** matchInsights |
| — | 与 MatchResult 生命周期绑定 · r7k2 多数 viewer **无** MatchResult |

### 8.3 r8 结论

**推荐选项 A**（新 sidecar 表）。**r8 不实现 migration** — schema 见 **[P7.6-r8a](./P7.6-r8a-allowlist-apply-sidecar-schema-design.md)**（`p76_allowlist_apply_meta` · DESIGN PASS）；migration 在 **r8b** 实现阶段创建。

## 10. Rollback 设计

rollback **必须**做到：

| 动作 | 说明 |
|------|------|
| 一键关闭 env | `PEIMA_P76_ALLOWLIST_APPLY_ENABLED=0` |
| allowlist 清空 | `PEIMA_P76_ALLOWLIST_VIEWER_IDS=` |
| sidecar 标记 | `rolledBack=true` |
| display | safe fallback (baseline display)（若未来接了 display gate） |
| worker | **不受影响** |
| MatchResult / finalScore | **无需恢复**（r8 未改） |

**Rollback 字段：** `rolledBack` · `rolledBackAt` · `rolledBackBy` · `rollbackReason`
