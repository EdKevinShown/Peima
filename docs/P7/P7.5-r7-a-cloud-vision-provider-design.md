> **状态**：**设计定稿**（**仅文档** · **不接**真实云 API · **不**改业务代码）

## 1. 一句话结论

**P7.5-r7-a 只设计云视觉识图能力**：通过可插拔 **Cloud Vision Provider**，把用户照片分析为 **`photoVisualTags` / `qualityTags` / `sceneTags`** 与可用性信号，写入现有 **`detectionScoreJson.vision`**（`OnboardingVisionProfileV1`），供 **`visualRankingShadow`**、preview pool 与后续 **`photoVisualSignal`** 只读消费。

**本文档不实现、不接 API、不做人脸识别 / 颜值 / 性别推断 / AI 美化**；**不**启用 percent 灰度；**不**改 worker、`finalScore`、`MatchResult`、正式匹配主链；**无** DB migration。

---

## 2. 为什么需要 Cloud Vision

### 2.1 现网局限（rules / stub / mapping）

当前视觉信号主要来自：

| 来源 | 能力 | 局限 |
|------|------|------|
| **rules** | 从 P7.4 `quality` / `face` / `warnings` 启发式映射 | **不读像素内容**；无法区分「阳光明亮」vs「室内暗光」等语义 |
| **stub** | 固定标签，跑通链路 | 无真实判别力 |
| **demo mapping** | `dev-assets/test-user-images/mapping.json` 人工标注 | **非**真实用户上传；无法规模化 |

因此可以 **跑通** onboarding preview funnel、shadow audit、allowlist-only `APPLY_TO_POOL`，但 **不能** 对真实用户照片稳定、自动识别例如：

| 维度 | 期望识别（示例） |
|------|------------------|
| 气质 | 清爽自然、阳光明亮（≈运动阳光 + 亮光线）、温柔亲和（≈文艺温柔）、高级感 |
| 感觉 | 生活感、精致感、松弛感 |
| 场景 | 户外 / 室内 / 旅行 / 日常 / 都市 / 社交 |
| 质量 | 构图、光线、清晰度（辅助 confidence，**非**颜值） |

商业化后，用户上传 **真实照片** 需要 **自动生成** 封闭词表内的 `photoVisualTags`，并与 `UserPreference.styleTags`（审美题）在排序层面对齐。

### 2.2 设计目标（r7 轨道）

1. **可插拔** cloud provider（厂商无关的 `cloud` 抽象；具体 GLM / 其它 VL 在 **r7-b** 适配）。  
2. **输出可审计**：仅持久化 **封闭标签** + 弱信号；**不**存模型全文。  
3. **失败可降级**：超时 / 拒识 → `visionStatus=skipped|failed` + **rules fallback**（与 r2 一致，**不阻断**上传）。  
4. **与 r5 放量解耦**：先 **shadow / 覆盖率** 验证，再讨论 `APPLY_TO_POOL` / percent（[r5-d](./P7.5-r5-d-percent-rollout-design.md) 已锁定顺序）。

| 能力 | 说明 |
|------|------|
| **`visualRankingShadow`** | 与 v1 池 **对比** 排序；`appliedToPool` 根字段兼容 false |
| **`APPLY_TO_POOL` allowlist-only** | [r5-c4](./P7.5-r5-c4-allowlist-apply-closeout-and-runbook.md) closeout；生产 **默认关闭** |
| **`sourceImageKey` 去重** | [r5-c2a](./P7.5-r5-c2a-shadow-source-image-dedup-fix-closeout.md) |

| **`styleTags` 单一数据源** | 用户审美偏好 **仅** `UserPreference.styleTags`；**不**用 cloud 改写 |

### 3.3 明确尚未具备

- **无** 真实云 VL HTTP 调用。  
- **无** `qualityTags` / `sceneTags` 字段（仅有 `qualitySignals` 枚举与 `styleSignals` 内部 key）。  
- **无** 面向产品的 `photoVisualSignal` 聚合类型（本文档 **定义** 读模型，**不实现**）。  
- 真实用户照片 **不能** 自动稳定产出「阳光」「清爽」「生活感」「高级感」等 **语义标签**（仅靠 rules 权重近似）。

## 4. Provider 架构

### 4.1 三类 Provider（设计口径）

```ts
/** r7-a 设计枚举；实现阶段可扩 vendor adapter */
type VisionProvider = "rules" | "stub" | "cloud";

/** 与现网 OnboardingVisionProvider 对齐说明 */
// 现网: "rules" | "stub" | "zhipu"（占位）
// r7-b 建议: PROVIDER=cloud + CLOUD_VENDOR=zhipu|openai|...
// 或逐步将 "zhipu" 收敛为 cloud adapter 的一种 vendor
```

| Provider | 输入 | 输出 | 网络 | 用途 |
|----------|------|------|------|------|
| **rules** | `detectionScoreJson`（quality/face/warnings）+ 可选 `viewerStyleTags` | `OnboardingVisionProfileV1` | **无** | 默认、降级、零成本基线 |
| **stub** | 无 / 固定 | 固定 tags | **无** | 测试、流水线 |
| **cloud** | **图像 bytes** 或短时 **签名 URL** + 封闭词表 prompt 约束 | 原始 label → **归一化** 为封闭 tags | **有**（async） | 真实用户照片语义识别 |

### 4.2 分层结构（建议实现）

```
┌─────────────────────────────────────────────────────────┐
│ OnboardingVisionService.buildVisionProfile()            │
├─────────────────────────────────────────────────────────┤
│ VisionProviderRouter  ← PEIMA_ONBOARDING_VISION_PROVIDER│
├──────────┬──────────────────────┬─────────────────────┤
│ Rules    │ Stub                 │ CloudVisionFacade     │
│ Provider │ Provider             │  ├─ VendorAdapter A  │
│          │                      │  ├─ VendorAdapter B  │
│          │                      │  └─ TagNormalizer   │
├──────────┴──────────────────────┴─────────────────────┤
│ assembleOnboardingVisionProfile + taxonomy normalize    │
├─────────────────────────────────────────────────────────┤
│ mergeVisionIntoDetectionScoreJson (sidecar)             │
└─────────────────────────────────────────────────────────┘
```

**原则**

- **Cloud 只负责「识图 → 原始标签」**；**TagNormalizer** 负责映射到 **封闭词表**（§6）。  
- **Router** 在 cloud 失败时 **不得** 抛到上传主链；走 **rules fallback** 或 `skipped`。  
- **VendorAdapter** 隔离 HTTP/SDK；**禁止** 把 vendor 类型泄漏到 `MatchResult` / worker。

### 4.3 `photoVisualSignal`（读模型，r7-a 仅定义）

供 preview pool / shadow / 未来 UI 解释的 **稳定只读结构**（可由 `OnboardingVisionProfileV1` 投影）：

```ts
type PhotoVisualSignalV1 = {
  schemaVersion: "photo-visual-signal-v1";
  usable: boolean; // visionStatus===ok && photoVisualTags.length>0
  photoVisualTags: string[];
  qualityTags: string[];
  sceneTags: string[];
  confidence: number;
  provider: VisionProvider;
  sourceVersion: string;
};
```

**不单独落库**；优先从 `detectionScoreJson.vision` 计算；避免第二数据源漂移。

## 5. 标签体系：photoVisualTags / qualityTags / sceneTags

### 5.1 分工

| 字段 | 面向 | 词表 | 用途 |
|------|------|------|------|
| **`photoVisualTags`** | 产品 / 排序 | **已有** `p7.5-v1`（18 中文） | 与 `UserPreference.styleTags` 做 overlap；aesthetic_fit / style_similar |
| **`qualityTags`** | 技术 / 降权 | **新增** `quality-taxonomy-v1`（封闭，中文或 snake_case 内部码） | 清晰度、光线、构图；调 `confidence`；**不**直接展示给用户 |
| **`sceneTags`** | 技术 / 映射 | **新增** `scene-taxonomy-v1`（封闭） | 场景上下文；**辅助** 映射到 `photoVisualTags`；reflow 多样性 |

### 5.2 `photoVisualTags`（沿用 p7.5-v1）

与 [P7.5 §3](./P7.5-onboarding-vision-design.md) 一致，**18** 个标签，例如：

清爽自然、甜美可爱、运动阳光、生活感、精致感、高级感、户外感、室内日常、简约干净、 …

- Cloud **不得** 输出词表外中文；Normalizer **丢弃** 未知 tag。  
- 数量：**3–6**（`PEIMA_ONBOARDING_VISION_MAX_TAGS`）。  
- **禁止** 用 cloud 输出 **改写** `User.gender` 或推断种族 / 年龄。

### 5.3 `qualityTags`（建议 v1 封闭集）

与现有 `qualitySignals` **并存**；`qualitySignals` 保留枚举便于 rules；`qualityTags` 便于 cloud 多标签与 audit。

| qualityTag | 含义 | 与 rules 关系 |
|------------|------|----------------|
| `清晰` | 主体清晰 | `clarity=high` |
| `略模糊` | 轻度模糊 | `clarity=low\|medium` |
| `光线偏暗` | 欠曝 | `lighting=dark` |
| `光线明亮` | 高亮 / 阳光感 | `lighting=bright` |
| `光线正常` | 默认 | `lighting=normal` |
| `构图居中` | 人脸居中 | `composition=centered_face` |
| `半身构图` | half body | `composition=half_body` |
| `背景杂乱` | busy bg | `composition=busy_bg` |
| `多人脸` | 非 P0 拒绝，仅 warning | `faceSignals.multipleFacesWarning` |

**不做**：`颜值高` / `颜值低` / `好看` 等 **评分型** 标签。

### 5.4 `sceneTags`（建议 v1 封闭集）

| sceneTag | 映射倾向（photoVisualTags） |
|----------|------------------------------|
| `室内日常` | 室内日常、生活感 |
| `户外自然` | 户外感、清爽自然、运动阳光 |
| `都市街景` | 都市精致、高级感 |
| `旅行度假` | 户外感、氛围感、松弛感 |
| `社交聚会` | 社交感、生活感 |
| `运动活动` | 运动阳光 |
| `工作通勤` | 成熟稳重、简约干净 |
| `证件棚拍` | 证件感弱（降权） |

Normalizer 可用 sceneTags **加权** photoVisualTags，但 **最终持久化** 仍以 `photoVisualTags` 为主（与 UI / 审美题一致）。

### 5.5 Schema 扩展（设计，r7-b 实现时评审）

在 `OnboardingVisionProfileV1` 上 **可选** 增加（**无 migration** — 仍存 JSON）：

```ts
type OnboardingVisionProfileV1 = {
  // ... 现有字段 ...
  photoVisualTags: string[];
  qualityTags?: string[];   // quality-taxonomy-v1
  sceneTags?: string[];     // scene-taxonomy-v1
  qualitySignals?: { ... }; // 保留，rules/cloud 均可填
  styleSignals?: string[];  // 保留内部诊断
};
```

`photoVisualTaxonomyVersion` 仍为 `p7.5-v1`；新增：

- `qualityTaxonomyVersion?: "quality-v1"`
- `sceneTaxonomyVersion?: "scene-v1"`

## 6. Cloud Provider 接口（设计）

### 6.1 输入 `CloudVisionAnalyzeInput`

| 字段 | 必填 | 说明 |
|------|------|------|
| `imageRef` | 是 | `{ kind: "bytes"; mimeType; buffer }` 或 `{ kind: "signedUrl"; url; expiresAt }` |
| `imageId` | 否 | 内部 `UserImage.id`（**不进** prompt） |
| `taxonomyHints` | 是 | 封闭 `photoVisualTags` / `qualityTags` / `sceneTags` 列表（供 constrained output） |
| `viewerStyleTags` | 否 | **仅** 作偏好上下文；**禁止** 当作 ground truth |
| `locale` | 否 | 默认 `zh-CN` |

**禁止输入**：手机号、实名、`reviewNote`、其它用户 PII、`User.gender`。

### 6.2 输出 `CloudVisionRawResult`（不落库全文）

```ts
type CloudVisionRawResult = {
  vendor: string;
  model: string;
  latencyMs: number;
  requestId?: string;
  labels: {
    photoVisual: Array<{ tag: string; score: number }>;
    quality: Array<{ tag: string; score: number }>;
    scene: Array<{ tag: string; score: number }>;
  };
  refusal?: { code: string; message: string }; //  política / 安全拒识
};
```

### 6.3 归一化 `normalizeCloudVisionResult`

1. 按 score 排序，取 top-K。  
2. **交集** 封闭词表；未知 tag → 丢弃 + `warnings.push("VISION_CLOUD_UNKNOWN_TAG")`。  
3. 若 `photoVisualTags` 为空 → `visionStatus=skipped`，`fallbackUsed=true`，交 **rules** 重算或保留 skipped。  
4. `confidence` = f(模型 score 均值, qualityTags 严重度, faceCount warning)；**clamp** 至 `0.15–0.85`（与 r1 一致）。  
5. `provider: "cloud"`，`sourceVersion` 例：`p7.5-r7-cloud-zhipu-v1`（vendor 写入 **sourceVersion**，便于 audit 分桶）。

### 6.4 Prompt / 输出约束（原则）

- **结构化输出**（JSON schema / tool call），**禁止** 自由散文。  
- 明确指令：**只描述画面气质与场景，不判断性别、年龄、种族、吸引力、身份**。  
- 明确指令：**标签只能从给定列表选择**。  
- **不要求** 返回人脸 ID、embedding、bbox 明细（若 vendor 返回，**strip** 后仅保留 `faceCount` 等等价弱信号，与 P7.4 一致）。

## 7. 写入路径与触发时机

### 7.1 仍写入 `detectionScoreJson.vision`

与 [r2](./P7.5-r2-onboarding-vision-score-json-sidecar-closeout.md) 一致：

```
UserImage 上传 → P7.4 detection (quality/face) → detectionScoreJson
                    ↓ (async 或 deferred)
              CloudVisionFacade.analyze → normalize → merge vision
```

| 路径 | 建议 |
|------|------|
| **同步（上传请求内）** | **不推荐**；易超 `TIMEOUT_MS`，拖慢 onboarding |
| **异步（推荐）** | 上传成功后 **入队** / `setImmediate` 后台任务；完成后 **update** 同一 `UserImage.detectionScoreJson` |
| **On-demand** | DEV CLI / admin 补跑（类似 [r4-f](./P7.5-r4-f-vision-sidecar-backfill-closeout.md)） |

### 7.2 与 review / gate 边界

- **Photo review 决策** 仍只读 P7.4 `quality` / `face` / `warnings`；**不**因 cloud tag 自动 reject。  
- `reviewStatus ∈ {rejected, needs_reupload, ...}` 的图 → shadow / ranking **不用** vision（与现网 `extractUsableVision` 一致）。  
- Cloud **失败** **不** 改变 `detectionStatus` / `reviewStatus`。

### 7.3 缓存

- Key：`(userImageId, imageContentHash, taxonomyVersion, model)`  
- TTL：`PEIMA_ONBOARDING_VISION_CACHE_TTL_MS`（默认 24h）  
- 存 **normalized profile** 或 **raw+normalized** 的小对象；**不** 存原图。

## 8. Env 设计（cloud 专用扩展）

在现有 `PEIMA_ONBOARDING_VISION_*` 上扩展（**r7-a 不落盘 .env.example**）：

```env
# 基线（与现网一致，生产建议保持）
PEIMA_ONBOARDING_VISION_ENABLED=0
PEIMA_ONBOARDING_VISION_PROVIDER=rules

# r7-b+ cloud（设计示例）
PEIMA_ONBOARDING_VISION_PROVIDER=cloud
PEIMA_ONBOARDING_VISION_CLOUD_VENDOR=zhipu
PEIMA_ONBOARDING_VISION_BASE_URL=
PEIMA_ONBOARDING_VISION_API_KEY=replace_me
PEIMA_ONBOARDING_VISION_MODEL=
PEIMA_ONBOARDING_VISION_TIMEOUT_MS=8000
PEIMA_ONBOARDING_VISION_MAX_TAGS=6
PEIMA_ONBOARDING_VISION_CLOUD_ASYNC=1
PEIMA_ONBOARDING_VISION_CLOUD_MAX_CONCURRENCY=4
```

| 变量 | 说明 |
|------|------|
| `PROVIDER=cloud` | 启用 CloudVisionFacade（**r7-b** 实现） |
| `CLOUD_VENDOR` | 厂商适配器选择；**不** 进入 DB |
| `CLOUD_ASYNC` | `1` = 上传后异步写 vision |
| `CLOUD_DRY_RUN` | `1` = 打日志 / metrics，**不发** HTTP（staging 首阶段） |
| `API_KEY` | **仅 env**；禁止入库 / 日志 |

**与 r5 放量正交**

- `PEIMA_ONBOARDING_VISION_APPLY_TO_POOL` / allowlist / percent：**不因** cloud 设计自动开启（[r5-c4](./P7.5-r5-c4-allowlist-apply-closeout-and-runbook.md)、[r5-d](./P7.5-r5-d-percent-rollout-design.md)）。

## 9. 降级、回滚与观测

### 9.1 降级链

```
cloud enabled?
  no  → rules/stub（现网）
  yes → call cloud
          ok + tags≥1 → persist cloud profile
          fail/timeout/empty → rules fallback (fallbackUsed=true)
          rules also skipped → visionStatus=skipped
```

### 9.2 回滚（运维）

| 操作 | 效果 |
|------|------|
| `ENABLED=0` | 新上传 **不** 再写/更新 vision |
| `PROVIDER=rules` | 新分析走 rules；**不** 删已有 cloud vision |
| `CLOUD_DRY_RUN=1` | 验证链路不发真实请求 |

**不批量** 清空历史 `detectionScoreJson.vision`（除非专用 backfill CLI + 审批）。

### 9.3 指标（实现阶段）

| 指标 | 用途 |
|------|------|
| `cloud_request_total` / `_success` / `_timeout` | 稳定性 |
| `cloud_latency_ms` p50/p95 | 容量 |
| `cloud_unknown_tag_dropped` | 词表漂移 |
| `cloud_fallback_to_rules` | 降级率 |
| `vision_usable_rate` | 与 [r4-g](./P7.5-r4-g-candidate-vision-coverage-audit-closeout.md) 对齐 |
| `photo_visual_tag_distribution` | 标签分布（**无** PII） |

## 10. 隐私、安全与合规

| 要求 | 说明 |
|------|------|
| **最小上传** | 优先 resize 至模型所需分辨率；**不传** 原图 EXIF GPS（strip） |
| **留存** | 厂商侧「不留存」条款优先；境内/区域部署 **Ops 评审** |
| **日志** | 仅 `requestId`、latency、tag 计数；**不** 打 base64 / URL token |
| **禁止能力** | 人脸 1:N、身份认证、颜值评分、性别/年龄/种族推断、AI 换脸/美化 |
| **性别门控** | 仍 **仅** DB `User.gender`；cloud tag **不得** 写入 profile gender |
| **用户告知** | 产品文案 / 隐私政策 **r7-c** 评审（本文档不代写法律文本） |

## 11. 与 shadow / APPLY_TO_POOL 的关系

| 阶段 | Cloud vision | APPLY_TO_POOL |
|------|--------------|---------------|
| **r7-b** | staging `CLOUD_DRY_RUN` + 小样本真实调用 | **关闭** |
| **r7-c** | 提高 usable rate；shadow audit 达标 | **仍关闭** 或仅 allowlist |
| **r5-d1+** | cloud 稳定后 | percent **另轨** 评审 |

**硬门槛（建议）**：在考虑扩大 `APPLY_TO_POOL` 前：

## 14. 测试计划（r7-b+ 实现时）

### 14.1 Unit

- Normalizer：已知 raw labels → 封闭 tags  
- 空/cloud 拒识 → rules fallback  
- 超 `MAX_TAGS` 截断  
- 未知 tag 丢弃 + warning  

### 14.2 Integration

- `ENABLED=false` 不写 vision  
- `CLOUD_DRY_RUN=1` 无 HTTP  
- 超时 → fallback；`detectionStatus` 不变  
- merge 保留 `quality` / `face` / `warnings`  

### 14.3 Signoff

- staging **≥50** 张真实样张（脱敏存储）· 人工 spot-check 标签合理性  
- shadow audit 指标 vs rules 基线对比  
- **0** P0（错性别门控、身份型标签泄露）

## 16. 风险与缓解

| 风险 | 缓解 |
|------|------|
| 模型幻觉标签 | 封闭词表 + Normalizer + 低 temperature |
| 标签漂移 / 版本升级 | `sourceVersion` + taxonomy version；golden 回归 |
| 延迟与成本 | 异步 + 缓存 + 并发上限 |
| 隐私泄露 | 最小像素、签 URL 短 TTL、日志脱敏 |
| 观感 P0（错性别等） | **不** 用 cloud 改 gender；门控仍 DB；active audit |
| 与 rules 不一致 | shadow 对比；分阶段 `APPLY_TO_POOL` |
