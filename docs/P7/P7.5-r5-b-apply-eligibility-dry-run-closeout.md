# P7.5-r5-b — APPLY_TO_POOL eligibility / dry-run Closeout

## 1. 本轮目标

在 **不改动真实** `OnboardingPhotoPreviewPoolItem`、**不改变** `generate()` 对前端的 3+2+1 返回的前提下，实现：

- 独立的 **apply env reader**（与 `readOnboardingVisionEnv` 分离）；
- **纯函数** eligibility + **稳定百分比桶**；
- 在 **visual ranking shadow** 计算并持久化时，写入 **`summary.applyDryRun`** 元数据；
- 全程 **`VisualRankingShadowV1.appliedToPool === false`**，**不**将 shadow 排序写回 pool。

## 2. Env reader

**文件**：`apps/api/src/modules/onboarding/vision/onboarding-vision-apply-env.ts`

**变量**（与 r5-a 设计一致）：

| 变量 | 行为 |
|------|------|
| `PEIMA_ONBOARDING_VISION_APPLY_TO_POOL` | **仅**当值为 **`"1"`**（去空白后精确相等）时为开启；`true` / `yes` 等 **不**开启 |
| `PEIMA_ONBOARDING_VISION_APPLY_ALLOWLIST_USER_IDS` | 逗号分隔；trim；空段丢弃 |
| `PEIMA_ONBOARDING_VISION_APPLY_PERCENT` | `0–100` 整数；非法或非数字 → **0** |
| `PEIMA_ONBOARDING_VISION_APPLY_SOURCE_VERSION` | 默认 **`onboarding-photo-preview-v2-vision`** |

**说明**：`readOnboardingVisionEnv` **已移除** `applyToPool` 字段；apply 相关 **只**由 `readOnboardingVisionApplyEnv` 读取。若运维曾用 `APPLY_TO_POOL=true` 期望 `summary.applyToPoolIgnored`，需改为 **`=1`** 才会触发 r5-b 行为。

`.env.example` §21 已补充上述变量注释。

## 3. Eligibility 规则

**文件**：`apps/api/src/modules/onboarding/vision/onboarding-vision-apply-eligibility.ts`

**判定顺序**（前者失败即返回 `not_eligible`）：

1. `!env.applyToPoolEnabled` → `env_disabled`
2. **Baseline guards**（与 r4-o2 对齐，纯函数 `evaluateApplyPoolBaselineGuards`）  
   - `poolGuardRows.length !== 6` → `candidate_count_not_six`  
   - `candidateUserId` 去重失败 → `insufficient_unique_candidates`  
   - `previewPoolRowDisplaySourceKey` 去重失败 → `insufficient_unique_source_images`  
   - 任一 `candidateUserId === viewerUserId` → `self_candidate_guard`  
   - viewer 非严格二元性别，或任一 candidate 非异性二元门控 → `gender_violation_guard`
3. `visualRankingShadow === null` → `shadow_missing`
4. shadow 结构非法（`schemaVersion`、`appliedToPool !== false`、`slots.length !== 6`）→ `shadow_invalid`
5. **allowlist 非空** 且 `viewerUserId` 不在列表 → `not_in_allowlist`
6. **allowlist 为空** 时：`getStablePercentBucket(viewerUserId) >= applyPercent` → `percent_not_hit`（**percent=0** 恒 miss；**percent=100** 恒 hit）
7. 否则 → `eligible: true`，`decision: "eligible_dry_run"`，`reason: "ok"`

**allowlist / percent 语义**：allowlist **非空且命中**时 **不再**做 percent 判定；allowlist **空**时才用 percent。

## 4. Stable hash

**文件**：`apps/api/src/modules/onboarding/vision/onboarding-vision-apply-percent-hash.ts`

- `getStablePercentBucket(viewerUserId)`：**FNV-1a 32-bit** → `unsigned % 100`
- **无** `Math.random`、**无**外部依赖

## 5. dry-run metadata 写入位置

- **挂载点**：`VisualRankingShadowV1.summary.applyDryRun`（可选对象）
- **形状**：

```ts
{
  evaluated: true;
  eligible: boolean;
  reason: string; // 与 eligibility 枚举一致或 "ok"
  applySourceVersion: string;
  appliedToPool: false;
}
```

- **写入时机**：`VisualRankingShadowService.computeShadow` 在 `buildVisualRankingShadowV1` 之后、`persistVisualRankingShadow` 之前；**即使** gate 关闭也会在 summary 中写入（通常为 `env_disabled`），便于观测「已评估但未开闸」。
- **异常**：evaluate 抛错时写入 `eligible: false`，`reason: "shadow_invalid"`，并 `logWarn`，**不**阻断 persist / generate。

**`applyToPoolIgnored`**：当 `readOnboardingVisionApplyEnv().applyToPoolEnabled` 为 true 时，builder 仍设置 `summary.applyToPoolIgnored: true`，表示「用户请求了 apply 路径但引擎仍未写真实 items」。

## 6. 为什么 `appliedToPool` 仍为 false

- 根类型 `VisualRankingShadowV1` 中 **`appliedToPool` 固定为字面量 `false`**；r5-b **不**实现真实 apply。
- dry-run 结果中的 `applyDryRun.appliedToPool` **恒为 `false`**，仅作显式冗余，防止误读。

## 7. 服务接入

- **`onboarding-photo-preview-pool.service.ts`**：`computeShadow` 增加 **`applyDryRunContext`**：  
  `viewerGenderRaw` + 按 `rankInPool` 排序的 6 行 `{ candidateUserId, candidateGenderRaw, firstImageUrl }`（来自生成时 `gById`），供 baseline guard 与 r4-o2 一致。
- **`generate()` / `toViewerBundle`**：无逻辑变更；items 仍为 v1 算法产物。

## 8. r4-c audit 兼容

- `parseVisualRankingShadowPayloadSafe` **忽略**未知 `summary` 键；**存在** `applyDryRun` 的旧/新 payload **均可**解析（见 `visual-ranking-shadow-audit.spec.ts` 新增用例）。

## 10. 未改动范围

- **未**修改真实 `OnboardingPhotoPreviewPoolItem` 的 `candidateUserId` / `rankInPool` / `tier` / `displayMode`
- **未**改 worker、`finalScore`、`MatchResult`、旧 `PreviewPool`、正式匹配主链
- **未**接云视觉 API；**未**做 AI 美化 / 头像、人脸比对、颜值、自动性别
- **未**新增 DB migration（`applyDryRun` 为 JSON payload 内字段）
- **未**将 `appliedToPool` 设为 true

## 11. 下一步（r5-c 建议）

1. 在 **gate + 全量门槛** 满足产品设计的前提下，实现 **将 shadow 排序写回新生成 items**（仍受 env 与 allowlist/percent 约束）。
2. 明确 **`appliedToPool: true`** 仅在真实写入成功后标记（或并行 metadata），并与 audit CLI 扩展（r5-a §9.4）对齐评审。
3. 前端 / 运维 runbook：`sourceVersion` 与 `summary.applyDryRun` 的观测字段说明（r5-e）。
