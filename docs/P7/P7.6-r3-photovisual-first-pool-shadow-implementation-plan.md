## 5. Scoring 设计

### 5.1 公式（r3 锁定初版）

```text
AtoBPhotoVisualFit = tagJaccard(viewerStyleTags, candidatePhotoVisualTags)

BtoAPhotoVisualFit = tagJaccard(candidateStyleTags, viewerPhotoVisualTags)

visualImbalancePenalty = 0   // r3a 初版固定为 0

mutualPhotoVisualFit =
  0.5 * AtoBPhotoVisualFit
+ 0.5 * BtoAPhotoVisualFit
- visualImbalancePenalty
```

**保守备选**（单测覆盖，**默认不用**）：

```text
mutualPhotoVisualFit = harmonicMean(AtoB, BtoA)
     = (AtoB > 0 && BtoA > 0) ? 2*AtoB*BtoA/(AtoB+BtoA) : 0
```

**与 r2 关系**：r2 保留公式选择权；**r3/r3a 锁定** weighted average + `penalty=0`，便于 audit 对比。

### 5.2 不采用（r3a）

| 项 | 原因 |
|----|------|
| `fit × confidence` | r2 未要求；visualRankingShadow aesthetic 有；**r3a 不加**，避免与 r7-e audit 难对比 |
| `×` 非 Jaccard 的 overlap 计数 | 与现有 shadow 不一致 |

### 5.3 分数范围

所有 fit 函数保证 **`0 ≤ score ≤ 1`**（`tagJaccard` 已保证）。

### 5.4 排序（`selectedCandidateIds`）

对 **eligible** pairs：

1. `mutualPhotoVisualFit` **降序**
2. 平局：`AtoBPhotoVisualFit` **降序**
3. 再平局：`candidateUserId` **升序**（稳定、可复现）

**`limit`**：默认 `6`（对齐 onboarding 6 槽）；由 `PhotoVisualPoolInputV1.selectionLimit` 传入。

## 6. Eligibility 设计

### 6.1 原则

- **Pure**：不 import `PrismaService`；不调用 `OnboardingPhotoPreviewPoolService.generate`。
- **Caller 负责**：从 DB 读出并填入 `PhotoVisualCandidateInput.gates` 与 vision 字段。
- **顺序**：按优先级追加 `ineligibleReasons`（可多码，但单测通常单码）。

### 6.2 `ineligibleReason` 枚举（与 r2 对齐）

| 码 | 触发条件（pure 输入） |
|----|----------------------|
| `SELF` | `gates.isSelf` |
| `GENDER_GATE` | `!gates.genderGatePassed` |
| `PREFERENCE_GATE` | `!gates.preferenceGatePassed` |
| `REVIEW_BLOCKED` | `!gates.reviewUsable` |
| `DETECTION_UNAVAILABLE` | `!gates.detectionUsable` |
| `VISION_NOT_OK` | `candidateVision` 缺失或 `visionStatus !== "ok"` |
| `EMPTY_PHOTO_VISUAL_TAGS` | candidate `photoVisualTags` 归一化后为空 |
| `VIEWER_VISION_MISSING` | B→A 需要 viewer `photoVisualTags`；viewer vision 缺失或空 |
| `USER_BLOCKED` | `gates.userBlocked` |
| `MISSING_PROFILE` | `gates.missingProfile` |
| `MISSING_STYLE_TAGS` | viewer **与** candidate 的 `styleTags` 均为空（可选：仅 candidate 空 → 仍 ineligible B→A=0 但 A→B 可能>0；**r3a 建议**：candidate `styleTags` 空不单独 ineligible，仅 B→A=0） |

**r3a 建议（B→A 缺 styleTags）**：

- candidate `styleTags` 空 → **不** ineligible；`BtoAPhotoVisualFit = 0`。
- viewer 无 vision → **`VIEWER_VISION_MISSING`** ineligible（双向眼缘需要 viewer 照片气质）。

### 6.3 `eligible` 判定

```text
eligible = ineligibleReasons.length === 0
```

Ineligible 行仍进入 `pairs[]`（audit），fit 字段为 **`null`**，不进入 `selectedCandidateIds`。
