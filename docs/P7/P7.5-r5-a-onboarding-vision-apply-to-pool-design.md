# P7.5-r5-a — Onboarding APPLY_TO_POOL 小流量设计

> **状态**：设计方案 · **禁止**本轮实现 APPLY、改 DB、改 pool 契约  
> **前置**：r4 audit 阈值与 staging signoff 流程已知；shadow 样本达标后再进入 r5-b+

---

## 1. 一句话结论

在满足 **audit 阈值 + staging signoff + PM spot-check** 后，仅对 **符合条件的 viewer**、在 **`generate()` 创建新 pool 的时机**内，按与 **shadow 相同的纯函数打分**重写各槽位的 **`candidateUserId` / `score` / `reasonTags`**，`sourceVersion` 升为 **`onboarding-photo-preview-v2-vision`**；通过 **三重 env（总开关 + allowlist + 百分比）与一键关闭**控制风险，**不写 worker / MatchResult / 旧 PreviewPool**。

---

## 2. APPLY_TO_POOL 启用前置条件

以下 **全部**满足方可进入 **r5-c 代码实现**，且实现后 **生产灰度仍由开关控制**：

| # | 条件 | 口径 |
|---|------|------|
| 1 | shadowCoverageRate | ≥ **0.8**（与同 filter 下的 pools 基数，见 r4-c） |
| 2 | validShadowRows | ≥ **50** |
| 3 | viewerVisionAvailableRate | ≥ **0.6** |
| 4 | Missing vision | **avgCandidatesMissingVision < 1.2** 或 **missing / (missing+vision) < 0.2** |
| 5 | avgChangedSlots | **0.3–2.5** |
| 6 | Full shuffle | `changedSlots=6` 行占比 **< 1%** |
| 7 | reflow tierChangeRate | **< 15%** |
| 8 | aesthetic_fit tierChangeRate | **< 40%** |
| 9 | style_similar tierChangeRate | **< 50%** |
| 10 | Staging | **P7.5-r5-d（或顺延）staging signoff** 通过 |
| 11 | 产品 | **PM spot-check**：换人样例、aesthetic/style/reflow 语义可接受 |
| 12 | 运维 | **`PEIMA_ONBOARDING_VISION_APPLY_TO_POOL` 可随时置 0**（不要求重 deploy 即可降级，若配合配置中心则更优） |

**说明**：r4-d 样本不足时 `ready=false` **不阻断**撰写本文档；实际开灰度必须以 **最近一次** audit JSON 存档为证。

---

## 3. 灰度 Env 设计

### 3.1 建议变量（r5-b Reader）

| Env | 默认 | 含义 |
|-----|------|------|
| `PEIMA_ONBOARDING_VISION_APPLY_TO_POOL` | `0` | 总闸：`0|false` → **永不**改写 items |
| `PEIMA_ONBOARDING_VISION_APPLY_ALLOWLIST_USER_IDS` | 空 | 逗号分隔 cuid；**非空则仅列表内 viewer 可进入下一层** |
| `PEIMA_ONBOARDING_VISION_APPLY_PERCENT` | `0` | 0–100；在通过 allowlist（或 allowlist 为空时视为「全量候选」）后，对 `userId` 做 **稳定哈希** 取模决定是否应用 |
| `PEIMA_ONBOARDING_VISION_APPLY_SOURCE_VERSION` | `onboarding-photo-preview-v2-vision` | 应用后写入 `OnboardingPhotoPreviewPool.sourceVersion`（与 r4 设计一致） |

### 3.2 判定顺序（建议）

1. `APPLY_TO_POOL` 为真 → 否则等同 v1；
2. 若 **allowlist 非空**：`viewerUserId ∉ allowlist` → **不应用**；
3. `hash(viewerUserId) % 100 < APPLY_PERCENT`（**Percent=100** 全开；**Percent=0** 全关）。

### 3.3 生效范围

| 维度 | 建议 |
|------|------|
| 新 vs 旧 pool | **只对本次 `generate()` 新创建的 pool 生效**；**不批量改写**已在库的 active/archived pool |
| 已有 active pool | **不动**；用户继续看旧排序直至再次 **generate**（若产品上需「一键刷新」，走显式 UX + 文档，本项目内为 **另行需求**） |

### 3.4 与 r4 关系

r4 阶段 **硬忽略** `APPLY_TO_POOL`；r5 实现后 **同一 env 名** 变为真时，在 `generate()` 内 **在 DB create 前** 选择 v1 或 v2 排序逻辑，**persist shadow 仍 fire-and-forget**（见 §7）。

## 4. 应用范围

### 4.1 允许变更的列（仅 `OnboardingPhotoPreviewPoolItem`）

- `candidateUserId`
- `score`
- `reasonTags`（保留 `onboarding-photo-preview-v1` 类 trace 可叠加 `tier:` + `vision:apply` 短码，具体见实现 closeout）

### 4.2 禁止变更

- 槽位 **数量** 恒为 6；**rankInPool** 1–6 固定；**tier** `aesthetic_fit` / `style_similar` / `reflow` 字符串不变；**displayMode** `clear` / `blurred` / `hidden` 不变
- **worker、finalScore、MatchResult、旧 PreviewPool** 零接触
- **GET me/latest** 仍不返回 shadow 表内容；若产品要「解释文案」走 **独立字段或前端 copy**，**不**在 r5 首版塞入 ID 或 raw vision

---

## 5. 排序策略

**原则**：与 **P7.5-r3 `visual-ranking-shadow-scoring` + builder** 相同的 **纯函数** 生成每 tier 的排序；apply 时 **不再**单独跑「仅 shadow」路径，而是 **直接**用该逻辑产出 `slotDefs` 写入 items（避免 v2 与 shadow 漂移）。

| Tier | 视觉增强 | Fallback（与 r3 一致） |
|------|----------|------------------------|
| **aesthetic_fit** | Jaccard(viewer `styleTags`, candidate `photoVisualTags`) × confidence | `computeStyleScore` |
| **style_similar** | Jaccard(viewer **passing** photo `photoVisualTags`, candidate tags) × confidence | `computePreferenceScore` |
| **reflow** | 仍以 **最旧注册** 为主序；vision 仅 **极小 ε tie-break**（与 r3） | `pickOldest` |

**Vision 可用性**（与 r3/r4 输入规则对齐）：

- Candidate：首张图 `visionStatus===ok`；`rejected` / `needs_reupload` / `appealed` / `appeal_rejected` **不用** vision
- Viewer：最新 **passing** 图且 vision ok；否则 style_similar 走 preference fallback
- `visionStatus !== ok` 或缺 vision → **该槽位使用 v1 等价分**（与 shadow fallback 一致）

**探索位**：reflow **禁止**因 vision 大幅改人；若 tie-break 导致与 v1 不同，须在 audit 中监控 **reflow tierChangeRate**。

## 6. sourceVersion 与回滚

| 场景 | 行为 |
|------|------|
| 应用开启且 eligibility 通过 | `OnboardingPhotoPreviewPool.sourceVersion = PEIMA_ONBOARDING_VISION_APPLY_SOURCE_VERSION`（默认 v2-vision） |
| 应用关闭 | 新 `generate()` 回到 **v1** 算法与 `onboarding-photo-preview-v1`（或沿用 Prisma default 常量） |
| 历史 pool | **不迁移**；仅新 pool 带 v2 |
| 回滚 | 关 env → 下一池 v1；**不**删库内旧 v2 pool |
| 用户「恢复」v1 | 产品上可 **重新 generate**（_archive 旧 active + 建新池）——若 archived 语义已存在则复用 |

**兼容性**：前端若依赖 `sourceVersion` 字符串，需在 r5-e closeout 中 **列兼容矩阵**。

## 7. 观测与审计

### 7.1 持续写入 shadow（建议）

- **每次** `generate()` 仍可计算 hypothetical shadow；**persist** 行为保留
- **`VisualRankingShadowV1.appliedToPool`**：今日 r3/r4 **恒 false**；r5 在 **实际应用**分支内置 **`true`**，并建议扩展：
  - `appliedSourceVersion?: string`
  - `baselineSourceVersion` 仍为 v1  
  （若避免改 TS schema  breaking，可用 `summary.applyMeta: { … }`，**须在 r5-b 定稿**）

### 7.2 r4-c CLI 扩展（r5-b/c 后）

- 增加可选 filter：`--appliedOnly` / `--payload.appliedToPool=true`
- 或 `schemaVersion` 升到 `visual-ranking-shadow-v2` 仅表示 **含 apply 元数据**（二选一，**实现前评审**）

### 7.3 Signoff

- **P7.5-r5-d**：staging 在 **小流量** 下跑 generate + me/latest + audit + 人工 spot-check
- **P7.5-r5-e**：closeout + 指标截图（覆盖率、换人率）

## 8. 风险

| 风险 | 缓解 |
|------|------|
| 标签不准导致大面积换人 | 阈值 + allowlist + 低 Percent 起步；监控 `avgChangedSlots` |
| style_similar 语义跳变 | PM spot-check + tierChangeRate 上限 |
| reflow 被误伤 | 强制极小 ε；独立监控 reflow rate |
| 用户无解释 | 前端 copy 仅描述「气质匹配」**不**暴露模型；**不**承诺「唯一正确」 |
| env 误开 | 默认 0；allowlist 先行；Code review + 配置审计 |
| 新旧 pool 混排 | 文档说明「仅新池 v2」；客服脚本可查 `sourceVersion` |

## 9. 测试计划（未来实现）

- `APPLY_TO_POOL=0`：items 与现网 v1 比特级一致（对同一随机种子/固定 fixture）
- allowlist：仅名单内 userId 的 create payload 含 v2 candidate 集
- `Percent=0`：不应用；`Percent=100` + 开关 on：应用
- 缺 vision / blocked review：fallback 路径与单测 golden
- reflow：与 v1 同一主序时 **多数情况**同一人
- `sourceVersion` 字段断言
- 关 env 后下一池 v1
- **回归**：worker / MatchResult / 旧 PreviewPool 相关测试 **零 diff**
