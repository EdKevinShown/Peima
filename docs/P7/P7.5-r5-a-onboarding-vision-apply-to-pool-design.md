# P7.5-r5-a — Onboarding Vision APPLY_TO_POOL 灰度设计

> **状态**：设计定稿（**仅文档**） · **不**在本轮实现 `APPLY_TO_POOL`、**不**改 DB / migration / worker / `finalScore` / `MatchResult` / 旧 `PreviewPool` / 正式匹配主链  
> **对齐**：与 [P7.5-r4-final-closeout](./P7.5-r4-final-closeout.md)、[r4-o3 本地签收](./P7.5-r4-o3-preview-pool-local-signoff.md)、[r4-o2 active audit](./P7.5-r4-o2-preview-pool-active-audit-and-image-source-dedup-closeout.md)、[r4-c shadow audit](./P7.5-r4-c-visual-ranking-shadow-audit-closeout.md)、[r4-d staging signoff](./P7.5-r4-d-visual-ranking-shadow-staging-signoff.md)、[r4-e 样本签收](./P7.5-r4-e-visual-ranking-shadow-sample-signoff.md) 表述一致；实现细节以 **P7.5-r3 visual ranking shadow** 与后续 r5-b+ closeout 为准。

---

## 1. 一句话结论

在 **r4 preview pool 链路稳定**、**funnel / active audit 无严重 violation**、**shadow audit 达到门槛** 之后，允许通过 **总开关 + allowlist + 百分比灰度**，将与 **r3 `visualRankingShadow` 同源** 的排序结果应用到 **新生成的** onboarding photo preview pool items。**r5-a 仅设计、不实现**；**默认关闭**；**不影响** worker、`finalScore`、`MatchResult`、旧 `PreviewPool`、正式匹配主链；**不接云视觉 API**，**不做** AI 美化 / AI 头像、人脸比对、身份认证、颜值评分、**不**根据照片自动判断性别。

- **`visualRankingShadow`** 已能 **计算并持久化**（r4-b 及后续）；**r4-c** 提供 **只读** shadow audit CLI 与 `readyForApplyToPoolDesign`（或等价 `recommendation.*` 字段，以 CLI 输出为准）阈值；**r4-d / r4-e** 记录 staging / 样本侧签收与复跑方法。

## 3. 设计目标

本阶段（r5-a）设计目标：

1. **明确**在什么条件下可以进入 **APPLY_TO_POOL 灰度实现**（门槛分 **preview pool 基线**、**shadow audit**、**PM spot-check** 三层）。
2. **明确** env：**总开关**、**allowlist**、**百分比灰度**、**sourceVersion 常量**，以及 **判定顺序**（先闸后名单后百分比）。
3. **明确**应用范围 **仅限** `generate()` **新创建** 的 onboarding photo preview pool（及对应 items）；**不**批量重写历史 active/archived pool；**不**改旧 `PreviewPool` 与正式匹配主链。
4. **明确可回滚**：关 env 后下一池回到 v1 等价逻辑与 v1 `sourceVersion` 语义；**不**要求删库内已生成的 v2 池。
5. **明确监控指标**：延续 r4-c 聚合指标 +（实现阶段）对「实际应用」分支的 shadow / audit 扩展方向。
6. **明确测试计划**（在 r5-b+ **实现时**执行）：开关 off 与 v1 一致、allowlist、percent、fallback、回归 worker / MatchResult / 旧池 **零 diff**。
7. **明确 r5-b / r5-c / r5-d（及建议的 r5-e）拆分**：设计评审与实现、staging signoff、closeout 分层，避免跳过设计直接上生产。

## 5. APPLY_TO_POOL 前置门槛

进入 **r5-b / r5-c 实现与合入** 前，建议将以下门槛视为 **门禁**。**数据暂不达标不阻止撰写本文档**；但 **不应** 以「设计已写」为由跳过门槛直接开生产灰度。

### 5.1 Preview pool 基线门槛

- **[P7.5-r4-final-closeout](./P7.5-r4-final-closeout.md)** 已完成（preview pool 稳定规则与限制已文档化）。
- **[r4-o3](./P7.5-r4-o3-preview-pool-local-signoff.md) 本地 signoff** 已完成（可重复手测路径）。
- **Active audit 无严重 violation**：对目标环境 **新生成** 的 active pool，[r4-o2](./P7.5-r4-o2-preview-pool-active-audit-and-image-source-dedup-closeout.md) 输出应满足签收口径（见 r4-final §7）。
- **生成的新 pool** 至少满足：
  - **`candidateUserId`**：6 槽 **全局唯一**（无 duplicate）。
  - **`sourceImageKey`**：在可解析 r4h slug 时 **同池互异**（无 duplicate image source）。
  - **无 viewer 本人**（`is_viewer_self` 全 false）。
  - **无 opposite gender violation**（二元异性门控）。
  - **6 个 items 完整**（不满 6 仍走既有 **候选不足** 语义，不凑重复）。

### 5.2 Shadow audit 门槛

沿用 **[r4-c](./P7.5-r4-c-visual-ranking-shadow-audit-closeout.md)** / **[r4-a](./P7.5-r4-a-visual-ranking-shadow-persist-design.md)** 阈值（与 CLI `readyForApplyToPoolDesign` 一致；比率为 **0–1** 或 **百分比** 等价表述）：

| 指标 | 条件 |
|------|------|
| `shadowCoverageRate` | ≥ **80%**（实现与 CLI 中多为 `≥ 0.8`） |
| `validShadowRows` | ≥ **50** |
| `viewerVisionAvailableRate` | ≥ **60%**（`≥ 0.6`） |
| Missing vision | **`avgCandidatesMissingVision` < 1.2** 或 **missing / (missing + vision) < 20%** |
| `avgChangedSlots` | **0.3–2.5**（含边界按 r4-c 单元测试定义） |
| `changedSlots = 6` 占比 | **< 1%** |
| `reflow` 的 `tierChangeRate` | **< 15%** |
| `aesthetic_fit` 的 `tierChangeRate` | **< 40%** |
| `style_similar` 的 `tierChangeRate` | **< 50%** |

**说明**

- **r4-d** 在 shadow 行数为 0 时 `readyForApplyToPoolDesign` 为 false **不视为 CLI 故障**；开灰度前应以 **最近一次** 满足阈值的 audit JSON **存档**为证（见 r4-d / r4-e）。
- **样本不足** 时：允许继续完善 **r5-a 设计** 与评审；**阻止**进入 **r5-b / r5-c** 实现与生产灰度。

### 5.3 PM / 产品 spot-check

在 **技术门槛** 满足后，建议 **产品**完成：

- 抽查至少 **20** 个 **新生成** pool（或与 staging  harness 等价批次）。
- 检查 **排序变化** 是否 **合理**（气质 / 风格 / reflow 语义可接受）。
- 检查是否出现 **明显低质候选上浮**、**重复图片**、**错性别**、**自己照片** 等 **P0/P1** 类问题。
- **记录通过**（简短签收表或 issue 评论）后，再进入 **灰度实现与 staging 小流量**（对应 **r5-d**）。

## 6. Env 设计

提出 **r5 实现阶段** 使用的 env（**名称以最终实现为准**；本文档为设计口径）：

```env
# 总闸：0 / false → 永不改写真实 pool items（与 r4「硬忽略」语义衔接，由实现 closeout 确认）
PEIMA_ONBOARDING_VISION_APPLY_TO_POOL=0

# 逗号分隔 viewer cuid；非空时仅名单内用户进入下一层百分比判定
PEIMA_ONBOARDING_VISION_APPLY_ALLOWLIST_USER_IDS=

# 0–100；在通过总闸 + allowlist（空则视为不限制名单）后，对 viewerUserId 做稳定哈希取模
PEIMA_ONBOARDING_VISION_APPLY_PERCENT=0

# 应用成功后写入 OnboardingPhotoPreviewPool.sourceVersion（与 r4 设计一致）
PEIMA_ONBOARDING_VISION_APPLY_SOURCE_VERSION=onboarding-photo-preview-v2-vision
```

**判定顺序（建议）**

1. **`APPLY_TO_POOL` 为真** → 否则 **等同 v1**，不应用 vision 排序到 items。
2. 若 **allowlist 非空**：`viewerUserId ∉ allowlist` → **不应用**。
3. **`hash(viewerUserId) % 100 < APPLY_PERCENT`**：`Percent=100` 表示在通过前两步后 **全开**；`Percent=0` 表示 **全关**（仅总闸 on 时仍不应用）。

**运维**

- **默认全关**；先行 **allowlist** + **低 Percent**；**随时可将总闸置 0** 完成降级（若配置中心可热更则更优，不要求在本设计定稿）。

## 7. 生效范围与写库边界

### 7.1 仅新池

| 维度 | 设计 |
|------|------|
| 新 vs 旧 | **仅**本次 `generate()` **新创建** 的 `OnboardingPhotoPreviewPool` / items **可**走 v2 排序写库；**不**批量改写已在库的 active/archived pool |
| 已有 active | **默认不动**；用户继续看旧排序直至再次 **generate**（若产品要「一键刷新」为 **另行 UX 需求**） |

### 7.2 允许变更的字段（建议仅限 items 层）

- `candidateUserId`
- `score`
- `reasonTags`（实现阶段定义 trace 短码，如 `tier:` + `vision:apply` 等，见 r5-e closeout）

### 7.3 禁止变更

- **槽位数** 恒为 **6**；**`rankInPool`** 1–6；**`tier`** 字符串（`aesthetic_fit` / `style_similar` / `reflow`）与 **`displayMode`**（`clear` / `blurred` / `hidden`）**不变**。
- **worker、`finalScore`、`MatchResult`、旧 `PreviewPool`**：**零接触**。
- **GET me/latest** 等 **不**返回 shadow 表原始内容；若需「解释文案」走 **独立字段或前端 copy**，**不**在 r5 首版塞入模型 ID 或 raw vision。

## 8. 排序原则（与 r3 shadow 同源）

**原则**：与 **P7.5-r3 `visual-ranking-shadow-scoring` + builder** 相同的 **纯函数** 生成每 tier 的排序；apply 分支应 **直接**使用该逻辑产出 slot 定义并写入 items，**避免**「仅 shadow 一套、apply 另一套」的长期漂移。

| Tier | 视觉增强（概要） | Fallback（与 r3 一致） |
|------|------------------|------------------------|
| **aesthetic_fit** | Jaccard(viewer `styleTags`, candidate `photoVisualTags`) × confidence | `computeStyleScore` |
| **style_similar** | Jaccard(viewer **passing** 图 `photoVisualTags`, candidate tags) × confidence | `computePreferenceScore` |
| **reflow** | **最旧注册** 为主序；vision **仅极小 ε tie-break** | `pickOldest` |

**Vision 可用性**（与 r3/r4 输入规则对齐，细节见 r3 文档与代码）：

- Candidate：首张图 `visionStatus === ok`；`rejected` / `needs_reupload` / `appealed` / `appeal_rejected` **不用** vision。
- Viewer：最新 **passing** 图且 vision ok；否则 `style_similar` 走 preference fallback。
- `visionStatus !== ok` 或缺 vision → **该槽位使用 v1 等价分**（与 shadow fallback 一致）。

**探索位**：reflow **禁止**因 vision **大幅**改人；若 tie-break 导致与 v1 不同，须依赖 **§5.2** 中 **reflow tierChangeRate** 监控。

## 9. sourceVersion、Shadow 观测与回滚

### 9.1 sourceVersion

| 场景 | 行为 |
|------|------|
| 应用开启且 eligibility 通过 | `OnboardingPhotoPreviewPool.sourceVersion = PEIMA_ONBOARDING_VISION_APPLY_SOURCE_VERSION`（默认 `onboarding-photo-preview-v2-vision`） |
| 应用关闭 | 新 `generate()` 回到 **v1** 算法与 v1 `sourceVersion` 语义（具体常量以实现为准） |
| 历史 pool | **不迁移**；仅新池可带 v2 |

### 9.2 Shadow 持续写入（建议）

- **每次** `generate()` 仍可计算并 **persist** hypothetical shadow（与 r4 一致）。
- **`VisualRankingShadowV1.appliedToPool`**：r3/r4 **恒 false**；r5 在实际应用分支内置 **`true`**，并可扩展 `appliedSourceVersion` / `summary.applyMeta` 等（**在 r5-b 定稿**，避免 breaking 变更）。

### 9.3 回滚

- **关 env** → 下一池 **v1**；**不**删库内旧 v2 pool。
- 用户侧「回到 v1 排序」：依赖 **再次 generate**（若已有 archive 语义则复用）。

### 9.4 r4-c CLI 扩展方向（r5-b/c 后评审）

- 可选 filter：`--appliedOnly` / payload `appliedToPool=true`。
- 或 `schemaVersion` 升到 `visual-ranking-shadow-v2` 仅表示 **含 apply 元数据**（二选一，**实现前评审**）。

## 10. 监控指标

**基线（已有）**：r4-c audit 输出的覆盖率、valid 行数、missing vision、`avgChangedSlots`、全洗牌占比、各 tier `tierChangeRate` 等（见 §5.2）。

**灰度期建议追加（实现阶段落地）**

- **应用率**：`appliedToPool=true` 的 shadow 行占比 / 与总 generate 次数比（定义在实现 closeout）。
- **按 `sourceVersion` 分桶**：v1 vs v2 新池数量；便于回滚验证。
- **Active audit 通过率**：v2 池是否仍 **100%** 满足 §5.1（可与 r4-o2 同源脚本扩展 filter）。
- **产品投诉 / 支持工单** 标签（若已有）：与灰度时间窗对齐的 **定性** 监控。

## 11. 测试计划（未来 r5-b+ 实现时执行）

- **`APPLY_TO_POOL=0`**：items 与现网 v1 **一致**（对固定 fixture / 种子可比特级或结构化快照断言）。
- **allowlist**：仅名单内 viewer 的 create payload 体现 v2 候选集。
- **`Percent=0`**：不应用；**`Percent=100`** + 总闸 on：在 allowlist 语义下 **全开**。
- **缺 vision / blocked review**：fallback 与单测 golden 对齐 r3 shadow。
- **reflow**：与 v1 同一主序时 **多数情况** 同人；异常在 audit 指标中可见。
- **`sourceVersion`** 字段断言。
- **关 env** 后下一池 **v1**。
- **回归**：worker、`MatchResult`、旧 `PreviewPool` 相关测试 **零 diff**。

## 13. 风险与缓解（摘要）

| 风险 | 缓解 |
|------|------|
| 标签不准导致大面积换人 | §5.2 阈值 + allowlist + 低 Percent；监控 `avgChangedSlots` |
