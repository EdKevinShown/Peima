# P7.5-r5-c1 — APPLY_TO_POOL Allowlist-only Writer Closeout

> **状态**：实现完成（allowlist-only 最小 writer） · 默认关闭 · **未**启用 percent 灰度  
> **对齐**：[P7.5-r5-c0](./P7.5-r5-c0-apply-to-pool-allowlist-writer-plan.md)、[P7.5-r5-b2](./P7.5-r5-b2-apply-dry-run-signoff-closeout.md)

---

## 1. 本轮目标

在 r5-b dry-run 签收基础上，实现 **allowlist-only** 的真实写池：仅当 env 总闸、allowlist、eligibility、shadow 与 guardrails 全部通过时，将 **visualRankingShadow 同源** 的 3+2+1 **候选与分数**写入**本次新生成**的 `OnboardingPhotoPreviewPoolItem`；否则回落 **v1 baseline**。

---

## 2. Env 行为（r5-c1 固定 allowlist-only）

| Case | 配置 | 结果 |
|------|------|------|
| 1 | `APPLY_TO_POOL=0` | v1 |
| 2 | `APPLY_TO_POOL=1`，allowlist 空，`PERCENT=100` | **v1**，`allowlist_empty` |
| 3 | `APPLY_TO_POOL=1`，viewer 不在 allowlist | v1，`not_in_allowlist` |
| 4 | allowlist 命中 + eligibility ok + guards ok | **v2** |
| 5 | allowlist 命中但 guard 失败 | v1，具体 guard reason |

`PEIMA_ONBOARDING_VISION_APPLY_PERCENT` **不参与** writer 决策。

---

## 3. Writer decision 规则

纯函数：`evaluateOnboardingVisionApplyWriterDecision`（`apps/api/src/modules/onboarding/vision/onboarding-vision-apply-writer-decision.ts`）

必须全部满足才 `shouldApply=true`：

1. `APPLY_TO_POOL === "1"`
2. allowlist 非空
3. viewer ∈ allowlist
4. `eligibility.eligible && eligibility.reason === "ok"`
5. shadow 结构有效（6 槽、tier 顺序）
6. shadow 槽位 guard（唯一 candidate、唯一 source key、无 self、二元性别门控）
7. 无 blocked review（首张图 `reviewStatus`）
8. `applySourceVersion` 在白名单（默认 `onboarding-photo-preview-v2-vision`）

---

## 4. v1 fallback

任一 writer 条件失败 → `sourceVersion=onboarding-photo-preview-v1`，items 来自 **baseline** `buildSixNonSelfPreviewSlots`；不向用户额外抛错（baseline 本身失败仍 `BadRequestException`）。

---

## 5. v2 写入范围

**Pool**：`sourceVersion = applySourceVersion`（默认 `onboarding-photo-preview-v2-vision`）

**Items**（每条）：

- `candidateUserId` = shadow `shadowCandidateUserId`
- `score` = shadow `shadowScore`
- `reasonTags` = `[applySourceVersion, tier:*, vision:apply]`
- **`rankInPool` / `tier` / `displayMode`** 保持 3+2+1 结构不变

---

## 6. Shadow metadata（兼容 r5-b / r4-c）

采用 **方案 B（保守）**：

- 根 **`appliedToPool` 仍为 `false`**（r4-c `parseVisualRankingShadowPayloadSafe` 无需分叉）
- **`summary.applyDryRun.appliedToPool` 恒 `false`**（dry-run 语义不变）
- 真实写回记录在 **`summary.applyResult`**：

```json
{
  "evaluated": true,
  "applied": true,
  "reason": "ok",
  "sourceVersion": "onboarding-photo-preview-v2-vision"
}
```

`generate()` 流程：`buildForGenerate` → writer decision → `create` pool/items → `computeShadow` persist（附带 `eligibility` + `writerDecision`）。
