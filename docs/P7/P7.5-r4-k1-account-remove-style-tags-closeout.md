# P7.5-r4-k1：从 /account 移除照片风格偏好 UI（closeout）

## 背景与原因

- r4-k 已将 **「整体气质 / 照片感觉」** 与 **`UserPreference.styleTags`** 对齐，数据源统一正确。
- 产品变更：**照片风格偏好只应在 onboarding 流程中编辑**，避免 `/account` 与 `/onboarding/photo-preference` 在位置上重复、分散用户心智。

## 保留的数据源

- **`UserPreference.styleTags`** 列与 Prisma 模型**保留**，未做 migration。
- **白名单** `ACCOUNT_STYLE_TAG_WHITELIST`、`ONBOARDING_PHOTO_STYLE_TAG_POOL` 等 shared 常量**保留**。

## 唯一编辑入口

- **`/onboarding/photo-preference`**：「整体气质 + 照片感觉」→ 写入 `styleTags`；「优先关注」仍不入库、不进入 `styleTags`。
- **`/account`**：**不再展示、不提交** `styleTags`。

## Account 保存不覆盖 `styleTags` 的保护

- **前端**：`AccountPage` 调用 `PUT /preferences/:userId` 时 **省略 `styleTags` 键**，不再随「保存偏好」发送。
- **后端**：`PreferencesService.buildUpdateInput` 仅在 `dto.styleTags !== undefined` 时更新该字段，故对已有偏好行属 **patch-like**；不传则 Prisma `update` 不触碰 `styleTags`。
- **回归测试**：`preferences.service.upsert-gate.spec.ts` 中 **「update without styleTags leaves existing styleTags untouched」** 固定该行为。

说明：若将来通过其它客户端显式传 `styleTags: []`，仍可能清空；当前 web Account 不再发送该字段。

## Onboarding 与后端

- **`POST /onboarding/photo-preferences`**、`OnboardingService.savePhotoPreferences` **未改**（本轮）：仍校验池 + 合并扩展标签 + 写 `onboardingPhotoAestheticCompletedAt`。
- **`PreferencesService`** 仍对 **显式传入** 的 `styleTags` 做白名单校验（供 API 其它调用方或未来用途）。

## 修改文件（r4-k1）

- `apps/web/src/pages/AccountPage.jsx` — 移除照片风格 chip 与相关 state / payload。
- `apps/api/test/preferences.service.upsert-gate.spec.ts` — 新增不传 `styleTags` 时不覆盖用例。
- `docs/P7/P7.5-r4-k-style-tags-single-source-closeout.md` — 补充「唯一编辑入口」与 account 行为。
- `docs/P7/P7.5-r4-k1-account-remove-style-tags-closeout.md` — 本文档。
