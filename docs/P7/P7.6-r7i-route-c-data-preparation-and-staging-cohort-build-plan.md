## 1. 一句话结论

P7.6-r7i 设计 Route C 所需的 **clean staging cohort** 数据准备方案：当前 [r7h](./P7.6-r7h-route-c-staging-cohort-readiness-closeout.md) 显示 **`recommendedForRouteC=true` 为 0**，无法执行真实 **PM 主证据**审计。本轮目标是规划如何准备 **5–10** 个 clean viewers，每个 viewer 至少 **6** 个 candidates，并补齐 image / Cloud Vision / 20D / preference / **clean active pool** / **MatchResult** / **M6** 对照。本轮**只做计划**，不改代码、不写 DB、不进入 r8。

## 4. Clean viewer 数据要求

每个 **viewer** 必须满足（与 [r7g §4.1](./P7.6-r7g-route-c-staging-cohort-execution-runbook.md) 一致）：

| 要求 | 阈值 |
|------|------|
| passed image | 至少一张 `detectionStatus=passed` |
| Cloud Vision tags | `detectionScoreJson` 含 usable `photoVisualTags` |
| 20D profile | `nonNull20DCount >= 4`（推荐 **≥18** 或完整 20D） |
| `user_preferences` | 行存在 · 与人口字段可互命中 |
| clean active onboarding pool | `status=active` · **非** `dev-p76-*` pool id |
| `candidatePoolCount` | **≥ 6** |
| `candidateWithVisionCount` | **≥ 6** |
| `candidateWith20DProfileCount` | **≥ 6** |
| `candidateWithPreferenceCount` | **≥ 6** |

### 4.1 增强（排序优先）

| 增强 | 说明 |
|------|------|
| `hasMatchResult=true` | legacy old-new 有对照 |
| `hasM6RrmTop2=true` | `matchInsights.rrmV2Top2Selector` 存在 |
| `seedDependent=false` | 无 `dev-p76-*` profile/pref 写入 |
| `syntheticPool=false` | 无 r7c5 式 synthetic pool |

## 5. Candidate 数据要求

每个 **candidate**（池内）必须：

| # | 要求 |
|---|------|
| 1 | **`candidateUserId` ≠ `viewerUserId`**（self check = 0） |
| 2 | 通过 **gender / preference** gate（与 r3b 一致） |
| 3 | passed image + Cloud Vision tags |
| 4 | meaningful **20D** `user_profile`（≥4 核心维） |
| 5 | **`user_preferences`** 行 |
| 6 | 无 image **review / detection** blocker |
| 7 | 尽量与池内他人有 **photoVisualTags / 20D / RRM** 差异（避免并列无效） |

**可复用素材（非 viewer）：** 见 [r7h §5](./P7.6-r7h-route-c-staging-cohort-readiness-closeout.md) — `cmr4hf000716…` · `cmr4hm000816…` · `cmfemn001…` 等（作 candidate 优先，作 viewer 须先有 pool）。

## 6. 数据准备路线

### 6.1 Route C-A — 现有真实 dev/staging user（**优先**）

| 步骤 | 动作 |
|------|------|
| 1 | 从库中筛 vision + 20D + preference **完整** user（[r7g §4](./P7.6-r7g-route-c-staging-cohort-execution-runbook.md) 扩展列表） |
| 2 | 排除 `dev-p76-*` seed 标记 · 排除 r7d 三 viewer |
| 3 | 通过**正常** onboarding / photo preview 流程生成 **active** pool（**非**手工 INSERT synthetic items） |
| 4 | 池内候选优先选已合格 user；不足则 onboarding 拉新用户 |
| 5 | staging **batch match** 生成 `MatchResult`（worker 自然写入） |
| 6 | 重跑 readiness SQL |

| 优点 | 缺点 |
|------|------|
| 最接近 PM 主证据 | 依赖 staging 用户量与流程可用 |

### 6.2 Route C-B — 导入半真实 staging cohort（**推荐若 A 不足**）

| 步骤 | 动作 |
|------|------|
| 1 | 准备 **5–10** 测试 viewer（anonymized / staging 账号） |
| 2 | 每人 **6–10** 候选（预定义 cohort 表） |
| 3 | 全员补齐 image · vision backfill · 问卷 20D · preference |
| 4 | 走现有 onboarding 生成 **clean** pool |
| 5 | batch match → MatchResult / M6 |
| 6 | readiness 验证 |

| 优点 | 缺点 |
|------|------|
| 可控 · 可复现 | 工作量较大 · 仍非 production 流量 |

### 6.3 Route C-C — 最小人工 staging cohort（**兜底**）

| 步骤 | 动作 |
|------|------|
| 1 | 小规模 PM 审阅专用 cohort |
| 2 | 文档标记 **`stagingOnly=true`** |
| 3 | **不**进入 production · **不**作全量 rollout 证据 |

| 优点 | 缺点 |
|------|------|
| 快速 unblock PM 讨论 | PM 证据强度弱于 A/B |

### 6.4 路线选择建议

| 情况 | 建议 |
|------|------|
| dev 库已有足够 onboarding 完成用户 | **C-A** 为主 |
| 用户量不足 | **C-A + C-B** |
| 仅 PM 工作坊 | **C-C**（须书面 scope） |

**禁止：** 把 [r7c5](./P7.6-r7c5-fixture-preparation-route-b-closeout.md) `dev-p76-r7c5-pool-*` **伪装**为 `syntheticPool=false`。
