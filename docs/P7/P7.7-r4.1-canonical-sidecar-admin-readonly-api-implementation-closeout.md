## 5. Query / DTO behavior

**Defaults:**

| Param | Default |
|-------|---------|
| `limit` | 50 (max 100) |
| `activeOnly` | `true` (`supersededAt` null) |
| `includeDeleted` | `false` (`deletedAt` null) |
| `appliedToMatchResult` | `false` when omitted |

**Filters:** `auditRunId`, `environment`, `viewerUserId`, `matchResultId`, `selectedCandidateId`, `sourceVersion`, `mode`, `promotionStatus`, `appliedTo*`, `rolledBack`, `generatedAtFrom`/`To` → **`createdAt`**, `cursor`.

**List item:** includes `safety` block (`isSidecarOnly`, `notAppliedTo*`, `readByGetPath=false`, `readByWorker=false`).

**Detail:** sanitized `dryRunPayload` / `stageSummary` / `guardrails` / `safeFallbackMeta`; `rollbackTokenPresent` / `previousSnapshotHashPresent` booleans only.

**Aggregate:** `sidecarOnlyCount`, `*ViolationCount`, `promotionStatusCounts`, `modeCounts`, etc.

---

## 6. Privacy / safety

- Recursive sanitize via `P76_CANONICAL_MATCH_RESULT_SIDECAR_WRITER_FORBIDDEN_JSON_KEYS`
- No raw `rollbackToken` / `previousSnapshotHash` in responses
- `readByGetPath` / `readByWorker` always `false` on list items
- Service uses only `p76CanonicalMatchResultMeta.findMany` / `findUnique`
- No `create` / `update` / `delete` / `matchResult` mutation
