# P7.3 — 照片质量检查 MVP（Closeout）

## 1. 本轮目标

- 在**不做 AI 美化**、**不生成 AI 头像**、**不做复杂人脸识别**的前提下，提升 **onboarding 照片上传** 的可用性与可预期质量。
- **仅做前端基础校验与用户提示**；不改变正式匹配主链、不改变 onboarding 预览池生成算法。

## 2. 已完成能力

- 支持 **`image/jpeg`**、**`image/png`**、**`image/webp`**
- 拦截 **GIF**、**HEIC**、**PDF**、**视频**、**非图片文件**（依赖 MIME + 可解码检查；`accept` 限制常见图片扩展名）
- 单张最大 **5MB**（与后端上传限制一致）
- **本地解码检查**（浏览器能否加载所选文件）
- **上传失败**时展示**中文**提示（含对后端错误的映射）
- **仅上传成功**后进入 **`/onboarding/photo-preference`**
- **上传失败**时留在 **`/onboarding/photo-upload`**

## 3. 修改文件

- `apps/web/src/utils/onboardingPhotoValidation.js`
- `apps/web/src/pages/OnboardingPhotoUploadPage.jsx`

## 4. 前端校验规则

1. 文件**不能为空**（含大小为 0）。
2. **`MIME`** 必须是 **`image/jpeg`**、**`image/png`**、**`image/webp`** 之一。
3. 文件大小**不能超过 5MB**。
4. 图片必须能被**浏览器成功解码**（`Image` + 对象 URL 探测）。

校验在**选择文件后**与**点击上传前**均会执行，避免不合格文件进入上传与跳转。

## 5. 错误文案（产品固定用语）

| 场景 | 文案 |
|------|------|
| 格式不支持 | 请上传 JPG、PNG 或 WebP 格式的照片。 |
| 超过大小限制 | 照片不能超过 5MB，请压缩后重新上传。 |
| 无法解码 / 损坏 | 这张图片无法读取，请换一张清晰照片。 |
| 空文件 | 请选择一张有效的照片。 |

上传接口失败时，另通过 **`mapOnboardingPhotoUploadError`** 将常见英文/状态码映射为简短中文（不暴露堆栈与原始技术细节）。

## 6. 后端说明

- **本轮未改 API**（无 `ImagesController` / `ImagesService` 等行为变更）。
- 现有 **`ImagesController`**（如 **`FileInterceptor` 5MB**）与 **`ImagesService.createFromUpload`**（**MIME**、**空 buffer** 等）已具备兜底能力。
- **Onboarding 路径上的格式收窄**主要由**前端**执行（仅 jpeg/png/webp）。
- 后端仍可能服务**其它**图片上传入口，故**未**在全局 `ImagesService` 中强行移除 GIF 等类型，以免破坏既有兼容行为。

## 8. 手测 checklist

- [ ] **JPG / PNG / WebP** 可正常选择、校验通过并成功上传  
- [ ] **PDF** 被前端拦截（格式 / 解码）  
- [ ] **GIF** 被前端拦截  
- [ ] **超过 5MB** 被前端拦截  
- [ ] **损坏或伪装图片** 无法解码时被拦截  
- [ ] **上传失败**不跳转，仍停留在 **`/onboarding/photo-upload`**  
- [ ] **上传成功**进入 **`/onboarding/photo-preference`**

## 9. 重要边界（明确未做 / 未改）

- 不做 **AI 美化**
- 不做 **AI 头像**
- 不做**真实人脸检测**
- 不做**单人照检测**
- 不做**清晰度评分**（无模型/无服务端画质分）
- 不做**视觉 embedding**
- 不改 **3+2+1** onboarding 预览池**生成逻辑**
- 不改 **worker**
- 不改 **`finalScore`**
- 不改 **`MatchResult`**
- 不改旧 **`PreviewPool` / `PreviewPoolItem`** 语义
