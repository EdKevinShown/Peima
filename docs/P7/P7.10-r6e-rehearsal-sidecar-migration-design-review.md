## 4. Prisma model review

### 4.1 Migration-review model (r6e adjustments vs r6d draft)

Changes from r6d §6.2 for **first migration**:

- `matchResultId` → **`String` required (NOT NULL)** — see §6.4 Option A
- `auditRunId` → **`String` required (NOT NULL)** — writer must always set; supports unique index
- Optional `viewer User @relation` — **deferred** in v1 (plain `viewerUserId` string, like minimal coupling path in r6d)
- **No** `MatchResult` relation / **no** reverse field on `MatchResult` in v1

```prisma
/// P7.10-r6e migration-review draft — NOT applied to schema.prisma
model P76CanonicalWriterRehearsalMeta {
  id String @id @default(cuid())

  viewerUserId    String
  matchResultId   String

  baselineCandidateUserId String?
  proposedCandidateUserId String?

  baselineFinalScore Float?
  proposedScore      Float?
  scoreVersion       String?

  wouldChangeCandidate Boolean @default(false)
  eligible             Boolean @default(false)
  guardrailReason      String
  scoreDeltaBand       String?

  sourceType            String
  sourceVersion         String
  pipelineVersion       String
  readPathSourceVersion String?

  allowlistApplyMetaId String?

  auditRunId     String
  rehearsalMode  String @default("sidecar_rehearsal")
  environment    String @default("dev")

  appliedToMatchResult Boolean @default(false)

  shadowPayload Json
  summary       Json?

  generatedAt  DateTime  @default(now())
  expiresAt    DateTime?
  supersededAt DateTime?
  deletedAt    DateTime?

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@unique([matchResultId, auditRunId, pipelineVersion])
  @@index([viewerUserId])
  @@index([matchResultId])
  @@index([sourceVersion])
  @@index([readPathSourceVersion])
  @@index([auditRunId])
  @@index([eligible])
  @@index([guardrailReason])
  @@index([appliedToMatchResult])
  @@index([supersededAt])
  @@index([generatedAt])
  @@index([environment, generatedAt])
  @@map("p76_canonical_writer_rehearsal_meta")
}
```

### 4.2 Field-level review

| Topic | Repo convention | r6e recommendation |
|-------|-----------------|----------------------|
| `id` | `@default(cuid())` on meta tables (`User`, `P76AllowlistApplyMeta`, RRM meta) | **Use `cuid()`** |
| `Json` | `JSONB` in PostgreSQL migrations (`p76_allowlist_apply_meta`, RRM meta) | **`Json` → JSONB** |
| `DateTime` | `TIMESTAMP(3)` in SQL migrations | **`DateTime` with ms precision** |
| `Float` vs `Decimal` | `MatchResult.finalScore` uses **`Float`**; preview pool scores use `Float` | **Use `Float?`** for scores (not `Decimal`) |
| `matchResultId` nullable (r6d) | RRM meta uses **required** `matchResultId` | **Required in v1** — rehearsal always tied to existing `MatchResult` row |
| `auditRunId` nullable (r6d) | Hook jobs use composite unique with required parts | **Required in v1** |
| `environment` default | New column; no precedent on P7.6 meta | **Default `"dev"`**; CHECK `dev` \| `staging` (§6.2) |
| `appliedToMatchResult` | Allowlist meta defaults **`false`**; boolean flags indexed | **Default `false`** + DB CHECK (§6.1) |
| `MatchResult` FK | RRM meta: **has** FK to `match_results`; allowlist: FK to `users` only | **No FK to `MatchResult` in v1** (opaque `matchResultId` string); optional FK in later milestone |
| `allowlistApplyMetaId` | N/A | **Plain string**, no FK v1 |
| `viewerUserId` FK | `P76AllowlistApplyMeta` → `User` CASCADE | **Defer FK** v1 (optional r6e2); validate in writer |
| Reverse relation on `MatchResult` | RRM adds `rrmTop2DisplayMeta` on model | **Do not add** in v1 per r6d |

**Writer rule (even if DB allows null elsewhere):** **`auditRunId` MUST be set** on every insert (UUID per CLI run or batch job id).

## 6. Constraint review

### 6.1 `appliedToMatchResult = false`

| | |
|---|---|
| **Option** | `CHECK ("appliedToMatchResult" = false)` |
| **Pros** | Hard P0 safety; misconfigured writer fails at insert |
| **Cons** | Future canonical phase would need **new table** or migration to drop CHECK — acceptable because rehearsal table must never apply to `MatchResult` |
| **Repo precedent** | **CHECK constraints not found** in existing `packages/database/prisma/migrations/` (rg search) — **new pattern** for Peima |
| **Recommendation** | **Add CHECK in v1** — rehearsal table purpose is compare-only |

### 6.2 `environment` block

| | |
|---|---|
| **Option** | `CHECK ("environment" IN ('dev', 'staging'))` |
| **Pros** | Blocks `production` inserts even if writer misconfigured |
| **Cons** | Custom local labels (e.g. `local-docker`) must map to `dev` in writer |
| **Recommendation** | **Add CHECK** + writer normalizes env to allowed enum |

### 6.3 `auditRunId` NOT NULL

| | |
|---|---|
| **Recommendation** | **NOT NULL** in migration; writer **always** generates `auditRunId` (cuid/uuid per run) |
| **Rationale** | Powers idempotent unique key; avoids null unique-index holes |

### 6.4 `matchResultId` — uniqueness & nulls

| Option | Description | Recommendation |
|--------|-------------|----------------|
| **A** | `matchResultId NOT NULL` | **Recommended v1** — matches r6a audit (always has `MatchResult` row) |
| B | Nullable + app idempotency | Weak unique constraint in Postgres (multiple NULLs) |
| C | Synthetic `subjectKey` | Extra complexity; defer |

**Postgres behavior:** `UNIQUE (match_result_id, …)` treats NULLs as distinct — **avoid nullable `matchResultId`** for v1.

**r6e decision:** **`matchResultId` NOT NULL** — no-row / `matching_pending` rehearsal is **out of scope** for first table (belongs to API contract + artifacts, not DB v1).

Rehearsal volume expected **low** (dev/staging audits). Index count acceptable for Admin read paths.

| Index | Query it supports | Keep? |
|-------|-------------------|-------|
| `viewerUserId` | Latest per viewer, Admin list | **Yes** |
| `matchResultId` | Drill-down from result | **Yes** |
| `sourceVersion` | Payload version filter | **Yes** |
| `readPathSourceVersion` | Cohort coverage (`p7.6-r7j3-staging-cohort-v1`) | **Yes** |
| `auditRunId` | Export/cleanup per run | **Yes** |
| `eligible` | “Would apply” dashboards | **Yes** |
| `guardrailReason` | `ok` / `missing_sidecar` / `rolled_back` histograms | **Yes** |
| `appliedToMatchResult` | Violation monitor (expect 0 rows `true`) | **Yes** (P0 guard) |
| `supersededAt` | Hide superseded rows | **Yes** |
| `generatedAt` | Time-range purge | **Yes** |
| `(environment, generatedAt)` | Env-scoped retention | **Yes** |
| Unique `(matchResultId, auditRunId, pipelineVersion)` | Idempotent insert | **Yes** (constraint) |

**Insert cost:** Higher than heap-only table; acceptable for audit/rehearsal frequency.
