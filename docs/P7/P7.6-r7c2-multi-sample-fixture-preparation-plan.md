## 4. Fixture 准备策略（优先级）

按以下顺序尝试，**前一步不足再进入下一步**：

| 优先级 | 策略 | 说明 |

| **1** | 使用现有真实 dev data | 查是否已有满足门槛但未出现在 r7c SQL 结果中的 user（LIMIT、过滤条件） |

**每一步都必须：**

- **dev-only**（非 production）
- **可回滚**（记录 before 快照 + rollback SQL）

- **有 before / after verification**（§10）
- **`seedDependent=true`**（若写入 fixture）
- **不写** `MatchResult` / **不改** `finalScore` / **不改** worker

## 8. SQL 诊断清单（只读）

**连接示例：**

```bash
docker exec -it peima-postgres psql -U user -d peima
```

**约定：** camelCase 列双引号；与 [r7c §4](./P7.6-r7c-multi-sample-audit-execution-runbook.md) 使用相同 `profile_dims`（6 核心维）近似 `nonNull20DCount`。

### 8.1 Partial viewer 池内 candidate 明细

```sql
-- r7c2: pool candidates for a viewer (READ-ONLY)
-- Replace :viewer_id

WITH profile_dims AS (
  SELECT
    up."userId",
    (
      (CASE WHEN up."relationshipPace"    IS NOT NULL THEN 1 ELSE 0 END) +
      (CASE WHEN up."emotionalStability" IS NOT NULL THEN 1 ELSE 0 END) +
      (CASE WHEN up."communicationStyle" IS NOT NULL THEN 1 ELSE 0 END) +
      (CASE WHEN up."conflictHandling"   IS NOT NULL THEN 1 ELSE 0 END) +
      (CASE WHEN up."lifePace"           IS NOT NULL THEN 1 ELSE 0 END) +
      (CASE WHEN up."socialNeed"         IS NOT NULL THEN 1 ELSE 0 END)
    ) AS non_null_core_dim_count
  FROM user_profile up
)
SELECT
  oppi."candidateUserId",
  EXISTS (
    SELECT 1 FROM user_images ui
    WHERE ui."userId" = oppi."candidateUserId"
      AND ui."detectionStatus" = 'passed'
      AND ui."detectionScoreJson" IS NOT NULL
  ) AS has_live_vision,
  COALESCE(pd.non_null_core_dim_count, 0) AS non_null_core_dim_count,
  (pref."userId" IS NOT NULL) AS has_preference
FROM onboarding_photo_preview_pools opp
JOIN onboarding_photo_preview_pool_items oppi ON oppi."poolId" = opp."id"
LEFT JOIN profile_dims pd ON pd."userId" = oppi."candidateUserId"
LEFT JOIN user_preferences pref ON pref."userId" = oppi."candidateUserId"
WHERE opp."status" = 'active'
  AND opp."userId" = 'cmp70ft7a001e6znksjb2jo03'
ORDER BY oppi."candidateUserId";
```

### 8.2 缺 20D profile 的 candidate（池内）

在 §8.1 结果上筛选 `non_null_core_dim_count < 4`。

### 8.3 缺 preference 的 candidate（池内）

在 §8.1 结果上筛选 `has_preference = false`。

### 8.4 缺 vision 的 candidate（池内）

在 §8.1 结果上筛选 `has_live_vision = false`。

### 8.5 可复用 candidate user 列表（全局 dev）

```sql
-- r7c2: users suitable as pool candidates (READ-ONLY)
WITH profile_dims AS (
  SELECT
    up."userId",
    (
      (CASE WHEN up."relationshipPace"    IS NOT NULL THEN 1 ELSE 0 END) +
      (CASE WHEN up."emotionalStability" IS NOT NULL THEN 1 ELSE 0 END) +
      (CASE WHEN up."communicationStyle" IS NOT NULL THEN 1 ELSE 0 END) +
      (CASE WHEN up."conflictHandling"   IS NOT NULL THEN 1 ELSE 0 END) +
      (CASE WHEN up."lifePace"           IS NOT NULL THEN 1 ELSE 0 END) +
      (CASE WHEN up."socialNeed"         IS NOT NULL THEN 1 ELSE 0 END)
    ) AS non_null_core_dim_count
  FROM user_profile up
)
SELECT u."id" AS "candidateUserId"
FROM users u
JOIN profile_dims pd ON pd."userId" = u."id" AND pd.non_null_core_dim_count >= 4
JOIN user_preferences pref ON pref."userId" = u."id"
WHERE EXISTS (
  SELECT 1 FROM user_images ui
  WHERE ui."userId" = u."id"
    AND ui."detectionStatus" = 'passed'
    AND ui."detectionScoreJson" IS NOT NULL
)
ORDER BY u."id"
LIMIT 50;
```

### 8.6 可作为 viewer 的 user（有 preference · 待查池）

```sql
-- r7c2: potential viewers — has preference, may lack pool/20D (READ-ONLY)
SELECT
  u."id" AS "viewerUserId",
  (pref."userId" IS NOT NULL) AS has_preference,
  EXISTS (
    SELECT 1 FROM onboarding_photo_preview_pools opp
    WHERE opp."userId" = u."id" AND opp."status" = 'active'
  ) AS has_active_pool
FROM users u
LEFT JOIN user_preferences pref ON pref."userId" = u."id"
WHERE pref."userId" IS NOT NULL
ORDER BY has_active_pool DESC, u."id"
LIMIT 30;
```

### 8.7 Onboarding pool 是否存在

```sql
-- r7c2: active onboarding pools (READ-ONLY)
SELECT
  opp."userId" AS "viewerUserId",
  opp."id" AS "poolId",
  opp."status",
  COUNT(oppi."candidateUserId") AS item_count
FROM onboarding_photo_preview_pools opp
LEFT JOIN onboarding_photo_preview_pool_items oppi ON oppi."poolId" = opp."id"
WHERE opp."status" = 'active'
GROUP BY opp."userId", opp."id", opp."status"
ORDER BY item_count DESC;
```

## 9. Seed / fixture 写入边界（设计 · r7c3 执行）

|------|------|

| `APPLY_TO_POOL` / percent | r8 前禁止 |
| 删除 legacy photo matching | r8 前禁止 |
