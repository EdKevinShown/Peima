## 1. 一句话结论

P7.6 采用**漏斗式双向匹配流程**：先用 **PhotoVisual** 建立双向照片兴趣池，再用 **20D** 双向画像兼容做核心排序，最后由 **RRM** 在 Top2 中做关系节奏 **2 选 1**。初期全程 **shadow**，不改 `MatchResult` / `finalScore` / worker / RRM 主链。

```text
PhotoVisual First Pool  →  20D Bidirectional Ranking  →  RRM Top2 Final Selector
     （进池 / 初筛）              （核心排序）                  （最终 2 选 1）
```

---

## 2. 为什么不是并列加权 aggregator

**错误模型**（本文档**不采用**）：

- 将 PhotoVisual、20D、RRM 三层**并列**输入一个 **Mutual Match Aggregator**
- 用 `0.55·20D + 0.20·Photo + 0.25·RRM` 等**统一加权**得到最终 `mutualMatchScore`

**产品定义**：

| 层 | 角色 |
|----|------|
| **照片（PhotoVisual）** | **入口吸引力** — 建立双方视觉风格互相不排斥、有基础吸引力的候选池；**只负责进池 / 初筛**，不决定最终匹配 |
| **20D** | **核心兼容判断** — 在 PhotoVisual Pool 内判断双方是否真的适合；输出 TopN / **Top2** |
| **RRM** | **最终关系推进 selector** — **仅**在 20D 产生的 Top2 / short list 中 **2 选 1**；**不参与**大池排序 |

因此正确流程是 **Photo → 20D → RRM**，而不是 Photo + 20D + RRM 一起平均加权。

旧照片匹配只能回答「A 是否喜欢 B 的照片」；商业化需要「A 适合 B 且 B 也适合 A」— 这由 **20D 双向排序** 与 **RRM Top2 选择** 完成，而非照片分与 20D 分相加。

## 3. Stage 1：PhotoVisual First Pool

**输入**：

- `A.styleTags` / `B.styleTags`
- `A.detectionScoreJson.vision.photoVisualTags` / `B` 同理
- `qualityTags` / `sceneTags` / `confidence` **仅作辅助**，不作为颜值分

**计算**：

```text
AtoBPhotoVisualFit = overlap(A.styleTags, B.photoVisualTags)
BtoAPhotoVisualFit = overlap(B.styleTags, A.photoVisualTags)

mutualPhotoVisualFit =
  0.5 * AtoBPhotoVisualFit + 0.5 * BtoAPhotoVisualFit - visualImbalancePenalty
```

**输出**：`PhotoVisualCandidatePool`（满足双向视觉基础吸引力的候选集合）

**边界**：

- 不判断 gender
- 不做人脸识别
- 不做颜值评分
- 不生成 AI 头像
- 不做 AI 美化
- 只用封闭词表 `photoVisualTags`（Cloud Vision，见 P7.5-r7）

**硬门控**（任一不通过 → 不进池）：性别 DB gate、年龄/城市/意向/dealbreaker、审核与用户状态、blocked/hidden/rejected、已匹配/已忽略等（见 Stage 2 前置 guardrails）。

---

## 4. Stage 2：20D Bidirectional Compatibility Ranking

**输入**：

- `PhotoVisualCandidatePool`
- A 的 20 维画像 / 偏好
- B 的 20 维画像 / 偏好
- **现有 20D scoring 结果**（P7.6 **不重写** 20 维算法）

**计算**：

```text
AtoB20DFit   — A 的择偶偏好 / 需求 与 B 的 20 维画像匹配度
BtoA20DFit   — B 的择偶偏好 / 需求 与 A 的 20 维画像匹配度
mutual20DFit — 双向综合
```

**推荐**：

```text
mutual20DFit = harmonicMean(AtoB20DFit, BtoA20DFit)
```

或：

```text
mutual20DFit = 0.5 * AtoB20DFit + 0.5 * BtoA20DFit - imbalancePenalty
```

（双向匹配中，**短板**比平均分更重要。）

**输出**：`Bidirectional20DShortlist` → **TopN / Top2**

**说明**：20D 是**核心排序层**。照片只决定**谁能进池**，**不替代** 20D 排序。

**Guardrails**（与 Stage 1 一致，前置过滤）：

- 性别 DB gate；**不用** AI 判断 gender
- 不做人脸识别 / 颜值评分 / 年龄种族判断

---

## 5. Stage 3：RRM Top2 Final Selector

**输入**：

- Stage 2 产生的 **Top2**（short list）
- A / B 关系节奏信号
- RRM context / RRM shadow

**计算**：

```text
AtoBRrmFit   — 从 A 的节奏、边界、推进偏好评估 B 是否让 A 感到顺、可持续
BtoARrmFit   — 从 B 的节奏、边界、推进偏好评估 A 是否让 B 感到顺、可持续
mutualRrmFit — 双向关系推进稳定性（可选：min × stabilityFactor 等保守式）
rrmRiskFlags — 风险标记
```

**决策**：在 Top2 中选择一个 **`finalRrmSelectedCandidate`**。

**RRM 关注**：

- 推进快慢是否匹配
- 主动 / 被动是否互补
- 互动频率是否匹配
- 边界感是否冲突
- 冷场 / 误解 / 越界风险
- 修复能力

**说明**：RRM **不参与** PhotoVisual 大池排序，**不参与** 20D 全量排序；**只做** Top2 最终 selector。

**后续闭环**（P7.6 初期 shadow，不直接改主画像）：

- **AI Assistant** / **Timeline** / **Feedback** → RRM evidence → **pending suggestion** → 用户确认后更新画像（不自动静默改画像）

## 6. Shadow 输出结构

按 **stage 分块**记录 shadow；**不做**并列加权 aggregator。

```typescript
PhotoFirstMutualMatchingShadowV1 = {
  schemaVersion: "p7.6-photo-first-mutual-matching-shadow-v1",
  sourceVersion: "p7.6-photo-20d-rrm-top2-shadow-v1",

  viewerUserId: string,
  poolId: string,

  stage1PhotoVisualPool: {
    candidatesCount: number,
    selectedCandidateIds: string[],
    appliedToPool: false,
  },

  stage2TwentyD: {
    rankedCandidates: Array<{
      candidateUserId: string,
      AtoB20DFit: number,
      BtoA20DFit: number,
      mutual20DFit: number,
    }>,
    top2CandidateIds: string[],
    appliedToFinalScore: false,
  },

  stage3RrmTop2: {
    top2CandidateIds: string[],
    selectedCandidateId: string,
    AtoBRrmFit?: number,
    BtoARrmFit?: number,
    mutualRrmFit?: number,
    rrmRiskFlags: string[],
    appliedToMatchResult: false,
    appliedToWorkerRanking: false,
  },

  finalShadow: {
    selectedCandidateId: string,
    wouldChangeLegacyResult: boolean,
    reason: string,
    applied: false,
  },
}
```

**说明**：无 `mutualMatchScore = w1·20D + w2·Photo + w3·RRM` 类字段；最终人选由 **Stage 3 RRM 在 Top2 中选择** 决定。
