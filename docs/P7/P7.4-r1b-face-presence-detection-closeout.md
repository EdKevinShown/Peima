# P7.4-r1b — 人脸存在性检测 + r1b-f1 冷启动修复（Closeout）

## 1. 本轮目标

- 在 **P7.4-r1a** 的 `UserImage` 检测状态框架上增加**人脸存在性检测**。
- 只判断照片里是否**至少存在一张**可识别人脸。
- **不做人脸比对**、**不做身份认证**、**不做 AI 美化**、**不做 AI 头像**、**不做颜值评分**。

## 2. 实现概要

### r1a 质量检测优先

- `UNREADABLE_IMAGE` / `TOO_DARK` / `TOO_BLUR` → `detectionStatus = failed`，**不跑人脸**。
- 画质通过后，才进入 r1b 人脸阶段（若开启）。

### r1b 人脸检测

| 结果 | `detectionStatus` | `detectionReasonCodes` | 其它 |
|------|-------------------|------------------------|------|
| `faceCount === 0` | `failed` | `FACE_NOT_FOUND` | — |
| `faceCount >= 1` | `passed` | `[]` | — |
| `faceCount > 1` | `passed` | `[]` | `detectionScoreJson.warnings: ["MULTIPLE_FACES"]`（不进 reasonCodes） |
| 模型 load / infer 异常 | `skipped` | `[]` | 与 r1a 一致，onboarding 可继续 |

### 开关

- `FACE_DETECTION_ENABLED=0`：关闭人脸检测，**只跑 r1a**；`detectionRulesVersion` 为 `p7.4-r1a-v1`。

## 3. r1b-f1 冷启动修复

### 原问题

- `blaze-face-detector.adapter.ts` 中 **3s timeout** 包住 **`loadModel()` + `estimateFaces()`** 整段。
- BlazeFace 在 Node 22 下冷启动 **load 约 3.3s**，首次上传易触发 `face detection timeout` → `detectionStatus = skipped`。
- **不影响服务稳定性**，但导致 **r1b 的 `FACE_NOT_FOUND` 在 API 重启后第一次请求不生效**。

### 修复后（P7.4-r1b-f1）

- **`getModel()`** 不受 infer timeout 限制。
- **`estimateFaces`** 单独使用 **`FACE_DETECTION_INFER_TIMEOUT_MS`**（默认 **8000ms**）。
- **model 缓存**：load 成功后复用同一实例。
- **`loadPromise` 并发共享**：多请求同时冷启动只 load 一次；load 失败清空 promise 便于重试。
- **`OnModuleInit` fire-and-forget 预热**：`FACE_DETECTION_ENABLED !== "0"` 时后台 `warmup()`；失败只 `warn`，**不阻塞 Nest 启动**。

### Jest 日志说明

- 测试日志中的 `"model load failed"` 来自用例 **`skipped when face detector throws`** 的**故意 mock**，不是 BlazeFace 真失败。

## 6. Env 行为

| 变量 | 行为 |
|------|------|
| `FACE_DETECTION_ENABLED=0` | 完全跳过人脸检测，仅 r1a 画质 |
| `FACE_DETECTION_INFER_TIMEOUT_MS` | 仅限制 `estimateFaces`；默认 **8000**；非法值回退默认 |
| （未设置时） | 人脸检测**开启**（除非显式 `=0`） |

- **模型 load 不受** infer timeout 限制。

## 7. `detectionScoreJson` 结构

写入 `UserImage.detectionScoreJson`（无新 DB 字段）：

```json
{
  "quality": {
    "meanLuma": 120,
    "laplacianVariance": 80,
    "width": 800,
    "height": 600
  },
  "face": {
    "faceCount": 1,
    "faces": [{ "score": 0.95, "box": { "x": 10, "y": 10, "width": 80, "height": 80 } }]
  },
  "warnings": ["MULTIPLE_FACES"],
  "pipeline": ["quality", "face"],
  "faceDetectionEnabled": true
}
```

- **`quality`**：r1a 指标摘要。
- **`face`**：人脸数量与框（仅检测，无比对）。
- **`warnings`**：非阻断提示（如 `MULTIPLE_FACES`）。
- **`pipeline`**：已执行阶段，如 `["quality"]` 或 `["quality","face"]`。
- **`faceDetectionEnabled`**：`false` 时表示本轮未跑人脸。

`detectionRulesVersion`：`p7.4-r1a-v1`（仅画质）或 `p7.4-r1b-v1`（含人脸）。

## 8. 前端行为

| 后端结果 | 行为 |
|----------|------|
| `failed` + `FACE_NOT_FOUND` | **阻断**，留在 `/onboarding/photo-upload`，展示中文提示 |
| `failed` + r1a 码 | **阻断**，留在上传页 |
| `passed` + `warnings` 含 `MULTIPLE_FACES` | **不阻断**；进入 `/onboarding/photo-preference`，偏好页展示 warning |
| `passed` | 进入 `/onboarding/photo-preference` |
| `skipped` | **兼容继续**（与 r1a skipped 一致；`hasPassingPhoto` 含 `skipped`） |

Onboarding `nextStep` / `hasPassingPhoto`：`passed` 与 `skipped` 视为可进入审美偏好；`failed` 不可。

## 12. 当前限制

- **多人脸**只是 **warning**，不 hard fail。
- **不判断**是不是本人。
- **不判断**是否正脸。
- **不判断**遮挡。
- **不判断**活体。
- **首次模型加载**仍可能较慢（约 3s+），但 **不再因 load 被 infer 超时误杀为 skipped**。
- 部署环境需确认 **tfjs / blazeface** 在 API runtime 可加载（无外网时需确认模型缓存策略；本轮未做离线打包模型）。
