# P7.5-r4-f — UserImage vision sidecar backfill (closeout)

## 1. 本轮目标

为已有 `UserImage` 补写 `detectionScoreJson.vision`（`OnboardingVisionProfileV1`），使 `visualRankingShadow` 在本地/staging 能使用 rules/stub 视觉标签，而不是全体 fallback。  
**不**实现 `APPLY_TO_POOL`、**不**改真实 3+2+1、worker、`finalScore`、`MatchResult`、旧 PreviewPool。

## 2. CLI 命令

**脚本（dev-only）**：`apps/api/src/dev-cli/p75-r4-f-backfill-onboarding-vision-runner.ts`  
**pnpm**（需 `DATABASE_URL` 或 dotenv）：

```text
pnpm --filter @peima/api run p75:r4-backfill-vision -- --limit=200 --dryRun=true
pnpm --filter @peima/api run p75:r4-backfill-vision -- --limit=200 --dryRun=false
```

**推荐（无 shell `DATABASE_URL`）**：

```text
cd apps/api
npx dotenv-cli -e ../../.env -- node dist/dev-cli/p75-r4-f-backfill-onboarding-vision-runner.js --limit=200 --dryRun=true
npx dotenv-cli -e ../../.env -- node dist/dev-cli/p75-r4-f-backfill-onboarding-vision-runner.js --limit=200 --dryRun=false
```

**参数**：

| 参数 | 默认 | 说明 |
|------|------|------|
| `--limit` | `100` | 最多处理条数（按 eligible 计） |
| `--userId` | — | 仅该用户的图片 |
| `--provider` | `rules` | `rules` \| `stub` |
| `--dryRun` | `true` | `true` 只统计不写库 |
| `--onlyMissingVision` | `true` | 跳过已有 `vision` |
| `--includeBlocked` | `false` | `false` 时跳过 blocked review |

## 3. 筛选规则

处理候选行（DB 预筛 + 内存分类）：

- `detectionScoreJson` **非 null**（Prisma `not: DbNull`）
- `onlyMissingVision=true` 时：`detectionScoreJson.vision` 不存在
- `includeBlocked=false` 时：`reviewStatus` **不在** `rejected` / `needs_reupload` / `appeal_rejected`
- 不读取 `reviewNote`；stdout **不输出** `imageUrl`、用户联系方式、原始 `detectionScoreJson`
- 非 object 的 `detectionScoreJson`：跳过，**不 throw**
- 排序优先：`detectionStatus` = `passed` → `skipped` → `failed`，同状态按 `createdAt` 降序

## 4. dry-run / write 行为

1. 读取 `detectionScoreJson`
2. `buildOnboardingVisionProfileForPersist`（`enabled=true`，CLI `provider` 覆盖，**`applyToPool` 强制 false**）
3. `mergeVisionIntoDetectionScoreJson` — 仅增/改 `vision`，保留 `quality` / `face` / `warnings` / `pipeline`
4. `dryRun=true`：`wouldUpdate++`，**无** `prisma.userImage.update`
5. `dryRun=false`：仅 `update` `detectionScoreJson`；**不改** `detectionStatus` / `reviewStatus`；单张失败不影响其余

## 5. 本地执行摘要（本轮）

### dry-run（`limit=200`）

| 指标 | 值 |

| eligible | 6 |
| wouldUpdate | 6 |

`sampleTags` 含 `生活感`、`高级感`、`简约干净` 等（rules 推断）。

### write（`dryRun=false`）

| 指标 | 值 |
|------|-----|
| updated | 6 |

**数据面说明**：全库仅 **6** 条 `UserImage` 含 `detectionScoreJson`；backfill 覆盖全部 6 条。其中约 **3** 条写入后 `visionStatus=ok`（可用于 shadow 抽取），其余为 `skipped` 或历史已有 vision 块（`onlyMissingVision` 下未覆盖）。

### 复跑 r4-e + audit（backfill 后）

| 步骤 | 结果 |
|------|------|
| `p75:r4-e-shadow-sample` ×20 | 成功；viewer shadow 行约 **40** |
| `p75:r4-shadow-audit` | `validShadowRows=40`，`shadowCoverageRate≈0.909` |

**Audit 视觉指标（仍偏低）**：

| 指标 | 值 |
|------|-----|
| avgCandidatesWithVision | **0** |
| avgCandidatesMissingVision | 6 |
| viewerVisionAvailableRate | **0** |
| avgChangedSlots | 0 |
| readyForApplyToPoolDesign | **false** |

**原因分析（非 backfill 写库失败）**：

- Shadow 从 **gated 候选人** 的 `UserImage` 读 vision；staging 大量候选人 **无** `detectionScoreJson` / `visionStatus=ok`，与已 backfill 的 6 个用户 **重叠不足**。
- `extractUsableVisionFromDetectionScoreJson` 要求 `visionStatus === "ok"` 且非空 `photoVisualTags`；`skipped` vision 不计入。
- 结论：需 **更多候选人照片跑过 detection + backfill**，或扩大有 `detectionScoreJson` 的测试用户集，再复跑 r4-e harness + audit。
