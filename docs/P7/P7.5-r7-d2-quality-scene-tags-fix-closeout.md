## 3. 根因判断

| 环节 | 结论 |
|------|------|
| **Prompt（主因）** | 旧 Zhipu prompt 对 quality / scene 要求不够强，模型常只返回 photoVisual 或返回空 quality / scene。 |
| **Parser（次要）** | quality / scene 缺键时兼容不足；修复后缺键视为 `[]`，photoVisual-only 不报错。 |
| **Normalizer** | 不是主因；合法 tag 会保留，未知 tag 会丢弃并记录 `VISION_CLOUD_UNKNOWN_TAG`。 |
| **Profile builder** | 行为符合设计：空数组会导致 qualityTags / sceneTags 在 DB 中表现为空。 |

**Live 观察（r7-d / d1 修复前）**：`visionStatus=ok` 且 `photoVisualTags` 有值、quality/scene 空 → 解析成功但模型未产出有效 quality/scene（多为省略或 `[]`），非 normalizer 误杀已知词表 tag。

---

## 4. 修复摘要

**Prompt**

- 明确要求 `labels` 下必须包含：
  - `photoVisual`: `[{ tag, score }]`
  - `quality`: `[{ tag, score }]`
  - `scene`: `[{ tag, score }]`
- **quality** 只能从 **quality-v1** 中选择：
  - 清晰
  - 略模糊
  - 光线偏暗
  - 光线明亮
  - 光线正常
  - 构图居中
  - 半身构图
  - 背景杂乱
  - 多人脸
- **scene** 只能从 **scene-v1** 中选择：
  - 室内日常
  - 户外自然
  - 都市街景
  - 旅行度假
  - 社交聚会
  - 运动活动
  - 工作通勤
  - 证件棚拍

**Parser**

- quality / scene 缺键兼容为 `[]`
- photoVisual 缺键仍走失败路径
- unknown tag 仍由 normalizer 丢弃并记录 `VISION_CLOUD_UNKNOWN_TAG`
