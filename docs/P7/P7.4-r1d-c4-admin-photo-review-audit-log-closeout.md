# P7.4-r1d-c4 — Admin Photo Review Audit Log Closeout

## 本轮目标

为 `approve` / `reject` / `needs-reupload` 审核写操作增加审计日志，记录 `UserImage` 审核字段变更，供运营追溯。

## AuditService / AuditLog 复用

**复用现有能力，无新表、无 migration：**

| 组件 | 路径 |
|------|------|
| `AuditLog` model | `packages/database/prisma/schema.prisma` |
| `AuditService.recordAction` | `apps/api/src/common/audit/audit.service.ts` |
| `AuditModule` | `apps/api/src/common/audit/audit.module.ts` |

与 `suggestion-center`、`rbac` 相同：`recordAction(userId, action, entityType, dto)` 写入 `audit_logs`。

## audit action 列表

| action | 触发 API |
|--------|----------|
| `PHOTO_REVIEW_APPROVE` | POST `.../approve` |
| `PHOTO_REVIEW_REJECT` | POST `.../reject` |
| `PHOTO_REVIEW_NEEDS_REUPLOAD` | POST `.../needs-reupload` |

- `entityType` = `USER_IMAGE`
- `entityId` = `imageId`
- `userId`（audit 表字段）= 当前 admin `actorUserId`

## oldValues / newValues / meta

**oldValues / newValues**（仅审核字段，ISO 日期字符串）：

- `reviewStatus`
- `reviewReasonCodes`
- `reviewedAt`
- `reviewedByUserId`
- `reviewNote`（与 suggestion-center 一致，写入完整 note；运营内网审计）

**newValues.meta**（嵌套在 `newValues` 内，因 `AuditLog` 无独立 meta 列）：

| 字段 | 说明 |
|------|------|
| `userId` | 照片所属用户 |
| `detectionStatus` | 机器检测状态（只读快照） |
| `detectionReasonCodes` | 机器 reason |
| `detectionRulesVersion` | 规则版本 |
| `hasWarnings` | 来自 `detectionScoreJson.warnings` 是否非空 |
| `requestReasonCodes` | POST body 中的 reasonCodes |
| `notePresent` | body 是否带非空 note |

**不写入：** `detectionScoreJson`、图片内容、base64、imageUrl。

## 事务一致性策略

**未使用 Prisma transaction 包裹 audit**（`AuditService` 内部独立 `auditLog.create`）。

流程：

1. `findUnique` 读取更新前快照（含 audit 所需字段）
2. `updateMany` 乐观锁更新
3. 成功 → `AuditService.recordAction`
4. `getItemDetail` 返回

原因：`AuditService` 已封装独立 create，且项目惯例为审计失败不阻断主流程。

## audit 失败策略

与 `AuditService.recordAction` 一致：

- create 异常 → **log error**，返回 `null`
- **不回滚** 已成功的 `UserImage` 更新
- **不影响** POST API 响应（仍返回 200 + 详情 DTO）

审核动作优先成功；审计为 best-effort。后续可增强：异步重试 / 告警。
