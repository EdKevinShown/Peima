# P7.5-r4-o1 — Preview pool gender labels & cross-tier dedupe (closeout)

## 1. 问题现象

- 男性浏览者在「符合你审美的人」首张仍出现**明显男性**肖像。
- 「符合你审美的人」与「和你风格相近的人」等 tier 之间出现**同一 candidate** 或**同一张图重复**的观感。
- 示例路径：`/onboarding/photo-preview?userId=...`，viewer 为 male，产品规则为仅展示 **User.gender** 为 female 的候选。

## 2. 根因

### 2.1 Demo mapping 与素材内容不一致（第一张「男性图」）

- `dev-assets/test-user-images/mapping.json` 曾将 **NAM01915.jpg**（内容为男性肖像）标注为 **female**（Demo Female 06）。  
  在 **User.gender** 与内容一致的前提下，男性浏览者仍会在女性候选池里抽到该用户，从而出现「规则为女、视觉为男」的矛盾。
- `test-user-images1.jpg`–`9.jpg` 在素材包内均为女性呈现，却有多行被标注为 **male**，属于**为凑 6M+6F 而编造性别**，与「标注须与图片一致」冲突。

### 2.2 Preview pool 跨 tier 重复候选

- `buildSixNonSelfPreviewSlots` 已用 `used` Set 串联各 tier；但若 `collectGatedCandidates` 结果中 **同一 `userId` 出现多行**（异常/重复扫描），`pickByStyleScore` 等会在**同一 tier 内**对同一 id 取多个名次，导致 **3+2+1 中 `candidateUserId` 不全局唯一**。
- 缺少在落库前对 **6 个 slot 的 `candidateUserId` 集合大小 === 6** 的硬断言。

### 2.3 同图重复观感（imageUrl）

- 不同 demo `userId` 可指向同一源文件，导入后 URL 不同，但**观感仍可能撞图**；本轮在 mapping 上减少无必要的错标，并在 closeout 标明 **dev 数据限制**：正式逻辑保证 **candidateUserId 不重复**，不保证 dev 下**视觉**完全不撞图。

## 3. 修复点

### 3.1 `mapping.json`

- 按人工核对（维护者目视），将 **test-user-images1–9** 对应的行统一为 **female**；**NAM01915.jpg** 单独对应 **male**。
- 诚实披露当前文件夹内**仅 1 张男性呈现素材**，因此 mapping 为 **11 female + 1 male**（仍 12 行、原 `userId` 保留），并增加 **`_devNote_r4o1`**：female 浏览者若仅依赖本文件夹无法凑满 6 名男性，需**补充男性测试图**或依赖**环境内其他数据**。

### 3.2 `onboarding-photo-preview-pool.service.ts`

- **`dedupeGatedCandidateRowsByUserId`**：`generate` 在 `gAll` 上按 `id` 保留首条，避免重复行进入选人生成。
- **`buildSixNonSelfPreviewSlots`**：`aesthetic_fit` / `style_similar` 各层 **id 集合去重检查**；slot 列表 **6 个 `candidateUserId` 必须互异**；`generate` 在 `create` 前再次校验 `new Set(...).size === 6`。
- **`toViewerBundle`**：对每个候选 **`userImage.findFirst`**（`createdAt` 升序）取首图，避免批量 `findMany` 再分组时的边界歧义。

### 3.3 测试

- 更新 **`onboarding-photo-preview-pool.service.spec.ts`**：`userImage` mock 改为 **`findFirst`**；增加 **Prisma 重复 `id` 行** 与 **`buildSixNonSelfPreviewSlots` 重复 id 抛错** 用例；首条用例增加 **6 人全局唯一 / 跨 tier 不重复** 断言。
- 更新 **`onboarding-preview-gender.spec.ts`**：**repo mapping** 仅 male/female，且 **female ≥ 6**。
- 更新 **`p75-r4-h-candidate-image-import.spec.ts`**：解析 **repo mapping** 的 gender 合法性。
- 更新 **`onboarding-photo-preview-pool-funnel.audit.spec.ts`**：**不再**要求 repo 必为 6M+6F；改为与 **`_devNote_r4o1`** 一致的计数断言。

## 4. Demo mapping 处理方式

- **人工维护** `gender`，与**图片内容一致**，不使用 AI/人脸识别。
- 当前 dev 包：**11F + 1M**，满足 **男性浏览者** 侧「至少 6 名异性候选」的开发和手测；**女性浏览者** 全链路 6 槽需另补 **5+** 男性素材或混用库内其他 male 用户。

## 5. 全局唯一 candidate 规则

- 六个 slot 的 **`candidateUserId` 必须互不相同**。
- **`aesthetic_fit`（3） + `style_similar`（2） + `reflow`（1）** 之间不允许重复同一 `candidateUserId`。
- **不允许**用 viewer 本人、**不允许**用错误/unknown 性别补位；候选不足 6 人仍抛既有 **`BadRequestException`（至少 6 位）**。

   - **female viewer** 若环境只有本 mapping 导入的库：可能仍 **<6 male**，符合 `_devNote_r4o1` 所述限制。
