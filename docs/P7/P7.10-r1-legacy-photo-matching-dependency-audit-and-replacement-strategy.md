## 2. Why this audit exists

用户已决定废弃**旧照片匹配**（以 `UserImage.styleTags` / legacy `PreviewPool` / onboarding v1 审美槽位 / `computeStyleScore` 等构成的照片优先决策链）。

但仓库中大量模块名称含 `match` / `result` / `display` / `legacy`，若不做拆分，容易在 deprecation 时**误删通用结果基础设施**（`MatchResult`、`GET /matching/result`、`resolveMatchResultDisplay` 等）。

P7.10-r1 目标：

1. 基于 repo **真实搜索** 列出旧照片匹配依赖；
2. 与通用 `MatchResult` 读展示基础设施划界；
3. 定义 **safe fallback** 替代「legacy photo matching fallback」产品语义；
4. 规划 **P7.6 canonical writer** 接管主链写入的路线；
5. 给出 **P7.10-r2～r7** 后续里程碑（仅计划）。

## 7. Safe fallback strategy

### 7.1 产品原则

- **旧照片匹配不再作为 fallback 路径。**
- Fallback 指：在 P7.6 read path / display overlay **无法**采用 sidecar 时，回退到**已存在的安全结果状态**，而不是回退到「再算一遍照片分」。

### 7.2 推荐读取优先级（GET / FinalMatch 语义层）

| Order | State | Meaning | Today in repo |
|-------|-------|---------|---------------|
| 1 | **P7.6 canonical `MatchResult`** | 正式主链 writer 写入的结果（未来） | **Not implemented** — worker v1 still canonical |
| 2 | **P7.6 approved sidecar display** | `p76_allowlist_sidecar_readonly` when eligible | `p76-read-path-display-resolver.ts` |
| 3 | **Last stable safe result** | `resolveMatchResultDisplay` baseline：`match_result_original` · `static_final` · `pairwise_final` · RRM readonly types | `matching-result-display.ts` |
| 4 | **`matching_pending`** | 已入队无结果：`batch_match_queue` `waiting` / `processing` | `getStatusForUser` + `MatchingWaitingPage.jsx` |
| 5 | **`no_result`** | 无队列无 `MatchResult` | `getLatestResultForUser` → **404** `No match result` · UI 需显式区分（**gap**：无统一 `no_result` DTO） |

### 7.3 与当前 P7.6 env 的关系

| Current | Maps to safe fallback |
|---------|----------------------|
| `PEIMA_P76_READ_PATH_FALLBACK_LEGACY=1` | Enable fallback to **#3 baseline display**（非 photo engine） |
| `fallbackReason=not_allowlisted` · `rolled_back` · `env_disabled` | Document as **safe_fallback_reason** |
| `displaySourceType=static_fallback` | **Finalize** fallback · rename docs to **stable_finalize_fallback** |

### 7.4 文案 / 监控迁移（P7.10-r2）

- 停用：「legacy photo matching fallback」「legacy display」
- 采用：`safe_fallback` · `safe_baseline_display` · `matching_pending` · `no_result`
- Grafana：`fallbackLegacyCount` → `safeFallbackCount`（spec 见 `artifacts/p76/r9c1/monitoring-query-pack.md`）

## 8. P7.6 canonical writer replacement route

### 8.1 现状（search-confirmed）

```text
[Legacy PreviewPool + styleTags] → batch-match.processor → MatchResult (candidateUserId, finalScore)
                                      ↑
                            computeFinalScoreV1 (preview 0.35 · style 0.15 · …)

[P7.6 funnel shadow] → dev-cli audits → JSON artifacts (appliedToMatchResult: false)
[p76_allowlist_apply_writer] → p76_allowlist_apply_meta only
[p76_read_path] → display overlay only (GET)
```

### 8.2 目标 canonical writer（设计边界 · r1 不实现）

**P7.6 canonical writer** 应成为**唯一**写入正式 `MatchResult` 的 production writer，负责：

| Responsibility | Detail |
|----------------|--------|
| Create / update **`MatchResult`** | `candidateUserId` · `finalScore`（或 successor score field） |
| Write **`matchInsights`** | 含 funnel stage snapshots · `resultSource` / `pipelineVersion` |
| Set **result provenance meta** | 替代隐式「来自 PreviewPool v1」 |
| **Display source defaults** | 与 `resolveMatchResultDisplay` 契约对齐；read path 读 provenance |
| **Idempotency / rollback** | 与 allowlist sidecar · kill switch 兼容 |

**Explicitly not canonical today:**

- `p76-allowlist-apply-writer.ts` — sidecar only（[r8b](./P7.6-r8b-allowlist-apply-writer-implementation-closeout.md)）
- Onboarding APPLY / `pickByStyleScore` — Category A

### 8.3 迁移阶段（逻辑顺序）

1. **Freeze** Category A 行为（不再扩大 APPLY / legacy pool features）
2. **Implement** canonical writer behind env flag · dual-write compare shadow
3. **Switch** read path to prefer canonical provenance + safe fallback (#7.2)
4. **Stop** worker calling `previewPool` + `computeStyleScore` path
5. **Remove** Category A code / tables（P7.10-r6+）
