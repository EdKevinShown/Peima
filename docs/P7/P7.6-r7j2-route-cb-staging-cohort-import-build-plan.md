## 6. 最小 cohort 设计

### 6.1 最低方案（unblock r7g audit）

| 项 | 设计 |
|----|------|
| viewers | **5** |
| total users | **8–12**（含交叉复用） |
| 每 viewer candidates | **6**（固定） |
| 交叉复用 | **允许**（同一 user 可作 A 的 candidate 与 B 的 viewer） |
| self | **禁止**（每池内不得含 viewer 自身） |
| 硬约束 | 每个 viewer **`candidatePoolCount ≥ 6`** |

**槽位粗算：** 5 viewers × 6 candidates = **30** 槽位；4 人全集最多贡献 **4×3=12** 非 self 槽位 → 须 **≥18** 槽位来自新增/导入 user（考虑 gender/preference gate 后宜预留 **≥22** 合格 candidate）。

### 6.2 推荐方案（PM 主证据强度）

| 项 | 设计 |
|----|------|
| viewers | **10** |
| total users | **15–25** |
| 每 viewer candidates | **6–10** |
| 多样性 | 覆盖不同 `photoVisualTags`、20D 分布、RRM rhythm profiles |
| MatchResult / M6 | 全员 batch match · 尽量齐 |

### 6.3 示例拓扑（最低 · 示意）

```text
Users: U1..U8 (U1..U4 = r7j1 四人 + U5..U8 新增)

Viewers: V1=U1, V2=U2, V3=U3, V4=U4, V5=U5
Each Vi pool: 6 distinct users from {U1..U8} \ {Vi}
  → 需保证 gate 互斥后仍 ≥6
```

**执行轮（r7j3）** 须产出 cohort 表（viewerId · candidateIds · 预期 gate 结果）再写 DB。
