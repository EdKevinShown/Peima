## 2. Why this design exists

Milestones **P7.10-r6 → r6c2a** established:

- Canonical writer **shadow builder** is safe (`appliedToMatchResult` always `false`).
- **Artifact-only** audits (r6a, r6b, P7.7-r2, r6c1) preserve no-write invariants.
- On the **allowlist-covered cohort** (r6c2a), **sidecarCoverageRate = 1.00** and builder + sidecar lookup behave correctly.
- On **unfiltered recent `MatchResult`** samples (r6c1), **sidecarCoverageRate = 0.10** — a **coverage / sampling** issue, not builder failure.

**Gap:** JSON artifacts under `artifacts/p76/` are sufficient for local smoke but weak for:

- Durable Ops/Admin review across runs
- Correlation by `auditRunId` / `sourceVersion`
- Supersede / retention without copying files
- Querying `eligible` / `guardrailReason` / `wouldChangeCandidate` at scale

[P7.10-r6c](./P7.10-r6c-canonical-writer-dual-write-rehearsal-design.md) **Option B** proposed a dedicated rehearsal store separate from `MatchResult` and from `p76_allowlist_apply_meta`. **This document specifies that table** for a **future** migration — **no migration or writer in r6d**.

## 4. Existing sidecar / schema observations

From `packages/database/prisma/schema.prisma` and `apps/api/src` (workspace search).

### 4.1 `MatchResult` (relevant fields)

| Field | Type | Notes |
|-------|------|-------|
| `id` | `String @id` | Baseline row key |
| `userId` | `String` | Viewer (maps to audit `viewerUserId`) |
| `candidateUserId` | `String` | Persisted baseline candidate |
| `batchId` | `String` | Batch scope |
| `finalScore` | `Float?` | Must **not** be updated by rehearsal |
| `matchInsights` | `Json?` | Must **not** be used for rehearsal v1 (Option C deferred) |
| `status` | `String` | Worker-owned |
| Relations | `rrmTop2DisplayMeta`, `rrmTop2DisplayHookJobs` | Separate meta/job pattern for display — **not** canonical writer |

**Rehearsal table:** optional `matchResultId` references this model; **no** required Prisma relation in v1 if migration wants minimal coupling (see §6.3).

### 4.2 `P76AllowlistApplyMeta` → `p76_allowlist_apply_meta`

| Field / pattern | Current meaning | Relevance to rehearsal sidecar |
|-----------------|-----------------|--------------------------------|
| `@@unique([viewerUserId, sourceVersion])` | One allowlist apply row per viewer per cohort | Rehearsal is **many rows per viewer** (per audit run / timestamp); **different** uniqueness |
| `selectedCandidateId` | Route C chosen candidate | Rehearsal **proposal** mirrors sidecar input, not replace this row |
| `sourceVersion` | e.g. `p7.6-r7j3-staging-cohort-v1` | Rehearsal should store **`readPathSourceVersion`** + payload `sourceVersion` separately |
| `appliedToMatchResult` | Default `false`; P0 forbid `true` | Rehearsal **`appliedToMatchResult` must default false** with DB check / app invariant |
| `rolledBack` / `rolledBackAt` / `rollbackReason` / `rollbackToken` | Ops rollback of **allowlist sidecar** | Rehearsal uses **`supersededAt`** / optional `deletedAt` — **do not** mutate allowlist row on rehearsal supersede |
| `applied` / `dryRun` | Sidecar write semantics | Rehearsal is **never** `applied` to product |
| `stage1SelectedCandidateIds` / `stage2Top2CandidateIds` / JSON blobs | Route C evidence | Rehearsal `shadowPayload` holds **canonical shadow v1** only |
| Indexes | `viewerUserId`, `sourceVersion`, `rolledBack`, … | Rehearsal indexes align to Admin list filters (§9) |

### 4.3 Other meta patterns in schema

| Model | Pattern | Lesson for rehearsal |
|-------|---------|----------------------|
| `MatchResultRrmTop2DisplayMeta` | `matchResultId @unique`, `meta Json`, `sourceVersion` | One frozen meta per result — **rehearsal is intentionally multi-row** |
| `MatchResultRrmTop2DisplayHookJob` | `@@unique([matchResultId, top2Fingerprint, sourceVersion])` | Idempotent job key — rehearsal may use `@@unique([matchResultId, auditRunId, pipelineVersion])` for writer idempotency |
| `expiresAt` | On `UserRole` only (grep) | **`expiresAt` on rehearsal is new** — not found on other P7.6 meta tables |
| `supersededAt` / `deletedAt` | **not found in current schema** on P7.6 tables | **New** lifecycle fields for rehearsal design |

## 5. Design goals

1. Store canonical writer **rehearsal proposal** (shadow payload + denormalized compare fields).
2. **Never** affect `GET /matching/result` or `resolveMatchResultDisplay` unless a **future, separate** gated project explicitly adds a dev-only flag (out of scope; default **off**).
3. **Never** affect FinalMatchPage.
4. **Never** affect worker ranking or batch-match.
5. **Never** mutate `MatchResult` / `matchInsights` / `candidateUserId` / `finalScore`.
6. Keep **`appliedToMatchResult = false`** on every row (DB default + writer assert).
7. Support **Admin / Ops read-only** list/detail later ([P7.6-r8g](./P7.6-r8g-admin-review-ui-api-design.md) patterns).
8. Support **supersede / cleanup** (`supersededAt`, optional `deletedAt`, retention job).
9. Support **`sourceVersion`**, **`readPathSourceVersion`**, **`auditRunId`** traceability.
10. **Avoid** sensitive raw fields in `shadowPayload` (same forbidden keys as r6a).
11. Keep rows **bounded** (denormalized columns for filters; full payload in `shadowPayload`).
12. Make accidental production apply **difficult** (env gate, `environment` column, no Apply API in v1).

## 6. Proposed table

### 6.1 Names

| Layer | Name |
|-------|------|
| SQL table | `p76_canonical_writer_rehearsal_meta` |
| Prisma model | `P76CanonicalWriterRehearsalMeta` |

### 6.2 Proposed Prisma model (design-only — not applied)

```prisma
/// P7.10-r6d design-only: canonical writer rehearsal compare store.
/// NOT production canonical write. NOT read by GET/worker by default.
model P76CanonicalWriterRehearsalMeta {
  id String @id @default(cuid())

  viewerUserId String
  matchResultId String?

  baselineCandidateUserId String?
  proposedCandidateUserId String?

  baselineFinalScore Float?
  proposedScore Float?
  scoreVersion String?

  wouldChangeCandidate Boolean @default(false)
  eligible Boolean @default(false)
  guardrailReason String
  scoreDeltaBand String?

  sourceType String
  sourceVersion String
  pipelineVersion String
  readPathSourceVersion String?

  allowlistApplyMetaId String?

  auditRunId String?
  rehearsalMode String @default("sidecar_rehearsal")
  environment String @default("dev")

  appliedToMatchResult Boolean @default(false)

  shadowPayload Json
  summary Json?

  generatedAt DateTime @default(now())
  expiresAt DateTime?
  supersededAt DateTime?
  deletedAt DateTime?

  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt

  @@index([viewerUserId])
  @@index([matchResultId])
  @@index([sourceVersion])
  @@index([readPathSourceVersion])
  @@index([auditRunId])
  @@index([eligible])
  @@index([guardrailReason])
  @@index([appliedToMatchResult])
  @@index([supersededAt])
  @@index([generatedAt])
  @@index([environment, generatedAt])
  @@unique([matchResultId, auditRunId, pipelineVersion])
  @@map("p76_canonical_writer_rehearsal_meta")
}
```

**Design notes vs r6c draft:**

| Field | Rationale |
|-------|-----------|
| `readPathSourceVersion` | Cohort key used for `p76_allowlist_apply_meta` lookup (`readP76ReadPathEnv`) — explains `missing_sidecar` vs `ok` |
| `allowlistApplyMetaId` | Optional link to existing sidecar row `id` (no FK required in v1) |
| `scoreDeltaBand` | Denormalized from `shadow.comparison.scoreDeltaBand` for Admin filters |
| `environment` | `dev` \| `staging` only in v1 writer; **block** `production` inserts |
| `summary` | Small JSON: `{ reasonCounts?, notes?, runnerSourceVersion? }` without duplicating full payload |
| `deletedAt` | Soft delete for cleanup; **not found** on existing P7.6 meta — new pattern |
| `@@unique([matchResultId, auditRunId, pipelineVersion])` | Idempotent rehearsal writer per run (nullable `auditRunId` handled below) |

**Nullable `auditRunId`:** If `auditRunId` is null, omit unique constraint match or use synthetic `auditRunId` at writer (e.g. UUID per CLI invocation). **Recommendation:** writer **always** sets `auditRunId` (required in implementation).

### 6.3 Relations (optional / deferred)

| Relation | Recommendation |
|----------|----------------|
| `viewer User` | Optional `@relation` on `viewerUserId` — consistent with `P76AllowlistApplyMeta` |
| `matchResult MatchResult` | **Defer FK** in migration v1 if team wants zero coupling; store `matchResultId` as opaque string + app validation |
| `allowlistApplyMeta` | **No FK** — store `allowlistApplyMetaId` only |

**Do not** add reverse relation on `MatchResult` until product needs Admin navigation (keeps Prisma graph simple).

### 6.4 `shadowPayload` JSON contract

Must validate as `P76CanonicalWriterShadowPayloadV1` (`apps/api/src/modules/matching/p76-canonical-writer-shadow.types.ts`):

| Rule | Enforcement |
|------|-------------|
| `mode` | `"shadow"` only |
| `appliedToMatchResult` | `false` only |
| Forbidden keys | Reject serialize if contains `rawPrompt`, `transcript`, `imageFeatures`, `rawImage`, `fullPrompt` (reuse r6a audit-json guard) |
| Max size | Cap e.g. 32 KB per row (implementation choice) |

### 6.5 `summary` JSON (optional denormalized)

```json
{
  "runnerSourceVersion": "p7.10-r6a-canonical-writer-shadow-audit-cli-v1",
  "auditKind": "p7.10-r6c2a-targeted-allowlist-cohort",

  "notes": []
```

## 7. Uniqueness, indexes, and query patterns

### 7.1 Uniqueness

| Constraint | Purpose |
|------------|---------|
| `@@unique([matchResultId, auditRunId, pipelineVersion])` | Prevent duplicate rehearsal rows for same audit pass |
| **No** `@@unique([viewerUserId, sourceVersion])` | Unlike allowlist apply meta — many rehearsal snapshots per viewer |

When `matchResultId` is null (edge case), writer should still set `viewerUserId` + `auditRunId` + `generatedAt` and use partial unique index in SQL migration review (implementation detail).

### 7.2 Expected queries (Admin / Ops read-only)

| Query | Index used |
|-------|------------|
| Latest rehearsal for viewer | `viewerUserId`, `generatedAt DESC`, `supersededAt IS NULL` |
| Rows by audit run | `auditRunId` |
| Eligible proposals only | `eligible`, `guardrailReason` |
| Violation guard | `appliedToMatchResult` (must always be 0 rows with `true`) |
| Cohort drill-down | `readPathSourceVersion` |

### 7.3 Retention

| Mechanism | Behavior |
|-----------|----------|
| `supersededAt` | New run for same `(viewerUserId, matchResultId)` may supersede prior row |
| `expiresAt` | Optional TTL (e.g. 90 days dev) |
| `deletedAt` | Soft delete; excluded from default Admin list |
| Hard delete | Dev-only script `DELETE … WHERE auditRunId = ?` — never touch `match_results` |

## 8. Separation from `p76_allowlist_apply_meta`

| Dimension | `p76_allowlist_apply_meta` | `p76_canonical_writer_rehearsal_meta` |
|-----------|---------------------------|--------------------------------------|
| Purpose | Route C allowlist **apply** evidence | Canonical writer **compare / rehearsal** snapshot |
| Cardinality | 1 row / viewer / `sourceVersion` | Many rows / viewer / audit run |
| Product “applied” | `applied` flag (sidecar written) | **Never** product-applied; `appliedToMatchResult` always false |
| GET read | Read path may use **allowlist** sidecar | **Must not** be read by GET |
| Writer | `p76-r8b-allowlist-apply-writer` | Future `p76-rehearsal-writer` (not r6d) |
| Rollback | `rolledBack` on allowlist row | `supersededAt` on rehearsal row only |

Rehearsal builder **reads** allowlist meta (read-only); **writes** rehearsal table only.
