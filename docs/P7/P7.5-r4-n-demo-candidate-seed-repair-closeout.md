# P7.5-r4-n — Demo candidate seed repair (onboarding photo preview pool)

## 本轮目标

本地 dev/staging 下，通过 **`dev-assets/test-user-images/mapping.json` + r4-h import** 补齐 **至少 6 男 + 6 女** 的 demo candidate，使 **onboarding photo preview pool** 在 **不放宽性别门、不补位** 的前提下能稳定生成 **6 人池**。

## 当前 funnel 根因（修复前）

对已确认账号（例：`viewer_gender_normalized = male`）：

- `after_preference_hard_gate` 已为 10 → 账号偏好不是主瓶颈。
- demo `mapping.json` 仅 **3 男 + 3 女**，且 `at_least_six_each_binary_gender = false`，与 **opposite-binary** 门组合后，**异性候选不足 6**。
- 部分 demo 行若缺 **`UserProfile`（relationProfile）** 或与 import 去重顺序问题，会在复跑时更难补齐（见 import 修复）。

## mapping 修复

| 维度 | 修复前 | 修复后 |
|------|--------|--------|
| `mapping.json` male / female 条目 | 各 3 | **各 ≥ 6**（共 12 条） |
| 物理图片文件数 | 文件夹内约 10 张（含 `NAM01915.jpg`） | **仍 < 12**；多行 **复用同一 JPG** 绑定不同 `userId` |
| `summarizeDemoMappingGender` | `at_least_six_each_binary_gender: false` | **`true`** |

**Dev-only 声明（r4-n）**：`_devNote_r4n` 写入 `mapping.json`。多用户复用同一张图 **仅用于本地/测试种子数据**，不代表生产多账户可共享同图策略。

## relationProfile 补齐策略

- **`User` ↔ `UserProfile`（Prisma）** 即 collector 的 `relationProfile: { isNot: null }`。
- Import 在 **`mergeDemoCandidateUserFields`** 中 **`UserProfile.upsert`**（幂等），对每个 **demo 种子** 强制存在一行 profile。
- **仅当** `User.phone` 以 **`demo-r4h`** 开头时才更新 `User.gender` / `UserProfile`，避免误伤真实用户手机号账户。

## Import 复跑行为（r4-n）

1. **先** 按 mapping 合并 `gender`、`nickname`（有限）并 **`userProfile.upsert`**。
2. **再** 按 `slug` 的 **dedup marker** 判断是否已存在对应 `UserImage`；若已存在 → **`skippedExisting`**，**不重复 insert**。
3. 映射行指向 **非 demo 手机** 的用户 id → **整条失败**（不计入 `createdUserImages`），不写入图片。

## Funnel CLI 增强（r4-m CLI 输出）

`foldPreviewPoolFunnelFromScannedUsers` 报告中增加（**无 PII、无 detectionScoreJson / reviewNote**）：

- `relation_profile_present_by_gender`
- `base_where_eligible_by_gender`
- `after_preference_hard_gate_by_gender`
- `after_opposite_gender_gate_final_by_gender`

`p75:r4-m-preview-pool-funnel` 仍只 `JSON.stringify` 报告；上述字段随 `funnel` 对象输出。

### Male viewer（示例步骤）

1. `DATABASE_URL`、`ALLOW_PREVIEW_POOL_FUNNEL_AUDIT=1`（若生产环境）照常。
2. 跑 import（示例）：  
   `pnpm --filter @peima/api run p75:r4-h-import-candidate-images -- --dryRun=false --folder=dev-assets/test-user-images --createMissingUsers=true ...`
3. 跑 funnel：  
   `pnpm --filter @peima/api run p75:r4-m-preview-pool-funnel -- --viewerUserId=<maleViewerId>`

**期望（数据已种子化后）**：

- `viewer_binary_for_gate`: **male**
- `after_preference_hard_gate_by_gender.female` **≥ 6**
- `after_opposite_gender_gate_final` **≥ 6**
- `generate` 成功且 **6 条 item 的 candidate 全为 female**（与既有单测「男 viewer 只用女候选」一致）
- `item.imageUrl` **不来自 viewer**（既有 DTO / service 约束）

### Female viewer

将测试 viewer 设为 **strict female** 后复测：

- `after_preference_hard_gate_by_gender.male` **≥ 6**
- `after_opposite_gender_gate_final` **≥ 6**
- 生成 **6 条全 male candidate**

> 本文档不绑定你库内具体 `cmp70…` 跑数；以本地 DB 在 **import 完成后** 的 funnel / generate 为准。

## 预览池是否能生成 6 人

在 **import 成功、异性候选 ≥6、viewer 自身性别 binary、已完成审美/照片门槛** 的前提下，`OnboardingPhotoPreviewPoolService.generate` 应返回 **6** 项；候选不足时 **仍抛中文 `BadRequestException`**，**不补 unknown / 不补同性别**（既有逻辑未改）。
