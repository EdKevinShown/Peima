# P7.5-r4-n1 — Demo candidate import image dedup + profile fix (closeout)

## 1. 根因

1. **`buildImportPlan` 按计划项合并 basename**：历史上用 basename 做主键或多行折叠，会导致 `eligibleImages`、`failed`、用户/图片计数与 mapping 不一致；同一物理文件只允许一条计划行。
2. **UserImage 去重只看「全局 `-r4h-import-${slug}`」**：第二个 demo user 复用同一源文件时命中「已存在」，跳过 `UserImage.create`，出现 `createdUsers > 0` 但 `createdUserImages === 0`；`maleCandidates`/`femaleCandidates` 若仅从「新建图片」统计，也会在复跑时为 0，误导排查。

## 2. 修改文件

- `apps/api/src/modules/dev/p75-r4-h-candidate-image-import.plan.ts`  
  - 恢复可用 `slugForImportFilename`、`r4hPerUserImageDedupMarker`、`r4hDedupMarkerInStoredName`；`buildImportPlan` 对 mapping **一行一项**（可重复 basename），`sourceFileMissing`；`R4_H_SCHEMA_VERSION` → `p7.5-r4-n1-candidate-image-import-v2`。
- `apps/api/src/modules/dev/candidate-image-dev-import.service.ts`  
  - 按 **`userId` + slug**（新 marker + legacy marker）查找重复；文件名/URL 嵌入 **按 user 分段** marker；补齐 gender + `UserProfile`；摘要新增 `failureReasons`、`skippedExistingUserImportImage`、`createdUserImagesMale/Female`、`ensuredProfiles` 等。
- `apps/api/test/p75-r4-h-candidate-image-import.spec.ts`  
  - 计划顺序与同文件两用户、两遍导入、`femaleCandidates` 在 skip 时不为 0、URL marker 断言等。

（未改 `dev-assets/test-user-images/mapping.json`：本轮以逻辑与测试为主；你已具备 12 条平衡的 mapping 时可按原流程导入验证。）

## 3. 新去重规则（仅 dev demo import）

- **计划**：mapping 每项独立成行；同一 `file` + 不同 `userId` 得到多行。
- **UserImage**：同一 **`userId` + 同一导入 slug**（`slugForImportFilename(basename)`）视为重复；查找条件为  
  `userId` 固定且 (`imageUrl` **contains** 新 marker **或** legacy `-r4h-import-${slug}`)，避免跨用户互删。
- **存储文件名**：`${userId}-${uuid}${r4hPerUserImageDedupMarker(userId, slug)}${ext}`，保证不同用户的 URL 分段不同。

## 4. Import summary（报告形态）

`schemaVersion`: **`p7.5-r4-n1-candidate-image-import-v2`**

新增/强调的字段：

| 字段 | 含义 |
|------|------|
| `failureReasons` | 聚合原因计数（不含 PII），如 `missing_file`、`invalid_gender`、`non_demo_user_blocked`、`copy_failed`、`detection_failed`、`db_error`、`unexpected_error`、`viewer_excluded` 等 |
| `skippedExistingUserImportImage` | 该 user + slug 已存在 r4h 导入图，跳过插入 |
| `skippedViewerExcluded` | 映射到 viewer 的行排除 |
| `createdUserImagesMale` / `createdUserImagesFemale` | **本 Run** 新建图片按 mapping 性别分桶 |
| `ensuredProfiles` | 本 Run 对每个合法 demo 行成功 `mergeDemoCandidateUserFields`（含 gender + `UserProfile` upsert）的次数 |
| `maleCandidates` / `femaleCandidates` | **本 Run** 已成功合并处理的合法 demo mapping 行数（含因用户级 dedup **未**再插图的行）；复跑不会因仅 skip 而变成 0/0 |

`failed` 仍为「硬性失败」（源文件缺失、非 demo、写盘/检测/DB 抛错等）；`invalid_gender` 等可走 `failureReasons` **同时**沿用原有 `skippedInvalidGender`/`invalidGenderCandidates`。
