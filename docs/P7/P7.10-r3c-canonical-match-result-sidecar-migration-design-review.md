    "id" TEXT NOT NULL,

    "viewerUserId" TEXT NOT NULL,
    "matchResultId" TEXT,
    "selectedCandidateId" TEXT NOT NULL,

    "sourceType" TEXT NOT NULL,
    "sourceVersion" TEXT NOT NULL,
    "schemaVersion" INTEGER NOT NULL,
    "mode" TEXT NOT NULL,

    "reasonSummary" TEXT,

    "stageSummary" JSONB NOT NULL,
    "safeFallbackMeta" JSONB NOT NULL,
    "guardrails" JSONB NOT NULL,
    "dryRunPayload" JSONB NOT NULL,

    "appliedToMatchResult" BOOLEAN NOT NULL DEFAULT false,
    "appliedToFinalScore" BOOLEAN NOT NULL DEFAULT false,
    "appliedToWorkerRanking" BOOLEAN NOT NULL DEFAULT false,

    "promotionStatus" TEXT NOT NULL DEFAULT 'not_promoted',
    "promotionTargetMatchResultId" TEXT,
    "rollbackToken" TEXT,
    "previousSnapshotHash" TEXT,

    "pmSignoffStatus" TEXT NOT NULL DEFAULT 'pending',
    "opsSignoffStatus" TEXT NOT NULL DEFAULT 'pending',

    "auditRunId" TEXT NOT NULL,
    "environment" TEXT NOT NULL DEFAULT 'dev',

## 6. CHECK constraints

| Constraint | SQL intent | r3e verify |
|------------|------------|------------|
| `appliedToWorkerRanking = false` | Hard block until worker milestone | INSERT `true` → **reject** |
| `mode` enum | `dry_run` \| `sidecar` \| `promoted` | invalid mode → **reject** |
| `promotionStatus` enum | four states | invalid status → **reject** |
| `appliedToMatchResult` ⇒ `promoted` | No main-chain flag without promotion | `true` + `not_promoted` → **reject** |
| `appliedToFinalScore` ⇒ `promoted` | Same for score flag | `true` + `not_promoted` → **reject** |
| `environment` | **dev/staging only** in v1 | `production` → **reject** |
| `rolledBack` ⇒ promotion state | Consistency | `rolledBack=true` + `not_promoted` → **reject** |

**Not in v1 CHECK (application-enforced):**

- `deletedAt IS NOT NULL` → block promotion ([r3b §5](./P7.10-r3b-canonical-match-result-sidecar-schema-and-writer-design.md))
- `guardrails.eligible` in JSON — writer must not insert ineligible rows when `ALLOW_DB_WRITE=1`

**Deferred CHECK (future promotion milestone):**

- `appliedToMatchResult = true` ⇒ `rollbackToken IS NOT NULL` — add when Admin Apply ships

## 7. Unique constraints

| Option | Definition | Pros | Cons |
|--------|------------|------|------|
| **A** | Partial unique `(viewerUserId, sourceVersion)` WHERE active sidecar | One active row per cohort | Prisma partial index awkward |
| **B** | `UNIQUE(auditRunId, viewerUserId, sourceVersion)` | Idempotent CLI smoke; aligns rehearsal | Requires `auditRunId` on every insert |
| **C** | No strict unique; supersede only | Flexible | Duplicate active rows risk |

### Recommendation

**Primary: Option B** — `@@unique([auditRunId, viewerUserId, sourceVersion])` (required `auditRunId` on writer path).

**Secondary: partial unique (Option A fragment)** — SQL partial index `active_sidecar_viewer_source_key` above — prevents two concurrent **`mode=sidecar`** active rows for same viewer+cohort when writer forgets to supersede.

**Do not** reuse rehearsal unique `(matchResultId, auditRunId, pipelineVersion)` — canonical sidecar may exist **before** `matchResultId` is known.

**Do not** use allowlist-style `@@unique([viewerUserId, sourceVersion])` alone — blocks audit re-runs; use supersede + auditRunId instead.
