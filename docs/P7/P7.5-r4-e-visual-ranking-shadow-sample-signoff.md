# P7.5-r4-e — Shadow sample accumulation & audit re-run (signoff)

## 1. 本轮目标

在本地 staging/dev 数据库中通过 **重复的 onboarding photo preview pool 生成** 积累 `OnboardingPhotoPreviewPoolShadow`（visual ranking shadow）行，复跑 `p75:r4-shadow-audit` CLI，验证 **shadow 持久化链路能产出可分析数据**。  
**不**进入 r5-b 实现、**不**启用 `APPLY_TO_POOL`、**不**改变真实 3+2+1 / worker / `finalScore` / `MatchResult` / 旧 PreviewPool。

## 2. 环境开关

本地 staging / dev 建议（`APPLY_TO_POOL` 必须为 `0`）：

| 变量 | 值 |
|------|-----|
| `PEIMA_ONBOARDING_VISION_ENABLED` | `1` |
| `PEIMA_ONBOARDING_VISION_PROVIDER` | `rules` 或 `stub` |
| `PEIMA_ONBOARDING_VISION_SHADOW_ENABLED` | `1` |

## 7. 隐私检查

- **Audit CLI**：本轮 JSON 输出中未见 `candidateUserId`、`viewerUserId`、`poolId`、`imageUrl`、`reviewNote`、`raw payloadJson`。
- **Harness**：stdout JSON 仅为计数与 masked viewer 占位符；stderr 进度行不打印 poolId（仅 iter 序号与 items 数量）。

## 8. 用户可见 3+2+1 不变确认（代码路径）

- `GET /onboarding/photo-preview-pool/me/latest` → `findLatestActiveForViewer` → 仅查询 `OnboardingPhotoPreviewPool` + items，调用 `toViewerBundle`。**不读取** shadow 表。
- Shadow 写入在 `generate()` 内通过 `visualRankingShadow.computeShadow(...)` 异步侧车；返回给客户端的 bundle 来自 **刚创建的正式 pool**，其 `candidateUserId` / `rankInPool` / `tier` / `displayMode` 由既有 3+2+1 逻辑决定，不因 shadow 行变更。

## 9. 是否建议进入 r5-b

**不建议在本轮后进入 r5-b 实现。**

依据：`validShadowRows = 20 < 50`，且 vision / `avgChangedSlots` 等门槛未满足。应 **继续积累 shadow** 与完善 vision 侧数据；可 **保留** r5-a 设计文档，待样本与指标达标后再议 r5-b（dry-run / eligibility reader only，仍不直接 APPLY）。
