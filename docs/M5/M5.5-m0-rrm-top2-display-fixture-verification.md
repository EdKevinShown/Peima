# M5.5-M0 — Local RRM Top2 Display Fixture Verification

## 1. 一句话结论

提供 **dev-only CLI** `apps/api/src/dev-cli/m55-m0-rrm-top2-display-fixture.ts`：在 **非 production** 且具备 `DATABASE_URL` 时，对指定 `MatchResult` **upsert 一条** `MatchResultRrmTop2DisplayMeta`（**不**改 `MatchResult` 主行）。`meta` JSON **严格**对齐 `parseMatchResultRrmTop2DisplayMetaV1Loose` 与 `validateRrmTop2DisplayEligibility` 所需字段；**不**放宽 parser / eligibility。若 `matchInsights` 中尚无合法 `rrmSimReadonlySummary`，CLI 会打印 `summaryTemplate` 供你在**自己的 DB 会话**中合并——本工具**不**自动写 `matchInsights`（与 M5.4 / 安全边界一致）。

## 2. 前置条件

- 已 `pnpm exec nest build`（`apps/api`）。
- `.env` 中 `DATABASE_URL` 可用。
- `NODE_ENV` **不为** `production`。
- 目标 `MatchResult`：`--viewerUserId` = `MatchResult.userId`；`MatchResult.candidateUserId` = Static Top2 baseline **`A`**；`--otherCandidateUserId` = Top2 另一人 **`B`**；`--selectedCandidateUserId` **必须为 `B`**（与 resolver 中 `[baseline, newDisplay]` 无重复一致）。
- 若希望 **`GET /matching/result`** 返回 `displaySourceType = rrm_top2_bounded_selector`：除侧车外，还需 **`matchInsights.rrmSimReadonlySummary`** 通过 `tryParseRrmSimReadonlySummaryPayloadV1FromMatchInsights`，且 `winnerUserId` 与 meta 的 `newDisplayCandidateUserId` 一致、`confidenceBucket` 非 `low`/`unknown`、`fallbackUsed === false`、guardrails 为 pass（与单测 `matching-result-display-candidate.spec.ts` 一致）。
- 验证 API 时设置 **`PEIMA_M5_RRM_TOP2_ENABLED=1`**（或 `true` / `yes`）。

## 3. 运行方式

在 **`apps/api`** 目录：

```bash
node dist/dev-cli/m55-m0-rrm-top2-display-fixture.js \
  --matchResultId=<match_result_id> \
  --viewerUserId=<viewer_user_id> \
  --selectedCandidateUserId=<rrm_winner_user_id> \
  --otherCandidateUserId=<top2_other_user_id> \
  [--top2Fingerprint=local-dev-fixture]
```

- **默认 dry-run**：只打印解析 / eligibility 摘要及 `summaryTemplate`（若 `rrm_summary_missing`），**不写库**。
- 追加 **`--apply`**：仅 **`upsert` `match_result_rrm_top2_display_meta`**；仍**不**修改 `match_results`。
- `--apply` 成功后会再次加载 `MatchResult` 并调用 **`resolveMatchResultDisplay`**，打印 `displaySourceType` / `displayCandidateUserId`（用于本地对照 `GET`，**不**写入文档或 Git）。

可选在 `package.json` 使用脚本：`pnpm run m55-m0:rrm-top2-display-fixture`（见 `apps/api/package.json`）。

## 4. meta 契约（与代码一致）

与 `rrm-top2-display-meta.parser.ts` / `rrm-top2-display-meta.types.ts` 一致，**不是**自由发挥的大 JSON。必填字段包括：

- `schemaVersion: 1`
- `sourceType: "rrm_top2_bounded_selector"`
- `sourceVersion`、`baselineCandidateUserId`、`previousDisplayCandidateUserId`、`newDisplayCandidateUserId`、`decisionRule`、`top2Fingerprint`
- `appliedToFinalScore: false`、`appliedToWorkerRanking: false`
- `rollbackAvailable: boolean`

表列 `top2Fingerprint` 与 JSON 内 `top2Fingerprint` 须一致（eligibility）。

## 5. 与 M5.4 / M5.3 的关系

- **M5.4**：rematch 产生新 `MatchResult` 后，若需验证 RRM display，可用本 CLI 挂侧车；**不**替代生产 writer。
- **M5.3**：resolver 逻辑不变；本工具仅便于 **本地** 验证「有合法 meta + 有合法 summary 时」读路径。
