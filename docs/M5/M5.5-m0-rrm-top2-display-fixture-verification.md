# M5.5-M0 / M5.5-M0.1 — Local RRM Top2 Display Fixture Verification

## 1. 一句话结论

提供 **dev-only CLI** `apps/api/src/dev-cli/m55-m0-rrm-top2-display-fixture.ts`：在 **`NODE_ENV !== "production"`** 且具备 `DATABASE_URL` 时，对指定 `MatchResult` **默认 dry-run** 校验并打印 JSON；**仅**在传入 **`--apply`** 时写库。

- **M5.5-M0（默认）**：**upsert** `MatchResultRrmTop2DisplayMeta`；**不**改 `MatchResult.candidateUserId` / `finalScore` / `display*` / `matchInsights`（除非启用下面的 M0.1 标志）。
- **M5.5-M0.1（`--withRrmSummaryFixture`）**：在 **dry-run** 下仅**内存**合并 viewer-safe `rrmSimReadonlySummary` 并跑 parser / eligibility 预检；在 **`--apply`** 下**先**把该 fixture **浅合并**进 `MatchResult.matchInsights` 的 `rrmSimReadonlySummary` **唯一键**，**再** upsert 侧车，**再**调用 `resolveMatchResultDisplay`。这不是正式生产 writer；生产侧持久化仍规划在 **M5.5-M1 / M5.5-M2**（例如受控 writer / 仿真路径）。

`meta` JSON **严格**对齐 `parseMatchResultRrmTop2DisplayMetaV1Loose` 与 `validateRrmTop2DisplayEligibility`；**不**放宽 parser / eligibility。若未传 `--withRrmSummaryFixture` 且 `matchInsights` 中尚无合法 `rrmSimReadonlySummary`，CLI 会打印 `summaryTemplate` 供你在**自己的 DB 会话**中合并，或改用 **`--withRrmSummaryFixture`** 做本地一次性 fixture。

## 2. 前置条件

- 已 `pnpm exec nest build`（`apps/api`）。
- `.env` 中 `DATABASE_URL` 可用。
- `NODE_ENV` **不为** `production`。
- 目标 `MatchResult`：`--viewerUserId` = `MatchResult.userId`；`MatchResult.candidateUserId` = Static Top2 baseline **`A`**；RRM 胜出方为 **`B`**：`--selectedCandidateUserId` 与 `--otherCandidateUserId` **均填 `B`**（`B` ≠ `A`）；与 resolver 中 `newDisplayCandidateUserId = B`、`baselineCandidateUserId = A` 一致。
- 若希望 **`GET /matching/result`** 返回 `displaySourceType = rrm_top2_bounded_selector`：除侧车外，还需 **`matchInsights.rrmSimReadonlySummary`** 通过 `tryParseRrmSimReadonlySummaryPayloadV1FromMatchInsights`，且 `winnerUserId` 与 meta 的 `newDisplayCandidateUserId` 一致、`confidenceBucket` 非 `low`/`unknown`、`fallbackUsed === false`、guardrails 为 pass（与单测 `matching-result-display-candidate.spec.ts` 一致）。
- 验证 API 时设置 **`PEIMA_M5_RRM_TOP2_ENABLED=1`**（或 `true` / `yes`）。

## 3. 运行方式

在 **`apps/api`** 目录（需先 `pnpm exec nest build`）：

**Dry-run（默认，不写库）**

```bash
pnpm run m55-m0:rrm-top2-display-fixture -- \
  --matchResultId=<local_match_result_id> \
  --viewerUserId=<local_viewer_user_id> \
  --selectedCandidateUserId=<local_candidate_b> \
  --otherCandidateUserId=<local_candidate_b> \
  [--top2Fingerprint=local-dev-fixture] \
  [--withRrmSummaryFixture]
```

说明：`MatchResult.candidateUserId` 为 Static Top2 baseline **`A`**；`--otherCandidateUserId` 与 `--selectedCandidateUserId` 均为 RRM 胜出方 **`B`**（与 resolver 的 `[baseline, newDisplay]` 一致；**不得**把 `other` 设成与 baseline 相同）。

**Apply（显式写库）**

```bash
pnpm run m55-m0:rrm-top2-display-fixture -- \
  --matchResultId=<local_match_result_id> \
  --viewerUserId=<local_viewer_user_id> \
  --selectedCandidateUserId=<local_candidate_b> \
  --otherCandidateUserId=<local_candidate_b> \
  [--top2Fingerprint=local-dev-fixture] \
  [--withRrmSummaryFixture] \
  --apply
```

- **默认 dry-run**：打印 JSON；未传 `--withRrmSummaryFixture` 时行为与 M5.5-M0 一致（含 `summaryTemplate` 提示，若 `rrm_summary_missing`）。传 **`--withRrmSummaryFixture`** 时额外输出 `wouldWriteMatchInsightsSummary`、`parserValid`、`rrmSummaryParseValid`、`eligibilityEligible`、`noOpReasonCode`、`nextCommand` 等预检字段（**仍不写库**）。
- **`--apply`**：先（若带 `--withRrmSummaryFixture`）**仅**更新 `match_results.matchInsights` 中的 **`rrmSimReadonlySummary`**（浅合并，保留 `explanation` / `riskFlags` / `openingTopics` / `chatSimulationSummary` 等）；再 **`upsert` `match_result_rrm_top2_display_meta`**；再 **`resolveMatchResultDisplay`**。`candidateUserId` / `finalScore` **不得**被本工具修改。
- **`NODE_ENV=production`**：CLI **拒绝**运行。

脚本入口：`apps/api/package.json` 中的 `m55-m0:rrm-top2-display-fixture`。

## 4. meta 契约（与代码一致）

与 `rrm-top2-display-meta.parser.ts` / `rrm-top2-display-meta.types.ts` 一致，**不是**自由发挥的大 JSON。必填字段包括：

- `schemaVersion: 1`
- `sourceType: "rrm_top2_bounded_selector"`
- `sourceVersion`、`baselineCandidateUserId`、`previousDisplayCandidateUserId`、`newDisplayCandidateUserId`、`decisionRule`、`top2Fingerprint`
- `appliedToFinalScore: false`、`appliedToWorkerRanking: false`
- `rollbackAvailable: boolean`

表列 `top2Fingerprint` 与 JSON 内 `top2Fingerprint` 须一致（eligibility）。

## 5. 与 M5.4 / M5.3 的关系

- **M5.4**：rematch 产生新 `MatchResult` 后，若需验证 RRM display，可用本 CLI 挂侧车；**不**替代生产 writer。
- **M5.3**：resolver 逻辑不变；本工具仅便于 **本地** 验证「有合法 meta + 有合法 summary 时」读路径。
