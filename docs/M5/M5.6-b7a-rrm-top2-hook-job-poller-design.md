# M5.6-B7-A — Worker / Independent Poller Design（RRM Top2 Hook Job）

> **范围**：**设计文档 only**。规划如何将 **M5.6-B5-B** controlled apply runner 的能力演进为 **独立 poller** / **worker dry-run** / **worker apply** 模式。**本轮不写代码**、**不接** `apps/worker/src/main.ts`、**不**启动自动轮询、**不**改 Prisma schema / migration。不含真实业务 id、token、`DATABASE_URL`。

---

## 1. 一句话结论

**B7-A** 只完成 **worker / independent poller** 的架构设计。**不推荐**把 B5-B dev-cli 里的 **状态迁移 + writer 编排** 再复制一份到 worker；**推荐**先抽出 **`rrm-top2-hook-job-apply.service.ts`（shared apply service）**，由 **B5 CLI runner** 与未来 **poller** **共用同一处理路径**，再按阶段打开 **dry-run** / **staging apply** 能力。

---

## 3. 为什么不能直接复制 B5 runner

若将 B5-B `m56-b5-*.ts` 内逻辑 **原样复制** 到 worker / poller：

- **Apply 与 writer 结果分类** 易 **分叉**（CLI 修 bug、worker 忘跟）。  
- **`no-op` → `skipped` / `failed` / `processed`** 映射易 **分叉**。  
- **`sanitizeRrmTop2HookJobError` / `mark*`** 语义易 **漂移**。  
- **单测与回归** 成本 **翻倍**（两套几乎相同用例）。  
- **运维排障** 困难：同一 pending job 在 CLI 与 worker 上行为不一致。

**结论**：在 **B7-B** 及以后实现前，**先**抽出 **shared apply service**，poller **只编排**（调度、退避、指标、env），**不**重写状态机。

---

## 4. 推荐抽出的 shared apply service

**建议新增**（**B7-B 实现**；文件名可微调）：

`apps/api/src/modules/matching/rrm-top2-hook-job-apply.service.ts`

**建议职责**（命名示意）：

| 符号 | 职责 |
|------|------|
| `applySingleRrmTop2HookJob` | 单条：`markProcessing` → 预检 → `writeRrmTop2DisplayMetaForMatchResult` → `markProcessed` / `markSkipped` / `markFailed`。 |
| `processRrmTop2HookJobsApplyBatch` | 小批量：`findPending` + 循环调用 `applySingle…` + 聚合 viewer-safe 结果。 |
| `mapWriterResultToHookStatus` | 将 writer 输出映射为 `processed` / `skipped` / `failed` 决策（与 B5-A / B5-B 文档一致）。 |
| `mapWriterNoOpToSkippedReason` | 统一 **no-op** code 落库（含未知 no-op 的 **skipped** 策略）。 |
| `sanitizeApplyError` | 包装 / 复用 `sanitizeRrmTop2HookJobError`（或薄委托）。 |

**B5 CLI runner** 后续应 **调用** 该 service，**删除** runner 内重复编排（B7-B 范围）。

## 5. Poller 方案比较

### Option A — 接入 `apps/worker/src/main.ts` 自动注册 poller

| | |
|--|--|
| **优点** | 与现有 worker **同进程**部署；运维模型单一。 |
| **缺点** | 默认常驻易 **持续**写库；必须 **强 env gate** + 先 **dry-run** 模式；与 `ai-simulation` / `pairwise` 队列 worker **耦合**在同一入口。 |

### Option B — 独立 dev-cli / **手动触发** poller

| | |
|--|--|
| **优点** | **最安全**；适合 staging **逐步验证**；**不**自动影响生产。 |
| **缺点** | 需 **人工 / CI 定时任务** 触发。 |

### Option C — **独立** worker 包 / cron 风格 runner

| | |
|--|--|
| **优点** | 与 batch-match **解耦**；可 **独立扩缩容**。 |
| **缺点** | 实现与部署面 **更大**。 |

**推荐路线**：

| 阶段 | 内容 |
|------|------|
| **B7-B** | **Option B 思路** + **抽出 shared service**；**B5 CLI** 复用；**仍不接** `worker/main.ts`。 |
| **B8** | Independent poller **dry-run**（手动或受控调度）；**默认不写** meta / 默认不改 HookJob（或仅可选 `recordDryRunResult`，需单独设计）。 |
| **B9** | **Staging apply**；多重 env gate + 小批量 + run record；**仍不**默认全开生产。 |

## 6. Worker / Poller 模式设计

### 6.1 `dry-run` mode（建议 **B8**）

- 读取 pending hook jobs（小 `limit`）。  
- 调用 shared service / consumer：**writer 强制 `dryRun: true`**。  
- **不**写 `MatchResultRrmTop2DisplayMeta`；**不**写 summary apply。  
- **默认不**改 HookJob `status`；若需审计，**仅**在显式 **`recordDryRunResult`**（或等价 gate）下写 **viewer-safe** `auditMeta` / `metaWriteResult` 摘要（**须**单独评审，**不在** B7-A 定稿实现）。

### 6.2 `apply` mode（建议 **B9 staging**）

- **多重 env gate**，示例（实现阶段可调名，语义须保留）：  
  - `PEIMA_M5_RRM_TOP2_HOOK_POLLER_ENABLED=1`  
  - `PEIMA_M5_RRM_TOP2_HOOK_POLLER_MODE=apply`  
  - `PEIMA_M5_RRM_TOP2_META_WRITE_ENABLED=1`  
  - （按需）summary 相关 env  
- **小批量**：`pending` → `processing` → `processed` / `skipped` / `failed`（**与 B5-B 同一套** service 逻辑）。  
- **不接 GET**；**不**在 poller 内调用 resolver 写库。

## 7. 建议新增 env（实现阶段）

| 变量 | 建议默认 | 说明 |
|------|----------|------|
| `PEIMA_M5_RRM_TOP2_HOOK_POLLER_ENABLED` | `0` | 总开关。 |
| `PEIMA_M5_RRM_TOP2_HOOK_POLLER_MODE` | `dry_run` | `dry_run` \| `apply`。 |
| `PEIMA_M5_RRM_TOP2_HOOK_POLLER_INTERVAL_MS` | `30000` | 轮询间隔（仅 **enabled** 且非纯 CLI 时有效）。 |
| `PEIMA_M5_RRM_TOP2_HOOK_POLLER_LIMIT` | `5` | 每 tick 最大处理条数；**硬顶**建议仍 **≤ 10**（与 B5-B 对齐）。 |
| `PEIMA_M5_RRM_TOP2_HOOK_POLLER_APPLY_CONFIRM` | （空） | 与 B5 **`I_UNDERSTAND`** 同类 **显式确认**；**apply** 模式 **必填** 方可写状态。 |

**默认策略**：`enabled=false`、`mode=dry_run`；**不**自动开启生产写库。

---

## 8. 状态迁移复用

**poller 不实现** `mark*` / writer 细节。

poller **仅**调用 shared service，例如：

`processRrmTop2HookJobsApplyBatch({ prisma, limit, mode, clock, … })`

由 service **统一**负责：

- `findPendingRrmTop2HookJobs`  
- `markRrmTop2HookJobProcessing`  
- `writeRrmTop2DisplayMetaForMatchResult`（`dryRun` 由 mode 决定）  
- `markProcessed` / `markSkipped` / `markFailed`  
- **sanitize**、聚合 **viewer-safe** 指标

---

## 9. 安全边界

**永远不改**：

- `MatchResult.candidateUserId`  
- `finalScore`  
- worker ranking  
- `PairwisePoolFinalizeMeta`  
- user profile  
- questionnaire profile  
- chat messages  

**GET** **仍只读**。

**poller 禁止**：

- 直接经 **GET / resolver** 写库；  
- 重跑 **RRM evaluator** 或重算 **finalScore**；  
- **覆盖** frozen meta（须走 writer 既有语义）；  
- **大批量、无确认** 的 apply。
