## 5. 结果解读

因 **CLI 未成功执行**，无法基于真实样本解读分布。若未来 rerun 成功，建议按下列维度阅读 `summary`：

- **sampleCount**：参与聚合的有效 sidecar 条数（与 `itemsWithValidSidecar` 对齐）。
- **modeShadowCount**：在强制 `shadowEnabled=true` 的 audit 口径下，侧车 `mode === "shadow"` 的条数。
- **m5ProposedNonNullCount** / **wouldChangeCurrentDisplayTrueCount**：shadow 共识下“若启用展示会提议谁、是否会改变当前展示”的**纯模拟**计数；**不改变**线上用户所见。
- **decisionRuleCounts** / **shadowReasonCounts**：主要失败/阻塞原因（如 pairwise / rrmSim 不可用、guardrail、冲突等）。
- **pairwiseSourceAvailableCount** / **rrmSimSourceAvailableCount**：hydrated 源可用性粗览。
- **guardrailPassViewerSafeNoCautionSignalCount**：仅表示 **viewer-safe payload 未发现 caution / risk / finalize fallback 信号**（`viewer_safe_no_caution_signal`），**不是**完整产品级 guardrail 引擎“通过”。

**阻塞点与下一步**：在具备合法本地/预发 DB 与 `.env` 的机器上配置 `DATABASE_URL` 后重跑同一命令；将新的聚合 JSON 附录于 Round 2 文档或本文件修订记录，避免在本轮无数据时编造数字。

## 6. 是否满足进入 M5.3 的条件

**判断：目前不应进入 M5.3 enabled display 代码阶段。**

理由：

1. 本轮 **无有效 audit 样本输出**，无法用数据证明 shadow 共识与 guardrail 边界在生产形态下足够安全。

- M5.2 **shadow proposal** 不改变用户当前看到的匹配对象；**`m5AppliedToDisplay` 必须为 false**（当前实现如此）。

- 本 audit CLI 默认只看**最近 N 条** `MatchResult`，**不代表全量生产质量**。
- 未接入真实 **M6.1 feedback attribution** 前，不应商业化宣称「RRM 已提升满意度」等。
