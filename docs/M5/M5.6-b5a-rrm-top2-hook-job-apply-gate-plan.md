# M5.6-B5-A — Controlled Apply Gate / HookJob Status Transition Plan

> **范围**：**设计文档 only**。规划如何从 **M5.6-B4B** dry-run consumer 进入 **受控 apply gate** 与 **HookJob 状态迁移**。**不**在本轮实现 apply、**不**接 GET、**不**接 worker 自动轮询、**不**改 Prisma schema、**不**新增 migration。不含真实 `userId` / `candidateUserId` / `matchResultId` / `hookJobId`、不含 token / API key / `DATABASE_URL`。

---

## 1. 一句话结论

**B5-A** 只定义 **controlled apply gate** 与 **HookJob 状态迁移** 的方案与验收方向：在显式确认与小批量前提下，把 **B4B** 的 dry-run 决策 **安全**推进到可选的 **writer apply** 与 **状态落库**；**仍**不接 GET、**仍**不接 worker 自动轮询、**仍**不改 `MatchResult.candidateUserId` / `finalScore`。

---

## 2. 当前事实

| 项 | 说明 |
|----|------|
| **B3** | Controlled runner 可 **dry-run 预览** pending hook job 创建语义；`--apply` 可 **创建** `status = pending` 的 hook job 行。 |
| **B4B** | 可 **读取** pending hook job，并对每条调用 `processRrmTop2HookJobDryRun`；**仅 dry-run**，**不**更新 HookJob 状态、**不**写 meta / summary。 |
| **B4D（验证）** | 已验证 `totalJobsRead = 1` 场景下，writer dry-run 可识别 **`existing_meta_frozen`** 为 **安全 no-op**（不覆盖已 frozen 的 `MatchResultRrmTop2DisplayMeta`）。 |
| **缺口** | 当前 **没有** controlled apply gate（无显式确认即不得写状态 / 写 meta）。 |
| **缺口** | 当前 **没有** `pending → processing → skipped | processed | failed` 的 **受控**状态迁移实现（B4B 刻意不写）。 |

---

## 3. B5 的目标

B5（实现阶段，**不在 B5-A**）应达成：

| 能力 | 说明 |
|------|------|
| **受控读取** | 读取 pending hook job（小 `limit`，与 B4B 同思路）。 |
| **租约 / 占用** | 对单条或少量 job 进入 **`processing`**（避免并发双消费，需设计锁字段语义）。 |
| **Writer** | 在确认 gate 下调用 `writeRrmTop2DisplayMetaForMatchResult`（见 §9）。 |
| **状态回写** | 按 writer 与异常结果写 **`processed` / `skipped` / `failed`**。 |
| **边界** | **仍**不接 GET；**仍**不自动注册 worker loop；**仍**不改 `candidateUserId` / `finalScore`。 |

---

## 4. Apply Gate 原则

**只有**在调用方提供 **全部**显式参数时才允许进入 apply 路径，例如（命名可在 B5-B 实现时微调，语义须保留）：

- `--apply`
- `--maxJobs=1`（或小整数上界）
- `--confirmControlledApply=I_UNDERSTAND`

**默认**行为 **仍须为 dry-run**（与 B4B 一致：无上述参数则不写状态、不写 meta）。

若缺少任一确认参数：

- **拒绝** apply；
- **输出**清晰提示（viewer-safe / 无密钥）；
- **不写** HookJob 状态；
- **不写** `MatchResultRrmTop2DisplayMeta` / summary。

---

## 5. 状态迁移规则

定义状态边：

```
pending → processing
processing → processed
processing → skipped
processing → failed
```

| 转移 | 条件（草案） |
|------|----------------|
| **`pending` → `processing`** | apply gate 通过；对选中 job 原子/乐观更新为 `processing`；**`lockedAt = now`**；**`attempts += 1`**（与现有 `markRrmTop2HookJobProcessing` 语义对齐）。 |
| **`processing` → `processed`** | Writer **apply** 成功且 **已**按产品定义完成 meta（及按需 summary）写入；**`processedAt = now`**；**`noOpReasonCode = null`**；**`metaWriteResult`** 存 viewer-safe 摘要。 |
| **`processing` → `skipped`** | Writer 返回 **预期内 no-op**（见 §6）；**`processedAt = now`**；**`noOpReasonCode`** 为规范 code；**不**视为错误。 |
| **`processing` → `failed`** | 非预期异常、Prisma 错误、不可归类 payload、writer 抛错等；**`lastErrorCode` / `lastErrorMessage`（sanitize）**；**不**将业务 no-op 误标为 failed（见 §6、§14）。 |

**说明**：B5-B 实现时应复用或薄封装现有 `markRrmTop2HookJob*` helpers，避免重复造轮与语义漂移。

---

## 6. no-op → `skipped` 映射

以下 **writer / eligibility no-op**（含当前 writer 已暴露的 code 与 B5 期望归类的语义 bucket）应落 **`skipped`**（**不是** `failed`）：

- `writer_disabled`
- `existing_meta_frozen`
- `static_top2_missing`
- `rrm_summary_missing`
- `rrm_summary_invalid`
- `guardrails_missing`
- `guardrails_invalid`（实现层可将 UI 语义上的 caution / block / not_evaluated 归并到此 code 再映射 skipped，**或**在落库前规范化为下列显式 code）
- `guardrails_caution`（若 B5 引入显式规范化层）
- `guardrails_block`
- `guardrails_not_evaluated`
- `rrm_confidence_low`
- `rrm_fallback_used`
- `selected_not_in_top2`（或与现有 eligibility **winner / top2** 相关 code 对齐后映射）

**原则**：

- **no-op 不是错误**；用户侧展示 **不应**因 skipped 而「报错页」化。  
- **`skipped` 不应破坏**用户当前可见的 RRM / pairwise / 原始匹配等 **现有 GET fallback** 行为（GET **仍只读**、**不写库**）。

---

## 7. `processed` 的定义

| 场景 | 建议 |
|------|------|
| Writer **apply** 成功 **写入** `MatchResultRrmTop2DisplayMeta`（`wroteMeta === true` 且与产品一致） | **`processed`**：`processedAt`；`metaWriteResult` 存 **viewer-safe** 摘要；清理租约字段（如 `lockedAt`）。 |
| **`existing_meta_frozen`** | **`skipped`**（**B4D** 已验证）：本 job **未产生新写入**；标为 `processed` 易误导审计与重放策略。 |

若 writer 成功但 **仅**写 summary、meta 因故未写（若未来组合路径存在），B5-B 须在计划中 **单独枚举** `processed` / `skipped` 判定表，避免歧义。

---

## 8. `failed` 的定义

以下进入 **`failed`**：

- Prisma 已知/未知请求异常
- **未捕获**的运行时异常
- **无法解析**的 job payload（无法映射到 skipped / processed）
- Writer **抛异常**（与返回 `ok: false` + 已知 no-op code **区分**）

**必须**写入：

- `lastErrorCode`（短、稳定枚举或分类前缀）
- `lastErrorMessage`：**仅**经 **sanitize**（与现有 `sanitizeRrmTop2HookJobError` 同精神）后的文本

**禁止**写入：

- API key、token、`DATABASE_URL`
- raw prompt、transcript、raw score

---

## 9. Writer 调用方式

Controlled apply gate 在通过 §4 门闸后调用：

`writeRrmTop2DisplayMetaForMatchResult`

| 项 | 说明 |
|----|------|
| **`dryRun`** | `--apply` 且确认通过时：**`dryRun = false`**。 |
| **Env 门闸** | **不**在 runner 内强行绕过 writer 既有开关：`PEIMA_M5_RRM_TOP2_META_WRITE_ENABLED`、`PEIMA_M5_RRM_SIM_READONLY_SUMMARY_WRITE_ENABLED`。Env off → writer 返回 `writer_disabled` / `summary_write_disabled` 等 → 映射 **`skipped`**（或产品定义的 noop），**不**伪造成功。 |
| **Summary** | 仅当 writer 与 env 允许时写 `matchInsights.rrmSimReadonlySummary`；B5-A **不**扩展新写入面。 |

---

## 10. 安全边界

**永远不改**（与既有 M5 约束一致）：

- `MatchResult.candidateUserId`
- `finalScore`
- worker ranking（及不在本文列举的其它排名侧车，除非未来单独里程碑）
- `PairwisePoolFinalizeMeta`
- user profile
- questionnaire profile
- chat messages

**允许写**（仅当 apply gate 通过且 writer/env 允许）：

- `MatchResultRrmTop2DisplayMeta`
- `matchInsights.rrmSimReadonlySummary`（writer + summary env）
- HookJob 行字段：`status`、`attempts`、`lockedAt`、`processedAt`、`noOpReasonCode`、`metaWriteResult`、`lastErrorCode`、`lastErrorMessage`、`auditMeta`（若采用）

**GET**：**只读**；**不**因本链路写库。

- `apps/api/src/dev-cli/m56-b5-rrm-top2-hook-job-apply-runner.ts`

## 12. 测试建议（B5-B）

单测 / 集成测试应覆盖：

- 无 `--apply` → **不写** HookJob 状态。
- 无 `confirm` → **拒绝** apply、**不写**状态。
- `pending → processing` 租约语义。
- Writer ok + meta 写入 → **`processed`**。
- Writer no-op **`existing_meta_frozen`** → **`skipped`**。
- Writer no-op **`rrm_summary_missing`** → **`skipped`**。
- Writer **抛错** / Prisma 错 → **`failed`** + sanitize。
- **不改** `candidateUserId` / `finalScore`。
- **不接** GET 写库路径。

---

## 13. Run Record（B5-C）

B5-C 应做一次 **受控跑批记录**（非敏感），建议包含：

- dry-run 基线；
- 对 **`existing_meta_frozen`** 类 job 做 **controlled apply** 后，确认 job 变为 **`skipped`**；
- 确认 **未**写 meta（与 frozen 语义一致）；
- 确认 **未**改 `candidateUserId` / `finalScore`。

---

## 14. 验收标准（B5 完成）

| # | 标准 |
|---|------|
| 1 | Controlled apply **必须**显式确认（§4）。 |
| 2 | Apply **最多**小批量（§11 `limit` 上界）。 |
| 3 | 状态迁移 **正确**（§5），与租约/重试策略文档一致。 |
| 4 | **`existing_meta_frozen`** 能安全 **`skipped`**。 |
| 5 | **已知 no-op 不当 `failed`**。 |
| 6 | **`candidateUserId` / `finalScore` 不变**。 |
| 7 | **GET 不写库**。 |
| 8 | **不接**自动 worker loop。 |
