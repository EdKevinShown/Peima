# M5.5-M1 — RRM Top2 Meta Writer Plan

## 1. 一句话结论

M5.5-M1 **不写代码**，只定义正式 **RRM Top2 meta writer** 的计划与约束。目标是把 **M5.5-M0** dev-cli / fixture 的**手动写入链路**，升级为 **受控、幂等、可观测** 的生产写入链路：在合适时机自动写入 **`matchInsights.rrmSimReadonlySummary`** 与 **`MatchResultRrmTop2DisplayMeta`**，使 **`GET /matching/result`** 在开关与数据齐备时能返回 **`displaySourceType = rrm_top2_bounded_selector`**，且**不改变** `MatchResult.candidateUserId`、`finalScore`、pairwise 侧车、worker 排名与用户画像。

---

## 2. 当前事实

- **`MatchResultRrmTop2DisplayMeta`**：仓库内 **Prisma 写入**（`upsert`）目前仅出现在 **`apps/api/src/dev-cli/m55-m0-rrm-top2-display-fixture.runner.ts`**（及单测 mock）。`apps/api/src/modules` 下 **`resolveMatchResultDisplay`** 仅为 **`findUnique` 读路径**，无 create / update / upsert。
- **`rrmSimReadonlySummary`**：**`writeRrmSimReadonlySummaryToMatchResult`**（`matching-rrm-sim-readonly-summary-writer.ts`）已实现，并由 **`readM5RrmSimReadonlySummaryWriteEnabled()`**（`PEIMA_M5_RRM_SIM_READONLY_SUMMARY_WRITE_ENABLED`）门控；**尚未**接入 worker、matching service、AI simulation job、RRM proposal 等主流程。本地验证多依赖 **M5.5-M0** fixture 合并 `matchInsights`。
- **`resolveMatchResultDisplay`**（`matching-result-display.ts`）：**只读**；不写 `MatchResult`、不写侧车、不重跑 RRM evaluator。
- **`GET /matching/result`**：设计上 **不得写库**、**不得重算 RRM**；仅消费已持久化或可解析的 viewer-safe 数据。
- **`displaySourceType = rrm_top2_bounded_selector`**：依赖 **`PEIMA_M5_RRM_TOP2_ENABLED`**、侧车 **存在且 `frozen`**、`meta` 可被 **`parseMatchResultRrmTop2DisplayMetaV1Loose`** 解析、`matchInsights` 上 **`tryParseRrmSimReadonlySummaryPayloadV1FromMatchInsights`** 成功、**`validateRrmTop2DisplayEligibility`** 通过、展示用户存在于 `users`。
- **无合格 meta / summary / eligibility 失败时**：resolver **跳过 RRM 分支**，回退到 **pairwise finalize**（若 env 与侧车命中）或 **`match_result_original`**。

---

## 3. Writer 的目标

在 **基础匹配已完成** 且 **上游条件满足** 时，由 **受控异步或后处理钩子**（非 GET）自动：

1. 写入（或浅合并）**`matchInsights.rrmSimReadonlySummary`** — 仅该键，契约对齐 **`matching-rrm-sim-readonly-summary.ts`** / **`tryParseRrmSimReadonlySummaryFromMatchInsights`**。
2. **upsert `MatchResultRrmTop2DisplayMeta`** — JSON 对齐 **`MatchResultRrmTop2DisplayMetaV1`**（`rrm-top2-display-meta.types.ts`）与 parser。

使 **`GET /matching/result`** 在 reader 侧能 **自动** 得到 **`rrm_top2_bounded_selector`**（在 **`PEIMA_M5_RRM_TOP2_ENABLED`** 开启且读路径条件仍满足时）。

**明确不改**：

- `MatchResult.candidateUserId`
- `MatchResult.finalScore`
- worker ranking 持久化语义
- **`PairwisePoolFinalizeMeta`** 内容（writer 不替代 pairwise finalize）
- 用户画像主数据

---

## 4. 推荐接线点

### Option A：`GET /matching/result` 读路径写入

**结论：禁止。**

- GET 不得写 DB，违反幂等与缓存语义。
- GET 不得重跑 RRM evaluator（与 M5.1 / M5.2 / M5.3 红线一致）。
- 读路径变重、错误与重试行为不可控。

### Option B：worker batch-match 完成后写入

**评估：**

- **优点**：`MatchResult` 刚生成，`matchResultId` / `batchId` / `userId` 绑定清晰。
- **缺点**：此时 **RRM-Sim / ranking proposal** 可能尚未完成，`rrmSimReadonlySummary` 常缺失；若强行写 meta 会违背「summary 必须已解析且 eligible」。
- **适合**：**条件写入** — 仅当 summary（及 Top2 证据）**已就绪**时写 meta；否则 **no-op**。可与 Option C **组合**为「先 match，后由仿真 completion 补写」。

### Option C：RRM simulation / proposal 完成后写入

**推荐（短期主路径）。**

- 最接近 **RRM 结果来源**；可先从 **只读产物** 构建 **M5.2-M2A viewer-safe summary**，再 **`writeRrmSimReadonlySummaryToMatchResult`**，最后在 **同一事务或有序两步** 内 upsert **`MatchResultRrmTop2DisplayMeta`**（先 summary 后 meta，便于 eligibility 自检）。
- 与 **`resolveMatchResultDisplay`** 消费路径一致：GET 只读 **已写入** 的 summary + meta。

### Option D：独立 post-match source aggregation job

**中期推荐。**

- **输入**清晰：`MatchResult` + **稳定 Static Top2** + RRM summary + **显式 guardrails**。
- **可重试、可审计、可批量回放**；不污染 GET、不阻塞主匹配 HTTP。
- 适合 **M5.6 / M9** 与多源共识演进。

### 综合推荐

| 阶段 | 建议 |
|------|------|
| **短期 M5.5-M2** | **Option C 为主**；必要时 **Option B + C**：match 完成仅打标或入队；**simulation / proposal completion** 触发实际写入。不在 batch-match 同步路径阻塞等待 RRM。 |
| **中期 M5.6 / M9** | **Option D**：独立 **source aggregation** job，统一 Top2 / summary / guardrails / meta 版本与回放。 |

## 5. 输入来源定义

Writer 逻辑上需要（**实现时可分阶段补齐，缺失则 no-op**）：

1. **`MatchResult`**  
   - `id`、`userId`、`candidateUserId`、`finalScore`、`matchInsights`、`batchId`（及 `createdAt` 等审计用字段）。  
   - **不**用 `finalScore` / `candidateUserId` 推导展示切换；baseline 恒为 **`candidateUserId`**。

2. **Static Top2（稳定来源）**  
   - **baseline**：与 `MatchResult.candidateUserId` 一致（静态 Top1）。  
   - **second**：与 baseline 不同、且与 **同一 batch / 同一 shortlist 冻结视图** 绑定的第二名。  
   - **`top2Fingerprint`**：与 RRM summary / meta 绑定的**稳定摘要指针**（仅允许来自已持久化侧车或明确冻结的快照，见 §6）。  
   - **`sourceVersion`**：Top2 快照来源版本串（用于审计，非用户可见文案）。

3. **RRM-Sim readonly summary（目标形态）**  
   - `schemaVersion`、`sourceVersion`（须在 **`ALLOWED_RRM_SIM_READONLY_SOURCE_VERSIONS`** 与 M5.3 eligibility 白名单对齐的子集内）。  
   - `winnerUserId`、与 Top2 集合一致性、`confidenceBucket`、`fallbackUsed`。  
   - `suggestedAction` / `progressionWindow` / `simulatedRhythmScore` 等 **M5.2 契约字段**（以 parser 为准）。  
   - **禁止**写入 raw 维度向量、公式、prompt、transcript、另一候选人敏感对比。

4. **Guardrails 显式摘要**  
   - 仅来自 **拟写入的 `meta.guardrails`**（M5.5-M0.2）：`status` ∈ `pass` \| `caution` \| `block` \| `not_evaluated`；`blockReasons` / `cautionReasons` 数组。  
   - **`status === "pass"`** 且两数组均为空，才允许通过 eligibility（与 **`validateRrmTop2DisplayEligibility`** 一致）。

5. **已有侧车行（若存在）**  
   - 是否 **`frozen`**、**`top2Fingerprint`** 是否与本次一致、是否允许覆盖（默认 **不允许覆盖已 frozen**）。

---

## 6. Static Top2 来源问题

**不能**将 **`FinalMatchDecisionMeta` 的 `selectedCandidateUserId` / `pairwiseWinnerCandidateUserId`** 当作唯一、稳定的 **Static Top2** 来源；该类字段服务于 **pairwise 展示解析**，与 **RRM Top2 bounded** 所需的 **冻结 Top2 集合 + fingerprint** 未必同一生命周期。

**需要稳定来源（候选，按产品优先级选型）：**

- **Relationship shortlist / Top2 冻结快照**（若 schema 已有或即将有明确「viewer + batch → top2」行）。
- **`AiPairwiseDecisionJob` shortlist 快照**（仅当 **frozen** 且与 `MatchResult` / batch 可证明绑定）。
- **Preview pool rank**（`PreviewPoolItem` / `rankInPool`）— 仅当能证明与 **最终 `MatchResult` 同一决策批次** 且不可变。
- **未来**：`staticTop2ReadonlySummary` 一类只读侧车（与 `rrmSimReadonlySummary` 对称）。

**约束：**

- **M5.5-M2 不得在 GET 热路径重算 Top2**。
- **若无稳定 Top2（两 distinct id + fingerprint）** → writer **`no-op`**，建议审计 reason：**`static_top2_missing`** / **`static_top2_not_frozen`** / **`static_top2_fingerprint_missing`** / **`static_top2_selected_not_in_top2`**（与代码内 **`RRM_TOP2_DISPLAY_NO_OP_REASON_CODES`** 可映射：`top2_count_invalid`、`baseline_mismatch`、`rrm_winner_not_in_top2` 等，审计层可用更粗粒度 code）。

## 7. RRM summary 写入规则

**复用** **`writeRrmSimReadonlySummaryToMatchResult`**（或与其 **相同校验 + 相同浅合并** 的一层薄封装）。

规则对齐现有实现与注释：

- **仅**更新 **`matchInsights`** 中的 **`rrmSimReadonlySummary`** 键（**`mergeRrmSimReadonlySummaryIntoMatchInsights`**），**不覆盖** `explanation`、`riskFlags`、`openingTopics` 等其他键。
- 若已有 summary 且 **`frozenAt`** 非空 → **不覆盖**（`frozen_existing_summary`）。
- **incoming** 必须经过与 GET 侧一致的 **tryParse** 校验；失败则 **不写**。
- **禁止**写入 raw score、C/A/S/E/F/Q/D/R 细向量、公式、prompt、transcript、另一候选人敏感对比（与 M5.2 / M5.3 文档一致）。

**门控**：继续由 **`PEIMA_M5_RRM_SIM_READONLY_SUMMARY_WRITE_ENABLED`** 控制是否允许落库；M5.5-M2 可与 **`PEIMA_M5_RRM_TOP2_META_WRITE_ENABLED`**（§12）组合为「双开关都 on 才写」或「summary 开关优先」— **实现阶段二选一写清，默认偏保守**。

## 8. `MatchResultRrmTop2DisplayMeta` 写入规则

对表 **`match_result_rrm_top2_display_meta`**（Prisma：`MatchResultRrmTop2DisplayMeta`）执行 **upsert** 时须满足：

| 约束 | 说明 |
|------|------|
| `matchResultId` | **全局 unique**，与目标 `MatchResult.id` 一致。 |
| `viewerUserId` | **等于** `MatchResult.userId`。 |
| `frozen` | 生产写入建议 **`true`**（与 resolver 读 **`rrmRow?.frozen`** 一致）；若未来支持草稿行，须与 resolver 约定一致，**默认仍 frozen=true**。 |
| `schemaVersion` | 表字段 **`Int`**；与 JSON **`meta.schemaVersion === 1`** 对齐（见 `MATCH_RESULT_RRM_TOP2_DISPLAY_META_SCHEMA_VERSION`）。 |
| `sourceVersion` | 表字段与 **`meta.sourceVersion`** 一致，表示 writer / 上游版本。 |
| `top2Fingerprint` | **非空**（与 `meta.top2Fingerprint`、eligibility 输入一致）。 |
| `meta` | 合法 **`MatchResultRrmTop2DisplayMetaV1`**：`sourceType` = **`rrm_top2_bounded_selector`**；**`appliedToFinalScore: false`**、**`appliedToWorkerRanking: false`**（字面量 `false`，与 parser 校验一致）；**`rollbackAvailable: true`**（策略见 §11）。 |
| **`meta.guardrails`** | **必须存在**；**`status` 必须显式写入**；只有通过 §9 校验后才允许落库。 |
| **`baselineCandidateUserId`** | **等于** `MatchResult.candidateUserId`。 |
| **`previousDisplayCandidateUserId`** | 首次写入可为 baseline；若未来存在「展示修订链」，则为上一展示候选（M5.5-M2 可简化为 baseline）。 |
| **`newDisplayCandidateUserId`** | RRM **bounded winner**，且必须 ∈ Top2。 |
| **`decisionRule`** | 建议 **`rrm_top2_bounded_selector`**（与 `MATCH_RESULT_RRM_TOP2_DISPLAY_META_SOURCE_TYPE` 语义对齐，便于审计）。 |

**不写**：`MatchResult` 主行上的任何展示列若未来出现，亦不在本轮覆盖；**不**改 `pairwise_pool_finalize_meta`。

---

## 9. Eligibility 对齐

Writer 在 **持久化 meta 之前** 必须执行与 **`resolveMatchResultDisplay`** 等价的 **`validateRrmTop2DisplayEligibility`** 调用（相同输入形状：`m5RrmTop2Enabled`、`matchResultCandidateUserId`、`top2CandidateUserIds`、`top2Fingerprint`、`rrmDisplayMeta`、`rowTop2Fingerprint`、`rrmSimReadonlySummary`）。

**通过条件摘要**（与 `rrm-top2-display-eligibility.ts` 一致）：

- summary 存在且 schema / `sourceVersion` 白名单通过；`fallbackUsed !== true`；`confidenceBucket` 非 `low` / `unknown`。  
- meta 存在且 `appliedToFinalScore` / `appliedToWorkerRanking` 均为 `false`；fingerprint 与 baseline 一致；winner 与 `newDisplayCandidateUserId` 一致且在 Top2。  
- **guardrails**：存在、`status === "pass"`、`blockReasons` / `cautionReasons` 均为空数组。

**若不通过**：**不写 meta**（若 summary 已单独写入且仍无效，则 **整次 writer no-op** 或仅 meta no-op — **不得**留下「无 summary 却有 RRM meta」的 resolver 半状态；推荐 **先 summary 后 meta，同一编排内校验**）。

---

## 10. No-op / fallback 规则

**no-op 不是错误**：不改变 `MatchResult` 主行；**GET** 继续走 pairwise / **`match_result_original`**。

### 10.1 与 resolver 共用的 code（`RRM_TOP2_DISPLAY_NO_OP_REASON_CODES`）

写入逻辑应能映射到现有枚举，包括但不限于：`env_off`、`meta_missing`、`meta_schema_invalid`、`meta_applied_flags_invalid`、`top2_count_invalid`、`top2_duplicate`、`baseline_mismatch`、`fingerprint_mismatch`、`rrm_summary_missing`、`rrm_summary_schema_invalid`、`rrm_summary_version_rejected`、`rrm_winner_not_in_top2`、`rrm_meta_winner_mismatch`、`rrm_confidence_low`、`rrm_confidence_unknown`、`rrm_fallback_used`、`guardrails_missing`、`guardrails_block`、`guardrails_caution`、`guardrails_not_evaluated`、`guardrails_pass_predicate_failed`、`proposed_user_not_found`。

### 10.2 Writer 编排层补充审计 code（示例）

| Code | 含义 |
|------|------|
| `writer_disabled` | **`PEIMA_M5_RRM_TOP2_META_WRITE_ENABLED`** 未开启。 |
| `static_top2_missing` | 无法从冻结源解析两枚 distinct Top2。 |
| `static_top2_not_frozen` | Top2 快照未冻结仍可变。 |
| `static_top2_fingerprint_missing` | 无稳定 fingerprint。 |
| `static_top2_selected_not_in_top2` | RRM 选中不在 Top2。 |
| `existing_meta_frozen` | 已存在 frozen 侧车行，策略为不覆盖。 |
| `summary_write_failed` | summary writer 返回未写入且 meta 不应单独写。 |

**说明**：`rrm_summary_invalid` 可与 `rrm_summary_schema_invalid` / writer 的 `invalid_summary` 对齐；`candidate_user_missing` 可与 **`proposed_user_not_found`**（展示用户 DB 不存在）对齐。

## 11. 幂等与冻结策略

- **已存在 `MatchResultRrmTop2DisplayMeta` 且 `frozen === true`**：**默认不覆盖**整行 JSON（**`existing_meta_frozen`**）；若需修订，引入 **新 revision 表或新 fingerprint 行**（**不在 M5.5-M2 范围**）。
- **同一 `top2Fingerprint` + 同一 `newDisplayCandidateUserId` + summary 仍有效**：可 **no-op success**（幂等键由 writer 定义，如 `matchResultId` + `top2Fingerprint`）。
- **`fingerprint` 变更**：**不覆盖**旧 frozen meta；新决策应走 **新 `MatchResult` 或显式 admin 解冻流程**（未来）。
- **禁止**因重复 **GET** 触发任何写入。
- **本轮不做自动 rollback**；**`rollbackAvailable: true`** 表示产品语义上可回退（例如关 **`PEIMA_M5_RRM_TOP2_ENABLED`** 后 resolver 不再选 RRM），**非**自动删行。

## 13. Admin / audit 输出

正式 writer 应输出 **viewer-safe、无 PII 敏感扩展** 的结构化日志或审计表字段（若后续有），例如：

- **`sourceVersion`**（meta / summary）、**`decisionRule`**、**`noOpReason`** / **`noOpReasonCode`**、**`selectedChanged`**（bool）、**`guardrailsStatus`**、**`summarySourceVersion`**、**`top2Fingerprint`**、**`fallbackUsed`**。

**不要记录**：raw prompt、transcript、raw score、细维度向量、API key、token、另一候选人敏感对比。**`matchResultId`** 等仅内部日志需符合现有日志脱敏规范；**本文档不列举真实 ID**。

## 14. 与 M6.1 Feedback 的关系

M6.1 **feedback `decisionContext`** 宜记录（viewer-safe、可聚合）：

- `displaySourceType`
- `matchResultId`（或内部稳定引用）
- `displayCandidateUserId` vs **`candidateUserId`**
- **是否**处于 RRM display 活跃态
- **`sourceVersion`**（summary / meta）
- **无** raw RRM score / 公式 / Top2 外候选人细节

便于 **M9** 评估：RRM 展示对反馈的影响、no-op 原因分布、static / pairwise / RRM 源质量对比。

## 15. M5.5-M2 最小实现建议

**新增（建议文件）**：

- `matching-rrm-top2-display-meta-writer.ts` — 编排：读 `MatchResult`、拉 Top2、调 summary writer、组装 `meta`、**`validateRrmTop2DisplayEligibility`**、prisma upsert。
- `matching-rrm-top2-display-meta-write-env.ts` — 读取 **`PEIMA_M5_RRM_TOP2_META_WRITE_ENABLED`**。
- **单测** — env off、summary 缺失、Top2 缺失、guardrails 非 pass、已 frozen meta 不覆盖、`candidateUserId` / `finalScore` 不变、eligible 时 upsert。

**可选接线**：

- **AI simulation v1 job 完成** 或 **RRM ranking proposal 定稿** 回调中调用 writer（**同一进程或 worker 消息**，需防重入）。
- 或 **先**扩展 **dev/admin controlled runner**（非 GET）验证双写顺序。

**不做（M5.5-M2 范围外）**：

- 不接 GET；不改 `finalScore` / `candidateUserId`；不改 FinalMatch / Chat UI；**不做** Admin 页面；**不做** 全量 batch 回放。

## 16. 验收标准（M5.5-M2）

- **`PEIMA_M5_RRM_TOP2_META_WRITE_ENABLED`** off → **不写 meta**。
- summary 缺失或 invalid → **no-op**，不写 meta（或整次 no-op）。
- Static Top2 缺失 / 未冻结 → **no-op**。
- guardrails caution / block / not_evaluated → **no-op**。
- eligible → **summary（若开关）+ meta upsert** 成功。
- **已存在 frozen meta** → **不覆盖**。
- **`MatchResult.candidateUserId` / `finalScore` 不变**（单测断言 + 集成抽检）。
- 双开 reader + writer 开关后，**`GET /matching/result`** 可对 **新完成链路** 的用例自动返回 **`rrm_top2_bounded_selector`**。
- 文档 / PR **不提交**真实 userId、candidateId、matchResultId、token、key、`DATABASE_URL`；**不修改** `PEIMA_PREVIEW_VISUAL_ENHANCE_ENABLED`。
