# M5.5-M2 — RRM Top2 Meta Writer Foundation

## 概述

本轮交付 **RRM Top2 display meta 受控 writer 基础能力**：环境开关、纯编排服务、与 **`validateRrmTop2DisplayEligibility`** 对齐的前置校验、可选 **`rrmSimReadonlySummary`** 写入与 **`MatchResultRrmTop2DisplayMeta`** upsert、结构化 no-op 原因、单元测试，以及 **dev-only CLI**（默认 dry-run）。

**本轮不做**：接入 `GET /matching/result`、worker、AI simulation job、生产自动钩子；不改 `MatchResult.candidateUserId` / `finalScore` / FinalMatch / Chat。

## 开关

| 变量 | 作用 |
|------|------|
| **`PEIMA_M5_RRM_TOP2_META_WRITE_ENABLED`** | 为 `1` / `true` / `yes` 时允许 writer upsert meta（默认关闭）。 |
| **`PEIMA_M5_RRM_SIM_READONLY_SUMMARY_WRITE_ENABLED`** | 与既有 M5.2-M2B 一致；**模式 2**（传入 summary payload 并持久化）在 apply 路径需要开启。 |

## CLI 用法

`apps/api` 下 `pnpm exec nest build` 后：

```bash
pnpm --filter @peima/api run m55-m2:rrm-top2-meta-writer
# 等价 node dist/dev-cli/m55-m2-rrm-top2-meta-writer-cli.js ...
```

参数：`--matchResultId`、`--top2CandidateUserIdA`、`--top2CandidateUserIdB`（须含 `MatchResult.candidateUserId`）、`--rrmWinnerCandidateUserId`（须为 Top2 之一）、`--top2Fingerprint`；可选 `--mergeSummary`（合并 fixture 形状 summary）、`--apply`（否则 dry-run）。

## Writer 行为摘要

1. **内存先跑通 eligibility**（含 summary + 拟写入 meta），再写 DB，避免「仅有 meta 无 summary」的半状态。  
2. **模式 1**：`matchInsights` 上已有可解析 summary → 只写 meta。  
3. **模式 2**：传入 `rrmSimReadonlySummaryPayload` 且 summary 写入开关 on → 先 **`writeRrmSimReadonlySummaryToMatchResult`**，reload 后再 **二次 eligibility**，通过才 upsert meta。  
4. **已 frozen 的侧车行** → `existing_meta_frozen`，不覆盖。  
5. **显式 guardrails**：仅 `status === "pass"` 且 `blockReasons` / `cautionReasons` 均为空数组时继续（不使用 `matchInsights.explanation.cautions` 替代）。
