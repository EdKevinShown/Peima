# M5.6-B6-A — Apply Runner Capability Review + Env-on Apply Test Plan

> **范围**：**设计 / 评审文档 only**。判断 **M5.6-B5-B** 是否已覆盖原路线中 “M5.6-B6 hook job consumer apply runner” 的 **核心能力**；定义 **env-on apply** 测试计划与 **B7** independent poller **复用**策略。**不**新增第二套 apply runner、**不**含真实业务 id、token、`DATABASE_URL`。

---

## 1. 一句话结论

**M5.6-B5-B** 已实现并验证 **controlled hook job consumer apply runner** 的 **核心能力**（pending 读取、apply gate、状态迁移、writer apply、no-op → skipped、异常 → failed、小批量 limit、不接 GET / worker loop、不变更 `candidateUserId` / `finalScore`）。**M5.6-B6** **不应**再实现第二套 CLI apply runner。**M5.6-B6-A** 的作用是对齐认知：**能力评审** + **env-on apply 测试计划** + **B7 poller 复用 B5-B 逻辑** 的路线定义。

---

## 2. 当前能力清单（B5-B 已具备）

| 能力 | 说明 |
|------|------|
| **Pending 枚举** | `findPendingRrmTop2HookJobs` + `--limit`（默认 **1**、最大 **10**）。 |
| **Dry-run 模式** | 无 `--apply` 时调用 `processRrmTop2HookJobDryRun`，**不写** HookJob 状态、**不写** meta。 |
| **Apply gate** | 必须 **`--apply`** 且 **`--confirmControlledApply=I_UNDERSTAND`**；否则 **refused**，不写状态、不调 writer apply。 |
| **状态迁移** | `pending` → `processing`（`markRrmTop2HookJobProcessing`）→ `processed` / `skipped` / `failed`。 |
| **Writer apply** | `writeRrmTop2DisplayMetaForMatchResult`，**`dryRun: false`**；**不**强行覆盖 `PEIMA_M5_RRM_TOP2_META_WRITE_ENABLED` / summary 相关 env。 |
| **no-op → skipped** | 已知 writer no-op 与预检失败均 **`markSkipped`**（不当 `failed`）。 |
| **`existing_meta_frozen`** | 在 skip 集合中；**env-on 且 writer 能执行到侧车检查时**预期 `skipped` + 该 code（见 §5 Case 1）。 |
| **Writer 异常 → failed** | `markRrmTop2HookJobFailed` + `sanitizeRrmTop2HookJobError`。 |
| **`processed` 条件** | **`ok === true && wroteMeta === true`** 才 `markProcessed`。 |
| **边界** | **不接** GET；**不接** worker 自动轮询；**不改** `MatchResult.candidateUserId` / `finalScore`。 |

## 4. 为什么 B6 不应重复造 runner

若再实现一套 “B6 apply runner”：

- **Apply 与 no-op 映射** 易在两条 CLI 间 **分叉**，审计与排障困难。  
- **状态迁移**（processing / lease / attempts）易 **重复实现**，产生语义漂移。  
- **单测与回归** 成本 **翻倍**。  
- **B7 worker / independent poller** 难以选择 “唯一真相” 路径，易复制粘贴 dev-cli 逻辑。

**结论**：**B6** 定位为 **capability review + 测试与复用规划**（本文档及后续 env-on run record），**不**新增第二套 apply runner。

## 5. Env-on apply 测试计划（建议 B6-B / B6-C）

### Case 1：env on + 已有 frozen meta

**前置（概念）**：

- `PEIMA_M5_RRM_TOP2_META_WRITE_ENABLED=1`（及按需 summary env，与产品策略一致）。  
- 存在 **pending** hook job，其 `MatchResult` 已有关联 **frozen** 的 `MatchResultRrmTop2DisplayMeta`。

**预期**：

- Writer **不**覆盖 frozen meta；`noOpReasonCode = **existing_meta_frozen**`。  
- Hook job **`skipped`**。  
- **`candidateUserId` / `finalScore` 不变**。

### Case 2：env on + 可写入的 “新鲜” 任务（staged）

**前置（概念）**：

- 目标 `MatchResult` **无** frozen meta（或可安全写入路径）。  
- `rrmSimReadonlySummary` 可解析且与 Top2 / fingerprint / guardrails **一致**。  
- Meta（及按需 summary）env **开启**。

**预期**：

- Writer **`wroteMeta === true`** → hook job **`processed`**。  
- GET `/matching/result` **后续**可读展示（**GET 本身仍只读**；不在本里程碑改 GET）。  
- **`candidateUserId` / `finalScore` 不变**。

若 **Case 2** 在本地不易构造数据，可 **保留为 staged test plan**，在专用环境或 fixture 后再跑；**不**强制与 B6-A 同轮执行。

## 6. B7 independent poller 复用策略

**B7 不应复制 apply 业务逻辑。**

推荐做法：

- 将 **与 DB / writer / 状态机相关** 的处理收敛为 **单一实现面**（见 §7），由 **dev-cli** 与 **independent poller** 共用。  
- **B7 poller / worker 侧** 仅负责：**定时**、**小批量**、**退避**、**可观测性**、**与主 worker 解耦**；每条仍走 **同一** apply path（含 env gate 与 confirm 策略若通过配置或内部等价 gate 实现）。  
- **不接 GET**；**不**把 poller 绑死在现有 worker main 阻塞链路上（设计目标：independent）。
