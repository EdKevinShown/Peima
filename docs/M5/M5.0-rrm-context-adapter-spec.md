# M5.0 — RRM Context Adapter Spec

本文档定义 Peima / 配吗 在 **多模块、多数据源** 下使用 RRM 的正式边界：RRM **不是**所有模块共用同一套原始参数直接代入同一公式计算，而是 **RRM Core + Context Adapters + SourceVersion + 降级规则**。  
实现代码以仓库为准；本规范约束后续 M5～M9 的设计与评审。

---

## 1. 一句话结论

仓库内 **唯一完整实现 C / A / S / E / F / Q / D / R 闭环** 的是 **`evaluateRrmSimFromSimulationV2`（`rrm-sim.evaluator.ts`）+ `rrm-sim-extractor.ts`**，其输入为 **RRM-ready 的 AI simulation v2 载荷**（`AiSimulationLlmPayloadV2`）及可选 **staticContext**。  
**Pairwise（RRM-lite）、Chat、Copilot、Timeline、Feedback** 目前 **都没有**接入上述 **同一套完整 RRM 公式**（Pairwise 为独立契约与提示词；其余模块无该求值入口）。  
因此 **禁止跨场景混用参数或混用 `sourceVersion`**；必须在适配器层拆分输入输出，并各自声明 **SourceVersion** 与降级策略。

## 2. RRM Core 当前事实

### 2.1 核心文件（路径均相对于 `apps/api/src/modules/ai-simulation-v1/` 或注明）

| 文件 | 职责 |
|------|------|
| `rrm-sim-formula.ts` | `computeRfiScenario`、`aggregateRfiSim`、`rfiToSimulatedRhythmScore`、`applyFsimCap` 等数学层。 |
| `rrm-sim.evaluator.ts` | `evaluateRrmSimFromSimulationV2`、`isFullRrmSimEvaluatorInput`、`buildFallbackRrmSimResult`；编排抽取器与门控输出。 |
| `rrm-sim-extractor.ts` | `extractCPred`、`extractDPre`、`extractRPre`、`extractFGlobal`；每场景 `extractSPerScenario` / `extractEPerScenario` / `extractQPerScenario` / `extractRScenario`。 |
| `rrm-sim.constants.ts` | 场景权重、F 封顶、R/D 门控阈值、progression 分数阈值等常量。 |
| `ai-simulation-v1-rrm.constants.ts` | `AI_SIMULATION_RRM_SOURCE_VERSION`、`RRM_SCENARIO_KEYS_ORDERED`、`RRM_SCENARIO_APPROACH_INTENSITY` 等载荷与场景契约。 |
| `rrm-sim.types.ts` | `RrmSimResult`、`RrmSimScoresBlock`、`RrmSimScenarioScoreRow` 等 DTO。 |
| `ai-simulation-v1.service.ts` | `enrichResultsWithRrmSim`：在 job 结果上附加 `rrmSimResult`（成功项拉问卷构建 staticContext，失败则 `staticContext = null`）。 |
| `ai-simulation-v1-rrm-ranking-proposal.ts` | `buildRrmRankingProposal`：基于多候选诊断生成 **只读** 排序提案。 |
| `apps/api/src/modules/matching/matching-rrm-ranking-proposal.service.ts` | `MatchingRrmRankingProposalService`：JWT 只读 RRM 提案 HTTP 封装；**不写**匹配主结果。 |

### 2.2 行为说明（与代码一致）

- **`computeRfiScenario`** 是 RRM-Sim **核心公式**（给定 C_pred、全局 F_sim、D_pre、R_pre 及每场景 A、S、E、Q、R_scenario）。  
- **`evaluateRrmSimFromSimulationV2`** 是当前 **唯一完整 RRM-Sim 求值入口**（纯函数、无额外 LLM）。  
- **A（每场景 advancement intensity）** 由 **`RRM_SCENARIO_APPROACH_INTENSITY`** 与载荷内 `scenarioApproachIntensity` 对齐（校验容差见 `isFullRrmSimEvaluatorInput`），**不由 LLM 自由生成浮点「场景强度」**。  
- **`buildRrmRankingProposal` / Matching 只读提案**：仅产出观察用排序与 reasonCodes；**不**写 `MatchResult`、**不**改 `finalScore`、**不**改 `displayCandidateUserId`（与 M4.0 / matching DTO 承诺一致）。

## 3. RRM Core 变量

以下为 **语义定义**（与 `rrm-sim.types.ts` / extractor 命名对齐）。**变量名在文档中统一**，但 **不同 Adapter 上下文下来源不同，禁止混用或跨场景直接代入同一公式**。

| 符号 | 含义 |
|------|------|
| **C** | Relationship capacity（关系容量 / 上下文适配度），实现上对应 **`C_pred`**。 |
| **A** | Advancement intensity（推进强度），实现上为 **每场景** **`A_scenario`**（与 `scenarioApproachIntensity` 绑定）。 |
| **S** | Smoothness（顺滑 / 承接），实现上 **`S_sim`**（每场景）。 |
| **E** | Emotional safety（情绪安全 / 低压力边界），实现上 **`E_sim`**（每场景）。 |
| **F** | Confidence / feedback reliability（跨场景一致性与置信综合），实现上全局 **`F_sim`**。 |
| **Q** | Interaction quality（互动质量），实现上 **`Q_sim`**（每场景）。 |
| **D** | Friction / cost（摩擦与前置成本），实现上 **`D_pre`**（全局）。 |
| **R** | Respect / boundary risk（尊重与边界风险），实现上 **`R_pre`**（全局）及 **`R_scenario`**（每场景）。 |

## 4. Adapter 1：RRM-Sim

### 4.1 用途

- 匹配前（无真实聊天）的关系节奏 **模拟**层。  
- **AI simulation** 结果富化。  
- **RRM ranking proposal**（只读）。  
- **M5 Multi-source Final Decision** 中，凡标注为「RRM 分数 / 节奏门控」的输入 **必须**来自本 Adapter（见第 11 节）。

### 4.2 输入

- `AiSimulationLlmPayloadV2`（ persisted **`transcriptLite`**，校验通过即为 full）。  
- 可选 **`staticContext`**（由问卷画像 + `buildAiSimulationStaticContext` 等链路构建）。  
- **Questionnaire profile**（经现有服务转为 static 摘要，不存原始开放题全文于 RRM 侧车）。

### 4.3 输出

- **`RrmSimResult`**（`sourceVersion: "rrm-sim-v1"`）。  
- **`rrmRankingProposal`**（只读提案结构，含 `reasonCodes` 等）。  
- **`progressionWindow`**、**`suggestedAction`**、**`simulatedRhythmScore`**。  
- **Caution / reasonCodes**（如 `RRM_FALLBACK`、`RRM_UNAVAILABLE` 等，与 matching 行 DTO 对齐）。

### 4.4 参数（与实现对齐）

- `C_pred`  
- `A_scenario`（每场景）  
- `S_sim`、`E_sim`、`Q_sim`（每场景）  
- `F_sim`（全局）  
- `D_pre`（全局）  
- `R_pre`（全局）、`R_scenario`（每场景）

### 4.5 规则

| 规则 | 说明 |
|------|------|
| **A_scenario** | **fixed_by_scenario**：以 `RRM_SCENARIO_APPROACH_INTENSITY` 为契约，载荷须满足顺序、键名与强度容差；否则 **不得**当作 full RRM-Sim。 |
| **无 full v2 payload** | 走 **`buildFallbackRrmSimResult`**（`fallbackUsed: true`，`rrmUnavailableReason` 非空）。 |
| **无 staticContext** | `extractCPred` / `extractDPre` 等走 **保守** transcript-heavy 路径；不得假称含完整静态对齐。 |
| **M5** | 本 Adapter 输出可参与 **display 层 / sidecar** 门控与叙事；**不**直接改持久化 `MatchResult.candidateUserId`、**不**改 `finalScore`（与 finalize meta 设计一致）。 |
| **持久化事实** | **不**将 RRM-Sim 写为「法律上的唯一匹配对象」；仅作为多源之一。 |

## 5. Adapter 2：RRM-Observed

### 5.1 用途

- 真实聊天后的关系节奏 **观察**（非 Sim 重算）。  
- Chat insight、Timeline 信号、Assistant 上下文的 **观测摘要**（若接入，须与本 Adapter 类型绑定）。

### 5.2 输入

- `Message[]`  
- Conversation **summary**（如 `ConversationSummary`）  
- **Reply interval**、**message count**  
- **Behavior signals**  
- **Feedback**（评分/结构化，仅作观测特征）  
- **Timeline events**（如 `ConversationTimelineResponseDto.items`）

### 5.3 输出（建议字段，实现待定）

- `pace`  
- `coldRisk`  
- `boundaryRisk`  
- `observedQuality`  
- `suggestedAction`（**不得**与 `rrm-sim-v1` 枚举混用同一持久化 schema 而不加版本隔离）  
- `confidence`

### 5.4 规则

| 规则 | 说明 |
|------|------|
| **当前仓库** | **尚无**与本规范等价的正式实现与持久化类型。 |
| **sourceVersion** | **禁止**复用 **`rrm-sim-v1`** 表示观测结果。 |
| **表述** | **禁止**将 RRM-Sim 的预测表述为「已发生的真实聊天结果」。 |
| **消息量** | 少于阈值 **N**（产品常数，实现时定义）→ 返回 **`insufficient_data`**，不伪造高分。 |
| **决策** | **不得**直接影响 **final decision**（含不通过 feedback 间接覆盖 `MatchResult`）。 |

### 5.5 建议 sourceVersion

`rrm-observed-v0`

## 6. Adapter 3：RRM-Assistant

### 6.1 用途

- 开场建议、接话建议、推进节奏建议。  
- 冷场风险提醒、越界风险提醒。  
- 「是否适合邀约」「是否应放慢」等 **用户可控** 提示。

### 6.2 输入

- **RRM-Sim 摘要**（若存在且非 fallback，或明确标注低置信）。  
- **RRM-Observed 摘要**（若未来实现）。  
- **最近聊天消息**（脱敏、单会话）。  
- **用户输入草稿**  
- **Feedback**（可选）  
- **Match context**（不含另一候选人可识别敏感对比 raw）

### 6.3 输出（建议）

- `suggestedReply`（文案建议，非自动发送）  
- `suggestedAction` / `pace` / `coldRisk` / `boundaryRisk`  
- `confidence`  
- `explanation`（用户可读短说明，**无公式**）

### 6.4 规则

| 规则 | 说明 |
|------|------|
| 公式 | **不**在助手层重新实现 `computeRfiScenario`；**复用**服务端已计算的 **Sim/Observed 摘要**。 |
| 安全展示 | **不**暴露 RRM 公式、**不**暴露 **raw score**、**不**暴露 **另一候选人** 信息。 |
| 行为 | **不**自动发送消息；**不**做临床心理诊断；**不**输出操控对方的话术策略。 |
| 控制 | 建议仅展示给用户，**默认可关闭**。 |

### 6.5 建议 sourceVersion

`rrm-assistant-v0`

---

## 7. Adapter 4：RRM-Timeline

### 7.1 用途

- 关系 **阶段**、推进 **速度趋势**、**主动性** 对比。  
- **冷场** / **拉扯** 趋势、**越界风险** 提示。  
- **下一步** 建议（只读叙事层）。

### 7.2 输入

- `ConversationTimelineResponseDto.items`  
- **Messages**（与 timeline 一致的只读子集）  
- **`summary_snapshot`** 类事件  
- **Feedback events**、**behavior signals**、其他 **timeline events**

### 7.3 输出（建议）

- `stage`  
- `paceTrend`  
- `initiativeBalance`  
- `coldRisk`  
- `boundaryRisk`  
- `suggestedAction`  
- `confidence`

### 7.4 规则

| 规则 | 说明 |
|------|------|
| 只读 | **只读 insight**；不自动写用户画像、不写 `MatchResult`。 |
| 画像 | 若需影响画像，**仅允许**生成 **`ProfileUpdateSuggestion`**，且 **用户 accept** 后由既有流程落库。 |

### 7.5 建议 sourceVersion

`rrm-timeline-v0`

---

## 8. Adapter 5：RRM-Eval

### 8.1 用途

- 验证 **RRM-Sim** 是否对体验/留存有贡献。  
- 验证 **RRM-supported** 决策桶的满意度。  
- 验证 **RRM caution** 是否与负向反馈共现。  
- 关联 **feedback**、**聊天持续**、**助手反馈**、**timeline 信号**（作 **结果变量** 或 **分桶维度**，不作 Sim 公式输入）。

### 8.2 输入

- `UserFeedback`、**`structuredPayload`**  
- **`decisionContext`**（M6 计划字段：RRM-Sim / Pairwise / display 摘要枚举）  
- **Chat continuation** 指标  
- **Assistant feedback**  
- **Timeline signal**（Observed / Timeline adapter 输出摘要）

### 8.3 输出（建议）

- **Quality metrics**（聚合层）  
- **Bucketed satisfaction**  
- **`rrmSupported` success rate**  
- **Caution bucket negative rate**  
- **Assistant helpful rate**

### 8.4 规则

| 规则 | 说明 |
|------|------|
| 匹配 | **不**直接改匹配结果、**不**自动改画像、**不**自动改 final decision。 |
| 用途 | **仅**用于聚合分析、实验与版本迭代决策（人审 + 发布流程）。 |

### 8.5 建议 sourceVersion

`rrm-eval-v0`

## 9. 参数可提取性矩阵

**图例**：`direct`｜`derived`｜`llm_extracted`｜`fixed_by_scenario`｜`unavailable`｜`unsafe`  
**输出**：相对 **RRM-Sim 语义**（C/A/S/E/F/Q/D/R）的可得性；Pairwise 为 **RRM-lite 平行契约**，**不等同** `RrmSimResult` 各字段 1:1。

| 模块 | C | A | S | E | F | Q | D | R | 输出侧 | 是否影响决策（当前/规范） |
|------|---|---|---|---|---|---|---|---|--------|---------------------------|
| **Matching without sim** | unavailable | unavailable | unavailable | unavailable | unavailable | unavailable | unavailable | unavailable | 无 RRM-Sim | **否** |
| **Matching + AI Sim full** | direct | fixed_by_scenario | direct | direct | direct | direct | direct | direct | `RrmSimResult` + proposal | **仅** M5 display / sidecar；不改 `MatchResult` / `finalScore` |
| **Matching + AI Sim fallback** | derived（弱）/fallback | unavailable | unavailable | unavailable | unavailable | unavailable | partial / low | unavailable | fallback `RrmSimResult` | **否**强接管；仅 caution / 只读提案 |
| **Pairwise RRM-lite** | llm_extracted（proxy） | **unsafe** 若让 LLM 自定 A；契约 **无** Sim 之 A | llm_extracted | llm_extracted | llm_extracted | llm_extracted | llm_extracted | llm_extracted（含 strongRisk） | `AiPairwiseDecision` | **可**影响 **display**（finalize enabled 时）；**非** RRM-Sim 公式输出 |
| **Chat** | unavailable | unavailable | unavailable | unavailable | unavailable | unavailable | unavailable | unavailable | 待 RRM-Observed | **否**（规范） |
| **Copilot** | unavailable | unavailable | derived | derived | unavailable | derived | derived | derived | 规则/LLM insights | **否** |
| **Timeline** | unavailable | unavailable | derived | derived | unavailable | derived | derived | derived | 待 RRM-Timeline | **否** |
| **Feedback** | unsafe | unsafe | llm_extracted（comment） | derived | derived | derived | unavailable | unavailable | RRM-Eval 聚合 | **否** |
| **Profile suggestion** | partial（静态） | unavailable | unavailable | unavailable | unavailable | unavailable | partial | unavailable | 用户 accept 后画像 | **否**作 RRM 输入 unless accept |

## 10. 缺参数与降级规则

| 条件 | 处理 |
|------|------|
| **没有 AI simulation** | **RRM-Sim unavailable**；不调用 `evaluateRrmSimFromSimulationV2` 冒充成功；M5 不得假设存在 `simulatedRhythmScore`。 |
| **没有 completed pairwise job** | M5 **不得**假设 pairwise finalize 可用；`displayCandidateUserId` 解析以环境开关与 meta 为准。 |
| **没有真实聊天** | **RRM-Observed unavailable**；仅用 RRM-Sim 或规则层。 |
| **消息少于 N 条** | RRM-Observed / Timeline：**`insufficient_data`**。 |
| **没有 feedback** | RRM-Eval 中 F 相关 proxy **降低权重**；**不**视为失败；助手可省略反馈条件分支。 |
| **没有 timeline 某类 event** | Timeline insight **低置信**，显式标注覆盖不全。 |
| **RRM confidence low**（fallback、缺失项多、unavailableReason） | **仅 caution**；**不**接管 display / 不覆盖 `MatchResult`。 |
| **risk high / `strongRisk`** | **Guardrail block**：与 respect 门控一致方向，禁止「推进」类展示升级。 |
| **schema_validation 失败** | **不**伪造成功：走 **fallback**、job **failed** 或审计路径；保留 **audit** 可追溯原因。 |

## 11. 与 M5 / M6 / M7 / M8 / M9 的关系

| 里程碑 | Adapter / 数据 |
|--------|----------------|
| **M5 Multi-source Final Decision** | **仅**使用 **RRM-Sim** 作为「RRM 公式侧」输入；Pairwise / static / guardrails 为 **其他源**；**禁止**用 Chat/Observed 冒充 `rrm-sim-v1`。 |
| **M6 decisionContext** | 记录 **RRM-Sim**（摘要枚举 / job 指针）、**Pairwise finalize**、**`displaySourceType`** 等；**不**混写为同一 `sourceVersion`。 |
| **M7 AI Assistant** | 使用 **RRM-Assistant**（可引用 Sim/Observed **摘要**，非重算公式）。 |
| **M8 Timeline** | 使用 **RRM-Timeline**（只读）。 |
| **M9 Evaluation** | 使用 **RRM-Eval**（聚合与分桶）。 |
| **全局** | **不允许**跨场景混用 **`sourceVersion`** 或把 Sim 载荷字段当作真实聊天观测字段。 |

---

## 12. 红线

- **不**跨场景混用参数或同一 JSON 形状表示不同语义。  
- **不**在匹配阶段使用「真实聊天」观测参数替代 RRM-Sim 输入。  
- **不**在聊天阶段把 **RRM-Sim** 输出表述为 **真实关系**已发生的结果。  
- **不**让 LLM **自由决定 A**（advancement intensity 须符合场景表与校验）。  
- **不**直接覆盖 **`MatchResult.candidateUserId`**。  
- **不**改 **`finalScore`**。  
- **不**让 Assistant **自动发送消息**。  
- **不**让 Timeline **自动改画像**。  
- **不**让 Feedback **自动改 final decision**。  
- **不**暴露 RRM **公式**、**raw score**、**另一候选人**敏感对比信息。
