# M5.6-B8-A — Independent Dry-run Poller Plan（RRM Top2 Hook Job）

> **范围**：**设计文档 only（B8-A）**。规划如何实现 **independent dry-run poller**。**本轮不写代码**、**不接** `apps/worker/src/main.ts`、**不**启动自动轮询、**不** apply、**不**改 Prisma schema / migration。文档不含真实业务 id、token、`DATABASE_URL`。

---

## 1. 一句话结论

**B8-A** 只规划 **independent dry-run poller**。poller **应复用** M5.6-B7-B 的 **shared apply service** 的 **dry-run aggregate**（`processRrmTop2HookJobsDryRunAggregate` 及既有 `processRrmTop2HookJobDryRun` 路径），**不复制** pending 扫描、聚合与 viewer-safe 输出逻辑。

---

## 2. 当前基础

| 项 | 说明 |
|----|------|
| **Hook job schema** | 已有（`MatchResultRrmTop2DisplayHookJob` 等）。 |
| **Hook job helper** | 已有（`rrm-top2-hook-job.service.ts`：`findPending`、`mark*` 等）。 |
| **B5 apply runner** | 已有；受控 apply gate；已委托 shared service。 |
| **Shared apply service** | 已有（`rrm-top2-hook-job-apply.service.ts`）：含 **dry-run aggregate** 与 **apply batch**。 |
| **B4B** | Controlled **consumer** runner 已可 **手动** 对 pending jobs 做 **dry-run**（与 B5 编排形态不同，但语义上同属「显式触发、可控」）。 |
| **自动 / 半自动 poller** | **尚未**存在；无独立进程按周期仅做 dry-run 聚合输出。 |

---

## 3. Poller 目标

| 目标 | 说明 |
|------|------|
| **读取 pending** | **周期性**或 **单次**读取 pending hook jobs（上限由 `limit` 或 env 约束）。 |
| **调用路径** | 调 **shared service** 的 **dry-run path**（`processRrmTop2HookJobsDryRunAggregate`），内部仍用 `processRrmTop2HookJobDryRun`。 |
| **输出** | **Aggregate-safe JSON**（与 B5-B dry-run 形态对齐：`totalJobsRead`、`wouldProcessCount`、`wouldSkipCount`、`noOpReasonCounts`、`writerOkCount`、`writerNoOpCount`、`items[]` 等；**不**输出真实业务 id）。 |
| **不写 meta** | **不**调用 `writeRrmTop2DisplayMetaForMatchResult` 的 **非 dryRun** 路径；dry-run 内 writer 若存在仅为其 dry 语义。 |
| **不写 summary** | **不**写 `matchInsights` 内 RRM summary。 |
| **默认不写 HookJob 状态** | **默认**不 `markProcessing` / `markProcessed` / `skipped` / `failed`；若未来单独增加「仅审计用的 dry-run 记录」须在后续里程碑 **显式** 设计，**非 B8-A 范围**。 |
| **不接 GET** | **不**扩展或修改 GET `/matching/result` 等只读 API 来驱动 poller。 |

---

## 4. 为什么先 dry-run

1. **防止自动写入风险**：在未有 staging apply（B9）与强 gate 前，避免任何隐式 apply。  
2. **验证 pending job 流量**：观察队列深度与来源是否稳定。  
3. **观察 no-op 分布**：`noOpReasonCounts`、单项 `wouldSkip` / `wouldProcess` 便于调参与排障。  
4. **验证 shared service 复用**：证明 poller 与 B5 CLI **同一路径**，避免分叉。  
5. **为 B9 staging apply 做准备**：先有可观测的 dry-run，再开受控 apply。

---

## 5. 运行方式（建议）

**建议先做** dev-cli / **手动触发** 形态的 poller（与 B7-A Option B 一致），例如：

- **脚本 / 包名示意**：`m56-b8:rrm-top2-hook-job-dry-run-poller`（具体路径与 npm script 在 **B8-B** 实现时确定）。  
- **参数（建议）**：  
  - `--limit=<N>`（默认与上限在实现文档中约束，例如默认 5、上限与 B5 类似可单独定义）  
  - `--once`：执行 **一轮** 后退出（无常驻循环）  
  - `--pretty`：JSON 美化输出  
- **不支持 `--apply`**：本 poller **仅** dry-run；apply 仍仅走 B5-B（或未来 B9）受控路径。  
- **`NODE_ENV=production`**：**拒绝执行** 或要求 **额外显式 env**（例如 `PEIMA_M5_RRM_TOP2_HOOK_POLLER_ALLOW_PRODUCTION=1`），具体策略在 **B8-B** 与运维约定；**B8-A 只记录选项**，不实现。

## 7. 与 B4B 的区别

| | **B4B** | **B8 dry-run poller** |
|--|-----------|------------------------|
| **定位** | Controlled **consumer** runner（手动、与 consumer 验证强相关）。 | **Future worker/poller 形态** 的前置、**独立** dry-run 入口。 |
| **演进** | 偏「单次诊断 / 回放 consumer」。 | 偏「可重复观测 pending + 聚合」；未来可接 interval（仍先 dry-run）。 |
| **复用** | 与 B8 **均应**通过 **shared service** dry-run aggregate **复用**同一套逻辑，**避免**两套手写 `findPending` + 聚合分叉。 |

---

## 8. 安全边界（永远不改 / 不做）

以下 **永远**不因本 poller 而修改或写入（与 B5/B7 不变量一致）：

- **`MatchResult.candidateUserId`**  
- **`MatchResult.finalScore`**  
- **worker ranking**（既有 ranking 管线）  
- **`PairwisePoolFinalizeMeta`**  
- **user profile**  
- **chat messages**  

**GET** 保持 **只读**；poller **不**依赖、**不**修改 GET 响应语义。

---

## 9. B8-B 最小实现建议（下一里程碑，非本轮）

1. **新增** independent **dry-run poller CLI**（dev-cli 或等价入口）。  
2. **复用** `processRrmTop2HookJobsDryRunAggregate`（传入 `prisma`、`limit`、`sourceVersion` 与可选 deps 注入以便测试）。  
3. **不支持** `--apply`。  
4. **不写** HookJob 状态（不调用 `mark*`）。  
5. **不**在 `apps/worker/src/main.ts` **自动注册** poller。  
6. **单测**：无 DB 写路径（或 mock 断言无 `mark*`）、无 apply、聚合 JSON 字段与「无 pending 时 `totalJobsRead=0`」等。

---

## 10. Run Record（B8-C 建议记录）

**B8-C**（run record 文档）宜记录：

- **无 pending**：`totalJobsRead === 0`，其余计数为 0 或空聚合。  
- **有 pending**：`totalJobsRead > 0`，`wouldProcessCount` / `wouldSkipCount`、`noOpReasonCounts` 分布。  
- **明确**：本轮 **不写库**（无 meta、无 summary、无 HookJob 状态变更）。

---

## 11. 验收标准（B8 系列对齐）

- **不接 GET**（不扩展 `/matching/result` 等驱动 poller）。  
- **不接** `apps/worker/src/main.ts`（B8-B 亦不默认注册）。  
- **不支持 apply**（dry-run poller 无 `--apply`）。  
- **复用 shared service**（`processRrmTop2HookJobsDryRunAggregate`）。  
- **`candidateUserId` / `finalScore`** 不变。
