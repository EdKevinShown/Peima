# M5.6-B4 — RRM Top2 Hook Job Consumer (Dry-run Foundation)

> **范围**：在应用层实现 **hook job → display meta writer** 的 **dry-run 决策**（`processRrmTop2HookJobDryRun`）。**不**自动注册 worker、**不**开启轮询、**不**写 `MatchResultRrmTop2DisplayMeta`、**不**写 `matchInsights.rrmSimReadonlySummary`、**不**改 `MatchResult.candidateUserId` / `finalScore`。本文不含真实业务 ID、token、`DATABASE_URL`。

## 1. 行为摘要

| 项 | 说明 |
|----|------|
| **入口** | `apps/api/src/modules/matching/rrm-top2-hook-job-consumer.ts` → `processRrmTop2HookJobDryRun` |
| **Writer 调用** | 仅当预检通过时调用 `writeRrmTop2DisplayMetaForMatchResult`，且 **强制** `dryRun: true`、`summaryWriteEnabled: false`（默认）；`metaWriteEnabled` 默认 `true`（可由入参覆盖，便于测试）。 |
| **Explicit pass guardrails** | 与 writer 一致：仅当 `status === "pass"` 且 `blockReasons` / `cautionReasons` 均为空数组时视为 pass。此时若已能加载 `MatchResult` 且 **缺少** 可解析的 `rrmSimReadonlySummary`，则 **不调用 writer**，直接 `wouldSkip` + `noOpReasonCode: rrm_summary_missing`（本轮不从 simulation job 构造 summary）。 |
| **非 pass guardrails** | 仍调用 writer dry-run（例如 `guardrails_invalid`），不依赖 summary 预检。 |
| **DB** | **不**更新 hook job 状态；**不** `matchResult.update`；**不** `matchResultRrmTop2DisplayMeta.upsert`。 |

## 2. Snapshot / Guardrails 解析

- **Top2**：从 `staticTop2Snapshot` 读取 `candidateUserIds`（优先）或兼容 `top2` 数组；需 **两个非空且互异** 的 id，否则 `static_top2_missing` / `top2_invalid` / `top2_duplicate`。  
- **Guardrails**：需可解析为 `RrmTop2DisplayMetaGuardrailsV1`；否则 `guardrails_missing`。

## 3. 与 B3 controlled runner 的关系

- **B3**：只负责 **创建 / 复用** hook job 行。  
- **B4**：在 **已有 job 行 + MatchResult 上下文** 下，对 writer 做 **dry-run 预演**。  
- **下一步（B4B / B5）**：controlled runner、**apply** 门闸、真实 worker consumer 与状态迁移等 **不在** 本里程碑。
