## 5. Round B — B5-B controlled apply（`--apply` + `--confirmControlledApply=I_UNDERSTAND`）

| 字段 | 实测值 |
|------|--------|
| `refused` | `false` |
| `mode` | `apply` |
| `apply` | `true` |
| `totalJobsRead` | `1` |
| `processedCount` | `0` |
| `skippedCount` | `1` |
| `failedCount` | `0` |
| `noOpReasonCounts` | `{ "writer_disabled": 1 }` |
| `items[0].outcome` | `skipped` |
| `items[0].noOpReasonCode` | **`writer_disabled`**（非 `existing_meta_frozen`） |

**结论**：

- 已执行 **`pending` → `processing` → `skipped`** 状态迁移（单条 job 消费完毕）。  
- **未**进入 `processed`（`processedCount = 0`）。  
- **未**写新的 `MatchResultRrmTop2DisplayMeta`（writer 在 env 关闭时直接 `writer_disabled`，与 B5-B「**不绕过** `PEIMA_M5_RRM_TOP2_META_WRITE_ENABLED`」一致）。  
- **未**改 `MatchResult.candidateUserId` / `finalScore`（writer 未做 apply 写入侧车 meta）。  

**与 Round A 的 `noOpReasonCode` 差异说明**：

- **Dry-run** 路径仍可能使用 consumer 内对 `metaWriteEnabled` 的默认，从而命中 **`existing_meta_frozen`**。  
- **Apply** 路径对 `writeRrmTop2DisplayMetaForMatchResult` **不传** `metaWriteEnabled`，完全依赖 **env**；当 meta write env 为 off 时，writer 在检查 frozen 侧车 **之前**即返回 **`writer_disabled`**，故落库 skip 原因为 **`writer_disabled`**。行为符合设计；若要在 apply 下复现 `existing_meta_frozen`，需 **打开** `PEIMA_M5_RRM_TOP2_META_WRITE_ENABLED` 且仍存在 frozen meta。
