## 1. 一句话结论

RRM **只有一套 Core Formula**，但 **不是**每个产品模块都直接运行它。正确结构是：

```text
Layer 1 — RRM Core Formula     （仅当 C、A 可稳定定义时求 RFI）
Layer 2 — RRM Signal Adapter   （从各模块提取 S/E/F/Q/D/R 等信号摘要）
Layer 3 — RRM Consumer         （只消费已有结果：解释、建议、观测、Eval；禁止重算 RFI）
```

当前仓库 **唯一完整 Core 实现** 仍是 **RRM-Sim**（`evaluateRrmSimFromSimulationV2`）。Pairwise、Feedback、Eval、Explanation、Admin 观测 **不得**冒充 Sim 公式输出。

---

## 2. 为什么不能「每个功能一个公式」

早期草案为不同模块各写一套加权分（例如 `PairwiseDecisionScore = …`、`ObservedRhythmScore = …`），会导致：

- 理论不统一（都叫 RRM 却不共用 C/A/S/E/F/Q/D/R 语义）；
- 或强行套 Core 却在 **无稳定 A/C** 的场景下产生伪精度。

**Core Formula 的前提**必须能回答：

1. 当前推进强度 **A** 是多少？  
2. 当前关系容量 **C** 能承受到哪？

无法满足的模块 → **Signal Adapter** 或 **Consumer**，不直接跑完整 RFI。

## 3. Layer 1 — RRM Core Formula

### 3.1 使用条件

- 可定义 **C**（关系容量）与 **A**（推进强度，**离散分桶**，非 LLM 自由浮点）。  
- 可定义 **S / E / F / Q / D / R** 及 `sourceVersion`。  
- `fallback` / `insufficient_data` 规则明确。

### 3.2 分段公式（全仓库唯一数学形态）

**正常推进**（`A ≤ C`）：

```text
RFI = S × E × A + F × Q − D
```

**越界推进**（`A > C`）：

```text
P = 1 + (1 − S) + (1 − E) + R
RFI = F × Q − D − (A − C) × P
```

实现：`apps/api/src/modules/ai-simulation-v1/rrm-sim-formula.ts` → `computeRfiScenario`。

### 3.3 当前直接适用（已实现）

| 模块 | 说明 |
|------|------|
| **RRM-Sim** | `A_scenario` 绑定 `RRM_SCENARIO_APPROACH_INTENSITY`；入口 `evaluateRrmSimFromSimulationV2` |

### 3.4 有条件 Core 形态（M5.1 r5～r9 已落地部分）

| 模块 | M5.1 轨道状态 | 说明 |
|------|---------------|------|
| **RRM-Observed** | **r5–r6 DONE** | v1 仅 `S_obs`…`R_obs` signal summary；**无** `RFI_obs`（见 [future](./M5.1-future-core-formula-update-recommendations.md)） |
| **RRM-Assistant** | **r7–r8 DONE** | 非推进 → 语气建议；推进草稿 → `ActionFit`（`computeRfiScenario` 同形） |
| **RRM-Timeline** | **r9 DONE** | 默认趋势；推进窗口 → `RFI_t`（HTTP 仅 `rhythmBand`） |

## 4. Layer 2 — RRM Signal Adapter

Adapter **不**产出最终匹配决策；输出结构化摘要，例如：

- `RrmObservedSignalSummary`（`rrm-observed-v1`）  
- `RrmAssistantActionSignal`（`rrm-assistant-v1`）  
- `RrmTimelineSignalSummary`（`rrm-timeline-v1`）

**规则摘要**（详见 M5.0 §5–7）：

| 模块 | v1（已交付） | 后续 |
|------|-------------|------|
| **RRM-Observed** | `S_obs`…`R_obs`、`advancementDetected`、`insufficient_data` | 推进窗口 `RFI_obs`（未实现） |
| **RRM-Assistant** | 非推进语气建议；推进 → `ActionFit` | 可选 Sim hint 接线 |
| **RRM-Timeline** | `stage`、`paceTrend`、`coldRisk`…；推进窗口 `RFI_t` | Kalman / EMA 趋势（future doc） |

---

## 5. Layer 3 — RRM Consumer

Consumer **禁止**重新计算 RFI。只读消费 Sim / Adapter 摘要或聚合计数。

| Consumer | 职责 | 仓库锚点 |
|----------|------|----------|
| **Final Match Explanation** | 解释推荐与 caution | M6 display / meta |
| **M4.0 ranking proposal** | 只读「若仅按 RRM 重排」 | `buildRrmRankingProposal` |
| **Admin / P7.11 observability** | 管线健康聚合 | `matching-observability` |
| **RRM-Eval** | 脱敏聚合验证 Outcome ~ 信号 | `GET /admin/rrm-eval/aggregate` · `rrm-eval-v1` |

**禁止**：改 `MatchResult`、改 `finalScore`、改 worker 主排序、自动发消息、暴露 raw 公式向量给终端用户。

## 6. 模块总表（与 docx §4 / §14 对齐）

| 模块 | 直接用 Core？ | 定位 |
|------|-------------|------|
| **RRM-Sim** | **是** | 唯一正式 Core 实现 |
| **Pairwise** | **否** | Comparator（Preference + Safety + Compatibility − Risk − Uncertainty） |
| **RRM-Observed** | 有条件 | 默认 Signal Summary；推进事件才 RFI_obs |
| **RRM-Assistant** | 有条件 | 默认建议；草稿推进才 ActionFit |
| **RRM-Timeline** | 有条件 | 默认趋势；推进窗口才 RFI_t |
| **Feedback** | **否** | 校准 / outcome 信号 |
| **RRM-Eval** | **否** | 聚合指标（成功率、ObservedVsSimDelta…） |
| **Final Match Explanation** | **否** | Consumer |
| **Admin Observability** | **否** | Consumer |

### 6.1 Pairwise 特别说明

详见 **[M5.1-pairwise-comparator-spec.md](./M5.1-pairwise-comparator-spec.md)**（commit 4）。摘要：Pairwise **没有稳定 A**；禁止 `RFI = S×E×A+…`；`sourceVersion` = `rrm-lite-pairwise-decision-v1`（`rrm-shared`）；**不** `import evaluateRrmSimFromSimulationV2`。
