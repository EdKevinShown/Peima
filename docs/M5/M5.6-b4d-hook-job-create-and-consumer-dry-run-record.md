# M5.6-B4D — Hook Job Create + Consumer Dry-run Validation Record

> **性质**：本地串联验证 **M5.6-B3**（controlled hook job create runner）与 **M5.6-B4B**（pending consumer dry-run runner）的非敏感记录。不含真实 `userId` / `candidateUserId` / `matchResultId` / `hookJobId`、不含 token / API key / `DATABASE_URL`。

## 1. 元数据

| 项 | 值 |
|----|-----|
| **记录类型** | 本地验证手记（B4D） |
| **涉及里程碑** | B3 controlled create runner；B4B consumer dry-run runner |
| **参考文档** | `docs/M5/M5.6-b3-rrm-top2-hook-job-controlled-runner.md`、`docs/M5/M5.6-b4b-rrm-top2-hook-job-consumer-runner.md` |

---

## 2. 步骤一 — B3 dry-run（创建 hook job 预览）

在本地使用 B3 runner **默认 dry-run**（未传 `--apply`），输出摘要如下（字段级，无 id）：

| 字段 | 值 |
|------|-----|
| `mode` | `dry_run` |
| `apply` | `false` |
| `created` | `null` |
| `status` | `pending`（预演语义，非落库行） |
| `sourceVersion` | `m5.6-b3-rrm-top2-hook-job-v1` |
| `guardrailsStatus` | `pass` |
| `candidateUserIdUnchanged` | `true` |
| `finalScoreUnchanged` | `true` |

**结论**：**未写 DB**；仅预览将创建的 hook job 语义。

---

## 3. 步骤二 — B3 apply（创建 pending hook job）

在同一流程下传入 **`--apply`**，输出摘要：

| 字段 | 值 |
|------|-----|
| `mode` | `apply` |
| `dryRun` | `false` |
| `apply` | `true` |
| `created` | `true` |
| `status` | `pending` |
| `sourceVersion` | `m5.6-b3-rrm-top2-hook-job-v1` |
| `guardrailsStatus` | `pass` |
| `candidateUserIdUnchanged` | `true` |
| `finalScoreUnchanged` | `true` |

**结论**：在目标库中 **创建了一条** `MatchResultRrmTop2DisplayHookJob` 行（`status = pending`）。**不在此记录真实 `hookJobId`。**

**重要说明**：B3 apply **只**负责创建 / 幂等复用 **hook job 行**；**不代表** RRM 展示已对终端用户生效（展示仍依赖后续 consumer + writer 等链路，见 B3 文档）。

---

## 4. 步骤三 — B4B consumer dry-run（pending 枚举 + writer dry-run）

在表已迁移、且存在上述 pending hook job 的前提下，运行 B4B consumer dry-run runner，聚合输出摘要：

| 字段 | 值 |
|------|-----|
| `mode` | `dry_run` |
| `totalJobsRead` | `1` |
| `wouldProcessCount` | `0` |
| `wouldSkipCount` | `1` |
| `noOpReasonCounts` | `{ "existing_meta_frozen": 1 }` |
| `writerOkCount` | `0` |
| `writerNoOpCount` | `1` |
| `candidateUserIdUnchangedAll` | `true` |
| `finalScoreUnchangedAll` | `true` |

**逐条摘要（`items`，无 id）**：

- `index = 0`：`wouldSkip = true`，`noOpReasonCode = existing_meta_frozen`。

**结论**：

- B4B **仅 dry-run**：**不**写 `MatchResultRrmTop2DisplayMeta`、**不**写 `matchInsights` 内 `rrmSimReadonlySummary`、**不**改 HookJob `status`、**不**改 `MatchResult.candidateUserId`、**不**改 `finalScore`。  
- **`existing_meta_frozen` 为安全 no-op**：对应 `MatchResult` 上已存在 **frozen** 的 RRM Top2 display meta 侧车时，writer 按设计 **不会**覆盖已有 frozen meta；consumer dry-run 与 writer 一致地判定跳过，避免破坏已冻结展示。

---

## 5. 不变量核对（三步合计）

| 项 | 结论 |
|----|------|
| **`candidateUserId` / `finalScore`** | **未改**（B3 / B4B 设计均不修改） |
| **B3 apply 与 RRM 展示生效** | **不等价**；仅创建 pending outbox 类职责的 hook job 行 |
| **B4B 与 apply writer** | **不等价**；本轮无 meta / summary 持久化、无状态迁移 |
