## 1. 一句话结论

**Pairwise 是 Top2 比较器（Comparator）**，在 **20D 静态 shortlist 的 2 人** 之间做 LLM 辅助的 **相对适配** 决策；**不是** RRM-Sim Core Formula，**不**产出 `RFI = S×E×A + F×Q − D`，**不**调用 `evaluateRrmSimFromSimulationV2`。

与 **P7.6 Stage 3 RRM Top2 selector** 的关系：P7.6 shadow 描述的是 **关系节奏 2 选 1** 的 **未来/并行观测**；当前生产 Pairwise 链路由 **M3.8** 落地（finalize / display），二者 **sourceVersion 与契约分离**，禁止混称为「完整 RRM 公式输出」。

## 3. 契约：输出什么（与代码对齐）

权威类型：`apps/api/src/modules/ai-pairwise-decision/ai-pairwise-decision.types.ts`

### 3.1 概念映射（Comparator 语义）

| 设计报告字段 | 实现字段 | 说明 |
|--------------|----------|------|
| `pairwisePreferredCandidate` | `winnerCandidateId` | LLM 相对更优候选人 |
| `confidence` | `decisionConfidence` | `0–1`；低于阈值 → static fallback（见 proposal） |
| `safetyFlags` | `candidate*.strongRisk`、`dimensions.riskControl` | 强风险 → fallback 策略 |
| `riskFlags` | `majorRisks`（shortlist 侧）、`strongRisk` | 来自 shortlist + 决策块 |
| `reasonCodes` | `decisionReason`、`reasonSummary`（候选块） | 用户可读摘要，非公式向量 |
| `displayCandidateSuggestion` | `buildPairwiseFinalMatchProposal` → `candidateUserId` | **proposal_only**；见 §4 |
| `sourceVersion` | `sourceVersion: "rrm-lite-pairwise-decision-v1"` | 登记在 `rrm-shared`；**≠** `rrm-sim-v1` |

### 3.2 比较器结构（文档公式，非代码中的 RFI）

设计层表达（**不**写入 TypeScript 求值）：

```text
PairwiseComparator(i) =
  PreferenceSignal_i
  + SafetySignal_i
  + CompatibilitySignal_i
  − RiskSignal_i
  − UncertaintyPenalty_i
```

实现上体现为 **六维 LLM 分**（`conversationFit` … `riskControl`）与 **`decisionScoreA/B`**，而非 C/A/S/E/F/Q/D/R 闭环。

### 3.3 冻结字段（M3.8）

| 字段 | 值 |
|------|-----|
| `schemaVersion` | `1` |
| `sourceVersion` | `rrm-lite-pairwise-decision-v1` |
| `appliedToFinalScore` | `false` |
| `appliedToWorkerRanking` | `false` |

## 4. 下游 Consumer（已接通，非独立）

| Consumer | 路径 | 行为 |
|----------|------|------|
| **Final match proposal** | `ai-pairwise-final-match-proposal.ts` | `PairwiseFinalMatchProposal`，`mode: "proposal_only"` |
| **Finalize meta** | `POST /matching/finalize-with-pairwise`（M11+） | 写 `pairwise_pool_finalize_meta`；**不改** `MatchResult.candidateUserId` 语义见 M3.8 |
| **Display** | `resolveMatchResultDisplay` / M13 | `displayCandidateUserId`、`displaySourceType` |
| **P7.11 观测** | `matching-observability` pairwise 段 | 计数 status / fallback / `sourceVersion` 分布 |
| **M4 三路对照** | M4.1 计划 | Pairwise 与 Static / RRM-Sim **分栏**展示 |

**禁止 Consumer 行为**：对 Pairwise job 再跑 `evaluateRrmSimFromSimulationV2` 并把结果标为 Pairwise 输出。

---

## 5. 明确不做什么

- **不**使用 `RFI = S × E × A + F × Q − D` 或 `computeRfiScenario`。  
- **不** `import` / 调用 `evaluateRrmSimFromSimulationV2`（守卫：`apps/api/test/rrm-sim.evaluator.spec.ts`）。  
- **不**让 LLM 自由生成浮点 **A_pair**（当前契约 **无** A）。  
- **不**改 worker `batch-match` 主排序或 `MatchResult.finalScore`。  
- **不**将 `sourceVersion` 标为 `rrm-sim-v1`（`assertAdapterSourceVersionNotCoreSim` 约束的是未来 Adapter 层；Pairwise 已用独立 version）。

---

## 6. 与 RRM-Sim 的边界

| 维度 | RRM-Sim | Pairwise |
|------|---------|----------|
| 输入 | `AiSimulationLlmPayloadV2` + optional staticContext | `RelationshipShortlistTop2` + LLM |
| 候选数 | 模拟 shortlist（多候选） | **固定 2** |
| 输出 | `RrmSimResult`（C_pred, scenarioScores, …） | `AiPairwiseDecision` |
| Core Formula | **是** | **否** |
| 影响 display | 仅只读 sidecar / M4.0 提案 | finalize enabled 时可影响 **display** |

同一 viewer 可同时存在 **completed simulation job**（Sim）与 **succeeded pairwise job**；读路径须按 **`sourceVersion`** 区分，不得合并为一条「RRM 分」。

---

## 7. 未来：若接入 Core Formula（前置条件）

在 **任何**「Pairwise 跑 RFI」之前，必须：

1. 定义 **固定 pairwise scenarios**（类似 `RRM_SCENARIO_KEYS_ORDERED`）。  
2. **`A_pair` 离散分桶**（禁止 LLM 浮点 A）。  
3. **shadow** 对比 `winnerCandidateId` vs RRM Top2 selector vs 20D-only。  
4. 新 `sourceVersion`（例如 `rrm-pairwise-core-v1`）写入 **rrm-shared registry**，**不得**覆盖 `rrm-lite-pairwise-decision-v1` 历史 job。

在此之前：**维持 Comparator 定位**。
