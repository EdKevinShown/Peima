# M5.6-A — RRM Top2 Hook Outbox Schema Plan

> **范围**：仅设计文档。规划 **durable outbox / hook job 表**，用于安全承接 RRM Top2 automatic hook。**不写业务代码**、**不改 Prisma schema**、**不新增 migration**。本文不出现真实 `userId` / `candidateUserId` / `matchResultId`、token、API key、`DATABASE_URL`。

---

## 1. 一句话结论

为了避免 **`matchResultId` ↔ RRM job ↔ Static Top2 ↔ `top2Fingerprint`** 在自动化链路中 **错绑**，需要引入 **durable outbox / hook job 表**（建议物理表名 **`match_result_rrm_top2_display_hook_jobs`**，见 §3）。该表把 **writer intent** 与 **审计状态** 固化为数据库真值，使异步 consumer 不再依赖 **`latest MatchResult`** 等启发式（与 `M5.5-m6a` 扫描结论一致）。

---

## 2. 为什么需要 outbox

- **`AiSimulationV1Job` 没有 `matchResultId`**：simulation / job 完成态无法单独锁定「应对哪一条 `MatchResult` 写侧车」。
- **`MatchResult` 没有 `poolId`**：无法从结果行 **一键**反查「匹配当时」的池上下文。
- **Static Top2 没有与 `matchResultId` 的一列式绑定**：真源分散在 pairwise / finalize / binding 等路径，编排错误即 **展示侧车绑错行**（见 `M5.5-m6a` §4）。
- **`latest MatchResult` 推断** 在 **rematch、多批次、重跑** 场景存在 **错绑** 风险。
- **`existing_meta_frozen`（writer 内）** 只能 **防覆盖** `MatchResultRrmTop2DisplayMeta`，**不能**表达 **`pending` / `skipped` / `failed` / 有限重试（`failed` → `pending`）** 等 **工作流状态**。
- 需要 **`noOpReasonCode`、`processedAt`、`attempts`、`sourceVersion`** 等 **审计字段**，以及 **`lockedAt` 租约** 支撑并发消费与回放。

---

## 3. 建议表名

**物理表名（`@@map`）**：`match_result_rrm_top2_display_hook_jobs`  

**Prisma model 名（建议）**：`MatchResultRrmTop2DisplayHookJob`（与既有 `MatchResultRrmTop2DisplayMeta` 命名风格对齐）。

---

## 4. 新表职责

- 记录 **单条 `MatchResult`** 的一次 **RRM Top2 display writer intent**（可有多行历史，由 **唯一键** 控制幂等创建）。
- **持久化** 与 writer 输入对齐的 **Static Top2 snapshot** + **`top2Fingerprint`**（禁止在 consumer 内重算 shortlist 冒充 frozen，见 `M5.5-m5` / `M5.5-m6a`）。
- 记录 **RRM summary** 的来源说明（**`rrmSummarySourceVersion` 可空**；实际 payload 可由行内 JSON 或「仅引用 job 侧车 + consumer 构造」策略在 M5.6-B 定稿）。
- 记录 **`RrmTop2DisplayMetaGuardrailsV1` 形状的 explicit guardrails**（见 `rrm-top2-display-meta.types.ts`），**不**用 `matchInsights.explanation.cautions` 顶替。
- 管理 **`pending` → `processing` → `processed` | `skipped` | `failed`** 状态机（§8）。
- 支持 **幂等创建**、**有限重试**、**人工 replay**（§7、§10）。

---

## 5. 建议字段

### 5.1 必选（最小闭环）

| 字段 | 类型（概念） | 说明 |
|------|----------------|------|
| `id` | 主键 | 标准 cuid / uuid。 |
| `matchResultId` | FK → `MatchResult.id` | **durable 锚点**；consumer 加载 `MatchResult` 行。 |
| `viewerUserId` | FK → `User.id` | 与 `MatchResult.userId` **应一致**；实现阶段可加校验约束或应用层断言。 |
| `sourceVersion` | `String` | **hook job 契约世代**（区别于 meta JSON 内 `sourceVersion`）；参与 **唯一键**（§7）。 |
| `status` | `String`（枚举） | `pending` / `processing` / `processed` / `skipped` / `failed`（§8）。 |
| `staticTop2Snapshot` | `Json` | **只存 viewer-safe** 的两枚 `candidateUserId` 与必要契约元数据（如 rank、schema 版本指针）；**禁止** raw transcript / prompt / 公式细节。 |
| `top2Fingerprint` | `String` | 与 snapshot / summary **绑定**；与 **`validateRrmTop2DisplayEligibility`**（`rrm-top2-display-eligibility.ts`）一致。 |
| `rrmSourceType` | `String` | 例如 `ai_simulation_v1_job` / `pairwise_job` / `manual_controlled` 等（实现轮收敛枚举）。 |
| `rrmSourceId` | `String?` | 对应上游 job **主键**；无则空。 |
| `rrmSummarySourceVersion` | `String?` | 计划写入的 **`rrmSimReadonlySummary.sourceVersion`** 或等价标签；若 summary 仅由 consumer 现场构造，可记录 **目标 allow-list 版本**。 |
| `guardrails` | `Json` | **`RrmTop2DisplayMetaGuardrailsV1`** 显式快照；**仅** structured summary，**不**存 raw risk 向量、**不**存 prompt。 |
| `noOpReasonCode` | `String?` | **终态**或 **skipped** 时记录 writer / 前置校验的 **规范化原因**（§11）。 |
| `attempts` | `Int` | 已尝试处理次数（含 `processing` 开始即 +1 的策略由实现定义）。 |
| `lastErrorCode` | `String?` | **短枚举**，如 `db_error` / `unexpected` / `parse_error`。 |
| `lastErrorMessage` | `String?` | **必须 sanitized**：截断、剥离堆栈中的路径与密钥、**禁止**原始 LLM 文本。 |
| `lockedAt` | `DateTime?` | **乐观锁 / 租约**；超时回收策略在 M5.6-B 定义。 |
| `processedAt` | `DateTime?` | **终态**时间戳。 |
| `createdAt` / `updatedAt` | `DateTime` | 常规审计列。 |

### 5.2 可选（推荐用于审计与回放）

| 字段 | 说明 |
|------|------|
| `aiSimulationJobId` | 可空；若加 FK，指向 **`AiSimulationV1Job.id`**（schema 已存在 `@@map("ai_simulation_v1_jobs")`）。 |
| `pairwiseJobId` | 可空；若加 FK，指向 **`AiPairwiseDecisionJob.id`**（`ai_pairwise_decision_jobs`）。 |
| `poolId` | 可空；**编排上下文**，非 `MatchResult` 真源列。 |
| `batchId` | 可空；指向 **`MatchBatch.id`**，便于按批次排障。 |
| `metaWriteResult` | `Json?` | **viewer-safe** 摘要：`ok`、`wroteMeta`、`wroteSummary`、`displayCandidateUserId`（若策略允许）、`writerSourceVersion` 等；**禁止** raw payload。 |
| `auditMeta` | `Json?` | **viewer-safe** 扩展：consumer 版本、部署标识、上游事件 id 等。 |

### 5.3 字段安全强调

- **`staticTop2Snapshot`**：仅 **viewer-safe** 结构；**不**存问卷全文、**不**存聊天原文、**不**存可识别敏感自由文本（除非产品明确允许且脱敏）。
- **`guardrails`**：仅 **`RrmTop2DisplayMetaGuardrailsV1`** 显式结构；**不**与 `buildGuardrailsReadonly` 输出混用而不经映射（见 `M5.5-m6a` §6）。
- **`lastErrorMessage`**：**必须 sanitized**（长度上限、无 token、无连接串、无堆栈敏感路径）。

## 6. 关系 / FK

**建议**：

- **`matchResultId`** → **`MatchResult.id`**，`onDelete: Cascade`（或 `Restrict` + 业务选择；实现轮与法务对齐）。
- **`viewerUserId`** → **`User.id`**；建议 **应用层校验** `viewerUserId === matchResult.userId`。

**可选 FK**（本轮文档 **不强行定死**；若加 FK 需评估 **job 删除策略**）：

- **`aiSimulationJobId`** → `AiSimulationV1Job`（Prisma model 已存在）。
- **`pairwiseJobId`** → `AiPairwiseDecisionJob`（已存在）。

若跨 package / 迁移顺序复杂，**第一版可仅存 `rrmSourceType` + `rrmSourceId` 字符串**，不加 FK，由 **应用层** 保证引用完整性。

---

## 7. 索引与唯一键

**建议唯一约束**：

```text
@@unique([matchResultId, top2Fingerprint, sourceVersion])
```

**含义**：

- **同一** `MatchResult` + **同一** Top2 指纹 + **同一** hook 契约世代 → **至多一行 intent**，支撑 **create 幂等**（`upsert` 或 `create` + catch）。

**建议索引**：

- `@@index([status, createdAt])` — consumer **按创建时间升序**拉 `pending`（§10）。
- `@@index([viewerUserId, status])` — 用户维度排障。
- `@@index([matchResultId])` — 从结果反查 hook 历史。
- `@@index([rrmSourceType, rrmSourceId])` — 从上游 job 反查关联 hook 行（**稀疏**时可接受）。

**说明**：

- **`MatchResultRrmTop2DisplayMeta` 的 `existing_meta_frozen`** 仍为 **writer 侧第二道防线**；outbox **不替代** writer 不变量。
- **`status` + `createdAt`** 为 **轮询主路径**；`lockedAt` 配合 **跳过超时租约**。

## 8. 状态机

### 8.1 状态集合

| 状态 | 含义 |
|------|------|
| `pending` | 已入队，等待 consumer 领取。 |
| `processing` | 已租约锁定，正在执行读取 / writer。 |
| `processed` | **成功**调用 writer 且 **落库 meta（及可选 summary）** 达成预期终态。 |
| `skipped` | **稳定 no-op**（业务规则或 writer **skipped** 类结果）；**非**异常。 |
| `failed` | **异常**（DB、未捕获错误、**sanitized** 后仍判为不可恢复等）。 |

### 8.2 允许迁移

- `pending` → `processing` → `processed`
- `pending` → `processing` → `skipped`
- `pending` → `processing` → `failed`
- `failed` → `pending`：**有限次重试**（`attempts` 上限 + 死信策略；实现轮定义）。

### 8.3 语义说明

- **`skipped`**：用于 **guardrails 非 pass**、**Top2 缺失**、**summary 缺失**、**`writer_disabled`**、**`existing_meta_frozen`** 等 **预期内 no-op**（与 `matching-rrm-top2-display-meta-writer` 的 `noOpReasonCode` 对齐）。
- **`failed`**：用于 **异常路径**；**no-op 不等于 failed**。
- **`processed`**：表示 **hook 职责完成**；若 writer **dry-run** 策略在 future 出现，应在 M5.6-B **明确是否允许** `processed` 与 **零写库** 的组合（默认 **生产 consumer 不应 dry-run**）。

---

## 9. Job 创建时机

**候选来源**（可多阶段补全同一行或由多行合并策略在实现轮定稿）：

1. **`batch-match` 创建 `MatchResult` 之后**：仅插入 **lightweight** `pending` 行（**不**在同步尾部写 meta / summary）。
2. **RRM simulation / proposal 完成**：更新或关联 **`rrmSourceType` / `rrmSourceId` / `rrmSummarySourceVersion`**，或写入 **只读引用** 供 consumer 构造 summary。
3. **Pairwise / shortlist 完成**：写入 **`staticTop2Snapshot` / `top2Fingerprint` / `guardrails`**（若上游已能产出 explicit pass；否则保持缺省并由 consumer **skipped**）。
4. **Admin / M5.5-M4 controlled runner**：**手动创建**或 **replay** 指定 hook 行。

**第一版推荐**（与 `M5.5-m5` 一致）：

- **不在** `batch-match` **同步尾部**写 **`MatchResultRrmTop2DisplayMeta`** 或 **`matchInsights.rrmSimReadonlySummary`**。
- **优先**：**controlled 创建** hook job 行 + **异步 consumer** 处理 `pending`；待契约稳定后再接 **batch-match enqueue only**。

---

## 10. Consumer 行为（规范）

Consumer **轮询**（概念 SQL）：

- `status = 'pending'`
- `order by createdAt asc`
- `limit N`

**处理步骤**（顺序建议）：

1. **租约**：`pending` → `processing`，设置 **`lockedAt`**（或版本号）；超时租约回收为 `pending`（实现轮定义）。
2. **读取** `MatchResult`（**不改** `candidateUserId` / `finalScore`）。
3. **读取** 行内 **`staticTop2Snapshot`**，解析为 **两枚 distinct** `candidateUserId`，且 **包含** `MatchResult.candidateUserId`；否则 **`skipped`**。
4. **读取 / 构造** **`rrmSimReadonlySummaryPayload`**（若策略为「仅 DB 已有」则缺省 → **`skipped`**）；须满足 **`tryParseRrmSimReadonlySummaryPayloadV1FromMatchInsights`** 与 writer 模式约定。
5. **校验** **`guardrails`** 为 **explicit pass**（与 `isExplicitPassGuardrails` 语义一致）；否则 **`skipped`**。
6. 调用 **`writeRrmTop2DisplayMetaForMatchResult`**（`matching-rrm-top2-display-meta-writer.ts`）；**禁止复制**第二套写库逻辑。
7. 根据 writer 返回值与环境：写 **`processed` / `skipped` / `failed`**，填充 **`noOpReasonCode`、`processedAt`、`lastError*`**。
8. **永不**：改 **`MatchResult.candidateUserId`**、**`finalScore`**；**不**在 **GET** `/matching/result` 路径写库；**不**改 **RRM resolver** 纯函数契约（本里程碑不改代码，仅约束未来实现）。

---

## 11. No-op 映射

### 11.1 → `skipped`（稳定 no-op，预期内）

以下 **writer / 前置校验 no-op** 在 hook job 终态应记为 **`skipped`**（可与 `noOpReasonCode` 一一对应；若 writer 返回额外枚举，实现轮与 `RrmTop2MetaWriterNoOpReason` / `RrmTop2DisplayNoOpReasonCode` 对齐）：

- `writer_disabled`
- `static_top2_missing`
- `rrm_summary_missing`
- `guardrails_missing`
- `guardrails_caution`
- `guardrails_block`
- `guardrails_not_evaluated`
- `existing_meta_frozen`
- `rrm_confidence_low`
- `rrm_fallback_used`
- `selected_not_in_top2`

（实现时亦可合并 **`rrm_summary_invalid`**、**`summary_write_disabled`**、**`guardrails_invalid`**、**`guardrails_pass_predicate_failed`**、**`rrm_confidence_unknown`**、**`rrm_winner_not_in_top2`** 等与 writer 输出等价的码，统一落入 **`skipped`**。）

### 11.2 → `failed`（异常）

- **DB error**（连接、事务、未预期的约束违反等）。
- **parser unexpected exception**（解析 hook 行或上游 JSON 时的未捕获异常）。
- **unknown exception**（`lastErrorMessage` **仍须 sanitized**）。

---

## 12. 安全边界

**永远不改**：

- `MatchResult.candidateUserId`
- `MatchResult.finalScore`
- **worker ranking** 语义与持久化
- **`PairwisePoolFinalizeMeta`** 主语义
- **用户画像 / 问卷主数据**
- **chat message**（不自动代发）

**只允许写**（通过 **M5.5-M2 writer** 及其已允许的子 writer）：

- `matchInsights` 中的 **`rrmSimReadonlySummary`**（受控合并）
- **`MatchResultRrmTop2DisplayMeta`**
- **本 hook job 表** 的状态与审计字段

**`GET /matching/result`**：**必须只读**（不接 writer、不重跑 RRM）。

## 15. M5.6-B 最小实现建议（下一轮代码）

1. **Prisma schema + migration**：新增 **`match_result_rrm_top2_display_hook_jobs`**（或最终表名）及 §7 索引 / 唯一键。  
2. **类型与 parser**：对 `staticTop2Snapshot`、`guardrails`、`metaWriteResult` 做 **strict / loose** 分层（对齐现有 meta parser 风格）。  
3. **Repository / service helper**：create / claim / finish / sanitize error。  
4. **Controlled create-job runner**（dev/staging）：类似 `m55-m4`，**仅**插入 hook 行，不冒充生产全自动。  
5. **Consumer dry-run worker**：轮询 + **可**调用 writer 的 `dryRun: true` 验证链（实现轮二选一：**仅 DB 状态迁移** vs **真 writer dry-run**）。  
6. **不接 GET**；**不**自动全库 production apply。  
7. **测试**：状态机、**唯一键幂等**、`skipped` vs `failed`、**sanitized** `lastErrorMessage`、`existing_meta_frozen` 与 writer 联动。

## 16. 验收标准（M5.6-B）

- **migration** 成功应用。  
- **env off**：**不处理** pending（不领取、不写库）；或等价地 **领取后立即 `skipped` + `writer_disabled`** —— 实现轮二选一，须在 PR 写清。  
- **create hook job** 在唯一键下 **幂等**。  
- **`pending` → `processed` / `skipped` / `failed`** 路径可测。  
- **`noOpReasonCode` 映射** 与 §11 一致。  
- **已 frozen** 的 `MatchResultRrmTop2DisplayMeta` **不被覆盖**。  
- **`MatchResult.candidateUserId` / `finalScore` 不变**。  
- **GET 不写库**。  
- **PR / 文档不提交** 真实 ID、token、`DATABASE_URL`。
