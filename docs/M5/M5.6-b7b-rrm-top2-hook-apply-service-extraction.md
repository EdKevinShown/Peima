# M5.6-B7-B — Extract shared RRM Top2 hook apply service

## Summary

This milestone **extracts** the batch dry-run and apply orchestration from the M5.6-B5-B controlled CLI runner into a **shared module**:

- `apps/api/src/modules/matching/rrm-top2-hook-job-apply.service.ts`

The B5 dev-cli runner (`m56-b5-rrm-top2-hook-job-apply-runner.ts`) now **delegates** to that service for both default dry-run and gated `--apply` paths, so a future **B8** independent dry-run poller (per [M5.6-b7a-rrm-top2-hook-job-poller-design.md](./M5.6-b7a-rrm-top2-hook-job-poller-design.md)) can reuse the **same** apply path without copying B5 logic.

## What changed

- **New** shared service: find pending hook jobs, per-job `markProcessing` → writer → `processed` / `skipped` / `failed`, aggregates, no real business IDs in JSON aggregates (same policy as B5-B).
- **Dry-run** (`processRrmTop2HookJobsDryRunAggregate`): no `mark*` on hook jobs; uses `processRrmTop2HookJobDryRun`; aggregate fields aligned with prior B5-B JSON (`wouldProcessCount`, `wouldSkipCount`, `writerOkCount`, `writerNoOpCount`, etc.).
- **Apply** (`processRrmTop2HookJobsApplyBatch`, `applySingleRrmTop2HookJob`): real writes; **caller** must enforce apply gate (CLI `--apply` + `--confirmControlledApply=I_UNDERSTAND` remains in the runner only).

## Explicit non-goals (this milestone)

- **No** wiring in `apps/worker/src/main.ts`.
- **No** new automatic poller loop.
- **No** changes to GET `/matching/result` or other HTTP read paths.
- **No** Prisma schema or migrations.
- **No** change to persisted `MatchResult.candidateUserId` or `finalScore` (writer contract unchanged; runner still reports `candidateUserIdUnchangedAll` / `finalScoreUnchangedAll` as `true` for B5-C compatibility).
- **No** FinalMatchPage / ChatPage changes.

## CLI behavior

B5 runner **CLI flags, production refusal, dry-run default, apply confirmation requirement, limit clamp (1–10), and JSON shape** are intended to remain **compatible** with B5-B / B5-C run records; only the implementation location moved behind the shared service.

## Next step

**M5.6-B8** (or follow-on): independent dry-run poller that calls the shared service (or dry-run aggregate) from a worker-safe entry, still without duplicating B5 runner code.
