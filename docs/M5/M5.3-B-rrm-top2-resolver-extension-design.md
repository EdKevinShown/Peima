# M5.3-B — RRM Top2 Resolver Extension Design

**文档性质**：实现前 **resolver 扩展** 设计说明（**仅文档**；本轮 **不写代码**、不改 schema / env 样例文件）。  
**文档版本**：**v1.1** — Eligible 校验函数、`noOpReasonCode`、meta 存储方案、测试矩阵与验收标准收口（M5.3-C 进场就绪）。  
**上游规划**：[`M5.3-rrm-top2-enabled-display-plan.md`](./M5.3-rrm-top2-enabled-display-plan.md)（M5.3-A v1.4）。

---

## 1. 一句话结论

M5.3-B **只设计**如何在 **`apps/api/src/modules/matching/matching-result-display.ts`** 中 **扩展现有** M3.8-M13 **`resolveMatchResultDisplay`**：在 **`PEIMA_M5_RRM_TOP2_ENABLED`** 开启且 **§12 Eligible Rules**（见 M5.3-A）全部满足时，从 **已持久化的 RRM Top2 enabled meta** 读取展示决策，并返回 **`displayCandidateUserId`** 与 **`displaySourceType = "rrm_top2_bounded_selector"`**；否则 **fallback** 到现有 Pairwise finalize 分支或 **`match_result_original`**。**不**修改 `MatchResult.candidateUserId`、**不**修改 `finalScore`、**不在 GET 上重算** Top2 或 RRM evaluator（与 M5.3-A §10 一致）。**本轮不写代码。**

## 2. 当前 M3.8 resolver 行为（代码对齐）

实现位置：**`resolveMatchResultDisplay(prisma, matchRow)`**（`matching-result-display.ts`）。

| 步骤 | 行为 |
|------|------|
| 基准 | `original = matchRow.candidateUserId`（**永不**在本函数内改写行上字段）。 |
| Pairwise env | **`readPairwiseFinalizeEnv()`**（`pairwise-finalize-env.ts`）：`PAIRWISE_FINAL_MATCH_ENABLED === "1"` 且 **`PAIRWISE_FINAL_MATCH_MODE === "enabled"`** 才继续；否则 **立即** 返回 `{ displayCandidateUserId: original, displaySourceType: "match_result_original", finalMatchDecisionMeta: null }`（**不**查询 `pairwise_pool_finalize_meta`）。 |
| DB 读 | `pairwisePoolFinalizeMeta.findMany({ where: { viewerUserId: matchRow.userId, frozen: true }, orderBy: ..., take: 12 })`。 |
| Meta 解析 | **`parseFinalizeMetaV1Loose(row.meta)`**：`schemaVersion === 1`、`selected` / `staticTop1` 非空、`appliedTo*` 恒 `false`、`frozen === true`、`mode` ∈ `proposal_only` \| `shadow` \| `enabled`（解析层接受，但 **仅 enabled 产品路径** 会走到此前置条件）。 |
| Pool / baseline 绑定 | **`meta.staticTop1CandidateUserId === matchRow.candidateUserId`**；否则跳过该行（**不猜 poolId**，与注释一致）。 |
| `selected` 校验 | 非空；**`User`** 表存在；且 **`selected` ∈ { `staticTop1CandidateUserId`, `pairwiseWinnerCandidateUserId`（若非空）}**。 |
| 返回值 | **`displayCandidateUserId = selected`**；**`displaySourceType`** 由 **`mapDisplaySourceTypeFromMeta(meta, selected, original)`** 映射为 `pairwise_final` / `static_final` / `static_fallback`；**`finalMatchDecisionMeta`** 为 **`toViewerSafeFinalMatchDecisionMeta(meta)`**（`FinalMatchDecisionMetaV1` → `ViewerSafeFinalMatchDecisionMeta`）。 |
| 无命中行 | 返回 **`match_result_original`** + `finalMatchDecisionMeta: null`。 |

**写路径（本设计不展开实现，仅锚定语义）**：**`MatchingFinalizePairwiseService.finalizeWithPairwise`** 写入 **`PairwisePoolFinalizeMeta`**，**声明**不更新 **`MatchResult.candidateUserId` / `finalScore`**（`matching-finalize-pairwise.service.ts`）。Meta 构建：**`buildFinalMatchDecisionMetaV1`**（`final-match-decision-meta.builder.ts`）。

**GET 聚合**：**`MatchingService.getLatestResultForUser`** 调用 **`resolveMatchResultDisplay`** 后将字段 spread 进 **`MatchResultViewerPayload`**（`matching.service.ts`）；**`multiSourceFinalDecision`** 仍 **不参与** display 解析。

## 3. M5.3 resolver 新增能力（设计增量）

| 增量项 | 说明 |
|--------|------|
| **Env** | **`readM5RrmTop2DisplayEnv()`**（新模块，对齐 `readPairwiseFinalizeEnv` 风格）：至少包含 **`PEIMA_M5_RRM_TOP2_ENABLED`**（`"1"` / 其他视为 off）。可选：**`PEIMA_M5_RRM_TOP2_SOURCE_VERSION`**（meta / summary 契约 era）。 |
| **`displaySourceType`** | 扩展 **`MatchResultDisplaySourceType`**，新增 canonical：**`"rrm_top2_bounded_selector"`**（M5.3-A §15）。 |
| **Meta 形态** | **二选一（M5.3-C 前须拍板）**：**(A)** **`FinalMatchDecisionMetaV2`** 与 V1 并列新类型 + 新表或新 JSON 列；**(B)** **平行侧车表**（例如 `match_result_rrm_top2_display_meta`）存 RRM 专用 JSON，**`finalMatchDecisionMeta` GET 字段** 仍返回 **viewer-safe 联合投影**（V1 或 V2 或 **合成** 单一 `ViewerSafeFinalMatchDecisionMeta` 扩展 — **M5.3-C** 实现时二选一并单测）。推荐 **(B)** 避免污染 `pairwise_pool_finalize_meta` 语义。 |
| **Resolver 分支** | 在 **不触发 GET 重算** 前提下：按 **§4 优先级** 先尝试 **RRM Top2 enabled** 读路径；失败则 **现有 Pairwise 循环**；再失败则 **`match_result_original`**。 |
| **Fallback** | 全部 **§13** 条件映射为 **不应用 RRM 分支**，进入下一优先级（M5.3-A 已列）。 |

**与 `matchInsights` 的关系**：今日 **`rrmSimReadonlySummary`** 已约定写入 **`matchInsights`**（见 `matching-rrm-sim-readonly-summary.ts` / `RRM_SIM_READONLY_SUMMARY_INSIGHTS_KEY`）。Resolver **只读**该摘要 + **读 RRM display 侧车 meta**；**不**调用 evaluator。

## 4. Resolver 优先级表（冻结）

以下顺序在 **`resolveMatchResultDisplay`** 内 **固定**（产品若调整须改本文件 **修订记录** 并回归单测）：

| 优先级 | 条件 | 返回 |
|--------|------|------|
| **1** | **`PEIMA_M5_RRM_TOP2_ENABLED === "1"`** 且 **RRM Top2 enabled meta** 可解析、且 **M5.3-A §12 Eligible** 全通过 | **`displayCandidateUserId`** = meta 中冻结的 RRM winner（∈ Top2）；**`displaySourceType`** = **`rrm_top2_bounded_selector`**；**`finalMatchDecisionMeta`** = **viewer-safe** 的 RRM 决策投影（V2 或平行结构映射，**不得**泄漏非 winner 的敏感对比）。 |
| **2** | 否则：**`readPairwiseFinalizeEnv()`** 满足 **enabled 门**（与 **§2** 一致）且存在 **合法** `pairwise_pool_finalize_meta` 行 | **现有 M3.8 行为**（`static_final` / `pairwise_final` / `static_fallback` + V1 meta）。 |
| **3** | 否则 | **`displayCandidateUserId = matchRow.candidateUserId`**，**`displaySourceType = "match_result_original"`**，**`finalMatchDecisionMeta = null`**。 |

**与 Pairwise 的先后**：本设计 **明确推荐** —— 当 **RRM Top2 enabled 与 Pairwise finalize 均可命中** 时，**RRM Top2 分支优先**（更高层 display synthesis，且与 M5.3-A「RRM bounded 为 MVP 主展示增量」一致）。若产品日后要求 **Pairwise 永远覆盖 RRM**，须在 **修订本表** 并评估 **已冻结 RRM meta** 的用户解释成本。

**互斥写侧**：**同一 `matchResult` 展示冻结** 在 M5.3-A §11.4 要求 **单 enabled 写源**；resolver **只读**侧车，不负责写；写侧由 **finalize / job completion** 保证 **不** 同时写入冲突 winner（**M5.3-C** 事务策略）。

## 5. Env 设计（建议）

与 **`pairwise-finalize-env.ts`** 对称，新增 **`m5-rrm-top2-display-env.ts`**（文件名仅建议）：

```text
# 默认关闭；= "1" 时允许 resolver 尝试 RRM Top2 enabled 分支（仍须 meta + eligible 全过）

# 可选：RRM display meta / 绑定指纹的契约 era（parser allow-list 用）
```

**说明**：

- **默认 `false`**：生产与预发 **零行为变更**，直至运维显式打开。

- **`.env.example`** 的落地属 **M5.3-C** PR，本设计轮次 **不** 修改该文件（与任务约束一致）。

## 6. 读路径伪代码（实现提纲）

```text
resolveMatchResultDisplay(prisma, matchRow):
  original := matchRow.candidateUserId

  if readM5RrmTop2DisplayEnv().enabled:
    rrm := tryResolveRrmTop2Display(prisma, matchRow)  // 只读侧车 + matchInsights；无 LLM / 无 Top2 重算
    if rrm.ok:
      return rrm.fields  // displaySourceType === "rrm_top2_bounded_selector"

  pairwiseEnv := readPairwiseFinalizeEnv()
  if pairwiseEnv.enabledFlag && pairwiseEnv.mode === "enabled":
    // === 现有 for 循环（§2）===
    ...

  return { original, "match_result_original", null }
```

**`tryResolveRrmTop2Display`**（实现时拆分函数）：校验 **baseline**、**fingerprint**、**`rrmSimReadonlySummary`**、`guardrails` 等价输入、**Top2 集合**；失败返回 `ok: false`（**不**抛错，保证 GET 稳定）。

## 9. Eligible validation function design（纯函数）

### 9.1 建议 API（M5.3-C 新增）

与 **`parseFinalizeMetaV1Loose`** 同类：**纯函数、无 Prisma、无 env 读取**（env 由调用方注入布尔或已解析的 `readM5RrmTop2DisplayEnv()` 结果），便于单测矩阵。

```ts
validateRrmTop2DisplayEligibility(input): RrmTop2DisplayEligibilityResult
```

### 9.2 `input` 建议形状（逻辑字段）

| 字段 | 说明 |
|------|------|
| `m5RrmTop2Enabled` | 调用方已解析：`PEIMA_M5_RRM_TOP2_ENABLED === "1"`。 |
| `matchResultUserId` / `matchResultCandidateUserId` | 与 `MatchResult` 行一致；**baseline** = `matchResultCandidateUserId`。 |
| `rrmDisplayMeta` | 已 JSON 解析的 **RRM Top2 display 侧车**（见 **§11**）；`null` → 不合格。 |
| `rrmSimReadonlySummary` | 已解析的 **`RrmSimReadonlySummaryPayloadV1`** 或 **parse 失败** 的 `null`。 |
| `guardrailsReadonly` | 与 **`MultiSourceGuardrailsSourceReadonly`** 同构的最小切片（`status`、`blockReasons`、`cautionReasons`、`sourceSummary`）；可由调用方从 **hydration** 复用 M5.1  builder 产出，**不得**在 validator 内调 LLM。 |
| `top2CandidateUserIds` | 长度 2、互异、来自 meta 或 **static_top2_readonly_summary** 冻结证据。 |
| `top2Fingerprint` | 与 meta / summary **绑定一致** 的字符串。 |

**禁止**：在 `validateRrmTop2DisplayEligibility` 内调用 **`buildRelationshipShortlistTop2`** 或任何 **Top2 重算**。

### 9.3 `RrmTop2DisplayEligibilityResult` 建议形状

| 字段 | 类型 | 语义 |
|------|------|------|
| `ok` | `boolean` | `true` 表示 **可**返回 RRM Top2 display（仍须 resolver 侧 **User 存在性** 等 DB 校验，若有）。 |
| `noOpReasonCode` | `RrmTop2DisplayNoOpReasonCode \| null` | `ok === true` 时为 `null`；否则为 **§10** 枚举之一。 |
| `debugLabels` | `string[]`（可选） | **仅**测试或 **Admin** 遥测；**禁止**默认塞进 GET 响应。 |

### 9.4 规则映射（与 M5.3-A §12 / §13 对齐）

校验顺序建议 **短路**（先 cheap 后重）：

1. `m5RrmTop2Enabled` 为 false → `env_off`（或不在本函数检 env，由外层短路）。  
2. `rrmDisplayMeta` 缺失 / `schemaVersion` 不支持 → `meta_missing` / `meta_schema_invalid`。  
3. `top2CandidateUserIds` 非恰好 2 或重复 → `top2_count_invalid` / `top2_duplicate`。  
4. `baseline` 与 `matchResultCandidateUserId` 不一致 → `baseline_mismatch`。  
5. `top2Fingerprint` 与 meta / summary 绑定不一致 → `fingerprint_mismatch`。  
6. `rrmSimReadonlySummary` 缺失或 `sourceVersion` 不在 allow-list → `rrm_summary_missing` / `rrm_summary_version_rejected`。  
7. **RRM winner**（从 summary 字段按 M5.3-A §11.3 冻结的规则提取）∉ Top2 集合 → `rrm_winner_not_in_top2`。  
8. `confidenceBucket === "low"` 或 `"unknown"`（M5.3-A §12-7）→ `rrm_confidence_low` / `rrm_confidence_unknown`。  
9. `fallbackUsed === true` → `rrm_fallback_used`。  
10. `guardrails.status !== "pass"` → `guardrails_block` / `guardrails_caution` / `guardrails_not_evaluated`（**细分枚举** 便于审计）。  
11. **禁止**将 `sourceSummary === "no_viewer_safe_caution_signals"` 单独视为 pass（M5.3-A §12-10）→ 须在 guardrails 分支内 **显式** 要求 `status === "pass"` 且 `blockReasons.length === 0`。  
12. `appliedToFinalScore !== false` 或 `appliedToWorkerRanking !== false`（若 meta 含此类字段）→ `meta_applied_flags_invalid`。

**DB 依赖项**（`User` 存在性）：可放在 **`validateRrmTop2DisplayEligibility` 之外**（`tryResolveRrmTop2Display` 内 `prisma.user.findUnique`），避免纯函数异步化；**M5.3-C** 二选一并文档化。

## 10. `noOpReasonCode` 冻结枚举

以下字符串为 **canonical**（`snake_case`）；与 M5.3-A §11.3 示例 **对齐并可扩展**，以本表为 **SSOT**。

| `noOpReasonCode` | 典型触发（交叉引用） |
|------------------|----------------------|
| `env_off` | M5.3-A §13 env off |
| `meta_missing` | 无侧车 / 无绑定行 |
| `meta_schema_invalid` | JSON 不符合 RRM display meta schema |
| `meta_applied_flags_invalid` | `appliedTo*` 非 false |
| `top2_count_invalid` | Top2 ≠ 2 |
| `top2_duplicate` | 两 ID 相同 |
| `baseline_mismatch` | baseline ≠ `MatchResult.candidateUserId` |
| `fingerprint_mismatch` | M5.3-A §12 / §13 fingerprint 规则 |
| `rrm_summary_missing` | 无 `rrmSimReadonlySummary` |
| `rrm_summary_schema_invalid` | summary JSON 非法 |
| `rrm_summary_version_rejected` | allow-list 拒绝 |
| `rrm_winner_not_in_top2` | winner 不在 Top2 |
| `rrm_confidence_low` | `confidenceBucket === "low"` |
| `rrm_confidence_unknown` | `confidenceBucket === "unknown"` |
| `rrm_fallback_used` | `fallbackUsed === true` |
| `guardrails_block` | `status === "block"` |
| `guardrails_caution` | `status === "caution"`（初始 enabled 禁入） |
| `guardrails_not_evaluated` | `status === "not_evaluated"` |
| `guardrails_pass_predicate_failed` | 非 pass 或 blockReasons 非空等组合失败 |
| `display_source_type_unknown` | current meta 与已知枚举不兼容（§13 行级 fallback） |
| `proposed_user_not_found` | DB 无 RRM winner 用户行（若 DB 校验外置） |

**Resolver 行为**：任一 `ok === false` → **不**返回 `rrm_top2_bounded_selector`，进入 **§4** 下一优先级；**不**记录用户可见错误（与 M5.3-A「Fallback 非错误」一致）。**Admin / 结构化日志** 可记录 `noOpReasonCode`（**无 PII**）。

## 11. Meta 存储方案（冻结推荐）

### 11.1 方案对比（简）

| 方案 | 优点 | 缺点 |
|------|------|------|
| **(A)** 扩展 `pairwise_pool_finalize_meta` | 少一张表 | 语义混杂；Pairwise 与 RRM 生命周期不同 |
| **(B) 推荐：新侧车表 `MatchResultRrmTop2DisplayMeta`（名称 M5.3-C 可微调）** | 与 finalize 解耦；**`matchResultId` 唯一** 绑定清晰 | 需 migration（**M5.3-C**） |
| **(C)** `matchInsights` 内嵌 JSON key | 无新表 | 与现有 `rrmSimReadonlySummary` 争用同一 blob；并发写风险 |

**冻结推荐**：**(B)** — 行级 **1:0..1** 于 `MatchResult`；字段最小集：`matchResultId`、`viewerUserId`（冗余校验）、`schemaVersion`、`sourceVersion`、`frozen`、`frozenAt`、**`meta` JSON**（viewer-safe decision trace，对齐 M5.3-A §14.3）、**`top2Fingerprint`**（可选顶层索引）。

### 11.2 Resolver 读路径

`tryResolveRrmTop2Display`：`findUnique`（或 `findFirst` + `orderBy` 若允许多版本）按 **`matchResultId`** 读取；**`frozen === true`** 才参与；解析失败 → `meta_schema_invalid`。

### 11.3 写路径（非本轮）

由 **RRM bounded job 完成** 或 **专用 finalize 端点** 写入；须 **幂等**（重复写同 fingerprint → `already_frozen` 语义可对齐 Pairwise）。**事务**：与 `matchInsights` 中 summary 写入顺序在 **M5.3-C** PR 中单测冻结。

## 12. 测试矩阵（M5.3-C Jest）

| # | 场景 | `PEIMA_M5_RRM_TOP2_ENABLED` | Pairwise finalize env | RRM meta | 期望 `displaySourceType` |
|---|------|----------------------------|-------------------------|----------|---------------------------|
| 1 | 仅 RRM 合格 | on | off / shadow | valid | `rrm_top2_bounded_selector` |
| 2 | RRM 不合格，无 Pairwise | on | off | invalid | `match_result_original` |
| 3 | RRM 不合格，有 Pairwise | on | enabled + 有 meta | invalid | `static_*` / `pairwise_*`（现有映射） |
| 4 | RRM 合格 + Pairwise 合格 | on | enabled + 有 meta | valid | **`rrm_top2_bounded_selector`**（§4 优先） |
| 5 | RRM off，有 Pairwise | off | enabled + 有 meta | valid | 现有 Pairwise |
| 6 | 全 off | off | off | any | `match_result_original` |
| 7 | `guardrails_caution` | on | any | 否则合格 | fallback（非 RRM） |
| 8 | `fingerprint_mismatch` | on | any | 绑错 | fallback |

**`validateRrmTop2DisplayEligibility` 单测**：对 **§9.4** 每行至少 **1** 个用例；对 `ok: true` **黄金路径** ≥1。

**`MatchingService` 集成轻测**（可选）：`multiSourceFinalDecision.m5AppliedToDisplay` 恒 `false`，且 `currentDisplay*` 与 resolver 输出一致。

## 13. 验收标准（M5.3-C PR 合并门槛）

1. **优先级**：满足 **§4** 表；**#4** 场景有 Jest 锁定 RRM 优先于 Pairwise。  
2. **红线**：任意路径 **不** `update` `MatchResult.candidateUserId` / `finalScore`；GET **无** `buildRelationshipShortlistTop2`、**无** RRM evaluator。  
3. **Eligible**：`validateRrmTop2DisplayEligibility`（或等价）覆盖 **§9.4**；`noOpReasonCode` 使用 **§10** 枚举（无魔法字符串散落）。  
4. **类型**：`MatchResultDisplaySourceType` + Web `MatchingResultResponse` 已含 **`rrm_top2_bounded_selector`**（§7）。  
5. **UI**：`FinalMatchTechnicalDetails` 在 **无 pairwise 字段** 的 RRM meta 下 **不崩溃**（可选字段渲染）。  
6. **侧车**：`multiSourceFinalDecision` **仍不** 改写 display（回归 §8）。  
7. **默认 off**：未设 env 或 `false` 时与 **M3.8** 行为 diff **为空**（除代码路径存在死分支外无用户可见变化）。
