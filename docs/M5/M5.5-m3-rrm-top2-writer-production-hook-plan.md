# M5.5-M3 — RRM Top2 Writer Production Hook Plan

## 1. 一句话结论

M5.5-M3 **不写代码**，只定义 **production hook** 如何把 **M5.5-M2** 的 `writeRrmTop2DisplayMetaForMatchResult` foundation **安全**接到真实数据流：在**非 GET**、**非 worker 主链路阻塞**的前提下完成 summary / meta 落库，使 **`GET /matching/result`** 仍**只读**即可在条件满足时得到 **`rrm_top2_bounded_selector`**，且**永不**污染 **`MatchResult.candidateUserId`**、**`finalScore`**、**worker ranking**、**pairwise finalize** 或用户画像。

---

## 2. 当前状态

- **Writer foundation（M5.5-M2）已交付**：`readM5RrmTop2MetaWriteEnabled()`、`writeRrmTop2DisplayMetaForMatchResult`、与 **`validateRrmTop2DisplayEligibility`** 对齐的编排、**`writeRrmSimReadonlySummaryToMatchResult`** 可选路径、结构化 **no-op**、单测、**`m55-m2`** controlled CLI（默认 dry-run，`NODE_ENV=production` 拒绝）。
- **Writer 默认 off**：`PEIMA_M5_RRM_TOP2_META_WRITE_ENABLED`；summary 写入另受 **`PEIMA_M5_RRM_SIM_READONLY_SUMMARY_WRITE_ENABLED`** 约束（与 M5.2-M2B 一致）。
- **`GET /matching/result`**：仍仅通过 **`resolveMatchResultDisplay`** **读** `MatchResult` + 侧车 + `matchInsights.rrmSimReadonlySummary`；**不写库**、**不重跑 RRM evaluator**。
- **RRM Top2 展示**：在 **`PEIMA_M5_RRM_TOP2_ENABLED`** 与 **frozen meta + 合法 summary + eligibility** 齐备时，读路径可返回 **`rrm_top2_bounded_selector`**（与 M5.3 / M5.5-M0/M1 设计一致）。
- **缺口**：尚无 **自动 production hook** 在真实业务完成后调用 writer；Top2 / summary / guardrails 的**稳定生产来源**仍须在 hook 设计里逐项钉死。

---

## 3. Production Hook 候选方案

### Option A：`GET /matching/result` 时触发 writer

**结论：禁止。**

- GET **不得写库**；违反幂等、缓存与运维预期。
- GET **不得重跑 RRM**（M5.1 / M5.2 / M5.3 红线）。
- 读路径变重、副作用不可预测（重试风暴、多副本重复写等）。

### Option B：worker batch-match 完成后触发 writer

**优点**

- `MatchResult` 刚生成，`matchResultId`、`batchId`、`userId` 绑定清晰。
- 与「匹配批次」自然对齐。

**缺点**

- 该时刻 **RRM simulation / proposal** 往往尚未产出 **`rrmSimReadonlySummary`**。
- **Static Top2** 未必已有**冻结**快照；在 hook 内**现算** shortlist 会违背「不在热路径重算 Top2」原则。
- 易使 **worker 主链路** 变慢或失败语义变复杂。

**适合用法**

- **仅 no-op safe 探测**：例如记录「待 aggregation」状态；**仅当** summary 已在 `matchInsights` 且 Top2 证据齐备时才调用 writer；否则 **`no-op` + audit**，不阻塞 batch 成功语义。

### Option C：RRM simulation / proposal 完成后触发 writer

**优点**

- 最接近 **RRM 只读产物**；可用 **M5.2-M2A builder** 生成 viewer-safe **`rrmSimReadonlySummary`**，再调 M5.5-M2 writer（先 summary 后 meta 的顺序已由 foundation 保证）。
- 与 **`resolveMatchResultDisplay`** 消费模型一致：GET 只读已落库数据。

**缺点**

- 必须能 **稳定关联** `matchResultId`（及 viewer / batch）。
- 仍依赖 **Static Top2 + `top2Fingerprint`** 与 **显式 guardrails** 的生产来源；simulation 完成**不等于**三者齐备。

**适合**

- **M5.5-M5** 及以后：在 **completion 回调** 或 **异步队列消费者** 中调用 writer（仍须 env 与幂等闸门）。

### Option D：独立 post-match aggregation job

**优点**

- **输入最清晰**：`MatchResult` + 冻结 Top2 快照 + summary + guardrails；可 **重试、批量 replay、admin 触发**。
- **不污染** worker 同步路径与 GET。

**缺点**

- 多一套 runner / 队列 / 调度；实现与运维成本高于单次 CLI。

**适合**

- **M5.6 / M9**：多源共识、质量评估与回放的主形态。

---

## 4. 推荐方案

| 阶段 | 建议 |
|------|------|
| **M5.5-M4（短期）** | **Option C-lite + controlled runner**：**不接 GET**、**不改 worker 主流程**；新增 **受 env 控制的 production hook runner**（或扩展 CLI 族，**建议新文件**如 `m55-m4-rrm-top2-production-hook-runner`），输入 **`matchResultId`** + **从已存在冻结源读取的 Top2 / fingerprint** + **summary（磁盘或受控注入）** + **显式 guardrails**；默认 **dry-run**，**`--apply`** 才写库；不满足则 **no-op**。 |
| **M5.5-M5** | 在 **RRM simulation / proposal completion** 后 **自动**调用 writer（仍双开关 + 幂等）；或引入 **pending 表 / 队列** 由消费者调用 writer。 |
| **中期** | **Option D**：独立 **post-match aggregation job**（与 M5.5-M1 §4 一致）。 |

**不在 M5.5-M4 做**：worker batch-match 内联重逻辑、GET 侧写库、全量 cron 扫全库无差别写 meta。

---

## 5. Static Top2 来源决策

**关键风险（必须写进实现 checklist）**：**不能**仅凭 **`FinalMatchDecisionMeta`** 的 `selectedCandidateUserId` / `pairwiseWinnerCandidateUserId` 推断 **稳定 Static Top2**；其与 **RRM bounded Top2 + fingerprint** 的生命周期与语义未必一致。

**允许来源（优先级建议）**

1. **已冻结的 Relationship / shortlist Top2 快照**（若 schema 与产品定义中有明确「viewer + batch → 冻结 Top2」行）。
2. **`AiPairwiseDecisionJob` shortlist 快照** — 仅当 **frozen**、与 `MatchResult` / `batchId` **可证明绑定**、且导出字段 **viewer-safe**。
3. **`PreviewPoolItem` / `rankInPool` 等** 导出的 **只读 Top2 快照** — 仅当与 **该次 `MatchResult` 同一决策批次** 且不可变。
4. **未来**：`staticTop2ReadonlySummary` 或专用侧车 JSON（与 `rrmSimReadonlySummary` 对称）。

**M5.5-M4 规则**

- 若无 **冻结且可解析** 的 Top2 快照（两 distinct id + **`top2Fingerprint`**），writer **必须 `no-op`**（审计原因建议：**`static_top2_missing`** / **`static_top2_not_frozen`** / **`top2_fingerprint_missing`** / **`baseline_mismatch`** / **`selected_not_in_top2`** 等，与 M5.5-M2 / eligibility 对齐）。
- **禁止**在 hook 内为「凑 Top2」**重算** shortlist 或扫 GET 热路径。

---

## 6. RRM Summary 来源决策

Writer 需要 **已能通过** **`tryParseRrmSimReadonlySummaryPayloadV1FromMatchInsights`** 的 **`matchInsights.rrmSimReadonlySummary`**（或由 **`writeRrmSimReadonlySummaryToMatchResult`** 先持久化后再读）。

**允许来源**

1. **已存在于** `MatchResult.matchInsights.rrmSimReadonlySummary`（生产或前置 job 写入）。
2. **RRM simulation 结果** → **M5.2-M2A** builder → summary payload → **`writeRrmSimReadonlySummaryToMatchResult`**（再 writer）。
3. **RRM ranking proposal（M4.0 等）** → 同一 builder 路径（`sourceVersion` 须在 allow-list）。
4. **Dev/staging**：controlled runner / fixture（**非**生产默认路径）。

**M5.5-M4 禁止**：把 **raw transcript、prompt、公式、C/A/S/E/F/Q/D/R 向量、另一候选人敏感对比** 写入 `matchInsights` 或侧车 meta。

---

## 7. Guardrails 来源决策

**Writer 要求显式 `meta.guardrails`**（与 M5.5-M0.2 / parser / eligibility 一致）。**仅当**：

- `guardrails.status === "pass"`
- `blockReasons` 与 `cautionReasons` 均为 **空数组**

才允许进入 **eligible** 写 meta 路径。

**若无显式 guardrails**：**`guardrails_missing`**（或 writer 前置 **`guardrails_invalid`**）— **no-op**。

**禁止**

- 用 **`matchInsights.explanation.cautions`** 或「没有某段文案」**冒充** `pass`。
- 在 hook 内 **清空** 既有 `matchInsights.explanation.cautions`（与 M5.5-M0 文档一致）。

**生产建议**：guardrails 由 **独立策略模块 / aggregation job** 产出 viewer-safe 快照字段；M5.5-M4 runner 可先接受 **显式 CLI / 配置文件块**（仅非生产），生产由 **M5.5-M5+** 从可信服务注入。

## 8. M5.5-M4 最小实现建议（代码占位，本轮不实现）

- 新增 **controlled production hook runner**（**建议新文件** `apps/api/src/dev-cli/m55-m4-rrm-top2-production-hook-runner.ts` + 独立 `*-cli.ts` 入口，与 **M5.5-M2** `m55-m2` 并列，避免职责混淆）。
- **默认 dry-run**；**`--apply`** 才写库；**`NODE_ENV=production`** 拒绝（与 M5.5-M2 一致）。
- **Env**：`PEIMA_M5_RRM_TOP2_META_WRITE_ENABLED`、`PEIMA_M5_RRM_SIM_READONLY_SUMMARY_WRITE_ENABLED`（若需写 summary）、可选 **`PEIMA_M5_RRM_TOP2_HOOK_*`** 细粒度开关（实现时命名再定）。
- **输入**：至少 **`matchResultId`**；Top2 / fingerprint / guardrails 从 **只读冻结源** 拉取，缺失则 **no-op**；summary 从 **DB** 读取或经 **builder** 生成后写入（仍走 M5.2 writer）。
- **输出**：**aggregate-safe / viewer-safe** JSON（**no-op reason**、`wroteSummary`、`wroteMeta`、**不含** raw prompt / transcript / score / 真实 ID 进 **文档**；日志脱敏策略与现有 API 一致）。

**不接**：GET、worker 主流程、FinalMatchPage、ChatPage。

## 9. M5.5-M5 再考虑自动 hook

**M5.5-M5** 才评估：

- 在 **AI simulation v1 job completion** 或 **RRM proposal 定稿** 后 **异步**调用 writer（或入队由 worker **旁路消费者**处理，**非** batch-match 同步事务内）。
- **独立 cron / job**：扫描 **`pending_rrm_top2_display`** 类状态（若未来引入）或「summary 已就绪且缺 meta」的受控查询。
- **Admin 手动触发** production hook（无 UI 也可先 HTTP internal + RBAC）。

**M5.5-M4 不做**：全库无差别自动写、simulation 内联阻塞、无 Top2 仍强行写 meta。

## 10. No-op 与 audit

以下 **必须保留为 no-op（非错误）**，且 **不改变** 既有 `MatchResult` 主行展示语义；**GET** 继续 **pairwise / `match_result_original`** fallback：

| 类别 | 示例 reason（与 M5.5-M2 / `validateRrmTop2DisplayEligibility` 对齐） |
|------|---------------------------------------------------------------------|
| 开关 / 行缺失 | `writer_disabled`、`match_result_missing` |
| Summary | `rrm_summary_missing`、`rrm_summary_invalid`、`rrm_summary_version_rejected`、`summary_write_disabled`、`summary_write_failed` |
| Static Top2 | `static_top2_missing`、`static_top2_not_frozen`、`top2_fingerprint_missing`、`baseline_mismatch`、`selected_not_in_top2`、`top2_duplicate`、`fingerprint_mismatch` |
| Guardrails | `guardrails_missing`、`guardrails_invalid`、`guardrails_caution`、`guardrails_block`、`guardrails_not_evaluated`、`guardrails_pass_predicate_failed` |
| 侧车幂等 | `existing_meta_frozen` |
| RRM 质量 | `rrm_confidence_low`、`rrm_confidence_unknown`、`rrm_fallback_used`、`rrm_winner_not_in_top2`、`rrm_meta_winner_mismatch` 等 |

**说明**：no-op **不是**用户可见错误；应 **结构化 audit**（`sourceVersion`、`noOpReasonCode`、`top2Fingerprint`、`summarySourceVersion`、`guardrails.status` 等），**不**写 PII 敏感扩展、**不**写 raw RRM 维、**不**写另一候选人对比细节。

## 11. 安全边界（再次冻结）

**Writer / hook 永远不能改**

- `MatchResult.candidateUserId`
- `MatchResult.finalScore`
- worker ranking 持久化语义
- **`PairwisePoolFinalizeMeta`**
- 用户画像 / 问卷主数据
- **Chat `Message`** 或自动代发消息

**Writer 仅允许写**（在 env 与 eligibility 允许时）

- `matchInsights` 下的 **`rrmSimReadonlySummary`**（仅该键的受控浅合并，见 **`writeRrmSimReadonlySummaryToMatchResult`**）
- **`MatchResultRrmTop2DisplayMeta`**（`writeRrmTop2DisplayMetaForMatchResult`）

---

## 12. 与 M6.1 Feedback 的关系

M6.1 **`decisionContext`**（或等价结构）宜持久化/传递 **viewer-safe** 字段，便于归因与 M9 评估：

- `matchResultId`（内部引用）
- `candidateUserId` vs **`displayCandidateUserId`**
- **`displaySourceType`**
- **是否**处于 RRM display 活跃态
- **writer / meta `sourceVersion`**
- **`noOpReasonCode`**（若曾尝试 hook 但未写）
- **无** raw RRM score、公式、prompt、transcript、Top2 外候选人敏感对比

## 13. M5.5-M4 代码验收标准（实现轮使用）

- **Env off**：不写 summary、不写 meta。
- **summary 缺失 / invalid**：**no-op**，不写 meta（或整次 no-op）。
- **static top2 缺失 / 未冻结**：**no-op**。
- **guardrails 非 pass 或数组非空**：**no-op**。
- **eligible**：**upsert meta**（及按需 summary）；**已 frozen meta**：**不覆盖**。
- **`candidateUserId` / `finalScore` 不变**。
- **GET 不写库**；**controlled runner dry-run 不写库**；**`--apply` 才写库**。
- **日志 / 文档 / PR 描述**不输出 raw prompt、transcript、score 向量、API key、token、真实业务 ID 样例。
