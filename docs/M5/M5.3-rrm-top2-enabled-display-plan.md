# M5.3-A — RRM Top2 Enabled Display Plan

**文档版本**：M5.3-A **v1.3**（v1.2 基础上补齐 **Eligible / Fallback / Display 应用规则** 与 **meta 记录草案**，供 M5.3-B 实现门禁与类型同步验收。）

## 1. 一句话结论

M5.3 **不**重新造一套最终展示系统，而是**复用 M3.8-M13 已落地的** `displayCandidateUserId` / `displaySourceType` / `finalMatchDecisionMeta`（及 `resolveMatchResultDisplay` 读路径）。M5.3 的目标是在**严格开关与 eligible rules** 下，让 **20 维 / Static 先产出 Top2**，再让 **RRM-Sim 仅在 Top2 内做 bounded 二选一**，经 **Guardrails** 校验后，**才把 RRM winner 写进展示层**（即与 today 相同的 display 字段语义）；**始终不覆盖** `MatchResult.candidateUserId`、**不修改** `finalScore`。

## 2. 为什么改成 RRM Top2 bounded selector

全量候选 + Pairwise + RRM + Guardrails 的多源主链在工程与 AI 成本上偏重。为压缩 MVP / 商业化早期成本，产品路线收敛为：

- **20 维 / Static**：低成本筛出 **Top2**（与既有 preview pool + shortlist 能力对齐，见 M3.8-M1 与 `relationshipShortlistTop2` 相关实现）。
- **RRM**：**只在 Top2 内二选一**（bounded selector），避免 RRM 在全池自由排序。
- **Pairwise**：从「每次必跑主链」降级为 **optional**（audit / fallback / premium 档位），主展示不依赖 Pairwise 必成功。
- **GET `/matching/result`**：**不**在现场重跑 RRM evaluator（与 M5.1/M5.2 红线一致）；展示依赖**已持久化或可复算的 viewer-safe 摘要**（如 `rrmSimReadonlySummary` 写入路径，见 M5.2 文档与 writer）。
- **FinalMatchPage**：继续只读 API 返回的 `displayCandidateUserId`（与 M3.8-M13 一致）。

### 3.2 M3.8 已经实现的 display 机制（代码还原）

1. **`GET /matching/result/:userId`**（`MatchingController.getResult` → `MatchingService.getLatestResultForUser`）在返回 `MatchResult` 行之外，**合并** `resolveMatchResultDisplay` 产出的 **`displayCandidateUserId` / `displaySourceType` / `finalMatchDecisionMeta`**，并附加 M5.x 的 **`multiSourceFinalDecision`** 只读侧车（不改变 display 解析结果）。
2. **`resolveMatchResultDisplay(prisma, matchRow)`**（`matching-result-display.ts`）：
   - 若 **`readPairwiseFinalizeEnv()`** 为 `enabledFlag !== true` 或 **`mode !== "enabled"`**：直接返回 **`displayCandidateUserId = matchRow.candidateUserId`**，`displaySourceType = "match_result_original"`，`finalMatchDecisionMeta = null`**。
   - 否则：按 `viewerUserId` + `frozen: true` 查询最多 12 条 **`pairwise_pool_finalize_meta`**，解析 `meta` 为 **`FinalMatchDecisionMetaV1`**（`parseFinalizeMetaV1Loose`），且要求 **`meta.staticTop1CandidateUserId === matchRow.candidateUserId`**（与 batch 静态 Top1 绑定）；校验 **`selectedCandidateUserId`** 存在于 `User` 表，且属于 `{staticTop1, pairwiseWinner}` 允许集合；通过后返回 **`displayCandidateUserId = selected`**，并由 **`mapDisplaySourceTypeFromMeta`** 决定 **`displaySourceType`**，附带 **viewer-safe** 的 **`finalMatchDecisionMeta`**。
3. **`MatchingFinalizePairwiseService`** 将冻结元数据写入 **`PairwisePoolFinalizeMeta`**，**不**写 `MatchResult`（与 M3.8-M11 注释一致）。

### 3.3 `displayCandidateUserId` 在哪里生成 / 解析 / 返回

- **生成（展示语义）**：在 **`resolveMatchResultDisplay`** 内计算；**非** SQL 生成列，而是 API 读路径组合 `MatchResult` + `pairwise_pool_finalize_meta` + env gate。
- **返回**：`MatchingService.getLatestResultForUser` 将 `display` 字段 spread 进响应（`MatchResultViewerPayload`）。

### 3.4 `displaySourceType` 当前可能取值

类型定义见 **`MatchResultDisplaySourceType`**（`matching-result-display.ts`）：

- `match_result_original`
- `static_final`
- `pairwise_final`
- `static_fallback`

映射规则见 **`mapDisplaySourceTypeFromMeta`**：若 `selected !== originalCandidateUserId` → `pairwise_final`；否则依 `meta.sourceType` 区分 `static_fallback` / `pairwise_final` / `static_final`。

### 3.5 `finalMatchDecisionMeta` 当前 viewer-safe 字段

**API 对外**使用 **`ViewerSafeFinalMatchDecisionMeta`**（`toViewerSafeFinalMatchDecisionMeta` 投影自 **`FinalMatchDecisionMetaV1`**），字段包括：

`sourceType`, `mode`, `pairwiseProposalRecommendation`, `selectedCandidateUserId`, `staticTop1CandidateUserId`, `pairwiseWinnerCandidateUserId`, `wouldChangeStaticResult`, `fallbackReason`, `frozen`, `frozenAt`, **`appliedToFinalScore`**, **`appliedToWorkerRanking`**

（不含 raw pairwise 分数、六维、`strongRisk` 等；与 M3.8-M11 设计一致。）

### 3.6 Pairwise finalize 是否已能影响 `displayCandidateUserId`

**能**——在 **`PAIRWISE_FINAL_MATCH_ENABLED=1` 且 `PAIRWISE_FINAL_MATCH_MODE=enabled`** 且存在**绑定成功**的冻结 `pairwise_pool_finalize_meta` 时，`resolveMatchResultDisplay` 可将 **`displayCandidateUserId`** 设为 **`meta.selectedCandidateUserId`**（可能等于 static Top1 或 pairwise winner，取决于 `buildFinalMatchDecisionMetaV1` 的门禁逻辑）。

### 3.7 `appliedToFinalScore` / `appliedToWorkerRanking`

- **`FinalMatchDecisionMetaV1`** 中两字段类型为字面量 **`false`**（`final-match-decision-meta.builder.ts`）。
- **`parseFinalizeMetaV1Loose`** 拒绝 **`appliedToFinalScore !== false` 或 `appliedToWorkerRanking !== false`** 的持久化 JSON。
- **Viewer-safe** 响应中照抄为 **boolean**，当前产品路径下恒为 **`false`**。

### 3.8 是否已做到「不改 `MatchResult.candidateUserId`、不改 `finalScore`，只改 display」

**是（在现有 finalize 与 GET 路径下）**：`MatchingFinalizePairwiseService` 文档化承诺**不**更新 `MatchResult` 行；`getLatestResultForUser` **不**写库；展示通过 **额外字段** `displayCandidateUserId` / `displaySourceType` 表达。`finalScore` 仍为行上原始分数。

### 3.9 M5.3 可复用的 M3.8 能力

- **`resolveMatchResultDisplay`** 的 **env gate + DB 绑定 + viewer-safe meta** 模式。
- **`displayCandidateUserId` / `displaySourceType` / `finalMatchDecisionMeta`** 作为**唯一**用户可见「当前匹配对象」来源（前端已用 `displayCandidateUserId || candidateUserId`，`FinalMatchPage.jsx`）。
- **`pairwise_pool_finalize_meta`** 作为「展示决策侧车」落库范式（M5.3 可考虑**同类侧车**或**扩展 meta schemaVersion**，本计划**不写代码**）。
- **`MatchResultViewerPayload` + `MatchingResultResponse`** 的扩展习惯（已含 `multiSourceFinalDecision`）。

### 3.10 M5.3 不能复用或需补齐的能力

| 能力 | 状态 |
|------|------|
| **RRM Top2 bounded 二选一的展示门禁** | **未实现** — 今日 resolver 只理解 **pairwise finalize meta**；RRM winner 进入 display 需 **新 eligible 规则 + 新 meta 或 schemaVersion 扩展**，属 **M5.3-B+ 代码里程碑**。 |
| **产品级 Guardrails 引擎（非 M5.1 侧车 cautions）** | **未与 display 写路径挂钩** — M5.1 `sources.guardrails` 为只读侧车；**需 M5.3-B** 定义硬拦截与 `viewer_safe_no_caution_signal` 的边界。 |

## 4. M5.3 与 M3.8 的关系

**M3.8 已解决：**

- **`MatchResult.candidateUserId`** 保留为 **batch / worker 语义下的 baseline（静态 Top1）**。
- **`finalScore`** 保留为行上原始分数。
- **实际展示**由 **`displayCandidateUserId` / `displaySourceType` / `finalMatchDecisionMeta`** 组合表达；前端**不必**等于 `candidateUserId`。
- **Pairwise** 通过 **finalize 侧车表** 影响展示，且不写回 `MatchResult` 主列。

**M5.3 不推翻 M3.8**，只在 **同一 display 层**增加一种（或多种）**受控来源**：

- 建议新增 `displaySourceType` 取值（**命名预案**，实现属 M5.3-B）：例如 **`rrm_top2_bounded_selector`** 或 **`multi_source_rrm_top2`**，与现有 `pairwise_final` / `static_final` 等并列，由 **`resolveMatchResultDisplay`（或与其等价的单一 resolver）** 在开关打开时择优返回。
- **`multiSourceFinalDecision`**（M5.1/M5.2）继续作为 **只读审计 / shadow**；是否进入 **enabled** 的 **决策 trace** 应写入 **meta 或侧车 JSON**（与 M5.2-M4 audit 口径衔接），具体字段 **M5.3-B** 冻结。

## 5. M5.3 Enabled Display 的目标

### 5.1 M5.3 要做

- 在 **feature flag + eligible rules** 下允许 **RRM Top2 bounded selector** 影响 **`displayCandidateUserId`** 与 **`displaySourceType`**。
- **扩展 / 版本化** `finalMatchDecisionMeta`（或平行结构）以记录 **来源、规则版本、shadow/consensus 引用、回滚指针**（不写 raw RRM 向量）。
- **支持回滚**：关闭开关或 guardrail fail → 回退到 **`match_result_original` 或 static/pairwise 既有路径**（优先级在 M5.3-B 写死）。
- **Admin audit**：延续 M5.2-M4 CLI / 聚合思路，对 **enabled** 决策单独出 run record（**不**在本计划写实现）。
- **为 M6.1 `decisionContext` 预留**：在 meta 中预留 **稳定、可审计、无敏感比较** 的字段位（具体 schema **M5.3-B**）。

### 5.2 M5.3 不做（红线）

- **不**改 `MatchResult.candidateUserId`、**不**改 `finalScore`、**不**改 20 维画像算法本体、**不**改 RRM evaluator 公式实现。
- **不**改 Pairwise **生成**逻辑（可将调用频次降为 optional，而非改 prompt/schema）。
- **不**在 **`GET /matching/result` read path** 现场跑 RRM；**不**让 RRM 脱离 Top2；**不**让 RRM 绕过 Guardrails。
- **不做** M7 Assistant / M8 Timeline / M9 evaluation dashboard（与本里程碑无关）。

## 6. 推荐流程（产品 / 工程顺序）

```text
Step 1：Hard filters / preference filters（既有池与门禁）
Step 2：20 维画像 + Static scoring 生成 Top2（复用 shortlist / pool 现有能力）
Step 3：RRM-Sim 仅对 Top2 做二选一（离线或异步 job；结果进入 viewer-safe 摘要 / meta）
Step 4：生成并校验 viewer-safe rrmSimReadonlySummary（与 M5.2 契约一致）
Step 5：Guardrails 检查 RRM winner（产品规则 + 与 M5.1 侧车信号的关系在 M5.3-B 定义）
Step 6：若 enabled 开关打开且满足 eligible rules，则：
        displayCandidateUserId = RRM Top2 winner
        displaySourceType = rrm_top2_bounded_selector（或计划最终命名）
Step 7：保留 MatchResult.candidateUserId / finalScore 不变
Step 8：记录 decisionContext，为 M6.1 feedback 做准备
```

## 7. 风险与红线

- **Shadow ≠ Enabled**：M5.2 shadow proposal **不改变**用户所见；M5.3 enabled 一旦误配，**直接影响** `displayCandidateUserId`，需 **默认 off + 灰度 + 回滚**。
- **`viewer_safe_no_caution_signal` 误读**：M5.1/M5.2 侧车中的 pass **不等于**完整安全系统通过（见 M5.2-M4 audit 注释）；M5.3 **必须**单独定义 **eligible guardrails**。
- **Top2 漂移**：若 RRM 输入与 static shortlist 不一致，可能出现 **合规 / 解释**风险；需 **单一事实来源**（fingerprint / job 绑定）。
- **Resolver 复杂度**：`resolveMatchResultDisplay` 已含 pairwise 分支；追加 RRM 需 **明确优先级与互斥**，避免多源竞态。

## 8. 与 M5.1 / M5.2 的衔接

- **M5.1** `multiSourceFinalDecision`：**只读**侧车；可作为 **enabled** 前的 **观测与 shadow 共识**输入（已实现 M5.2-M3 shadow proposal 纯计算）。
- **M5.2** `rrmSimReadonlySummary` **writer**：enabled 后应保证 **GET** 仍 **不**重跑 evaluator；展示依赖 **已写入** 或 **可推导** 的 viewer-safe 摘要。
- **M5.2-M4B CLI**：可作为 **Admin** 侧回归工具；**不**替代产品 telemetry。

## 10. Top2 来源冻结计划（M5.3-B 前置）

本节冻结 **RRM bounded selector 的输入 Top2** 从哪里来、**禁止**在何处重算、以及 **enabled** 的最低证据要求。实现细节属 M5.3-B；此处只锁产品与数据契约边界。

### 10.1 GET read path 红线

- **M5.3-B 不得在 `GET /matching/result`（及任何用户热读路径）上重新跑「全量 static ranking」**（例如对全库/全池候选重新打分排序）。该路径必须保持 **轻量、可缓存、可审计**。
- **Top2 必须在写侧或异步 job 完成时** 已经落入 **持久化 JSON** 或 **viewer-safe summary**；读路径只做 **校验 + 绑定 + 投影**（与今日 `resolveMatchResultDisplay` 消费 `pairwise_pool_finalize_meta` 的模式一致）。
- **允许**在 GET 上做的仅是：按 `matchResultId` / `poolId` / `fingerprint` **读取已存快照**、校验 schemaVersion、校验与 `MatchResult.candidateUserId`（baseline Top1）的绑定关系；**不允许**为「凑 Top2」临时调用 `AiPairwiseTop2ShortlistService.buildRelationshipShortlistTop2` 等 **重算 shortlist**（除非产品明确将某只读端点定义为非 GET 主链且单独审计——**本计划默认禁止**）。

### 10.2 当前可选 Top2 来源（仓库对照）

| # | 来源 | 仓库位置 / 语义 | 是否适合作为 RRM Top2 **唯一事实来源**（enabled） |
|---|------|-----------------|----------------------------------|
| 1 | **`RelationshipShortlistTop2` 契约 + 快照** | 类型：`apps/api/src/modules/ai-pairwise-decision/ai-pairwise-decision.types.ts`（`RelationshipShortlistTop2`，含 `candidates` 二元组、`shortlistFingerprint`、`poolId`）。构建（非 GET）：`AiPairwiseTop2ShortlistService.buildRelationshipShortlistTop2`（`ai-pairwise-top2-shortlist.service.ts`）基于 **`PreviewPool` + `PreviewPoolItem.rankInPool` 有序** + G1-R 门禁得到 Top2。持久化：**`AiPairwiseDecisionJob.shortlistSnapshot`**（`schema.prisma` → `ai_pairwise_decision_jobs.shortlistSnapshot`）。Finalize 校验：`matching-finalize-pairwise.service.ts` 对 `shortlistSnapshot` 做 `parseAndValidateRelationshipShortlistTop2`。 | **优先**：若某次 RRM bounded run 能 **引用与之一致且已落库** 的 `shortlistSnapshot`（或下文 **static_top2_readonly_summary**），且 **fingerprint** 与 RRM job 绑定一致，则可作为 **enabled** 的 Top2 证据。 |
| 2 | **Preview pool item rank** | `PreviewPoolItem.rankInPool`（`schema.prisma`）。是 shortlist builder 的 **输入序**，本身 **不是** 独立「Top2 契约」；pool 变更后 rank 语义可能变。 | **不可单独**作为 enabled 依据；必须与 **(1) 快照** 或 **(5) 冻结 summary** 绑定。 |
| 3 | **Worker / batch 排序痕迹** | `MatchResult` 仅持久化 **单一** `candidateUserId` + `finalScore` + 可选 `matchInsights`（`schema.prisma`）。**未找到**与「该 viewer 当次 batch 的明确 Top2 列表」等价的 **稳定、版本化** 只读契约暴露给 GET。 | **默认不作为** RRM Top2 来源；若未来 worker 写入结构化 `top2CandidateUserIds`，需 **新 schemaVersion** 与 M5.3-B 评审。**当前视为未找到稳定来源**。 |
| 4 | **`finalMatchDecisionMeta.staticTop1CandidateUserId` + `pairwiseWinnerCandidateUserId`** | `final-match-decision-meta.builder.ts` / `ViewerSafeFinalMatchDecisionMeta`。表达的是 **pairwise 决策语境**下的 static Top1 与 **LLM winner**，**不是**「20 维 static 全池 Top2 排名」的冻结列表；且 winner 可能与 Top2 第二名不同语义。 | **不可**单独拼成「Static Top2」用于 RRM bounded：**两字段不构成** 经过 `RelationshipShortlistTop2` 校验的 **ordered Top2**。**不能与** (1) 的 `candidates[0].staticRank` / fingerprint 混用为同一事实来源。 |
| 5 | **`staticTop2ReadonlySummary`（未来契约）** | 见 **§10.4**。与 (1) 对齐的 **瘦身只读 DTO**，便于非 pairwise 管线复用。 | **推荐**作为 M5.3-B 写入、M5.3-C 读取的 **统一 Top2 侧车** 形态（与 RRM job、`display`  resolver 绑定同一 `fingerprint`）。 |

### 10.3 Enabled 门禁（必须写进 M5.3-B 验收）

1. **若已有稳定、可解析、已持久化的 `RelationshipShortlistTop2` 等价快照**（典型路径：`ai_pairwise_decision_jobs.shortlistSnapshot` 或 §10.4 summary），**应作为优先来源**；RRM job 必须携带 **同一 `shortlistFingerprint`（或 summary 内 fingerprint）**。
2. **若 Top2 仅存在于某次请求的临时内存计算**（未写入任何 job / meta / summary），**禁止 enabled**：只能 shadow / proposal_only，**不得**改写 `displayCandidateUserId`。
3. **若证据链只能还原 `staticTop1`（单一 candidate），没有第二人进入 bounded 集**：**禁止启用 RRM Top2 selector**（二选一无定义域）；resolver **必须 no-op** 回 **`match_result_original` 或已有 pairwise 路径**（优先级 M5.3-B 表驱动）。
4. **若 RRM 输入侧解析出的 Top2 集合**（有序或无序经规范后）与 **Static Top2 快照**（`top2CandidateUserIds` 或 `RelationshipShortlistTop2.candidates`）**在集合层面不一致**（缺人、多人、或 ID 不一致）：**必须 no-op**（**不允许**「以 RRM 为准覆盖 static」）；并应记 **audit / shadow** 原因码（字段名 M5.3-B 冻结）。

### 10.4 Future contract：`static_top2_readonly_summary`（草案 v1）

与 `RelationshipShortlistTop2` **语义对齐**的只读摘要，供 **非 pairwise** 管线（如纯 RRM Top2 bounded）引用；**字段名与枚举值可在 M5.3-B 微调**，但须满足：**可绑定 viewer + pool + fingerprint + 生成时间**。

```json
{
  "schemaVersion": 1,
  "sourceType": "static_top2_readonly_summary",
  "sourceVersion": "static-top2-v1",
  "viewerUserId": "<viewer_user_id>",
  "poolId": "<pool_id_or_null>",
  "top2CandidateUserIds": ["<candidate_a>", "<candidate_b>"],
  "baselineCandidateUserId": "<candidate_a>",
  "fingerprint": "<stable_top2_fingerprint>",
  "generatedAt": "2026-05-03T00:00:00.000Z"
}
```

**说明**：

- `top2CandidateUserIds` **长度必须为 2** 且元素互异；顺序应与 static rank（rank 1 在前）或产品在 M5.3-B 冻结的规则一致。
- `baselineCandidateUserId` 必须与 **`MatchResult.candidateUserId`**（worker 静态 Top1）一致时才允许进入「与 match 行绑定」的 enabled 路径；否则 **no-op**（与 M3.8 `staticTop1CandidateUserId === matchRow.candidateUserId` 绑定思想一致）。
- `fingerprint` 必须与 **RRM bounded job** 写入的绑定字段一致，否则 **no-op**。
- 占位符仅示意；**禁止**在文档或仓库中提交真实生产 ID。

## 11. RRM Top2 selector 输入 / 输出契约（M5.3-B 冻结）

本节定义 **bounded 二选一** 在 **写侧 / async job**（**非** `GET /matching/result`）消费与产出的 **逻辑契约**。实现可落在独立 pure function + 持久化包装；字段名可在 M5.3-B 微调，但 **语义不得漂移**。

### 11.1 契约边界

- **输入**：必须已满足 **§10**（Top2 来自持久化快照或 `static_top2_readonly_summary`；`baselineCandidateUserId === MatchResult.candidateUserId`；`top2Fingerprint` 与 RRM job 绑定一致）。
- **RRM 证据**：`rrmSimReadonlySummary` 在仓库中的 **viewer-safe 形状** 见 `apps/api/src/modules/matching/matching-rrm-sim-readonly-summary.ts`（`RrmSimReadonlySummaryPayloadV1`）；持久化键为 `matchInsights.rrmSimReadonlySummary`（`matching-multi-source-final-decision-m51m0.ts` 中 `RRM_SIM_READONLY_SUMMARY_INSIGHTS_KEY`）。selector **不得**从 raw transcript / evaluator blob 反推。
- **Guardrails 证据**：与 M5.1 侧车对齐时，**结构语义** 见 `MultiSourceGuardrailsSourceReadonly`（`matching-multi-source-final-decision-m51m0.ts`：`status`、`blockReasons`、`cautionReasons`、`sourceSummary`）。本计划用 **`guardrailsReadonlySummary`** 命名 **selector 输入切片**（可与上述类型同构或为其子集；**M5.3-B** 选定其一并单测冻结）。
- **输出**：**不**直接写 `MatchResult.candidateUserId` / `finalScore`；仅产出 **拟应用的 display 三元组建议** + **no-op 原因码**，由 **finalize 等价写路径**（侧车表 / `matchInsights` 扩展，M5.3-B 选型）落库后，再由 **`resolveMatchResultDisplay`** 同类逻辑在 GET 上 **只读投影**。

### 11.2 Selector 输入（JSON 草案）

下列对象为 **一次 selector 调用的完整输入**（占位符仅示意）。`rrmSimReadonlySummary` / `guardrailsReadonlySummary` 在真实现中应为 **已解析的 object**，文档中用 `{}` 表示「非空且通过 schema 校验」。

```json
{
  "viewerUserId": "<viewer_user_id>",
  "baselineCandidateUserId": "<candidate_a>",
  "top2CandidateUserIds": ["<candidate_a>", "<candidate_b>"],
  "currentDisplayCandidateUserId": "<candidate_a>",
  "currentDisplaySourceType": "match_result_original",
  "rrmSimReadonlySummary": {},
  "guardrailsReadonlySummary": {},
  "top2Fingerprint": "<stable_top2_fingerprint>"
}
```

| 字段 | 必填 | 语义与校验（M5.3-B 实现） |
|------|------|---------------------------|
| `viewerUserId` | 是 | 与 JWT / `MatchResult.userId` 一致。 |
| `baselineCandidateUserId` | 是 | **必须**等于 `MatchResult.candidateUserId`（worker Top1）；否则整段输入 **reject** / no-op。 |
| `top2CandidateUserIds` | 是 | **长度 2**、互异、**集合**须与 §10.4 / `RelationshipShortlistTop2.candidates` 冻结证据一致；**顺序**须与 M5.3-B 冻结的 rank 规则一致（通常 static rank 1 在前）。 |
| `currentDisplayCandidateUserId` | 是 | 调用时刻 **已解析** 的展示候选（等同 GET 上 `displayCandidateUserId` 语义），用于审计「变更前后」。 |
| `currentDisplaySourceType` | 是 | 取值须为现有 **`MatchResultDisplaySourceType`** 之一（`matching-result-display.ts`）；未知值 → no-op。 |
| `rrmSimReadonlySummary` | 是 | **viewer-safe** RRM 摘要；**winner / candidate 绑定**须落在 `top2CandidateUserIds` 集合内，否则 **§10.3 第 4 条** → no-op。 |
| `guardrailsReadonlySummary` | 是 | **enabled** 路径下 **M5.3-B** 须定义：`status === "block"` → **禁止**采纳 RRM winner；`"not_evaluated"` 是否允许进入 enabled **必须**显式策略（建议默认 **no-op** 与 M5.2 shadow 保守口径对齐）。 |
| `top2Fingerprint` | 是 | 须与 `rrmSimReadonlySummary` / 侧车上记录的绑定指纹一致；不一致 → no-op。 |

### 11.3 Selector 输出（JSON 草案）

输出供 **持久化层** 消费；**不**等同于 HTTP GET 响应体。

```json
{
  "schemaVersion": 1,
  "sourceVersion": "rrm-top2-bounded-selector-v1",
  "outcome": "applied",
  "noOpReasonCode": null,
  "proposedDisplayCandidateUserId": "<candidate_b>",
  "proposedDisplaySourceType": "rrm_top2_bounded_selector",
  "rrmWinnerCandidateUserId": "<candidate_b>",
  "baselinePreservedCandidateUserId": "<candidate_a>",
  "top2FingerprintEcho": "<stable_top2_fingerprint>",
  "guardrailsStatusEcho": "pass",
  "eligibleRulesPassed": ["top2_set_matches_static", "rrm_winner_in_top2", "guardrails_pass"],
  "generatedAt": "2026-05-03T00:00:00.000Z"
}
```

| 字段 | 语义 |
|------|------|
| `outcome` | `"applied"`：通过所有 eligible 规则，**建议**改写 display；`"no_op"`：**不**建议改写（`proposed*` 应为 `null` 或与 current 相同，由 M5.3-B 二选一冻结）。 |
| `noOpReasonCode` | 机器可读；例：`top2_mismatch`、`guardrails_block`、`guardrails_not_evaluated`、`rrm_winner_not_in_top2`、`fingerprint_mismatch`、`baseline_mismatch`、`summary_schema_invalid`（**枚举在 M5.3-B 冻结**）。 |
| `proposedDisplayCandidateUserId` | **仅**为 `top2CandidateUserIds` 之一；`outcome === "no_op"` 时为 `null` 或回显 current（二选一由 M5.3-B 固定）。 |
| `proposedDisplaySourceType` | 新枚举占位 **`rrm_top2_bounded_selector`**（与 §4 命名预案一致）；`no_op` 时不覆盖现有 source。 |
| `rrmWinnerCandidateUserId` | 从 `rrmSimReadonlySummary` 推导的 bounded winner（须在 Top2 内）。 |
| `eligibleRulesPassed` | 字符串数组，便于 M6.1 `decisionContext` 引用；**不得**含自由文本 PII。 |

### 11.4 与现有 M5.1 / M5.2 侧车的关系

- **`multiSourceFinalDecision`**（M5.2-M3）当前 **不参与** display 解析；selector **可**在写侧重复利用其中 **hydration 规则** 以组装输入，但 **enabled 采纳** 必须依赖 **本节输出 + 独立持久化**，避免把 GET 侧车误当写契约。
- **Shadow proposal**（`m5ProposedDisplayCandidateUserId` 等）与 **selector `proposed*`** 并存时，**优先级与互斥** 由 **§7** 与 **M5.3-B 优先级表** 冻结；本计划只要求：**同一 match 行同一时刻最多一个 enabled 写源**。

## 12. Eligible Rules（M5.3 enabled display 全量门禁）

以下规则须 **同时满足**，才允许 M5.3 **接管** `displayCandidateUserId` / `displaySourceType`（写侧落库 + GET 投影）。任一不满足 → **§13 fallback**（no-op）。**M5.3-B** 应将每条规则映射为 **单测 + 可选遥测计数器**（不含 PII）。

1. **`PEIMA_M5_RRM_TOP2_ENABLED=true`**（命名预案；**M5.3-B** 若采用不同 env key，须在本文件修订记录中 **显式改名** 并同步 `.env.example`）。**未设置或非 true** → 整段 M5.3 逻辑短路。
2. **Top2 来源存在且可信**：满足 **§10**（持久化 `RelationshipShortlistTop2` 等价快照或 `static_top2_readonly_summary`）；**不得**依赖 GET 上临时重算。
3. **Top2 exactly 2 个不同 candidate**：`top2CandidateUserIds` 长度 **= 2** 且 **去重后仍为 2**。
4. **Top2 fingerprint 与 RRM-Sim summary 对齐**（或经 M5.3-B 书面批准的 **等价稳定绑定**，例如侧车 JSON 内嵌同一 `fingerprint` / `shortlistFingerprint` 字段）；**不得**仅凭 poolId 弱关联。
5. **`rrmSimReadonlySummary` available**：可解析为 **`RrmSimReadonlySummaryPayloadV1`**（`matching-rrm-sim-readonly-summary.ts`），且 `sourceVersion` 落在 M5.1/M5.2 parser **allow-list**（见 `matching-multi-source-final-decision-m51m0.ts` 中 `ALLOWED_RRM_SIM_READONLY_SOURCE_VERSIONS`）；否则视为 **unavailable**。
6. **RRM winner 在 Top2 内**：从 summary 推导的 **bounded winner**（见 §11.3 `rrmWinnerCandidateUserId` 语义）**必须** ∈ `top2CandidateUserIds`（集合相等性校验见 §10.3-4）。
7. **RRM `confidenceBucket` 不是 `low`**：字段来源为 `RrmSimReadonlySummaryPayloadV1.confidenceBucket`。**`unknown`** 在 **M5.3 初始 enabled 版本** 视为 **不满足**（与「保守默认」一致）；**M5.3-B** 若放宽须在修订记录中单独立项。
8. **`fallbackUsed !== true`**：对应 summary 字段 `fallbackUsed`；为 `true` → **不满足**。
9. **Guardrails `status` 必须是明确的 `pass`**：以 `MultiSourceGuardrailsSourceReadonly.status`（`matching-multi-source-final-decision-m51m0.ts`）为准。
10. **不能把 `viewer_safe_no_caution_signal` 当成明确 pass**：该字符串出现在 M5.2 **shadow audit** 聚合条件中（`matching-m5-shadow-audit.ts`：对 `sourceSummary` 的 **组合**判断），**不得**在 M5.3 enabled 路径中简化为「字符串相等即 pass」。Enabled **必须**校验 **`status === "pass"`** 且 **`blockReasons` 为空**（及 M5.3-B 冻结的任何附加不变式）。
11. **`currentDisplayCandidateUserId` 可读**：非空、存在于 `User`、且与 **当前** `resolveMatchResultDisplay` 语义一致；解析失败 → no-op。
12. **Rollback path 明确**：须能仅通过 **关 env / 删或失效侧车记录 / resolver 优先级** 回到 **M3.8 既有 display**（含 `match_result_original` 与 pairwise finalize 路径）；**不得**依赖手工改 `MatchResult` 行。
13. **`displaySourceType` 新枚举已在 API / Web 类型中同步**：`rrm_top2_bounded_selector`（或最终命名）须进入 **`MatchResultDisplaySourceType`**（`matching-result-display.ts`）、**`MatchingResultResponse`**（`apps/web/src/api/matching.ts`）及 **FinalMatchPage / 技术细节组件** 的联合类型或分支；**未同步类型前不得宣称 enabled GA**。
14. **不暴露另一候选人的敏感比较**：viewer-safe meta **不得**包含对 **非** `newDisplayCandidateUserId` 的逐维对比、贬损文案或可反推身份的细节；侧车审计可走 Admin **脱敏**通道（**M5.3-D**）。

### 12.1 Guardrails `caution` 策略（初始 enabled）

- **M5.3 初始 enabled 版本不允许** 在 `guardrails.status === "caution"` 时 **自动** 采纳 RRM 改写 display；**等同不满足 §12-9**（走 §13）。
- **`caution`** 仅进入 **shadow / audit**（与 M5.2 侧车、`multiSourceFinalDecision` 观测一致）。
- **`caution` 下仍 enabled 接管 display** 留到 **后续灰度阶段**（单独里程碑 / feature sub-flag；**不在** M5.3-C 默认交付范围）。

## 13. Fallback Rules（no-op 全集）

凡触发下列任一条件，**不**应用 M5.3 展示改写，**保留 M3.8 当前 display 解析结果**（即：等价于「本轮 M5.3 **无资格**接管」）。**Fallback 不代表错误**；表示 **guard 未通过或证据不足**，产品应 **静默** 保持用户已熟悉的展示（与 §7「默认 off」一致）。

| 条件 | 行为 |
|------|------|
| env off（`PEIMA_M5_RRM_TOP2_ENABLED` 未启用） | 保留 M3.8 current display |
| Top2 missing（无持久化快照 / summary） | 保留 M3.8 current display |
| Top2 **不足** 2 个 | 保留 M3.8 current display |
| Top2 **多于** 2 个（未规范为 bounded 集） | 保留 M3.8 current display |
| Top2 **重复** candidate | 保留 M3.8 current display |
| RRM summary missing / schema 非法 / allow-list 拒绝 | 保留 M3.8 current display |
| RRM winner **不在** Top2 | 保留 M3.8 current display |
| RRM `confidenceBucket === "low"`（或 `unknown` per §12-7） | 保留 M3.8 current display |
| RRM `fallbackUsed === true` | 保留 M3.8 current display |
| Guardrails `block` | 保留 M3.8 current display |
| Guardrails `caution`（**初期**，见 §12.1） | 保留 M3.8 current display |
| Guardrails `not_evaluated` | 保留 M3.8 current display |
| fingerprint mismatch | 保留 M3.8 current display |
| `currentDisplaySourceType` **非**已知枚举 / 类型不支持 | 保留 M3.8 current display |

**与 §11 对齐**：上表每一行应能映射到 **`noOpReasonCode`**（§11.3）之一，便于审计与 M6.1 `decisionContext`。

## 14. Display 应用规则与 meta 记录草案

### 14.1 允许改变（M5.3 enabled 且通过 §12）

- **`displayCandidateUserId`**（GET 聚合字段，见 §3）。
- **`displaySourceType`**（扩展枚举后，取值如 `rrm_top2_bounded_selector`）。
- **`finalMatchDecisionMeta` 或等价侧车 meta** 中的 **display decision trace**（viewer-safe 子集）：须能回答 **谁 → 谁**、**哪条规则**、**哪枚 fingerprint**、**是否可回滚**，**不得**写入 raw RRM 维度分或完整 prompt。

### 14.2 禁止改变（红线，与 §5.2 / M3.8 一致）

- **`MatchResult.candidateUserId`**
- **`finalScore`**（行上分数）
- **`user_profile` / questionnaire 原始答卷**（不得借 display 改写之机回写画像）
- **Static baseline** 语义（worker Top1 行含义不变）
- **RRM evaluator 原始输出**（不得为适配 display 而篡改已落库的 evaluator JSON；仅允许 **新建** viewer-safe 摘要层）

### 14.3 建议持久化的 viewer-safe 记录（JSON 草案）

可与 **`FinalMatchDecisionMetaV1`** 并行 **新 schemaVersion** 或扩展字段（**M5.3-B** 选型）；下列为 **最小** 可审计切片：

```json
{
  "sourceType": "rrm_top2_bounded_selector",
  "sourceVersion": "m5.3-rrm-top2-enabled-display-v1",
  "baselineCandidateUserId": "<candidate_a>",
  "previousDisplayCandidateUserId": "<candidate_a>",
  "newDisplayCandidateUserId": "<candidate_b>",
  "decisionRule": "rrm_top2_winner_guardrails_pass",
  "top2Fingerprint": "<stable_top2_fingerprint>",
  "appliedToFinalScore": false,
  "appliedToWorkerRanking": false,
  "rollbackAvailable": true
}
```

- **`appliedToFinalScore` / `appliedToWorkerRanking`**：须 **恒为 `false`**，与 M3.8 finalize meta 及 `parseFinalizeMetaV1Loose` 约束一致；若未来扩展为可写 **true**，须 **新里程碑**，**禁止**在 M5.3 内打开。
- **`decisionRule`**：枚举由 **M5.3-B** 冻结；须与 §11.3 `eligibleRulesPassed` / `noOpReasonCode` 可互查。
- 占位符仅示意；**禁止**提交真实 ID。
