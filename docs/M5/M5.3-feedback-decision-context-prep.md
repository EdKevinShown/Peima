# M5.3-E — Feedback decisionContext Prep

## 1. 一句话结论

M5.3-E 只为 M6.1 feedback attribution 做准备。Feedback 可以记录 RRM Top2 display decision 的 context，但不能自动修改最终匹配结果、画像、RRM meta 或 finalScore。

## 2. 当前状态

- **M5.3 resolver（C1 / C2 / C2.1）**：在 `PEIMA_M5_RRM_TOP2_ENABLED` 为 on 且 eligible 时，`GET` 读路径可返回 `displaySourceType = rrm_top2_bounded_selector`，并将 RRM 选中的候选人投影到 `displayCandidateUserId`；**`MatchResult.candidateUserId` 与 `finalScore` 不变**；不写 `MatchResult`；RRM 命中时 `finalMatchDecisionMeta` 仍为 `null`（避免伪造 Pairwise 形 meta）。实现见 `apps/api/src/modules/matching/matching-result-display.ts`；回归见 `docs/M5/M5.3-enabled-display-regression-run-round1.md`。
- **Feedback（M6.0 基线）**：`UserFeedback` 已持久化（`packages/database/prisma/schema.prisma`：`structuredPayload Json?`）；`CreateFeedbackDto` 允许可选 `structuredPayload: Record<string, unknown>`（`apps/api/src/modules/feedback/dto/create-feedback.dto.ts`）。**当前写入路径**：若携带 `structuredPayload`，`FeedbackService.create` 仅走 **`assertValidP612StructuredPayloadV0`**（`apps/api/src/modules/feedback/p612-structured-payload-v0.validate.ts`），即 **P6.12 会话结构化反馈**（`sourceVersion === p6.12-chat-feedback-structured-v0`、`subjectKind === conversation` 等）。**尚未**有专用于「最终匹配 / display」的 `decisionContext` schema 或 `sourceVersion` 分支。
- **Matching 响应类型**：`MatchingResultResponse`（`apps/web/src/api/matching.ts`）已含 `displayCandidateUserId`、`displaySourceType`（含 `rrm_top2_bounded_selector`）、`finalMatchDecisionMeta` 等，可供 **M6.1** 在客户端或中间层组装 **viewer-safe** 的 `decisionContext` 快照（本里程碑不写代码）。
- **M6.0 文档索引**：仓库内无独立 `docs/M6/M6.0-*.md`；**M6.0 Feedback 基础能力**在 [M5.0-B — Multi-source Matching Decision Plan](./M5.0-multi-source-matching-decision-plan.md) §2 表格中定义为已完成（`UserFeedback`、`structuredPayload` 等），并标明 **M6.1** 负责 **`decisionContext`**。
- **M6.1 目标**：把用户反馈与 **当时生效的 display decision**（baseline / pairwise finalize / RRM Top2 bounded）**归因关联**，供 M9 聚合分析；**不**反向驱动 resolver 或写回匹配主数据。

## 3. decisionContext 推荐形状

建议 **M6.1** 采用的 JSON 形状（**viewer-safe、可归因、可版本演进**；字段名可在实现时微调，但语义应保持一致）：

```json
{
  "schemaVersion": 1,
  "decisionSourceType": "rrm_top2_bounded_selector",
  "displaySourceType": "rrm_top2_bounded_selector",
  "displayCandidateUserId": "<candidate_id>",
  "baselineCandidateUserId": "<candidate_id>",
  "decisionRule": "rrm_top2_winner_guardrails_pass",
  "rrmSupported": "top2_selector",
  "baselineCandidatePreserved": true,
  "finalScoreChanged": false,
  "wouldChangeDisplayOnly": true,
  "top2SelectorEnabled": true,
  "top2Fingerprint": "<stable_top2_fingerprint_or_null>",
  "feedbackAttributionOnly": true,
  "assistantAdviceType": null,
  "timelineRrmSignal": null
}
```

**禁止放入 `decisionContext` 的内容（与 M5.0 / M5.3 计划一致）**：

- 不放 **raw score**、公式、维度向量（含 C/A/S/E/F/Q/D/R 等实现细节）。
- 不放 **transcript**、**prompt**、模型原始输出。
- 不放 **另一候选人的敏感比较**（可识别对端、可复原 pairwise 全文等）。

**说明**：

- `decisionSourceType` / `displaySourceType` 在归因层可与 API 的 `displaySourceType` 对齐；反馈侧另可用 §4 的 **映射枚举**做聚合桶。
- `top2Fingerprint` 仅允许来自 **已持久化侧车**（如 `MatchResultRrmTop2DisplayMeta.top2Fingerprint`）的 **稳定摘要指针**；若无则 `null`。
- `feedbackAttributionOnly: true` 强调该对象 **不参与** 任何自动写回或重算。

## 4. displaySourceType 映射

为 **M9 聚合与报表**，建议将 API 层的 `displaySourceType`（及相近取值）映射到 **feedback 归因桶** `decisionSourceType`（或单独字段 `feedbackDisplayAttribution`）：

| API / resolver `displaySourceType`（或等价） | 反馈归因桶（建议枚举值） |
|-----------------------------------------------|-------------------------|
| `match_result_original` | `baseline_match_result` |
| `pairwise_final` 及既有 **pairwise finalize 展示**相关取值 | `pairwise_finalize_display` |
| `rrm_top2_bounded_selector` | `rrm_top2_display` |
| 未知或未识别 | `unknown_display_source` |

**注意**：`static_final` / `static_fallback` 等仍属 **static / pairwise 元数据驱动** 的展示语义；M6.1 实现时可归入 `pairwise_finalize_display` 或与 `baseline_match_result` 二选一策略，**须在 M6.1 实现 PR 中写清单表冻结**，本 prep 文档不强行唯一映射。

## 5. Feedback 行为红线

- Feedback **不**自动改 `MatchResult.candidateUserId`。
- Feedback **不**自动改 `finalScore`。
- Feedback **不**自动改 `displayCandidateUserId`（展示仍只由 matching 读路径与既有 writer 决定）。
- Feedback **不**自动改 `displaySourceType`。
- Feedback **不**自动改 **RRM Top2 meta**（`match_result_rrm_top2_display_meta` 等）。
- Feedback **不**自动改 **`user_profile`** 或问卷主数据。
- Feedback **不**自动触发 **重新匹配**、worker 重跑、或 Pairwise / RRM evaluator 的 **写路径**。
- Feedback 数据 **只**进入后续 **M9 evaluation / aggregate analysis**（及人工运营流程若另行定义），**不**作为 resolver 输入。

## 6. M6.1 最小代码建议

若后续实现（**不在 M5.3-E 范围**），建议顺序：

1. **新增** `buildFeedbackDecisionContextFromMatchResultDisplay(...)`（或同名 util）：入参为 **已返回给 viewer 的** `MatchingResultResponse` 子集（`displayCandidateUserId`、`displaySourceType`、`candidateUserId`、`finalScore`、可选 `top2Fingerprint` 指针等），出参为 §3 的 **viewer-safe** 对象；**不**调用 Prisma、**不**重算 Top2、**不**调 RRM evaluator。
2. **提交 feedback 时**可选携带 `structuredPayload.decisionContext`（或顶层并列字段，需与 DTO / DB 一致）；**新增** `sourceVersion`（例如 `m6.1-match-feedback-decision-context-v1`）与 **独立校验器**（白名单键 + 类型 + 长度上限），与 **P6.12** 分支 **互斥或并列分支**（避免破坏现有 `p612-structured-payload-v0.validate` 契约）。
3. **后端**对 `decisionContext` 只做 **schema validation + 大小限制**，不做业务副作用。
4. 持久化：写入 **`user_feedbacks.structuredPayload`**（或未来拆列，需新 migration，**非**本里程碑）。
5. **不影响** `resolveMatchResultDisplay` 与 **GET `/matching/result`** 读路径。

## 7. Admin / Evaluation 用途

未来 **M9** 可基于 §3 / §4 字段统计（示例）：

- **`rrm_top2_display`** 桶下的 positive / negative feedback 占比。
- **`pairwise_finalize_display`** 桶下的 positive / negative feedback 占比。
- **`baseline_match_result`** 桶下的 positive / negative feedback 占比。
- **`wouldChangeDisplayOnly === true`** 且用户对 **展示对象** 的满意度（与 baseline 对比时 **仅用归因字段**，不拉 raw 分）。
- **Guardrails caution / fallback** 之后（若 `decisionRule` 或侧车 reason code 扩展）的反馈分布。
