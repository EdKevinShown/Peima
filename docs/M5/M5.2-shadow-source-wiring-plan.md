# M5.2-M1 — Shadow Source Wiring Plan

本文档 **只规划** M5.2 后续真正进行 **shadow decision** 时，各 **source** 的安全接入方式；**不实现代码**。  
上游规范：[M5.0-rrm-context-adapter-spec.md](./M5.0-rrm-context-adapter-spec.md)、[M5.0-multi-source-matching-decision-plan.md](./M5.0-multi-source-matching-decision-plan.md)。  
当前侧车实现以 `apps/api/src/modules/matching/matching-multi-source-final-decision-m51m0.ts` 为准。

---

## 1. 一句话结论

**M5.2-M1** 只回答「shadow proposal 需要哪些 **viewer-safe** 输入、从哪里读、缺口在哪、哪一阶段补」，**不写代码**。  
**M5.2-M0** 已在 `GET /matching/result` 上提供 **shadow contract**（`mode` / `shadow` / `decisionTrace`），但 **仍不产生** `m5ProposedDisplayCandidateUserId`。  
真正 **shadow proposed display** 必须等 **Pairwise / RRM-Sim / Guardrails** 的 **viewer-safe 信号**在单一读路径上 **可依赖、可版本化、可测试** 后再做（**M5.2-M2+**）。  
**禁止**为迁就文档完整性而改代码或「临时补字段」。

**表内建议结论（与上表一致）**

- **MatchResult baseline / Current display**：已可支撑 **对比** 与 **契约**。
- **Pairwise finalize meta**：**部分可用**，可作 pairwise 分支信号，**不可**单独定 shadow proposal。
- **RRM-Sim readonly summary**：**默认不可用** → **核心缺口**；**M5.2-M2** 前的硬前置是 **写入 viewer-safe 摘要**（§5）。
- **Guardrails**：当前 **仅有 caution 级** 材料，**block 级不完整**。
- **Static 全量排序 / Admin / batch / local report**：**不**进入 viewer GET shadow 决策输入。

## 4. Pairwise Source 计划

### 4.1 当前 GET 路径上已存在的 viewer-safe 字段（`finalMatchDecisionMeta`）

与实现及 `FinalMatchDecisionMetaV1` 设计一致，可依赖字段包括：

- `selectedCandidateUserId`
- `pairwiseWinnerCandidateUserId`
- `staticTop1CandidateUserId`
- `sourceType`
- `mode`
- `pairwiseProposalRecommendation`
- `fallbackReason`
- `wouldChangeStaticResult`
- `appliedToFinalScore`（恒 `false` 契约）
- `appliedToWorkerRanking`（恒 `false` 契约）
- `frozen`
- `frozenAt`

### 4.2 明确禁止（M5.2 仍遵守）

- **禁止**在 `GET /matching/result` read path **查 raw pairwise job** 以推断 **`decisionConfidence` / `strongRisk`**。
- **禁止**为补齐 Pairwise **新增复杂 DB 查询**（与 M5.1-M2 红线一致）。
- **禁止**把 **RRM-lite pairwise JSON** 当作 **RRM-Sim**（见 M5.0-A）。

### 4.3 Shadow 中的角色

- Pairwise 可作为 **「Top2 内关系判断」** 的 **候选信号**。
- **不得**单独触发 **M5 shadow proposed candidate**（需与 **RRM-Sim 摘要** 与 **guardrail 门控** 组合，见 M5.0-B 多源原则）。
- **推荐门闩（规划）**：**Pairwise 与 RRM-Sim** 在 **viewer-safe** 前提下 **方向一致** 且 **无 guardrail 否决** 时，才允许进入 **shadow 候选集**（具体规则 **M5.2-M2** 冻结）。

## 5. RRM-Sim Source 计划（核心缺口）

### 5.1 当前事实（代码层）

- **`evaluateRrmSimFromSimulationV2` + `rrm-sim-extractor`**：仓库内 **唯一** 完整 **C/A/S/E/F/Q/D/R** 闭环（M5.0-A）。
- **`GET /matching/result`**：**默认** 无内嵌完整 RRM-Sim DTO；RRM 主数据仍在 **`ai_simulation` job**、**M4.0 readonly proposal**、**M4.1 comparison**、**M4.2 batch** 等路径。
- **M5.1-M2** 已预留 **`matchInsights.rrmSimReadonlySummary`**（常量键 `rrmSimReadonlySummary`），白名单 **`sourceVersion`**：`rrm-sim-v1`、`m4.0-readonly-rrm-ranking-proposal-v1`；且需 **`suggestedAction` / `progressionWindow` / `simulatedRhythmScore`** 至少其一。

### 5.2 三种接入方案比较

#### Option A：`GET /matching/result` read path **主动查询** M4.0 proposal / M4.1 comparison

| 项 | 内容 |
|----|------|
| 思路 | 在 GET 时按 `poolId` / `viewerUserId` 拉 proposal 或四源对照。 |
| **结论** | **不推荐**作为 M5.2 **首选**。 |
| 原因 | GET **变重**、延迟与缓存复杂；与 **admin/evaluation** 路径 **耦合**；失败面扩大（pool 缺失、job 未完成、权限边界）。 |

#### Option B：在 **RRM proposal / comparison / simulation 完成时** 写入 **viewer-safe `rrmSimReadonlySummary`**

| 项 | 内容 |
|----|------|
| 思路 | 异步或写路径生成 **精简摘要**（无公式、无 raw 向量），写入 **`matchInsights.rrmSimReadonlySummary`** 或 **未来 M5 侧车 meta**（持久化策略 **M5.2-M3** 定）。 |
| **结论** | **推荐**作为 **M5.2-M2 或 M5.2-M3** 的 **优先路线**。 |
| 原因 | **GET 保持轻**；契约与 **M5.1-M2 解析器** 对齐；可单测、可版本化；符合 M5.0-A「不混用 adapter」。 |

#### Option C：新增 **M5 source aggregation** 层（独立服务 / 模块）

| 项 | 内容 |
|----|------|
| 思路 | 聚合 pairwise + rrm + guardrail，read path **轻量调用**或异步物化。 |
| **结论** | **中期可行**；**不适合**作为 M5.2-M1 立即编码任务。 |
| 原因 | 架构收益高，但引入 **部署边界、缓存、一致性**；适合 **M5.2-M3 后** 或 **M5.3 前** 结构化。 |

### 5.3 推荐路线（冻结给 M5.2-M2/M3）

**M5.2 推荐先走 Option B：**

1. 在 **simulation job 完成 / M4.0 proposal 定稿 / M4.1 comparison 快照** 等 **已有 RRM 结果** 的时刻，生成 **viewer-safe** `rrmSimReadonlySummary`（字段见 §6）。  
2. **写入** `matchInsights`（或未来 **专用 sidecar 表** —— **M5.2-M3** 决策）。  
3. **`GET /matching/result`** **只消费** 已写入摘要，**不**在 read path **重查** M4.0 / M4.1 **、不**重跑 **evaluator**。

**不要让 `GET /matching/result` 临时去重查 RRM proposal / comparison** —— 避免读路径变重与行为分叉。

## 6. `rrmSimReadonlySummary` 推荐契约（对齐 M5.1-M2 解析器）

以下 JSON **为推荐形状**；**须与实现一致**：`schemaVersion` 为 **数字** `1`；`simulatedRhythmScore` 为 **number**（0–100，与 `RrmSimResult` 百分制一致）；`suggestedAction` 须为产品 **RRM 侧车枚举**（如 `maintain`、`continue_lightly`、`slow_down` 等），**勿**使用未定义自由字符串冒充枚举。

```json
{
  "schemaVersion": 1,
  "sourceType": "rrm_sim_readonly_summary",
  "sourceVersion": "rrm-sim-v1",
  "candidateUserId": "candidate_user_id",
  "winnerUserId": "candidate_user_id",
  "proposalCandidateUserId": "candidate_user_id",
  "scenarioKey": "early_conversation",
  "suggestedAction": "maintain",
  "progressionWindow": "weak_open",
  "simulatedRhythmScore": 62,
  "recommendation": "diagnostic_only",
  "confidenceBucket": "medium",
  "fallbackUsed": false,
  "unavailableReason": null,
  "cautionFlags": ["pace_mismatch"],
  "generatedAt": "2026-05-01T00:00:00.000Z",
  "frozenAt": null
}
```

**说明**

- `sourceVersion` 亦可为 **`m4.0-readonly-rrm-ranking-proposal-v1`**（与解析器白名单一致），表示 **M4.0 只读提案** 的 **echo**，仍 **不得**含 raw 公式向量。  
- **至少提供** `suggestedAction`、`progressionWindow`、`simulatedRhythmScore` **之一**，否则解析器返回 `null`（与当前代码一致）。  
- **禁止**在摘要中塞入 **另一候选人** 对比明细、**raw C/A/S/E/F/Q/D/R**、或 **完整 simulation transcript**。

## 7. Guardrails Source 计划

### 7.1 当前 guardrails 信号主要来自何处

与 **`matching-multi-source-final-decision-m51m0.ts`** 中 **只读 hydration** 一致，当前 **可依赖** 的输入仅有：

- `matchInsights.explanation.cautions`
- `matchInsights.riskFlags`
- **`finalMatchDecisionMeta`** 上的 viewer-safe **`fallbackReason`**（finalize 路径）

以上材料在侧车中至多推导出 **`caution`** 或 **`not_evaluated`** 级别的 **`sources.guardrails`**；**不是**完整产品级 guardrail 引擎。

### 7.2 当前限制（冻结到 M5.2-M2 前）

- **不读取** raw pairwise job 中的 **`strongRisk`**（GET read path 禁止补查）。
- **不新增** guardrail **计算**（不在 GET 上为「好看」而加规则分支）。
- **没有**明确 **`block` / `pass`** 的 viewer-safe 枚举来源时，侧车只能 **`caution` / `not_evaluated`**（与现实现一致）。
- **M5.2 shadow proposal**：在 guardrails **语义不清**（仅有零散 caution、无统一 `status: block` 证据链）时，**不得**做强切换或高风险 **proposed** 展示升级；策略应保持 **conservative**（与 M5.0-B **Guardrail-first** 一致）。

### 7.3 推荐路线（进入 M5.2-M2 / M5.2-M3 的前置）

- **M5.2-M2 之前**：先定义 **viewer-safe guardrail summary** 的 **写入契约**（与 RRM 摘要类似：**写入侧**生成、**GET** 只读）。
- **`status`** 建议显式支持：`pass` \| `caution` \| `block` \| `not_evaluated`。
- **`blockReasons` / `cautionReasons`**：短枚举或短 code 列表，**禁止** raw LLM 全文、禁止另一候选人敏感对比。
- **无** `block` / `pass` 的明确信号时：**shadow proposal** 仍 **保守**（等价于不生成可采纳的 `m5ProposedDisplayCandidateUserId`，直至 **M5.2-M3** 规则冻结）。

### 7.4 建议契约（规划稿，非当前 GET 必填字段）

写入位置可为 **`matchInsights.guardrailsReadonlySummary`** 或 **未来 M5 侧车 JSON**（与 `rrmSimReadonlySummary` 同层级策略）；**当前仓库未实现该写入**，下文仅供 **M5.2-M2+** 对齐。

```json
{
  "schemaVersion": 1,
  "sourceVersion": "m5-guardrails-summary-v1",
  "status": "pass",
  "blockReasons": [],
  "cautionReasons": []
}
```

**说明**：`status` 的取值语义须在实现时与 **Pairwise finalize**、**RRM-Sim 门控**、**静态底线** 的合成顺序一起评审；**M5.2-M1 不实现**。

## 8. Static Source 计划

### 8.1 当前事实

- **`GET /matching/result`** **不保证**携带 **完整 static shortlist / Top-K 排名**；worker 主排序细节 **不**作为标准字段暴露在 viewer payload 中。
- 因此 **M5.1 / M5.2 早期**：仅能将 **`MatchResult.candidateUserId`** 视作 **static-derived baseline**（与 M5.0-B、§3 总览表一致），**不应**在文档或产品中声称「已重新读取完整 Static shortlist」。

### 8.2 若未来需要显式 static Top-K（前置条件）

须在规格中 **单独固定来源**之一（或多源组合），例如：

- `MatchResult` 或侧车上的 **静态摘要指针**（**非**本轮已有字段）
- **preview pool** 内条目的 **rank**（需 pool 与 match 行绑定策略）
- **worker ranking trace**（若产品决定持久化 **viewer-safe** 片段）
- **future `staticReadonlySummary`** 一类契约（与 `rrmSimReadonlySummary` 对称）

**在以上任一来源未落地前**：**M5.2 shadow proposal 早期不依赖完整 static Top-K**，只做 **baseline 对照** 与 **与 finalize meta 内 `staticTop1CandidateUserId` 的对齐**（后者已属 Pairwise finalize viewer-safe 切片，见 §4）。

## 9. M5.2 Shadow Proposal 前置条件

在进入 **M5.2-M2 / M5.2-M3** 并允许在 sidecar 上 **计算** shadow 层 **`m5ProposedDisplayCandidateUserId`**（**仍不**应用 `display`）之前，**至少**需要同时满足：

1. **Pairwise viewer-safe winner 可用**：`finalMatchDecisionMeta` 已存在且 **`pairwiseWinnerCandidateUserId`**（或与 `selectedCandidateUserId` 一致的 winner 语义）在 **Top2 / finalize 契约**下可解释。  
2. **RRM-Sim viewer-safe winner 可用**：`matchInsights.rrmSimReadonlySummary` **已写入**且通过 **M5.1-M2** 解析契约，且 **`fallbackUsed` 不为 true**、**非** invalid contract（即 **RRM-Sim 不能处于 fallback / 非法** 状态参与共识）。  
3. **Guardrails `status` 至少不是 `block`**：若仅有 §7 现状，则须 **已落地** §7.3 的 **guardrailsReadonlySummary**（或等效 viewer-safe 块）；**在仅有 caution / not_evaluated 时** shadow **保持保守**（见 §7.2）。  
4. **Pairwise 与 RRM-Sim 对同一 `candidateUserId` 达成共识**（规划语义：二者推荐的 **viewer-safe winner** 指向 **同一** 候选人；具体判定 **M5.2-M3** 冻结）。  
5. **`currentDisplayCandidateUserId`**（及 `displaySourceType`）已由 **`resolveMatchResultDisplay`** 正确解析，可作为 delta 对照基准。  
6. **不暴露** raw score、公式、完整 simulation transcript、prompt、或 **另一候选人** 敏感对比（红线见 §11）。  
7. **`m5AppliedToDisplay` 在 M5.2-M2/M3 仍为 `false`**；**M5.3 enabled display** 才允许在严格开关与 guardrail 下改变 **展示层**（仍 **不改** `MatchResult.candidateUserId` / `finalScore`）。

**阶段边界（再次强调）**

- **M5.2-M1**：**不**计算 proposed candidate。  
- **M5.2-M2 / M5.2-M3**：才允许在 sidecar 内 **计算** **`m5ProposedDisplayCandidateUserId`**（及 `wouldChangeCurrentDisplay` 等 **shadow 语义字段**），且 **默认仍不写 DB**（持久化 **M5.2-M4** 另议）。  
- **M5.3**：**enabled display** —— 展示层采纳 proposed 的规则与回滚，**仍不**覆盖 `MatchResult.candidateUserId` / `finalScore`（与 M5.0-B 一致）。

## 10. 后续阶段建议

### M5.2-M2 — Viewer-safe RRM-Sim Summary Writer

**目标**：在 **RRM proposal / comparison / simulation** 等 **已有产出** 的时刻，生成 **viewer-safe** 摘要并写入 **`matchInsights.rrmSimReadonlySummary`**（或 **future meta**），使 `GET /matching/result` **只读消费**，**不改变** `display`。  
**前置**：§5 Option B 路线评审通过；与 **M5.1-M2** 解析白名单对齐。

### M5.2-M3 — Shadow Proposal Computation

**目标**：在 **`multiSourceFinalDecision`** 内 **计算** **`m5ProposedDisplayCandidateUserId`**（及 `wouldChangeCurrentDisplay` 等），**仍不**应用至 `displayCandidateUserId`；**不写** `MatchResult`。  
**条件**：**Pairwise + RRM-Sim consensus** 且 **Guardrails 非 `block`**（§9）；**禁止** Pairwise 或 RRM-Sim **单独**触发 proposal。

### M5.2-M4 — Shadow Run Record / Admin Audit

**目标**：统计 **`wouldChangeCurrentDisplay`** 比例、**missing source** 比例、**consensus** 比例、**blocked** 比例；可先 **CLI / 结构化日志**，**不**强求立刻有 Admin dashboard。  
**前置**：M5.2-M3 产出可观测字段；**脱敏**要求同 M4.2。

### M5.3 — Enabled Display

**目标**：在 **环境开关 + 严格 guardrail** 下，允许 **展示层**使用 M5 proposed candidate（**`displayCandidateUserId`** 解析规则扩展）；**仍不**改 **`MatchResult.candidateUserId`**、**不改 `finalScore`**。  
**前置**：M5.2-M4 观测与回滚策略就绪。

## 11. 红线

1. **不在** `GET` read path **主动运行** RRM **evaluator**。  
2. **不在** `GET` read path **主动生成** RRM **proposal**（不调用 M4.0/M4.1 服务补数）。  
3. **不把** admin / batch regression / local report 数据 **直接暴露**给 viewer `GET /matching/result`。  
4. **不暴露** raw score。
