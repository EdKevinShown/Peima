# M5.2-M1 — Shadow Source Wiring Plan

本文档 **只规划** M5.2 后续真正进行 **shadow decision** 时，各 **source** 的安全接入方式；**不实现代码**。  
上游规范：[M5.0-rrm-context-adapter-spec.md](./M5.0-rrm-context-adapter-spec.md)、[M5.0-multi-source-matching-decision-plan.md](./M5.0-multi-source-matching-decision-plan.md)。  
当前侧车实现以 `apps/api/src/modules/matching/matching-multi-source-final-decision-m51m0.ts` 为准。

---

## 1. 一句话结论

**M5.2-M1** 只回答「shadow proposal 需要哪些 **viewer-safe** 输入、从哪里读、缺口在哪、哪一阶段补」，**不写代码**。  
**M5.2-M0** 已在 `GET /matching/result` 上提供 **shadow contract**（`mode` / `shadow` / `decisionTrace`），但 **仍不产生** `m5ProposedDisplayCandidateUserId`。  
真正 **shadow proposed display** 必须等 **Pairwise / RRM-Sim / Guardrails** 的 **viewer-safe 信号**在单一读路径上 **可依赖、可版本化、可测试** 后再做（**M5.2-M2+**）。  
**禁止**为迁就文档完整性而改代码或「临时补字段」。

## 3. Source Wiring 总览表

| Source | 当前是否可用 | 当前读取位置 | 是否 viewer-safe | 是否可用于 M5.2 shadow proposal | 缺口 | 推荐接入阶段 |
|--------|--------------|--------------|------------------|-----------------------------------|------|----------------|
| **MatchResult baseline** | **可用** | `MatchResult` 行：`candidateUserId`、`finalScore`、`reasonSummary` 等 | 是（已暴露字段） | **是**（作为 **baseline** 与合法性锚点） | 无 | **M5.2-M2** 起参与对比 `wouldChangeCurrentDisplay` |
| **Current display** | **可用** | `resolveMatchResultDisplay` → `displayCandidateUserId`、`displaySourceType`、`finalMatchDecisionMeta` | 是（finalize meta 已 viewer-safe 约束） | **是**（shadow 只算「相对当前展示」的 delta，**不**回写） | 与 pool 绑定依赖 finalize 环境开关 | **M5.2-M2** |
| **Pairwise finalize meta** | **部分可用** | `pairwise_pool_finalize_meta` → `ViewerSafeFinalMatchDecisionMeta` | **是**（无 raw 分 / 维度 / strongRisk） | **部分**（可作 **强信号之一**，**不可**单独触发 shadow proposal） | **无** `confidence` / **`strongRisk`** 于 GET 路径；**禁止**在 GET read path 查 raw pairwise job 补齐 | **M5.2-M2** 消费现有字段；若需更强 gate 再走 **写入侧** viewer-safe 摘要（见 §4） |
| **RRM-Sim readonly summary** | **默认不可用** | 仅当 `matchInsights.rrmSimReadonlySummary` 合法存在 | **设计为是**（白名单 `sourceVersion`） | **条件可用**（hydrated 后才参与） | **生产默认未写入**；主 RRM 仍在 **simulation job / M4.0 / M4.1 / batch** | **M5.2-M2 / M5.2-M3** 走 **§5 Option B** |
| **Guardrails / caution** | **部分可用** | `matchInsights` cautions / riskFlags；finalize `fallbackReason`；**无**独立 block 枚举 | **部分**（caution 级摘要有；**非**完整 guardrail 引擎） | **部分**（可作 **否决/降级** 的弱输入） | **无** 统一 `guardrailStatus: block` 的只读来源；**不**在 GET 上新增计算 | **M5.2-M2** 继续只用现有摘要；完整 block 需 **M5.3 前** 单独设计 |
| **Static full ranking** | **不可用（完整列表）** | `GET /matching/result` **不**携带 static shortlist 全量 | N/A | **否**（不能把「池内完整排序」当作已存在 payload） | 仅能把 **`MatchResult.candidateUserId`** 视作 **worker 写入的 static-derived baseline**；与 M5.0-B「Static Source」叙述一致 | **M5.2-M3+** 若需要显式 static Top-K，需 **侧车或单独只读 API**，**不在**本轮 |
| **Admin / batch regression / local report** | **不可用（viewer GET）** | 管理端、脚本、本地报告 | Admin/batch **不等同** viewer-safe 契约 | **否**（**禁止**直接进入用户 `GET /matching/result`） | 与 JWT viewer 路径隔离 | **M5.9 / 离线** 评估；若需线上影子，走 **脱敏聚合服务**，**不是**本 GET |

**表内建议结论（与上表一致）**

- **MatchResult baseline / Current display**：已可支撑 **对比** 与 **契约**。
- **Pairwise finalize meta**：**部分可用**，可作 pairwise 分支信号，**不可**单独定 shadow proposal。
- **RRM-Sim readonly summary**：**默认不可用** → **核心缺口**；**M5.2-M2** 前的硬前置是 **写入 viewer-safe 摘要**（§5）。
- **Guardrails**：当前 **仅有 caution 级** 材料，**block 级不完整**。
- **Static 全量排序 / Admin / batch / local report**：**不**进入 viewer GET shadow 决策输入。

## 4. Pairwise Source 计划

### 4.1 当前 GET 路径上已存在的 viewer-safe 字段（`finalMatchDecisionMeta`）

与实现及 `FinalMatchDecisionMetaV1` 设计一致，可依赖字段包括：

- `selectedCandidateUserId`
- `pairwiseWinnerCandidateUserId`
- `staticTop1CandidateUserId`
- `sourceType`
- `mode`
- `pairwiseProposalRecommendation`
- `fallbackReason`
- `wouldChangeStaticResult`
- `appliedToFinalScore`（恒 `false` 契约）
- `appliedToWorkerRanking`（恒 `false` 契约）
- `frozen`
- `frozenAt`

### 4.2 明确禁止（M5.2 仍遵守）

- **禁止**在 `GET /matching/result` read path **查 raw pairwise job** 以推断 **`decisionConfidence` / `strongRisk`**。
- **禁止**为补齐 Pairwise **新增复杂 DB 查询**（与 M5.1-M2 红线一致）。
- **禁止**把 **RRM-lite pairwise JSON** 当作 **RRM-Sim**（见 M5.0-A）。

### 4.3 Shadow 中的角色

- Pairwise 可作为 **「Top2 内关系判断」** 的 **候选信号**。
- **不得**单独触发 **M5 shadow proposed candidate**（需与 **RRM-Sim 摘要** 与 **guardrail 门控** 组合，见 M5.0-B 多源原则）。
- **推荐门闩（规划）**：**Pairwise 与 RRM-Sim** 在 **viewer-safe** 前提下 **方向一致** 且 **无 guardrail 否决** 时，才允许进入 **shadow 候选集**（具体规则 **M5.2-M2** 冻结）。

## 5. RRM-Sim Source 计划（核心缺口）

### 5.1 当前事实（代码层）

- **`evaluateRrmSimFromSimulationV2` + `rrm-sim-extractor`**：仓库内 **唯一** 完整 **C/A/S/E/F/Q/D/R** 闭环（M5.0-A）。
- **`GET /matching/result`**：**默认** 无内嵌完整 RRM-Sim DTO；RRM 主数据仍在 **`ai_simulation` job**、**M4.0 readonly proposal**、**M4.1 comparison**、**M4.2 batch** 等路径。
- **M5.1-M2** 已预留 **`matchInsights.rrmSimReadonlySummary`**（常量键 `rrmSimReadonlySummary`），白名单 **`sourceVersion`**：`rrm-sim-v1`、`m4.0-readonly-rrm-ranking-proposal-v1`；且需 **`suggestedAction` / `progressionWindow` / `simulatedRhythmScore`** 至少其一。

### 5.2 三种接入方案比较

#### Option A：`GET /matching/result` read path **主动查询** M4.0 proposal / M4.1 comparison

| 项 | 内容 |
|----|------|
| 思路 | 在 GET 时按 `poolId` / `viewerUserId` 拉 proposal 或四源对照。 |
| **结论** | **不推荐**作为 M5.2 **首选**。 |
| 原因 | GET **变重**、延迟与缓存复杂；与 **admin/evaluation** 路径 **耦合**；失败面扩大（pool 缺失、job 未完成、权限边界）。 |

#### Option B：在 **RRM proposal / comparison / simulation 完成时** 写入 **viewer-safe `rrmSimReadonlySummary`**

| 项 | 内容 |
|----|------|
| 思路 | 异步或写路径生成 **精简摘要**（无公式、无 raw 向量），写入 **`matchInsights.rrmSimReadonlySummary`** 或 **未来 M5 侧车 meta**（持久化策略 **M5.2-M3** 定）。 |
| **结论** | **推荐**作为 **M5.2-M2 或 M5.2-M3** 的 **优先路线**。 |
| 原因 | **GET 保持轻**；契约与 **M5.1-M2 解析器** 对齐；可单测、可版本化；符合 M5.0-A「不混用 adapter」。 |

#### Option C：新增 **M5 source aggregation** 层（独立服务 / 模块）

| 项 | 内容 |
|----|------|
| 思路 | 聚合 pairwise + rrm + guardrail，read path **轻量调用**或异步物化。 |
| **结论** | **中期可行**；**不适合**作为 M5.2-M1 立即编码任务。 |
| 原因 | 架构收益高，但引入 **部署边界、缓存、一致性**；适合 **M5.2-M3 后** 或 **M5.3 前** 结构化。 |

### 5.3 推荐路线（冻结给 M5.2-M2/M3）

**M5.2 推荐先走 Option B：**

1. 在 **simulation job 完成 / M4.0 proposal 定稿 / M4.1 comparison 快照** 等 **已有 RRM 结果** 的时刻，生成 **viewer-safe** `rrmSimReadonlySummary`（字段见 §6）。  
2. **写入** `matchInsights`（或未来 **专用 sidecar 表** —— **M5.2-M3** 决策）。  
3. **`GET /matching/result`** **只消费** 已写入摘要，**不**在 read path **重查** M4.0 / M4.1 **、不**重跑 **evaluator**。

**不要让 `GET /matching/result` 临时去重查 RRM proposal / comparison** —— 避免读路径变重与行为分叉。

## 6. `rrmSimReadonlySummary` 推荐契约（对齐 M5.1-M2 解析器）

以下 JSON **为推荐形状**；**须与实现一致**：`schemaVersion` 为 **数字** `1`；`simulatedRhythmScore` 为 **number**（0–100，与 `RrmSimResult` 百分制一致）；`suggestedAction` 须为产品 **RRM 侧车枚举**（如 `maintain`、`continue_lightly`、`slow_down` 等），**勿**使用未定义自由字符串冒充枚举。

```json
{
  "schemaVersion": 1,
  "sourceType": "rrm_sim_readonly_summary",
  "sourceVersion": "rrm-sim-v1",
  "candidateUserId": "candidate_user_id",
  "winnerUserId": "candidate_user_id",
  "proposalCandidateUserId": "candidate_user_id",
  "scenarioKey": "early_conversation",
  "suggestedAction": "maintain",
  "progressionWindow": "weak_open",
  "simulatedRhythmScore": 62,
  "recommendation": "diagnostic_only",
  "confidenceBucket": "medium",
  "fallbackUsed": false,
  "unavailableReason": null,
  "cautionFlags": ["pace_mismatch"],
  "generatedAt": "2026-05-01T00:00:00.000Z",
  "frozenAt": null
}
```

**说明**

- `sourceVersion` 亦可为 **`m4.0-readonly-rrm-ranking-proposal-v1`**（与解析器白名单一致），表示 **M4.0 只读提案** 的 **echo**，仍 **不得**含 raw 公式向量。  
- **至少提供** `suggestedAction`、`progressionWindow`、`simulatedRhythmScore` **之一**，否则解析器返回 `null`（与当前代码一致）。  
- **禁止**在摘要中塞入 **另一候选人** 对比明细、**raw C/A/S/E/F/Q/D/R**、或 **完整 simulation transcript**。
