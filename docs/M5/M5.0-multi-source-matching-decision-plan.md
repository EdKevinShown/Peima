# M5.0-B — Multi-source Matching Decision Plan

本文档定义 **M5 多源最终匹配（展示）决策层** 的产品与技术计划，**不实现代码**。  
实现将拆分为 **M5.1**（Final Decision Sidecar）、**M5.2**（Shadow）、**M5.3**（Enabled display）；本文件 **M5.0-B** 仅锁定目标、边界、四源定义、决策原则与 **contract 草案**。

**对齐前提**：必须先遵守 [M5.0 — RRM Context Adapter Spec](./M5.0-rrm-context-adapter-spec.md)（M5.0-A）：M5 中与「RRM 公式分」相关的输入 **仅允许 RRM-Sim**；禁止把 Pairwise RRM-lite、Chat、Observed 混为 `rrm-sim-v1`。

---

## 1. 一句话结论

**M5** 的目标是建立一个 **多源最终展示决策层**：由 **Static、Pairwise、RRM-Sim、Guardrails** 共同约束或解释「**最终向用户展示谁**」（`displayCandidateUserId`），但 **不**直接覆盖 **`MatchResult.candidateUserId`**，也 **不**修改 **`finalScore`**。  
**M5.0-B** 只定义计划、边界、四源语义、决策原则与侧车 **JSON contract 草案**；**不写代码、不建表、不改 API**。

## 3. M5 的边界

### 3.1 M5 要做

- **新增** multi-source **final decision sidecar**（持久化形态与表结构由 **M5.1** 定义；本计划只约定语义）。  
- **汇总**四源：**Static、Pairwise、RRM-Sim、Guardrails**。  
- 输出 **`displayCandidateUserId`** 的 **来源解释**（`displaySourceType` / `decisionRule` 等，与现有 `matching-result-display` 概念对齐并扩展）。  
- 支持 **shadow mode**（全量计算、**不**改变线上展示；**M5.2** 实现）。  
- 支持 **enabled display mode**（灰度、可回滚；**M5.3** 实现）。  
- 为 **M6.1 Feedback `decisionContext`** 预留字段（sidecar 指针、枚举摘要、`wouldChangeDisplay` 等）。  
- 为 **M7 Assistant / M8 Timeline** 提供 **可信、可追溯** 的 match decision context（**不含**公式与 raw 分对外暴露）。

### 3.2 M5 不做

- **不重做** 20 维画像算法、worker 主排序公式。  
- **不重做** Pairwise LLM 契约与 normalize/validate 核心。  
- **不重做** `evaluateRrmSimFromSimulationV2` / `rrm-sim-extractor` 数学语义。  
- **不改** 原始 **`MatchResult.candidateUserId`**。  
- **不改** **`finalScore`**。  
- **不让 RRM-Sim 单独接管**「展示升级」；须与 Guardrails / Pairwise / Static 规则共同约束。  
- **不让 Feedback** 反向 **自动**修改最终展示决策或 `MatchResult`。  
- **不做** AI Assistant（M7）、**不做** Timeline RRM insight 产品（M8）。  
- **不做** Admin 可视化大盘、**不做**商业化套餐。

## 4. 多源输入定义

以下四类为 **M5 multi-source 层唯一允许的「公式/信号源」分类**（Guardrails 为横切合成源）。

### 4.1 Static Source

**来源**

- 20 维画像、基础偏好  
- static shortlist、**worker 原始匹配排序**  
- 原始 **`MatchResult.candidateUserId`**  
- **`finalScore`**、`reasonSummary` 等已有只读字段  

**作用**

- 作为 **baseline** 与 **最低可用 fallback**。  
- 当 Pairwise / RRM-Sim **不可用**或 **guardrail block** 时，**保持**展示与 baseline 一致（不强行「升级」display）。

**输出摘要（侧车或计算中间态）**

| 字段 | 说明 |
|------|------|
| `staticCandidateUserId` | 通常与 worker Top1 / 当前池绑定静态首位一致（具体绑定规则在 M5.1 与现有 `staticTop1CandidateUserId` 对齐）。 |
| `staticRank` | 在池内静态排序位次。 |
| `staticScore` / `finalScore` | 对用户解释可用「兼容度」等文案映射；**数值不随 M5 重写**。 |
| `staticReasonSummary` | 来自现有 match 解释链路的摘要指针或短文本。 |
| `staticAvailable` | 恒为 `true`（若匹配结果存在）；若缺失匹配行则为 `false` 并走错误路径而非静默改人。 |

**决策地位**

- **永远保留**；**不被覆盖**，仅被 **display 层**引用。  
- **`MatchResult.candidateUserId` 与 `finalScore` 不因 M5 变更。**

---

### 4.2 Pairwise Source

**来源**

- **completed** pairwise job、`AiPairwiseDecision`  
- **`pairwise_pool_finalize_meta`**（`FinalMatchDecisionMetaV1` 等）  
- **`strongRisk`**、`decisionReason` / `decisionConfidence`、`fallbackUsed`  
- 当前 **pairwise finalize** 环境：`proposal_only` / `shadow` / `enabled`（与 `readPairwiseFinalizeEnv` 行为对齐）

**作用**

- 提供 **LLM pairwise 关系判断**（**RRM-lite 契约**，见 M5.0-A）。  
- 可作为 **display 强信号**（在 **enabled** 且 gate 通过时，与现有产品行为一致方向）。  
- **不得**将 Pairwise 输出等同于 **RRM-Sim** 的 C/A/S/E/F/Q/D/R 完整公式结果。

**输出摘要**

| 字段 | 说明 |
|------|------|
| `pairwiseWinnerUserId` | Top2 内胜者；可能为 null。 |
| `pairwiseDecision` | 如 `pairwise_winner_eligible` / fallback 枚举（与 finalize shadow 对齐）。 |
| `pairwiseConfidence` | 数值或分桶：`high` / `medium` / `low` / `unavailable`。 |
| `pairwiseStrongRisk` | 布尔。 |
| `pairwiseReasonSummary` | 用户安全短摘要；**无**维度 raw 向量对外字段。 |
| `pairwiseAvailable` | job 完成且决策可解析。 |
| `pairwiseSourceVersion` | 如 `rrm-lite-pairwise-decision-v1`（示例，以实际契约为准）。 |

**决策地位**

- **可**参与 sidecar；**unavailable** 时 **不阻塞** static baseline。  
- **`strongRisk` 命中** → 必须贡献 **Guardrails** 的 **caution/block**（见 4.4）。

---

### 4.3 RRM-Sim Source

**来源**

- AI simulation **v2**、`transcriptLite` 满足 full RRM-ready 校验  
- **`evaluateRrmSimFromSimulationV2`** + **`rrm-sim-extractor`**  
- **`RrmSimResult`**、`buildRrmRankingProposal` / M4.0 只读提案行  
- 场景 **A_scenario**：**fixed_by_scenario**（M5.0-A）

**作用**

- 提供 **关系节奏模拟**（rhythm / progression / caution / risk bucket）。  
- **仅预测型 simulation**；**禁止**与 **RRM-Observed** 混用或冒充真实聊天结果。

**输出摘要**

| 字段 | 说明 |
|------|------|
| `rrmCandidateUserId` / `rankingProposalWinnerUserId` | RRM 提案 Top1；可与 static Top1 不一致。 |
| `simulatedRhythmScore` | 百分制节奏分；**用户侧不展示 raw**。 |
| `progressionWindow` | `closed` / `weak_open` / `open` / `strong_open`。 |
| `suggestedAction` | 与 `rrm-sim-v1` 枚举一致。 |
| `cautionFlags` | 如 `RRM_FALLBACK`、`too_many_fallbacks`、`respect_gate` 等 **reasonCodes 级**枚举。 |
| `rrmConfidence` | 映射 M4.0 `confidenceLevel` + `fallbackUsed` + `unavailableReason` 的合成桶。 |
| `fallbackUsed` | 布尔。 |
| `unavailableReason` | 与 `RrmSimResult` 一致或 `missing_simulation`。 |
| `rrmSourceVersion` | 固定 **`rrm-sim-v1`**（与 M5.0-A 一致）。 |

**决策地位**

- **M5 公式侧 RRM 仅使用本源**（M5.0-A §11）。  
- **`fallbackUsed` / low confidence** → **仅 caution**；**禁止**在 **enabled** 下单独因 RRM **升级** display。  
- **full confidence 且与 Static/Pairwise 不冲突、且 Guardrails pass** 时，可作为 **增强** display 决策的 **非独占**输入。

---

### 4.4 Guardrails Source

**来源（可叠加）**

- hard preference / dealbreaker 类 **mismatch**（来自现有静态与业务规则，具体清单 M5.1 对齐代码）  
- **Respect / boundary risk**：RRM-Sim `R_pre` 门控、Pairwise `strongRisk`  
- **RRM caution / high risk**：`D_pre` 门控、`stop_or_step_back`、M4.0 `do_not_use_for_ranking` 等  
- **schema_validation failure**（pairwise 或 sim 持久化失败审计）  
- **missing source**（无 sim、无 pairwise、池不一致）  
- **安全 / 隐私 / 可靠性**：池归属、JWT viewer、侧车 meta 解析失败等  

**作用**

- 判定某候选 **是否允许** 成为 **`displayCandidateUserId` 的「升级目标」**。  
- **高风险 → block display upgrade**；**不负责选最优**，只做 **拦截与降级**。

**输出摘要**

| 字段 | 说明 |
|------|------|
| `guardrailStatus` | `pass` \| `caution` \| `block` |
| `blockReasons` | 枚举数组，可审计。 |
| `cautionReasons` | 枚举数组。 |
| `sourceSummary` | 各子规则命中简表（不含 PII）。 |
| `severity` | 可选序数或枚举，供 Admin 排序。 |

**决策地位**

- **Guardrail `block` 优先级最高**：**不允许**任何 **display upgrade**（相对 `matchResultCandidateUserId`）。  
- **`caution`**：允许继续展示路径，但 **FinalMatch / 叙事** 必须 **降低确定性**（与 M4.3 一致方向）。  

---

## 5. 多源决策原则

1. **Baseline-first**：**`MatchResult.candidateUserId`** 永远作为 **审计与体验 baseline**；任何展示变化必须可解释相对该 baseline 的 **delta**。  
2. **No destructive overwrite**：**不**覆盖 **`MatchResult.candidateUserId`**。  
3. **No finalScore mutation**：**不**修改 **`finalScore`**。  
4. **Sidecar-only**：多源合成结果写入 **sidecar**（新表或扩展 meta 由 M5.1 定案）；**主结果行不变**。  
5. **Display separation**：用户主路径以 **`displayCandidateUserId`** 为准；与 **`candidateUserId`** 分离已有先例，M5 统一 **decisionRule** 归因。  
6. **Source traceability**：每次 display 决策必须可追溯 **static / pairwise / rrmSim / guardrails** 的贡献与 **decisionRule** 枚举。  
7. **Confidence-aware**：任一方 **low confidence / fallback** → **不得**单独触发 **enabled override**；至多 **caution** 或 **shadow 记录**。  
8. **Guardrail-first**：**block** 优于一切「分数更高」的展示升级。  
9. **Shadow before enabled**：先 **shadow** 全量写侧车并统计 **`wouldChangeDisplay`**，再 **enabled** 灰度（M5.2 → M5.3）。  
10. **Feedback-ready**：侧车预留 **M6.1** 可序列化字段：`decisionRule`、`displaySourceType`、`rrmConfidenceBucket`、`pairwiseProposalRecommendation` 摘要、`guardrailStatus` 等（**不**含 raw 公式向量）。  
11. **User-safe explanation**：用户仅见 **摘要级**解释；**不**见公式、**不**见 **raw score**、**不**见 **另一候选人** 敏感对比细节。  
12. **Admin-observable**：Admin 可查询 **`sourceVersion`**、**fallback**、**`decisionRule`**、**`wouldChangeDisplay`**、**guardrail** 枚举与 **decisionTrace**（实现属 M5.1+）。

## 6. 决策输出 contract 草案

以下为 **侧车 JSON** 的 **计划草案**（字段名可在 M5.1 冻结时微调）。**示例 ID 为占位符**，禁止粘贴真实生产 ID。

```json
{
  "sourceVersion": "m5.0-multi-source-final-decision-plan-v1",
  "mode": "shadow",
  "baseline": {
    "matchResultCandidateUserId": "user_x",
    "finalScore": 0.82,
    "sourceType": "match_result_baseline"
  },
  "display": {
    "displayCandidateUserId": "user_x",
    "displaySourceType": "match_result_baseline",
    "wouldChangeDisplay": false,
    "decisionRule": "baseline_preserved"
  },
  "sources": {
    "static": {
      "available": true,
      "candidateUserId": "user_x",
      "summary": "static baseline available"
    },
    "pairwise": {
      "available": false,
      "winnerUserId": null,
      "confidence": "unavailable",
      "strongRisk": false
    },
    "rrmSim": {
      "available": false,
      "winnerUserId": null,
      "confidence": "unavailable",
      "fallbackUsed": true,
      "unavailableReason": "missing_simulation"
    },
    "guardrails": {
      "status": "pass",
      "blockReasons": [],
      "cautionReasons": []
    }
  },
  "admin": {
    "decisionTrace": [],
    "missingSources": ["pairwise", "rrmSim"],
    "notes": []
  }
}
```

**说明**

- **`sourceVersion`**：本 plan 文档版本；实现侧车 schema 冻结时可 bump 为 `m5.1-final-decision-sidecar-v1` 等（由 M5.1 文档定义）。  
- **`mode`**：`shadow` \| `enabled` \| `proposal_only`（与现有 finalize 语义对齐处见 M5.1）。  
- **`display.displaySourceType`**：在现有 `match_result_original` / `static_final` / `pairwise_final` / `static_fallback` 基础上，M5.1 可扩展 **`rrm_sim_aligned`**、**`multi_source_v1`** 等枚举（本计划不冻结最终实现名）。  
- **`admin.decisionTrace`**：有序步骤列表（规则 id、输入摘要 hash、时间戳），**M5.1** 定义最大长度与脱敏策略。

## 7. 与 M5.0-A 的对齐（强制）

- M5 中 **RRM 公式分** 仅来自 **RRM-Sim Adapter**（`rrm-sim-v1`）；**禁止**用 Pairwise、Chat、Timeline 顶替。  
- **RRM-Observed / RRM-Assistant / RRM-Timeline / RRM-Eval** **不进入** M5 **display 合成公式**；Eval 仅服务 M9 / M6.1 归因。  
- **红线** 全文继承 M5.0-A §12，与本计划 §3.2、§5 一并遵守。
