# M5.5-M5 — RRM Top2 Automatic Hook Design

> **范围**：仅设计文档。不写代码、不改 schema、不新增 migration。本文不出现真实业务 ID、token、`DATABASE_URL`。

## 1. 一句话结论

M5.5-M5 规划如何把 **M5.5-M2** `writeRrmTop2DisplayMetaForMatchResult` 与 **M5.5-M4** 受控 runner 的验证结论，升级为 **自动 hook**：在 **非 GET**、**不阻塞 worker 主事务** 的前提下，于 **RRM 产物就绪且冻结 Top2 / guardrails 齐备** 时调用 writer；否则 **no-op** 并 **可审计**。**GET `/matching/result` 保持只读**。

---

## 2. 自动 hook 应接在哪里（候选比较）

| 位置 | 优点 | 风险 / 缺点 | 适用度 |
|------|------|-------------|--------|
| **RRM simulation job completion** | 最接近 RRM 原始结果；可就地 build **`rrmSimReadonlySummary`** 并关联 `matchResultId`（若 job 已持有）。 | Job 失败 / 重试 / 多版本时需严格 **幂等**；**Static Top2** 未必在同一进程就绪。 | **高**（作为 **触发源之一** 或 **入队消息** 的生产者）。 |
| **RRM proposal completion（M4.0 等）** | 与只读 proposal 契约一致；可生成 allow-list 内 `sourceVersion` 的 summary。 | 同样需 **matchResultId** 与 **Top2** 绑定；可能与 simulation 重复触发，需 **去重键**。 | **高**（常与 simulation **二选一或合并** 为同一「RRM 就绪」事件）。 |
| **Post-match aggregation job（独立消费者）** | **不污染** worker HTTP/批处理主路径；输入可显式聚合 **MatchResult + 冻结 Top2 + summary + guardrails**；易 **重试 / replay / 批量补写**。 | 多一套队列或调度；延迟略高于内联。 | **短期最推荐**（与 `M5.5-m3` Option D 一致）。 |
| **Worker batch-match 后置阶段（同步或同进程尾部）** | `MatchResult` 已存在，绑定清晰。 | RRM / summary 常 **未就绪**；易拖慢主链路；Top2 仍可能未冻结。 | **低–中**（仅适合 **enqueue**「待 aggregation」**一行/一条消息**，**不**在内联写 meta）。 |

**结论**：**主推荐**为 **post-match aggregation job（或等价异步消费者）** 消费「RRM 就绪 + MatchResult 已存在」事件；**RRM simulation / proposal completion** 作为 **事件生产者**（写入队列或 `pending` 状态），**不**在 batch-match 同步尾部直接写侧车。

---

## 3. 推荐方案（短期 / 中期）

| 维度 | 建议 |
|------|------|
| **短期（M5.5-M5 实现阶段）** | 引入 **轻量异步路径**：simulation 或 proposal **完成**后发布 **内部事件 / 队列任务**（payload 仅含 **viewer-safe 引用**：如 `matchResultId` 内部 ID、job id、**top2Fingerprint** 指针等），由 **独立 worker 进程或 Nest 队列消费者** 调用现有 **`writeRrmTop2DisplayMetaForMatchResult`**（仍受 **`PEIMA_M5_RRM_TOP2_META_WRITE_ENABLED`** 等闸门约束）。 |
| **是否做 post-match aggregation job** | **是（推荐）** — 即使第一版只有一个 consumer 文件 + DB 表或复用现有 job 表，也应在 **架构上**视为 aggregation：**聚合** Top2 快照、summary、guardrails 后再写。 |
| **是否避免污染 worker 主流程** | **是** — batch-match **仅 enqueue**；**禁止**在匹配请求同步返回前等待 RRM writer。 |
| **GET 是否保持只读** | **是** — **永不**在 GET 内写库或重跑 RRM；读路径继续 **`resolveMatchResultDisplay`**。 |

## 4. 自动 hook 的输入来源（必须齐备才写）

| 输入 | 说明 |
|------|------|
| **`MatchResult`** | 至少 `id`、`userId`、`candidateUserId`（baseline）、`matchInsights`、`batchId`；**不**用 `finalScore` / `candidateUserId` 推导展示切换。 |
| **Static Top2 frozen snapshot** | **两枚 distinct** `candidateUserId`，须 **包含** `MatchResult.candidateUserId`；须来自 **已冻结**源（shortlist 侧车、pairwise 冻结快照、未来 `staticTop2ReadonlySummary` 等），**禁止**在 hook 内现算 shortlist 或仅从 `FinalMatchDecisionMeta` 武断推断（见 `M5.5-m3` §5）。 |
| **`rrmSimReadonlySummary`** | 已持久化在 `matchInsights` 或由 **M5.2-M2A builder** 在 **同一次受控写入** 中生成并经 **`writeRrmSimReadonlySummaryToMatchResult`** 落库；须通过 **`tryParseRrmSimReadonlySummaryPayloadV1FromMatchInsights`**。 |
| **Explicit guardrails（pass）** | **`meta.guardrails`**：`status === "pass"` 且 `blockReasons` / `cautionReasons` 均为空数组；**禁止**用 `matchInsights.explanation.cautions` 冒充。 |
| **`top2Fingerprint`** | 与 summary / 侧车 meta 绑定的 **稳定指针**；须与冻结 Top2 快照一致；与 **`validateRrmTop2DisplayEligibility`** 一致。 |

**触发时机（逻辑上）**：当且仅当 **RRM 只读产物已提交** + **Top2 快照已冻结** + **guardrails 已生成**（或可由上游服务原子写入）后，consumer **一次**调用 writer；若任一项滞后，应 **no-op 或延迟重试**（带上限与死信策略，实现阶段定义）。

---

## 5. 何时 no-op（非错误）

以下任一成立则 **不写 meta**（及不写 summary，若本步负责 summary）；**不影响** `MatchResult` 主行；GET 继续 pairwise / `match_result_original` fallback：

| 条件 | 典型 `noOpReasonCode` / 审计语义 |
|------|----------------------------------|
| **`rrmSimReadonlySummary` 缺失或非法** | `rrm_summary_missing` / `rrm_summary_invalid` / `summary_write_disabled` 等 |
| **Static Top2 缺失或未冻结** | `static_top2_missing` / `static_top2_not_frozen` / `top2_fingerprint_missing` / `baseline_mismatch` 等 |
| **guardrails 非 pass** | `guardrails_missing` / `guardrails_invalid` / `guardrails_caution` / `guardrails_block` / `guardrails_not_evaluated` 等 |
| **已存在 frozen 侧车** | **`existing_meta_frozen`**（与 M5.5-M4B Round 3 行为一致） |
| **`PEIMA_M5_RRM_TOP2_META_WRITE_ENABLED` 关闭** | **`writer_disabled`** |
| **eligibility 任一失败** | 与 **`validateRrmTop2DisplayEligibility`** 枚举对齐（如 `rrm_confidence_low`、`rrm_fallback_used`、`fingerprint_mismatch` 等） |

**原则**：no-op **必须可审计**；**禁止**静默重试无限刷库。

## 6. 安全边界（冻结）

自动 hook **不得**修改：

- `MatchResult.candidateUserId`
- `MatchResult.finalScore`
- **worker ranking** 持久化语义
- **`PairwisePoolFinalizeMeta`**
- **用户画像 / 问卷主数据**
- **Chat 消息**（不自动代发）

**允许写入**（仅当 env + eligibility 允许，与 M5.5-M2 一致）：

- `matchInsights.rrmSimReadonlySummary`（仅该键的受控合并）
- **`MatchResultRrmTop2DisplayMeta`**

**GET**：**不**写库、**不**重跑 RRM evaluator。

## 8. 实现阶段建议（非本轮代码）

1. **定义事件 payload**（无 PII 泄漏到日志明文策略）。  
2. **去重键**：`matchResultId` + `top2Fingerprint` + `sourceVersion`（或 hash）。  
3. **消费者**：单线程顺序或 per-`matchResultId` 锁，避免并发双写。  
4. **监控**：no-op 率、`existing_meta_frozen` 率、writer 错误率。  
5. **M6.1**：`decisionContext` 记录 `displaySourceType`、是否 RRM 活跃、`noOpReasonCode`（见 `M5.5-m3` §12）。
