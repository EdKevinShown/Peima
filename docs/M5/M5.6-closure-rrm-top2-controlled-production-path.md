# M5.6 Closure — RRM Top2 Controlled Production Path

> **范围**：**收口文档 only**。总结 **M5.6** 受控生产路径完成情况，声明 **M5** 可阶段性结束并进入 **M6**。不含真实业务 id、token、`DATABASE_URL`。

---

## 1. 一句话结论

**M5.6** 已完成 **RRM Top2 controlled production path**：RRM 已从 **fixture / 手动侧车** 验证，推进到 **hook job outbox**、**controlled create**、**dry-run consumer**、**apply gate**、**shared apply service**、**independent dry-run poller**、以及 **staging-style apply run record**（复用 B5 runner）的完整 **受控** 链路。

**M5** 可在此维度上 **阶段性收口**。下一阶段进入 **M6**（用户反馈、质量观测、运营工具等，见 §9）。

## 3. 当前能力边界

系统现已具备（在 **受控 dev/staging 工具链** 前提下）：

| 能力 | 说明 |
|------|------|
| **创建** | 可创建 **RRM Top2 hook job**（B3）。 |
| **读取 pending** | 可枚举 **pending** hook jobs（B2 / B4B / B8）。 |
| **Dry-run** | 可判断 **`wouldProcess` / `wouldSkip`** 及 no-op 分布（B4 / B4B / shared dry-run aggregate）。 |
| **Controlled apply** | 可 **小批量 apply**（B5 + shared service）。 |
| **Known no-op** | 可将 **已知 writer no-op** 映射为 **`skipped`**（含 `existing_meta_frozen`）。 |
| **异常** | 可将 **writer 异常** 映射为 **`failed`** + sanitize。 |
| **Frozen meta** | 可 **保护** 已冻结 meta（skip 路径，见 B6-B / B9-B）。 |
| **不变量** | 可保证 **`MatchResult.candidateUserId` / `finalScore`** 不因本链路修改。 |
| **Run record** | 可对 **env-off / env-on / frozen / staging** 等场景留档（各 `M5.6-b*c` / `b9b` 文档）。 |

## 5. 关键不变量（再次确认）

以下 **永远不因** RRM Top2 hook / apply / poller **CLI 路径**而直接篡改：

- **`MatchResult.candidateUserId`**
- **`MatchResult.finalScore`**
- **worker ranking**
- **`PairwisePoolFinalizeMeta`**
- **user profile**
- **questionnaire profile**
- **chat messages**

**`GET /matching/result`**（及同类 GET）保持 **只读**；本链路 **不** 以 GET 驱动写库。

## 9. M6 建议方向

建议 **M6** 从 **用户反馈** 与 **质量评估** 进入，**避免**在 M5 上无限扩张。

可包含（示意）：

1. **M6.1 — `decisionContext` / feedback**  
   记录 `matchResultId`、`candidateUserId`、`displayCandidateUserId`、`displaySourceType`、`hookJobId`、`noOpReasonCode`、RRM active 等（**设计时**继续遵守最小必要与脱敏策略）。

2. **M6.2 — RRM quality analytics**  
   成功率、skipped reason 分布、static / pairwise / RRM 反馈对比等。

3. **M6.3 — Admin observation**  
   Hook job 状态总览、no-op 原因看板、apply run records 聚合视图等。

4. **M6.4 — Optional production poller（仅后期考虑）**  
   **多重** env gate、**先 dry-run**、**staging 先于 production**；**仍**不接隐式 GET 写库。

## 10. Closure 判定

**M5 / M5.6 可以收口**，理由：

- **Controlled production path** 已从 schema 贯通到 **dry-run / apply / shared service / poller / staging record**。  
- **Outbox / job** 容器与 **helper** 已存在且可测。  
- **Dry-run、apply、no-op、frozen、staging-style** 均有 **可追溯 run record**。  
- **关键不变量**（`candidateUserId` / `finalScore`、GET 只读等）在设计与记录中 **反复明确**。  
- **剩余「生产默认自动化」** 应归入 **M6+** 的显式里程碑，**而非**继续堆在 M5 名下。
