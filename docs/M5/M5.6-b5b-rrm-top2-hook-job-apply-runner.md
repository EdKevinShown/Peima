# M5.6-B5-B — RRM Top2 Hook Job Controlled Apply Runner

> **范围**：**controlled dev-cli**：在显式确认下，将 **pending** hook job 推进为 **`processing` → `processed` | `skipped` | `failed`**，并可选调用 `writeRrmTop2DisplayMetaForMatchResult`（**`dryRun: false`**）。**不**接 GET、**不**接 worker 自动轮询。不含真实业务 id、token、`DATABASE_URL`。

## 1. 行为摘要

| 项 | 说明 |
|----|------|
| **`NODE_ENV=production`** | **拒绝运行**（CLI 输出 refused JSON 后以非零码退出）。 |
| **默认** | **dry-run**：枚举 pending，对每条调用 `processRrmTop2HookJobDryRun`；**不**改 HookJob 状态、**不**写 meta。 |
| **Apply** | 必须同时传入 **`--apply`** 与 **`--confirmControlledApply=I_UNDERSTAND`**；否则 **refused**，**不写**状态、**不调** writer apply。 |
| **`--limit`** | 默认 **`1`**，最大 **`10`**（小批量 apply）。 |
| **Writer env** | **不**绕过 `PEIMA_M5_RRM_TOP2_META_WRITE_ENABLED` / `PEIMA_M5_RRM_SIM_READONLY_SUMMARY_WRITE_ENABLED`。 |

## 2. 构建与运行

在 `apps/api` 下 `pnpm exec nest build` 后：

```bash
pnpm --filter @peima/api run m56-b5:rrm-top2-hook-job-apply -- --limit=1 --pretty

# Apply（显式确认）
pnpm --filter @peima/api run m56-b5:rrm-top2-hook-job-apply -- --limit=1 --apply --confirmControlledApply=I_UNDERSTAND --pretty
```

## 3. Apply 路径（概要）

1. `findPendingRrmTop2HookJobs`  
2. 每条：`markRrmTop2HookJobProcessing`（`lockedAt`、`attempts`）  
3. 预检（与 B4 consumer 一致）：snapshot / guardrails /（pass 时）summary  
4. `writeRrmTop2DisplayMetaForMatchResult`（**`dryRun: false`**，env 门闸保留）  
5. 分类：  
   - **`ok && wroteMeta`** → `markProcessed` + viewer-safe `metaWriteResult`  
   - **`existing_meta_frozen`** 及其它 **已知 writer no-op** → **`markSkipped`**（不当 `failed`）  
   - **Writer 抛错** / 未预期异常 → **`markFailed`** + `sanitizeRrmTop2HookJobError`

## 4. 安全边界

- **不改** `MatchResult.candidateUserId`、`finalScore`。  
- **不写** GET；**不**注册 worker loop。  
- **允许**写：HookJob 状态与审计字段；`MatchResultRrmTop2DisplayMeta` / `rrmSimReadonlySummary` **仅**通过 writer 且 env 允许时。
