# Peima / 配吗｜P2.5 阶段总结（阶段同步稿）

大家好，

这是一份 **Peima / 配吗** 的 **P2.5 阶段总结**，用于和队友、合作者对齐「当前仓库真实做到哪一步」，**不是**需求文档（PRD），也**不是**详细技术设计。细节仍以代码与 `docs/P2` 为准。

---

## 一、先把阶段说清楚：P0 / P1 / P2-MVP / P2.5

为避免口径混在一起，先区分四层（均为当前仓库已采纳的划分方式）：

| 阶段 | 含义（一句话） |
|------|----------------|
| **P0** | **稳定主链路**：注册/登录、问卷、预览池、匹配入队与 worker 批匹配、结果页、开聊与发消息等端到端可跑通。 |
| **P1** | **结构化占位能力**：匹配洞察、预览条目元数据、聊天摘要（当时以只读占位为主）、worker 与文案收口等，**内容由规则/模板/占位逻辑生成，不替代真实模型推理**。 |
| **P2-MVP** | **最小闭环**：为摘要持久化、结构化反馈、画像更新建议、行为信号、轻量统计、会话级 **规则化 Copilot 建议** 等补齐 **数据表 + API + 聊天页轻量展示**；Copilot **只读、不落库**；整体仍是 **研发向 MVP**，不是完整运营/AI 中台。 |
| **P2.5** | **在 P2-MVP 之上的产品化补完**：不扩大「AI 能力」边界，主要把 **体验、权限、结构可复现、联调可重复** 做到更利于协作与演示。 |

**重要边界（必须读）**

- 当前绝大多数「摘要、建议、洞察、反馈结构」仍由 **规则 / 模板 / 占位逻辑**（及简单聚合）驱动。
- **真实 AI Agent、多 Agent 编排、真实 simulation 产品化流水线尚未在本仓库正式接入**；也**不应**把现状表述成「已上生产级大模型链路」。

---

## 二、P2.5 开始前：我们处在什么状态

在进入 P2.5 之前，**P2-MVP 已经具备**（概括）：

- **数据**：P2 相关持久化结构已在当前代码中实际使用，包括会话摘要快照、用户反馈、画像更新建议、行为信号等。
- **API**：上述能力的读写/只读接口，风格与现有 chat 鉴权方式对齐（JWT、参与者校验等）。
- **Web**：`ChatPage` 上对摘要、Copilot、反馈、待处理建议等 **条件展示**，失败时尽量 **不阻塞发消息**。

但当时仍存在典型的「MVP 缝隙」：例如聊天里对画像建议 **缺少完整操作闭环**、Copilot **缺少独立浏览页**、摘要 **缺少明确的手动更新入口**、全局统计 **对任意登录用户开放** 不利于对外演示、P2 表在部分环境 **仅靠 push 与 schema 漂移**、**缺少一份可重复的联调/验收步骤** 等。P2.5 主要对准这些缝隙做收口。

---

## 三、P2.5 这一轮具体完成了什么

本轮 **P2.5** 的交付项（与仓库当前状态一致）包括：

1. **画像建议前端闭环**：在聊天页可查看建议列表，对 **待处理** 项直接 **接受 / 忽略**，成功后刷新列表；**已处理** 与 **待处理** 分区展示，已处理区默认折叠，减少页面冗长。
2. **独立 Copilot 页**：新增 **`/copilot?conversationId=`** 路由（`CopilotPage`），在同一套只读接口上提供更完整展示（含依据来源等）；聊天内仍保留轻量卡片，**不代发消息、不做提醒型产品**。
3. **摘要手动生成入口**：在 `ChatPage` 提供 **「生成并更新摘要」**，调用已有 `POST .../summary/generate`，成功后用户能直接看到 **最新摘要**，而不必依赖发消息等间接路径。
4. **Analytics 权限收口**：**`GET /analytics/p2-overview/mine`** 仍为 **普通登录用户** 可读；**全局** **`GET /analytics/p2-overview`** 改为仅 **环境变量白名单**（用户 id 列表）可访问，未授权返回 **403**，避免「任意登录用户可读全局盘」的演示/安全风险。
5. **建议展示优化**：画像建议区域的 **状态与分区** 更清晰，偏产品化呈现，**未**单独做「建议中心」大页面。
6. **P2 migration 正式收口**：P2 相关表纳入 **正式 Prisma migration**（如 `20260405100000_p2_persistence_mvp`），**空库 `migrate deploy` 可复现**；若历史环境曾用 `db push`，需按运维说明自行 baseline，这一点在文档中有提示。
7. **联调 / 验收文档固化**：新增 **`docs/P2/P2.5-integration-checklist.md`**，包含环境前置、**curl / PowerShell 示例**、分模块 **手动验收勾选清单**；与 `P2-validation-summary` 等互为补充。

---

## 四、当前项目到什么程度了

用一句话概括：**当前已具备便于演示、联调与阶段同步的产品化研发基础**，主链路稳定，P2 能力在前后端 **能走完闭环**；但这 **仍不等于**「真实 AI 生产系统」，也 **不是**「完整运营/安全/可观测平台」。

---

## 五、还没有做什么（避免过度承诺）

包括但不限于（与 README / P2 文档口径一致）：

- **真实大模型调用链**、**AI Agent**、**多 Agent**、端到端 **simulation 产品化流水线**。
- Copilot / 摘要的 **Worker 侧自动生成**、**历史版本** 的产品化治理、完整 **运营后台**。
- 独立的 **设置 / 建议中心** 大模块（当前能力集中在 **ChatPage** 与 **CopilotPage**）。
- 生产级 **RBAC、审计、大盘监控、自动化测试体系** 等（未作为本阶段交付目标）。

---

## 六、P2.5 的价值（为什么值得单独做一轮）

- **协作**：新同学或合作方可以用 **清单文档** 快速跑通关键路径，减少「口口相传」。
- **演示**：聊天内闭环 + 独立 Copilot 页，**对外说明「规则建议层」** 更直观。
- **安全/边界**：全局统计 **白名单** 把「内测统计」和「普通用户」分开，更符合真实部署预期。
- **工程**：migration 收口让 **结构可复现**，减少「只有某台机器能跑」的隐性成本。

---

## 七、下一阶段建议（方向性，非承诺）

可在 **不破坏 P0 契约** 的前提下，按优先级考虑：更细的权限与缓存、Worker 与信号/摘要策略、Copilot/摘要 **历史与治理**、以及在未来某阶段将 **规则生成替换为模型或策略服务**（并延续 `sourceType` / `sourceVersion` 一类溯源字段）。具体范围需另开阶段规划，**本文不将其记为已完成**。

---

## 八、发给队友的一句阶段性总结（可直接复制）

**P2.5 已收尾：主链路和 P2-MVP 能力不变，我们在聊天里补全了画像建议操作、加了 Copilot 独立只读页和摘要手动生成，把全局统计收成白名单、P2 表进了正式 migration，并固化了联调验收清单；内容仍以规则/占位为主，真实 AI 生产链还没接。下一阶段再单独排期。**
