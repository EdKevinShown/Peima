# M6.0-E — Worker scoreShadow Implementation

> **范围**：在 **不改 Prisma schema**、**不新增 migration**、**不替换 `MatchResult.finalScore`**、**不改胜者 / `candidateUserId` / RRM** 的前提下，于 **worker batch-match** 写入 **`matchInsights.scoreShadow`**，并让 **GET `/matching/result`** 的 **`relationshipProfileScore`** **优先**读取该结构化字段。  
> 设计依据：**`docs/M6/M6.0-d-final-score-v2-shadow-plan.md`**。

---

## 1. 本轮交付

| 项 | 说明 |
|----|------|
| **Worker** | **`buildScoreShadowM60`**（`apps/worker/src/jobs/matching-score.ts`）：`finalScoreV1` = **`computeFinalScoreV1` 的 `finalScore`**，`relationshipProfileScore` = **`profileScore`**，`scoringVersion` = **`m6.0-profile-score-shadow-v1`**。 |
| **写库** | **`batch-match.processor.ts`**：在 **`buildMatchInsightsPlaceholder`** 结果上 **浅合并** **`scoreShadow`** 后写入 **`MatchResult.matchInsights`**。 |
| **共享类型** | **`packages/shared/types/match-p1.ts`**：`MatchInsights` 增加可选 **`scoreShadow`**。 |
| **API** | **`resolveRelationshipProfileScoreShadow`**：优先 **`matchInsights.scoreShadow`**；否则 **M6.0-C** 的 **`reasonSummary` → `scoreBreakdown`**。 |
| **`source` 枚举** | **`match_insights_score_shadow`** \| **`score_breakdown_profile_score`** \| **`missing`** |
| **测试** | **`matching-relationship-profile-score.spec.ts`** 扩展；**`worker-score-shadow-m60.spec.ts`**（从 worker 源码导入纯函数）。 |

---

## 2. `scoreShadow` JSON 形状

```json
{
  "finalScoreV1": 0.894,
  "relationshipProfileScore": 0.821217,
  "scoringVersion": "m6.0-profile-score-shadow-v1"
}
```

- **`finalScoreV1`**：与 **`MatchResult.finalScore`** 一致（冗余便于审计切片）。  
- **`relationshipProfileScore`**：与 v1 分量中的 **`profileScore`** 一致（20 维 G1-R 适配度）。  
- **不含**：问卷原文、**`userId`**、RRM raw 分。
