# M6.0-r5 — RRM V2 Selector Readonly Display Meta Contract

> **本轮性质**：**contract design（合同设计）**，**不是** implementation。**不**新增或修改 API / resolver / worker / 前端 / Prisma schema / migration / 测试代码；**不**虚构已上线能力。  
> **上游依据**：`M6.0-r3b-rrm-v2-top2-selector-db-regression.md`（**r3b**：DB 实测摘要）、`M6.0-r4-rrm-v2-top2-selector-readonly-display-preflight.md`（**R4**：readonly display 边界与 flag）、`M6.0-r3-rrm-v2-top2-selector-shadow.md`（**R3**：worker shadow）、`M6.0-r1-rrm-v2-integration-scan-plan.md`（**R1**：`displaySourceType` / M5 RRM）、`M6.0-j1c-matching-pipeline-v2-responsibility-alignment.md`、`M6.0-j4-api-frontend-score-shadow-v2-display.md`、`M6.0-d-final-score-v2-shadow-plan.md` 等与 **scoreShadow**、**GET display**、**FinalMatch** 相关的 M6 文档。  
> **本文不写**：真实 **`userId` / `candidateUserId` / `matchResultId` / `conversationId` / token**。

---

## 1. 本轮目标

- **R3B** 已证明：**`matchInsights.rrmV2Top2Selector`** 可在真实 DB 的 **`MatchResult`** 上产出 **`selectedTop2`**（及 **`eligible` / `reason` / `contextFlags`** 等）。  
- **R4** 已定义：**readonly display** 的安全边界、**fallback**、**FinalMatchPage** 不直读 selector、**feature flag** 命名建议（**`PEIMA_M6_RRM_V2_SELECTOR_DISPLAY_ENABLED`**）。  
- **R5（本文）** 只定义：**readonly display meta** 的 **payload 合同**、**`displaySourceType`** 建议、**parser/validator** 规则、**fallback** 合同、**写入策略**选项与 **FinalMatchPage** 消费边界。  
- **R5+ 正式 contract**：**只依赖 `matchInsights.scoreShadowV2`**（**V2-only 主线**）。**`scoreShadow`（v1）** 仅作 **legacy observation / historical compatibility**，**不参与** parser / validator / fallback 的 **pass/fail**。  
- **明确不做**：**不**实现 **R6** 的 resolver 接线、**不**改 **README**、**不**改 schema / migration。

## 2. 输入基线

以下输入用于 **派生或校验** readonly display meta（**逻辑只读**；**不**改写 **`MatchResult`** 主决策列）。

| 输入 | 说明 |
|------|------|
| **`MatchResult` 主结果** | **`candidateUserId`**、**`finalScore`**、**`reasonSummary`**、**`matchInsights`** 等 **worker 真源**；meta **不得**反写这些列。 |
| **`scoreShadowV2` 存在性** | **Required**：**`matchInsights.scoreShadowV2`** 须存在且版本合规（**R3**）；用于 **RRM V2 selector readonly display contract** 的 **pass/fail** 输入。 |
| **`scoreShadow`（v1）legacy observation** | **Optional**：**`matchInsights.scoreShadow`** 仅作 **历史兼容 / 观测说明**；**不是** **R5+ required input**；**缺失不得**触发 **RRM V2 readonly display** 的 **fallback**。 |

**显式规则**

- **`scoreShadow` v1** **不再**作为 **required input**。  
- **`scoreShadow` v1 缺失** **不得**触发 **RRM V2 readonly display** 的 **fallback**。
| **`rrmV2Top2Selector` output** | **`matchInsights.rrmV2Top2Selector`** 整段 JSON（**R3** shadow **`version`** = **`m6.0-rrm-v2-top2-selector-shadow-v1`**）。 |
| **`selectedTop2`** | **至多 2** 条展示候选摘要来源；**不是**新的最终匹配结果。 |
| **`eligible` / `reason`** | Selector 层 always-on 输出（**R2B**）。 |
| **`contextFlags` / `thresholds`** | 风险提示；validator 可定义 **strict** 展示门闩（见 **§5**）。 |
| **`sourceVersion`** | 合同内记录 **selector shadow** 或 **上游 JSON** 的版本串，便于 **parser** 对齐（可与 **`rrmV2Top2Selector.version`** 一致或映射表维护）。 |
| **`generatedAt`** | Meta 生成或观测时间（**ISO-8601**）；可与 **`MatchResult.createdAt`** 分离，便于审计 **「展示解释快照」** 非 **「匹配发生时间」**。 |

**不变量**：上述输入 **均不得** 被 meta 管线 **改写** **`MatchResult.finalScore`**、**`MatchResult.candidateUserId`**、worker **ranking** 真源；**不**触发 **RRM 模型 resolver**（M5 路径）除非未来 **显式** 合并里程碑。

## 3. 推荐 meta contract shape（草案 JSON）

以下为 **readonly display meta payload** 草案，供 **R6** 实现前对齐 **TypeScript / Zod / 手写 parse**。**字段名可微调**，**`schemaVersion`** 与 **`sourceType`** 为合同锚点。

```json
{
  "schemaVersion": 1,
  "sourceType": "rrm_v2_selector_readonly_display_v1",
  "sourceVersion": "m6.0-rrm-v2-top2-selector-shadow-v1",
  "matchResultRef": {
    "kind": "match_result",
    "fingerprint": "<non-reversible-hash-or-opaque-ref-contract-r6>"
  },
  "eligible": true,
  "reason": "ok",
  "selectedTop2": [
    {
      "rank": 1,
      "candidateRef": {
        "kind": "user",
        "fingerprint": "<opaque-ref-contract-r6>"
      },
      "displayReasonCode": "V2_TOP1_READONLY",
      "scoreSummary": {
        "displayScore100": 0,
        "band": "high"
      },
      "safetySummary": {
        "withinTop2Subset": true,
        "fallbackIfMissingProfile": true
      }
    }
  ],
  "contextFlags": {
    "top2GapLarge": false,
    "hasLowBand": false,
    "hasStrongConflictBand": false,
    "anyBelowSuggestedFloor": false
  },
  "scoreShadowPresence": {
    "v2": true,
    "v1LegacyPresent": true
  },
  "generatedAt": "<ISO-8601-datetime>"
}
```

**`scoreShadowPresence` 说明（合同）**

- **`v2`**：**required**；**`true`** 表示 **V2 shadow** 可用于本 readonly display 路径。  
- **`v1LegacyPresent`**：**optional observation**；**不参与** **§5** validator 的 **pass/fail**（可为 **`false`** 或 **省略**）。

### 3.1 顶层字段（最小集）

| 字段 | 类型（概念） | 说明 |
|------|--------------|------|
| **`schemaVersion`** | `number` | **Meta 合同**版本；**R5** 初值为 **`1`**。 |
| **`sourceType`** | `string` | 区分 **M6 V2 selector readonly** 与其它 meta（**R6** 常量表）。 |
| **`sourceVersion`** | `string` | 对齐 **`rrmV2Top2Selector.version`** 或映射后的 **合同版本串**。 |
| **`matchResultRef`** | `object` | **匿名引用**：**不**写明文 **`matchResultId`**；**R6** 实现 **hash / fingerprint** 策略（见 **§9** 日志与隐私）。 |
| **`eligible` / `reason`** | `boolean` / `string` | 自 **`rrmV2Top2Selector`** 拷贝或 **derive**；**不得**扩写为「新匹配决策」。 |
| **`selectedTop2`** | `array` | **长度 ≤ 2**；每项见 **§3.2**。 |
| **`contextFlags`** | `object` | 与 **R2B** 同形或 **子集**（**R6** 决定是否镜像全量）。 |
| **`scoreShadowPresence`** | `object` | **至少**含 **`v2: true`**（**required**）；**可选**含 **`v1LegacyPresent`**（**legacy 观测**）。**仅** **`v2`** 参与 **§5** validator；**`v1LegacyPresent`** **不参与** pass/fail。 |
| **`generatedAt`** | `string` | **ISO-8601**。 |

### 3.2 `selectedTop2` item（每项最小集）

| 字段 | 说明 |
|------|------|
| **`rank`** | **`1`** 或 **`2`**；与 **`top1` / `top2`** 语义一致；**不重复**。 |
| **`candidateRef`** | **匿名候选引用**（**fingerprint**）；**不**在合同示例中写真实 **`candidateUserId`**。**R6** 若需在 **resolver 内存** 中解析为 UUID，**不得**把明文 id 写入 **客户端错误 payload**。 |
| **`candidateUserId` 持久化说明** | **默认**：本 meta **不定义**对 **`MatchResult.candidateUserId`** 的更新；若 **M5 风格** 的 **frozen display meta 表** 在 **R6+** 复用，**`newDisplayCandidateUserId`** 类字段 **仅** 允许落在 **`selectedTop2` 子集** 内，且 **须** 与 **`displaySourceType`** 联查；**主行 `candidateUserId` 仍真源**。 |
| **`displayReasonCode`** | 短枚举串（**R6** 定表），用于 **UI 解释** / 日志聚合 **不含 PII**。 |
| **`scoreSummary`** | **`displayScore100` / `band`** 等 **脱敏数值**；**不**复制完整 **`matchInsights`**。 |
| **`safetySummary`** | **fallback** 相关布尔或计数（例如 **profile 缺失时是否允许仅展示 rank1**）；**R6** 细化。 |

**禁止语义**：**`selectedTop2`** **不是**「新的最终匹配结果」；**`rank=1`** **不等价**于 **worker winner** 除非与 **`top1CandidateUserId`** 与 **`MatchResult.candidateUserId`** 关系已在 **R6** 文档化且 **validator** 校验通过。

## 4. `displaySourceType` contract

### 4.1 候选项（概念）

| 值 | 含义（摘要） |
|----|----------------|
| **`rrm_top2_bounded_selector`** | **现有 M5.3**：**`MatchResultRrmTop2DisplayMeta`** 驱动；与 **V2 selector shadow** **不同源**（**R1** / **R4**）。 |
| **`rrm_top2_v2_selector_readonly`**（**建议新增**） | **M6**：**只读**消费 **`rrmV2Top2Selector`（及/或 §3 meta）** 的 **GET 展示路径**；**不**表示 **RRM 模型已裁决**。 |

### 4.2 建议（R5 合同）

- **优先使用**：**`rrm_top2_v2_selector_readonly`** 作为 **M6 V2 selector readonly display** 的 **`displaySourceType`**（当 **validator 全通过** 且 **flag 开启** 时）。  
- **理由**：与 **M5 `rrm_top2_bounded_selector`** **区分**，避免运维 / 产品将 **「M5 RRM meta 展示」** 与 **「M6 selector 只读展示」** 混淆；**不**暗示 **真实 RRM decision** 已完成。  

### 4.3 实现前闸门（R6）

**是否**在 **TypeScript union / Prisma / OpenAPI** 中 **新增枚举字面量**，须在 **R6 开干前** **diff** 现有 **`matching-result-display.ts`**（及 API DTO）再定；**R5 不修改代码**。

## 5. Parser / validator contract

未来 **parser / validator**（**R6** 落地）**必须**满足以下检查；**任一失败** → **fallback**（**§6**），**禁止**将解析错误 **throw** 到用户可见页面（服务端记录 **脱敏** 日志）。

| # | 规则 |
|---|------|
| 1 | **`schemaVersion === 1`**（或当时最新合同版本）。 |
| 2 | **`sourceVersion`** 与 **R5** 表定义一致（初值建议对齐 **`m6.0-rrm-v2-top2-selector-shadow-v1`** 或 **映射表** 一行）。 |
| 3 | **`eligible === true`**。 |
| 4 | **`reason === 'ok'`**（**strict** 路径；弱理由模式须 **新 schemaVersion**，**不在 R5**）。 |
| 5 | **`selectedTop2`** 为 **数组**。 |
| 6 | **`selectedTop2.length >= 1`** 且 **`<= 2`**。 |
| 7 | 每项含 **`rank`**，且 **`rank`** 在 **`{1,2}`** 内 **不重复**。 |
| 8 | **`candidateRef`** 合法（**kind** + **fingerprint** 非空；**R6** 定义解析回内部 id 的规则）。 |
| 9 | **`contextFlags` 全部处于可展示状态**（**strict V2 readonly display** 合同：**四个布尔均为 `false`**）。*说明：* **R2B** 允许 **`eligible=true`** 且 **部分 flag 为 `true`**；本 **strict** 门用于 **「无风险提示的只读展示路径」**。若产品需 **「带风险提示仍展示」**，须在 **后续 schemaVersion** 单列策略（**R6+**）。 |
| 10 | **`scoreShadowPresence.v2 === true`**。**不得**检查 **`scoreShadowPresence.v1 === true`**（或 **`v1LegacyPresent`**）作为通过条件；**v1 缺失** **不**触发 **fallback**。 |

## 6. Fallback contract

### 6.1 触发 fallback 的条件（任一）

- **meta** 不存在（无表行 / 无 JSON 键 / 未生成镜像）。  
- **Payload parse** 失败（JSON 非法 / 类型漂移）。  
- **`schemaVersion`** 不匹配。  
- **`sourceVersion`** 不匹配。  
- **`eligible !== true`**。  
- **`reason !== 'ok'`**（**strict** 路径）。  
- **`selectedTop2`** 为空。  
- **`selectedTop2.length > 2`**（数据异常）。  
- **候选用户**不存在或 **profile** 不存在。  
- **`contextFlags`** 未满足 **§5 strict**（或 **产品定义** 的高风险拦截）。  
- **`scoreShadow` v2** 缺失（不满足 **§5** 第 **10** 条）。  
- **`scoreShadow` v1** 缺失 **不**触发 **fallback**；若 **当前实现** 仍显式依赖旧 **v1** 作为 **required**，应在 **R6** 前 **移除**或 **降级**为 **legacy observation**。  
- **`PEIMA_M6_RRM_V2_SELECTOR_DISPLAY_ENABLED`** **关闭**。  
- **任意未捕获异常**（内部 **fallback**）。

### 6.2 优先级（与 **R4** 一致）

1. **已有 pairwise display path**（若仓库 **env + meta** 已存在且 **validator** 通过）。  
2. **`match_result_original`**（**`displayCandidateUserId = candidateUserId`**，**`meta`** 按 **R1** 空 / null 约定）。

**强调**：fallback 是 **展示层 fallback**，**不是**重新匹配；**不**改变 **`MatchResult`** 主行 **决策字段**。

## 7. 数据写入策略建议（仅讨论，不实现）

| 方案 | 描述 | 利弊（摘要） |
|------|------|----------------|
| **A** | **Dedicated display meta 表**（新表或新 JSONB 列专用于 **M6 readonly**）。 | 观测与 **M5** 隔离最好；需 **migration** 与审计成本。 |
| **B** | **复用 `MatchResultRrmTop2DisplayMeta`**（扩 **`meta` / `version`** 字段区分 **M5 vs M6**）。 | 少一张表；**易与 M5 RRM 语义耦合**，须 **严格 `sourceType` / `version` 分支**（**R6** 评审）。 |
| **C** | **暂不从新表读**：仅从 **`matchInsights.rrmV2Top2Selector`**（及必要 **GET** 组装字段）**现场构造** §3 形状 **in-memory**，**不持久化** meta。 | **零 migration**、**R6 最小接线**；**可重复计算**、无 **frozen** 快照，若需 **审计轨迹** 再演进到 **A/B**。 |

**推荐（R5）**

- **短期（R6）**：优先 **方案 C** 或 **最小 B**（仅在 **不破坏 M5 冻结语义** 的前提下 **扩展**），以 **避免 schema migration** 阻塞试验。  
- **中期**：若生产观测需要 **冻结快照 / 审计 / 对账**，再评估 **方案 A** 或 **清洁版 B**。

## 8. Feature flag contract

| 项 | 合同 |
|----|------|
| **名称** | **`PEIMA_M6_RRM_V2_SELECTOR_DISPLAY_ENABLED`**（与 **R4** 一致）。 |
| **默认** | **关闭** → **完全**走既有 **GET** 路径（**不**构造 §3 meta）。 |
| **开启** | **仅**当 **resolver** 尝试 **V2 selector readonly display** 分支；**任一 validator 失败** → **fallback**。 |
| **作用域** | **只影响 display resolver（及聚合 DTO）**；**不影响** worker、**`finalScore`**、**`candidateUserId`**、**M5 RRM resolver** 调用链。 |

## 9. FinalMatchPage contract

- **不**解析 **`matchInsights.rrmV2Top2Selector`**。  
- **不**计算 **`selectedTop2`**、**不**判断 **`eligible` / `contextFlags`**。  
- **只**消费后端 **GET** 已返回的 **`displayCandidateUserId`**、**`displaySourceType`**、**`explanation` / `reasonSummary`** 等 **payload**（与 **R4**、**R1** 分层一致）。  
- **页面层**最多展示：**`displaySourceType`**、**`sourceVersion`**（若 API 暴露）、**`fallbackUsed`**（若 **R6** 增加）、**`reasonSummary`** 等 **非敏感** 文案；**不**展示 raw **`matchInsights`** JSON。

## 10. `scoreShadow` v1 lifecycle（合同层说明）

- **R3B** 曾记录 **v1 / v2 均存在**，是 **历史 DB 实测事实**（见 **`M6.0-r3b-rrm-v2-top2-selector-db-regression.md`** **§v1.1**），**不**反向约束 **R5+** 合同。  
- **R5+ 正式 contract** **只依赖** **`scoreShadowV2`**（**V2-only 主线**）。  
- **`scoreShadow` v1** 当前合同定位为：**legacy / deprecated / non-blocking**（**观测**、**历史兼容**）。  
- **从 R5 开始**：**不允许**为 **RRM V2 selector readonly display** **新增** 对 **v1** 的 **required** 依赖。  
- **v1 removal**（代码 / worker / API 清理）**不在 R5** 做。  
- 待 **RRM V2 readonly display MVP** 完成并通过回归后，**单独**进入：  
  - **M6.0-r9** — **`scoreShadow` v1 dependency audit**  
  - **M6.0-r10** — **`scoreShadow` v1 removal**
