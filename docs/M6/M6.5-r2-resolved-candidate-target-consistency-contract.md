# M6.5-r2 — Resolved Candidate / Target Consistency Contract

## 1. 本轮目标

- **M6.5-r1** 已定义 **true bounded decision pilot design**（**A/B/C** 路径、**gates**、**API / admin** 需求草案）。
- **M6.5-r2（本文）**：专门定义 **`resolvedCandidate`** 与 **各下游 target**（页面、**chat**、**timeline**、**feedback**、**explanation**、**score**）**必须跟随谁**，防止「**页面一个人、聊天另一个人、解释又指向第三个人**」。
- **r2** **只**输出**合同文档**；**不**实现代码；**不**改变现有业务逻辑（**`resolveMatchResultDisplay`**、**`FinalMatchPage.jsx`**、**worker** 等**本轮均不改**）。

---

## 2. 问题背景

当未来出现以下**任一**组合时，若缺少统一 **`resolvedCandidate`** 合同，系统易出现**用户可见不一致**：

| 现象 | 风险 |
|------|------|
| **`MatchResult.candidateUserId` = A** | **持久化 baseline** 仍为 **A**。 |
| **`displayCandidateUserId` = B** | **读层 override** 或 **readonly display** 可能展示 **B**。 |
| **FinalMatchPage 展示 B** | 用户以为「匹配对象是 **B**」。 |
| **Chat 进入 A** | **会话**仍按 **`candidateUserId`** 或旧入口绑定。 |
| **Timeline 记录 A** | **关系时间线**与展示不一致。 |
| **`finalScore` 仍解释 A** | **分数**与 **B** 的展示语义冲突。 |
| **`primaryConclusion` / `matchReview` 混用 A 与 B** | **解释层**不可信。 |
| **Feedback 归因不明** | **污染**后续学习与运营判断。 |

**本合同目标：** 在 **API 层**定义 **`resolvedCandidate`** 与各 **owner / target** 的**解析规则**与 **fallback**；**前端**只消费**投影字段**，**不**自算 **RRM switch**。

---

## 3. 核心概念定义

以下名称为**逻辑角色**（**r2 不**新增 DB 列）；**不写**真实 **userId**。

### 3.1 `baselineCandidate`

- **含义**：当前 **worker baseline winner**。
- **通常**：等于 **`MatchResult.candidateUserId`**（**`batch-match.processor.ts`** 主路径落库）。
- **性质**：**持久化主结果**锚点；**flag off** 时一切用户动作**应**可退回至此。

### 3.2 `displayCandidate`

- **含义**：当前 **页面主展示**应使用的候选对象。
- **来源**：可能等于 **baseline**；也可能来自 **M6.0** **readonly display**（**`rrm_top2_v2_selector_readonly`**）、未来 **bounded read-layer override** 等（见 **`resolveMatchResultDisplay`**，**`matching-result-display.ts`**）。
- **性质**：**读层**语义；**不等于**自动承认 **true bounded** 已改写主结果。

### 3.3 `decisionCandidate`

- **含义**：**未来** **true bounded decision** 在 **meta** 中选中的对象（**Top2 闭包**内）。
- **生效条件**：仅当 **true flag + gates** 允许且 **`actualSwitch=true`**（**Strategy C** 时还可能与 **`candidateUserId`** 对齐）时，才与 **baseline** 可能不同。
- **当前**：**dry-run** 下仅有 **「would」** 语义，**不得**当作 **`resolvedCandidate`** 唯一来源。

### 3.4 `resolvedCandidate`

- **含义**：**用户体验层**默认应统一的「**最终对象**」。
- **约束**：**FinalMatchPage** 主视图、**chat**、**timeline**、**feedback** **默认**均围绕 **`resolvedCandidate`**，**除非**产品显式定义「双轨」且**用户可见**披露（**一般禁止默认双轨无提示**）。

### 3.5 `scoreOwnerCandidate`

- **`finalScore` / `relationshipProfileScore`** 所**归属解释**的候选。
- **禁止**：把 **A** 的分数**直接**当作 **B** 的匹配质量解释（**M6.4-r2 §10**）。

### 3.6 `explanationOwnerCandidate`

- **`primaryConclusion` / `matchExplanation` / `matchReview` / `reasonSummary`** 等解释文本所**绑定**的候选。
- **通常**：**应等于** **`resolvedCandidate`**；若不等，**须** **UI** 显式区分（**技术折叠区**），且 **M6.5-r3+** 锁 **OpenAPI** 语义。

---

## 4. Candidate resolution rule 草案

**优先级草案**（**由上至下**匹配；**不**在本轮实现）。**任何异常** → **§11 fallback**。

1. **若** **true bounded decision enabled** 且 **`actualSwitch=true`**（**Strategy C** 已落地且门控通过）：  
   **`resolvedCandidate` = `decisionCandidate`**（且 **`candidateUserId`** 已与 **C** 合同对齐时，三者可收敛）。

2. **若** **read-layer override enabled** 且 **display override** 合法（**Strategy A**，**未**改 **`candidateUserId`**）：  
   **`resolvedCandidate` = `displayCandidate`**。  
   **必须**：**`resolvedSourceType`**（或等价字段）标记为 **read_layer_override**；**`displaySourceType` / `decisionSourceType`** 明示 **bounded / fallback**；**文档与用户可见文案**须说明 **`candidateUserId`（baseline）未改**。

3. **若** **readonly display path** 合法（**M6.0**，**`rrm_top2_v2_selector_readonly`** 等）：  
   **`resolvedCandidate` = `displayCandidate`**。  
   **必须**：**不得**将 **readonly** 误标为 **true bounded decision**（**M6.0-r8** 精神）。

4. **否则**：  
   **`resolvedCandidate` = `baselineCandidate`**。

**冲突处理：** 若 **2** 与 **3** 同时「看似可用」，**须**在 **M6.5-r3** 固定 **优先级表**（建议：**safety > readonly > experiment**），**r2** 不强行定案数值优先级，只要求**唯一** outcome。

## 5. Target consistency matrix

| Target | Should follow | Notes |
|--------|---------------|-------|
| **FinalMatchPage 主资料 / Hero** | **`resolvedCandidate`** | 主展示对象与 **API** 投影一致。 |
| **Chat target** | **`resolvedCandidate`** | **须**与 **Start Chat** 入口一致；若与 **`candidateUserId`** 不同，**须** **`chatTargetUserId`** 显式返回（**§8**）。 |
| **Timeline target** | **`resolvedCandidate`** | 关系记录归属与展示一致。 |
| **Feedback target** | **`resolvedCandidate`** | 反馈归因与产品对象一致。 |
| **Match explanation 系列** | **`explanationOwnerCandidate`** | **通常** **= `resolvedCandidate`**；若不等则 **§7** 禁止默认无提示混用。 |
| **Score 主视觉 / 文案** | **`scoreOwnerCandidate`** | **不得**混用 **baseline** 分解释 **display-only** 的另一候选（**§6**）。 |
| **Technical details（折叠区）** | **baseline + resolved + source** | 可展示 **`displaySourceType` / `fallbackReason` / owners**；**不改变**默认主路径语义。 |

---

## 6. Score consistency rules

| 情形 | 规则 |
|------|------|
| **`resolvedCandidate` = `baselineCandidate`** | **`finalScore`** **可**沿用 **baseline** 语义（与当前产线一致）。 |
| **`resolvedCandidate` ≠ `baselineCandidate`** | **禁止**把 **baseline `finalScore`** **直接**当作 **`resolvedCandidate`** 的匹配质量解释。 |

**未来实现候选**（**r2 不定案**；与 **M6.4-r2 §10** 对齐）：

| 策略 | 含义 |
|------|------|
| **A** | **`resolvedScore`** = **target** 在池内已存在、可追溯的分数分量。 |
| **B** | **`decisionScore`** = **bounded decision** 专用分量，与 **`finalScore`** 解耦展示。 |
| **C** | **`finalScore`** **仍** = **baseline**，**UI** **明确** **`scoreOwnerCandidateUserId`** 与 **「展示对象为 B、分数仍为 A」** 的语义（**一般仅过渡**）。 |

**禁止原则：** **无** **score contract** 时，**不得**上线「**展示 B + 默认暗示分数属于 B**」的组合。

---

## 7. Explanation consistency rules

若 **`resolvedCandidate`** 相对 **baseline** **发生变化**（**read-layer** 或 **true**），**须同步**以下语义归属（**全**绑定 **`explanationOwnerCandidate`**，**默认** = **`resolvedCandidate`**）：

- **`primaryConclusion`**
- **`matchExplanation`**
- **`matchReview`**
- **`relationshipProfileScore`**（展示向）
- **`reasonSummary`**
- **风险备注 / conversation starters / chat tips**（若存在且用户可见）

**禁止：** 页面展示 **B**，但上述任一块仍**默认**引用 **A** 的文案而不加 **显式** **来源** / **fallback** 说明。

---

## 8. Chat / Timeline / Feedback consistency

### 8.1 Chat

- 用户触发 **「Start Chat」**（或等价入口）时，**应**进入 **`resolvedCandidate`** 对应的会话对象。
- **若** **`resolvedCandidate` ≠ `MatchResult.candidateUserId`**：**API** **必须**返回 **`chatTargetUserId`**（或与 **`resolvedCandidateUserId`** 同值），**前端** **禁止**自推。

### 8.2 Timeline

- **Timeline entry** **应**归属 **`resolvedCandidate`**。
- **若**因技术限制仍绑定 **baseline**：**须** **`timelineTargetUserId`** 与 **UI** 一致，或 **fallback** 并 **标记** **override disabled**（**不得**静默混用）。

### 8.3 Feedback

- **反馈** **应**归因到 **`resolvedCandidate`**。
- **否则**后续 **ML / 运营 / 质量** 分析会被 **错误标签** 污染。

## 9. API response contract needs

**未来** **`GET /matching/result`**（及同源只读 API）**可能**需扩展的**投影字段**（**r2 不实现**；路径占位 **`/matching/result/:userId`** 以项目实际路由为准）：

| 字段 | 说明 |
|------|------|
| **`candidateUserId`** | **持久化**主字段（**baseline**）。 |
| **`baselineCandidateUserId`** | 通常与 **`candidateUserId`** 相同；用于显式对账。 |
| **`displayCandidateUserId`** | **已存在**于 **display slice**；未来与 **`resolvedCandidate`** 对齐策略在 **M6.5-r3** 锁死。 |
| **`decisionCandidateUserId`** | **Meta** 选中对象（**审计**）。 |
| **`resolvedCandidateUserId`** | **用户体验**默认锚点。 |
| **`resolvedSourceType`** | **baseline / readonly_display / read_layer_override / true_bounded / fallback_baseline** 等（**枚举在 r3** 定稿）。 |
| **`displaySourceType`** | 见 **`MatchResultDisplaySourceType`**（**`matching-result-display.ts`**）。 |
| **`decisionSourceType`** | **bounded / baseline / fallback** 等（**可选**新字段）。 |
| **`fallbackUsed` / `fallbackReason`** | 与 **resolver** 分支一致。 |
| **`scoreOwnerCandidateUserId`** | **§6**。 |
| **`explanationOwnerCandidateUserId`** | **§7**。 |
| **`chatTargetUserId` / `timelineTargetUserId` / `feedbackTargetUserId`** | **§8**；**默认**应等于 **`resolvedCandidateUserId`**。 |

## 10. Source type taxonomy

下表区分 **「类型标签」** 与 **当前代码是否已有同名 `displaySourceType`**；**未来**可收敛到 **`resolvedSourceType` + `displaySourceType`** 组合。

| Taxonomy | 影响 `resolvedCandidate`？ | 影响 `candidateUserId`？ | Chat / Timeline 默认 |
|-----------|----------------------------|---------------------------|------------------------|
| **`match_result_original`** | **否**（= baseline） | **否** | **baseline** |
| **`static_final` / `pairwise_final` / `static_fallback`**（现有 **finalize** 路径） | **可能**（= **`displayCandidate`**） | **否**（**pairwise** 合同下 **selected** 与主字段关系见 **resolver** 注释） | **须**与 **finalize** 合同一致 |
| **`rrm_top2_bounded_selector`**（**M5** display meta） | **可能** | **否** | **须**随 **`displayCandidate`** / 合同 |
| **`rrm_top2_v2_selector_readonly`**（**M6.0**，已存在 **`MatchResultDisplaySourceType`**） | **可能**（**display** ≠ **baseline** 时） | **否** | **应**随 **`resolvedCandidate`**（**= display** 若采纳 **§4.3**） |
| **`rrm_decision_shadow`** | **否**（**仅 meta**；**不**自动切换用户动作） | **否** | **baseline**（除非上层显式消费，**当前不推荐**） |
| **`rrm_bounded_decision_dry_run`** | **否** | **否** | **baseline** |
| **`rrm_true_bounded_decision_read_layer`**（**建议名**，**r3** 可改名） | **是**（若门控通过） | **否** | **`resolvedCandidate`** |
| **`rrm_true_bounded_decision_enabled`**（**建议名**） | **是** | **可能**（**Strategy C**） | **`resolvedCandidate`** |
| **`fallback_baseline`** | **强制**回 **baseline** | **否** | **baseline** |

## 11. Fallback rules

**任一**以下条件成立 → **fallback baseline**（**`resolvedCandidate` = `baselineCandidate`**，**`fallbackUsed=true`**，**`fallbackReason`** 为闭集字符串，与 **M6.3-r2 / M6.4-r1** 对齐）：

- **Resolved target** 缺失或不可用（用户删、池外等）。
- **User / profile** 缺失。
- **`scoreOwner` / `explanationOwner`** 与 **`resolvedCandidate`** **无法**一致绑定。
- **Chat / timeline** 目标不可用。
- **`sourceVersion` / `schemaVersion`** 不匹配或 **meta malformed**。
- **`guardrail` blocked**。
- **True flag off** 或 **read-layer flag off**。
- **Unexpected exception**（**resolver** **吞并**并 **fallback**，**不** **500** 用户页）。

---

## 12. Frontend rule

- **`FinalMatchPage.jsx`** **不**解析 raw **`rrmDecisionShadow` / `rrmBoundedDecision`**。
- **不**自行判断 **`switch` / `wouldSwitch`**。
- **只**消费 **API** 返回的 **`resolved*` / `display*` / `chatTarget*`** 等投影字段（**M6.0-r8** 延伸）。
- **Chat / Timeline** 按钮使用 **API** 返回的 **target IDs**。
- **技术折叠区**可展示 **source / fallback / owner**；**不**在客户端重算 **resolver** 逻辑。

---

## 13. Backend resolver responsibility

**`resolveMatchResultDisplay`** 及未来 **`GET /matching/result`** 聚合层**必须**：

- 读取 **baseline**（**`MatchResult`** 行）。
- **校验** **display / decision meta**（版本、**Top2**、**guardrails**、**flag**）。
- **决定** **`resolvedCandidate`**、**`scoreOwnerCandidate`**、**`explanationOwnerCandidate`**。
- **决定** **`chatTarget` / `timelineTarget` / `feedbackTarget`**（**默认**对齐 **`resolvedCandidate`**）。
- **输出**统一 **API contract**（**M6.5-r3** 落 OpenAPI 草案）。
- **异常** → **fallback baseline**；**不 throw** 到用户页。
