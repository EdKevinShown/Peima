# M6.0-H2 — FinalMatchPage V2 primary score feature flag

> **范围**：落实 **M6.0-H1** 方案：在 **`FinalMatchPage`** 用 **前端 feature flag** 控制主视觉是否优先 **`relationshipProfileScoreV2.displayScore100`**，并保留 **legacy `finalScore` v1** 于技术区。  
> **本轮**：**仅改 Web 前端**（及 **`.env.example` 说明**）；**不改 API**、**不改 worker**、**不改** **`MatchResult.finalScore` / `candidateUserId` / `displayCandidateUserId` / RRM**。

---

## 1. 一句话结论

**`VITE_FINAL_MATCH_USE_V2_PRIMARY_SCORE=1`** 时，**主视觉**优先展示 **合法 V2**（**`displayScore100` / 100** + **band 副文案** + **H1 说明句**）；**`missing` / `invalid`** 时 **fallback `legacy finalScore` v1`** 并附 **轻提示 / 状态提示**；**flag 关闭**时行为与 **H2 前**一致。**技术折叠区**（含 **legacy**、**scoreBreakdown**、**V2 实验**、**RRM**）**全保留**。

---

## 2. Flag 与代码位置

| 项 | 说明 |
|----|------|
| **变量名** | **`VITE_FINAL_MATCH_USE_V2_PRIMARY_SCORE`** |
| **启用值** | 仅 **`"1"`**（字符串）为 **开启** |
| **默认** | **未设置或非 `1`** → **legacy 主视觉** |
| **读取** | `apps/web/src/pages/FinalMatchPage.jsx` → **`readV2PrimaryScoreFlag()`** |
| **主分逻辑** | **`resolvePrimaryMatchScore(result)`**（同文件） |
| **Hero** | `apps/web/src/components/final-match/FinalMatchHero.jsx` |

---

## 3. `resolvePrimaryMatchScore` 行为摘要

1. **Flag 关**：`{ kind: "legacy" }` → Hero 使用 **`formatScoreDisplay(finalScore)`**（现网逻辑）。  
2. **Flag 开 + `relationshipProfileScoreV2.source === "match_insights_score_shadow_v2"` 且 `displayScore100` 为 0–100 有限数**：`{ kind: "v2", ... }` → Hero 展示 **V2**。  
3. **Flag 开 + `source === "missing"`**（或无合法 V2）：`legacy_fallback` + **`finalScore`** + **「该结果生成较早，暂无 V2 关系画像分。」**（Hero 内）。  
4. **Flag 开 + `source === "invalid"`**：`legacy_fallback` + **`finalScore`** + **Hero 下方** **`role="status"`** 提示 **「V2 shadow 数据异常，已使用旧版匹配指数。」**

---

## 4. 未改动的系统边界

- **API** 响应契约、**`matching.service.ts`**、**worker**、**Prisma**、**RRM resolver** 均未改。  
- **`MatchResult.finalScore`** **仅作读数与 fallback**，**不写入、不重算**。
