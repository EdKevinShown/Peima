# M6.3-r1 — RRM Bounded Decision Contract

## 1. 本轮目标

- **M6.0** 已完成：**RRM V2 readonly display**（**resolver behind flag**、**FinalMatchPage** 只读展示面、**`scoreShadow` v1** runtime 依赖移除等）。
- **M6.1** 已完成：**RRM decision shadow**（**`matchInsights.rrmDecisionShadow`** 设计、**`PEIMA_M6_RRM_DECISION_SHADOW_ENABLED`** 下 worker **shadow-only** 写入、回归与 **push prep**）。
- **M6.2** 已完成：**Shadow batch evaluation**（计划、只读聚合器、本地 run、正式报告、**r5** 最终回归 / **push prep**）。
- **M6.3** 开始定义 **RRM bounded decision**：在 **Top2 / shadow payload / guardrails** 约束下的**有限**正式决策空间（**与**全池重算 **RRM ranking** **区分**）。
- **M6.3-r1（本文）**：**仅**输出 **安全合同**（定义、输入输出、flag、允许切换条件、**fallback**、评估门槛、解释统一要求）；**不实现代码**；**不让 RRM 在本轮改正式匹配结果**。

## 3. Bounded decision 定义

**Bounded decision** **=** **RRM**（或等价编排）**仅允许**在以下**已有闭包**内做**有限**的「是否采用 **shadow** 指向的 **Top2 内**候选」判断：

- **不得**扩大候选池或从全池重选；
- **不得**调用**额外**的 **RRM resolver** 以改写全局 **ranking** 或 **worker** 主排序逻辑；
- **不得**绕过 **M6.1** 已定义的 **guardrails** 与 **`blockReasons`** 语义；
- **不得**在条件不满足时**无条件**推翻 **worker baseline winner**。

**与 M6.1 shadow 的关系：** **Shadow** 至今为**观测**侧车；**bounded decision** 若未来生效，是在**更强门控**下，**可选地**将 **shadow** 的 **`switch_to_top2_candidate`** **收敛**为**正式**路径 — **须在单独 flag 与实现**中完成（**不在 r1**）。

---

## 4. Baseline / Shadow / Bounded decision 三者关系

| 概念 | 定义 |
|------|------|
| **Baseline** | **当前 worker** 的正式 **winner**：**`MatchResult.candidateUserId`**、**`finalScore`**、以及既有 **ranking / matchInsights** 中与 baseline 一致解释的字段。 |
| **Shadow** | **`matchInsights.rrmDecisionShadow`**（**M6.1-r2 contract**）：**`same` / `switch` / `no_shadow`**、**`comparison`**、**`guardrails`**、**`inputPresence`**；**默认不**改变 **`candidateUserId`**。 |
| **Bounded decision** | **未来**在**单独 feature flag**（见 **§5**）下，依据 **shadow + guardrails + 输入完备性**，在 **`selectedTop2`** 闭包内决定是否采用 **RRM** 建议的 **switch**；**必须**保留 **fallback 到 baseline** 的优先级高于「激进采用 shadow」。 |

## 5. Feature flag contract

### 5.1 主开关（建议名）

**`PEIMA_M6_RRM_BOUNDED_DECISION_ENABLED`**

| 语义 | 说明 |
|------|------|
| **默认** | **关闭**（未设置或非 **`"1"`**）。 |
| **开启** | 仅 **`"1"`** 表示允许 **bounded decision** **参与**正式结果路径（具体写策略见 **M6.3-r2**）。 |
| **关闭时** | **完全**沿用 **baseline worker winner**（与 **M6.1** 仅 shadow 写入时一致）。 |
| **异常** | 任意未捕获异常或契约不满足 → **fallback baseline**（与 **M6.1**「shadow 不 throw 主流程」精神一致，但 **bounded** 层**不得**留下与 baseline 矛盾的半状态）。 |
| **无 shadow 行** | **不得**因缺失 **`rrmDecisionShadow`** 而失败；**视为** baseline。 |

### 5.2 可选干跑开关（建议名）

**`PEIMA_M6_RRM_BOUNDED_DECISION_DRY_RUN`**

| 语义 | 说明 |
|------|------|
| **用途** | 未来实现阶段可先**记录** bounded **suggestion**（例如写入**只读 meta** 或日志），**不**改变 **`candidateUserId`** / **展示**；用于观测与对账。 |
| **默认** | **关闭**；与主开关组合策略在 **r2** 细化。 |

**说明：** **r1** 不绑定具体 env 解析实现；仅定义**语义合同**。

## 6. Input contract

### 6.1 允许读取（白名单）

Bounded decision 逻辑**仅可**基于以下**已持久化或已由 worker 计算**的输入（**不得**隐式拉全池或重跑 LLM）：

- **Baseline 候选**：当前 **worker winner** 标识（在代码层为内部 ID；**文档不写真实 ID**）。
- **`finalScore`**（及与 **baseline** 解释一致的摘要字段，若需要）。
- **`matchInsights.scoreShadowV2`**
- **`matchInsights.rrmV2Top2Selector`**（含 **`selectedTop2`**、**`contextFlags`**、**`eligible`**、**`reason`** 等契约字段）。
- **`matchInsights.rrmDecisionShadow`**
- **`sourceVersion` / `generatedAt`**（用于版本门控与审计）。

### 6.2 明确禁止

- **不读取**、**不依赖** **`scoreShadow`（v1）**；**不因 v1 缺失**而 **fallback** 到任何「特殊分支」。
- **不使用 raw LLM** 对匹配结果做**重新决策**。
- **不扩大**候选池；**不在 `selectedTop2` 外**选择 switch target。

---

## 7. Allow switch conditions（未来实现的最低条件）

以下**全部**满足时，**才允许**进入「考虑 **`use_rrm_switch`**」路径（**仍**可能因 **dry-run** 或 **写策略** 不落库）：

- **`PEIMA_M6_RRM_BOUNDED_DECISION_ENABLED === "1"`**
- **`rrmDecisionShadow`** 存在且为**可解析对象**
- **`schemaVersion === 1`**
- **`sourceType === "rrm_decision_shadow"`**
- **`sourceVersion`** 与允许列表一致（当前产线为 **`m6.1-rrm-decision-shadow-v1`**，未来变更须**显式**扩容白名单）
- **`shadow.decision === "switch_to_top2_candidate"`**
- **Switch target** 严格位于 **`selectedTop2`** 内，且与 **shadow** 内一致引用
- **Switch target** **用户**存在；**`UserProfile`**（或契约等价物）存在且满足最低可读性门槛
- **`scoreShadowV2`** 存在
- **`rrmV2Top2Selector.eligible === true`**
- **`rrmV2Top2Selector.reason === "ok"`**
- **`contextFlags`** 处于**合同定义的安全组合**（无 **low band**、**strong conflict**、**below suggested floor**、**top2 gap large** 等高风险信号 — 与 **M6.1** **blockReasons** 闭集对齐）
- **`guardrails.blocked === false`**
- **`guardrails.blockReasons`** 为空数组
- **无** **`unexpected_exception`** / **`parse_error`**（及 **invalid selector** 类原因）
- **存在**可用的 **fallback 到 baseline** 路径（实现层须保证原子性或可回滚叙事）

---

## 8. Must fallback conditions

**任一**成立则**必须** **`use_baseline` / `fallback_baseline`**（**不得**采用 switch）：

- **Bounded flag** 未开启或非 **`"1"`**
- **缺失** **`rrmDecisionShadow`** 或 **malformed**
- **`decision === "same_as_baseline"`** 或 **`decision === "no_shadow_decision"`**
- **`sourceVersion` / `schemaVersion` / `sourceType`** 与允许值不一致
- **`scoreShadowV2`** 缺失
- **`selectedTop2`** 缺失或语义为空
- **Switch target 不在 Top2** 或与 selector 行不一致
- **候选用户或 profile 缺失**
- **`guardrails.blocked === true`** 或 **`blockReasons`** 非空
- **`contextFlags`** 命中高风险（与 **§7** 互斥）
- **`reason !== "ok"`** 或 **`eligible !== true`**
- **异常**、**解析错误**、**unexpected_exception**
- **评估门槛未满足**（见 **§12**：样本多样性、**admin observation**、聚合指标等）
- **若产品要求**：**admin / observation gate** 未就绪 → **fallback**

## 10. `candidateUserId` / `displayCandidateUserId` / `finalScore` 处理原则

**候选策略（r1 不选定案，仅列风险与原则）：**

| 方案 | 思路 | 优点 | 缺点 / 风险 |
|------|------|------|-------------|
| **A** | **Bounded** 只影响 **`displayCandidateUserId`**（或等价只读展示字段），**不改** **`MatchResult.candidateUserId`** | **与正式链解耦**，回滚简单 | **非**完整「正式决策」；解释层须防漂移 |
| **B** | **Flag** 开启时**直接改** **`MatchResult.candidateUserId`** | **进入正式决策链** | **风险最高**；须 **事务**、**审计**、**回滚**、与 **conversation / review** 一致 |
| **C** | **新增** **`decisionCandidateUserId` / `decisionSourceType`** 等 meta，**保留**原 **`candidateUserId`** | **可追踪**、对账友好 | 可能涉及 **schema / API** 扩展 — **须单独立项** |

**r1 原则（必须遵守）：**

- **不得**让 **`candidateUserId`**、**`displayCandidateUserId`**、**`finalScore`** 在**产品解释**上**互相矛盾**。
- 若最终**修改** **`candidateUserId`**，**必须**同步：**解释层**、**fallback meta**、以及与 **M6.0 readonly display** 相关的 **`displaySourceType`** 叙事。
- **`finalScore`** **不应**在无重新计算契约的情况下，**直接复用 baseline 分数**去「代表」switch target（除非 **r2** 定义明确的 **score 语义**与 **版本**）。

**定案时机：** **M6.3-r2 — Bounded Decision Write Strategy**。

## 12. Evaluation gate（进入 **implementation** 前）

在 **bounded decision implementation** 之前，**至少**需要：

- **M6.2** aggregator **可用**、可复现。
- **`unexpectedExceptionRate === 0`**（在约定样本窗内）。
- **`invalidSelectorRate` / `missingInputRate`** 处于**可接受**阈值（阈值在 **M6.2** 报告后续迭代中量化）。
- **`blockedRate`** **可解释**（非随机异常）。
- **`sampleSize`** 与 **场景多样性**满足 **M6.2-r1** **pre-pilot** 方向（**多 viewer / 多 pool**）。
- **Admin observation** 方案**明确**（只读聚合、导出、或内部工具 — **不在 r1** 定实现）。
- **Feature flag / rollback** 方案**明确**（见 **§5**）。

**明确：** **当前 M6.2-r4** 的**同质样本**不足以支撑 **implementation** 放行。
