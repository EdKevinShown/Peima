# M6.3-r2 — RRM Bounded Decision Write Strategy

## 1. 本轮目标

- **M6.3-r1** 已定义 **RRM bounded decision** **安全合同**（范围、flag 语义、allow / fallback、输出草案、解释统一门槛等）。
- **M6.3-r2（本文）**：在 **r1** 合同之上，**专门比较并确定** bounded decision 的**写入策略**（改哪些字段、是否 meta、**schema** 取舍、**`finalScore`** 解释、**fallback / audit**）。
- **r2** **不实现代码**；**不让 RRM bounded decision** 在本轮**生效**。

---

## 2. 当前基线

| 项 | 说明 |
|----|------|
| **Baseline winner** | 来自 **worker `batch-match`** 主路径（**ranking / scoring** 不变）。 |
| **`MatchResult.candidateUserId`** | **正式**「最终匹配对象」字段；**M6.1 shadow** **未**修改该字段。 |
| **`displayCandidateUserId`（及 `displaySourceType`）** | **展示读取路径**使用；**M6.0** 已支持在**不改主结果**下，通过 **flag + resolver** 调整只读展示来源（见 **M6.0-r8**）。 |
| **M6.1** | **`matchInsights.rrmDecisionShadow`** 可写入（**shadow-only**）。 |
| **M6.2** | 聚合证明 **shadow** 链路**稳定**，但**样本同质**（**M6.2-r4**），**不足以**直接 **implementation** 改正式 **`candidateUserId`**。 |
| **Bounded decision** | **尚未** **implementation**；**r1** 输出合同与门控已就绪。 |

---

## 3. 写入策略候选

### 方案 A：Display-only bounded decision

**含义：**

- **Bounded** 结论仅影响 **`displayCandidateUserId`** / **`displaySourceType`**（或等价只读展示字段）。
- **不改** **`MatchResult.candidateUserId`**。
- **不改** **`finalScore`**（与 baseline 一致或按 **M6.0** 既有规则解释）。
- 语义上类似 **M6.0 readonly display** 的「升级版」：展示层表达 **RRM** 倾向，**正式行**仍为 baseline。

**优点：** **最安全**；**回滚**简单（关展示 flag）；可作为 **UI pilot**。  
**缺点：** **非**「正式 RRM 决策」；**`candidateUserId`** 与展示对象可能长期不一致，**解释层**必须显著区分「正式 vs 展示来源」。  
**适合：** **M6.3-r3 dry-run** 的**并行观测**或后续 **display pilot** — **但**若仅改展示、**不写**任何持久化 **meta**，**审计**与离线对账弱于 **方案 B**。

---

### 方案 B：Decision meta bounded decision（**推荐：dry-run 首选**）

**含义：**

- **不**直接改 **`candidateUserId`**。
- **新增或复用** **`matchInsights`** 内 **JSON meta**（建议键名 **`rrmBoundedDecision`**），记录 **bounded** 结论、**wouldSwitch**、**fallback**、**guardrails**、**inputPresence**、**`generatedAt`** 等（**红acted ref**，见 **§5**）。
- **后端 resolver** / **聚合脚本** **可选择**读取该 **meta** 做评估或**未来**展示 — **r3** 可默认**不**让 **FinalMatchPage** 读取。
- **正式主字段**仍保留 **baseline** **`candidateUserId`**。

**优点：** **可追踪**、**可审计**、**无需**立即改主结果；为 **方案 C** 过渡提供证据链。  
**缺点：** 依赖 **`matchInsights` JSON** 契约与 **resolver** 纪律；前后端须避免把 **meta** 误当 **`candidateUserId`**。  
**适合：** **M6.3-r3** **dry-run implementation**（**首选**）。

---

### 方案 C：`candidateUserId` bounded decision

**含义：**

- **`PEIMA_M6_RRM_BOUNDED_DECISION_ENABLED`**（**r1**）开启且满足 **allow switch** 时，**直接**将 **`MatchResult.candidateUserId`** 写为 **bounded** 选中候选。

**优点：** **真正**进入「正式决策链」；聊天 / 时间线若默认跟 **`candidateUserId`**，**一致性强**。  
**缺点：** **风险最高**；**`finalScore`** 与 **解释字段** 易不一致；回滚与审计复杂；**需要** **M6.2** 后阶段更大样本与 **admin observation**（**M6.2-r4 / r1 §12**）。  
**适合：** **M6.4+** 或更后；**不适合**作为 **M6.3-r3** 的首发实现。

---

## 4. 推荐策略

**M6.3-r3 推荐采用：方案 B — Decision meta bounded decision（dry-run）**

**具体：**

- **Behind** **`PEIMA_M6_RRM_BOUNDED_DECISION_DRY_RUN_ENABLED`**（见 **§6**）。
- **写入** **`matchInsights.rrmBoundedDecision`**（键名可在 **r3** 与 **Prisma JSON** 约定中微调，**不**新增 **DB migration** 列时仍落在 **`match_insights`**）。
- **不改** **`MatchResult.candidateUserId`**。
- **不改** **`finalScore`**。
- **不改** worker **winner / ranking** 生成逻辑；**不改** **RRM resolver** 主路径。
- **不让**「正式 switch」**生效**（**`wouldSwitch`** 仅为模拟字段）。
- **记录**：若未来在 **强门控**下生效会选谁、为何、是否 **fallback**。

**可选（产品 / 工程折中）：**

- **M6.3-r3**：**display resolver** **暂不**读取 **`rrmBoundedDecision`**；**或**仅 **admin / debug** 读取。
- **展示与 meta 联动**推迟到 **M6.3-r4 / r5** 或专门 **readonly bounded preview** 里程碑，避免与 **M6.0** 展示语义打架。

**方案 A** 可作为 **r3** 之后的 **UI 层**补充，但 **不应替代** **meta** 若目标是 **审计 + 离线评估**。

## 5. `rrmBoundedDecision` meta 草案（**不实现**）

未来 **dry-run** 写入 **`matchInsights`** 的 **JSON** 形状建议（**不含真实 ID**；**`ref` 仅示意**）：

```json
{
  "schemaVersion": 1,
  "sourceType": "rrm_bounded_decision",
  "sourceVersion": "m6.3-rrm-bounded-decision-v1",
  "mode": "dry_run",
  "decision": "would_use_baseline",
  "baselineRef": { "redacted": true },
  "boundedRef": { "redacted": true },
  "decisionSource": "baseline",
  "wouldSwitch": false,
  "fallbackUsed": false,
  "fallbackReason": null,
  "guardrails": {},
  "inputPresence": {},
  "generatedAt": "ISO_TIMESTAMP"
}
```

**字段约定：**

- **`mode`**：**`dry_run`**（**r3** 固定；未来若存在 **live** 模式须 **版本 bump**）。
- **`decision`**：**`would_use_baseline`** | **`would_switch_to_rrm`** | **`fallback_baseline`**（与 **r1** **`use_*`** 命名区分，强调**未生效**）。
- **`wouldSwitch`**：**boolean**，与 **`shadow.decision === "switch_to_top2_candidate"`** 及门控对齐的**模拟**结论。
- **`guardrails` / `inputPresence`**：结构与 **M6.1** 对齐的子集或引用，**便于**对账。

## 7. `finalScore` 处理原则

- **Dry-run 阶段**：**不改** **`finalScore`**；**不**将 baseline 的 **`finalScore`** **直接解释**为「若 switch 则仍适用目标候选」的分数。
- **即使** **`wouldSwitch=true`**（仅模拟），**不得**在无新契约的情况下把 **baseline `finalScore`** **赋给** bounded target 的语义解释。
- **若未来真正 switch（方案 C）**，须**重新定义**其一或组合（**r2 不定案**）：
  - 复用 **baseline** 分数（高风险，通常 **不推荐**）；
  - 使用 **target** 在池内已算分量（须从 **worker** 侧车或重放规则取值）；
  - 使用 **bounded decision score** 新字段；
  - 或 **`decisionScore` / `explanationScore`** 与 **`finalScore`** 解耦展示。
- **M6.3-r2 结论**：**禁止**在文档与实现上**混用**「baseline **`finalScore`**」与「bounded target 匹配质量」**除非** **r4+** 给出显式 **score 语义版本**。

---

## 8. `candidateUserId` / `displayCandidateUserId` 处理原则

- **M6.3-r3 dry-run**：**不改** **`candidateUserId`**；**不改** **`displayCandidateUserId`**；**仅**写 **`rrmBoundedDecision`** **meta**。
- **后续**若 **display resolver** 读取 **meta**：须**单独设计**阶段（**flag**、**优先级低于** **M6.0** **readonly**、**冲突规则**）。
- **后续**若走 **方案 C**：**必须**执行 **M6.3-r1 §11** **explanation unification** 全清单。

---

## 9. Fallback / audit contract

**必须**在 **meta** 中可复原（允许 **`null` / 空对象`** 但字段键建议齐全）：

- **`fallbackUsed`**
- **`fallbackReason`**
- **`guardrails.blocked`**（若与 **shadow** 对齐子结构）
- **`blockReasons`**（数组）
- **`sourceVersion`**
- **`generatedAt`**
- **`baselineRef`** / **`boundedRef`**（**redacted**）
- **`wouldSwitch`**
- **`decision`**（**would_*** 枚举）

**`fallbackReason` 建议闭集（字符串枚举）：**

| 值 | 含义方向 |
|----|-----------|
| **`flag_off`** | Dry-run 或 bounded 主开关未开。 |
| **`missing_shadow`** | 无 **`rrmDecisionShadow`**。 |
| **`shadow_not_switch`** | **`decision`** 非 **`switch_to_top2_candidate`**。 |
| **`malformed_shadow`** | **Shadow** 不可解析。 |
| **`missing_score_shadow_v2`** | 缺 **V2**。 |
| **`missing_selected_top2`** | 缺 **Top2**。 |
| **`target_not_in_top2`** | 目标不在 **Top2**。 |
| **`missing_candidate_user`** | 候选用户不存在。 |
| **`missing_candidate_profile`** | 缺 **profile**。 |
| **`guardrail_blocked`** | **`blocked`** 或 **`blockReasons`** 非空。 |
| **`context_flags_high_risk`** | **contextFlags** 命中高风险。 |
| **`source_version_mismatch`** | **`sourceVersion`** / **`schemaVersion`** 不匹配。 |
| **`evaluation_gate_not_satisfied`** | **M6.2 / admin** 门槛未过。 |
| **`unexpected_exception`** | 运行时异常转入 **fallback**。 |

---

## 10. Evaluation / admin gates

**M6.3-r3 dry-run** **不需要**完整 **admin UI**；但至少需要：

- **Batch evaluation** 样本量与**多样性**提升（**switch / blocked** 真实分布）（相对 **M6.2-r4**）。
- **Admin observation** 或 **debug report** 路径（导出 **meta**、按批次聚合）。
- **One-click disable**（**dry-run flag** 关即停写）。
- **`fallbackReason`** **可查**、可聚合。
- **Final explanation unified**（**在真正生效前** 仍为 **r1** **§11** 要求）。
- **Feature flag 默认关闭**（**§6**）。

- **不影响** **`FinalMatchPage`**（**r3** 默认不读 **meta** 或仅 debug）。
