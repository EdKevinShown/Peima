# M6.1-r2 — RRM Decision Shadow Payload Contract

## 1. 本轮目标

- **M6.1-r1** 已定义 **RRM decision shadow mode** 的产品 / 架构边界（baseline vs shadow、guardrails、flag 方向、写入方案 A/B/C 讨论），见 **`M6.1-r1-rrm-decision-shadow-mode-design.md`**。
- **M6.1-r2（本文）** 在 r1 之上 **冻结（文档级）payload contract**：**正式 JSON 形状**、**`sourceType` / `sourceVersion` / `schemaVersion`**、**`decision` 枚举**、**`reasonCode` / `blockReasons` 允许集合**、**parser / validator 规则**、**feature flag 语义**、**r3 写入策略建议**。
- **本轮仍只写文档**；**不实现**代码、不改 worker、不改 API、不改 schema / migration、不改测试。
- **Shadow 结果** 在任何阶段均 **不改变** 正式匹配决策（**`finalScore`**、**`MatchResult.candidateUserId`**、**worker winner / ranking**）。

---

## 2. M6.1-r1 基线（契约前提）

| 概念 | 定义 |
|------|------|
| **Shadow mode** | **Baseline**（当前正式 **worker / `MatchResult`** 结果）与 **RRM shadow decision**（旁路对照）的 **成对描述**；用于观测与评估。 |
| **Baseline** | 当前正式链路的 **winner**：**`MatchResult.candidateUserId`**、**`finalScore`**、既有 **ranking** 语义；**不可**被 shadow 覆盖。 |
| **Shadow** | 基于 **V2 shadow 输入** 与 **`rrmV2Top2Selector`** 等 **只读旁路** 推导的对照结论；**非**正式 RRM resolver 决策输出。 |
| **不变性** | **不改** **`finalScore`**、**`MatchResult.candidateUserId`**、**worker winner / ranking**、**RRM 正式 resolver**、**FinalMatchPage** 正式展示逻辑。 |
| **Shadow 输入** | **唯一**新链路 required shadow 计分输入为 **`matchInsights.scoreShadowV2`**（版本 **`m6.0-relationship-profile-score-v2-shadow`**）；**不依赖**、**不读取** **`matchInsights.scoreShadow`（v1）** 作为 pass/fail 条件。 |

---

## 3. 推荐 `sourceType` / `sourceVersion`

| 字段 | 值 | 说明 |
|------|-----|------|
| **`schemaVersion`** | **`1`** | Payload **结构版本**；未来字段演进时递增；parser **拒识**未知 major 或约定不兼容版本。 |
| **`sourceType`** | **`"rrm_decision_shadow"`** | 与 **M6.0 readonly display** 的 **`displaySourceType`**（如 **`rrm_top2_v2_selector_readonly`**）及 **`matchInsights.rrmV2Top2Selector`** **区分**；专指标 **决策影子** 载荷。 |
| **`sourceVersion`** | **`"m6.1-rrm-decision-shadow-v1"`** | 生成器 / parser / 回归定位用 **逻辑版本**；与 **`rrmV2Top2Selector.version`**（**`m6.0-rrm-v2-top2-selector-shadow-v1`**）**独立**。 |

## 4. Payload shape 正式草案

以下 JSON 为 **contract 草案**（**r3+** 实现须对齐）；**禁止**写入真实 **`userId` / `matchResultId` / `conversationId`**。持久化时使用 **`redacted: true`** 的占位结构或 **opaque hash**（实现细节由 r3 定义，**不在 r2 写死算法**）。

```json
{
  "schemaVersion": 1,
  "sourceType": "rrm_decision_shadow",
  "sourceVersion": "m6.1-rrm-decision-shadow-v1",
  "matchResultRef": {
    "kind": "match_result",
    "redacted": true
  },
  "baseline": {
    "candidateRef": {
      "kind": "user",
      "redacted": true
    },
    "source": "worker_current_winner",
    "finalScoreBand": "low",
    "rank": 1
  },
  "shadow": {
    "candidateRef": {
      "kind": "user",
      "redacted": true
    },
    "rankWithinSelectedTop2": 1,
    "decision": "same_as_baseline",
    "reasonCode": "same_as_baseline_high_consistency",
    "confidenceBand": "medium"
  },
  "comparison": {
    "sameAsBaseline": true,
    "switchSuggested": false,
    "top2GapBand": "small",
    "scoreDeltaBand": "small",
    "riskFlags": []
  },
  "guardrails": {
    "blocked": false,
    "blockReasons": [],
    "blockedByLowBand": false,
    "blockedByStrongConflict": false,
    "blockedByMissingProfile": false,
    "blockedByInvalidSelector": false,
    "blockedByBelowSuggestedFloor": false,
    "blockedByParseError": false
  },
  "inputPresence": {
    "scoreShadowV2": true,
    "rrmV2Top2Selector": true,
    "selectedTop2": true,
    "scoreShadowV1LegacyPresent": false
  },
  "generatedAt": "ISO_TIMESTAMP"
}
```

**字段约束（契约级）：**

- **`finalScoreBand` / `top2GapBand` / `scoreDeltaBand` / `confidenceBand`**：枚举见上表；**`unknown`** 表示无法从输入安全归类（仍允许产出 **`no_shadow_decision`** 类 payload）。
- **`comparison.switchSuggested`**：与 **`shadow.decision === "switch_to_top2_candidate"`** 语义对齐；**仅观察**，**不触发**任何正式写回。
- **`inputPresence.scoreShadowV1LegacyPresent`**：**仅**历史观测（旧行可能仍有 v1 键）；**不得**参与 eligibility 或 validator **pass/fail**。
- **不得**将 **`shadow.candidateRef`** 解释为 **`MatchResult.candidateUserId`**。

---

## 5. `decision` 枚举

| 值 | 含义 |
|----|------|
| **`same_as_baseline`** | RRM shadow 指向的候选与 **正式 baseline**（**`worker_current_winner`**）**一致**，或无可切换语义下的等价结论。 |
| **`switch_to_top2_candidate`** | 在 **guardrails 全开且通过** 的前提下，标记：若未来进入 **decision pilot**，**可能**在 **`selectedTop2`** 内考虑另一候选；**在 r2 / r3 仍不生效**于正式结果，**仅观测**。 |
| **`no_shadow_decision`** | 输入不足、parse 失败、风险 **`contextFlags`**、**`eligible` / `reason`** 不合规等；**不**输出可执行的 shadow 建议。 |

**明确：**

- **`switch_to_top2_candidate`** **≠** 正式切换；**不改变** **`candidateUserId` / `finalScore`**。
- **`no_shadow_decision`** **≠** 主流程失败；主流程 **不得** 因 shadow **throw**。

---

## 6. `reasonCode` 建议集合（初版）

以下 **`reasonCode`** 为 **闭集草案**；消费方应 **拒识**未知码（视为 **`no_shadow_unknown`** 处理策略由 r3 定）。

| `reasonCode` | 用途 |
|--------------|------|
| **`same_as_baseline_high_consistency`** | Baseline 与 shadow 候选一致，且 V2 / Top2 信号稳定，**高一致性**对照结论。 |
| **`same_as_baseline_low_gap`** | Baseline 与 shadow 一致；Top2 分差小，**切换动机弱**。 |
| **`switch_suggested_stronger_v2_profile_fit`** | **Guardrails 通过** 时，V2 profile 拟合相对更有利于 **Top2 内另一候选**（**仅建议**，不生效）。 |
| **`switch_suggested_better_guardrail_balance`** | **Guardrails 通过** 时，另一候选在 **风险 / band** 平衡上更优（**仅建议**）。 |
| **`no_shadow_missing_score_shadow_v2`** | 缺少或版本不合规的 **`scoreShadowV2`**。 |
| **`no_shadow_missing_selector`** | 缺少 **`rrmV2Top2Selector`** 对象。 |
| **`no_shadow_invalid_selector`** | Selector 结构 / 版本 / 字段与契约不一致。 |
| **`no_shadow_empty_selected_top2`** | **`selectedTop2`** 缺失或长度为 **0**。 |
| **`no_shadow_missing_candidate_profile`** | 对照所需 **profile** 缺失（若 r3 引入 DB / 缓存读）。 |
| **`no_shadow_context_flags_blocked`** | **`contextFlags`** 任一高风险为 **true**（与 M6.0 只读路径对齐：`top2GapLarge`、`hasLowBand`、`hasStrongConflictBand`、`anyBelowSuggestedFloor`）。 |
| **`no_shadow_low_band_blocked`** | 显式 **`hasLowBand`** 阻断。 |
| **`no_shadow_strong_conflict_blocked`** | 显式 **`hasStrongConflictBand`** 阻断。 |
| **`no_shadow_below_suggested_floor`** | **`anyBelowSuggestedFloor`** 阻断。 |
| **`no_shadow_parse_error`** | 输入 JSON / 嵌套字段 parse 失败。 |
| **`no_shadow_unknown`** | 未分类异常或 **reserved** 扩展前默认桶。 |

---

## 7. Guardrail `blockReasons` 集合

**`guardrails.blockReasons`** 为 **字符串数组**，元素 **必须**来自下表（**闭集**）；可多选；**仅影响** shadow payload 解释，**不影响**主流程。

| `blockReason` | 含义 |
|---------------|------|
| **`missing_score_shadow_v2`** | 无合规 **`scoreShadowV2`**。 |
| **`missing_rrm_v2_top2_selector`** | 无 **`rrmV2Top2Selector`**。 |
| **`invalid_selector_payload`** | version / eligible / reason / **`selectedTop2`** 形状等不通过输入校验。 |
| **`empty_selected_top2`** | **`selectedTop2`** 为空数组。 |
| **`missing_candidate_user`** | 候选用户行不存在（若 r3 做 DB 存在性检查）。 |
| **`missing_candidate_profile`** | 候选 **profile** 不足以做 shadow 对照。 |
| **`has_low_band`** | **`contextFlags.hasLowBand === true`**。 |
| **`has_strong_conflict_band`** | **`contextFlags.hasStrongConflictBand === true`**。 |
| **`any_below_suggested_floor`** | **`contextFlags.anyBelowSuggestedFloor === true`**。 |
| **`top2_gap_large`** | **`contextFlags.top2GapLarge === true`**。 |
| **`reason_not_ok`** | **`reason !== "ok"`**。 |
| **`eligible_not_true`** | **`eligible !== true`**。 |
| **`parse_error`** | 结构解析失败。 |
| **`unexpected_exception`** | 生成器内部异常（应被吞并并映射到此，**不冒泡**）。 |

**规则：**

- **`blocked === true`** 时 **`blockReasons.length >= 1`**（建议）；**`decision`** 应为 **`no_shadow_decision`**（或与 **`switch_suggested_*`** **互斥**）。
- **主流程不得 `throw`**；shadow 生成失败 → **`no_shadow_decision`** 或 **省略写入**（由 r3 定一种一致策略）。

## 8. Parser / validator contract

### 8.1 消费侧（post-persist parser / strict read）

未来 **读取** `rrmDecisionShadow` 的 parser **必须**验证：

| 检查项 | 规则 |
|--------|------|
| **`schemaVersion`** | **`=== 1`**（在 v1 契约期内）。 |
| **`sourceType`** | **`=== "rrm_decision_shadow"`**。 |
| **`sourceVersion`** | **`=== "m6.1-rrm-decision-shadow-v1"`**（或实现支持的子版本集合）。 |
| **`decision`** | **`∈ { same_as_baseline, switch_to_top2_candidate, no_shadow_decision }`**。 |
| **顶层对象** | **`baseline`**、**`shadow`**、**`comparison`**、**`guardrails`**、**`inputPresence`** 均存在且为 **object**。 |
| **`inputPresence.scoreShadowV2`** | 类型为 **`boolean`**。 |
| **`inputPresence.scoreShadowV1LegacyPresent`** | 类型为 **`boolean`**；**不参与** accept/reject。 |
| **`guardrails.blockReasons`** | 数组内每一项 **`∈`** §7 闭集。 |
| **`shadow.reasonCode`** | **`∈`** §6 闭集（或实现显式扩展后的并集）。 |
| **`generatedAt`** | 类型为 **非空 string**（ISO-8601 建议格式，**r3** 可收紧 regex）。 |

任一失败：**拒绝**将该 blob 当作有效 shadow contract（落库方应保证写入前已通过 **generator self-check**）。

### 8.2 生成前（pre-write input validator）

在 **写入** shadow 之前，生成器 **应**校验（与 **`matching-rrm-v2-selector-readonly-display.ts`** 安全思路对齐，**可略宽或略严**由 r3 微调但不得放宽 **风险 flag**）：

| 检查项 | 规则 |
|--------|------|
| **`scoreShadowV2`** | 存在且 **`scoringVersion === "m6.0-relationship-profile-score-v2-shadow"`**（与现有 M6 常量一致）。 |
| **`rrmV2Top2Selector`** | 存在且为 object。 |
| **`selectedTop2`** | 数组且 **`1 <= length <= 2`**。 |
| **`eligible`** | **`=== true`**。 |
| **`reason`** | **`=== "ok"`**。 |
| **`contextFlags` 安全** | **`top2GapLarge`、`hasLowBand`、`hasStrongConflictBand`、`anyBelowSuggestedFloor`** 均为 **非 true**（与 M6.0 readonly **一致**）。 |
| **Candidate user / profile** | 若 r3 引入存在性检查：缺失则 **blocked**，不写 **`switch_*`**。 |

**任一失败：**

- 输出 **`decision: "no_shadow_decision"`** 的 **完整** payload（带 **`blockReasons` / `reasonCode`**），**或**
- **省略** shadow 写入，仅结构化日志记录 fallback（**二选一**，**r3 统一**）；

**无论如何** **不得** 影响 **`MatchResult`** 主写入与 **worker winner**。

## 9. 写入策略建议（r3 导向）

| 方案 | 建议 |
|------|------|
| **A. `matchInsights.rrmDecisionShadow`** | **推荐作为 M6.1-r3 首选**：**无**新表、**无** migration；与 **`MatchResult.matchInsights`** 同生命周期；利于本地回归与和 **M6.0** 只读 payload **同仓**观测。 |
| **B. `rrm_decision_shadow_meta` 表** | **暂不推荐 r3**：需 **schema / migration**，适合后续 **admin / 数仓** 阶段。 |
| **C. log only** | **可作 fallback / 联调**：风险最低；不利于批量 join 分析。 |

**r2 结论：** **M6.1-r3** 优先在 **`PEIMA_M6_RRM_DECISION_SHADOW_ENABLED === "1"`** 时尝试生成并写入 **`matchInsights.rrmDecisionShadow`**；**flag 默认关闭**；任何异常 **只影响** shadow 路径。

## 10. Feature flag contract

### 10.1 `PEIMA_M6_RRM_DECISION_SHADOW_ENABLED`

| 语义 | 说明 |
|------|------|
| **开启条件** | 与 M6.0 display 一致：**仅当** 值为 **`"1"`** 时 **`enabled: true`**（**`"TRUE"`** 等 **不**开启）。 |
| **默认** | **关闭**（未设置或 **≠ `"1"`**）。 |
| **作用域** | **仅**控制 **shadow payload 的生成 / 写入尝试**（具体 A/C 组合由 r3 定）。 |
| **不得影响** | **`finalScore`**、**`MatchResult.candidateUserId`**、**worker winner / ranking**、**RRM 正式 resolver**、**FinalMatchPage`**、**M6.0 readonly display** 的 flag 与 fallback。 |
| **异常** | 只导致 **`no_shadow_decision`**、**省略写入** 或 **日志**；**不 throw** 到主流程。 |

### 10.2 可选后续：`PEIMA_M6_RRM_DECISION_SHADOW_LOG_ONLY`

- 若为 **`"1"`**，强制 **仅日志 / 不写 `matchInsights`**（与主开关组合语义由 r3 定义，**r2 仅占位**）。

## 11. 与 M6.0 readonly display 的关系

| 维度 | M6.0 readonly display | M6.1 shadow decision |
|------|----------------------|------------------------|
| **问题域** | **展示读取**增强（API **`displaySourceType`**） | **决策对照**增强（**旁路**） |
| **共享输入** | 可共用 **`scoreShadowV2`**、**`rrmV2Top2Selector`** | 同左，但 **消费契约** 为 **`sourceType: rrm_decision_shadow`** |
| **`displaySourceType`** | 如 **`rrm_top2_v2_selector_readonly`** | **`rrm_decision_shadow`** **不是** **`displaySourceType`**；**不得**因写入 shadow **自动改变** **`displaySourceType`** |
| **FinalMatchPage** | 展示已解析的 **readonly** 分支 | **暂不解析、不展示** shadow payload（除非另开 UI 里程碑） |

## 12. 不变性要求

- **不改** **`finalScore`**、**`MatchResult.candidateUserId`**。
- **不改** **worker winner / ranking**、**batch-match 主决策**。
- **不改** **RRM 正式 resolver**。
- **不改** **Prisma schema / migration**（直至显式里程碑）。
- **不恢复** **scoreShadow v1** 依赖。
- **不让 FinalMatchPage** 解析 **`rrmDecisionShadow`** raw payload。
- **不影响** **M6.0 readonly display** 的 **fallback** 与 **`PEIMA_M6_RRM_V2_SELECTOR_DISPLAY_ENABLED`** 语义。
