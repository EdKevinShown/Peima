# M6.0-J3 — Worker relationshipProfileScore V2 shadow

## Scope

This milestone **wires the J2 pure helper into the batch-match worker** so each persisted `MatchResult` includes **`matchInsights.scoreShadowV2`**, alongside the existing P1-1 fields and **`matchInsights.scoreShadow`** (M6.0-E v1).

Implementation lives in:

- `apps/worker/src/jobs/batch-match-match-insights.ts` — merges placeholder insights + `scoreShadow` + `scoreShadowV2`
- `apps/worker/src/jobs/batch-match.processor.ts` — calls the merge when creating the winning row’s `matchInsights`

## Explicit non-goals

- **Does not** replace or alter `MatchResult.finalScore` (still `computeFinalScoreV1`).
- **Does not** change worker winner selection, candidate ordering for ranking, or `reasonSummary` derivation.
- **Does not** change `candidateUserId` or `displayCandidateUserId`.
- **Does not** change RRM resolvers or any RRM-only fields.
- **Does not** change API response contracts or `FinalMatchPage`.
- **Does not** change Prisma schema or add migrations.
- **Does not** write raw questionnaire answers, raw user ids, or RRM raw scores into `matchInsights`.

## Data contract

`scoreShadowV2` mirrors `computeRelationshipProfileScoreV2` output (see `docs/M6/M6.0-j2-relationship-profile-score-v2-helper.md`), typed as `MatchInsightsScoreShadowV2` in `packages/shared/types/match-p1.ts`.

Profiles are taken from the **same** `UserProfile` rows already loaded for `computeFinalScoreV1` / `computeProfileScore` (20 G1-R axes only).
