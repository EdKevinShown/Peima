# M6.1-r1 — RRM Decision Shadow Mode Design

## 1. 本轮目标

- **M6.0** 已完成 **RRM V2 readonly display MVP**（resolver + flag + FinalMatchPage **`displaySourceType`** 展示），并完成 **scoreShadow v1** 运行时代码移除与 **R11** 本地回归记录（见 **`M6.0-r11-final-local-regression-and-push-prep.md`**）。
- **M6.1** 目标：进入 **RRM decision shadow mode** — 在后台生成 **影子决策（shadow decision）**，用于与当前 **正式 winner** 对照、观测与评估，**不改变**用户看到的正式匹配结果。
- **本轮（M6.1-r1）** 仅产出**设计文档**；**不实现代码**、不改 schema、不改 worker、不改 API 行为。

---

## 2. M6.0 基线（设计前提）

| 项 | 状态 |
|----|------|
| **scoreShadowV2** | 新 worker 输出的 **唯一 required shadow 计分输入**（与 **`m6.0-relationship-profile-score-v2-shadow`** 校验一致）。 |
| **scoreShadow v1** | **已从**新生成 **`matchInsights`** **移除写入**；历史行可能仍有 v1 字段，**不作为** M6.1 shadow 的依赖。 |
| **RRM V2 selector readonly display** | 由 **`PEIMA_M6_RRM_V2_SELECTOR_DISPLAY_ENABLED === "1"`** 门控；解析逻辑见 **`matching-rrm-v2-selector-readonly-display.ts`**（要求合规 **`scoreShadowV2`** + **`rrmV2Top2Selector`** + 安全 **`contextFlags`** 等）。 |
| **Worker `matchInsights`** | **`buildWorkerMatchInsightsForBestMatch`** 写入 **`scoreShadowV2`**，可选 **`rrmV2Top2Selector`**（**`m6.0-rrm-v2-top2-selector-shadow-v1`**），见 **`batch-match-match-insights.ts`**。 |

## 3. Shadow mode 的定义

### 3.1 正式决策（baseline，不可被 shadow 覆盖）

- **Worker** 产生的 **winner** 与 **ranking / candidate order**。
- **`MatchResult.candidateUserId`**（正式绑定对象）。
- **`finalScore`** 及用户最终看到的 **正式匹配结果**（含既有 pairwise / static 等语义）。

### 3.2 影子决策（shadow，仅对照）

- 基于 **RRM V2 相关输入**（如 **`scoreShadowV2`**、**`rrmV2Top2Selector`**、**`selectedTop2`**、**`contextFlags`**、**`reason`** 等）在 **旁路** 推导的 **shadow winner / shadow rank / shadow reason / flags**。
- **不得**写回 **`MatchResult.candidateUserId`**。
- **不得**修改 **`finalScore`** 或 **worker ranking**。
- **不得**替代用户 UI 上的正式结果；**默认不向 FinalMatchPage 暴露** shadow 内容（除非后续单独开 UI 里程碑）。
- **持久化位置**：**M6.1-r1 不拍板**；候选见 **§9**（**r2** 再定契约与落点）。

## 4. Shadow mode 输入（建议集合）

以下输入用于 **r2+** 的 parser / generator 设计参考（**r1 不实现**）：

| 输入 | 说明 |
|------|------|
| **MatchResult 主结果** | 行级 **`candidateUserId`**、**`finalScore`**、**`reasonSummary`** 等（仅只读对照）。 |
| **Baseline candidate** | 与 **`MatchResult.candidateUserId`** 对齐的正式对象引用（持久化时用 **opaque ref**，见 §5）。 |
| **`matchInsights.scoreShadowV2`** | **必须**存在且版本合规时，才允许进入「完整 shadow 决策」路径；缺失则 **blocked / no_shadow_decision**（见 §6）。 |
| **`matchInsights.rrmV2Top2Selector`** | **`selectedTop2`**、**`top1CandidateUserId` / `top2CandidateUserId`**、**`top2Gap`**、**`contextFlags`**、**`reason`**、**`eligible`**、**`thresholds`** 等。 |
| **`selectedTop2`** | Shadow 对照的核心序关系来源之一（与 worker pool 写入方式对齐，见 **`batch-match-match-insights.ts`**）。 |
| **Candidate profile availability** | 若 shadow 逻辑需要 profile 维度，**缺失则 guardrail**（不抛主流程）。 |
| **Display resolver 结果（若有）** | 只读展示路径的解析结果可作为 **观测旁证**，**不得**反向驱动 shadow 写入正式字段；**不得**因 shadow 开启自动改写 **`displaySourceType`**（见 §7）。 |
| **`generatedAt` / `sourceVersion`** | 影子载荷版本与生成时间，便于回放与指标聚合。 |

**明确约束：**

- **不使用、不依赖 `matchInsights.scoreShadow`（v1）**。
- **不因 v1 缺失失败**；v1 存在与否 **不参与** shadow  eligibility。

## 5. Shadow decision 输出草案（JSON shape，非实现）

以下为 **草案**，字段名与枚举可在 **M6.1-r2** 收敛；**不包含**真实 **userId / matchResultId / conversationId** — 持久化时应使用 **opaque token** 或 **哈希化引用**（由 r2 定义）。

```json
{
  "schemaVersion": 1,
  "sourceType": "rrm_decision_shadow",
  "sourceVersion": "m6.1-rrm-decision-shadow-v1",
  "matchResultRef": "<opaque-correlation-token>",
  "baseline": {
    "candidateRef": "<opaque-candidate-token>",
    "finalScoreSummary": "<non-identifying-numeric-or-band-summary>",
    "source": "worker_current_winner"
  },
  "shadow": {
    "candidateRef": "<opaque-candidate-token>",
    "rankWithinSelectedTop2": 1,
    "decision": "same_as_baseline",
    "reasonCode": "shadow_ok",
    "confidenceBand": "medium"
  },
  "comparison": {
    "sameAsBaseline": true,
    "switchSuggested": false,
    "top2GapSummary": "<non-identifying-summary>",
    "riskFlags": []
  },
  "guardrails": {
    "blockedByLowBand": false,
    "blockedByStrongConflict": false,
    "blockedByMissingProfile": false,
    "blockedByInvalidSelector": false
  },
  "generatedAt": "<ISO-8601-timestamp>"
}
```

**`shadow.decision` 枚举（草案）：**

- **`same_as_baseline`**：影子建议与正式 winner **一致**（或无可切换语义）。
- **`switch_to_top2_candidate`**：在 **严格 guardrails 全通过** 时，标记「**若**将来启用决策，可考虑的另一对象」— **r1 仍不写入正式结果**。
- **`no_shadow_decision`**：输入不足、blocked、或策略选择不产出对照结论。

**注意：**

- **不得**把 **`shadow.candidateRef`** 当作 **`MatchResult.candidateUserId`**。
- **不得**在 r1 阶段假设该 JSON 已落库；仅定义 **观测载荷形状**。

## 6. Shadow decision guardrails

以下任一成立时，**不得**输出 **`switch_to_top2_candidate`**；应输出 **`no_shadow_decision`** 或带 **`blocked*`** / **`fallbackReason`** 的安全结构，且 **不得 `throw`** 影响主流程：

| 条件 | 期望行为 |
|------|-----------|
| **`scoreShadowV2` 缺失** | `no_shadow_decision` / blocked |
| **`selectedTop2` 缺失或非数组** | blocked |
| **`selectedTop2` 为空** | blocked |
| **Candidate 用户不存在（DB）** | blocked（若 r2 引入 DB 读） |
| **Candidate profile 不存在** | `blockedByMissingProfile` |
| **`contextFlags` 高风险**（与 M6.0 只读路径一致：`top2GapLarge`、`hasLowBand`、`hasStrongConflictBand`、`anyBelowSuggestedFloor` 等） | 逐项置位 + **不**建议 switch |
| **`hasLowBand === true`** | blocked |
| **`hasStrongConflictBand === true`** | blocked |
| **`anyBelowSuggestedFloor === true`** | blocked |
| **`reason !== "ok"`** | blocked |
| **`eligible !== true`** | blocked |
| **Top2 gap 过大且无明确安全理由** | blocked（与「对照可信度」策略绑定，r2 细化） |
| **Payload parse failed** | fallback / `no_shadow_decision` |
| **任意未捕获异常** | 吞并记录 shadow fallback；**主流程继续** |

---

## 7. Shadow mode 与 readonly display 的关系

| 维度 | M6.0 readonly display | M6.1 shadow mode |
|------|---------------------|------------------|
| **目的** | **展示读取增强**（API 解析后给前端的 **`displaySourceType`**） | **决策对照增强**（正式链不变） |
| **数据** | 复用 **`scoreShadowV2` + `rrmV2Top2Selector`** 的 **严格**解析 | 可复用 **同一套 `selectedTop2`**，但语义为 **shadow**，非正式决策 |
| **正式决策** | **不修改** | **不修改** |
| **`displaySourceType`** | 由 **`PEIMA_M6_RRM_V2_SELECTOR_DISPLAY_ENABLED`** 与 resolver 决定 | **不应**因 shadow 生成而 **自动改变**；shadow 为 **并行观测面** |
| **FinalMatchPage** | 已支持 **`rrm_top2_v2_selector_readonly`** 展示 | **r1 默认不展示** shadow decision；若未来展示需 **单独 UI / API 字段设计** |

## 8. Feature flag 建议

### 8.1 主开关（建议名）

**`PEIMA_M6_RRM_DECISION_SHADOW_ENABLED`**

| 语义 | 说明 |
|------|------|
| **默认** | **关闭**（未设置或非约定真值 → 不生成 shadow decision）。 |
| **开启时** | 仅允许 **旁路生成 / 持久化 / 日志** shadow payload（具体由 r2 定）。 |
| **不得影响** | **`finalScore`**、**`MatchResult.candidateUserId`**、**worker winner / ranking**、**FinalMatchPage 正式展示**、**M6.0 readonly display fallback** 行为。 |
| **异常** | 仅记录 **shadow fallback**；**不冒泡**阻断匹配主流程。 |

### 8.2 可选后续开关（r2+ 再定）

- **`PEIMA_M6_RRM_DECISION_SHADOW_LOG_ONLY`**：仅结构化日志、不落 `matchInsights`。
- 其它采样率、按队列启用等 **不在 r1 展开**。

## 9. 写入策略讨论（仅方案，r1 不决定）

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| **A** | 写入 **`matchInsights.rrmDecisionShadow`**（或并列键名由 r2 定） | **无新表**、**无 migration**、与 **MatchResult** 同生命周期绑定 | **`matchInsights` 体积增大**；历史行解析需 **schemaVersion** 兼容 |
| **B** | 新增 **dedicated shadow meta 表** | 查询与观测清晰 | **需 schema / migration**，**不适合 r1** |
| **C** | **仅结构化日志**（不落库） | **风险最低**、上线最快 | **不利于**离线批量评估与 join |

**建议：** **M6.1-r2** 可优先评估 **A** 或 **C**；若短期只要观测，**C**；若要产品与数据对账，**A** + 严格版本字段。**r1 不选定最终实现。**

## 10. 评估指标（供 M6.1-r3 / r4 使用）

后续聚合与看板可跟踪（命名可调整）：

- **`shadowCoverageRate`**：满足生成条件且产出非空 shadow 的比例。
- **`sameAsBaselineRate`**：**`comparison.sameAsBaseline === true`** 比例。
- **`switchSuggestedRate`**：**`shadow.decision === "switch_to_top2_candidate"`** 比例（应 **极低** 且受 guardrails 约束）。
- **`blockedRate`** / **`fallbackRate`**：因 guardrails 或解析失败未给出对照的比例。
- **`missingProfileRate`**、**`invalidSelectorRate`**。
- **`strongConflictBlockRate`**、**`lowBandBlockRate`**。
- **`top2GapLargeRate`**（在 shadow 样本中的出现频率）。
- **`shadowReasonDistribution`**：**`reasonCode`** 直方图。

## 11. 不变性要求（M6.1 全阶段须遵守）

- **不改** **`finalScore`**。
- **不改** **`MatchResult.candidateUserId`**。
- **不改** **worker winner / ranking**。
- **不改** **batch-match 主决策**。
- **不改** **RRM 正式 resolver**（shadow 为旁路）。
- **不改** **Prisma schema / migration**（直至显式里程碑批准）。
- **不恢复** **scoreShadow v1** 写入或 API 读依赖。
- **不让 FinalMatchPage** 在 **M6.1-r1** 阶段 **计算或展示** shadow decision（后续需单独设计）。
- **不影响** **M6.0 readonly display** 的 **flag / fallback** 语义。
