## 3. Owner mismatch 规则

在 `FinalMatchPage` 中基于 API 与主路径已解析的 `resolvedCandidateUserId` 计算：

- **scoreOwnerMismatch**  
  `resolvedCandidateUserId`、`scoreOwnerCandidateUserId` 均为非空字符串（trim 后），且二者不相等。

- **explanationOwnerMismatch**  
  `resolvedCandidateUserId`、`explanationOwnerCandidateUserId` 均为非空字符串（trim 后），且二者不相等。

任一字段缺失 → 对应 mismatch 为 **false**，避免误报。

与 **consistencyWarnings** 去重：若 API 已包含 `code === "score_owner_mismatch"` 或 `code === "explanation_owner_mismatch"`，主路径对应短提示不再重复展示（仍可在技术区 JSON 与 M6.6-C5 只读行看到 API 已声明）。

## 4. UI 行为

- **分数**：在「匹配分数构成」折叠区内，当 `scoreOwnerMismatch` 且 API 未单独列出 `score_owner_mismatch` 时，显示一句说明：分数仍按稳定基线对象计算，未为展示对象重算；**不改动分数数字**，不阻断操作。
- **说明 / 复审区**：在结构化解读区块上方，当 `explanationOwnerMismatch` 且 API 未列出 `explanation_owner_mismatch` 时，显示一句说明：说明仍按稳定基线对象生成；不改变生成逻辑。
- **技术来源说明**：在 M6.5-C2 resolved 小节内展示 `scoreOwnerMismatch` / `explanationOwnerMismatch` 布尔值，并注明 API 是否已含对应 consistency code；`consistencyWarnings` 仍以 JSON 展示；用户标识符仅在技术折叠区以 `code` 形式出现，主路径短文案不含完整 ID。
