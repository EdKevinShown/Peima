# M6.0-Q2 — Promote q29 / q30 to canonical

## 1. 变更摘要

- **`apps/api/src/modules/questionnaire/data/questions.ts`**：`q29`、`q30` 的 **`sourceTier`** 由 **`draft`** 升为 **`canonical`**；**`questionKey`、题干、选项、`tags` 未改**（沿用既有打点）。
- **效果**：**`q01`–`q30` 全部** 进入 **`scoreQuestionnaireG1r` / `isQuestionProductionReady`** 闸门；**`totalCanonical` = 30**；**`confidence` = 已答 canonical 题数 / 30**（在仅统计 canonical 题的前提下，与 **M6.0-Q1** 前 **分母 28** 相比已更新）。
- **`POST /questionnaire/submit`**：仍须 **恰好 30 条**、键集合与 **`getQuestionKeys()`** 完全一致；**缺 `q29` 或 `q30` 仍 `400`（BadRequest）**。
- **`relationshipProfileScore`**（worker 侧基于 **20 维 `user_profile`** 的对比）：**会**随 **`q29`/`q30` 答案** 进入 v2 聚合而 **间接变化**（此前两题仅落库、**不参与** 20 维轴）。

## 2. 明确未改项（本轮边界）

- **未改** **`finalScore` v1**、**worker 排序 / ranking**、**`MatchResult.finalScore`**。
- **未改** **`candidateUserId` / `displayCandidateUserId`**、**RRM resolver**。
- **未改** **Prisma schema**、**无新 migration**。
- **未做** **low-effort questionnaire detection**。

## 3. 测试与回归

- **`apps/api/test/questionnaire.scorer.regression.e2e-spec.ts`**：`confidence` 分母 **28 → 30** 等与闸门对齐。
- **`apps/api/test/questionnaire-canonical-q29-q30.spec.ts`**：**30 题 canonical**、`q29`/`q30` 轴敏感、`submit` 缺题失败与 **30 题 mock 事务** 路径。

## 4. 产品后续

- 需重新跑 **All-A / All-B / All-C / All-D / Normal**（及既有 **M6.0-G2** 类记录），对比 **`relationshipProfileScore`**、**`finalScore` v1**、**`matchInsights.scoreShadow.relationshipProfileScore`** — **此前在仅 28 题 canonical 下得到的数值表不可直接等同沿用**。
