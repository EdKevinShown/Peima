# M6.0-R3 — RRM V2 Top2 selector shadow（matchInsights）

## 范围

本轮将 **R2B** 的 `selectV2Top2Candidates` 输出写入 **`MatchResult.matchInsights.rrmV2Top2Selector`**（只读 shadow），在 **`apps/worker/src/jobs/batch-match-match-insights.ts`** 与 **`batch-match.processor.ts`** 的 batch-match 路径中生成。

## 行为

- **数据来源**：对当前队列已加载的 **同一 viewer** 下、本批 **已打分候选集合**（`scored`）中每一人，用已有 **`UserProfile`** 调用 **`computeRelationshipProfileScoreV2(viewerProfile, candidateProfile)`**，再映射为 selector 所需的 **`scoreShadowV2`** 形状，**不新增大范围 DB 查询**。
- **不写**原始问卷答案全文、**不写** token、**不写** RRM 原始输出。
- **不覆盖** `scoreShadow`（v1）、**不覆盖** `scoreShadowV2`；**不删除** `explanation` / `openingTopics` 等 placeholder 字段。

## 与 RRM / 展示的关系

- **不调用 RRM**；**不改** RRM resolver。
- **不改** `displayCandidateUserId`、**不改** `candidateUserId`、**不改** `MatchResult.finalScore`。
- **不改** worker 胜者逻辑：**`candidateUserId` 仍由 legacy `computeFinalScoreV1` 排序后的第一名决定**。
- `rrmV2Top2Selector` **仅作观察字段**；**低分 / `low` / `strong_conflict` / 分差大** 只体现在 **`contextFlags`** 中，**不**在 selector 层阻止 `eligible === true`（只要有两个合法 V2 shadow 行）。
- **RRM 不得跳出 V2 Top2 外选人**（产品约束；**R4** 起由 RRM 侧读取该 shadow 并遵守）。

## Shadow 版本

`rrmV2Top2Selector.version === "m6.0-rrm-v2-top2-selector-shadow-v1"`（见 `packages/shared/types/match-p1.ts`）。

## 下一步（非 R3）

**M6.0-R4**：让 RRM 读取 **`matchInsights.rrmV2Top2Selector`**，在 **`top1` / `top2`** 内做展示仲裁，并遵守 **always-on** 与 **contextFlags** 语义。
