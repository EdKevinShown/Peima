# M6.4-r2 — True Bounded Decision Write Strategy Detailed Contract

## 1. 本轮目标

- **M6.4-r1** 已完成：**true bounded decision** 的 **gating design**（**Evaluation / System / Product / Observation** 四层门、**`wouldSwitch` vs `actualSwitch`** 区分、**`PEIMA_M6_RRM_BOUNDED_DECISION_ENABLED`** 语义设计但**未接线**、**Strategy A/B/C** 草图、**explanation unification** 与 **rollback / kill switch**、**implementation 不早于 M6.4-r5**）。
- **M6.4-r2（本文）**：在 **r1** 门控设计之上，**进一步细化** **true bounded decision** 的**写入与读路径合同**，重点比较 **resolver override（展示生效）**、**decision meta（审计 + resolver 契约）**、**`MatchResult.candidateUserId` 直接写入** 三条路径，并给出 **M6.4-r3** 起**最安全**的推荐。
- **r2** **只**做文档；**不**实现代码；**不**让 **true decision** 在产线**生效**；**不**接线 **`PEIMA_M6_RRM_BOUNDED_DECISION_ENABLED`**；**不**让 **RRM** 在本轮改**正式**匹配结果。

## 2. 当前基线

| 项 | 说明 |
|----|------|

## 3. Strategy A：Resolver override / display effective

### 3.1 定义

- **不改** **`MatchResult.candidateUserId`**。
- **不改** **`MatchResult.finalScore`**。
- **不改** **worker** **winner / ranking**；**不改** **RRM resolver** 扩大候选池。
- 在 **API read layer**（例如 **`resolveMatchResultDisplay`**）中：若未来 **`PEIMA_M6_RRM_BOUNDED_DECISION_ENABLED`**（或专用只读子 flag）**on** 且 **r1** **gates** 全部满足，则将 **`displayCandidateUserId`** 指向 **bounded target**；**`displaySourceType`** 扩展为可表达 **bounded read-layer override**（例如未来枚举 **`rrm_true_bounded_readonly`** 类，**具体命名以 r3+ ADR 为准**）；若引入 **`decisionSourceType`**，须标记 **bounded override** 与 **fallback** 状态。
- **DB 主行**仍保留 **baseline** **`candidateUserId`**。

### 3.2 优点

- **风险低**；**无** Prisma **schema / migration** 义务即可试验读路径。
- **易回滚**：关 flag → resolver **忽略** override，回到 **`match_result_original`** 或既有 **M6.0** 只读链。
- **可**支持小规模 **UI pilot**，与 **M6.0 readonly display** 精神一致。

### 3.3 缺点

- **`candidateUserId`** 与 **`displayCandidateUserId`** **长期分离**。
- **Chat / timeline / feedback** 若默认跟 **`candidateUserId`**，必须与 **display** **显式对齐**（见 **§11**），否则出现「详情 A、会话 B」。
- **不是**「持久化正式 winner 写入」；**审计**弱于 **Strategy B** 若**不写**结构化 **meta**。
- **解释层**若缺少 **`decisionSourceType` / fallback 文案**，易与用户心智冲突。

### 3.4 适合阶段

- **M6.4-r3 / r4** 的**最小** **true-read-layer** 实验**之一**。
- **必须**在文档与产品中标明：**仍是 read-layer override**，**不是** **full decision write**（**Strategy C**）。

## 4. Strategy B：Decision meta + resolver contract

### 4.1 定义

- **写入** **`matchInsights`** JSON： **`rrmTrueBoundedDecision`** **或** 在严格 **schemaVersion / sourceVersion** 下**升级 / 并列** **`rrmBoundedDecision`**（**从 `dry_run` 扩展到 `read_layer_override` / `enabled` 等 mode**；**具体键名与兼容策略由 r3+ 合同锁定**）。
- **Meta** 至少记录：**baseline**、**selected**、**`actualSwitch`**、**`fallbackReason`**、**`decisionSource`**、**guardrails**、**evaluation 快照引用**、**`generatedAt`**（**不**在文档中写真实 ID；**`baselineRef` / `selectedRef`** **redacted**）。
- **API resolver**（**`matching-result-display.ts`** 及同源只读 API）**读取 meta**，统一输出 **`displayCandidateUserId` / `displaySourceType` /（可选）`decisionSourceType`** 与用户可见 **fallback** 提示。
- **`MatchResult.candidateUserId`** **可暂不改**（与 **M6.3** **dry-run** 基线一致）。

### 4.2 优点

- **审计清晰**；**offline / admin** 可对账 **`wouldSwitch` 历史** 与 **true** 路径 **`actualSwitch`**。
- **支持 fallback / rollback**：**flag off** 或 **parse 失败** → **baseline**；**meta** 仍保留观测。
- **可逐步升级**到 **Strategy C**（须 **单独里程碑**）。
- **不一定**需要 **DB migration**（延续 **`match_insights` JSON**）。

### 4.3 缺点

- **JSON meta** 须有**严格版本**与 **parser 拒收策略**。
- **API / Web** **必须**统一解释；**禁止**前端解析 raw **`matchInsights`** 自作主张（见 **§8**）。
- **主字段与展示字段**仍可能分离 → **§11** 为硬门槛。

### 4.4 适合阶段

- **M6.4** **最推荐**的 **true-read-layer gated path**（与 **M6.4-r1 §7 Strategy B** 一致）。

## 5. Strategy C：Direct `candidateUserId` write

### 5.1 定义

- **Worker** 在 **`MatchResult.create`（final 行落库）** 时：若 **true bounded decision** 通过 **r1** **gates**，则将 **bounded target** **直接写入** **`MatchResult.candidateUserId`**。
- **进入**「主结果链」：默认 **chat / timeline** 若跟 **`candidateUserId`**，**产品语义最直白**。

### 5.2 优点

- **候选 / 聊天 / 时间线**默认 **一致**。
- **无需** **`displayCandidateUserId`** 与 **`candidateUserId`** 双轨（在实现正确前提下）。

### 5.3 缺点

- **风险最高**：**`finalScore`**、**`primaryConclusion` / `matchExplanation` / `matchReview` / `relationshipProfileScore` / `reasonSummary`** 必须与新候选 **严格一致**（**M6.4-r1 §8.2**）。
- **Audit / fallback / rollback** 成本高；**异常**时可能留下**难修**主行状态（即使有关闭 flag，也需 **meta** 与 **对账**）。
- **须**更强 **evaluation**（对比 **M6.2-r4** 同质样本警示）与 **admin observation**（**M6.4-r4**）。
- **不适合**作为 **M6.4-r3** **首发 implementation**（与 **M6.4-r1**、**M6.3-r2** 结论一致）。

### 5.4 结论

- **Strategy C** **推迟**到 **M6.5+** 或更后，且须 **ADR + migration 评审**（若引入新列或 **score** 合同）。
- **禁止**将 **Strategy C** 列为 **M6.4-r3** **直接 implementation** 目标。

| 推荐项 | 说明 |

## 7. Meta versioning contract

以下为未来 **true / read-layer** **meta** 的**合同草案**（**r2 不实现、不落库**）。**不写**真实 **`userId` / `matchResultId`**。

| 字段 | 类型 / 取值 | 说明 |
|------|----------------|------|
| **`sourceType`** | 常量 **`rrm_true_bounded_decision`** | 与 **dry-run** **`rrm_bounded_decision`** 区分（**或**通过 **`sourceVersion` + `mode`** 联合区分，**二选一须在 r3 锁死**）。 |
| **`sourceVersion`** | **`m6.4-rrm-true-bounded-decision-v1`**（示例） | **Bump** 规则：**任何**语义不兼容变更须 **+version**。 |
| **`schemaVersion`** | **`1`**（整数） | **Parser** **拒收**未知 major。 |
| **`mode`** | **`dry_run`** \| **`read_layer_override`** \| **`enabled`** \| **`fallback`** | **`dry_run`**：**`wouldSwitch`** 观测，**无** **`actualSwitch=true`**。**`read_layer_override`**：**可** **`actualSwitch=false`** 但 **display override=true`**（展示与持久化 winner 不同但**合同允许**的显式模式）。**`enabled`**：**才允许** **`actualSwitch=true`**（与 **Strategy C** 对齐时）。**`fallback`**：异常或门控失败记录。 |
| **`decision`** | **`use_baseline`** \| **`use_rrm_bounded`** \| **`fallback_baseline`** | 与 **r1** 草案一致；**dry-run** 侧 **`would_*`** 命名可继续存在于 **`m6.3` v1** payload，**true** payload **须**版本化对齐。 |
| **`actualSwitch`** | **boolean** | **仅**在 **true** 合同下与 **`wouldSwitch`** 区分；**`wouldSwitch` ≠ `actualSwitch`**。 |
| **`fallbackUsed`** | **boolean** | |
| **`fallbackReason`** | **string \| null** | 闭集建议延续 **M6.3-r2 §9**（如 **`guardrail_blocked`**、**`unexpected_exception`** 等）。 |
| **Required** | **`baselineRef`**、**`selectedRef`**、**`decisionSource`**、**`guardrails`**、**`evaluationGate`**（或引用占位）、**`sourceVersions`**（worker/shadow/selector 等摘要）、**`generatedAt`** | **`ref`** **必须 redacted** 或 **抽象 token**；**禁止**日志明文。 |

**语义约束：**

- **`dry_run`** 的 **`wouldSwitch`** **不等于** **`actualSwitch`**。
- **`read_layer_override`**：**允许** **`actualSwitch=false`** 且 **展示层仍 override**（**Strategy A**）— **必须在 §11 产品合同**中写清 **chat/timeline** 跟谁走。
- **`enabled`**：**才允许** **`actualSwitch=true`**（通常绑定 **Strategy C** 或未来「主字段同步」子合同）。
- **r2** **不**实现上述字段的写入或读取逻辑。

## 8. API resolver contract

若采用 **Strategy B** 和/或 **Strategy A**，**未来** **API resolver**（以 **`resolveMatchResultDisplay`** 为锚点）**必须**：

| 必须 | 说明 |
|------|------|
| **读取主结果** | 自 **`MatchResult.candidateUserId`**（**baseline**）。 |
| **读取 meta** | **`matchInsights.rrmTrueBoundedDecision`** **或** 版本化后的 **`rrmBoundedDecision`**。 |
| **校验** | **`schemaVersion` / `sourceVersion`**、**feature flag**、**`fallbackUsed` / guardrails**、**selected target 可用性**（DB / pool / Top2 闭包，**不**扩大候选池）。 |
| **输出** | **`displayCandidateUserId`**、**`displaySourceType`**、**（可选）`decisionSourceType`**；**与** **GET** 其他投影字段 **一致**。 |
| **容错** | **不 throw 到页面**；失败 → **fallback baseline** 展示 slice。 |

| 不得 | 说明 |
|------|------|
| **前端** | **解析** raw **`matchInsights`**；**自行**判断 **switch**。 |
| **Resolver** | 依赖 **`scoreShadow` v1** 作为门槛；**扩大**候选池或改写 **worker ranking**。 |

## 9. Worker write contract

**若未来** **worker** 写 **true meta**（**非 r2 义务**）：

| 必须 | 说明 |
|------|------|
| **时机** | 在 **final `MatchResult.create` 前** 确定 **baseline** 与 **selected**（与 **insights** 闭包一致）。 |
| **审计** | 保留 **`baselineRef`**、**`selectedRef`**、**`fallbackReason`**、**`sourceVersion`**。 |
| **透明** | **不得**「隐藏」改写 winner：若**不改** **`candidateUserId`**，**`mode`** **必须**为 **`dry_run`** 或 **`read_layer_override`**（**或** **`fallback`**）。 |
| **若改** **`candidateUserId`** | **`mode`** **必须为** **`enabled`**，且完成 **explanation unification**（**M6.4-r1 §11**）与 **finalScore strategy**（**§10**）。 |

## 10. `finalScore` strategy

### 10.1 候选

| 选项 | 含义 | 权衡 |
|------|------|------|
| **A. Keep baseline `finalScore`** | **切换展示或切换候选后**仍展示 **baseline** 分数。 | **实现简单**；若 **display / chat** 指向 **selected**，**解释可能错误** → **须** UI 声明或禁止该组合上线（**§11**）。 |
| **B. Use selected target score if already available** | 若 **worker** 侧车或池内已有 **target** 分量，**投影**为解释分数。 | **更合理**；须保证 **分量可追溯**、**版本**与 **guardrail** 一致。 |
| **C. Introduce `decisionScore` / `explanationScore`** | 与持久化 **`finalScore`** 解耦的展示分。 | **语义最清晰**；须 **API/UI** 新合同。 |

### 10.2 r2 推荐

- **M6.4** **不**直接改 **`finalScore`**。
- **True read-layer override** 阶段：**默认** **`finalScore` remains baseline**，**除非** **单独 score contract**（**§10.1 B/C**）已 **ADR 锁定**并 **全链路实现**。
- **若进入** **`candidateUserId` write（Strategy C）**：**必须先**完成 **`finalScore` strategy contract** 与 **explanation unification**。

## 11. Product consistency contract

**必须**书面定义（**不统一则不允许上线 true 路径**）：

| 维度 | 必须定义「权威对象」 |
|------|----------------------|
| **FinalMatchPage 展示对象** | **`displayCandidateUserId`** **或** **`candidateUserId`**；**与 Hero / 分数 / 文案一致**。 |
| **Chat target** | 与 **展示**或 **持久化**一致；**禁止**默认进 **A** 而详情 **B**。 |
| **Timeline target** | 同上。 |
| **Feedback 归因** | 评价对象 **userId** 与 **匹配对** 解释一致。 |
| **MatchReview / Explanation** | 解释 **同一** candidate；**技术折叠区**说明 **source**。 |
| **`primaryConclusion`** | 与 **展示候选** 一致。 |
| **Fallback 文案** | **用户可见**一句 **稳定基线** / **系统回退**；**技术细节**在 **FinalMatchTechnicalDetails** 类区域折叠（与 **M6.0-r8** 模式对齐）。 |

**结论：** 若**仅** **read-layer override** 且**无法**保证 **chat/timeline** 与 **FinalMatchPage** **同一对象**，**不允许**上线该 flag 组合。

## 13. Rollback contract

| 要求 | 说明 |
|------|------|
| **Flag off** | **立即**回到 **baseline** 行为（展示与解释）。 |
| **Fallback path** | **永远存在**；resolver **失败不 500**。 |
| **`baselineRef` in meta** | 支持审计与对账（**redacted**）。 |
| **一键关闭** | **异常率**或 **gate** 违背时关闭 **true flag**；**不依赖** **DB migration rollback**。 |
| **历史行** | 保留 **meta** **不**应影响 **flag off** 后的读路径（**读路径忽略 true 语义**）。 |
