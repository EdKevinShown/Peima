# M6.7-C1 — RRM Debug Observation Snapshot

## 1. 本轮目标

- M6.7 目标是补齐 admin / debug observation 基础能力。
- C1 先落地一个只读 observation snapshot script，观察最近 `MatchResult` 的 RRM / resolved / handoff / owner 相关信号。
- 本轮不做 true bounded decision，不接线 `PEIMA_M6_RRM_BOUNDED_DECISION_ENABLED`，不改正式匹配结果。

## 2. 修改文件

- `packages/database/scripts/m6-r7-rrm-observation-snapshot.mjs`
- `docs/M6/M6.7-C1-rrm-debug-observation-snapshot.md`

## 3. Script 行为

- 只读 Prisma 查询：`matchResult.findMany`，仅 `select.matchInsights` / `createdAt`。
- 不写 DB，不更新任何 `MatchResult` 字段。
- 不输出真实 `id` / `userId` / `candidateUserId` / `conversationId`。
- 支持 `--limit` / `--pretty` / `--json` / `--since`。
- 对 malformed `matchInsights` 做逐行容错；单行异常不影响整体聚合输出。

## 4. 观测字段

脚本输出 summary（匿名）包含：

- 顶层覆盖：`sampleSize`、`withScoreShadowV2`、`withScoreShadowV1Legacy`、`withRrmV2Top2Selector`、`withRrmDecisionShadow`、`withRrmBoundedDecision`、`withResolvedProjectionUnavailableInDbNote`。
- `decisionShadow` 分布：`same_as_baseline` / `switch_to_top2_candidate` / `no_shadow_decision` / `blocked` / `unexpected_exception`。
- `boundedDecision` 分布：`would_use_baseline` / `would_switch_to_rrm` / `fallback_baseline` / `fallbackReasonDistribution`。
- `inputPresence` 计数：`scoreShadowV2True` / `rrmV2Top2SelectorTrue` / `selectedTop2True` / `scoreShadowV1LegacyPresentTrue`。
- `quality`：`malformedCount` / `parseErrorCount` / `unexpectedExceptionCount`。
- `notes` 明确：
  - resolved projection 是 API runtime projection，不在 DB 直接持久化；
  - handoff mismatch / owner warning 主要是 runtime UI 信号，不一定可从 DB 直接统计。

## 5. 本地运行结果

### 命令

```bash
node --env-file=.env packages/database/scripts/m6-r7-rrm-observation-snapshot.mjs --limit 50 --pretty
node --env-file=.env packages/database/scripts/m6-r7-rrm-observation-snapshot.mjs --limit 20 --pretty
```

### 结果

- 两次执行均失败，错误一致：`Can't reach database server at localhost:5432`。
- 当前环境无法连接本地 DB，因此未生成可用 `sampleSize` 与各分布的匿名数值快照。
- 失败为环境连通性问题，不涉及脚本写路径（脚本本身无写操作）。
