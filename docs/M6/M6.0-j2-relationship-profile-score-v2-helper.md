# M6.0-J2 — relationshipProfileScore V2 pure helper

## Scope (this milestone)

This milestone adds a **pure TypeScript helper** and **unit tests** only:

- `apps/worker/src/jobs/relationship-profile-score-v2.ts` — `computeRelationshipProfileScoreV2(viewerProfile, candidateProfile)` plus exported axis metadata and mapping helpers used by tests.
- `apps/worker/test/relationship-profile-score-v2.spec.ts` — Jest coverage for the formula contract.

There is **no** integration with the batch worker, Prisma, HTTP APIs, or the web app.

## Explicit non-goals (unchanged in J2)

- **Does not** change `MatchResult.finalScore` or any persisted match score used for ranking.
- **Does not** change worker winner selection, batch-match write paths, or match ranking.
- **Does not** change `candidateUserId` or `displayCandidateUserId`.
- **Does not** change RRM resolvers, RRM metadata, or any RRM-only display logic.
- **Does not** add `matchInsights` payloads or API response fields.
- **Does not** modify `FinalMatchPage`, `matching.service.ts`, `batch-match.processor.ts`, or Prisma schema / migrations.

Formula details and pipeline placement are documented in:

- `docs/M6/M6.0-j1b-relationship-profile-score-v2-formula-design.md`
- `docs/M6/M6.0-j1c-matching-pipeline-v2-responsibility-alignment.md`

## Shadow contract

`scoringVersion` is `m6.0-relationship-profile-score-v2-shadow`. Output is suitable for future **score shadow** sidecars only until a later milestone wires it.

## Next step (M6.0-J3)

**J3** will attach this helper to the worker **score shadow** path (read profiles, compute V2, persist shadow fields) without replacing legacy `finalScore` or touching RRM / display candidate resolution.
