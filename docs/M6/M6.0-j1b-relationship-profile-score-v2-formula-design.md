# M6.0-J1B — relationshipProfileScore v2 Formula Design

> **依据**：**`docs/M6/M6.0-j-relationship-profile-score-v2-product-requirements.md`**（产品要求）、**`docs/M6/M6.0-g3-30-canonical-answer-pattern-regression.md`**（G3 五态 v1 观测）、**`docs/M6/M6.0-q2-promote-q29-q30-canonical.md`**（30 canonical）。  
> **对齐实现**：轴字段顺序与 **`G1R_PROFILE_KEYS`**（`questionnaire.scorer.ts`）及 worker **`PROFILE_DIMS`**（`matching-score.ts`）一致。  
> **本轮**：**只定公式与 JSON 契约草案**，**不改** 代码、worker、API、schema、**`MatchResult.finalScore`**、排序、**`candidateUserId` / `displayCandidateUserId`**、RRM。

---

## 1. 一句话结论

**v2** 不再是 **20 维等权平均相似度**（v1 的 `computeProfileScore`），而是：**加权画像相似度** → **`weightedBaseScore`** → **按轴分级 `penaltyTotal`（有上限）** → **`rawCompatibilityScore`** → **冲突驱动的 `capApplied`** → **`cappedRawScore`** → **分段单调映射** → **`displayScore100`（0–100）** 与 **`band`**。本轮 **仅文档冻结初版参数**；实现落在 **M6.0-J2/J3**，回归在 **M6.0-G4**。

---

## 2. v2 输出目标（JSON 结构）

**写入位置（实现阶段）**：建议嵌在 **`matchInsights.scoreShadow`** 的扩展对象中（与现有 **`m6.0-profile-score-shadow-v1`** 并存或版本字段区分）；**`GET /matching/result` 不写库**（只读聚合）。

**输出对象（字段名冻结为契约；数值范围在注释中标明）**：

```json
{
  "scoringVersion": "m6.0-relationship-profile-score-v2-shadow",
  "rawCompatibilityScore": 0.0,
  "weightedBaseScore": 0.0,
  "penaltyTotal": 0.0,
  "cappedRawScore": 0.0,
  "displayScore100": 0,
  "band": "strong_conflict",
  "capApplied": null,
  "coreConflictCount": 0,
  "strongConflictCount": 0,
  "redFlagConflictCount": 0,
  "source": "profile_v2_shadow"
}
```

| 字段 | 类型 | 范围 / 枚举 | 说明 |
|------|------|-------------|------|
| **`scoringVersion`** | `string` | 固定 **`"m6.0-relationship-profile-score-v2-shadow"`** | 与 **M6.0-E** v1 shadow 版本字符串 **区分**。 |
| **`rawCompatibilityScore`** | `number` | **\[0, 1\]** | **初版定义**：**`weightedBaseScore - penaltyTotal`** 后 **clamp 到 \[0,1\]**（见 **§4**）；**再** 与 **cap** 合成 **`cappedRawScore`** 时，**本字段可存「cap 前」或「cap 后」** 二选一，**须在 J2 实现时固定**；推荐：**`rawCompatibilityScore` = cap 前**、**`cappedRawScore` = min(raw, cap)**，便于审计。 |
| **`weightedBaseScore`** | `number` | **\[0, 1\]** | 仅加权相似度，**无 penalty**。 |
| **`penaltyTotal`** | `number` | **\[0, 0.30\]** | 各轴扣分之和 **上限 0.30**（见 **§5**）。 |
| **`cappedRawScore`** | `number` | **\[0, 1\]** | **`min(rawCompatibilityScore, capApplied)`**，`capApplied == null` 时视为 **无 cap**（等价 **1.0**）。 |
| **`displayScore100`** | `number` | **\[0, 100\]**，整数或一位小数 | **用户可见主候选分**；由 **`cappedRawScore`** 经 **§7** 映射。 |
| **`band`** | `string` | **`strong_conflict` \| `low` \| `medium` \| `good` \| `high`** | 由 **`displayScore100`** 分档（**§8**）。 |
| **`capApplied`** | `number \| null` | **(0,1\] 或 null** | 实际生效的 **上限值**；**`null`** = 未触发。 |
| **`coreConflictCount`** | `number` | **非负整数** | **核心轴**上 **`diff > 0.45`** 的轴数（**含** `diff > 0.60` 的轴）。 |
| **`strongConflictCount`** | `number` | **非负整数** | **核心轴**上 **`diff > 0.60`** 的轴数。 |
| **`redFlagConflictCount`** | `number` | **非负整数** | **红线轴**上触发 **红线规则** 的次数（见 **§6**）。 |
| **`source`** | `string` | 固定 **`"profile_v2_shadow"`** | 与 API **`relationshipProfileScore` 的 `source`** 枚举扩展时对齐（实现阶段）。 |

**补充（实现建议，非本 JSON 根字段）**：若有效双端非 null 轴数 **低于阈值**（建议 **`< 10`**），应在兄弟字段或 **`matchInsights`** 旁路标记 **`insufficient_profile: true`**（**J2** 定稿）；**本对象根上可不强制**，但 **G4 验收** 须覆盖。

**闸门**：**v2 先 shadow**；**不替换** **`MatchResult.finalScore`**；**不改变** worker **胜者**；**不改** **`candidateUserId` / `displayCandidateUserId`**；**不碰** RRM。

## 4. rawCompatibilityScore 计算

### 4.1 单轴相似度

对每一轴 `k`（viewer 值 `v`、candidate 值 `c` 均为 **\[0,1\]** 上的数或 **`null`**）：

```text
axisSimilarity(k) = 1 - |v - c|
```

### 4.2 加权基底分 `weightedBaseScore`

```text
weightedBaseScore = Σ_k ( axisSimilarity(k) × weight(k) ) / Σ_k weight(k)
```

其中求和 **仅包含** 同时满足 **`v != null` 且 `c != null`** 的轴；**不把 `null` 当 0**。

**`sexualValues`**：若 **`weight = 0`** 或任一端为 **`null`**，则 **跳过**（**不进分子与分母**）。

### 4.3 penalty 与 raw（cap 前）

按 **§5** 对每个 **参与 penalty** 的轴计算扣分档位，**每轴只取最高档一次**，求和得 **`penaltyTotal`**，并 **clamp**：

```text
penaltyTotal = min(0.30, Σ penalties)
rawCompatibilityScore = clamp01( weightedBaseScore - penaltyTotal )
```

`clamp01(x) = min(1, max(0, x))`。

### 4.4 cap 后 `cappedRawScore`

```text
capApplied = min(触发的各 cap 上界)  // 若无触发则为 null
cappedRawScore = min(rawCompatibilityScore, capApplied ?? 1.0)
```

**计数定义**（与 **§5、§6** 一致）：

- **`strongConflictCount`**：**核心轴**中 **`diff > 0.60`** 的个数。  
- **`coreConflictCount`**：**核心轴**中 **`diff > 0.45`** 的个数（**包含** strong 档）。  
- **`redFlagConflictCount`**：**红线轴**上满足 **`diff > 0.50`** 的个数（阈值 **J2** 可配置为 **0.48–0.55**，G4 冻结）。

---

## 5. penalty 规则（核心轴）

对 **参与 penalty** 的轴（**§3 总表「是否参与 penalty = 是」**），令 **`diff = |v - c|`**（**两端均非 `null`**）。

| 条件（同一轴 **只取最高档**） | 等级 | 扣分（加到 `penaltyTotal`） |
|------------------------------|------|-------------------------------|
| `diff > 0.60` | strong | **0.070** |
| `0.45 < diff ≤ 0.60` | core | **0.035** |
| `0.35 < diff ≤ 0.45` | mild | **0.015** |
| `diff ≤ 0.35` | none | **0** |

**上限**：**`penaltyTotal ≤ 0.30`**（超过则截断，避免基底被一次性打穿）。

**辅助轴**：**默认不进入 penalty**；若产品后续要求「辅助轴 mild」，须在 **修订版** 中单开表并 **重跑 G4**。

---

## 6. cap 规则（上限压制高分）

**目的**：**只限制高分**，不是替代排序逻辑；与 **penalty** 叠加后仍能 **把「多冲突仍表面相似」的样本** 压到 **中低 raw**，再配合 **§7** 落入 **0–40 / 40–60**。

**红线轴集合**（与产品要求一致）：`marriageExpectation`, `childrenIntent`, `familyView`, `conflictHandling`, `securityNeed`。

**触发条件与上界**（多条件同时满足时，**`capApplied`** 取各上界的 **最小值**）：

| 条件 | `cap` 上界（对 `rawCompatibilityScore` 生效） |
|------|-----------------------------------------------|
| **`strongConflictCount ≥ 1`** | **0.82** |
| **`coreConflictCount ≥ 2`** | **0.78** |
| **`coreConflictCount ≥ 3`** | **0.72** |
| **`redFlagConflictCount ≥ 1`** | **0.68** |

```text
candidates = []
if strongConflictCount >= 1: candidates.push(0.82)
if coreConflictCount >= 2:   candidates.push(0.78)
if coreConflictCount >= 3:   candidates.push(0.72)
if redFlagConflictCount >= 1: candidates.push(0.68)
capApplied = candidates.length ? min(candidates) : null
cappedRawScore = min(rawCompatibilityScore, capApplied ?? 1.0)
```

## 7. displayScore100 映射（分段线性、单调）

**输入**：**`cappedRawScore` ∈ \[0, 1\]`**（连续）。**输出**：**`displayScore100` ∈ \[0, 100\]`**。

**工具函数**（实现可直接拷贝为纯函数）：

```text
mapRange(x, inMin, inMax, outMin, outMax) =
  outMin + (clamp01((x - inMin) / (inMax - inMin))) * (outMax - outMin)
```

其中 **`(x - inMin)/(inMax - inMin)`** 在 **`x < inMin`** 取 **0**，**`x > inMax`** 取 **1**（即 **clamp 到段内再线性插值**）。

**初版分段（五段，整体单调非减）**：

| 条件（`r = cappedRawScore`） | 输出区间（闭区间端点按段内插值） |
|------------------------------|----------------------------------|
| **`r ≥ 0.90`** | **\[90, 100\]**：`display = mapRange(r, 0.90, 1.00, 90, 100)` |
| **`0.82 ≤ r < 0.90`** | **\[78, 90\)**：`display = mapRange(r, 0.82, 0.90, 78, 90)` |
| **`0.72 ≤ r < 0.82`** | **\[62, 78\)**：`display = mapRange(r, 0.72, 0.82, 62, 78)` |
| **`0.55 ≤ r < 0.72`** | **\[40, 62\)**：`display = mapRange(r, 0.55, 0.72, 40, 62)` |
| **`r < 0.55`** | **\[0, 40\)**：`display = mapRange(r, 0.00, 0.55, 0, 40)` |

**边界连续性检查**（设计值）：在 **`r = 0.82`** 第二段下端 **= 78**；**`r = 0.72`** 第三段下端 **= 62**；**`r = 0.55`** 第四段下端 **= 40**；**`r = 0.90`** 第一段下端 **= 90**，与第二段上端一致。

**设计样例（验证数量级，非实测）**：

| `cappedRawScore` | `displayScore100`（约） |
|------------------|-------------------------|
| 0.82 | **78** |
| 0.75 | **≈ 67.5 → 68**（线性内插） |
| 0.60 | **≈ 46.5 → 47** |
| 0.45 | **≈ 32.7 → 33** |

**要求对照产品**：

- **整体单调**：`r` 增大 **`displayScore100` 不减小**。  
- **避免 0.75–0.85 全挤 80+**：同 raw 下 v1×100 约 **75–85**；本映射在 **\[0.72,0.82)** 仅映射到 **62–78**，**配合 penalty/cap** 可把 **All-C 类** 进一步压到 **<0.72** 进入 **40–62** 或 **<0.55** 进入 **0–40**（**G4 验收**，见 **§9**）。  
- **强冲突 0–40**：需 **`cappedRawScore` < 0.55**；由 **大 penalty + 低 cap** 驱动，**G4** 用 **人工构造高 diff** 用例验收。

**取整**：展示可 **`Math.round`** 到整数，或 **保留一位小数**；**`band`** 以 **四舍五入后的整数分** 判定（**J2** 固定一种）。

## 8. band 规则与前端文案建议

按 **`displayScore100`**（**整数，0–100**）：

| 区间 | `band` | 前端主文案建议 | 辅色 / 图标建议 |
|------|--------|----------------|-----------------|
| **0–40** | **`strong_conflict`** | **强冲突 · 不建议继续投入** | 警示红、停止向 |
| **40–60** | **`low`** | **低适配 · 建议谨慎了解** | 橙红 |
| **60–75** | **`medium`** | **中等适配 · 可继续观察** | 琥珀 |
| **75–88** | **`good`** | **较好适配 · 值得深入** | 绿黄 |
| **88–100** | **`high`** | **高度适配 · 优先了解** | 深绿 |

**边界**：**`displayScore100 === 40`** 归入 **`strong_conflict`** 上沿或 **`low`** 下沿由产品择一 **固定**（建议 **40 归入 `low`**，**39 及以下** 为 **`strong_conflict`**）；须在 **J2** 与 UI **统一**。

## 9. G3 数据的预期再解释（无 v2 实测编造）

**已知 G3（v1 `relationshipProfileScore` / `profileScore`）**：约 **0.754–0.842**；若 **×100** 仅 **75–84**，**无法满足** **M6.0-J** 的 **0–100 全区间与低段语义**。

**对 v2 的预期（须在 M6.0-G4 用实测验证）**：

- **All-C**：在 **核心/红线 diff** 构造合理时，**`penaltyTotal` + `cap`** 应能把 **`cappedRawScore`** 压到 **<0.72** 甚至 **<0.55**，**`displayScore100`** 应 **明显低于 75**，进入 **`low` / `strong_conflict`** 候选区。  
- **Normal**：若与 candidate **确实接近**，**`weightedBaseScore` 高** 且 **冲突计数低**，**应保持 `good` 档** 为主（**不保证**永远高于 All-A/B/D）。  
- **All-A / All-B / All-D**：**不一定** 系统性地低；若 **直线卷导致核心轴仍对齐** 则分仍可能偏高——**这正是 v2 与后续 low-effort 解耦的原因**：**v2 负责「画像冲突几何」**；**low-effort 负责「答卷可信度」**（见 **§10**）。

**不在本文写死 v2 数值**：**G4** 填表。

---

## 10. 与 low-effort detection 的边界

- **本轮及 J1B**：**不做** low-effort detection。  
- **All-A / B / C / D**：继续作为 **压力测试样本**，**不** 直接打「低质量」标签。  
- **v2 拉开分数**：**必须** 在 **无 low-effort** 的前提下仍能通过 **penalty / cap / 映射** 实现 **§7、M6.0-J** 的区间目标。  
- **后续**：low-effort 可作为 **并列提示**（可信度），**不阻塞** v2 shadow 上线。

---

## 11. 与前端主分数切换（M6.0-H）的关系

- **H 不应** 直接把主视觉 **绑在 v1 `relationshipProfileScore`（0–1 温和带）** 上。  
- **建议顺序**：**J2** 纯函数 **`computeRelationshipProfileScoreV2(viewerProfile, candidateProfile)`** + **单测** → **J3** worker **写入 shadow** → **G4** 回归表 → 若 **`displayScore100`** 与 **band** 通过验收，**H** 再将 **主分数** 切到 **`displayScore100`**（**legacy `finalScore` v1** 保留技术折叠区）。

### 13.1 M6.0-G4 回归验收标准（草案）

1. **单调性**：在 **\[0,1\]** 内 **`cappedRawScore` 单调增** 时，**`displayScore100`** **不减**。  
2. **全区间可达性**：存在用例使 **`displayScore100`** 分别落入 **\[0,40\]**、**(40,60\]**、**(60,75\]**、**(75,88\]**、**(88,100\]**（与 **M6.0-J** 文案一致，边界实现按 **§8** 固定）。  
3. **G3 对照**：在 **同一 viewer / candidate** 重放 **G3 五态** 时，**All-C** 的 **`displayScore100`** 应 **显著低于** **Normal / All-A / All-B / All-D** 的展示分（**除非** 该候选在 **C 档直线** 上仍与 viewer **极低 diff**——此时须记录为 **数据特例** 而非放宽公式）。  
4. **强冲突构造**：至少 **1 组** 合成画像使 **`redFlagConflictCount ≥ 1`** 或 **`strongConflictCount ≥ 1`**，且 **`displayScore100 ≤ 40`**（或按 **§8** 归入 **`strong_conflict`**）。  
5. **不足画像**：有效双端轴 **< 10** 时 **`insufficient_profile`** 行为符合 **J2** 约定（**不崩**、**不默认满分**）。  
6. **不变量复查**：**G4** 跑后 **`MatchResult.finalScore`**、**排序**、**`candidateUserId`**、**RRM** 与基线 **diff 为零**。
