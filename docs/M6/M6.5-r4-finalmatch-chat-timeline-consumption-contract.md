# M6.5-r4 — FinalMatchPage / Chat / Timeline Consumption Contract

## 1. 本轮目标

- **M6.5-r2** 已定义 **`resolvedCandidate`** 与各 **target / owner** 的**一致性**要求。
- **M6.5-r3** 已定义 **`GET /matching/result/:userId`**（**`getMatchingResult`**，见 **`apps/web/src/api/matching.ts`**）**未来** **`resolved*`**、**owner**、**fallback**、**`consistencyWarnings`** 等字段合同。
- **M6.5-r4（本文）**：定义 **`FinalMatchPage.jsx`**（及相关组件如 **`FinalMatchTechnicalDetails.jsx`**，见 **M6.0-r8**）与 **Chat / Timeline / Feedback / Score / Explanation** 动作入口**如何消费**上述字段，**避免**「**页面上 B、聊天进 A、解释像 C**」。
- **r4** **只**输出**前端消费合同**；**不**改 **`FinalMatchPage`**、**不**改 **API**、**不**实现 **true bounded**。

---

## 2. 当前风险

若缺少书面消费合同，**未来**在 **`displayCandidateUserId` ≠ `candidateUserId`** 或 **`resolved*`** 引入后，易出现：

| 风险 | 表现 |
|------|------|
| **展示与聊天分裂** | **FinalMatchPage** 主卡片展示 **B**，**Start Chat** 仍绑定 **`candidateUserId`** → **A**。 |
| **时间线分裂** | **Timeline** 记录 **A**，页面展示 **B**。 |
| **反馈归因错误** | 用户对 **B** 的评价写入 **A** 维度。 |
| **分数与对象错配** | **`finalScore`** 仍解释 **baseline**，页面却暗示属于 **B**（**M6.5-r3** 示例一）。 |
| **解释对象漂移** | **`matchExplanation` / `matchReview`** 仍引用 **A** 的侧车，**Hero** 已切 **B**。 |
| **自拼 RRM** | 前端读 **`matchInsights`** 推断 **switch** → 与后端 **resolver** 不一致。 |

---

## 3. 前端消费原则

| 原则 | 说明 |
|------|------|
| **不解析 raw meta** | **`FinalMatchPage`** **不**解析 **`matchInsights.rrmDecisionShadow` / `rrmBoundedDecision`**（及 **M6.0-r8** 已禁止的 **`rrmV2Top2Selector` / `scoreShadow`** 原文）。 |
| **不自算 switch** | **不**根据 **`wouldSwitch` / `shadow.decision`** 等在前端分支业务。 |
| **优先 `resolved*`** | **主路径**以 **`resolvedCandidate` / `resolvedCandidateUserId`**（若 API 提供）为**第一**展示与动作锚点；缺省时见 **§12**。 |
| **动作按钮只用 API target** | **Chat / Timeline / Feedback** 使用 **`chatTargetUserId` / `timelineTargetUserId` / `feedbackTargetUserId`**，**禁止**仅依赖 **`candidateUserId`** 作为**唯一**来源。 |
| **技术区只展示、不决策** | **来源 / fallback / warnings** 仅用于**说明**与**合规提示**，**不**参与「是否切换对象」的客户端裁决。 |

---

## 4. FinalMatchPage display contract

**未来** **`FinalMatchPage`**（及 **Hero / 主资料区**）**应优先**消费：

| 字段 | 用途 |
|------|------|
| **`resolvedCandidate`**（若有嵌套对象） | **主卡片**资料、头像、标签等。 |
| **`resolvedCandidateUserId`** | **无**嵌套对象时，用于拉取 profile 的**键**（与现有数据加载方式对齐）。 |
| **`resolvedSourceType`** | **主** **source badge** / 用户可见「当前匹配对象来源」摘要。 |
| **`displaySourceType` / `decisionSourceType`** | **辅助**说明（与 **M6.0-r8** 表格兼容）；**不得**与 **`resolvedSourceType`** 矛盾且无解释。 |
| **`fallbackUsed` / `fallbackReason`** | **fallback note**（与 **M6.0-r8** **`fallbackUsed`** 文案方向一致）。 |
| **`consistencyWarnings`** | **横幅 / 内联** 按 **§10** 分级展示。 |

**分区建议：**

- **主卡片**：**只**围绕 **`resolvedCandidate*`**。
- **Source badge**：**`resolvedSourceType`** 为主，**`displaySourceType`** 为辅。
- **Technical details（折叠）**：可对照 **baseline / display / decision / resolved** 的差异（**§11** 脱敏规则）。

---

## 5. Chat button contract

| 规则 | 说明 |
|------|------|
| **必须使用** | **`chatTargetUserId`**（来自 **GET**）。 |
| **默认** | **`chatTargetUserId` = `resolvedCandidateUserId`**（由后端保证，**M6.5-r3 §4**）。 |
| **`chatTargetUserId` 缺失** | **禁用** **Start Chat** **或** 显式降级到 **`baselineCandidateUserId`** 且 **`fallbackUsed` + warning**（**不得**静默用错人）。 |
| **禁止** | **唯一**使用 **`candidateUserId`** 作为聊天入口（除非其与 **`chatTargetUserId`** **经 API 证明相同**）。 |
| **禁止** | 从 **`displayCandidateUserId`** **前端推断**聊天对象。 |

---

## 6. Timeline button contract

| 规则 | 说明 |
|------|------|
| **必须使用** | **`timelineTargetUserId`**。 |
| **默认** | **`timelineTargetUserId` = `resolvedCandidateUserId`**。 |
| **若** **`timelineTargetUserId` ≠ `resolvedCandidateUserId`** | **必须**存在 **`consistencyWarnings`** 中 **`timeline_target_mismatch`**（或等价 **code**），**severity** **≥ warning**。 |
| **禁止** | **静默**跳转到 **baseline** 而页面仍展示 **非 baseline** **且无提示**。 |

---

## 7. Feedback contract

| 规则 | 说明 |
|------|------|
| **必须归因到** | **`feedbackTargetUserId`**（**POST body** 或 **侧车字段**与 **GET** 对齐策略由实现阶段定）。 |
| **默认** | **`feedbackTargetUserId` = `resolvedCandidateUserId`**。 |
| **若** **`fallbackUsed`** 且 **UI** 明确展示 **baseline** 为主对象 | 反馈可归 **baseline**，**但**须在 **payload** 或 **元数据** 中记录 **`fallbackSource` / `resolvedSourceType`**，避免学习管道误标。 |
| **禁止** | 用户对 **当前主卡片展示对象** 的反馈写入 **另一用户**，**除非**页面**大字**说明「反馈对象为 **baseline**」并获得产品 **sign-off**。 |

---

## 8. Score display contract

| 规则 | 说明 |
|------|------|
| **必须读取** | **`scoreOwnerCandidateUserId`**（**M6.5-r3**）。 |
| **`scoreOwnerCandidateUserId` = `resolvedCandidateUserId`** | **可**将 **`finalScore`** / **分项** 作为 **resolved** 的分数语义展示。 |
| **若不同** | **须** **info / warning**（见 **M6.5-r3** **`score_owner_mismatch`**）；**不得**把 **baseline `finalScore`** **文案化**为「**resolved 对象的匹配指数**」。 |
| **禁止** | **无 score contract** 时暗示 **分数属于 switched target**（**M6.4-r2 §10**）。 |

---

## 9. Explanation display contract

**解释模块**（含 **`primaryConclusion` / `matchExplanation` / `matchReview` / `reasonSummary` / `relationshipProfileScore` 文案向 / conversation starters / chat tips / risk notes**）**必须以** **`explanationOwnerCandidateUserId`** **为语义锚点**。

| 条件 | UI |
|------|-----|
| **`explanationOwnerCandidateUserId` = `resolvedCandidateUserId`** | 正常展示。 |
| **不等** | **须** **warning** 或 **显式 fallback** 区块；**禁止**静默展示「像 resolved」的解释。 |

---

## 10. Consistency warnings UI

**未来** **`consistencyWarnings[]`**（**M6.5-r3 §8**）在 **UI** 的映射：

| **`severity`** | 行为 |
|----------------|------|
| **`info`** | 技术层 **source** 差异；**不**阻断主动作（可放折叠区顶部一句）。 |
| **`warning`** | **owner** 不一致或 **score/explanation** 与 **resolved** 不对齐；**须**用户可见短文案 + 链到技术说明。 |
| **`blocking`** | **缺目标**、**高风险**或 **chat/timeline** 不可用；**禁用**对应按钮或整页降级为 **baseline-only** 安全态。 |

**示例 `code`（与 r3 对齐，可扩展）：**

- **`score_owner_mismatch`**
- **`explanation_owner_mismatch`**
- **`chat_target_mismatch`**
- **`timeline_target_mismatch`**
- **`feedback_target_mismatch`**
- **`resolved_fallback_to_baseline`**

---

## 11. Technical details contract

**折叠区「技术来源说明」**（与 **M6.0-r8**、**`FinalMatchTechnicalDetails.jsx`** 精神一致）**可以**展示：

- **`baselineCandidateUserId` / `displayCandidateUserId` / `decisionCandidateUserId` / `resolvedCandidateUserId`**：**脱敏**（**掩码 / 截断 / hash**；**禁止**完整明文 **userId** 给**普通用户**）。
- **`resolvedSourceType` / `fallbackReason` / `fallbackFromSourceType`**
- **`sourceVersion`**（**聚合摘要**，非整段 JSON）
- **`consistencyWarnings`**（可复制为 debug 导出，**受权限**约束）

**不得**对**普通用户**默认展示：

- **raw 完整 ID**
- **raw `matchInsights`** 全文
- **raw internal shadow / bounded payload**

**管理员 / debug** 模式可由**单独** **flag + 权限** 放开，**不在** **M6.5-r4** 实现范围。

## 12. Backward compatibility

| 阶段 | 行为 |
|------|------|
| **`resolvedCandidateUserId` 缺省**（旧 API） | **可** **fallback**：**`displayCandidateUserId` ?? `candidateUserId`**；**须**在**客户端**打 **`localDevOnly` / `telemetry`** 级标记或 **UI** 一句「使用旧 API 解析路径」（**产品**定稿）。 |
| **迁移完成** | **必须**切换为 **r3** **resolved** 字段为**主**读路径。 |
| **`fallbackUsed`** | **API** 与 **本地 fallback** **不得**互相矛盾；优先信 **API**。 |
