# M6.10-C1 — Top2 Score Snapshot Normalization

## 1. 本轮目标

为后续 `resolvedFinalScore` projection 做准备：在 worker 写入 `matchInsights` 时补充 Top2 两人的分数快照（第一版仅 Top2）。

本轮不改 winner 选择，不改 `MatchResult.candidateUserId` / `MatchResult.finalScore`，不改 read-layer 决策逻辑。

## 3. 新增字段结构

新增 `matchInsights.top2ScoreSnapshot`（可选）：

- `schemaVersion: 1`
- `sourceType: "top2_score_snapshot"`
- `sourceVersion: "m6.10-top2-score-snapshot-v1"`
- `items: Array<Top2Item>`（最多两条，按 rank 1/2）

每个 `Top2Item`：

- `candidateUserId`
- `rank`（`1 | 2`）
- `finalScore`（来自 worker `scored[]` 对应候选的 `components.finalScore`）
- `displayScore100` / `band`（与 `rrmV2Top2Selector.selectedTop2` 对齐）
- `components`（`previewPoolScore` / `preferenceScore` / `styleScore` / `profileScore` / `finalScore`）
- `scoreOwnerCandidateUserId`（与 `candidateUserId` 一致）

## 4. Worker 写入行为

- `batch-match.processor` 继续沿用既有排序与 winner 选择逻辑（不变）。
- 在调用 `buildWorkerMatchInsightsForBestMatch` 时，把每个候选的 `scoreComponents`（来自内存 `scored[]`）一并传入。
- `batch-match-match-insights` 继续先构建 `rrmV2Top2Selector`，再按其 `selectedTop2` 顺序生成 `top2ScoreSnapshot.items`：
  - `rank` 与 `selectedTop2` 顺序严格对齐；
  - `displayScore100` / `band` 复用 selector；
  - `finalScore/components` 来自 worker 计算结果映射。
- 若某候选缺失 `scoreComponents`，快照项仍保留，但数值字段为 `null`（不 throw）。
- 当 Top2 不可用（例如候选不足），`top2ScoreSnapshot.items` 为 `[]`，`matchInsights` 仍正常生成。

## 5. 与 RRM / resolved score 的关系

- 本轮只做 Top2 score snapshot 标准化，不改 API projection。
- 后续 M6.10-C2 可据 `resolvedCandidateUserId` 在 `top2ScoreSnapshot.items` 中查找对应分数，构建 `resolvedFinalScore`。
