# M6.0-C — relationshipProfileScore Shadow

> **范围**：在 **不改 `MatchResult.finalScore`**、**不改 worker**、**不写 DB**、**不改 RRM**、**不改 `candidateUserId` / `displayCandidateUserId`** 的前提下，为 **GET `/matching/result`** 增加 **viewer-safe** 的 **`relationshipProfileScore`** shadow，并在 **FinalMatchPage** 展示「关系画像适配度」。  
> 产品总线见 **`docs/M6/M6.0-a2-scoring-v2-product-logic-plan.md`**；可解释性前置见 **`docs/M6/M6.0-b-score-breakdown.md`**。

---

## 1. 本轮交付

| 项 | 说明 |
|----|------|
| **API** | 响应体新增 **`relationshipProfileScore: { score, source }`**。 |
| **第一版规则** | **`score` = `scoreBreakdown.profileScore`**（当其为有限数）；否则 **`score: null`**，**`source: "missing"`**。 |
| **`source` 枚举** | **`score_breakdown_profile_score`** \| **`missing`** |
| **前端** | **FinalMatchPage** 在 **主分数（Hero）下方** 展示 **关系画像适配度**（百分数一位小数或「暂无」）+ 说明文案；**RRM 展示** 时追加一句 **不改基础分**。 |
| **单测** | `apps/api/test/matching-relationship-profile-score.spec.ts` |

---

## 2. 明确未做（边界）

- **未**重算或读取 **`user_profiles`**、**问卷原始答案**。  
- **未**修改 **`formatReasonSummaryV1`** / worker **`matching-score.ts`**。  
- **未**修改 **RRM resolver** 或 **`displayCandidateUserId`** 语义。  
- **未**替换页面主 **legacy 匹配指数** 标题或主展示逻辑。  
- **下一步（M6.0-D 及以后）**：才考虑 **worker 内并行 v1/v2** 或 **脱离 `reasonSummary` 的正式 `relationshipProfileScore`**。

---

## 3. 与 M6.0-B 的关系

- **`scoreBreakdown`** 仍由 **`reasonSummary`** 只读解析（M6.0-B）。  
- **`relationshipProfileScore`** 仅由已解析的 **`scoreBreakdown`** 派生，**不**二次解析字符串。
