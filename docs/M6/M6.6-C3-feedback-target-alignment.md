## 4. Target 规则

### FinalMatchPage

- **`data-m65-feedback-target-user-id`**：**`feedbackTargetUserId` → `resolvedCandidateUserId` → `displayCandidateUserId` → `candidateUserId`**（**`resolveTargetId`**，与 **M6.5-C3** 一致）。
- 页内补充一句：**结构化反馈在聊天页提交**；锚点供自动化与 **M6.5** API 链对齐。

### ChatPage

- **P6.12 `targetUserId`**：**始终** **`actualConversationPeerUserId`**（当前 **`conversation.candidateUserId`**，与 **M6.6-C1** 定义一致）。
- **Handoff mismatch** 时：**不**把 **`expectedPeerUserId`** 写入 **`targetUserId`**；仍以 **actual** 归因。
- **`data-m65-feedback-target-user-id`**：与 **`actualConversationPeerUserId`** 对齐，便于与 **FinalMatch** 锚点命名一致。

---

## 5. mismatch 行为

- **不**阻止提交反馈。
- **不**自动切换或创建会话。
- **UI**：固定一句「本页反馈按当前会话对象归因。」；**mismatch** 时追加琥珀色说明：最终匹配入口与当前会话不一致时，**仍写入当前聊天对象**。
