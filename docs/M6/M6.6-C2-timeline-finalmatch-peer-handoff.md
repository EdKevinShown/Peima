# M6.6-C2 — Timeline `finalMatchPeerUserId` Handoff

## 1. 本轮目标

- **`FinalMatchPage`** 跳转 **`/chat/timeline`** 时已附带 **`finalMatchPeerUserId`**（与 **M6.5-C3** 一致）。
- **`RelationshipTimelinePage`**（路由 **`/chat/timeline`**）本轮读取该 query，与**当前会话**中的对方 **userId** 做轻量比对。
- **仅** **warning / debug**；**不**改时间线事件生成、**不**改 **`getConversationTimeline`** 请求参数语义、**不**改后端 schema。

---

## 2. 修改文件

| 文件 | 变更 |
|------|------|
| **`apps/web/src/pages/RelationshipTimelinePage.jsx`** | 读取 **`finalMatchPeerUserId`**、**`debug`**；**`peerLookup`** + 既有 **`getConversation(conversationId)`** 推导 **`actualTimelinePeerUserId`**（= **`conversation.candidateUserId`**）；**`timelineHandoffMatched` / `timelineHandoffMismatch`**；顶部 **「本页关系时间线」** 卡片 UI；本地 **`maskPeerIdForDebug`**。 |
| **`docs/M6/M6.6-C2-timeline-finalmatch-peer-handoff.md`** | 本文档。 |

**未改：** **`apps/web/src/api/chat.ts`**（仅复用已有 **`getConversation`**）、timeline 后端、worker、Prisma、README、ai-pairwise 指定路径。

**实现说明：** 时间线列表仍只依赖 **`getConversationTimeline`**；为推导 **peer**，在同一 **`conversationId`** 下**额外**发起一次客户端 **`getConversation`**（与 **ChatPage** 数据来源一致，**无**新后端接口）。

---

## 3. 行为说明

| 项 | 行为 |
|----|------|
| **expected** | **`searchParams.get("finalMatchPeerUserId")?.trim() || null`**。 |
| **actual** | **`getConversation`** 成功且 **`candidateUserId`** 非空 → **`actualTimelinePeerUserId`**；加载中 / 失败 / 空 candidate → 比对侧视为 **`null`**（与 **M6.6-C1** 相同 **matched** 公式，避免误报 mismatch）。 |
| **`timelineHandoffMatched`** | **`!expected || !actual || expected === actual`**。 |
| **mismatch** | 琥珀色提示：「当前时间线对象与最终匹配入口传入对象不一致，本页仍按当前时间线继续。」**不**改拉取参数、**不**阻止列表展示。 |
| **debug=1** | 无 handoff / 已对齐 / 加载中 / 拉会话失败 / candidate 空 / mismatch 脱敏行。 |

---
