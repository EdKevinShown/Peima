# M6.0-R2 / R2B — V2 Top2 selector 纯函数 helper

## 范围

本里程碑只实现一个纯函数 helper：

- `apps/worker/src/jobs/rrm-v2-top2-selector.ts` 中的 `selectV2Top2Candidates`
- `apps/worker/test/rrm-v2-top2-selector.spec.ts` 中的单元测试

本轮**不接入** RRM resolver、batch-match 持久化、Prisma、HTTP API 或 Web 前端。

## R2B 产品规则：RRM always-on

**selector 不再决定 RRM 是否应该运行。**  
它只负责从候选列表中，基于合法的 `scoreShadowV2`，稳定选出 **V2 Top2**。

只要有**至少两个不同候选**拥有**结构合法**的 V2 shadow payload，就返回：

- `eligible === true`
- `reason === "ok"`

后续 RRM 应该在这两个候选之间判断展示谁，也就是：

- `top1CandidateUserId`
- `top2CandidateUserId`

并且 **RRM 不允许选择 V2 Top2 之外的人**。

早期 R2 中曾用于阻止 RRM 的信号，现在都改为**提示信息**，只通过 `contextFlags` 暴露，并在 `thresholds` 中回显对应阈值：

| Flag | 含义 |
|------|------|
| `top2GapLarge` | Top1 − Top2 大于 `thresholds.largeGapThreshold`，默认 **12**；仅作为提示，不阻断 |
| `hasLowBand` | 选中的两个候选中，至少一个 `band === "low"` |
| `hasStrongConflictBand` | 选中的两个候选中，至少一个 `band === "strong_conflict"` |
| `anyBelowSuggestedFloor` | 选中的两个候选中，至少一个 `displayScore100` 低于 `thresholds.suggestedFloorDisplayScore100`，默认 **65**；仅作为提示，不阻断 |

`RrmV2Top2SelectorOptions` 支持可选覆盖：

- `suggestedFloorDisplayScore100`
- `largeGapThreshold`

但这些参数**只影响 `contextFlags` 和结果中的 `thresholds`**，**不影响谁会被选入 Top2**。

## 仍然会被过滤的内容：仅过滤非法数据

候选只有在 `scoreShadowV2` 满足以下条件时才被视为合法：

- `scoringVersion === "m6.0-relationship-profile-score-v2-shadow"`
- `source` 是 `profile_v2_shadow` 或 `insufficient_profile`
- `displayScore100` 是 **[0, 100]** 范围内的有限数值
- `band` 是以下之一：
  - `high`
  - `good`
  - `medium`
  - `low`
  - `strong_conflict`

以下情况会被从候选池中剔除：

- 缺少 `scoreShadowV2`
- `scoringVersion` 错误
- `source` 错误
- `displayScore100` 不是有限数值
- `displayScore100` 越界
- `band` 未知或非法

当所有输入候选都带有非空的 shadow 对象，但没有任何一个能够通过解析时，返回：

```ts
reason: "invalid_score_shadow_v2";
```

若解析后**合法候选不足两个**（含去重后），则：

```ts
eligible: false;
reason: "not_enough_valid_v2_candidates";
```

## 选择规则（与实现一致）

- 对合法行按 `displayScore100` **降序**排序；分数相同时按 `candidateUserId` **字典序**稳定决胜。
- 同一 `candidateUserId` 出现多行时保留**分数更高**的一条（同分取字典序更小 id）。

## 刻意不修改的范围

本 helper 为纯函数，**不**读写 `MatchResult.finalScore`、**不**改 worker 胜者排序、**不**改 `candidateUserId` / `displayCandidateUserId`、**不**改 RRM resolver；集成留在后续里程碑（如 R3）。
