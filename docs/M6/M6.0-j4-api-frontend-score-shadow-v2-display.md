# M6.0-J4 — API + frontend scoreShadowV2 display

## Scope

- **API**：`GET /matching/result/:userId` 在既有 payload 上增加 **`relationshipProfileScoreV2`**，由 `matchInsights.scoreShadowV2` 经 **`resolveRelationshipProfileScoreV2Shadow`** 校验后映射为 **viewer-safe** 固定字段（不返回问卷原文、不返回 raw userId、不返回 RRM raw score）。
- **Web**：`FinalMatchPage` 在 **「匹配分数构成」** 与 **「技术来源说明」** 之间增加折叠区 **「V2 关系画像适配度（实验）」**，只读展示；**不替换主分数 UI**。

## Explicit non-goals

- **不替换** 主匹配指数 / 主文案对 `finalScore` 的强调展示。
- **不改** `MatchResult.finalScore`、worker winner / ranking、`candidateUserId`、`displayCandidateUserId`、RRM resolver。
- **不改** Prisma schema、无新 migration。
- **不做** low-effort detection。

## API 契约摘要

- **`relationshipProfileScoreV2.source`**：`match_insights_score_shadow_v2` \| `missing` \| `invalid`（表示**本字段**的解析结果，不是 worker 行内的 `profile_v2_shadow` / `insufficient_profile`）。
- 合法时 **`scoringVersion`** 恒为 `m6.0-relationship-profile-score-v2-shadow`，并复制校验通过的数值字段；`missing` / `invalid` 时数值多为 `null`，**`band`** 为 **`missing`**。

## 前端摘要

- **`source === match_insights_score_shadow_v2`**：展示展示分、档位、raw、penalty、cap、冲突计数、有效/跳过维度等。
- **`missing`**：「暂无 V2 shadow」。
- **`invalid`**：「V2 shadow 数据异常，暂不展示」。
- 固定说明：新的 V2 关系画像适配分仅用于 **shadow 对照**，不改变最终匹配对象或 legacy 匹配指数。
