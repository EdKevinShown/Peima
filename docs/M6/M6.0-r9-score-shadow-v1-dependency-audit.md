# M6.0-r9 — scoreShadow v1 Dependency Audit

## 1. 本轮目标

- **R5+ 正式 contract**（readonly display / selector 等）：**只依赖 `matchInsights.scoreShadowV2`**（V2-only 主线）。
- **R6**：`matching-rrm-v2-selector-readonly-display` **未新增**对 **`scoreShadow`（v1）** 的 **required** 依赖；**不因 v1 缺失而 fallback**（缺 **v2** 才 fallback）。
- **R7/R8**：已记录 / 实现 **readonly display** 与 **FinalMatchPage** 对 M6 路径 **不解析** `rrmV2Top2Selector`、**不以客户端 JSON 推断** `scoreShadowV2`/`scoreShadow`。
- **R9（本轮）**：**仅审计** v1 仍出现的读/写/测/文档位置，**分类**并给出 **R10 建议动作**；**不删除 v1**、**不改** parser / resolver / worker / 前端运行时代码、**不改** schema。
- **R10**：才允许 **removal / 迁移测试 / 收紧新主线口径**（见 §9）。

## 5. 必须重点确认（结论）

| 问题 | 结论 |
|------|------|
| **R6 parser / validator 是否要求 `scoreShadow` v1？** | **否**。仅要求 **`scoreShadowV2`** 合规存在；**不读取** `matchInsights.scoreShadow`。 |
| **R6 fallback 是否因 v1 缺失触发？** | **否**（「仅因 v1 缺失」不触发）。**仅 v1、无 v2** 时因 **缺 v2** 不满足条件而 **fallback**，属 **v2 必需**，非 v1 惩罚。 |
| **R8 FinalMatchPage 是否读取 `scoreShadow` v1（raw）？** | **未**在客户端读取 **`result.matchInsights?.scoreShadow`** 用于 M6 展示路径。技术区展示 **`relationshipProfileScore`**，为 **GET 已聚合字段**（后端可由 v1 shadow 或 `reasonSummary` 导出）。 |
| **worker 是否还生成 v1？** | **是**（`batch-match-match-insights` + `buildScoreShadowM60`），与 v2 **并存写入**。 |
| **tests 是否还有「v1 必须存在」断言？** | **未发现**「没有 v1 则失败」的 **required** 断言；存在 **v1 fixture** 用于 **读路径 / worker 形状 / M6 负例**（见 §4.1 **B**）。 |
| **docs 是否仅为历史说明？** | **部分为历史回归事实**（F/G/J3B/R3b 等）；**R5/R6/R7/R8** 为 **现行合同 / 行为说明**（含「v1 不参与 R5 validator」）。 |

## 6. 初步删除策略草案（不执行）

**R10 可考虑删除 / 迁移**

- API 读路径 **`tryReadRelationshipProfileScoreFromScoreShadow`** 若产品确认 **不再需要 v1 影子读数**，可 **migrate** 到仅 **V2** 或仅 **`reasonSummary` fallback**（需评估旧行展示）。
- **新主线测试**中重复的 v1-only 负例，若行为已由更上层契约覆盖，可 **合并简化**（非强制）。

**R10 应保留**

- **历史 docs** 中「某时点 v1/v2 并存 / 匿名回归」陈述。
- **Worker** 在 **未单列「停写 v1」里程碑** 前继续写 v1（避免与旧消费者、审计、对照实验断裂）。
- **R5** 中 **`v1LegacyPresent`** 作为 **非 blocking** 观测的表述。
- **M6 R6/R7** 中「**不要求 v1**」的护栏测试。
