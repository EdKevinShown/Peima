# M6.5-r1 — True Bounded Decision Pilot Design

## 1. 本轮目标

- **M6.0–M6.4** 已完成 **RRM pre-decision chain**（只读展示、**decision shadow**、**batch evaluation**、**bounded dry-run meta**、**true bounded** 门控与写入策略合同；见 **M6.4-r3** 总结）。
- **M6.5** 开始设计 **true bounded decision pilot**：在**不**改变**持久化主结果**的前提下，规划**极小范围**、**可回滚**、**可观测**的验证路径。
- **M6.5-r1（本文）**：**仅** **pilot design** 文档。
- **r1** **不**接线 **`PEIMA_M6_RRM_BOUNDED_DECISION_ENABLED`**；**不**写业务代码；**不**让 **RRM bounded switch** 改**正式** **`candidateUserId` / `finalScore`**。

## 3. Pilot 的定义

**True bounded decision pilot** **指**：在 **feature flag** 默认 **关闭**、**可一键关闭**、**可观测**前提下，用**极小流量或指定沙箱**验证「**在 Top2 闭包 + guardrails 内**，**read-layer** 和/或 **decision meta** 是否可**安全**演进」，且**全程**满足：

| 约束 | 说明 |
|------|------|
| **范围极小** | **非**全量；建议 **allowlist / pool / percent** 与 **M6.4-r1** 灰度草图一致，**具体阈值在 r5 readiness** 锁死。 |
| **默认关闭** | **未**显式开启的环境行为与 **纯 baseline** 一致。 |
| **必须可回滚** | **关 flag** 即回 **baseline** 读路径；**不**依赖 **DB migration rollback**（见 **§10**）。 |
| **必须有 fallback** | **任一**契约破坏、门控失败、解释未就绪 → **baseline**（**M6.4-r1 §10**）。 |
| **不扩大候选池** | **仅** **Top2**；**不**调用额外 **resolver** 改写全局 **ranking**（**M6.4-r1 §3**）。 |
| **必须记录 audit meta** | **结构化** **`matchInsights`** meta（版本、`generatedAt`、`fallbackReason`、`guardrails`、**redacted ref**），与 **M6.4-r2 §7** 对齐。 |
| **不允许无观察全量** | **须**具备 **admin / debug** 观测面（**§9**）与 **rate / 异常** 汇总，**禁止**「未观测直接全开」。 |

---

## 4. Pilot 不做什么

| 禁止 | 说明 |
|------|------|
| **不全量开启** | **无** allowlist / 分阶段则**不开** **read-layer true** 或 **meta 升级**。 |
| **不直接重写所有 `candidateUserId`** | **Strategy C** **不作为** **M6.5-r2** 直接目标（见 **§5**）。 |
| **不跳过 explanation unification** | **§7** 未闭环则**不允许**任何 **write** 类 pilot。 |
| **不跳过 admin / debug observation** | **须**有查询/导出/聚合方案（**不含**随意泄露生产真实 ID 到非受控系统）。 |
| **不用 `scoreShadow` v1** | **不**恢复、**不**依赖 v1 **作为通过门槛**。 |
| **不让前端自己判断 RRM switch** | **禁止** **`FinalMatchPage.jsx`** 或他处解析 **`matchInsights`** 自算 switch；**唯一**权威在 **后端 resolver**（**M6.4-r2 §8**）。 |
| **不绕过 fallback** | **不得**为「好看指标」吞掉 **`guardrail_blocked`** / **`malformed`**。 |

## 5. Pilot strategy candidates

### A. Read-layer override pilot

- **不改** **`MatchResult.candidateUserId`**。
- **Resolver**（**`resolveMatchResultDisplay`**）在 **gate + flag** 满足时，根据 **true meta** / **bounded meta** 输出 **`displayCandidateUserId`**（及 **`displaySourceType` / `decisionSourceType`** 扩展）。
- **风险**：相对 **C** **低**；**必须**处理 **chat / timeline / feedback** 与 **display** 一致性（**§7**、**M6.4-r2 §11**）。

### B. Meta-only `actualSwitch` simulation

- **写** **true 形态 meta**（或 **升级后的 `rrmBoundedDecision`**），但 **`actualSwitch=false`** 或 **`mode`** 仍为观测向（**不改变**用户可见默认路径，**或**仅 **admin** 可读）。
- **继续**积累 **`wouldSwitch` / blocked / fallback** 分布与异常率。
- **最安全**，但**用户侧**「还不是」真 **read-layer pilot**；适合 **r5 前** 或 **与 A 串行**。

### C. True `candidateUserId` write pilot

- **直接**改 **`candidateUserId`**。
- **风险最高**；须 **`finalScore` / explanation / chat / timeline`** 全统一（**M6.4-r2 Strategy C**）。
- **不建议**作为 **M6.5-r2** **直接** implementation 目标。

### 推荐（r1）

- **M6.5-r2** **优先**做 **A** 或 **B** 的 **preflight**（文档 + 最小代码门槛在 **r4** 定义），**不做 C**。
- **若**未来在 **M6.5** 内考虑 **C**，**须** **§6 gates** + **§7** + **§8 API contract** + **§10** **全部**书面 **sign-off** 后再单独立项（**不建议**默认纳入 **M6.5** 范围）。

## 6. Pilot gates

**进入**任何 **true bounded pilot**（**read-layer** 或 **meta 升级**）**前**建议**同时**满足：

| Gate | 要求 |
|------|------|
| **稳定性** | **`unexpectedExceptionRate = 0`**（与 **M6.2-r4 / M6.4-r1** 口径一致）。 |
| **解析** | **`malformedCount` / `parseErrorCount`** 为 **0**（或书面豁免阈值 **=0**）。 |
| **输入** | **`missingInputRate`**、**`invalidSelectorRate`** **可解释**且在书面阈值内。 |
| **Guardrails** | **`blockedRate`** **可解释**；**非**静默吞没。 |
| **样本** | **`sampleSize` 更大且更多样**（相对 **M6.2-r4** 同质警示；须含 **switch / blocked / fallback** 多样场景或**书面采样计划**）。 |
| **观测** | **至少**具备 **debug** 或 **admin** 观测方案（**§9**）。 |
| **解释** | **Explanation unification** **方案明确**（**§7** + **M6.5-r2** 合同）。 |
| **回滚** | **Rollback / kill switch** **方案明确**且演练 **one-click disable**（**§10**）。 |

## 7. Required consistency before pilot

在 **pilot** 扩大前（尤其任何接近 **`candidateUserId` write** 的步骤），**必须**书面统一以下「**owner**」指向**同一 resolved candidate** 或**显式双轨**（用户可见）：

| 维度 | 须定义 |
|------|--------|
| **FinalMatchPage 展示对象** | 与 **`displayCandidateUserId`** / **`resolvedCandidateUserId`** 合同一致。 |
| **Chat target** | 与展示或持久化**二选一并全链一致**。 |
| **Timeline target** | 同上。 |
| **Feedback target** | 归因对象与匹配解释一致。 |
| **Explanation target** | **`matchExplanation` / `matchReview` / `reasonSummary`** 解释谁。 |
| **Score owner** | **`finalScore` / `relationshipProfileScore`** 语义归属（**M6.4-r2 §10**）。 |
| **`primaryConclusion` owner** | 与展示候选一致。 |
| **`matchReview` owner** | 与展示候选一致。 |
| **Fallback owner** | **谁**展示 fallback 文案、**谁**承担「稳定基线」语义。 |

**硬规则：** 若上述**未**统一，**不允许** **`candidateUserId` write pilot**；**read-layer pilot** 也须在 **§7** 合同下**显式**处理 **chat/timeline**，否则**不允许上线**该 flag 组合。

## 8. API contract needs

以下字段为 **GET /matching/result** 及同源只读 API **未来可能**需要扩展或细化的**投影需求**（**r1 不实现**；命名可与 **OpenAPI / ADR** 再对齐）：

| 字段 | 用途（设计层） |
|------|----------------|
| **`baselineCandidateUserId`** | **持久化主结果**（通常等于 **`matchResult.candidateUserId`**）；供对账与 **fallback** 展示。 |
| **`displayCandidateUserId`** | **已存在**；**read-layer pilot** 可能指向 **bounded target**。 |
| **`resolvedCandidateUserId`** | **单一「解析后」用户 ID**（**产品动作**默认跟随对象）；**可与 display 或 baseline 对齐**，**须**文档定义。 |
| **`decisionCandidateUserId`** | **RRM bounded 在 meta 中选中的对象**（**审计向**）；**可与 selected 对齐**。 |
| **`decisionSourceType`** | **bounded / baseline / fallback / readonly_override** 等枚举扩展。 |
| **`displaySourceType`** | **已存在**（**`MatchResultDisplaySourceType`**）；**可能**新增 **`rrm_true_bounded_*`** 类取值。 |
| **`fallbackUsed`** | **已部分使用**；**须**与 **resolver** 分支一致。 |
| **`fallbackReason`** | **闭集**字符串；**用户可见**与 **debug** 分级（**M6.3-r2**）。 |
| **`scoreOwnerCandidateUserId`** | **分数**解释的归属候选（**M6.4-r2 §10** 未定时默认 **baseline**）。 |
| **`explanationOwnerCandidateUserId`** | **AI 解释**绑定候选。 |
| **`chatTargetUserId`** | **发起会话**对象（**须**与 **§7** 一致）。 |
| **`timelineTargetUserId`** | **时间线**对象。 |
| **`feedbackTargetUserId`** | **反馈**归因对象。 |

**原则：** **前端不消费** raw **`matchInsights`** 推导上述 ID；**以后端投影为准**。

## 9. Admin / debug needs

**观测面**（**不含**真实 **userId** 明文导出到非受控日志）**至少**应能区分：

| 维度 | 说明 |
|------|------|
| **Flags** | **`PEIMA_M6_RRM_BOUNDED_DECISION_DRY_RUN_ENABLED`** / **未来 true flag** / **read-layer sub-flag** 是否开启（环境维度）。 |
| **Mode** | **`dry_run` / `read_layer_override` / `enabled` / `fallback`**（与 **M6.4-r2 §7** 对齐）。 |
| **`wouldSwitch` / `actualSwitch`** | **Dry** vs **true** 语义分离。 |
| **`fallbackReason`** | 分布与 Top **reason codes**。 |
| **`guardrails` / `blockReasons`** | **blocked** 是否命中、原因枚举聚合。 |
| **`sourceVersions`** | **shadow / bounded / selector / scoreShadowV2** 版本一致性。 |
| **Baseline vs selected** | **Redacted ref** 或 **hash**；**禁止**随意打印全量 ID。 |
| **Exception / malformed** | 计数与样本标签（**匿名**）。 |
| **Rate summary** | **coverage**、**switch rate**、**unexpected** 与 **M6.2** 聚合器口径可对齐。 |

## 10. Rollback design

| 要求 | 说明 |
|------|------|
| **Flag off → baseline** | **读路径**与**写路径（若有）**均回到 **`match_result_original`** 或既有优先级链。 |
| **Resolver 不 500** | **Parse 失败**、**版本不匹配** → **fallback** slice，**不**抛毁 **GET**。 |
| **历史 meta** | **保留**行上 **JSON** **不**影响 **flag off** 后行为（**读路径忽略 true 语义**）。 |
| **无 migration rollback** | **kill switch** **仅**配置层即可恢复安全态。 |
| **未来 `candidateUserId` write** | **必须** **`baselineRef`**（**redacted**）可追溯；**半状态** **禁止**落库。 |
