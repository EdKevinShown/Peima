> **范围**：整理 **M6.0 评分体系** 当前状态、已完成能力、未完成边界、**上线策略**与**下一步路线**。**本轮只写文档**；**不写** Web / API / worker / schema；**不**做 low-effort detection；**本文不写** 真实 **`userId` / `token` / `DATABASE_URL`**。  
> **依据**：**`docs/M6/M6.0-j1c-matching-pipeline-v2-responsibility-alignment.md`**、**`M6.0-j1b-relationship-profile-score-v2-formula-design.md`**、**`M6.0-g4-v2-five-state-regression.md`**、**`M6.0-h1-final-match-primary-score-switch-plan.md`**、**`M6.0-h2-final-match-v2-primary-score-feature-flag.md`**、**`M6.0-g5-final-match-v2-primary-score-manual-run-record.md`**、**`M6.0-j5-v2-strong-conflict-regression.md`**；仓库总述见 **`README.md`**。

## 1. 一句话结论

**M6.0 已完成 Scoring V2 的「shadow → DB（`matchInsights.scoreShadowV2`）→ API（`relationshipProfileScoreV2`）→ 前端 feature flag 主视觉」闭环**：**G4** 五态证明 **V2 `displayScore100`** 相对 **legacy `finalScore` v1** 与 **RPS v1** 更能拉开；**J5** 合成回归证明 **强冲突 / 红线 / cap** 可触发，且 **0–40 / `strong_conflict`** 在极端样本下可达。**但** **`MatchResult.finalScore`** 与 **worker 胜者 / ranking** **尚未**切到 V2；**RRM** **也尚未**绑定「仅在 **V2 Top2** 上工作」的产品形态。**当前建议**：**先用 `VITE_FINAL_MATCH_USE_V2_PRIMARY_SCORE` 在 FinalMatchPage 主视觉展示 V2**（**staging / 灰度**可控），**legacy `finalScore` v1** 保留为技术区与审计对照；**winner 行与写库主分** 的切换 **单列后续里程碑**，避免展示与排序真源长期漂移却无文档收口。

---

## 2. 当前新匹配链路（目标态 vs M6.0 落地）

**目标态流程（与 J1C 对齐）**：

```text
硬筛（资格）
  → 长相 / 外在吸引力 / 外在偏好 → 生成「6 人」active 预览池
  → relationshipProfileScore V2：对池内 6 人计算基础关系画像适配（displayScore100 / band 等）
  → V2 Top2 / 高潜候选子集（产品阈值另文）
  → RRM：在子集上做节奏 / 风险 / 展示位二次判断 → displayCandidateUserId / displaySourceType
  → FinalMatchPage：主视觉展示 V2 主分 + RRM 展示来源说明；legacy 与分项进折叠区
```

**M6.0 本轮已落地（与上链路的对应关系）**：

- **30 canonical（Q2）**、**G1-R 20 维** 为 V2 输入真源之一。  
- **V2 纯 helper（J2）**、**worker 写入 `scoreShadowV2`（J3/J3B）**、**API 返回 `relationshipProfileScoreV2`（J4）**、**FinalMatchPage 技术区 + 主分 feature flag（H1/H2）** 已交付。  
- **尚未**按 J1C 全量重构：**preview pool / 6 人池生成** 仍走既有实现；**worker winner / `candidateUserId`** 仍由 **legacy `computeFinalScoreV1`** 等路径决定；**RRM** 仍按 **M5/M5.6** 既有闸门作用于读模型，**未**保证「**仅**在 **V2 Top2** 上生效」的专用绑定。

## 4. 回归结论摘要

### 4.1 G4（真实问卷五态）

- **legacy `finalScore` v1`**：极差约 **1.7 分**（百分制观感）。  
- **RPS v1（×100）**：极差约 **8.8 分**。  
- **V2 `displayScore100`**：极差约 **23 分**（**87 − 64**）。  
- **Normal**：**87**，**`band` = good**。  
- **All-C**：**64**，**`band` = medium**。  
- **本轮 G4 未触发** cap / strongConflict / redFlag（与 **J5** 互补）。

### 4.2 J5（合成 helper）

- **`displayScore100` 可进入 0–40**，**`band` 可为 `strong_conflict`**（全轴反向等极端构造）。  
- **`strongConflictCount` / `redFlagConflictCount` / `capApplied`** 均可触发；**多 cap 并存时取最严**（最低档 **0.68**）。  
- **`capApplied = 0.68` 不等于自动 &lt;40`**：当 **raw** 仍高时，**display 约 57**（分段映射），见 **`M6.0-j5-v2-strong-conflict-regression.md`** §7。

## 6. 推荐上线策略

### 阶段 A：前端主视觉 feature flag

- **dev / staging**：可开启 **`VITE_FINAL_MATCH_USE_V2_PRIMARY_SCORE=1`** 做产品与运营体感验证。  
- **production**：**默认关闭**或 **灰度**（按部署渠道 / 用户 cohort 配置），避免未沟通的大幅主视觉跳变。  
- **legacy `finalScore` v1`**：保留 **技术区**、**scoreBreakdown**、与 **V2 / RRM** 对照说明（与 **H1/H2** 一致）。

### 阶段 B：补验收

- **G5 v1.2+**：**missing fallback**、**invalid fallback**、**技术区全量截图** 手测勾选。  
- **强冲突**：可选 **截图 / mock** 归档（不写真实 id），与 **J5** 结论交叉验证。

### 阶段 C：后续算法与真源切换（单独里程碑）

- **worker ranking v2 shadow**（或等价）：排序与 shadow 真源对齐策略 **单独立项**。  
- **RRM 仅在 V2 Top2 / 高潜** 上生效：与 **J1C §8** 门槛一致，**依赖** 池与 V2 子集产品定义。  
- **low-effort detection（I1/I2）**：质量闸门后再扩大灰度。  
- **最后阶段**再讨论：**是否替换 / 并行正式字段** 替代 **`MatchResult.finalScore`**（涉及报表、历史兼容、迁移）。

## 7. 是否需要 J6 调参

**当前不建议立即启动 J6。**

**原因简述**：

- **J5** 已证明 **0–40** 与 **`strong_conflict`** 在极端合成下 **可达**。  
- **G4** 已证明 **V2** 相对 **v1** 在真实五态上 **区分度显著更好**。  
- **`capApplied = 0.68` 映射到约 57** 是 **J2 分段 display 设计**的结果，**不是实现 bug**；若强行在 J5 改公式会混淆「回归记录」与「产品调参」。

**若产品明确要求**：「**红线（redFlag）一旦触发，用户可见分必须 &lt;40**」——则 **另开 M6.0-J6**：调整 **penalty 上限、cap 档位或 `cappedRaw → display` 映射**，并 **重跑 G4/J5** 类回归。

## 8. 风险

| 风险 | 说明 |
|------|------|
| **旧 `MatchResult` 无 `scoreShadowV2`** | API / 前端须 **fallback** 至 legacy；**G5 missing** 待补全验证 |
| **主视觉分数体感跳变** | 例如 **~89 → ~76**；需 **产品沟通** + **灰度** |
| **production flag 误开** | 建议在 **部署清单** 中固定 **默认关** 与 **变更审批** |
| **low-effort 未做** | 低质量问卷仍可能进入池与 V2；**扩大面用户前**建议补 **I 线** |
| **RRM 未绑定 V2 Top2** | 展示主分与 **RRM 输入子集** 若长期不一致，易产生 **「主视觉说适配、排序真源仍 v1」** 的认知与运维成本 |
| **worker winner 仍为 legacy v1** | **主视觉（flag on）** 与 **实际写入胜者** 可能 **短期不一致**；须在 **阶段 C** 收口或文档上 **显式标注** 直至切换完成 |

1. **G5 v1.2+**：补 **missing fallback**、**invalid fallback**、**技术区全量手测**（见 **`M6.0-g5-final-match-v2-primary-score-manual-run-record.md`**）。

3. **I1 / I2**：**low-effort detection** 设计与实现（与问卷 / 池准入衔接）。  
4. **RRM-V2（工作名）**：**RRM 仅在 V2 Top2 / 高潜候选** 子集上生效（产品阈值 + 工程闸门）。  
5. **Worker ranking v2 shadow**：与 **finalScore** 真源策略 **一起评审**，避免双轨长期分裂。  
6. **再讨论**是否 **替换或新增正式字段** 承载 **`MatchResult.finalScore`** 语义（历史报表与下游消费需单列评估）。
