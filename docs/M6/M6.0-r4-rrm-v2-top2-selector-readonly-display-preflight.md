## 3. Display 接线边界（硬性）

后续 **readonly display** 层（未来实现时）对 **`rrmV2Top2Selector`** 的处理须遵守：

- **只读**：**selector 输出** 只能作为 **readonly display candidate source** 的**输入之一**，**不能**替代或改写 **主匹配决策**。  
- **禁止写回**：**不得**写回 **`MatchResult.finalScore`**；**不得**改 **`MatchResult.candidateUserId`**。  
- **禁止影响 worker**：**不得**改 **worker ranking / batch-match** 写库语义。  
- **禁止触发 RRM resolver（当前 M5 路径）**：若未来要「V2 selector 驱动展示」，**默认**应与「调用现有 RRM 模型 / 写 `MatchResultRrmTop2DisplayMeta`」**解耦**，除非后续里程碑**显式**合并设计并评审风险。  
- **禁止语义错误**：**不得**把 **`selectedTop2`** 当作新的 **「最终匹配结果」**；**`candidateUserId`** 仍为 **legacy 真源**（worker `computeFinalScoreV1` 胜者）。  
- **受控试验路径**：**`selectedTop2`** 仅用于 **「在两人子集内解释 / 选择展示对象」** 的受控读路径；任何 **持久化 `displayCandidateUserId`** 若引入，须由 **单独 meta 合同（R5）** 定义，**不在 R4 实现**。

## 4. 建议的 `displaySourceType` 语义（关系说明）

以下描述 **读模型** 语义层次，**不**改变现有枚举名 unless **R5+** 合同扩展。

| 来源 / 类型 | 角色 | 说明 |
|-------------|------|------|
| **`match_result_original`** | **Baseline fallback** | **`displayCandidateUserId = candidateUserId`**（与 **R1** 一致）；无 meta、无 override 时的 **真源对齐展示**。 |
| **`pairwise_final`**（及既有 **pairwise finalize** 冻结 meta 路径） | **现有增强展示路径** | **R1**：在 RRM 未命中等条件下，可尝试 **pairwise frozen meta**；**不假设** pairwise **一定**改写最终业务结果——它影响的是 **GET 层展示解析**，**不**回写 **`MatchResult` 主行 `candidateUserId`**。命名以代码 **`matching-result-display.ts`** 为准（如 **`pairwise_final`**）。 |
| **`rrm_top2_bounded_selector`**（**现有 M5.3**） | **RRM meta 驱动 bounded display** | 来源于 **`MatchResultRrmTop2DisplayMeta`** 等 **M5** 受控链路；**bounded** = 在 **baseline / winner 二元组** 等 **已冻结** 范围内切换展示（见 **R1**）。**与 R3 `rrmV2Top2Selector` 不是同一 JSON**（当前未接线）。 |
| **（未来建议名，仅草案 · R5+ 评审）** `rrm_top2_v2_selector_readonly` 或复用扩展 **meta `version`** | **只读 selector display path** | **若**未来接线：输入来自 **`matchInsights.rrmV2Top2Selector.selectedTop2` + `top1`/`top2`**；**bounded** = **仅在** 该 **Top2 子集**（及已存在的 **MatchResult / scoreShadow** 事实）内选择展示解释或 **解析出的展示用 id**，**不扩大**候选池；**readonly** = **只影响 GET 聚合展示**，**不**触发 worker 重算、**不**改 **`finalScore`**、**不**改 **`candidateUserId`**。**是否在类型层新增枚举** 留待 **R5 contract**，**R4 不决定最终实现名**。 |

**R4 不决定是否新增 `displaySourceType`**；最终是否复用 **`rrm_top2_bounded_selector`** 或新增 **`rrm_top2_v2_selector_readonly`**，留给 **R5 contract** 决定。

## 5. 推荐读取流程草案（未来实现时建议遵循）

**无具体代码**；顺序表达 **resolver / 聚合层** 应考虑的闸门。

**FinalMatchPage** 不应直接解析 **`matchInsights.rrmV2Top2Selector`**；它只消费后端 **display resolver** 已整理好的 **`displayCandidateUserId` / `displaySourceType` / explanation** 等 payload（与 **R1** 既有分层一致）。

1. 读取 **`MatchResult`**（含 **`candidateUserId`**、**`finalScore`**、**`matchInsights`**）。  
2. **Baseline**：始终保留 **`candidateUserId`** 作为 **业务真源** 与 **fallback** 锚点。  
3. **尝试读取** **`matchInsights.rrmV2Top2Selector`**（或未来 **readonly meta** 中的镜像字段，**R5** 定义）。  
4. **Parse**：JSON 形状是否符合共享类型 / **version** 是否为 **`m6.0-rrm-v2-top2-selector-shadow-v1`**（见 **`packages/shared/types/match-p1.ts`**）。  
5. **Eligibility**：**`eligible === true`** 且 **`reason === 'ok'`**（产品 always-on 展示仲裁前提；若未来允许弱理由展示，须另开合同，**不在 R4 预设**）。  
6. **`selectedTop2.length`**：至少 **1** 才可能有展示意义；**与 top1/top2 对齐** 时以 **`top1CandidateUserId` / `top2CandidateUserId`** 与 **`selectedTop2`** 一致性校验为准。  
7. **存在性**：**`selectedTop2` 内 `candidateUserId`** 对应 **User / profile** 仍存在（避免幽灵展示）。  
8. **`contextFlags`（可选策略层）**：**R2B** 不阻断 selector，但 **display 层** 可定义「高风险则 **fallback**、仅展示解释不切换人」等策略——**须 feature flag 控制**，**默认保守**。  
9. **若**上述均通过 **且** feature flag 开启：**解析得到的展示用候选人** 必须 **∈ {`top1CandidateUserId`, `top2CandidateUserId`}**（即 **`selectedTop2` 子集**）。**当前 selector JSON 并无 `newDisplayCandidateUserId` 字段**；若未来与 **M5 meta** 对齐出现该字段，须 **R5** 合同定义，**不得**指向 Top2 外用户。  
10. **`displaySourceType`**：若采用新枚举则 **R5** 命名；若短期复用既有值，须在 **R5** 明确 **与 M5 `rrm_top2_bounded_selector` 的区分**，避免观测混淆。  
11. **任一失败**：**fallback** — 优先 **既有 pairwise 路径**（若启用且校验通过），否则 **`match_result_original`**。  
12. **全程**：**不写** **`MatchResult`** 主决策字段（含 **`finalScore` / `candidateUserId`**）；展示差异仅体现在 **GET 响应字段** 或 **未来只读 meta 表**（**R5**）。

## 6. Fallback 设计

**Fallback 是展示层 fallback**，**不是**重新匹配；**不改变**数据库中的 **主结果行**（除非未来有 **显式、单独审计过的 meta 写路径**，**不在 R4 范围**）。

| 场景 | 建议行为 |
|------|----------|
| **`rrmV2Top2Selector` meta / 键不存在** | fallback |
| **Payload parse 失败 / `version` 不匹配** | fallback |
| **`eligible !== true`** | fallback |
| **`reason !== 'ok'`**（若产品坚持 strict gate） | fallback |
| **`selectedTop2` 为空或长度与 top1/top2 不一致** | fallback |
| **候选用户不存在 / profile 缺失** | fallback |
| **`contextFlags` 出现高风险状态**（若策略开启风险拦截） | fallback |
| **Feature flag 未开启** | **直接**走旧路径（与「未开启 selector display」不可区分） |
| **任何未捕获异常** | fallback（并记录服务端日志，**不**写用户标识到客户端错误串） |

**Fallback 优先级（建议）**

1. **既有 pairwise display 路径**（若项目当前 **env + meta** 已启用且校验通过）。  
2. **`match_result_original`**（**`displayCandidateUserId = candidateUserId`**，**`meta` 为 null** 等与 **R1** 一致的行为）。

## 7. 字段允许 / 禁止清单（display 层）

| 类别 | 字段 / 信息 | 允许只读读取 | 禁止 display 层改写或伪造 |
|------|-------------|--------------|---------------------------|
| **标识** | **`matchResult` 存在性**、匿名 **fingerprint**（若已有） | ✓（用于分支与日志 key 策略） | ✗ 伪造主键 |
| **Selector** | **`selectedTop2.length`**、**`selectedTop2` 内摘要**（id 脱敏展示规则由产品定） | ✓ | ✗ 写入 **Top2 外** 的「第三候选」 |
| **Selector** | **`eligible` / `reason` / `contextFlags` / `thresholds` / `top2Gap` / `version`** | ✓ | ✗ 改写 **`matchInsights`** 内已持久化 JSON（除非未来 **独立 admin 工具链**，**不在 R4**） |
| **Shadow** | **`scoreShadow` / `scoreShadowV2` 存在性与合规摘要** | ✓ | ✗ 改写 shadow **数值真源**（worker 职责） |
| **决策** | **`finalScore` / `candidateUserId` / worker winner / ranking** | ✓（只读展示或解释） | ✗ **任何**写回或「展示层重算覆盖」 |
| **展示** | **`displayCandidateUserId`（GET 聚合输出）** | ✓（解析结果） | ✗ **持久化**为主字段 **除非** **R5** 定义单独 **meta** 表/列且通过审计 |
| **RRM** | **现有 M5 RRM resolver 输出** | ✓（按现有路径） | ✗ 冒充 **V2 selector** 路径 **不写清 `displaySourceType`** |
| **RRM** | **真实 RRM 模型 I/O** | N/A（R4 不调用） | ✗ 在 **readonly selector** 路径中 **隐式触发** |

## 8. Feature flag 建议（仅命名与语义，不改代码）

| 建议项 | 说明 |
|--------|------|
| **主推荐 flag 名** | **`PEIMA_M6_RRM_V2_SELECTOR_DISPLAY_ENABLED`** |
| **与 M5 的关系** | **不建议**直接复用 **M5** 的 **`PEIMA_M5_RRM_TOP2_*`** 控制本路径，避免 **M5 RRM Top2 display** 与 **M6 V2 selector display** 观测混淆。仓库已有 **M5** 类 flag（见 **R1** / **`.env.example`**）；**M6** flag 应 **只控制「是否尝试读取 `matchInsights.rrmV2Top2Selector` 参与 GET 展示解析」**，**不**改变 **M5** 开关语义（**具体并列/互斥矩阵留 R5**）。 |
| **默认** | **关闭** → 行为与 **R3 前**一致（**不**读 selector 做展示）。 |
| **开启时** | 仅 **多一条**「校验通过则采用 readonly 展示候选 / 解释」的路径；**任一校验失败** → **fallback**。 |
| **不变量** | Flag **只影响读取与聚合展示**；**不影响** worker、**`finalScore`**、**`candidateUserId`**、**RRM 模型调用**（除非未来里程碑 **显式**合并）。 |
