# M6.8-r1 — True Bounded Decision Read-layer Activation Contract

## 1. 本轮目标

- M6.8 进入 true bounded decision behind flag 阶段。
- r1 仅定义 read-layer activation contract。
- r1 不写代码。
- 第一阶段仅影响 `GET /matching/result/:userId` 的 resolved projection。
- 不直接写 `MatchResult.candidateUserId`。

## 2. 当前基线

- M6.3 已有 `rrmBoundedDecision` dry-run meta（`matchInsights`）。
- M6.5 已有 `resolvedCandidateUserId` / target fields（`chatTargetUserId` / `timelineTargetUserId` / `feedbackTargetUserId`）。
- M6.6 已统一 Chat / Timeline / Feedback / Copilot target 消费路径。
- M6.7 已有 observation script 与 admin summary API（匿名聚合）。
- 当前 `PEIMA_M6_RRM_BOUNDED_DECISION_ENABLED` 未接线。
- `candidateUserId` / `finalScore` / worker winner 仍保持 baseline 逻辑。

## 3. Activation definition

True bounded decision read-layer activation 仅在以下条件**全部成立**时允许：

- `PEIMA_M6_RRM_BOUNDED_DECISION_ENABLED === "1"`。
- `matchInsights.rrmBoundedDecision` 存在。
- `rrmBoundedDecision.mode === "dry_run"`（或后续 true-compatible mode）。
- `rrmBoundedDecision.decision` 表示 `would_switch_to_rrm`。
- `rrmBoundedDecision.wouldSwitch === true`。
- bounded target 存在且通过 resolver 可读。
- `guardrails.blocked !== true`。
- `fallbackReason` 为空。
- `inputPresence` 满足 `scoreShadowV2` / `rrmDecisionShadow` / `rrmV2Top2Selector` / `selectedTop2`。
- target 对应 `User` 与 `UserProfile` 存在。
- 无 blocking consistency issue。

仅当以上 gate 全通过，API read-layer 才允许：

- `resolvedCandidateUserId = bounded target`
- `resolvedSourceType = "rrm_bounded_decision_read_layer"`
- `chatTargetUserId` / `timelineTargetUserId` / `feedbackTargetUserId = bounded target`

## 4. Explicit non-goals

本阶段不做：

- 不改 `MatchResult.candidateUserId`
- 不改 `finalScore`
- 不重算 score
- 不改 worker winner
- 不改 batch-match 主决策
- 不写新表
- 不改 schema
- 不让 worker 直接产出 true winner
- 不改 Copilot prompt
- 不改 FinalMatchPage 结构
- 不做 admin UI
- 不做 user-level drilldown

## 5. Feature flag contract

主开关：

- `PEIMA_M6_RRM_BOUNDED_DECISION_ENABLED`

规则：

- 默认关闭。
- 仅字面量 `"1"` 开启。
- `"true"` / `"TRUE"` / `"yes"` / 未设置均关闭。
- flag off 时必须完全走 M6.5/M6.6 既有 resolved projection。
- flag on 但任一 gate 失败，fallback baseline/display resolved。

可选未来 flag（本轮仅记录，不实现）：

- `PEIMA_M6_RRM_BOUNDED_DECISION_READ_LAYER_ONLY`

## 6. Input contract

允许读取：

- `MatchResult.candidateUserId`
- `matchInsights.scoreShadowV2`
- `matchInsights.rrmV2Top2Selector`
- `matchInsights.rrmDecisionShadow`
- `matchInsights.rrmBoundedDecision`
- existing display resolver result
- `User` / `UserProfile` existence check

禁止读取或依赖：

- `scoreShadow` v1 作为 pass/fail gate
- raw selectedTop2 ID 向前端输出
- LLM 重新判断
- 全池重新排序
- worker ranking 重算
- `candidateUserId` 写回

## 7. Output contract

当 RRM bounded read-layer activation 成功时，`GET /matching/result` 返回中新增或覆盖：

- `decisionCandidateUserId = bounded target`
- `decisionSourceType = "rrm_bounded_decision_read_layer"`
- `resolvedCandidateUserId = bounded target`
- `resolvedSourceType = "rrm_bounded_decision_read_layer"`
- `chatTargetUserId = bounded target`
- `timelineTargetUserId = bounded target`
- `feedbackTargetUserId = bounded target`
- `fallbackUsed = false`
- `fallbackReason = null`
- `consistencyWarnings` 可追加 info：`rrm_bounded_read_layer_active`

同时必须保持：

- `candidateUserId` 仍为 baseline
- `finalScore` 仍为 baseline score
- `scoreOwnerCandidateUserId` 仍为 baseline（除非后续 M6.8/M6.9 单独设计）
- `explanationOwnerCandidateUserId` 仍按 existing projection
- 当 resolved 与 score owner 不一致时必须保留 `score_owner_mismatch` warning

## 8. Fallback conditions

以下任一满足都必须 fallback，不得激活 read-layer bounded switch：

- flag off
- `rrmBoundedDecision` 缺失
- malformed `rrmBoundedDecision`
- mode 不兼容
- decision 不是 `would_switch_to_rrm`
- `wouldSwitch !== true`
- target 缺失
- target `User` 不存在
- target `UserProfile` 不存在
- `guardrails.blocked = true`
- `fallbackReason` 非空
- inputPresence 不满足 required
- `scoreShadowV2` 缺失
- `rrmDecisionShadow` 缺失
- `rrmV2Top2Selector` 缺失
- `selectedTop2` 缺失
- exception thrown
- target 与 baseline 相同
- target 不在 Top2 闭包内

fallback 行为：

- 不 throw 到用户页
- resolved 回到既有 M6.5 projection
- `fallbackUsed = true`
- `fallbackReason` 使用闭集 reason
- `consistencyWarnings` 追加 info/warning

## 9. Fallback reason closed set

闭集建议：

- `flag_off`
- `bounded_decision_missing`
- `bounded_decision_malformed`
- `incompatible_mode`
- `decision_not_switch`
- `would_switch_false`
- `bounded_target_missing`
- `bounded_target_user_missing`
- `bounded_target_profile_missing`
- `guardrail_blocked`
- `bounded_fallback_reason_present`
- `missing_score_shadow_v2`
- `missing_rrm_decision_shadow`
- `missing_rrm_v2_selector`
- `missing_selected_top2`
- `target_same_as_baseline`
- `target_outside_top2`
- `unexpected_exception`

## 10. Score / explanation owner rule

M6.8 read-layer activation 不重算 `finalScore`。因此当 resolved 切到 bounded target、score owner 仍是 baseline 时：

- 必须保留 `score_owner_mismatch` warning。
- FinalMatchPage 继续沿用 M6.6 warning surface。
- 禁止把 baseline `finalScore` 解释成 bounded target 专属分数。

explanation owner 同理：

- 不新增 explanation 系统。
- 不允许静默混用对象。
- score/explanation 重算策略放到后续（M6.9 或 M7）设计。

## 11. Observation requirements

M6.8 activation 必须持续可观测：

- admin summary API 可继续观测 `boundedDecision` 分布。
- `fallbackReason` 可聚合。
- read-layer activation 成功/失败均应通过 API technical fields 可见。
- 不输出真实 ID。
- 不输出 raw `matchInsights`。

若需要补充 runtime-only notes/warnings，应写在 resolved projection 可控字段中，不开放 raw payload。
