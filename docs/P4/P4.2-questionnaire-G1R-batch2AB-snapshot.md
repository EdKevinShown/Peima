# G1-R 问卷 Batch 2-A / 2-B 收口快照

> 本文档仅记录截至合入时仓库已实现的问卷与画像主链状态；可宣称 **`q01`–`q12` 与 `q25` 已 `canonical`** 及 **v2 scorer 回归（17 用例）与闸门对齐**；**不**宣称 **30 题全 `canonical` / 全量正式生产级真源与计分覆盖已结案**。

## 核心口径（六条，与仓库实现一致、不夸大完成度）

1. 当前问卷已推进到 **30 题**结构（`q01`–`q30`）。
2. 已引入 **`sourceTier`** 闸门（`canonical` / `draft` / `placeholder`）。
3. **`q01`–`q12` 与 `q25` 已为 `canonical`**；**`q13`–`q30` 仍未全部 `canonical`**（该段除 **`q25`** 外当前多为 **`draft`**；不把 `draft` 写成 `canonical`）。
4. 已打通 **v2 scorer**（`scoreQuestionnaireG1r`）与 **v2 profile 写入**（**`user_profile`**：20 个 G1-R 轴 + **`confidence`**）。
5. 前端已跟随后端**动态题数**（`questions.length`）。
6. **不能**宣称「**30 题全 `canonical` / 全量正式生产计分与真源已结案**」。

  - **`apps/api/test/questionnaire.scorer.regression.e2e-spec.ts`**：**17** 条用例与当前 **`totalCanonical`** / **`confidence`** 语义一致并已通过

- **Batch 2-B（前端）**

  - `QuestionnairePage.jsx`：完成条件与提交门槛跟随 **`questions.length`**，不再写死 12

- **`questionnaire.controller.ts`**
  - 审读结论：**零改动通过**

  - **不会**在 controller 层把 `tags` / `sourceTier` 拼进题面响应

### 尚未完成（与「全量正式生产」相关的差距）

- **`q13`–`q30` 仍未全部 `canonical`**（除 **`q25`** 外该段其余题当前多为 **`draft`**）→ **不能**宣称「**30 题**全 `canonical` / 全量正式生产真源与计分已结案」

- **这不等于**「30 题全量正式生产画像已跑满」或「全量正式生产计分已完成」
- **worker / matching** 是否全面消费 **20 维 G1-R**，**不在本快照问卷线范围内**（不展开 chat / matching 实现）
- 全仓 **e2e** 若仍有与 **30 题 / v2 profile** 不一致的假设，**另任务跟进**（**不在本快照交付范围内**）

## 四、controller 为何零改动通过

- **`GET .../questions`** 的题面形态由 **`getPublicQuestions()`** 决定，controller **仅转发** `getQuestionBank()`，无二次映射
- **`POST .../submit`** 仍使用既有 **`SubmitQuestionnaireDto`** + **`JwtAuthGuard`** + `userId` 一致性校验，无题数或旧维度硬编码
- 因此 **Batch 2-B 对 controller 无强制修改点**
