# P4.1-S1 验收基线文档（初稿）

> 建议文件名：`docs/P4/P4.1-S1-acceptance-baseline.md`

## 1. 文档目的与目标

本文件用于定义 P4.1-S1（跨页主链路验收固化）的最小验收基线。  
目标是在**不新增功能、不改后端契约、不改数据库/worker、不触碰真实 AI 链路**的前提下，将当前已完成的 P4 五个切片能力（重点为 Chat ↔ Copilot ↔ Timeline）固化为：

- 可重复执行的验收路径  
- 可对外说明的交付口径  
- 可持续复用的最小回归标准

---

## 2. 验收范围（In Scope）

本轮仅覆盖以下页面、共享组件与文档口径一致性：

### 2.1 页面与组件
- `ChatPage`
- `CopilotPage`
- `RelationshipTimelinePage`
- `ConversationContextBar`

### 2.2 文档
- `docs/P4/P4-current-slice-status.md`
- `README.md`
- （可选复核）`docs/P4/P4-ux-checklist.md`

### 2.3 能力范围（仅主链路）
- Chat 可跳转 Copilot/Timeline，并保持 `conversationId`（`userId` 有则透传）  
- Copilot 与 Timeline 可回到 Chat，参数不丢失  
- 三页统一展示顶部上下文栏（页标识、会话参数、三向入口、freshness 提示）  
- freshness 来源语义一致：  
  - Chat：`initial` / `manual` / `chat_action`  
  - Copilot：`initial` / `manual`  
  - Timeline：`initial` / `manual`（含“加载更多消息”）  
- 缺少 `conversationId` 时，三页给出一致风格引导；错误提示语义一致、可理解

---

## 3. 不在范围内（Out of Scope）

- 不新增业务能力（提醒、约会推荐、复杂 AI 模拟等）  
- 不改 API、后端模块、数据库 schema、worker 流程  
- 不将未来规划写成已完成  
- 不进入 P6 真实 AI 生产链开发  
- 不做本轮目标之外的大规模重构或样式重做

---

## 4. 验收前提（Preconditions）

执行本验收前需满足：

1. 可访问当前用户端页面：`/chat`、`/copilot`、`/chat/timeline`  
2. 测试会话具备有效 `conversationId`（建议同时具备 `userId` 用于回跳）  
3. Chat 页面可正常发送消息，且具备基础可读会话内容  
4. 三页可正常发起各自已有请求（不要求新增接口）  
5. 验收口径以当前仓库文档为准（README + `docs/P4/P4-current-slice-status.md`）

---

## 5. 主链路验收步骤（按执行顺序）

### 步骤 A：Chat 基线确认
1. 打开 Chat（携带有效 `conversationId`）  
2. 确认会话主体可加载  
3. 确认顶部上下文栏可见，且包含：页标识、`conversationId`、`userId`（如有）、三向入口、freshness 提示

**通过标准**：页面主体正常、上下文栏信息完整、无阻断错误

---

### 步骤 B：Chat → Copilot
1. 从 Chat 跳转到 Copilot  
2. 检查 URL/状态中 `conversationId` 是否保留（`userId` 有则应透传）  
3. 检查 Copilot 顶部上下文栏完整性  
4. 手动刷新洞察，确认 freshness 来源更新为 `manual`

**通过标准**：跳转成功、参数不丢失、刷新来源语义正确

---

### 步骤 C：Copilot → Timeline
1. 从 Copilot 跳转到 Timeline  
2. 检查 `conversationId`（和可选 `userId`）保持一致  
3. 检查 Timeline 顶部上下文栏完整性  
4. 执行“加载更多消息”（如可用），确认 freshness 来源更新为 `manual`

**通过标准**：互跳成功、参数连续、加载动作后 freshness 语义正确

---

### 步骤 D：Timeline / Copilot 回跳 Chat
1. 从 Timeline 回到 Chat，核对参数一致  
2. 再从 Chat 到 Copilot、Copilot 回 Chat，核对参数一致

**通过标准**：双向回跳稳定，未出现上下文断裂

---

### 步骤 E：Chat 动作后 freshness 语义验证
1. 在 Chat 发送消息或触发摘要更新  
2. 检查 freshness 来源是否变为 `chat_action`

**通过标准**：Chat 动作后的来源语义与定义一致

---

### 步骤 F：缺参与异常语义一致性
1. 分别在三页模拟缺少 `conversationId` 的访问  
2. 检查是否出现一致风格引导  
3. 检查空态/错误态文案术语是否统一（如“沟通洞察”“关系时间线”）

**通过标准**：引导一致、术语一致、信息可理解

---

## 6. 最小回归 Checklist（可复用）

- [ ] Chat 页在有效 `conversationId` 下可稳定加载会话主体  
- [ ] Chat → Copilot 跳转成功，`conversationId` 保持一致  
- [ ] Chat → Timeline 跳转成功，`conversationId` 保持一致  
- [ ] Copilot → Chat 回跳成功，参数保持一致  
- [ ] Timeline → Chat 回跳成功，参数保持一致  
- [ ] Copilot ↔ Timeline 互跳成功，参数保持一致  
- [ ] 三页顶部均展示共享上下文栏，字段与入口完整  
- [ ] 三页 freshness 文案与“最后刷新时间/来源”可见且语义正确  
- [ ] Chat 发送消息或摘要更新后，freshness 来源更新为 `chat_action`  
- [ ] Copilot 手动刷新后来源为 `manual`  
- [ ] Timeline “加载更多”后来源为 `manual`  
- [ ] 缺少 `conversationId` 时，三页均给出一致风格的缺参引导  
- [ ] 空态/错误态文案无明显冲突（术语统一为当前口径）

---

## 7. 风险点与关注事项

### 7.1 参数承接风险（中）
跨页跳转较多，若某页链接构造或回跳逻辑变化，可能出现 `conversationId/userId` 丢失。

### 7.2 freshness 语义漂移风险（中）
页面局部改动后，`initial/manual/chat_action` 的来源映射可能被破坏。

### 7.3 文案口径回退风险（中）
历史术语残留可能导致“洞察/建议/时间线”表述不一致，影响验收与汇报一致性。

### 7.4 文档与行为偏差风险（中）
README 与 P4 阶段文档若未同步更新，可能出现“文档已收口、页面表现未对齐”的认知偏差。

---

## 8. 结论与使用方式

本基线文档用于定义 P4.1-S1 的最小验收标准，适用于：

- 阶段收口验收  
- 后续每轮前端改动后的快速回归  
- 对内对外状态说明的统一依据

建议用法：

1. 每次涉及 Chat/Copilot/Timeline 任一页改动后，至少执行一次本 checklist。  
2. 若出现“通过项失败”，先修复页面一致性，再更新相关文档口径。  
3. 文档口径以 README 与 `docs/P4/P4-current-slice-status.md` 为主，本文件作为执行层验收基线。
