# P4.1-S2 一页式草案（结构稿）
## 阶段：口径与文档体系防漂移收口

### 1) 目标
在 **P4 五个最小切片已完成**、且 **P4.1-S1 首轮人工验收（#1~#13）已通过** 的基础上，完成文档口径收口，建立“单一事实源 + 更新触发规则 + 最小执行节奏”，避免后续出现状态描述与实际实现不一致。

---

### 2) 范围（In Scope）
仅处理 P4 当前已存在文档体系的口径治理，不涉及代码与功能变更：

- 明确现有文档角色分工（README / 当前状态 / 验收基线 / 模板 / 示例 /首轮记录）
- 固化单一事实源（Single Source of Truth）判定顺序
- 定义文档更新触发规则（何时更新哪些文档）
- 定义最小执行节奏（每轮验收与每次状态变更后的文档动作）

---

### 3) 不在范围内（Out of Scope）
- 不新增业务功能、不改页面、不改 API、不改数据库、不改 worker
- 不做测试自动化建设或框架迁移
- 不重构文档体系为更大流程平台
- 不扩展到 P5/P6 的能力规划与实现讨论

---

### 4) 文档职责矩阵（基于当前仓库）

| 文档 | 当前角色 | 是否权威 | 更新原则 |
|---|---|---|---|
| `README.md` | 对外总览与阶段摘要入口 | 否（摘要层） | 仅保留高层状态与索引，不写轮次级细节 |
| `docs/P4/P4-current-slice-status.md` | P4 当前阶段权威状态面板 | 是 | P4 切片状态变化或验收结论变化时更新 |
| `docs/P4/P4.1-S1-acceptance-baseline.md` | S1 验收标准定义（判定口径） | 是（标准层） | 仅当验收标准本身变更时更新 |
| `docs/P4/P4.1-S1-test-run-template.md` | 执行模板（可复用） | 否（模板层） | 优化模板结构时更新，不写真实结果 |
| `docs/P4/P4.1-S1-test-run-example.md` | 模板示例参考 | 否（示例层） | 仅示例体例调整时更新 |
| `docs/P4/P4.1-S1-test-run-round1.md` | 首轮真实执行记录（事实归档） | 是（记录层） | 已完成轮次归档，除勘误外不改口径 |

---

### 5) 单一事实源规则（SSOT）
为避免同一问题多份文档冲突，统一按以下顺序判定：

1. **P4 当前状态与阶段结论**：以 `docs/P4/P4-current-slice-status.md` 为准  
2. **S1 验收是否通过及轮次结果**：以 `docs/P4/P4.1-S1-test-run-round1.md` 为准  
3. **S1 判定标准本身**：以 `docs/P4/P4.1-S1-acceptance-baseline.md` 为准  
4. **README**：作为对外摘要，不覆盖上述细粒度事实

---

### 6) 文档更新触发规则
发生以下事件时，执行对应最小更新：

- **验收轮次完成（通过/失败/阻塞）**  
  - 必须更新：轮次执行记录（如 `...test-run-roundN.md`）  
  - 必须同步：`P4-current-slice-status.md`（状态结论）  
  - 可选同步：README 一句摘要

- **验收标准变更（检查项或通过口径变化）**  
  - 必须更新：`P4.1-S1-acceptance-baseline.md`  
  - 必须检查：模板与示例是否需同步

- **页面行为/文案/验收路径变化（即使未改接口契约）**  
  - 必须执行：文档同步检查（`P4-current-slice-status.md`、`P4.1-S1-acceptance-baseline.md`、执行模板/示例/轮次记录的相关段落是否仍一致）  
  - 必要时更新：受影响文档中的口径描述与执行步骤，避免“实现已变、文档未变”

- **仅文字措辞优化、无口径变化**  
  - 可更新对应文档  
  - 不应改动“通过结论”和“事实记录”

---

### 7) 最小执行节奏
保持轻量、可持续：

1. **每轮验收结束当日**：先落盘轮次记录  
2. **同一轮次内**：同步 `P4-current-slice-status.md` 的结果段  
3. **阶段对外同步前**：再决定是否给 README 增加一句摘要  
4. **后续每次 P4 子阶段完成**：重复以上 1~3，不新增复杂流程

---

### 8) 结论
P4.1-S2 的最小价值是：在不改任何功能与代码的前提下，确保当前已完成成果（P4 五切片 + S1 首轮通过）在文档层**可追溯、可复核、可持续同步**。  
该阶段完成后，可将 P4 文档体系视为“防漂移收口就绪”，支持后续阶段收口或下一子切片定义。
