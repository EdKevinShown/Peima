# P4.3 问卷画像 v3（只读分支画像 + 标签 + 总体解释）

本文描述 **当前 `main` 已合入** 的问卷画像 v3 能力：与 **G1-R v2 计分写库**（`POST /questionnaire/submit` → `user_profile` 二十轴 float + `confidence`）**并列存在**，语义分离。**不**替代 matching / worker 决策；**不**与 **P6.8** 聊天画像补全 POST 自动联动。

**关联**：题库 **`sourceTier`** 与 **30 题全 `canonical`（M6.0-Q2）** 口径见 **`docs/P4/P4.2-questionnaire-G1R-batch2AB-snapshot.md`**、**`docs/M6/M6.0-q2-promote-q29-q30-canonical.md`**。规则层最小 Jest 回归见 `apps/api/src/modules/questionnaire/questionnaire-v3.rules.spec.ts`（`pnpm --filter @peima/api test`）。

---

## 一、目标

- 基于用户已提交的 **`questionnaire_answer`** 与题库 **tag**，在 **不新增数据库字段**、**不改问卷提交 DTO** 的前提下，提供 **只读** 的 **第一层分支画像** 与 **人格标签** 展示。
- 提供 **展示用主标签**（永不为空）、**风格侧写至多 3 条**、以及 **规则拼装** 的 **总体解释**（**非 LLM**）。
- 通过 **`GET /questionnaire/profile/:userId`** 与 Web **`/questionnaire-profile`** 页完成交付与验收。

---

## 二、总体运行逻辑

1. 读取该用户的 **`questionnaire_answer`** 全量键值。
2. **`buildAxisBranchProfilesV3`**：按轴、按分支（A–E）累计 **hits**；按 **canonical 题目** 计 **opportunities**（按题、不按选项条数）；得 **rate**、**adjustedScore**；再算每轴 **dominantBranch** / **uncertainBranches**（阈值见 `QUESTIONNAIRE_BRANCH_PROFILE_V3` 等集中常量）。
3. **`matchPersonalityLabelsV3`**：主池规则 → **强主** `labels.primary`（全条件高确定性 dominant，可为 **null**）与 **候选**；风格池规则 → **`styleLabels`**（命中后排序并 **最多保留 3 条**）。
4. **`resolveDisplayPrimary`**：若有强主则与之一致；否则从候选中按 **matchRatio → matchedCount → requiredCount → 主池表顺序** 取最优一条；再无候选则尝试 **隐藏款稀有人格池**（弱匹配阈值 0.5、至少 2 条条件，`source: rare`）；仍无则 **兜底** `no_label_match`。**`displayPrimary` 永不为空**。
5. **`buildOverallExplanation`**：输入 `labels`、`displayPrimary`、`uncertainBranchesByAxis`，输出 **`{ title, paragraph }`**，文案来自 **`questionnaire-profile-copy.constants.ts`** 等词典与模板；**不**调用 AI；**不**用二十轴 float 驱动 paragraph。
6. 序列化 **`user_profile`** 行作为 **`profile`**（含二十轴 float），与 v3 结构一并返回。

---

## 三、分支画像（第一层）

对轴 **1–20**、分支 **A–E**（按题库 tag）：

| 字段 | 含义 |
|------|------|
| **hits** | 用户答案命中该 `(轴, 分支)` 的累计次数 |
| **opportunities** | 在 **canonical** 题目集合上，该轴该分支在题面上「有机会被表达」的题数（按题计） |
| **rate** | `hits / opportunities`（opportunities 为 0 时为 null） |
| **adjustedScore** | 公平平滑：`(hits + 1) / (opportunities + 2)`（opportunities 为 0 时无意义则为 null，具体以实现为准） |

各轴对象内还带 **`branches`** 下各分支的上述指标，以及 **`dominantBranch`** / **`uncertainBranches`**。

---

## 四、dominantBranch / uncertainBranches

- **dominantBranch**：该轴上 **adjustedScore** 第一名与第二名差距 ≥ 集中阈值时，取 **唯一** 占优分支；否则为 **null**。
- **uncertainBranches**：未形成唯一 dominant 时，保留 **接近并列** 的分支列表（可能为空数组）。
- API 中除 **`dimensionBranchProfiles`** 外，另有扁平字段 **`dominantBranches`**（`Record<轴字符串, 分支 | null>`）、**`uncertainBranchesByAxis`**（`Record<轴字符串, 分支[]>`）便于消费。

---

## 五、主标签 / 候选 / 风格

- **主标签池**（`PERSONALITY_CORE_LABEL_RULES`）：表达整体关系人格；**强主** `labels.primary` 至多一条，要求规则内 **每一条件** 均为高确定性 dominant（无 uncertain 托底）。
- **候选标签**：仍来自主池；允许弱匹配比例达阈值（常量 `QUESTIONNAIRE_LABEL_MATCH_V3`），条数有上限。
- **风格标签池**（`PERSONALITY_STYLE_LABEL_RULES`）：表达局部行为侧面；**不参与**强主位；每条规则内各条件须满足 **dominant 命中** 或 **高 adjustedScore + 无 uncertain**（见 `collectStyleLabels` 实现）。
- **`category`**（风格规则上）仅作文案/UI 分类，**不参与**匹配判定。

---

## 六、displayPrimary

- **语义**：页面与 **总体解释 title** 的「主心骨」，**永远有值**。
- **来源**：`source === "primary"` | `"candidate"` | `"fallback"`。
- **与 `labels.primary` 区分**：强主可为 **null**；此时 `displayPrimary` 由 **最强候选** 或 **兜底文案** 承担展示。

---

## 七、风格 top3

- 接口返回的 **`labels.styleLabels`** 在服务端已 **排序并截断为最多 3 条**（`MAX_STYLE_LABELS`）。
- 排序意图：优先 **强 dominant 条件数多** 的命中，其次 **规则 token 数**（更细），再 **`PERSONALITY_STYLE_LABEL_RULES` 表顺序**（详见源码 `collectStyleLabels`）。

---

## 八、overallExplanation

```json
{
  "title": "string",
  "paragraph": "string"
}
```

- **title**：强主时用语词典主标题；候选升格时用「更接近某人格取向」类模板；兜底时用固定标题。
- **paragraph**：**单段** 自然语言，由 **整体定性 → 候选补充 → 风格补充 → 不确定性提示** 顺序拼接；**无 bullets**；**不**枚举轴号；**不**引用二十轴 float 文案。

---

## 九、`GET /questionnaire/profile/:userId`

- **路径**：`/questionnaire/profile/:userId`（Nest **`QuestionnaireController.getProfile`** → **`QuestionnaireService.getProfileForUser`**）。
- **鉴权**：该 handler **未**声明 `JwtAuthGuard`（与 `POST /questionnaire/submit` 不同）；前端仍可惯例带 `Authorization`。**404**：用户不存在，或无 **`UserProfile`**。**无 `questionnaire_answer` 行**时当前实现仍返回 **200**（分支累计可为零/弱信号，`displayPrimary` 可走 **fallback**），以前端与验收为准。
- **响应类型**：`QuestionnaireProfileView`（`questionnaire.service.ts`）。

**顶层 JSON 字段（与当前类型一致）**

| 字段 | 说明 |
|------|------|
| **`profile`** | `UserProfile` 整行 JSON（二十轴 float、`confidence` 等；与 v2 submit 写库一致） |
| **`dimensionBranchProfiles`** | 键 `"1"`…`"20"`；值：`AxisBranchProfileV3`（`branches` 下 A–E 各含 `hits` / `opportunities` / `rate` / `adjustedScore`，及 `dominantBranch` / `uncertainBranches`） |
| **`byDimensionBranchScores`** | 各轴各分支 **仅 hits** 的扁平 `Record<轴, Record<分支, number>>` |
| **`dominantBranches`** | `Record<轴字符串, 分支 \| null>` |
| **`uncertainBranchesByAxis`** | `Record<轴字符串, 分支[]>` |
| **`labels`** | `{ primary, candidates, styleLabels }`（`styleLabels` 已截断为 **≤3**） |
| **`displayPrimary`** | `{ id, name, ruleTokens, matchedAxes, source }`，**永非空** |
| **`overallExplanation`** | `{ title, paragraph }`，规则拼装 |

**说明**：本接口 **不**写库；**不**调用 LLM；**不**返回 Copilot / P6.8 相关字段。

---

## 十、`/questionnaire-profile` 页面

- **路由**：`apps/web/src/router/index.jsx` 中 **`/questionnaire-profile`** → **`QuestionnaireProfilePage`**；首页导航含入口文案。
- **数据**：`GET /questionnaire/profile/:userId`（`apps/web/src/api/questionnaire.ts`）。
- **展示顺序（概要）**：整体解释（title + paragraph）→ 置信度 → 展示主标签 / 强主标签 / 候选 / 风格 → 各维分支明细表（高亮与标签依据一致）→ **折叠区** 二十轴 float。
- **强主与展示主**：分区展示；高亮集包含 **`displayPrimary.matchedAxes`** 与原有标签依据。

---

## 十一、二十轴 float 的定位

- 来自 **`user_profile`** 的连续分数，**仅**在页面 **次级折叠区** 展示。
- **不参与**主标签、候选、风格的判定；**不作为** `overallExplanation.paragraph` 的主要依据（与页面文案一致）。

---

## 十二、边界与限制

- **未做**：matching / worker / chat **读取** v3 分支画像或 `displayPrimary` 参与决策或展示（仍以既有链路为准）。
- **未做**：问卷画像 v3 与 **P6.8** `POST .../profile-completion-suggestion` 的自动合并或联动。
- **canonical（当前）**：**`q01`–`q30` 均已 `canonical`**（**M6.0-Q2**）；v3 只读层的 **opportunities** 与 **v2 scorer** 使用同一题库闸门。
- **总体解释**：规则模板生成，**非 AI**；不覆盖、不替代用户对问卷与关系的自行理解。
- **未宣称**：matching/worker 已全面消费 v3 分支画像；`overallExplanation` 已接 LLM。

---

## 十三、与 P6.8 的关系（一句）

**P6.8** 是聊天会话驱动画像补全建议的 **独立 POST 链路**（`docs/P6/acceptance/P6.8-conversation-profile-completion-round1.md`），与本文 v3 **只读 GET 聚合** **无自动联动**；后续若产品上要串，属 **另一条业务线**，不在本文交付范围内。
