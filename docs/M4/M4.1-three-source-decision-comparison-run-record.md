## 三、结论

**M4.1 第一轮真实 DB 验收通过。**

- **`GET /matching/decision-comparison/:poolId`** 能将 **`staticShortlist`**、**`matchResultOriginal`**、**`pairwiseFrozen`**、**`rrmReadonly`** 四源分栏返回，并生成 **`comparisonSummary`**。
- **本样本**：**Static shortlist Top1**（`cmoc1gnjc000x6z64esun9iur`）与 **`MatchResult` 原始**、**Pairwise 选中**、**RRM top1**（均为 `cmoc1gnil00006z64l9w2oa5t`）**不一致**；而 **MatchResult、Pairwise、RRM 三者一致**（`comparisonSummary` 中对应三项为 `true`）。
- **`GET /matching/result`** 保持 **M3.8 enabled-mode** 读路径与关键字段 **不变**。

## 四、补充说明（四源分栏必要性）

本验收 **证明 M4.1 四源分栏的必要性**：下列字段 **语义不同，不能混用**。

- **`staticShortlist.top1CandidateUserId`** — Preview Pool **shortlist contract v0** 排序首位  
- **`matchResultOriginal.candidateUserId`** — **`match_results`** 中 worker 落库的 **原始** 匹配候选  
- **`pairwiseFrozen.selectedCandidateUserId`** — **冻结侧车 meta** 中最终选用（与 M3.8 display 对齐字段同源）  
- **`rrmReadonly.rrmTop1CandidateUserId`** — **M4.0** 只读 RRM 节奏分排序头名（依赖同池 **completed** `AiSimulationV1Job`）
