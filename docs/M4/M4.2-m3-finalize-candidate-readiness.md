# M4.2-M3 — Finalize 候选 Readiness（执行准备，只读）

本文档说明 **finalize / M4.2 样本扩容** 用的 **readiness 标签** 与 **只读清单生成方式**。**不含**任何业务代码或数据库写操作；**不含** `viewerUserId` / `poolId` 等 cuid（避免误入版本库）。

**约束**：不改 `MatchResult` / `finalScore`；不改 `GET /matching/result`；不改 worker 主排序；不改 RRM 公式；不进入 M4.3。

---

## 1. 两节候选定义

### 第一节（可 finalize 的 backlog）

满足：

1. 存在 **`ai_pairwise_decision_jobs.status = 'succeeded'`**（每个 `(viewerUserId, poolId)` 取 **一条**代表 job，默认按 `completedAt` / `updatedAt` 最新）；  
2. **不存在** `pairwise_pool_finalize_meta` 的 **同一** `(viewerUserId, poolId)`。

对每条再只读检查：

- **preview_pools**：是否存在 `id = poolId` 且 `userId = viewerUserId`；  
- **ai_simulation_v1_jobs**：是否存在 **同一** `(viewerUserId, poolId)` 且 `jobStatus = 'completed'`；  
- **match_results**：是否存在 **任意** `userId = viewerUserId` 的行（P0 下用于 M4.1「落库结果」腿；表无 `poolId` 列）。

### 第二节（需先 pairwise）

满足：

1. 存在 **completed** 的 `ai_simulation_v1_jobs`（按 `(viewerUserId, poolId)` 去重）；  
2. **preview_pools** 归属一致；  
3. **尚无** pairwise `succeeded` 行；  
4. **尚无** `pairwise_pool_finalize_meta`。

用于在 **第一节为空** 时，优先对 **前若干条** 跑 pairwise worker / 任务，再进入 finalize。

---

## 2. Readiness 标签

| 标签 | 适用节 | 含义 |
|------|--------|------|
| **READY_TO_FINALIZE** | 一 | 可调用 `finalizeWithPairwise` 的典型「健康」池：preview ✓、completed sim ✓、MatchResult ✓；finalize **不写** `MatchResult`。 |
| **MISSING_PREVIEW_POOL** | 一 | pairwise 已成功但 **无** 对应 preview 行 → finalize 后 **仍不满足** M4.2 `sampleDefinition`。 |
| **NEED_SIMULATION_JOB** | 一 | 缺 completed simulation → M4.1 RRM 只读腿可能缺失；**不阻止** finalize API 本身（若 pairwise 已 succeeded）。 |
| **MISSING_MATCH_RESULT** | 一 | viewer 无 `match_results` → M4.1 可能标 `MATCH_RESULT_MISSING`。 |
| **NEED_PAIRWISE_JOB** | 二 | 需先跑 pairwise 至 **`succeeded`**，再考虑 finalize。 |

**优先级（建议）**：第一节内 **`READY_TO_FINALIZE` > `MISSING_MATCH_RESULT` > `NEED_SIMULATION_JOB` > `MISSING_PREVIEW_POOL`**。若第一节 **0 条**，则取第二节 **前 4～5 条** `NEED_PAIRWISE_JOB` 作为 **pairwise 扩容优先队列**，目标使后续 finalize 后 **M4.2 `sampleCount` ≥ 5**。

## 3. 生成本地清单（含 cuid）

从 monorepo 根目录：

```bash
node --env-file=.env packages/database/scripts/m4-2-m3-finalize-candidates-readonly.mjs
```

默认写入 **`docs/M4/M4.2-m3-finalize-candidate-list.local.md`**（根 `.gitignore` 已忽略，**勿提交**）。

可选输出路径：

```bash
node --env-file=.env packages/database/scripts/m4-2-m3-finalize-candidates-readonly.mjs --out tmp/my-candidates.local.md
```

**M4.2-M3-B（pairwise 跑 job，不 finalize）**：`POST /pairwise-decision/jobs/:id/run` 与 Admin 同源，仅 **入队**；本地无 worker 时不会自然变 `succeeded`。推荐用脚本 **`packages/database/scripts/m4-2-m3-b-run-pairwise-jobs-local.mjs`**：在 Nest 内调用 **`runPairwiseDecisionJobSync`**（与单测 / worker 执行链一致），从 `M4.2-m3-finalize-candidate-list.local.md` 解析前 N 条 **NEED_PAIRWISE_JOB**，将运行记录（含 cuid）写入 **已 ignore 的** **`docs/M4/M4.2-m3-pairwise-run.local.md`**（**勿提交**）。需先 `cd apps/api && pnpm exec nest build`，且配置 **`AI_PAIRWISE_DECISION_ENABLED` + `AI_PAIRWISE_DECISION_API_KEY`**。

清单含 **readiness 表、建议优先处理、第一节/第二节全表**；**不**含手机号、昵称等，仅 **内部 cuid** 供本地操作对照。
