# M4.3-M2 — Final Match 页 Smoke 验收记录（展示层）

## 文档性质

- **范围**：仅记录 M4.3-M1 之后 `FinalMatchPage` 真实页验收结论与步骤；**不修改**业务逻辑、API、`MatchResult`、`finalScore`、worker、pairwise finalize、RRM、M4.4 Admin 大盘。
- **本轮依据**：对 `apps/web/src/pages/FinalMatchPage.jsx` 与 `apps/web/src/components/final-match/**` 的 **静态代码路径复核**（未在编写本文档时绑定运行中后端做浏览器会话录屏）。执行人可在预发/本地补记「执行环境、操作者、日期」一行。

## 1. 验收目标

| 编号 | 目标 |
|------|------|
| G1 | 普通访问：主路径呈现「最终结论（Hero）→ 为什么匹配 → 相处节奏 → 需要留意 → 聊天开场」产品叙事（在数据满足条件时）。 |
| G2 | 普通访问：主路径正文不出现 `candidateUserId` / `userId` / pairwise·RRM **jobId** 等标识符；不出现双候选 A/B 对比、raw 四维表、RRM 公式；无手选候选人 UI。 |
| G3 | `?debug=1`：开发者工具与 ID 类信息仅在该模式下出现；技术折叠区内容保持 **viewer-safe**（与 M4.3-M1 设计一致）。 |
| G4 | **展示对象**仍为 `effectiveDisplayCandidateId = displayCandidateUserId \|\| candidateUserId`（仅用于请求与跳转，主路径不渲染为可读 ID）。 |
| G5 | **GET `/matching/result`**：本轮前端未改该接口消费语义；回归字段以「前后端契约不变」为验收边界（见 §5）。 |

## 2. 验收步骤（建议人工复测时照做）

1. 准备已存在 `MatchResult` 的 viewer `userId`（URL `?userId=` 或 `localStorage.peimaUserId`）。
2. **普通模式**：打开 `/final-match?userId=<viewer>`（**不带** `debug`）。
3. 确认首屏 **Hero**（`FinalMatchHero`）：标题「本轮匹配说明」、结论句、`finalScore`、更新日期；正文中无 UUID 形态的对方/本人 ID。
4. 确认 **`matchInsights` 合法**（`isValidMatchInsights` 为真）时：依次可见 **为什么匹配 / 相处节奏建议 / 需要留意的点 / 聊天开场建议**（`FinalMatchExplanationSections`），底部 **进入聊天** 等按钮可用。
5. 展开 **「技术来源说明」**（`FinalMatchTechnicalDetails`）：核对仅含 `displaySourceType`、`finalMatchDecisionMeta` 子集与可选读数 `debug` 子折叠；**不应**出现 `selectedCandidateUserId` 等带 UserId 的 meta 字段渲染（见组件实现）。
6. **降级路径**：若 `matchInsights` 不合法，应不出现上述五段中的「解释分段」组件；可出现读数 `headlineZh` 条或灰色提示文案（代码路径：`FinalMatchPage.jsx` 中 `!isValidMatchInsights` 分支）。
7. **`?debug=1`**：同 URL 增加 `&debug=1`（或 `?debug=1` 与 `userId` 并存）。
8. 确认页顶出现 **开发者调试** 类 `<details>`（深链、侧车状态、短名单表等）；底部出现 **「开发者调试信息（含 ID 与系统原文）」** 橙色折叠，内含 `userId`、`candidateUserId`、`effectiveDisplayCandidateId`、`reasonSummary` 等。
9. **API 回归**（可选、需凭据）：对同一 `userId` 连续两次请求 `GET /matching/result/:userId`，比对 JSON 中 `candidateUserId`、`displayCandidateUserId`、`finalScore`、`finalMatchDecisionMeta` 是否逐字一致（仅验证本轮未改前端拉数逻辑导致误传参）。

## 3. 页面普通模式结果（代码复核）

| 检查项 | 结果 | 说明 |
|--------|------|------|
| Hero + 五段叙事 | **条件通过** | `matchInsights` 合法时：`FinalMatchHero` + `FinalMatchExplanationSections`（含四节 + 开场内 Phase E 卡片）+ footer「进入聊天」。不合法时：无四节组件，保留 Hero + 可选读数条/提示。 |
| 不展示 candidateId / userId / jobId（主路径正文） | **通过** | 主文与 `FinalMatchHero` / `FinalMatchExplanationSections` 无 ID/jobId 渲染。`AiSimulationSidecarV0` 仅接收 `effectiveDisplayCandidateId` 作 prop，不向用户主叙事区回显该字符串（侧车内部若有 ID 需人工点进侧车再验，不在 M4.3 主路径要求内）。 |
| 不展示 A/B 对比 | **通过** | 双候选 ranked 表、`shortlistDecisionV0` 等仅在 `userId && isDebugMode` 内渲染。 |
| 不展示 raw dimensions / RRM 公式 | **通过** | 同上，四维原始表与决胜表在 debug 块内。 |
| 无手选候选人 | **通过** | 无 A/B 切换或第二人选择控件。 |
| 「技术来源说明」 | **可见（默认折叠）** | `FinalMatchTechnicalDetails` **不依赖** `debug=1`，普通用户也可展开；内容为来源类型与 finalize 元数据子集，**非** debug 专属。 |

## 4. Debug 模式结果（`?debug=1`，代码复核）

| 检查项 | 结果 | 说明 |
|--------|------|------|
| 技术来源说明 | **仍可见** | 与普通模式相同位置；额外多出页顶多组「开发者调试」`<details>` 与文末橙色「开发者调试信息」。 |
| viewer-safe | **通过** | `FinalMatchTechnicalDetails` 不渲染 `finalMatchDecisionMeta` 中带 `UserId` 的字段；主折叠为枚举式布尔与 `fallbackReason` 等。橙色 debug 块为 **刻意** 暴露 ID 供内部排障，不计入「普通主路径」。 |
| 展示对象未改 | **通过** | `effectiveDisplayCandidateId` 的 `useMemo` 仍为 `displayCandidateUserId \|\| candidateUserId`；未因 `debug` 分支改变。 |

## 5. GET `/matching/result` 回归字段（契约边界）

| 字段 | 本轮验收结论 |
|------|----------------|
| `candidateUserId` | 前端仅读取展示，**未改**写入或比较语义；`getMatchingResult` 调用路径未变。 |
| `displayCandidateUserId` | 同上，仍用于 `effectiveDisplayCandidateId` 首选。 |
| `finalScore` | 仍原样传入 `FinalMatchHero` 的 `formatScoreDisplay`；无客户端改写。 |
| `finalMatchDecisionMeta` | 仍传入 `FinalMatchExplanationSections`（温和文案映射）与 `FinalMatchTechnicalDetails`；无新增字段消费或删字段依赖。 |

**说明**：本文档编写时 **未** 对运行中 API 做双请求 diff；若需「已执行」盖章，请在 §2 步骤 9 填实际比对时间与环境。

---

## 6. 结论

- M4.3-M1 所要求的 **普通主路径隔离**（无 A/B、无 raw 维表、无主文 ID）与 **`debug=1` 下开发者可见性** 在代码路径上 **一致满足**。
- **五段产品叙事**在 `matchInsights` 完整时满足；缺失时按设计降级，不强行渲染空节。
- **「技术来源说明」** 对普通用户也可展开——与「仅 debug 才可见技术区」不同；若产品希望完全隐藏，需另开需求（超出 M4.3-M2 仅记录范围）。

## 7. 安全边界（重申）

- 不修改：`MatchResult` schema、`finalScore`、`GET /matching/result` 服务端语义、worker、pairwise finalize、RRM 计算与抽取、M4.4 Admin 大盘。
- 不修改：`FinalMatchPage.jsx` 与本 smoke 文档以外的代码（M4.3-M2 仅新增本文档）。
