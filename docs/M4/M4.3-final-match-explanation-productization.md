# M4.3 — Final Match 解释产品化（展示层）

## 1. M4.3 目标

在 **不改动最终匹配对象、不新增后端接口** 的前提下，将最终匹配页从「技术调试叙事」调整为 **用户向产品叙事**：结论清晰、分段可读、敏感技术信息与普通用户主路径隔离。

前置能力（不改本里程碑范围）：

- M3.8：Top-2 Pairwise AI Decision Simulation  
- M4.0：Readonly RRM Ranking Proposal  
- M4.1：decision-comparison 四源分栏  
- M4.2：batch regression、`sampleCount=5`、schema_validation audit / hardening / replay  

## 2. 本轮范围：仅 FinalMatchPage 展示产品化

**本轮（M4.3-M1）只做前端展示重组**，包括：

- `apps/web/src/pages/FinalMatchPage.jsx`  
- `apps/web/src/components/final-match/*`（Hero、解释分段、技术来源折叠、叙事辅助 `finalMatchNarrative.js`）  

**明确不做：**

- 修改 `MatchResult` schema、`MatchResult.candidateUserId`、`MatchResult.finalScore`  
- 修改 `displayCandidateUserId` / `displaySourceType` / `finalMatchDecisionMeta` 的 **服务端计算或 GET `/matching/result` 核心语义**  
- worker batch-match、pairwise finalize、RRM 公式 / evaluator / extractDPre  
- M4.1 / M4.2 指标脚本  
- 新增 `GET /matching/final-match-explanation/:userId`  
- M4.4 Admin 大盘  

## 3. 用户端可展示内容（主路径）

主路径按区块组织，数据仍来自既有接口与字段（仅消费方式变化）：

| 区块 | 主要数据来源 |
|------|----------------|
| 最终结论（Hero） | `readoutFusion.headlineZh`、`matchInsights.explanation.whyMatch` 等生成一句自然结论；**保留 `finalScore` 展示**（数值与含义不变）；`effectiveDisplayCandidateId = displayCandidateUserId \|\| candidateUserId` **仅用于拉资料与跳转，不在主路径展示 id** |
| 为什么匹配 | `whyMatch`、`strengths`、经去重的 `readoutFusion.bulletsZh`；可选「获取相处参考」后的 `aiReview`  strengths / explanation（与上方合并叙事，避免三套重复卡片） |
| 相处节奏 | `rhythmPrediction`、`chatSimulationSummary`、`readoutFusion.tensionZh`、`interactionLite` 等；文案温和，避免「AI 判定你们一定适合」 |
| 需要留意 | `cautions`、`aiReview.risks`、经用户化摘要的 `riskFlags`；`finalMatchDecisionMeta.fallbackReason === low_decision_confidence` 映射为温和提示（不写成「AI 低置信不可靠」） |
| 聊天开场 | `openingTopics`、`chatSimulationSummary`；与 Phase E / interaction lite 开场 **去重**；保留 **Start Chat** 等行动按钮 |

## 4. 用户端禁止展示内容（普通用户主路径）

主路径 **不出现**：

- 两名候选 **A/B 对比**、另一名候选的 **淘汰理由**  
- **raw dimensions**、**RRM 公式**、**pairwise / RRM jobId**  
- **`candidateUserId` / `userId`** 作为可读展示（仅内部用于请求与跳转）  
- 用户 **手动选择 A/B**  
- **`riskFlags` 原样大字** 当系统标签；**`strongRisk` raw**  
- 内部 shortlist / 四维决胜 / consumption 等 **调试块**：默认不展示；仅 **`?debug=1`** 或明确「开发者调试信息」折叠内可见（见下节）  

## 5. 技术来源折叠区边界

- **折叠标题**：`技术来源说明`（可等价理解为开发者向的读数来源摘要）。  
- **可放入**：`displaySourceType`、`finalMatchDecisionMeta` 中与 **来源/冻结/应用标志** 相关的子集（如 `sourceType`、`pairwiseProposalRecommendation`、`fallbackReason`、`appliedToFinalScore`、`appliedToWorkerRanking`、`frozen` 等）；读数融合 **规则 trace** 可放在内层子折叠。  
- **折叠区内仍避免**：向终端用户展示 **jobId、candidateUserId、userId、pairwiseJobId** 等标识符；`finalMatchDecisionMeta` 中带 **UserId** 的字段 intentionally 不在该组件中渲染。  
- **与主路径关系**：普通用户完成阅读主路径 **无需展开** 该区域。  

## 6. 不改决策链（重申）

本轮 **零改动**：MatchResult 持久化形状、`finalScore`、worker 排名、pairwise finalize、RRM 计算与抽取逻辑；仅 **FinalMatch 前端** 重组布局与默认可见性。
