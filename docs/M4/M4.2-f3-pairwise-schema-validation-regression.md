# M4.2-F3 — Pairwise `schema_validation` regression (post–M4.2-F2)

## Purpose

Re-run a **small cohort** of `ai_pairwise_decision_jobs` that previously ended in `failed` with `failureDetail.code === schema_validation`, using the **same synchronous path** as the first run (`replayFailedSchemaValidationPairwiseJobSync`: reset to `queued` → `runPairwiseDecisionJobSync`). This checks whether **M4.2-F2** (normalizer + prompt hardening, strict validator) reduced `schema_validation` failures **without** changing final matching: **no finalize**, no `MatchResult` / `finalScore` / worker ranking / RRM changes.

## F1 baseline (audit)

From **M4.2-F1** audit (pre–F2 hardening): **12** jobs failed with `schema_validation`. Dominant validator paths included: `candidateA.strongRisk`, `fallbackUsed`, `candidateA.suggestedAction`, `viewerUserId`, `candidateA.conversationFit`, `dimensions.conversationFit`, `decisionConfidence`.

## How to run locally

1. Configure `DATABASE_URL` and pairwise LLM env (same as normal API), e.g. `apps/api/.env` or repo-root `.env`.
2. Build API: from `apps/api`, `pnpm exec nest build` (requires workspace packages already built).
3. Optional **read-only / sizing**: `cd apps/api && node dist/dev-cli/m42-f3-replay-schema-validation-failed.js --dry-run --limit=5` — counts up to five matching failed jobs; **no replay**, no writes except stdout.
4. **Replay** (mutates those job rows; still no finalize):  
   `cd apps/api && pnpm run m42-f3:replay-schema-validation-failed -- --limit=5`  
   Or set `M42_F3_LIMIT=5` / `M42_F3_DRY_RUN=1`.

Optional local artifacts (gitignored; **not** committed here — do not paste their contents into this doc):

- `docs/M4/M4.2-f3-pairwise-schema-validation-regression.local.md`

## Results

This replay is a **sample of at most five** historical jobs that had **previously** failed with `failureDetail.code === schema_validation` (same selection rules as the F3 dev script: recent failures, filtered by that code, capped at five). It is **not** a full replay of all twelve F1 failures.

## Conclusion

- **M4.2-F2 hardening** appears **effective** in this sampled replay: every selected job completed successfully after re-run on the hardened path.
- **5 / 5** replay attempts **succeeded**.
- **`schema_validation remaining = 0`** for this cohort after replay.
- **`failureCodeDistribution`** is **empty** (no non-success failure codes in this run).

## Compared to F1

F1 reported **12** `schema_validation` failures globally across the audited set. This F3 exercise validates **five** of the historically failing jobs (by the script’s selection rules). For that slice, **zero** remained on `schema_validation` after replay, which is **strict improvement versus those jobs’ prior failure state**. Generalizing beyond this sample still benefits from ongoing monitoring or a wider replay window if needed.
