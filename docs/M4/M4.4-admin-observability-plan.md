# M4.4 — Admin Observability & Fallback Reliability（方案）

本文档为 **M4.4-M0 方案扫描** 落盘，并已追加 **M4.4-M1**（CLI 只读汇总脚本）说明：定义 Admin / developer 观测面范围、现状、缺口、观测对象、最小指标、实现路线、边界与冻结项。M4.4-M0 为纯方案；**M4.4-M1** 仅新增脚本与文档，不改 schema、不强制新增 Jest。

---

## 1. M4.4 目标

- 建立 **Admin / developer 观测面**，用于理解 **matching 决策链路**上的侧车与旁路信号，而非替代主决策。
- 重点可观察：
  - **fallback** 使用情况（pairwise、finalize meta、RRM 诊断中的 fallback 信号等）；
  - **LLM / 上游失败**（在不含敏感内容的前提下，按 `errorCode` / `failureDetail.code` 聚合）；
  - **pairwise job** 生命周期与失败分布；
  - **M4.0** `rrm-ranking-proposal` 只读结论的统计意义（在定义好的样本上）；
  - **M4.1** `decision-comparison` 四源一致 / 分歧摘要；
  - **M4.2** batch regression 脚本的输出与在线汇总口径对齐或引用。
- **只读**：不写入业务表、不调用会改变 `MatchResult` / 展示对象 / worker 排序的路径；**不改变最终匹配**。

## 3. 当前缺口

- **没有**跨表、跨 job 类型的 **一站式聚合只读 API 或固定格式报告**（运营/on-call 需多次请求或手写 SQL）。
- **Pairwise** 仅有 **单 job get**，**没有** admin **list / summary** 端点。
- **RRM proposal** 与 **decision-comparison** 均为 **viewer + `poolId`** 粒度，**没有**全局/时间窗维度的汇总（需 M4.4 聚合层定义样本与时间窗）。

## 4. M4.4 应观测对象

| 对象 | 说明 |
|------|------|
| **`ai_pairwise_decision_jobs`** | `status`、`fallbackUsed`、`failureDetail`、`decisionResult`（仅摘要级统计）、`finalSourceShadow`、`sourceVersion`、时间戳。 |
| **`ai_simulation_v1_jobs` / `ai_simulation_v1_items`** | job 级状态与侧车 JSON 是否存在；item 级 `status`、`errorCode`、`failureDetail`（含 `schema_validation` 等）。 |
| **`pairwise_pool_finalize_meta`** | `frozen`、`meta`（`FinalMatchDecisionMeta` v1 子集字段的分布）、`pairwiseJobId`（仅作 join key，报告默认脱敏或计数）。 |
| **`match_results`** | 与池/队列的关联 **计数或存在性** 摘要即可；不在汇总层展开另一候选人叙事。 |
| **`preview_pools`（及 items 如需）** | 池存在性、与 finalize / M4.2 样本定义对齐（例如 frozen + pool 存在）。 |
| **M4.0 `rrm-ranking-proposal`** | 在选定样本集合上调用或复用同一计算链后的 **聚合指标**（非逐条暴露全量 JSON）。 |
| **M4.1 `decision-comparison`** | 四源 **一致 / 不一致** 的计数与简单分类（实现须避免与 M4.1 业务规则漂移，宜复用服务层）。 |
| **M4.2 batch regression output** | 离线报告文件作为基线；在线汇总可与同口径字段对齐或记录「最近一次报告路径 / schemaVersion」。 |

## 5. 第一轮最小指标（建议口径）

以下建议配合 **时间窗**（如最近 7 天）和/或 **条数上限**（如最近 500 条），避免全表扫描与过大结果集。

**Pairwise（`ai_pairwise_decision_jobs`）**

- job **总数**；
- **`queued` / `running` / `succeeded` / `failed`** 数量；
- **`fallbackUsed`** 为 true 的比例（分母须在文档与实现中写死：例如仅 `succeeded`、或 `succeeded+failed`）；
- **`failureDetail.code`** 分布（含 `schema_validation`、其它已知 code、`unknown`）；
- **`schema_validation`** 条数（与 M4.2-F3 口径对齐）。

**AI simulation（`ai_simulation_v1_items`）**

- **`errorCode`** 分布；
- 与 **`schema_validation`** 相关的计数（若与 `errorCode` 或 `failureDetail` 一致则合并说明）。

**Finalize（`pairwise_pool_finalize_meta`）**

- **`frozen === true`** 的总数；
- 从 **`meta` JSON** 聚合（字段以契约为准）：
  - **`wouldChangeStaticResult`** 比例；
  - **`fallbackReason`** 分布；
  - **`pairwiseProposalRecommendation`** 分布；
  - **`appliedToFinalScore` / `appliedToWorkerRanking`** 比例（若 meta 中存在）。

**RRM（M4.0）**

- 在定义好的 pool/job 样本上：**「若仅按 RRM 重排则 top 是否变化」**类指标；文档与实现中可与 `rrmRankingProposal` 的 **`topCandidateChanged`**（或等价命名）对齐，统计为 **RRM 层 would-change-static 比例**（名称仅表示观测语义，**不**表示已写入静态结果）。

**M4.1 四源**

- **四源一致** 数量 / **至少一处不一致** 数量（或更细分类需在 M4.4-M1 实现时与 `MatchingDecisionComparisonService` 输出字段对齐后写死）。

## 6. 推荐实现路线

| 里程碑 | 内容 |
|--------|------|
| **M4.4-M1** | **CLI 只读汇总脚本**：`packages/database/scripts/m4-4-admin-observability-summary.mjs`（命名可微调，职责不变）。Prisma / SQL 聚合 §5 指标；输出 **JSON + Markdown + console summary**。 |
| **M4.4-M2** | **Admin 只读 API**：`GET /admin/matching-observability/summary`（路径可微调）；`JwtAuthGuard` + Admin gate；内部 **复用与 M1 脚本相同的查询模块**，避免双口径。 |
| **M4.4-M3** | **Admin 页面或大盘**：仅在 M4.4-M1/M2 **口径稳定**后实施，减少 UI 返工。 |

## 7. 为什么先脚本（M4.4-M1）

- 与 **M4.2** 工具链一致（`packages/database/scripts`、本地/CI、`DATABASE_URL`）。
- **不**经过面向用户的 Web 路由，**不暴露**普通用户面。
- 便于快速迭代 **聚合口径**（分母定义、时间窗、脱敏规则）。
- 避免在口径未定时先做 **Admin UI** 导致重复改版。

---

## 8. 用户不可见边界

- **不向**普通用户展示 Admin 指标或入口（仅 Admin 角色 / 内网脚本操作者）。
- **不展示**「另一候选人」故事线、淘汰理由、双候选对比叙事。
- **不展示** raw dimensions、**RRM 公式向量**、完整技术推导。
- **不展示** raw prompt、**raw LLM body**。
- **`failureDetail`** 在报告中仅 **code / path / short reason** 等安全子集；禁止整段复制 evaluator 全文或 transcript。
- **禁止**根据观测结果 **自动** 修改 `MatchResult`、触发 batch-match、或改写 finalize 业务语义。

## 9. 冻结项（M4.4 不得触碰）

- 不改 **`MatchResult.candidateUserId`**
- 不改 **`finalScore`**
- 不改 **`displayCandidateUserId`** 计算或语义
- 不改 **`GET /matching/result`** 核心语义
- 不改 **worker batch-match** 主排序
- 不改 **pairwise finalize** 业务语义
- 不改 **RRM 公式 / evaluator / extractDPre**
- 不改 **FinalMatchPage** 用户主路径（含非 debug 展示）

---

## 10. M4.4-M1 验收标准（CLI 脚本）

- **脚本只读**：不对业务表做 `INSERT`/`UPDATE`/`DELETE`。
- **输出**：至少支持 **JSON**、**Markdown** 与 **console summary** 中一种以上（推荐三种均可选）。
- **不提交含真实 ID 的原始报告**：默认输出脱敏（hash 前缀、计数桶）或明确「仅本地路径、不入库」；**禁止**将带大量 cuid 的原始 JSON 作为仓库提交物。
- **能回答**：pairwise / simulation items / finalize / fallback / `schema_validation` 的 **基础分布**（§5）。
- **不写 `MatchResult`**，**不改** Web/API 上的最终用户展示。

## 11. M4.4-M1 — CLI 脚本（已实现）

| 项 | 说明 |
|----|------|
| **路径** | `packages/database/scripts/m4-4-admin-observability-summary.mjs` |
| **依赖** | `@prisma/client`（与 `@peima/database` 一致）；需有效 `DATABASE_URL`（推荐 `node --env-file=.env` 从仓库根运行）。 |
| **行为** | 仅 `SELECT` / Prisma 只读查询与聚合；**不**写库、**不**调 LLM、**不**调 Nest API、**不**执行 finalize。 |
| **时间窗** | `--since-days`（默认 `30`）：作用于 `updatedAt` 的表上时间过滤；`match_results` / `preview_pools` **总数**为全表计数。 |
| **行上限** | `--limit`（默认 `500`）：用于 **finalize `meta` 行解析** 的最大行数（按 `updatedAt` 降序）；若窗口内行数大于该值，则 **抽样**（见 JSON `finalizeMeta.metaStatsSampled`）。Pairwise `failureDetail.code` 等为 **窗口内全量 SQL 聚合**，不受 `--limit` 约束。 |

### 11.1 CLI 参数

| 参数 | 默认 | 说明 |
|------|------|------|
| `--limit` | `500` | Finalize `meta` 解析最多处理的行数（1–50000）。 |
| `--since-days` | `30` | 回溯天数（1–3650）；窗口下界为 UTC 当日 00:00 起算。 |
| `--json <path>` | 无 | 写入 JSON 报告（建议 `docs/M4/M4.4-admin-observability-summary.local.json`）。 |
| `--markdown <path>` | 无 | 写入 Markdown 摘要（建议 `docs/M4/M4.4-admin-observability-summary.local.md`）。 |

### 11.2 运行示例（仓库根）

```bash
pnpm --filter @peima/database build

node --env-file=.env packages/database/scripts/m4-4-admin-observability-summary.mjs --limit 500 --since-days 30

node --env-file=.env packages/database/scripts/m4-4-admin-observability-summary.mjs ^
  --json docs/M4/M4.4-admin-observability-summary.local.json ^
  --markdown docs/M4/M4.4-admin-observability-summary.local.md
```

（Linux/macOS 将 `^` 换为 `\`。）

### 11.3 输出内容概要

- **Pairwise**：窗口内总数、`status` / `sourceVersion` 分布、`fallbackUsed` 真/假/空计数与比例、`failureDetail->>'code'` 分布、`schema_validation` 计数。  
- **Simulation**：窗口内 `jobStatus`；属于该窗口内 job 的 **item** `status`、`errorCode`、失败数、`schema_validation` 相关 item 数。  
- **Finalize**：窗口/全表总数、`frozen` 计数；从 `meta` 仅抽取安全字段聚合 `wouldChangeStaticResult`、`fallbackReason`、`pairwiseProposalRecommendation`、`appliedToFinalScore` / `appliedToWorkerRanking`；**不**输出原始 `meta`；解析异常计入 `metaParseErrorBuckets`。  
- **Match / preview**：`match_results` 与 `preview_pools` 全表总数；存在对应 `preview_pools` 的 finalize 行数；窗口内 **至少一次 succeeded** 模拟 job 的 **distinct `poolId`** 数。  
- **M4.1 / M4.2**：不重算四源；输出提示并引用 `m4-2-batch-regression-report.mjs` 与脱敏文档路径（若存在）。
