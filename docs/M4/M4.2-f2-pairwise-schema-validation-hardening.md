# M4.2-F2 — Pairwise schema validation hardening

## Goal

Reduce `schema_validation` failures when pairwise LLM JSON reaches `parseAndValidateAiPairwiseDecision`, **without** changing final matching semantics: no changes to `MatchResult`, `finalScore`, worker batch-match ordering, RRM formulas, or pairwise finalize business rules.

## Context (M4.2-F1 audit)

A readonly audit showed a cluster of post-normalizer failures dominated by:

- Booleans echoed as strings or `0`/`1` (`fallbackUsed`, `strongRisk`).
- `suggestedAction` placed in nested wrappers or non-canonical spelling.
- Unit scalars in `[0,1]` emitted as strings or shallow objects (`conversationFit`, `dimensions.*`, `decisionConfidence`).
- Wrong echoed binding ids (`viewerUserId`, etc.).

F2 addresses these at **normalize + prompt** layers first; the validator stays strict except for any future **minimal** relaxations if a proven-safe shape is still rejected.

## Normalizer (`ai-pairwise-decision-normalize-draft.ts`)

| Area | Behavior |
|------|----------|
| **Binding ids** | `viewerUserId`, `poolId`, `candidateAUserId`, `candidateBUserId` are **always** taken from the active `RelationshipShortlistTop2`; model echoes are ignored. |
| **fallbackUsed** | Coerce common string and numeric literals (`"true"`/`"false"`, `0`/`1`, `yes`/`no`) to booleans. |
| **strongRisk** | Coerce `"true"`/`"false"`, `0`/`1`, and `{ value: … }` wrappers to booleans where unambiguous. |
| **RRM-lite 0–1 axes** | Unwrap nested `{ score \| value \| rating }`; parse **plain numeric strings** in `[0,1]`; for **missing** per-candidate six-axis fields, optionally fill from **root** `dimensions.*` (same keys) when present. |
| **suggestedAction** | Hoist strict literals from nested maps (`action`, `recommendation`, `guidance`, `decision`, `candidate`, `profile`, **`dimensions`**) and canonicalize a **safe** subset (case, hyphen, `slowdown` → `slow_down`). |
| **decisionConfidence** | Unwrap numeric string in `[0,1]`, `{ confidence }`, and explicit alternate roots (`pairwiseDecision.decisionConfidence`, etc.) when the top-level field is missing or coercible. |

## Prompt (`ai-pairwise-decision.prompt.ts`)

The JSON schema hint stresses:

- Real JSON **booleans** for `fallbackUsed` and per-candidate `strongRisk` (with a note that the server may coerce a narrow set of mistakes).
- `suggestedAction` **only** `maintain` \| `slow_down` \| `stop_or_step_back`.
- `decisionConfidence` and all six axis scores as **numbers in `[0,1]`**, not percentages or strings.
- Binding ids are **server-owned** from the shortlist.

## Tests

- `apps/api/test/ai-pairwise-decision-normalize-draft.spec.ts` — per-field coercion/hoist cases and a **sanitised** combined draft (no production IDs, no raw LLM logs) that must normalize then pass `parseAndValidateAiPairwiseDecision`.
- `apps/api/test/ai-pairwise-decision-llm.service.spec.ts` — expectations updated so wrong echoed binding ids **succeed** after authoritative overwrite (winner/loser must still reference the corrected A/B ids).
