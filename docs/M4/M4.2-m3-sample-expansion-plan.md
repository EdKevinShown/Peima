# M4.2-M3 — 样本扩容规划（方案扫描，无业务代码变更）

本文档回答：**为何 M4.2 当前 `sampleDefinition` 下 `sampleCount` 极小**，以及**如何在不改核心匹配逻辑的前提下**把批量对照样本补到可用规模。约束对齐 M4.2 主文档：[M4.2-batch-regression-and-quality-metrics.md](./M4.2-batch-regression-and-quality-metrics.md)。

**硬边界（本阶段不做）**：不改 `MatchResult.finalScore`、`MatchResult.candidateUserId`；不改 `GET /matching/result`；不改 worker 主排序；不改 RRM 公式 / evaluator / `extractDPre`；不进入 M4.3。

**候选清单（只读、含 cuid、勿提交）**：见 [M4.2-m3-finalize-candidate-readiness.md](./M4.2-m3-finalize-candidate-readiness.md) 与脚本 `packages/database/scripts/m4-2-m3-finalize-candidates-readonly.mjs` 生成的 **`docs/M4/M4.2-m3-finalize-candidate-list.local.md`**（`.gitignore`）。

## 1. 为什么当前 `sampleDefinition` 下只命中 1 条？

M4.2 脚本 `collectSamples` 的逻辑等价于：

1. 在 **`pairwise_pool_finalize_meta`** 中取 **`frozen = true`** 的行，按 **`updatedAt` 降序**，最多拉取 `min(5000, max(limit, limit*5))` 条候选键 `(viewerUserId, poolId)`。  
2. 对每条键，再查 **`preview_pools`**：必须存在 **`id = poolId` 且 `userId = viewerUserId`**（与 M4.1 池归属一致）。  
3. 通过上述校验的键才进入 `sampleCount`。

因此 **`sampleCount` 的上界**是：

\[
\min(\texttt{limit},\ \#\{(viewer,pool)\ \text{满足步骤 1+2}\}})
\]

当库里 **满足 1+2 的 `(viewerUserId, poolId)` 只有 1 组**时，即使 `--limit 50`，**`sampleCount` 仍为 1**。这不是 `limit` 失效，而是 **漏斗末端只有一条可统计样本**。

## 2. `frozen` finalize 样本不足：可能原因拆解

下列因素按 **与 M4.2 样本定义的相关性** 排列（可多选并存）。

| 可能原因 | 说明 |
|----------|------|
| **`pairwise_pool_finalize_meta` 行数极少** | M4.2 的第一道闸门就是该表。行数若 ≈0～1，则无论 `preview_pools` 多少，**样本都不可能多**。Finalize 由 **`MatchingFinalizePairwiseService.finalizeWithPairwise`** 在首次成功路径上 **`create` 且 `frozen=true`**（见 `matching-finalize-pairwise.service.ts`），**不会**由 AI simulation job 自动写入。 |
| **`frozen=true` 不足** | 若历史上有 `frozen=false` 的扩展用法，会缩小集合；当前实现下 **新写入行即为 `frozen: true`**，因此更常见的是 **根本没有几行 meta**，而不是 `frozen` 过滤掉大量行。 |
| **`preview_pool` 与 finalize 的 `(viewerUserId, poolId)` 不一致** | 若 `poolId` 指向已删除/被新池替换的旧 `preview_pools.id`，或 `viewerUserId` 与池主 `userId` 不一致，会在步骤 2 被剔除。脚本已统计 **`frozen=true` 但缺匹配 preview_pool** 的数量辅助判断。 |
| **`preview_pools` 总数少** | 仅当 finalize 已较多、但被步骤 2 大量过滤时，才成为主因；若 finalize 本身只有 1 条，**preview 总数再大也不增加 M4.2 样本**。 |
| **`ai_simulation_v1_jobs` completed 少** | **不直接进入** M4.2 的 `collectSamples`；它影响 M4.1 **`getComparison`** 里 RRM 只读提案是否 `present`、以及 `missingCounts` 等，**但不决定** `sampleCount`。completed 多而 finalize 少时，应优先补 **pairwise finalize 链路**。 |
| **viewer / pool 绑定不完整** | 典型是 finalize 写在 **A 用户 + A 的 pool** 上，但 `preview_pools.userId` 与 `viewerUserId` 不一致（数据修复/导入错误）或 `poolId` 漂移。 |

## 3. 各阶段数量（只读 SQL + Prisma 思路）

### 3.1 列名约定

迁移里表名为：`preview_pools`、`ai_simulation_v1_jobs`、`pairwise_pool_finalize_meta`、`ai_pairwise_decision_jobs`、`match_results`；字段为 Prisma 默认 **camelCase 加双引号**（如 `"viewerUserId"`、`"poolId"`、`"userId"`、`"jobStatus"`）。

### 3.2 推荐只读 SQL（`psql` / 任意 SQL 客户端）

```sql
-- A. preview_pools 总行数
SELECT COUNT(*) AS preview_pools_total FROM "preview_pools";

-- B. 至少有一条 completed 的 ai_simulation_v1_job 的 pool 数（去重 poolId）
SELECT COUNT(DISTINCT "poolId") AS pools_with_completed_sim
FROM "ai_simulation_v1_jobs"
WHERE "jobStatus" = 'completed';

-- C. pairwise_pool_finalize_meta 涉及的 pool 数（去重）
SELECT COUNT(DISTINCT "poolId") AS pools_with_finalize_meta
FROM "pairwise_pool_finalize_meta";

-- D. frozen = true 的 finalize 行数
SELECT COUNT(*) AS finalize_meta_frozen_true
FROM "pairwise_pool_finalize_meta"
WHERE "frozen" = true;

-- E. M4.2 样本定义精确命中数（frozen + 存在归属一致的 preview_pool）
SELECT COUNT(*) AS m42_sample_definition_eligible
FROM "pairwise_pool_finalize_meta" f
WHERE f."frozen" = true
  AND EXISTS (
    SELECT 1
    FROM "preview_pools" p
    WHERE p."id" = f."poolId"
      AND p."userId" = f."viewerUserId"
  );

-- F. frozen=true 但 preview_pools 对不上的条数（孤儿 finalize）
SELECT COUNT(*) AS frozen_true_orphan_no_preview_pool
FROM "pairwise_pool_finalize_meta" f
WHERE f."frozen" = true
  AND NOT EXISTS (
    SELECT 1
    FROM "preview_pools" p
    WHERE p."id" = f."poolId"
      AND p."userId" = f."viewerUserId"
  );

-- G. 有 MatchResult 的 viewer 去重数（按 userId）
SELECT COUNT(DISTINCT "userId") AS distinct_viewers_with_match_result
FROM "match_results";

-- H. 已成功 pairwise job、但尚无 finalize meta 的 (viewer, pool) 数（潜在可 finalize 池）
SELECT COUNT(*) AS succeeded_pairwise_pairs_without_finalize
FROM (
  SELECT DISTINCT j."viewerUserId", j."poolId"
  FROM "ai_pairwise_decision_jobs" j
  WHERE j."status" = 'succeeded'
) s
WHERE NOT EXISTS (
  SELECT 1
  FROM "pairwise_pool_finalize_meta" f
  WHERE f."viewerUserId" = s."viewerUserId"
    AND f."poolId" = s."poolId"
);
```

### 3.3 Prisma 等价写法（便于在临时脚本 / REPL 中执行）

- `prisma.previewPool.count()`  
- `prisma.aiSimulationV1Job.groupBy({ by: ['poolId'], where: { jobStatus: 'completed' } })` → `length`  
- `prisma.pairwisePoolFinalizeMeta.groupBy({ by: ['poolId'] })` → `length`  
- `prisma.pairwisePoolFinalizeMeta.count({ where: { frozen: true } })`  
- M4.2 交集：对 `findMany({ where: { frozen: true }, select: { viewerUserId, poolId } })` 逐条 `previewPool.findFirst({ where: { id: poolId, userId: viewerUserId } })` 计数（与现脚本一致）  
- `prisma.matchResult.groupBy({ by: ['userId'] })` → `length`

### 3.4 示例环境一次性读数（2026-05-02，本地 DB；仅作形状参考）

| 指标 | 读数 |
|------|-----:|
| `preview_pools` 总数 | 41 |
| `jobStatus = 'completed'` 的 **不同 `poolId`** 数 | 8 |
| `pairwise_pool_finalize_meta` 的 **不同 `poolId`** 数 | 1 |
| `pairwise_pool_finalize_meta` **总行数** | 1 |
| **`frozen = true` 行数** | 1 |
| **M4.2 `sampleDefinition` 可纳入条数**（frozen + 匹配 preview_pool） | 1 |
| **`frozen=true` 但无匹配 preview_pool** | 0 |
| **`match_results` 不同 `userId`（viewer）** | 2 |
| `ai_simulation_v1_jobs` 按状态 | `completed`: 20（总行；与「8 个不同 pool」不矛盾） |

**解读**：瓶颈几乎完全是 **`pairwise_pool_finalize_meta` 只有 1 行**；`preview_pools` 与 completed simulation **并非当前主因**。要增大 `sampleCount`，应增加 **「已 finalize-with-pairwise 且池仍归属同一 viewer」** 的 `(viewerUserId, poolId)` 组数。

## 4. 最小补样方案（推荐顺序）

### 4.1 优先：**复用已有 preview pool + 已有 succeeded pairwise job**

若 SQL **§3.2-H** 显示 **存在**「pairwise `succeeded` 但尚无 `pairwise_pool_finalize_meta`」的 `(viewerUserId, poolId)`：

- **最小动作**：对该组调用产品已有的 **`finalizeWithPairwise`**（需合法 `pairwiseJobId`、短名单与决策 JSON 已通过校验），**不写 `MatchResult`**。  
- **优点**：不新建 viewer、不强制新 simulation、不依赖 worker 改排序。  
- **注意**：Finalize 按 `(viewerUserId, poolId)` **唯一**；同一池重复调用会返回 **`already_frozen`**，不会复制出新样本——需要 **不同的 pool** 或 **不同 viewer** 才能增加 `sampleCount`。

### 4.2 其次：**已有 preview pool，但缺 pairwise job / 未 succeeded**

- 走现有 **pairwise job 创建 + worker/轮询跑 job 至 `succeeded`**，再 **finalize**。  
- 若 RRM 对照需要 `completed` simulation：对同一 `(viewer, pool)` 确保 **M4.0 链路的 completed job**（与 M4.2 指标质量相关，但仍不决定 `collectSamples` 条数）。

### 4.3 再次：**新建测试 viewer / pool / simulation**

- 适用于没有可用真实池的 **staging / 本地**。  
- 需要完整跑：**问卷/画像 → preview pool 生成 →（可选）simulation → pairwise → finalize**。  
- **成本最高**，仅在前两种无法凑够样本时使用。

### 4.4 是否需要 worker？

- **Pairwise job 执行**：通常需要 **worker（或等价的 job 执行器）** 把 `ai_pairwise_decision_jobs` 从 `queued`/`running` 推到 **`succeeded`**，finalize 才有稳定输入。  
- **不改 worker 主排序逻辑** 的前提下，仅 **消费现有队列行为** 即可。  
- **Simulation**：同理，completed 依赖现有 worker/API 行为；**不修改**其评分公式与写库边界。

### 4.5 不建议作为「最小」方案

- **手工 INSERT `pairwise_pool_finalize_meta`**：`pairwiseJobId` / `meta` JSON 必须与真实 pairwise 输出一致，否则 M4.1 对照语义失真，且易与 `MatchingFinalizePairwiseService` 约束漂移。仅作极端调试手段。

## 5. M4.2-M3 推荐目标

| 阶段 | `sampleCount` 目标 | 用途 |
|------|-------------------|------|
| **M4.2-M3a** | **≥ 5** | 指标与分布开始有粗粒度意义；可发现明显回归。 |
| **M4.2-M3b** | **≥ 20** | 率类指标更稳定；`missingCounts`、fallback 分布更可读。 |

达成后再跑：`node --env-file=.env packages/database/scripts/m4-2-batch-regression-report.mjs --limit 50 …`，并更新 **脱敏** run record（不提交含 ID 的原始 JSON）。

## 6. 建议执行步骤（**先不要**执行破坏性操作）

以下为 **操作顺序建议**；其中 **DELETE / TRUNCATE / 改 MatchResult** 等一律跳过。

1. **只读复核**：在目标环境执行 **§3.2** SQL 或 Prisma 等价查询，确认 H 与 finalize 行数。  
2. **列清单**：导出（脱敏）「可对 finalize 的 `(viewerUserId, poolId, pairwiseJobId)`」候选表，仅用于内部跟踪。  
3. **对前 N 个候选池**（N 以凑满 5～20 为目标）：  
   - 确认 **`preview_pools`** 仍存在且 `userId` 与 viewer 一致；  
   - 调用 **`finalizeWithPairwise`**（或产品上等价入口），记录返回 `finalized` / `already_frozen` / `pending`。  
4. **若大量 `pending`**：检查 pairwise job 是否仍为 `queued`/`running`，用 **现有** worker 或手动触发 **允许的** job 执行路径（不改编排/主排序代码）。  
5. **重跑 M4.2 脚本** `--limit 50`，确认 `sampleCount` 上升。  
6. **更新** `docs/M4/M4.2-batch-regression-sanitized-run-record.md`（仅聚合字段）。  
7. **禁止**：为「凑样本」去 UPDATE `match_results`、改 `finalScore`、改 `candidateUserId`、删池误伤生产数据。
