# M4.0 — Read-only RRM Ranking Proposal（收口说明）

## 1. 一句话结论

**M4.0 是只读、不入正式决策链的 RRM 排序「假设」提案**：对内既有 admin job 响应中的 `rrmRankingProposal`，对 viewer 另有 **`GET /matching/rrm-ranking-proposal/:poolId`**（JWT + 池归属）。**不参与**真实匹配排序，**不写入** `MatchResult`，**不改变** `finalScore`、`displayCandidateUserId`、worker 主排序或 `FinalMatchPage` 展示对象。

## 2. 目标

在已有 **`rrmSimMultiCandidateDiagnostic`**（多候选只读诊断）之上，派生 **`rrmRankingProposal`**，便于在内部诊断页观察：**若仅按 RRM-Sim 节奏分重排，排序会如何变化**，以及该信号是否值得人工审阅。

- 数据源：与 admin `getJobById` **同一套只读计算链**（`formatJobResponse` → `enrichResultsWithRrmSim` → `buildRrmSimMultiCandidateDiagnostic` → `buildRrmRankingProposal`）；**不重跑 LLM**、**不写 DB**。
- 纯函数入口：`buildRrmRankingProposal`（`apps/api/src/modules/ai-simulation-v1/ai-simulation-v1-rrm-ranking-proposal.ts`）。

## 3. 输出结构（`rrmRankingProposal`）

| 字段 | 说明 |
|------|------|
| `schemaVersion` | 固定 `1` |
| `sourceVersion` | 固定 `m4.0-readonly-rrm-ranking-proposal-v1` |
| `mode` | 固定 `readonly` |
| `appliedToFinalScore` | 固定 `false` |
| `appliedToWorkerRanking` | 固定 `false` |
| `existingTopCandidateUserId` | `existingSimulationRank[0]` |
| `rrmTopCandidateUserId` | `rrmRhythmRank[0]` |
| `topCandidateChanged` | 与 diagnostic 的 `topCandidateChangedIfRrmOnly` 一致 |
| `scoreDistributionFlag` | 与 diagnostic 一致（`ok` \| `too_narrow` \| `too_many_fallbacks`） |
| `confidenceLevel` | `low` \| `medium` \| `high`（由 recommendation 分支推导） |
| `recommendation` | 见下节 |
| `items[]` | 每候选：`candidateUserId`, `existingRank`, `rrmRank`, `simulatedRhythmScore`, `suggestedAction`, `progressionWindow`, `fallbackUsed`, `reasonSummary` |
| `warnings` | 英文短句数组，提示分布/弱信号等（不含 C/A/S/E 等原始公式向量） |

**不包含**：面向普通用户的 C/A/S/E/F/Q/D/R 原始参数块；技术字段仅出现在 admin 诊断 API / 页面。

## 4. `recommendation` 规则（优先级自上而下）

1. **`do_not_use_for_ranking`** — `scoreDistributionFlag === "too_many_fallbacks"`（与 diagnostic 一致：`fallbackCount / total >= 0.5`）。
2. **`insufficient_separation`** — `scoreDistributionFlag === "too_narrow"`（`rrmAvailableCount >= 3` 且非 fallback 节奏分 `spread < 8`）。
3. **`review_manually`** — `topCandidateChangedIfRrmOnly === true` 且 `scoreRange.spread >= 8`，且未落入上述两类。
4. **`supports_existing_rank`** — `topCandidateChangedIfRrmOnly === false`，且 `existingTopCandidateUserId === rrmTopCandidateUserId`（两者非空），且未落入 1/2。
5. **`diagnostic_only`** — 其余情况（例如：top 会变但 spread &lt; 8、或存在少量 fallback 但未触发 `too_many_fallbacks` 等弱信号场景）。

## 5. 展示范围（含 M4.0.1 响应边界）

| 位置 | 是否展示 M4.0 / RRM 排序建议 | 使用的 job 读取 API |
|------|------------------------------|---------------------|
| **`AiSimulationJobDiagnosticPage.jsx`** | **是** — 折叠区「M4.0 — RRM 排序建议（只读 · 不入主链）」 | **`GET /admin/ai-simulation/v1/jobs/:jobId`**（`getAdminAiSimulationV1Job`） |
| **`FinalMatchPage`** / **`MatchingWaitingPage`**（侧车轮询） | **否** — 不出现 RRM 排序建议文案 | **`GET /ai-simulation/v1/jobs/:jobId`**（`getViewerAiSimulationV1Job`），**响应体不含** `rrmRankingProposal` / `rrmSimMultiCandidateDiagnostic` |
| **用户主路径** | **否** — 浏览器侧车不再经 admin GET 拉全量诊断 JSON |

**M4.0.1**：新增 viewer HTTP 路由，JWT 且 **仅 job 的 `viewerUserId`** 可读；服务层 `getJobForViewer` 返回 `{ ...base, results }`（含每条 `rrmSimResult`），与 admin `getJobById` 分离。

## 6. 明确不做什么

- 不改 **`finalScore`**（worker / matching 计分逻辑未因 M4.0 改动）。
- 不改 **worker `batch-match` 主排序**。
- 不改 **`MatchResult.finalScore`**。
- **不写 `MatchResult`**；**`GET /matching/rrm-ranking-proposal/:poolId` 不写 DB**，且**不改变** **`GET /matching/result`** 的契约与实现路径。
- 不让 **RRM-Sim / RRM 提案** 参与真实生产排序（M4.0 为**只读提案层**，不是正式决策层）。
- **不重跑 LLM**（基于已落库的 `AiSimulationV1Job` / items，在读取时与 admin 同源复算 `enrichResultsWithRrmSim` + diagnostic + proposal）。

## 7. 后续进入「正式 M4」排序融合的前置条件（建议）

在进入任何「生产排序融合」之前，至少应满足或可论证：

1. **多个真实 job** 上重复观察 `rrmSimMultiCandidateDiagnostic` / `rrmRankingProposal`，样本量足够。
2. **`scoreDistributionFlag` 在多数 job 上为 `ok`**，少数 `too_narrow` / `too_many_fallbacks` 可解释。
3. **`fallbackCount` 足够低**（相对总候选数），非 fallback 路径占主导。
4. **`topCandidateChangedIfRrmOnly` 为 true 的个案** 可由产品/算法/运营 **人工解释**，而非随机噪声。
5. **RRM 排序信号稳定**（跨时间、跨池、跨模型版本的可重复性有记录）。
6. **有回滚策略**（开关、灰度、数据兼容与监控告警）。
7. **先 shadow mode**：对比「仅记录差异」与线上排序，**不直接改写**生产 `MatchResult` / worker 决策，直到评审通过。

---

**API 对照**

- **`GET /admin/ai-simulation/v1/jobs/:jobId`**（须 admin allowlist）→ `getJobById` → 响应含 **`rrmSimMultiCandidateDiagnostic`**、**`rrmRankingProposal`**（`sourceVersion`：`m4.0-readonly-rrm-ranking-proposal-v1`）。
- **`GET /matching/rrm-ranking-proposal/:poolId`**（须 JWT，`req.user.userId` 为 **`viewerUserId`**，且 **`preview_pools.id === poolId` 且 `userId === viewerUserId`**）→ matching 专用 **HTTP DTO**（`schemaVersion`、`sourceVersion`、`mode: readonly`、`simulationJobId`、`staticTop1CandidateUserId`、`rrmTop1CandidateUserId`、`wouldChangeStaticResult`、`appliedToMatchResult` / `appliedToFinalScore` / `appliedToDisplayCandidate` 均为 **`false`**、`ranking[]`）。**依赖数据**：同池、同 viewer 下 **`jobStatus === completed`** 的 **`AiSimulationV1Job`** 中 **`updatedAt` 最新**的一条；若无此类 job → **404**，响应体带稳定 **`code: NO_SUCCEEDED_SIMULATION_JOB_FOR_POOL`**。池不存在或不属于当前用户 → **404**（普通 not found 文案）。**不改变** `GET /matching/result`。
- **`GET /ai-simulation/v1/jobs/:jobId`**（须 JWT，且 token `userId` 须为该 job 的 **`viewerUserId`**）→ `getJobForViewer` → **仅** `{ ...base, results }`，**不含** `rrmSimMultiCandidateDiagnostic`、**不含** `rrmRankingProposal`；非 owner 返回 **404**。

## 8. 真实 DB 验收记录（M4.0 第一轮收口）

**结论（摘要）**

M4.0 第一轮 **真实 DB 验收通过**：`GET /matching/rrm-ranking-proposal/:poolId` 能按池返回只读提案（本例 `wouldChangeStaticResult = true`，`appliedToMatchResult` / `appliedToFinalScore` / `appliedToDisplayCandidate` 均为 `false`）；**`GET /matching/result`** 回归通过，**M3.8 enabled-mode** 读路径与关键字段（`candidateUserId`、`finalScore`、`displayCandidateUserId`、`finalMatchDecisionMeta.*`）**不变**。

**完整请求/响应字段与 `ranking[]` 逐行快照**见：**[M4.0-readonly-rrm-ranking-proposal-run-record.md](./M4.0-readonly-rrm-ranking-proposal-run-record.md)**。

**`staticTop1CandidateUserId` 语义（与 `MatchResult` 脱钩）**

matching 响应中的 **`staticTop1CandidateUserId`** 取自该次 RRM proposal 所依赖的 **`AiSimulationV1Job.shortlistBinding`** 的静态顺序首位，**不得**直接等同于 **`MatchResult.candidateUserId`**。M4.1 三路对照阶段建议在观测面将 **Static 20 维 Top1**、**`MatchResult` 原始候选**、**Pairwise frozen `selectedCandidateUserId`**、**RRM top1** **分栏展示**（M4.1 未在本轮实现）。

**边界（验收后仍维持）**

不写 `MatchResult`；不改 `MatchResult.candidateUserId`；不改 `finalScore`；不改 `displayCandidateUserId`；不改 **`GET /matching/result`**；不改 worker；不改 `FinalMatchPage`；不改 pairwise finalize；不改 RRM 公式 / evaluator / `extractDPre`；**不进入 M4.1 实现**。
