# M4.2 — Batch Regression & Quality Metrics（批量观测层）

## 1. 目标

在 **M3.8**（pairwise frozen meta）、**M4.0**（RRM readonly proposal）、**M4.1**（`MatchingDecisionComparisonService.getComparison` 四源 DTO）之上，提供 **只读批量报告**，对真实 DB 中符合样本定义的 `(viewerUserId, poolId)` 集合，**循环复用 M4.1 单池对照逻辑**，汇总质量指标与分布。**不写库**、**不重跑 LLM**、**不改变** 最终匹配、`MatchResult`、`GET /matching/result`、worker、FinalMatchPage。

---

## 2. M4.2 不是决策层

M4.2 **仅批量观测与回归统计**，不参与排序、不写入 `MatchResult`、不修改 `displayCandidateUserId`、不替代产品决策。输出为 **JSON / Markdown / 控制台摘要**，供研发与运营离线审阅。

---

## 3. 样本定义（第一轮固定）

**`sampleDefinition`**（写死在报告顶层）：

`pairwise_pool_finalize_meta.frozen_true_with_existing_preview_pool`

**含义**：

1. 查询 **`pairwise_pool_finalize_meta`**，条件 **`frozen === true`**，按 **`updatedAt` 降序**。  
2. 对每条 **`(viewerUserId, poolId)`**，确认 **`preview_pools`** 存在且 **`id = poolId`** 且 **`userId = viewerUserId`**（与 M4.1 池归属一致）。  
3. **`--limit`**（默认 **50**）控制最多纳入的样本条数。

---

## 4. 指标定义与分母规则

脚本对每个样本调用 **`MatchingDecisionComparisonService.getComparison(viewerUserId, poolId)`**，在返回的 DTO 上聚合。每个 **rate** 同时输出 **`numerator` / `denominator` / `rate`**（`denominator === 0` 时 `rate` 为 `null`）。

| 指标 | 分子 | 分母 |
|------|------|------|
| **staticTop1EqualsMatchResultOriginalRate** | `comparisonSummary.staticTop1EqualsMatchResultOriginal === true` | `staticShortlist.top1CandidateUserId` 与 `matchResultOriginal.candidateUserId` **均存在**的样本数 |
| **pairwiseEqualsMatchResultRate** | `comparisonSummary.matchResultOriginalEqualsPairwiseSelected === true` | `pairwiseFrozen.present === true` 且 `matchResultOriginal.candidateUserId` **存在** |
| **rrmEqualsMatchResultRate** | `comparisonSummary.matchResultOriginalEqualsRrmTop1 === true` | `rrmReadonly.present === true` 且 `matchResultOriginal.candidateUserId` **存在** |
| **staticTop1EqualsRrmTop1Rate** | `comparisonSummary.staticTop1EqualsRrmTop1 === true` | `staticShortlist.top1` 与 `rrmReadonly.rrmTop1CandidateUserId` **均存在** |
| **pairwiseSelectedEqualsRrmTop1Rate** | `comparisonSummary.pairwiseSelectedEqualsRrmTop1 === true` | `pairwiseFrozen.selectedCandidateUserId` 与 `rrmReadonly.rrmTop1CandidateUserId` **均存在** |
| **rrmWouldChangeStaticResultRate** | `rrmReadonly.wouldChangeStaticResult === true` | `rrmReadonly.present === true` 且 `wouldChangeStaticResult !== null` |
| **pairwiseWouldChangeStaticResultRate** | `pairwiseFrozen.wouldChangeStaticResult === true` | `pairwiseFrozen.present === true` 且 `wouldChangeStaticResult !== null` |

**`missingCounts`**：对每条样本的 **`comparisonSummary.notes`** 中字符串计数（与 M4.1 常量一致）：`STATIC_SHORTLIST_MISSING`、`MATCH_RESULT_MISSING`、`PAIRWISE_META_MISSING`、`RRM_PROPOSAL_MISSING`。

**`distributions.uniqueCandidateCountDistribution`**：对 `comparisonSummary.uniqueCandidateCount` 做 **字符串键 → 出现次数** 的直方图。

**`fallbackReasonDistribution`**：在 **`pairwiseFrozen.present === true`** 时，取 **`fallbackReason`**；`null` / 空 **记为 `"none"`**。

**`perSample`**：可选 **`--include-samples=true`** 时输出精简行（`viewerUserId`、`poolId`、四源关键 id、`uniqueCandidateCount`、`notes`）；默认 **不展开** 以控制 JSON 体积。

---

## 5. 为什么复用 `MatchingDecisionComparisonService`

四源拼装、`notes`、`RRM` 缺 job 吞掉、`comparisonSummary` 布尔逻辑 **只维护一份**（M4.1）。M4.2 脚本通过 **Nest `createApplicationContext(AppModule)`** 注入 **`MatchingDecisionComparisonService`**，逐池调用 **`getComparison`**，**禁止**用裸 SQL 重算四源对照，避免与 M4.1 漂移。

---

## 6. 输出格式与运行方式

**脚本路径**：`packages/database/scripts/m4-2-batch-regression-report.mjs`

**前置**：已构建 API（生成 `apps/api/dist/**`）：

```bash
cd apps/api && pnpm exec nest build
```

**从 monorepo 根目录执行**（推荐 `--env-file=.env` 注入 `DATABASE_URL`、`JWT_SECRET` 等 Nest 启动所需变量）：

```bash
node --env-file=.env packages/database/scripts/m4-2-batch-regression-report.mjs --limit 50
node --env-file=.env packages/database/scripts/m4-2-batch-regression-report.mjs --limit 50 --json docs/M4/M4.2-batch-regression-report.json --markdown docs/M4/M4.2-batch-regression-run-record.md
node --env-file=.env packages/database/scripts/m4-2-batch-regression-report.mjs --include-samples=true
```

**CLI 参数**：

| 参数 | 默认 | 说明 |
|------|------|------|
| `--limit` | `50` | 最大样本数，范围 `1`～`5000` |
| `--json` | 无 | 写入机器可读报告路径 |
| `--markdown` | 无 | 写入 Markdown 摘要路径 |
| `--include-samples` | `false` | `true` 时在 JSON 中写入 `perSample[]` |

**报告顶层字段**：`schemaVersion`、`sourceVersion`（`m4.2-batch-regression-quality-metrics-v1`）、`generatedAt`、`sampleDefinition`、`sampleCount`、`metrics`、`missingCounts`、`distributions`、`fallbackReasonDistribution`、`perSample`。

**安全说明（提交前必读）**：`--json` / `--markdown` 输出 **可能包含真实 `userId` / `poolId` / `candidateUserId` 等**。**提交到 Git 前必须脱敏**；或 **将报告写到已加入 `.gitignore` 的本地路径**（见仓库根 `.gitignore` 中 M4.2 窄规则），避免误将批量报告产物推送到远程。

---

## 7. 安全边界

- **不写** `MatchResult`；**不改** `candidateUserId` / `finalScore`  
- **不改** `displayCandidateUserId`；**不改** **`GET /matching/result`**  
- **不改** worker batch-match；**不改** FinalMatchPage；**不改** pairwise finalize  
- **不改** RRM 公式、`evaluateRrmSimFromSimulationV2`、`extractDPre`  
- **不进入** M4.3 用户端解释、M4.4 Admin 大盘 UI  
- **不写**任何最终匹配结果落库字段  

---

## 8. M4.2 第一轮范围说明

- **脚本版**批量报告；**无** Admin HTTP API、**无** FinalMatchPage / 大盘 UI。  
- 后续若加 Admin 只读 API，应 **仍调用同一 Service**，不复制聚合逻辑。
