## 1. M3.8 阶段目标（摘要）

M3.8 在 **硬筛 → 人像 6 人池 → 20 维 Top 2 → Pairwise LLM 二选一 → Final Match 展示与冻结策略** 的产品语义下，完成 **Top-2 Pairwise AI Decision Simulation** 的 **契约、服务、队列、Worker、Viewer 轮询与 finalize、读路径展示与 shadow 元数据** 的落地与验证；在 **不写入 `MatchResult.candidateUserId`、不改 `finalScore`、不改 worker batch-match 主排序** 的前提下，使 **真实 LLM** 产生的 pairwise 决策可被 **安全消费**（含低置信度 **static fallback** 与 **`finalSourceShadow`** 审计面），并完成 **自动化构建与测试** 及 **端到端真实链路验收**。

## 6. 本阶段安全边界（明确不变项）

M3.8 收口后，以下 **仍属阶段红线**（与主规划 **非目标** 一致）；**下一阶段也不得在未立项 PR 的前提下突破**：

- **不改** **`MatchResult.candidateUserId`**（batch 静态 Top1 语义保持不变）。
- **不改** **`finalScore`**（含 **`MatchResult.finalScore`** 与 worker 产出语义）。
- **不改** **worker batch-match 主排序**。
- **不改** **Full RRM** 主链路语义；**不改** **`ai_simulation_v1`** 作为未授权的生产替代路径。
- **不改** **`evaluateRrmSimFromSimulationV2`**。
- **不改** **`extractDPre`**。
- **不改** **`rrm-sim-formula.ts` / `rrm-sim.constants.ts`**。
- **不进入正式 M4**（Full RRM 产品化主里程碑仍独立门禁）。

Pairwise 侧 **`appliedToFinalScore` / `appliedToWorkerRanking`** 在契约与 shadow 中保持 **false**，与上表一致。

## 7. 结论与下一阶段建议

**结论**：**M3.8 已完成收口**。证据链包含：**API / Web build 通过**；**`ai-pairwise` / `matching-finalize` / `matching-result-display` 相关 Jest 通过**；**MatchingWaitingPage + FinalMatchPage eslint 通过**；**真实 LLM pairwise job succeeded**；**`finalSourceShadow` 写入**；**`finalize-with-pairwise` 成功且 `PairwisePoolFinalizeMeta` 落库**；**`GET /matching/result` 读路径与 `finalMatchDecisionMeta` 一致**。

**下一阶段不应**：在 **无独立设计 / 无回归矩阵 / 无产品门禁** 的情况下，将 **Full RRM** 直接并入 **正式主链路** 或替代 **Top2 + pairwise** 已定义的 **读路径与冻结语义**。

**建议优先**：**读路径扩展**、**观测与告警**、**与 M4.0 只读排序提案对齐的边界设计**（参见 [`docs/M4/M4.0-readonly-rrm-ranking-proposal.md`](../M4/M4.0-readonly-rrm-ranking-proposal.md)）、以及 **产品化开关与审计** 的单独里程碑（**不等于**「默认开启 Full RRM」）。
