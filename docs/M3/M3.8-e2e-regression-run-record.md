### 8.6 M3.8-M15A — Pairwise JSON contract hardening（2026-05-02）

**背景（真实 LLM smoke，维护者本地两次跑 M3.8-M15）**

| 次序 | 现象 | 结论 |
|------|------|------|
| 第一次 | `json_extract_error` / `truncated_or_unbalanced_json` | 输出被截断或含非 JSON 包裹；已尝试调高 `AI_PAIRWISE_DECISION_MAX_TOKENS` / `TIMEOUT` |
| 第二次 | `schema_validation`，`path=viewerUserId`，`reason=expected_nonempty_string` | **worker / provider 链路已通**；模型能返回可解析 JSON，但 **省略顶层绑定元数据** |

**M15A 修复方向（实现见规划 §三十二 A）**

- **Prompt 收紧**：明确「仅一个 JSON 对象、无 markdown、无 transcript、顶层元数据不得省略」等。
- **Deterministic normalization**：在 `JSON.parse` 之后、schema 校验之前，对 **系统已知** 字段按 shortlist **补缺**；与 shortlist **冲突则不覆盖**，返回 **`binding_conflict` / `metadata_conflict`**（`failureDetail` 含 `path` / `expected` / `actual` / `reason`，**不**记录 raw LLM 全文）。
- **不变**：**不**放宽 winner/loser、分数区间、`strongRisk`、dimensions / candidate 块；**不**写 `MatchResult`、**不**改 **`finalScore`**、**不**进正式 **M4**。

**建议下一步**：在本地合并 M15A 代码后 **再跑一次 M3.8-M15 真实 LLM smoke**，确认 `schema_validation`（缺 `viewerUserId` 等）显著减少；若 provider 支持，可试验 `AI_PAIRWISE_DECISION_JSON_OBJECT_MODE=1`。

### 8.7 M3.8-M15B — Metadata literal tolerance（2026-05-02）

**背景（M15A 后再次真实 smoke）**

| 项 | 值 |
|----|-----|
| 示例 jobId | `cmonx253k00016zygrunp0t30`（维护者本地；**不**含密钥） |
| 现象 | JSON 已可解析；失败 **`metadata_conflict`**，`path=schemaVersion`，`actual="1.0"`，`reason=expected_literal_or_omit` |
| 判断 | 模型已输出结构化 JSON，但将 **`schemaVersion` 写成字符串 `"1.0"`** 等非严格字面量；属 **系统 metadata** 容错范畴，**非**核心决策字段 |

**M15B 修复（实现见规划 §三十二 B）**

- 在 **`normalizeAiPairwiseDecisionDraftFromShortlist`** 内对 **`schemaVersion`** 做安全等价归一（如 **`"1"` / `"1.0"` / 数值 `1`**）→ 输出 **`schemaVersion: 1`**（number）；仍拒绝 **`2` / `"2"` / `"v1"` / boolean / object / array`** 等。

- **Prompt** 补充：优先输出 **JSON number `1`** 作为 `schemaVersion`（服务端仍可纠正常见字符串）。
- **不变**：winner/loser、分数区间、dimensions、`strongRisk` 等 **仍仅由** `parseAndValidateAiPairwiseDecision` **严格校验**；**不**写 `MatchResult`、**不**改 **`finalScore`**、**不**进正式 **M4**。

**建议下一步**：合并 M15B 后 **再跑 M3.8-M15 真实 smoke**，确认 `schemaVersion="1.0"` 类失败消失。
