## 一、当前证据链（整理，n = 8 usable cohort）

以下汇总来自 **M1.3-M9 完成后** 的 shadow 工具链（`m13-m0-calibration-simulator`、`m13-m6-d-pre-major-risks-audit`）在 **usable job 数 = 8** 上的可复现结论；**不**在此粘贴含真实用户标识的原始报表。

| 证据点 | 结论 |
|--------|------|
| **样本量** | **n = 8** usable completed jobs（每 job 满足：completed、≥3 项 succeeded、**schema v2** + **`sourceVersion = ai-match-simulation-rrm-ready-v2`**、非伪造 transcript）。 |
| **current 诊断** | **8/8** `scoreDistributionFlag = too_narrow`，`recommendation = insufficient_separation`；**`too_many_fallbacks` = 0**（该 cohort 内）。 |
| **current spread** | **`avgSpread` ≈ 2.375**，**`medianSpread` = 2**（相对生产诊断阈值 **&lt; 8** 仍整体偏窄）。 |
| **D_admin** | **大量顶格**：M6 cohort 上 **`dPreAtClampCapRate` ≈ 0.97**；与 M3「enrich 后 D 顶格」叙事一致。 |
| **staticLift** | **仍高**：**mean ≈ 0.393**，**median ≈ 0.4**（与 M6 在更小 n 上 ~0.37 同向，说明静态路径对 D 的抬升不是小样本偶然）。 |
| **dedup proxy 稳定性** | **`d_pre_major_risk_dedup_proxy`** 在 **n = 4、n = 5、n = 8** 的连续跑数中均为 **current 对照下 `avgSpread` / `okCount` 最优的 active proxy**（当前 **n = 8**：**`okCount` = 4**，**`avgSpread` ≈ 6.5**，**`medianSpread` ≈ 7.5**）。 |
| **proxy 语义边界** | 该 proxy 在实现上为 **`D' = clamp01(D_tx + min(staticLift, 0.18))`**（见 `rrm-sim-calibration-whatif` 与 §9.9 文档），本质是 **capped static lift**，**不是** production 级 **majorRisks 语义去重**；**禁止**把 M5 表里的 **0.18** 等数字直接当作生产常数合入。 |
| **respect** | **高 R_pre** 审计路径上 **`respectSuggestedActionAllStopOrStepBack = true`**：高风险样本 **未被** 离线代理 **错误放松**（与 M8 结论一致）。 |
| **duplicateRatio vs staticLift** | **Pearson(duplicateRatio, staticLift) ≈ −0.26**（弱相关）：**不能**单靠「粗粒度主题重复」解释 staticLift；若上生产 dedup，仍需独立语义与 bad-case 证据。 |

**一句话**：证据支持「**静态上下文把 D 推到 clamp 顶格 → 同 job RFI 减项同质 → rhythm spread 偏窄**」；离线 **capped lift / dedup proxy** 验证了「**限制静态对 D_pre 的贡献**」与 spread 的单调关系，但**生产第一版**必须走 **可控、可回滚、与 proxy 参数解耦** 的实现路径（见下文候选 1 / 2 与 flag 设计）。

## 二、Production-safe 实现候选（仅设计，不实现）

以下编号与 M8 文档中 **A–E** 对齐，并补充 **M10 命名**，便于 PR / flag 引用。

### 候选 1：Static Lift Cap v1（对应 M8 **A**）

| 维度 | 设计要点 |
|------|----------|
| **核心** | 在 **`extractDPre`**（或等价「静态进入 D_pre 的唯一入口」）内，对**仅来自 staticContext 的增量**施加 **hard cap**，使合成 **D_pre** 不超过「transcript 风险 + capped 静态贡献」之和。 |
| **不改变** | **transcript-only** 风险路径（`transcriptLite` 主导项）；**`R_pre` respect gate** 与常量；**`computeRfiScenario` / `rrm-sim-formula.ts`**；RRM 聚合权重与 **F_sim cap**。 |
| **优点** | 与 **staticLift 高** 的证据直接对齐；比语义 dedup **可控**；无需粗糙 **topic mapper**；易 **feature flag** + **回滚**。 |
| **风险** | cap **过大** → 仍低估静态风险；cap **过小** → 与产品对「静态不合」叙事需对齐；需在实现阶段用 **保守默认** + **shadow 对比** 标定，**不**照抄 M5 **0.18 / dedup** 数值。 |

### 候选 2：Static Lift Soft Cap v1（对应 M8 **C**）

| 维度 | 设计要点 |
|------|----------|
| **核心** | 对等价 **staticLift** 或「静态加分」使用 **饱和曲线 / 分段线性软顶**，避免 hard cap 拐点。 |
| **优点** | 边界行为更平滑，极端静态画像上 less 锯齿。 |
| **风险** | 参数与产品解释成本 **高于** hard cap；需更多 **敏感性曲线** 与文档。 |

### 候选 3：MajorRisks Topic Dedup v1（对应 M8 **B**）

| 维度 | 设计要点 |
|------|----------|
| **核心** | 对 **majorRisks** 做主题归类，同类风险 **递减计权** 或合并。 |
| **风险** | 当前 M6 **topic mapper** 仍粗（含 **`unknown`** 桶）；误合并 **不同** 风险的中–高后果；**不适合第一版生产**。 |

### 候选 4：Two-track D_pre（对应 M8 **D**）

| 维度 | 设计要点 |
|------|----------|
| **核心** | **`riskLabelDPre`** 驱动 **suggestedAction / progressionWindow**；**`scoreDPre`** 驱动 **RFI 减项**；两轨可不同保守度。 |
| **风险** | 产品与合规对「两个 D」的解释成本高；若实现疏忽易 **悄悄放松** risk 轨。**不建议第一版**。 |

### 候选 5：Diagnostic-only（对应 M8 **E**）

| 维度 | 设计要点 |
|------|----------|
| **核心** | **不改 D_pre**；仅调整 **too_narrow / insufficient_separation** 的阈值、分档或 **admin 文案**（与 M4.0 read-only 叙事一致）。 |
| **优点** | 风险最低、可短期改善 **admin 解读**。 |
| **局限** | **不**改善 evaluator 真实分数分布；**不**替代对 **D_pre 来源** 的校准。 |

## 三、推荐第一版（与产品倾向对齐）

**建议优先考虑**：**Static Lift Cap v1** 或 **Static Lift Soft Cap v1**。

**第一版 production proposal 倾向**：**Static Lift Cap v1**。

| 理由 | 说明 |
|------|------|
| **证据对齐** | 与 **staticLift 高**、**D_admin 顶格** 的主线一致，干预点明确。 |
| **可控性** | 较语义 dedup **参数少、行为可证明**；较 soft cap **更易写回滚 Runbook**。 |
| **工程** | **behind flag**；**不动** respect 分支数学式；**不动** RFI 公式文件本身（仅改变传入的 **D_pre** 标量或等价注入点，具体插入点留待实现 PR 论证）。 |
| **必须声明** | **不**直接使用 M5 **`d_pre_major_risk_dedup_proxy`** 的 **0.18** 或 **`d_pre_static_cap_proxy`** 的 **0.25** 作为生产默认；生产常数需 **独立 shadow 标定**、**保守起步**、**按 cohort 复核** 后再收紧。 |
| **边界** | **不影响** `MatchResult` / **`finalScore`** / worker 主排序；**不让** RRM-Sim 进入真实排序。 |

**Soft Cap** 可作为 **v1.1 或并行 shadow 分支**（同一 flag 族下第二曲线），在 hard cap 验证 **respect / transcript-only 高风险** 集无回归后再评估。

## 四、Feature Flag 设计（M12：env 已接入；默认仍关闭）

以下环境变量在 **M1.3-M12** 已由 **`readDPreCalibrationEnvFromProcess`**（`rrm-sim-d-pre-calibration-shadow.ts`）与 **`.env.example`** 落地读取；**默认关闭**；生产 **`evaluateRrmSimFromSimulationV2`** 与持久化 **`rrmSimResult` 主路径不变**。

| 变量 | 取值 | 语义 |
|------|------|------|
| **`RRM_D_PRE_CALIBRATION_ENABLED`** | **`0`（默认）** / `1` | **总开关**：`0` 时行为与当前生产 **完全一致**（无任何 D_pre 校准分支）。 |
| **`RRM_D_PRE_STATIC_LIFT_CAP`** | 浮点，**规划占位默认 `0.25`** | **仅规划名**：表示「静态对 D 的额外贡献」上限思想；**实现时不得**未经 shadow 标定即采用 aggressive 值。 |
| **`RRM_D_PRE_CALIBRATION_MODE`** | **`shadow`** / `enabled` | **`shadow`**：仅计算并记录 **对照字段**（见 §五），**不**改变对外持久化的生产 **`rrmSimResult`** 主路径（或等价：主字段不变，诊断侧链落 **audit / sidecar**）。**`enabled`**：允许在 **RRM-Sim 侧链 / admin enrich** 中写入 **校准后** 展示字段，但仍 **不得** 写入 **`MatchResult`**、**不得** 影响 **`finalScore`**。 |
| **`RRM_D_PRE_CALIBRATION_VERSION`** | 如 **`m1.3-d-pre-static-cap-v1`** | 版本戳，用于报表、日志与回滚识别。 |

**强制要求**：

- **默认关闭**：`RRM_D_PRE_CALIBRATION_ENABLED=0` 时，与未部署该功能前 **bit-for-bit 业务语义一致**（实现阶段需 **单测 / 快照** 锁定）。  
- **`shadow`**：**不**改变生产 **`RrmSimResult`** 中用于既有契约的字段（或团队明确划定的「主字段」集）；仅附加诊断对比。  
- **`enabled`**：**仍不得** 进入 **`MatchResult` / `finalScore` / worker 排序**；仅限 **admin / dev / diagnostic API** 约定路径。  
- **可回滚**：一键 `ENABLED=0` 或切回旧版本常量；Runbook 记录 **版本号 + 时间窗**。

## 五、Shadow 输出设计（M12：`buildDPreStaticLiftCapShadowResult` 字段契约）

以下字段由 **`buildDPreStaticLiftCapShadowResult`** 返回；**M12** 下当 **`RRM_D_PRE_CALIBRATION_ENABLED=1`** 且运行 **`tools/m13-m0-calibration-simulator.mjs --includeDebug`** 时，作为 **`perJobDiff[].dPreCalibrationShadow`** 附加（**不写 DB**、**不调 LLM**）。**不得** 在 **FinalMatchPage**、**`getJobForViewer`** 或普通用户 API 中暴露。

| 字段 | 说明 |
|------|------|
| **currentDPre** | 与当前生产 **`extractDPre`** 输出一致（或从现算链路读取）。 |
| **calibratedDPre** | 应用 cap / soft 规则后的值。 |
| **staticLiftBefore** | 实现定义的「静态增量」度量（可与 M6 审计定义对齐，但**不必**相同公式）。 |
| **staticLiftAfter** | cap 后的静态贡献或残余。 |
| **currentRhythmScore** | 基线 **simulatedRhythmScore**（每候选或聚合，与实现 scope 一致）。 |
| **calibratedRhythmScore** | 用 **calibratedDPre** 重算后的 rhythm（若仅在 shadow 重算）。 |
| **currentRecommendation** | 基线 **M4.0 read-only proposal** 或诊断桶。 |
| **calibratedRecommendation** | 重算后诊断桶。 |
| **respectGateApplied** | 是否命中 **R_pre ≥ gate** 分支（必须为真时覆盖 rhythm cap 等既有行为）。 |
| **safetyOverrideApplied** | 是否命中其它安全覆盖（若有）。 |
| **calibrationVersion** | 与 **`RRM_D_PRE_CALIBRATION_VERSION`** 一致。 |
| **calibrationMode** | `shadow` / `enabled`。 |

## 六、安全红线（实现与 CR 必须逐条对照）

1. **`R_pre` respect gate 不能被降低**：常量 **`RRM_SIM_RESPECT_R_PRE_GATE`** 与 **`R_pre ≥ 0.7`** 分支行为（含 **rhythm cap 25**）保持产品权威；D_pre 校准 **不得** 绕过或削弱该分支。  
2. **`stop_or_step_back` 不得被降级**：respect 命中时 **`suggestedAction`** 不得因 D 校准变为更乐观枚举。  
3. **高 R_pre 样本必须保持保守**：校准前后 respect 路径 **一致** 或 **更保守**，禁止「为了 spread」放松。  
4. **transcript-only 高风险不能被 static cap 放松**：cap **仅限制静态增量**；**`extractDPre(transcriptLite, null)`** 或等价 transcript 主导项 **不得** 因 cap 被压低 below 产品安全下限（若实现采用「transcript + capped static」分解，需在 PR 中 **形式化证明**）。  
5. **不能把 D_pre 校准直接写入 `MatchResult`**。  
6. **不能直接影响 `finalScore`** 或 **worker 主排序**。  
7. **不能进入正式 M4**（只读 ranking proposal 契约不变，直至独立里程碑批准）。  
8. **不能把 `d_pre_major_risk_dedup_proxy` 当作生产规格直接上线**（见 §一）。
