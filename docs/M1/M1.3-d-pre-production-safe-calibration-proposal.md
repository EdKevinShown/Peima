## 一、当前证据链（M1.3-M3 / M5 / M6 / M7）

| 证据 | 结论 |
|------|------|
| **M3** | 在 early cohort 上：**D_admin（enrich 后）全员顶格 1.0**；**`extractDPre(transcriptLite, null)`（D_tx）约 0.54–0.78**；**job 内 D_pre spread = 0**；静态上下文抬升是主怀疑之一。 |
| **M5**（`--includeDebug`，usable **n = 5**） | **current**：**5/5** `too_narrow`，**`insufficient_separation`**，`avgSpread` 约 **2**。**`d_pre_major_risk_dedup_proxy`**：**`avgSpread` ≈ 7.8**，**`okCount` = 3**，仍为最强 config；实质为 **capped static lift**（`D' = clamp01(D_tx + min(staticLift, 0.18))`），**非**生产级语义去重。 |
| **M6** | **staticLift** cohort mean ≈ **0.37**；**majorRisks** 恒 **5 行**（摘要上限）；**duplicateRatio** 与 **staticLift** 的 Pearson **弱负**（量级约 **−0.23**）→ **duplicateRatio 不能单独解释 staticLift**；**D_admin 顶格率 100%**。 |
| **M7** | 第二 viewer job **`cmonhuv0k00066z444g63dwph`** 补至 **rrmReadyV2 ≥ 3**；**usableJobCount：4 → 5**；M5/M6 结论在 **5 job** 上仍成立。 |
| **respect** | M5 what-if 与 M6 审计：**高 R_pre** 样本 **未被** proxy **错误放松**（`suggestedAction` 仍为 **`stop_or_step_back`** 等）；**闸门常量未改**下的离线镜像一致。 |

**一句话**：观测支持「**静态路径把 D 推到 clamp 顶格 → 同 job 内 RFI 减项同质 → rhythm spread 偏窄**」；离线 **capped lift** 能拉开 spread，但**不能**直接等同于已验证的**生产**去重或安全配方。

## 二、Production-safe 方案候选（≥4）

以下均为 **产品设计/工程候选**，本轮**不实施**。

| id | 名称 | 核心思想 |
|----|------|----------|
| **A** | **Static Lift Hard Cap** | 将「仅来自 staticContext 的增量」限制在上限（例如与离线一致 **staticLift ≤ 0.25** 的思想），在 **`extractDPre`** 或静态摘要进入点统一施加。 |
| **B** | **MajorRisks Semantic Dedup** | 对 **`majorRisks` 文本**做主题桶去重或递减计权，避免多行同义叠加。 |
| **C** | **Static Lift Soft Cap** | 对 **staticLift** 或等价的「静态加分」做平滑压缩（如饱和曲线），避免硬阈值拐点。 |
| **D** | **D_pre Two-track** | **`riskLabelDPre`**：闸门 / SA / PW；**`scoreDPre`**：RFI 减项；对 **`scoreDPre`** 侧的静态增量更保守。 |
| **E** | **Diagnostic-only** | **不改 D_pre**；调整 **shadow 诊断**阈值或文案（`too_narrow` / `insufficient_separation` 解释），不声称已改善真实分离度。 |

## 三、方案对比（逐项）

表头缩写：**eval** = `extractDPre`；**RFI** = `computeRfiScenario` 数学式文件；**respect** = `R_pre ≥ 0.7` 分支；**SA/PW** = `suggestedAction` / `progressionWindow`；**offline** = 现有 M5 simulator；**小范围 prod** = 可控 rollout（feature flag）；**风险** = 误伤真实风险 / 语义漂移 / 解释成本。

| 方案 | 改 extractDPre？ | 改 RFI 公式？ | 影响 respect？ | 影响 SA/PW？ | 可能降安全？ | 可先 offline？ | 适合小范围 prod？ | 主要测试 | 风险等级 | 优先级 |
|------|------------------|---------------|----------------|--------------|--------------|----------------|-------------------|----------|----------|--------|
| **A** | **是**（主入口） | **否**（仍传单一标量进 RFI，除非走 D） | **可设计为否**（若闸门仍用原 D 或 risk 轨） | **间接**（D 变低 → D 门触发变少） | **中**（cap 过大则低估静态风险） | **是**（已有 static cap proxy） | **中**（需 flag + 回滚） | 多 viewer spread；respect 集；顶格率 | **中** | **1** |
| **B** | **是**（摘要/计数逻辑） | **否** | **否**（若不动 R_pre 提取） | **间接** | **中–高**（误合并不同风险） | **是**（需新 proxy 贴近语义，非仅 lift cap） | **低–中** | 人工 bad-case；跨语言；与问卷摘要一致性 | **中高** | **3**（依赖更细标签与审阅） |
| **C** | **是** | **否** | **可设计为否** | **间接** | **中**（参数难向产品解释） | **是**（可加 soft-cap proxy） | **中** | 同 A + 参数敏感性 | **中** | **2** |
| **D** | **是**（evaluator 传参/双标量） | **否**（公式签名可不变） | **可设计为否**（risk 轨保守） | **是**（显式两轨语义） | **高**（若 risk 轨被悄悄放松） | **是**（simulator 需 fork 两 D；**deferred**） | **低**（强评审前不上） | 安全签核；全链路 E2E；文案 | **高** | **4**（产品/安全强依赖） |
| **E** | **否** | **否** | **否** | **否** | **低**（不改分数） | **是**（阈值已在 M0） | **高**（最易上线） | 报表与 M4.0 解读一致性 | **低** | **0（并行）** |

**绝不能直接上线的方案（未经评审 / 无 flag / 无回滚即合入主分支）**：**A、B、C、D** 任一涉及 **`extractDPre` 或 evaluator 双轨** 的改动；**M5 `d_pre_major_risk_dedup_proxy` 及同类 proxy** 本身（仅为离线 capped lift，**非**产品规格）。

## 四、保守推荐路线（与您的倾向对齐）

1. **不动 respect gate**（常量与 **`R_pre ≥ 0.7`** 分支保持产品权威；任何 D 调整不得削弱该路径）。  
2. **不直接改 `finalScore` / worker 主排序 / `MatchResult`**（D 校准属于 **evaluator 输入层**，与排序字段解耦）。  
3. **当前阶段只做 production proposal 与门槛定义**，**不实施**代码变更。  
4. **若未来进入实现**：在**证据与评审**满足门槛的前提下，**优先考虑 A 或 C**（直接针对 **staticLift**，与 M5/M6 证据最对齐；C 需额外做参数与产品叙事）。  
5. **B** 需 **更精细的 majorRisk 主题标注 + 人工 spot-check**，当前 **duplicateRatio 不足以**支撑单独上生产 dedup。  
6. **D** 必须经 **产品 / 安全 / 法务式** 的「两轨含义」评审与测试矩阵，**默认不作为第一刀**。  
7. **E** 可作为 **短期 admin / shadow 诊断体验**改善（阈值或说明文案），**不能**替代对 **D_pre 来源** 的 evaluator 校准；与 **M4.0 read-only proposal** 文案一致即可。

## 五、进入实现前必须满足的门槛

| # | 门槛 |
|---|------|
| 1 | **usableJobCount ≥ 8**（建议 **≥ 10**）再谈 **extractDPre** 行为变更的合入评审。 |
| 2 | **至少 2 个 viewer**（M7 已满足；扩样本后需 **保持**）。 |
| 3 | **Offline**：**`d_pre_static_cap_proxy` / `d_pre_major_risk_dedup_proxy`**（或等价 A/C proxy）在更大 cohort 上 **仍稳定**改善 **`avgSpread` / `okCount`** 或明确「无效」结论，避免单批过拟合。 |
| 4 | **respect**：高 **R_pre** 集 **无**错误放松（SA/PW/rhythm cap 与现网一致）。 |
| 5 | **人工**：对 **静态 majorRisks** 抽样确认 **「全员顶格」非** 合理风险对齐的必然结果（避免把数据 artifact 当真相）。 |
| 6 | **工程**：**feature flag**、**按 viewer 或 job 灰度**、**回滚路径**（恢复旧 `extractDPre` 行为或关闭新分支）文档化。 |
| 7 | **分离**：**production evaluator 变更** 与 **仅诊断/报表变更**（方案 E）**分 PR、分发布说明**，避免用户误以为「分数已变好」。 |
