## 1. D_pre 当前来源（只读梳理 `extractDPre` + 闸门常量）

**实现位置**：`apps/api/src/modules/ai-simulation-v1/rrm-sim-extractor.ts` **`extractDPre`**；**输出层分支**在 `rrm-sim.evaluator.ts` **`evaluateRrmSimFromSimulationV2`**（**`D_pre` 同时进入每场景 `computeRfiScenario` 的减项与闸门逻辑**）。

### 1.1 公式组成（`extractDPre`）

| 组成 | 代码行为 | 量级直觉 |
|------|-----------|-----------|
| **base** | `d = 0.22` | 固定底数 |
| **transcript / mainRisks** | `mainRisks.join("\n")`：`+ 0.04 * min(8, length/8)`；`+ 0.06 * countMatches(..., /冲突|节奏|安全|目标|压力|控制/g)` | 长列表与关键词命中可显著抬高 |
| **`staticContext.majorRisks`** | 行数 `n`：`+ 0.055 * min(5, n)`；全文对 **`STATIC_RISK_D_BOOST_RE`** 匹配：`+ 0.05 * min(6, countMatches(...))` | **易与「模板化多行风险」叠加**，是 M3 观测中 **admin − transcript** 差的主贡献者之一 |
| **`relationshipGoalHint`** | 字符串命中 `/差异偏大|冲突|偏高/` → **`+ 0.07`** | 单次可加 **0.07** |
| **keyword risk（静态 regex）** | 上表 `STATIC_RISK_D_BOOST_RE`（婚姻、生育、节奏、冲突、控制、价值观等宽网） | 命中次数上限 **6** 次项，每次最多 **0.05** |
| **`clamp01`** | 全程 **`[0,1]`** 截断 | **顶格 1.0** 后所有更高「raw」信息被吃掉 |
| **（无）独立 soft-cap** | — | 当前**无**「超过 0.8 后缓冲」的中间层，仅靠 **clamp** |

### 1.2 D_pre 相关闸门（`rrm-sim.constants.ts` + evaluator）

| 常量 / 行为 | 值 | 含义 |
|-------------|-----|------|
| **`RRM_SIM_RESPECT_R_PRE_GATE`** | **0.7** | `R_pre ≥ 0.7` 时 **优先** respect 分支：`suggestedAction = stop_or_step_back`，`progressionWindow = closed`，**`simulatedRhythmScore = min(..., 25)`**；**此分支下不再走 `D_pre` 门** |
| **`RRM_SIM_STATIC_D_PRE_GATE`** | **0.8** | `R_pre < 0.7` 且 **`D_pre ≥ 0.8`** → **`slow_down`**；`progressionWindow` 见下行 |
| **`RRM_SIM_STATIC_D_PRE_CLOSED_WINDOW`** | **0.9** | 同上前提下 **`D_pre ≥ 0.9`** → **`progressionWindow = closed`**，否则 **`weak_open`** |

**说明**：常量注释中「output layer only」指 **闸门对 `suggestedAction` / `progressionWindow` 的分支**；**`D_pre` 本体仍进入 RFI 公式**（与注释字面不完全一致，以代码为准）。

### 1.3 当前最可能导致 `D_pre` 顶格（1.0）的来源（基于 M3 + 代码结构）

**排序（主 → 次）**：

1. **`staticContext.majorRisks` 行数项 `0.055 * min(5,n)`** 与 **`STATIC_RISK_D_BOOST_RE` 宽网命中 `0.05 * min(6,·)`** 叠加，在 **多行、重复主题** 的静态风险列表上极易触顶。  
2. **`relationshipGoalHint`** 命中 **+0.07**。  
3. **`mainRisks` 长度与关键词** 在 transcript 侧已能把 **transcript-only** 推到 **~0.54–0.78**；与静态叠加后 **`clamp01` → 1.0**。  
4. **`clamp01`**：一旦 raw **≥ 1**，全员 **失去跨候选差异**（M3：**job 内 D_pre spread = 0**）。

## 2. D_pre calibration 方案（≥5；**生产仍不实现**）

下列为 **设计选项**；**A/B/C** 已在 **M1.3-M5** 以 **offline proxy** 形式接入 `tools/m13-m0-calibration-simulator.impl.ts`（`--includeDebug`）；**D/E** 仅注册为 **deferred**；**F** 仍由 M0 threshold 类覆盖。

| 方案 | 一句话 |
|------|--------|
| **A** | **static contribution cap**：限制仅来自 `staticContext` 的增量上限。 |
| **B** | **majorRisks 去重 / 降权**：主题桶去重或次主题降权，避免线性累加。 |
| **C** | **D_pre soft cap**：高段压缩曲线，减少轻易顶到 1.0。 |
| **D** | **score / gate 分离**：用于 RFI 的 `scoreDPre` 与用于闸门的 `riskLabelDPre` 分叉。 |
| **E** | **viewer-level normalization**：同 viewer 多候选全顶格时保留相对秩（需谨慎）。 |
| **F** | **仅调诊断阈值**：不动 `D_pre` / RFI，只改 shadow **too_narrow** 报表解释。 |

## 3. 方案对比表（必选维度）

**图例**：**eval** = `extractDPre`；**RFI** = `computeRfiScenario` 是否用同一标量；**respect** = `R_pre` respect 分支；**SA/PW** = `suggestedAction` / `progressionWindow`；**sim** = 适合先 **offline simulator**；**prod** = 适合 **生产**（在充分安全评审后）。

| 方案 | 作用位置 | 改 eval？ | 改 RFI 公式文件？ | 影响 respect？ | 影响 SA/PW？ | 可能降安全？ | 先 offline sim？ | 先上 prod？ | 风险 | 优先级 |
|------|------------|-----------|-------------------|-----------------|--------------|--------------|-----------------|-------------|------|--------|
| **A static cap** | `extractDPre` 内静态块或上游 static 摘要 | 是（若上 prod） | **否**（仍用同一 `computeRfiScenario` 签名） | **否**（respect 仍只看 `R_pre`） | **间接**（D 变低可能少触发 D 门） | **中**（若 cap 过大） | **是** | 待定 | 中 | **1** |
| **B majorRisks dedup** | static 文本预处理或 `extractDPre` 内计数逻辑 | 是 | 否 | 否 | 间接 | **中** | **是** | 待定 | 中 | **2** |
| **C soft cap** | `extractDPre` 末尾或独立标量映射 | 是 | 否 | 否 | 间接 | **中–高**（若压过低） | **是** | 待定 | 中高 | **3** |
| **D gate split** | `evaluateRrmSimFromSimulationV2`：两路 D 标量 | 是（evaluator） | **否**（公式模块可不变，但**调用方**传参变化） | **可设计为否** | **是**（显式） | **高**（若 risk 标量放松） | **是**（proxy 模拟分叉） | 低–中（需强设计） | 高 | **4** |
| **E viewer relative** | 多候选归一（evaluator 或 job 级后处理） | 是 | 否 | 否 | **可能** | **高** | **是** | 低 | 高 | **5** |
| **F diagnostic only** | `buildRrmSimMultiCandidateDiagnostic` / 脚本阈值 | **否** | **否** | **否** | **否** | **低** | **是** | **是**（最易） | 低 | **并行 0**（与 D 解耦） |

**说明**：

- **「改 RFI 公式」**：指 `rrm-sim-formula.ts` 内 **`computeRfiScenario` 数学式**；**A/B/C** 通常只改变输入 **`D_pre`**，**不**必改公式文件。  
- **D 方案** 可能 **不改 formula 文件** 但 **改 evaluator 传参逻辑**（仍违反本轮「不改 evaluator」红线，仅作未来候选）。  
- **respect gate**：所有方案均应 **默认不削弱** `R_pre ≥ 0.7` 分支；验收见 §6。

## 4. 推荐最小安全路线（顺序）

1. **只做 offline what-if**（M1.3-M5 扩展或现有 `lower_d_pre_penalty` 族），**不改生产**。  
2. **优先在 simulator 验证「static contribution cap」类 proxy**（对应 **方案 A** 的离线近似：对 admin 已算出的 `D_pre` 或重算的 static 增量做 cap —— **注意**：不改 `extractDPre` 时，只能用 **后处理 proxy** 近似 A 的意图）。  
3. **再测 majorRisks 去重 / 降权 proxy**（**方案 B** 的离线近似：对「合成 D」或从 `transcriptLite`+静态摘要重算）。  
4. **respect 分支不动**；任何 config **不得**把 **高 `R_pre`** 样本放松成「可大力推进」。  
5. **不动 finalScore / MatchResult / worker 主排序**。  
6. **若** 多 viewer 样本下 **offline 效果稳定且安全评审通过**，再单开 **production proposal**（仍非「正式 M4」）。

## 11. M1.3-M6 — majorRisks 审阅与 dedup proxy 合理性（只读）

**工具**：`node --env-file=.env tools/m13-m6-d-pre-major-risks-audit.mjs --limit 20`  
**代码**：`apps/api/src/modules/ai-simulation-v1/rrm-sim-major-risks-audit.ts`（主题归类、指纹、审计行）；`tools/m13-m6-d-pre-major-risks-audit.impl.ts`；问卷加载复用 **`questionnaire-profile-view.util.ts`**（与 `QuestionnaireService.getProfileForUser` 同路径）。**不**写入 DB、**不**调 LLM；报表**不**含完整风险原文，仅 **主题标签 / 计数 / sha16 指纹 / 标量**。

### 11.1 样本与数据形状

| 维度 | 本环境结果（示意） |
|------|---------------------|
| **job / candidate** | **4** job、**18** 条 succeeded + RRM-ready v2 候选 |
| **majorRisksCount** | **恒为 5**（`buildMatchReviewStaticSummary` + `buildAiSimulationStaticContext` 对 `majorRisks.slice(0,5)` 的上限） |
| **staticLift**（D_admin−D_tx） | mean ≈ **0.37**，min≈0.22，max≈0.46 |
| **duplicateRatio**（粗粒度主题：5 行内同标签重复） | mean ≈ **0.23**，max **0.4**（同一 viewer 下多候选可共享**同一套**问卷摘要指纹） |
| **fingerprint** |  cohort 内主要 **2** 类 `majorRisksFingerprintSha16`（不同 viewer×摘要模板），非 18 条全异文案 |
| **relationshipGoalHint 风险命中**（evaluator 同构 `/差异偏大|冲突|偏高/`） | 本批 **0** |
| **D 顶格** | **D_admin = 1** 占满 18/18；**regex 命中数**在 majorRisks 联文上多为 **6**（触 `extractDPre` 中 `min(6,·)` 上限倾向） |
| **respect** | **R_pre ≥ 0.7** 的候选 **1** 条，`suggestedAction` 仍为 **`stop_or_step_back`** |

### 11.2 与 dedup proxy（M5）的关系

- **M5 `d_pre_major_risk_dedup_proxy`** 在公式上等价于 **`D' = clamp01(D_tx + min(staticLift, 0.18))`**，**不是**对 majorRisks 文本做生产去重。  
- **spread 改善**（M5：`avgSpread` 8.25 vs current 1.75）主要来自 **人为压低共享静态减项**，使候选间 **RFI** 差重新显现；**不能**等价于「已验证 majorRisks 应去重」。  
- **pearson(duplicateRatio, staticLift)** 在本批约为 **弱负**（量级约 **−0.23**）：**重复主题比例高并不线性解释更高的 staticLift**，与「顶格由多因子叠加（行数项 + regex cap + 同摘要）」一致。

### 11.3 审阅结论（七问摘要）

1. **是否存在明显重复主题？** — **有**：在粗标签粒度上，`conflict_style` 等在 5 行内重复出现；且 **多候选共享同一 fingerprint**。  
2. **D 顶格是否主要来自重复主题累加？** — **部分**：重复主题是**可见因子**，但 **恒 5 行**与 **regex 顶格**同样关键；**不应**单归因 dedup。  
3. **dedup proxy 改善 spread 是合理去重还是人为降风险？** — **以后者为主**（capped lift）；离线观察有价值，**非**语义去重证明。
